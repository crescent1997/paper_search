# Cache-Craft: Managing Chunk-Caches for Efficient Retrieval-Augmented Generation

## 概要
Cache-CraftはRAGで同じretrieved chunkが複数queryに繰り返し現れることを利用し、chunk単位のprecomputed KVを**chunk-cache**として保存・再利用する。単純連結で生じるquality degradationを少量のselective recomputationで修復するだけでなく、reuse判定、storage、loading、evictionまで扱うserving system。

## 問題設定
RAGではchunkがqueryごとに異なる順序・prefix contextで配置される。独立計算したKVをそのまま再利用すると、元のprefillで存在しなかったpreceding chunksとのattention interactionが欠けるため、full prefillとの差が生じる。[CacheBlend](2024-2405.16444-cacheblend.md)と同じ根本問題だが、Cache-Craftはsystem-wideなcache managementまで対象にする。

## Reusability / context dependency
chunkが新しいprompt contextでも安全に再利用できるかを、chunk内部および先行contextへのattention patternから推定する。旧contextと新contextの共通性、chunkのcontext dependencyを考慮して、どの程度cacheを修復すべきかを決める。

重要なのは全tokenを再計算するのではなく、**context changeの影響を強く受けるtokenを優先して再計算する**こと。

## Selective cache fixing
必要なrecomputation量をcache-fix overheadとして制御し、attention由来のimportance/context-dependency signalに基づいてtokenを選択する。

```text
cached chunk
  + new preceding context
       ↓
context-dependency / reuse判定
       ↓
recompute budget決定
       ↓
selected tokenだけ再計算
       ↓
fixed chunk-cache
```

full prefill approximationを小さいrecomputation budgetで得るという意味でCacheBlend系統。

## Efficient attention implementation
selected tokenだけをqueryとしてfull preceding KVへattentionさせるため、通常のdense attentionをそのまま実行すると計算削減が小さい。Cache-CraftはTriton-based FlashAttentionを変更し、**scattered recomputed queries**を効率的に処理する。

selective recomputationをalgorithmだけでなくkernelまで落とし込む点が重要。

## Cache management
Cache-Craftはchunk-cacheのreuse frequencyや修復costを考慮して保存・evictionを行う。さらにCPU/GPU間のcache loadingとGPU computationをoverlapし、cache I/O overheadを隠す。RAG servingで「何を再計算するか」だけでなく「どのcacheを残すか」も同時に最適化する。

## CacheBlendとの差
| | CacheBlend | Cache-Craft |
|---|---|---|
| 中心 | selective KV fusion | RAG chunk-cache system |
| repair | selective recomputation | selective recomputation |
| reuse判定 | algorithm中心 | context dependencyを含む |
| storage/eviction | 限定的 | 明示的に管理 |
| kernel | selective attention | scattered-q向けTriton attention |
| serving | reuse algorithm | end-to-end cache manager |

## Experiment Setup
production RAG workloadとsynthetic datasetsを用い、Llama-3-8B / 70Bなどでprefix caching、full recomputation等と比較。qualityを維持しながらredundant computation、throughput、end-to-end latencyを評価する。

## Main Results
prefix caching比でredundant computationを約51%削減、full recomputation比で約75%削減。continuous batchingを用いたproduction workloadではprefix cachingに対しthroughput約1.6×、end-to-end response latency約2×改善を報告する。

## Ablation / Analysis
主要な分析軸は、cache-fix budget、context similarity/dependency、selected token数、cache management policy、I/O-compute overlap。recomputationを増やすほどfull prefillへ近づく一方TTFT benefitは減るため、quality/latency trade-offをsystem側で制御する。

## Limitations
- attention statisticsとreuse判定自体にoverheadがある。
- selective-qを本当に高速化するにはcustom attention kernelが必要。
- chunk-cacheのstorage/transfer costが大きい。
- query/context分布が変化するとcache hitとrepair costも変わる。
- full-prefill exact equivalenceではなく近似的repair。

## KV-cache taxonomyでの位置づけ
**reuse / RAG chunk cache / inference-time selective repair / cache management / training-free**。
