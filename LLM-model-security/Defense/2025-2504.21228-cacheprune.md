# CachePrune: Teaching LLMs What Not to Follow via KV-Cache Editing

## 概要・選定理由

LLMの「入力データに含まれる命令を実行してしまう」失敗を、**外部コンテキストに対応するKVキャッシュの編集**として扱う。ユーザーが明示的に指示したタスクは遂行しながら、引用文・検索結果・文書中の命令は実行しないという**prompt/data separation**を目標とする。ACL 2026 Main採択を公式ACL Anthologyで確認済み。ユーザーのKVキャッシュ研究とも直接接続する。

本研究のCachePruneは、別論文 arXiv:2605.23640 の同名のKVキャッシュ共有・プライバシー保護手法とは**別物**。本ファイルは arXiv:2504.21228 / ACL Anthology 2026.acl-long.70 の論文に対応する。

## Problem Setting / Threat Model

正規ユーザーの命令と外部コンテキストを連結してモデルに与える。攻撃者は外部コンテキスト内の一部を操作し、ユーザーの依頼とは異なる出力を生成させる。防御側は、モデルの重みを変更せず、外部コンテキストを符号化した際のKVを操作できる**モデル内部アクセスあり**の条件を想定する。

| 項目 | 条件 |
|---|---|
| 攻撃primitive | lower-trust context内に埋め込む命令（間接prompt injection） |
| 攻撃者のアクセス | 外部文書・入力コンテキストの改変。正規system/user instructionの書換えは想定しない |
| 防御側のアクセス | KV-cacheテンソルと、attribution計算時のモデル内部表現・勾配 |
| White-box / Black-box | 防御側はwhite-box; 攻撃は静的/異種攻撃の転移を評価。完全適応型への保証はない |
| Target logits/gradient | 防御のoffline attributionでは必要。実運用の攻撃者に必要という意味ではない |
| 攻撃形状 | 外部データ中のin-context injectionが主対象。ユーザーの直接jailbreak suffixとは異なる |

## 先行研究からの改善点

StruQやSecAlignはモデルの学習によって境界を教えるが、CachePruneは**推論時に参照されるKV表現を変更する**。モデルを再学習せず、正規命令を変更せず、別検出LLMによる二重推論も行わない。GCG型の入力token最適化と異なり、防御側が表現の一部を減衰させる操作である。

## Method / Algorithm

### 1. KV単位の特徴量とattribution

外部コンテキストのtoken範囲を $[c_s,c_e]$ とし、各tokenに対する全layer・全head相当のK/V活性を $h_t$ とする。各要素のattributionを $a_t^i$ としたとき、ニューロン単位のスコアを

$$
a^{i,\mathrm{neu}}=\max_{c_s\le t\le c_e}a_t^i
$$

で集約する。maxを使う理由は、少数tokenで強く活性化する命令追従成分を拾うため。

### 2. Preferential attribution loss

同じ入力 $x$ に対して、攻撃者の命令に従ったpoisoned応答 $y_x^p$ と正規ユーザーの命令に従ったclean応答 $y_x^c$ を対比する。論文はDPO型の選好目的と関連付け、実際のattributionには、最尤代表応答を用いた近似

$$
\mathcal{L}_{\mathrm{attr}}=\mathbb{E}_{x}\left[p_\theta(y_x^{p,*}\mid x)-p_\theta(y_x^{c,*}\mid x)\right]
$$

を使う。**poisonedを増やす方向に効く成分**を選択的に検出する設計である。DPO上界との関係は理論的な動機づけであり、モデルにDPO学習を実施するわけではない。

### 3. Utility-preservingな選別集合 $\Phi$

attribution上位を無差別に消すと文書内容の理解まで壊すため、clean応答品質を妨げる成分を候補から除く集合 $\Phi$ を導入する。対象は全KVではなく、**外部コンテキスト区間に属する指定成分**に限定する。

### 4. KVマスク

選択された成分に対して

$$
m_i=1-\alpha\,\mathbf{1}[a^{i,\mathrm{neu}}\ge\tau\;\land\;i\in\Phi]
$$

を掛ける。$\alpha=1$ では対象成分をゼロ化する。$p$ はprune率、$\tau$ は閾値。位置ごとのtoken削除ではなく、**K/V活性のchannel/ニューロン成分のマスキング**である点に注意。トークン数削減や通常のKV evictionとは異なる。

## Experiment Setup

論文ではLlama-3-8B、Mistral-7B、Phi-3.5-mini-Instruct等を用い、SQuADなどの質問応答タスクで攻撃成功率（ASR）とF1（clean / attack）を併記。学習したマスクの異種攻撃への転移、attributionに使うサンプル数 $N$、pruning率 $p$、マスク候補 $\Phi$ の有無を分析する。実験表のASRは個別の攻撃条件・タスクに依存するため、一般的なprompt injection全般の成功率として扱わない。

## Main Results

論文のSQuAD / Llama3-8B ablation（マスク候補集合 $\Phi$ の有無）を抜粋する。数値はASR（低いほど良い）とF1（高いほど良い）。

| Prune率 | $\Phi$ | ASR % | Clean F1 | Attack F1 |
|---|---|---:|---:|---:|
| 0.5% | あり | 7.44 ± 0.22 | 28.68 ± 0.30 | 22.84 ± 0.49 |
| 0.5% | なし | 7.65 ± 0.63 | 29.06 ± 0.42 | 21.35 ± 0.44 |
| 1.0% | あり | 4.38 ± 0.32 | 28.12 ± 0.58 | 23.17 ± 0.30 |
| 1.0% | なし | 4.64 ± 0.53 | 26.01 ± 0.43 | 18.77 ± 0.91 |
| 5.0% | あり | **0.83 ± 0.07** | **27.48 ± 0.66** | **23.03 ± 0.64** |
| 5.0% | なし | 7.86 ± 0.86 | 6.48 ± 1.04 | 10.43 ± 2.05 |

ここで重要なのはASRを下げるだけでなく、**$\Phi$なしの強いpruningではF1が大きく低下する**こと。モデルにとって「命令」と「回答に必要な情報」を内部表現上で分離する必要性を示している。

## Generalization / Robustness / Adaptive Evaluation

- **Attribution sample数**：Llama3-8Bで $N=4/8/12$ のASRはそれぞれ8.15/7.44/7.52%。Mistral-7Bでは0.74/0.68/0.57%。少数サンプルでマスクを推定できるが、単調改善は保証されない。
- **攻撃の形式転移**：論文にはcode-based/text-based injection間のマスク転移表があり、単一の文字列表現への過学習だけではないことを検討している。
- **Adaptive attack**：付録Fに適応攻撃の検討があるが、ここで確認した資料だけでは攻撃予算と各ASRを厳密に転記できないため、数値は保留する。
- **既存Defense直接比較**：StruQ、SecAlign、Meta SecAlign、CaMeLを同一条件で突破/上回ったと断定できる直接比較数値は、確認済み箇所にはない。

## Limitations

防御モデルの内部K/Vとattributionのための勾配を必要とするため、API-only closed modelにはそのまま適用できない。マスクの構築には少数のclean/poisonedサンプルが必要で、別ドメイン・別モデルへの汎化は再検証が必要。$\Phi$とprune率により品質/防御性能が変わる。論文自体もadversarial fine-tuningとの直接比較を十分には扱っていないと明記している。KVキャッシュを共有・再利用するserving系では、マスク済みと未マスクのcacheを混在させない管理が必要と考えられる（研究上の推論）。

## LLM Model Security taxonomyでの位置づけ

| 軸 | 分類 |
|---|---|
| Trust boundary | trusted user instruction vs. untrusted context |
| Defense locus | model-internal KV-cache intervention |
| Learning | offline gradient attribution; model weights unchanged |
| Runtime | context KV mask; generation-side extra model callなし |
| Failure mode | lower-trust textのinstruction化 |
| 主な差異 | segment delimiter/SFT/DPOではなくKV表現を直接編集 |

## 実装・研究上の示唆

KVキャッシュの圧縮・再利用研究では、**どのtokenを残すか**だけでなく、**残したtokenのK/Vのどのchannelを無効化するか**という新しい制御軸を示す。層別・head別の選択マスク、再利用済みKVへのマスク適用順序、GQAでのK/V channel mapping、KV圧縮とinstruction/data分離の両立が重要な追試点。vLLMで実装する場合はcache blockの所有権とmask versionを区別する必要がある（提案・推論）。
