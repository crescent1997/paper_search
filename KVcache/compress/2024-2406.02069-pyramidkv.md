# PyramidKV: Dynamic KV Cache Compression based on Pyramidal Information Funneling

> KV compressionで全Transformer layerへ同じcache budgetを割り当てる必要はない。lower layerでは広いcontextを残し、informationが集約されたupper layerほどcacheを強く圧縮する。

## 概要

H₂O、SnapKV等のKV cache compressionは重要tokenだけを残すことでmemoryを削減するが、多くは各Transformer layerへ同じKV budgetを割り当てる。

PyramidKVはlong-context processing中のattention patternをlayer方向に解析し、

- lower layers: attentionが広いcontextへ分散
- middle layers: relevant context/segmentへ徐々に集中
- upper layers:少数のcritical token / attention sinkへ集中

する**Pyramidal Information Funneling**を観察する。

この構造を利用し、lower layerへ多く、upper layerへ少ないKV budgetを割り当てる。総KV数を一定にしたままlayer間allocationを変えることで、uniform compressionより高いaccuracyを得る。

## 問題設定

既存compressionでは、例えば全32 layerにそれぞれ128 tokenずつKVを残すようなuniform allocationが一般的。

しかし各layerで必要なinformation量が異なるなら、同じbudgetを与えることは非効率。

特にupper layerではattentionが既に少数tokenへ集中しているため余剰capacityが生じる一方、lower layerを同じ比率まで削ると、後段で集約される前のdistributed informationを失う。

PyramidKVは、

> **total KV budgetを変えずにlayer-wise allocationを最適化する**

ことを狙う。

## Pyramidal Information Funneling

著者らはmulti-document long-context promptのattention mapをlayerごとに可視化する。

lower layerでは複数document/tokenへattentionが広く散らばる。

layerが深くなるにつれてattentionは特定contextへまとまり、最終的には少数のcritical tokenやmassive activation / attention sinkへ強く集中する。

つまりTransformer内部では、

```text
wide distributed context
        ↓
context-level concentration
        ↓
few critical tokens
```

という情報集約が生じる。

このlayer-wise sparsity differenceがPyramidKVの根拠。

## Layer-wise KV budget

全layerへ同じcache sizeを割り当てるのではなく、layer depthに応じてbudgetを減らす。

概念的には、

```text
lower layers : large KV budget
middle layers: medium KV budget
upper layers : small KV budget
```

というpyramid形状になる。

重要なのは単純に総KV数を減らすだけではなく、**同じtotal budgetでもlayerごとの配分を変える**点。

## Token selection

各layer内部ではattention importanceに基づいて保持tokenを選ぶ。

prompt末尾のobservation windowを利用するSnapKV系のselectionと組み合わせ、current promptで重要と推定されるKVを残す。

したがってPyramidKVの主なinnovationはtoken scoringそのものより、

> **layer-wise non-uniform budget allocation**

にある。

model weightsのfine-tuningは不要。

## SnapKVとの差

[SnapKV](2024-snapkv.md)はprompt末尾のobservation windowから各attention headがgeneration時に参照しそうなtokenを推定し、重要KVを圧縮する。

PyramidKVはこの方向を継承しつつ、各layerへ同じbudgetを与えることをやめる。

| | SnapKV | PyramidKV |
|---|---|---|
| token importance | observation-window attention | attention-based |
| layer budget | uniform | pyramidal / non-uniform |
| lower layer | same budget | larger |
| upper layer | same budget | smaller |
| fine-tuning | 不要 | 不要 |

技術系譜は、

```text
H₂O / Scissorhands
    ↓ token importance
SnapKV
    ↓ prompt-aware token importance
PyramidKV
    ↓ layer-wise budget allocation
DynamicKV
```

と整理できる。

## H₂O / Keyformerとの差

[H₂O](2023-2306.14048-h2o.md)はcumulative attention Heavy Hittersを保持する。

[Keyformer](2024-2403.09054-keyformer.md)はeviction後のattention-score distribution shiftをGumbel regularizationで補正する。

これらは主に**layer内部でどのtokenを残すか**を改善する。

PyramidKVはそれと直交し、

> **各layerへ何token分のcacheを与えるか**

を扱う。

したがってlayer-wise allocationとより高度なtoken scoringを組み合わせる余地がある。

## Position handling

KVを圧縮しても、保持tokenは元prompt上のposition semanticsを維持する。

残ったtokenだけを新しい連続positionへ詰め直すのではない。

これは[Keyformer](2024-2403.09054-keyformer.md)のposition ablationとも整合し、同一prompt内でtokenをevictするcompressionではoriginal positionを維持することが重要。

reuseでdocumentを異なるglobal positionへ移動させるre-RoPE問題とは異なり、PyramidKVではtoken自体の元位置を変更しない。

## Experiment Setup

LongBenchとNeedle-in-a-Haystackを中心に評価する。

modelにはLlama系、Mistral系、Llama-3-70B等を用いる。

baselinesには、

- Full KV
- StreamingLLM
- H₂O
- SnapKV

等を含む。

同じtotal KV budgetでuniform allocationとPyramidKV allocationを比較し、極端に小さいcache budgetでもlong-context understandingを維持できるか評価する。

## Main Results

### LongBench

**full KV cacheの12%だけを保持してfull-cache modelと同程度のperformance**を報告する。

さらにmemory-constrained settingでは、わずか**0.7%のKV cache**しか保持しない条件でも既存compression法を上回る。

TRECでは極端なcompression下で最大**+20.5 absolute accuracy**の改善を報告する。

### Needle-in-a-Haystack

Llama-3-70B-Instructでは、layerあたりわずか**128 KV entries**を残す設定でも100% accuracyを達成し、full KVと一致する。

long-range retrieval informationをupper layerで大きく圧縮しても保持できることを示す。

## Ablation / Analysis

### Uniform vs pyramidal allocation

同じtotal KV budgetでも、全layerへ均等配分するよりlower layerへ多く、upper layerへ少なく割り当てる方が高精度。

compression ratioが高いほどallocation strategyの差が大きくなる。

### Layer-wise attention concentration

attention visualizationではlayer depthとともにattention targetが少数context/tokenへ集約される。

この観察が単なるmemory heuristicではなく、model内部information flowに対応していることを示す。

### Extreme compression

moderate budgetでは複数compression法がfull KVに近いが、budgetを64/128 token程度まで削るとuniform methodが急激に崩れ、PyramidKVとの差が拡大する。

## Serving上の意味

layerごとにKV cache lengthが異なるため、serving engineでは全layer共通のblock tableを前提にしにくい。

PagedAttention系へ統合する場合、

- layer-specific block table
- layer-specific allocation/free
- heterogeneous KV capacity

が必要になる。

一方、upper layerのKV read量も減るため、適切にkernel/runtimeへ統合できればcapacityだけでなくdecode memory bandwidthも削減可能。

## DynamicKVへの技術系譜

PyramidKVはlayer depthに基づくstaticなpyramid allocationを導入した。

しかしtask/inputによってattention concentration patternが異なる可能性がある。

後続のDynamicKVはこの問題をさらに進め、runtime observationに応じてlayer-wise budgetを動的に調整する。

```text
Uniform layer budget
       ↓
PyramidKV
static layer-adaptive budget
       ↓
DynamicKV
input-adaptive layer budget
```

という流れで理解できる。

## Limitations

1. pyramidal attention patternが全model/task/inputで同じ強さとは限らない。
2. layer-wise heterogeneous KV sizeはserving engineのmemory managementを複雑にする。
3. token evictionは不可逆であり、generation後半でimportanceが変化したtokenを復元できない。
4. main evaluationはaccuracy/memory efficiency中心で、production servingでのend-to-end throughput評価は限定的。
5. layer allocation ruleはmodel architectureやlayer数に応じた調整余地がある。

## KV-cache taxonomyでの位置づけ

**compress / token selection / layer-wise non-uniform budget / attention-based / training-free**。

PyramidKVの重要性はtoken scoringを新しくしたことより、

> **KV cache compressionにlayer axisを導入した**

点にある。

既登録compression系を整理すると、

| Method | 主なcompression axis |
|---|---|
| [Scissorhands](2023-2305.17118-scissorhands.md) | historical token importance |
| [H₂O](2023-2306.14048-h2o.md) | Heavy-Hitter token |
| [StreamingLLM](2023-2309.17453-streamingllm.md) | sink + recent token |
| [Keyformer](2024-2403.09054-keyformer.md) | distribution-aware token importance |
| [SnapKV](2024-snapkv.md) | prompt-aware/head-wise token importance |
| PyramidKV | **layer budget + token importance** |

## まとめ

PyramidKVはlong-context Transformer内部でinformationがlayerを進むほど少数tokenへ集約されるPyramidal Information Funnelingを利用し、layerごとのKV budgetを非均一にする。

中心的な発見は、

- lower layerはdistributed informationを保持するためlarge cache
- upper layerはattentionが集中するためsmall cache

でよいということ。

full KVの12%で同等performance、0.7%という極端な圧縮でも既存法を上回り、Llama-3-70Bではlayer当たり128 KV entriesでNeedle-in-a-Haystack 100% accuracyを報告する。

SnapKVまでの「どのtokenを残すか」という研究軸に対して、**どのlayerへどれだけcacheを配るか**という新しいaxisを加え、後続DynamicKVへつながる重要なhistorical development。
