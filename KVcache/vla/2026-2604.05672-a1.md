# A1 — Adaptive truncated VLA

## 概要・問題設定
VLA推論は巨大VLM backboneと複数stepのflow-matching action headという二つのコストを持つ。backboneだけearly exitしても、各候補層で完全なdenoisingを実行するとaction headの計算が支配的になり、FLOPs削減がwall-clock latency短縮に結び付かない。A1はこの不一致を中心課題とする。Molmo由来のVLMと、flow-matching（FM）またはMLP action headを組み合わせ、action chunkを出力する。

## 先行研究との差
- [VLA-Cache](2025-2502.02175-vla-cache.md) / [DySta](2026-2602.03983-dysta.md): 連続観測間のvisual KV再利用を主眼とする。A1は**同一観測内のVLM層深度とFM反復数**を削減する。
- [EfficientVLA](2025-2506.10100-efficientvla.md): 中間特徴やlayerの削減に対し、A1はaction一致判定と層間warm-startを一体化。
- [FASTER](2026-2603.19199-faster.md): action開始の時間短縮・非同期化に対し、A1は実行する計算自体を減らす。両者の直接比較はない。
- [MEM](2026-2603.03596-mem.md): 外部・長期記憶を持つ手法ではない。LIBERO-Longは長期episodic memoryの性能検証と同義ではない。

## Method
### Multi-exit training
中間VLM layerごとに共有action headを接続し、複数の深さからactionを教師あり学習する。推論では隣接層のaction予測の差が、訓練データから定めた閾値以下ならearly exitする。閾値パラメータ`c`が小さいほど積極的に途中終了する。

### Inter-Layer Truncated Flow Matching
通常のFMでは1回の推論に10 step程度のdenoisingを行う。early-exitの各候補層でこれを繰り返すと、VLMを短縮してもFMコストが増える。そこで各層のdenoisingを少数step（実験ではδ=2）に切り詰め、次層の初期値に前層の予測を渡す（warm-start）。同一stepのランダム初期化と比較して、層間で収束を引き継ぐことが本質。

## Experiment Setup
LIBERO（Spatial/Object/Goal/Long）、VLABench、RoboChallenge、実機Franka/AgiBot等。Molmo初期化のVLM、FM headとMLP headを評価。pretrainingは公開ロボットデータと自社軌跡、AdamW、200K steps、batch 1024。LIBERO fine-tuningは50K steps、batch 128。GPU memory、action control frequencyの同一条件での詳細比較は未確認。推論時間は表の**per-episode model inference time**であり、単一actionのlatencyではない。

## Main Results
### LIBERO: FMの早期終了とwarm-start（論文Table 6）
| 構成 | 平均成功率 | TFLOPs/episode | 推論秒/episode |
|---|---:|---:|---:|
| Multi-exit学習、no exit、10 denoise | 96.0% | 229.8 | 37.8 |
| early exit c=1.0、10 denoise | 96.4% | 150.6 | **40.9** |
| early exit c=1.0、2 denoise、warm-startなし | 95.4% | 167.9 | 27.5 |
| early exit c=1.0、2 denoise、warm-startあり | **96.4%** | 156.8 | **10.5** |
| early exit c=0.8、2 denoise、warm-startあり | 94.6% | 116.8 | 9.0 |

重要なのは、**early exitだけでは37.8→40.9秒と遅くなる**点。warm-startを含む方式で37.8→10.5秒（72.3%短縮）となる。c=0.8ではさらに9.0秒だが成功率が94.6%へ低下。

### MLP head（Table 5）
Multi-exit学習、no exit: 96.5%、243 TFLOPs、17.5秒。c=0.7: 96.3%、148.1 TFLOPs、16.5秒。c=0.1: 92.3%、57.0 TFLOPs、5.6秒。MLPでもaccuracy/computeのtradeoffが明確。

### 外部ベンチ
RoboChallenge Table30平均29.00%、π0 28.33%、X-VLA 21.33%、RDT-1B 15.00%。ただしDM0 62.00%等のより高い方式も存在し、全方式で最高という意味ではない。LIBERO-Plusのzero-shot平均75.3%、OpenVLA-OFT 69.6%。これは**no-exit設定の評価**であり、early-exit高速化条件でのOOD性能を直接示すものではない。

## 主要Ablation
- Multi-exit学習自体で、FMのno-exit平均がfull-layer学習92.6%から96.0%へ変化する。加速効果と学習方式の違いを混同しない。
- FMでdenoise 10→2（warm-startなし）: 40.9→27.5秒だが96.4→95.4%。warm-start追加で10.5秒、96.4%へ戻る。
- MLPのcを下げるとFLOPsは大幅減少するが、成功率も低下。中間層exitの判断がtask依存である。

## Limitations
多段exit用の追加学習とaction headの調整が必要。FM推論時間はper-episode値で、実機制御周期・end-to-end sensor-to-action latencyの保証ではない。GPU VRAM、エネルギー消費、長時間のmemory retentionは主要比較で定量化されていない。early exitで生成したKVを将来フレームに再利用する設計ではなく、Transformer KV cache圧縮手法として評価すべきではない。PDFの直接取得は環境上失敗し、公式arXiv HTML全文とAppendixを確認した。

## Taxonomy・研究上の示唆
`KVcache/vla/` の **action-head / adaptive-compute / flow-matching inference**。KV reuseと独立な最適化軸。実装ではFLOPsよりもearly-exit判定に伴うaction headの反復実行がTTFAを支配し得る点を重視すべき。
