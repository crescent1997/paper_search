# ZipCache: Accurate and Efficient KV Cache Quantization with Salient Token Identification

## 概要
ZipCacheはKV tokenを捨てるevictionではなく、重要tokenを高precision、重要度の低いtokenを低precisionで保存する**saliency-aware mixed-precision KV quantization**。高圧縮率ではsalient tokenの誤判定がquality degradationへ直結するため、position biasを補正したattention-based saliencyとFlashAttentionを壊さずscoreを得るefficient probingを導入する。

## 問題設定
uniform low-bit quantizationは全tokenを同precisionで扱うがgenerationへの寄与はtokenごとに異なる。重要tokenまで強く量子化するとaccuracyが崩れ、全tokenを高precisionにするとcompression率が上がらない。importance-aware mixed precisionにはsalient tokenを正確かつ安価に見つける必要がある。

## Channel-separable token-wise quantization
KVをtoken単位で扱いつつquantization parameterのmetadata overheadを抑えるchannel-separableな構成を採る。fine-grained group quantizationではscale/zero-point自体のstorage costが無視できないため、実効compression ratioまで含めて設計する。

## Salient token identification
単純なcumulative attention scoreにはposition biasがある。prompt前方tokenは後続queryからattentionされる機会そのものが多い。ZipCacheはattentionを受ける機会で正規化したscoreを使い、token saliencyをより公平に推定する。

## Probe-based estimation
full attention matrixをmaterializeしてimportanceを測るとFlashAttentionのmemory-efficient性を失う。recent tokenとrandomly sampled tokenからなる少数probe queryだけについてattention scoreを取り、全queryのattentionを保存せずsaliencyを近似する。

## Mixed-precision policy
```text
probe attention → normalized saliency → salient/non-salient → high-bit/low-bit KV
```
evictionと異なり情報を完全には捨てないため、後から参照されるtokenも低精度ながら残る。

## KIVIとの差
[KIVI](2024-2402.02750-kivi.md)はKey/Valueのoutlier構造差を利用しKeyをper-channel、Valueをper-tokenで2-bit量子化する。ZipCacheは全KVを同一precisionにせず**token importanceに応じてprecisionを変える**。

| | KIVI | ZipCache |
|---|---|---|
| compression | low-bit quantization | mixed-precision |
| saliency | 基本的に使わない | attention-based |
| token eviction | なし | なし |
| position-bias correction | - | normalized score |
| importance取得 | - | probe-based |

## Experiment Setup
LLaMA/Mistral系modelでlanguage modeling、reasoning、long-context task等を評価し、accuracy/perplexityとmemory・latencyを既存KV quantization / importance-aware compressionと比較する。

## Main Results
Mistral-7B/GSM8Kでは約**4.98× KV cache compression**でaccuracy低下を**0.38%**に抑える。Llama-3-8B、4096-token inputではprefill latency約37.3%、decode latency約56.9%、GPU memory約19.8%削減を報告する。

## Ablation / Analysis
normalized attention scoreによりraw cumulative scoreのposition biasを抑え、probe tokenだけでも十分なsaliency rankingを得られることを分析。salient tokenへ高precisionを残すmixed precisionは、同等memory budgetのuniform quantizationよりqualityを維持しやすい。

## Runtime上の意味
quantizationはcapacityだけでなくdecode時のKV memory trafficを削減可能。ただしmixed precisionではbit-width別layout、dequantization kernel、saliency更新costが必要。probe方式はimportance取得のため巨大attention matrixを作ることを避ける。

## Limitations
- saliencyは過去/probe attentionからの推定で将来query変化を完全には予測できない。
- mixed-precision layoutとquant/dequant kernelが必要。
- 極低bitではsalient判定ミスの影響が大きい。
- end-to-end speedupはGPU、batch、kernel実装に依存。
- eviction系との併用ではtoken selectionとprecision allocationのjoint optimizationが課題。

## KV-cache taxonomyでの位置づけ
**compress / quantization / saliency-aware mixed precision / training-free**。eviction系の「何token残すか」に対しZipCacheは「各tokenを何bitで残すか」を扱う。
