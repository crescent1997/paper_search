# ChatInject: Abusing Chat Templates for Prompt Injection in LLM Agents

## 概要

ChatInjectは、LLM agentが外部tool outputを低信頼データとして受け取っていても、その内部にnative chat templateに似せたrole tagsを埋め込むことで、modelに偽のsystem / user / assistant messageとして解釈させるIndirect Prompt Injection (IPI) である。

攻撃の本質は単なる「ignore previous instructions」ではなく、modelがinstruction tuningで学習したrole hierarchyそのものをtool data内からspoofする点にある。さらにMulti-turn variantでは、一つのtool output内に複数turnの説得的dialogueを偽造し、one-shot injectionでありながらmulti-turn persuasionの効果を利用する。

## Threat Model

attackerはweb page、retrieved content、tool response等のexternal environment outputを制御できるが、agentのsystem promptやuser instructionそのものは変更できない。典型的なtrust relationは System / Developer > User > Tool / External Data であり、ChatInjectは最下位のTool / External Data領域へhigher-role syntaxを埋め込み、この境界を崩す。

### Attacker Access

- target model gradient: 不要
- logits: 不要
- hidden states: 不要
- model weights: 不要
- system prompt knowledge: 不要
- user instruction knowledge: 不要
- external/tool outputへのwrite access: 必要
- model-specific chat template: basic ChatInjectでは利用
- exact target template knowledge: Mixture-of-Templates (MoT)では不要

したがってGCG型white-box optimizationとは異なるblack-box structural attackである。

## Attack Primitive: Chat-Template Forgery

instruction-tuned modelはsystem / user / assistant等のstructured serializationを学習している。ChatInjectはtool output中のmalicious payloadをtarget modelのtemplateに似せてformatし、実際にはtool dataの一部でしかない文字列をhigher-role messageとしてmodelに強く解釈させる。

plain injectionが low-trust text + malicious semantics であるのに対し、ChatInjectは low-trust text + forged high-role structure + malicious semantics である。このためInstruction Hierarchy / Privilege Separation研究との関係が強い。

## Multi-turn Variant

Multi-turn variantは、一つのtool output内へ偽のconversation historyを埋め込む。例えば forged user がbenign prerequisite questionを提示し、forged assistantがsensitive actionの必要性を説明し、最後のforged userがmalicious actionを要求する。real agent interactionとしてはsingle injectionだが、modelから見ると複数turnのpersuasive contextに近いsignalを持つ。

## Persuasion

multi-turn dialogueはmalicious requestを突然提示するのではなく、authority / utility / justification等を段階的に形成する。ChatInjectはchat-template exploitationとpersuasionを組み合わせることで、単なるrole-tag injection以上のASRを得る。

## Mixture-of-Templates (MoT)

closed-source modelではexact native templateが不明である。そこで複数model familyのchat-template styleをpayloadへ混合し、targetのtemplateを正確に知らなくても学習済みrole cueのどれかが反応することを狙う。これはtemplate attackのblack-box applicabilityを高める。

## Transferability

model A向けchat templateで作成したpayloadがmodel Bでも機能し、closed-source modelにもtransferする。したがって脆弱性は特定token sequenceへの完全一致だけではなく、instruction-tuned LLMが共有するrole/message structureの学習に由来すると考えられる。

## Experiment Setup

主なbenchmarkはAgentDojoとInjecAgent。plain-text injection、ChatInject、Multi-turn variant等をfrontier/open/closed modelsで比較し、主にAttack Success Rate (ASR)を評価する。

## Main Results

- AgentDojo: plain injection 5.18% → ChatInject 32.05%
- InjecAgent: plain injection 15.13% → ChatInject 45.90%
- InjecAgent Multi-turn: average ASR 52.33%

chat-template structureを付加することでplain-text attackから大幅に成功率が上がる。

## Cross-model / Closed-model Results

ChatInjectはtarget-specific templateだけでなくcross-template transferを示す。またMoTによってunderlying model/templateが不明なsettingでも攻撃可能であり、closed APIだからtemplate-based attackを回避できるわけではない。

## Defense Evaluation

論文ではInstructional Prevention、Data Delimiter、User Instruction Repetition、Prompt Injection Detector、Lakera Guard等を評価する。既存Defenseは特にMulti-turn ChatInjectに対して十分なrobustnessを示さず、semantic injection detectorやdelimiterだけではrole structureを模倣したpayloadを完全にneutralizeできない。

## Template Perturbation

known role tagsを削除するrule-based sanitizerに対し、attackerはtemplate文字列をperturbできる。一定割合のtemplate perturbationでもattack effectivenessが残り、exact special-token string blacklistだけでは根本的Defenseにならない。

## GCGとの違い

[GCG](2023-2307.15043-gcg.md)はtarget model gradientを使ってadversarial suffix tokenを離散最適化する。一方ChatInjectはexternal tool contentへforged role/template structureを埋め込むpriority spoofingであり、target gradient/logit accessもiterative token optimizationも不要である。

GCGが「どんなtoken列ならalignmentを破れるか」を探索するのに対し、ChatInjectは「modelが既に信頼するmessage serializationを低信頼dataから再現する」。

## Faster-GCG / SlotGCGとの関係

[Faster-GCG](2024-2410.15362-faster-gcg.md)や[SlotGCG](2026-2606.05609-slotgcg.md)はoptimization efficiencyやattack positionを改善する。ChatInjectはtoken optimizationとは別系統であり、attack surfaceをrole serializationへ移す。将来的にはChatInject template内部のpayloadをGCGで最適化するhybrid attackも考えられる。

## Prompt Injection as Role Confusionとの関係

[Prompt Injection as Role Confusion](2026-2603.12277-prompt-injection-role-confusion.md)はprompt injection成功時にlow-trust textがmodel内部でtrusted roleに近いrepresentationを持つことを分析する。ChatInjectはその現象を直接狙う具体的Attackと解釈できる。

技術系譜としては ChatInject: forged role cues → role / priority spoofing attack、Role Confusion: hidden-state analysis → why low-trust content can acquire trusted-role behavior と整理できる。公開順ではChatInjectが先行し、Role Confusionがmechanistic explanationを与える関係である。

## Instruction Hierarchyとの関係

[The Instruction Hierarchy](../Defense/2024-2404.13208-instruction-hierarchy.md)はmessage sourceに応じたpriority followingをmodelへ学習させる。ChatInjectは、そのsource informationがserialization上spoof可能ならhierarchy trainingだけでは不十分になり得ることを示す。

semantic priorityだけでなくprovenance-authenticated priorityが必要という示唆が重要である。

## ISE型Defenseへの示唆

[Instructional Segment Embedding](../Defense/2024-2410.09102-instructional-segment-embedding.md)はtrusted segmentのsource informationをmodel内部embeddingとして与える。ChatInjectのようにtext内role tagを偽造するAttackに対しては、raw textではなくharnessが付与したunspoofable source metadataをmodelへ伝える方式が原理的に有利である。ただしmodelがtextual forged role cueをなお強く解釈する可能性は残るためadaptive evaluationが必要である。

## StruQ / SecAlign / Meta SecAlignとの関係

[StruQ](../Defense/2024-2402.06363-struq.md)、[SecAlign](../Defense/2024-2410.05451-secalign.md)、[Meta SecAlign](../Defense/2025-2507.02735-meta-secalign.md)はprompt / data separationを学習させる。ChatInjectはuntrusted data内にtrusted-message-like syntaxを作るため、このseparationのgeneralizationをstress testするAttackとして重要である。

## CaMeLとの関係

[CaMeL](../Defense/2025-2503.18813-defeating-prompt-injections-by-design-camel.md)はtextual role recognitionだけにauthorityを任せず、capability / provenanceをsystem architectureで管理する。そのためChatInjectは、model-only privilege inferenceよりprovenance-aware enforcementが必要であることを支持する例でもある。

## Adaptive Attackとの関係

[The Attacker Moves Second](2025-2510.09023-attacker-moves-second.md)や[PISmith](2026-2603.13026-pismith.md)はDefense-aware optimizationを行う。ChatInject自体はgradient/RLによるDefense-specific optimizationではないため、ChatInject structural spoofing + PISmith/adaptive optimizationはさらに強いstress testになり得る。

## Query / Compute Cost

GCGのような多数のgradient evaluationやcandidate suffix scoringは不要である。basic ChatInjectはpayload formatting中心で、targetへのiterative optimization queryを必須としない。MoTも複数templateをpayloadへ組み込む方式であり、target modelへ大量queryしてtemplateをreverse engineerする必要はない。

## JailbreakとPrompt Injectionの違い

ChatInjectは一般的なsafety jailbreakではなくIndirect Prompt Injectionである。jailbreakではuser自身がmodel policy/refusalを破ろうとするのに対し、ChatInjectではattacker-controlled external dataがagentへ別task/actionを実行させる。security boundaryはmodel-vs-userだけでなくuser intent vs untrusted environmentである。

## Limitations

- agent/tool pipelineへの依存がありpure standalone-model attackではない。
- chat-template serializationへ強く依存する。
- harnessがexternal dataをtoken-levelで強くisolateする場合はattack surfaceが縮小する。
- evaluated Defense setは将来のprovenance-aware Defenseを網羅しない。
- adaptive optimizationとの組み合わせは十分検証されていない。
- successful role spoofingが必ずunauthorized real-world actionにつながるわけではなくtool permission layerにも依存する。

## LLM Model Security Taxonomyでの位置づけ

Optimization-based: GCG / Faster-GCG / SlotGCG。Adaptive: Attacker Moves Second / PISmith。Role / priority spoofing: ChatInject。その後のmechanistic explanationとしてPrompt Injection as Role Confusionを置ける。

Instruction Hierarchyをrole serializationからspoofするAttackとして重要な位置を占める。

## 実装・研究上の示唆

Defense側ではexternal content内のrole-looking stringsを単にescapeするだけでなく、(1) source provenanceをtext tokenから分離、(2) untrusted segmentをarchitecture-levelに識別、(3) forged role tagsをprivilege signalとして扱わない、(4) cross-template / perturbed-template attackを評価、(5) adaptive attackerと組み合わせてstress test、が必要になる。

特にchat templateが「表示形式」ではなくsecurity-relevant interfaceになっていることを明示した点が重要である。
