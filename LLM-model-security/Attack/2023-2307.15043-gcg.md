# Universal and Transferable Adversarial Attacks on Aligned Language Models

## 概要

本論文は、aligned LLMに対するjailbreakを**離散token列のoptimization problem**として定式化し、Greedy Coordinate Gradient (GCG)によってadversarial suffixを自動生成する代表的研究である。

人手で「DAN」のようなjailbreak promptを設計する代わりに、harmful user requestの後ろへ付加するsuffixをgradientで最適化する。さらに複数prompt・複数white-box modelに対して同時最適化することで、得られたsuffixが未知promptだけでなくChatGPT等のblack-box modelにもtransferすることを示した。

本repositoryでは、GCGそのものはInstruction Hierarchy attackではないものの、[SecAlign](../Defense/2024-2410.05451-secalign.md)や[Meta SecAlign](../Defense/2025-2507.02735-meta-secalign.md)などのmodel-level defenseをstress-testするoptimization-based attackの技術的祖先として位置づける。

## 問題設定 / Threat Model

attackerはaligned LLMへ入力するuser promptを制御できる。元のharmful instructionを (x_{1:n})、追加するadversarial suffixを (x_{n+1:n+m}) とすると、攻撃目的はmodelがrefusalではなくattackerの望む肯定的な応答を開始するようsuffixを選ぶことである。

基本設定は**white-box**であり、target modelのweights、tokenizer、logits、token embeddingにアクセスし、lossのgradientを計算できる。

ただし最終的なtransfer experimentでは、white-box surrogate群で得たuniversal suffixをgradient accessのないblack-box modelへ入力する。

### JailbreakとPrompt Injectionの違い

GCG原論文の主対象はjailbreakである。

- GCG: user自身がuser-level promptへsuffixを付加し、safety alignmentを回避
- prompt injection: tool / external data等のlower-trust channelからhigher-priority instructionを上書き

したがってGCG自体はprivilege separationを直接モデル化しない。しかし「モデルが拒否するようtrainingされたbehaviorを、gradient-based discrete optimizationで逆転させる」というattack primitiveは、後続のprompt-injection defense評価にも転用されている。

## 先行研究からの改善点

従来のmanual jailbreakはattack designerの試行錯誤に依存し、modelやpromptごとに作り直す必要があった。AutoPrompt等のgradient-guided discrete prompt optimizationも存在したが、本論文はより強いcoordinate searchを導入し、aligned chat modelに対して高いattack successを実現する。

主な改善点は、

1. 全suffix coordinateについてgradientから有望tokenを抽出
2. candidate replacementを実際のforward lossで評価
3. 複数behaviorに共通するuniversal suffixへ拡張
4. 複数modelで同時最適化しtransferabilityを高める

ことである。

## Method / Algorithm

### Attack Objective

target responseの先頭に肯定的なprefix（例: "Sure, here is ..."）を生成させるtargeted objectiveを置き、そのtoken列のnegative log-likelihoodを最小化する。

[
mathcal{L}(x_{1:n+m}) =
-log p(x_{target}mid x_{1:n+m})
]

suffix tokenはdiscreteなので通常のgradient descentを直接適用できない。

### Greedy Coordinate Gradient

各suffix位置 (i) について現在tokenのone-hot表現に対するgradientを計算し、lossを減らす方向のtop-k tokenをcandidate setとする。

概略は、

1. 全coordinateのtoken gradientを計算
2. 各coordinateからtop-k replacement候補を得る
3. coordinateとreplacementを組み合わせたcandidate suffixをbatch生成
4. candidateをforwardして実lossを計算
5. 最小lossのreplacementを採用
6. 反復

となる。

AutoPrompt型の「先に更新coordinateを固定してからtokenを選ぶ」方法より、複数coordinateを横断してcandidateを比較できる。

### Universal Attack

単一prompt (x^{(j)}) だけでなく複数harmful behaviorについて共通suffix (p) を求める。

[
min_p sum_j mathcal L_j(x^{(j)} Vert p)
]

これにより特定promptへのoverfitを減らし、未知behaviorへのtransferを狙う。

### Multi-model Optimization

さらに複数white-box modelについてloss / gradientをaggregateしてsuffixを更新する。

[
min_p sum_{m}sum_j
mathcal L_{m,j}(x^{(j)} Vert p)
]

model-specific artifactではなく、複数aligned modelに共通するfailure modeを探索することでblack-box transferabilityを高める。

## Experiment Setup

評価には本論文で整備されたAdvBenchを利用する。

- Harmful Behaviors: 500 harmful instructions
- Harmful Strings: 500 target strings

white-box modelとしてVicunaやLlama-family等を使用し、個別attack、universal attack、multi-model transferを評価する。

attack successは、target stringの生成やrefusalを回避してharmful responseを生成できるかで測定する。

## Main Results

white-box Vicuna settingでは非常に高い成功率を示し、代表的にはharmful behaviorで99/100、exact harmful-string generationで88/100を成功させる。従来のAutoPromptと比べても大幅な改善である。

より重要なのはtransferabilityで、複数white-box model / behavior上で最適化したsuffixを、直接gradientを取得できないChatGPT、Bard、Claude等へ移しても一定のjailbreak成功が観測された。

これにより「adversarial suffixは単一modelのgradient artifact」という説明だけでは不十分で、aligned LLM間に共有された脆弱性が存在する可能性を示した。

## White-box / Black-box条件

### White-box optimization

suffix生成そのものには基本的に以下が必要である。

- model weights
- tokenizer
- logits
- token-level gradient

したがってclosed API modelを直接GCGでoptimizationすることはできない。

### Black-box transfer

一方、一度surrogate modelでsuffixを生成すれば、target APIに必要なのは通常のtext queryだけである。この段階ではgradient/logit accessは不要。

このwhite-box-to-black-box transferがGCGの実用上重要な性質である。

## Compute / Query Cost

GCGの弱点は高いoptimization costである。各iterationでgradient計算に加え、多数のcandidate suffixをforward評価する必要がある。

後続の[Faster-GCG](2024-2410.15362-faster-gcg.md)は、このcandidate evaluationが約256K evaluations / behavior規模になる点を問題視し、32K程度へ削減する。

つまりGCGはquery-efficient black-box attackではなく、**surrogate上で大きなwhite-box computeを使い、その成果物をtransferする**attackと理解するのが適切である。

## Transferability

transferabilityには二段階ある。

1. **behavior transfer**: 複数harmful promptで共通suffixを学習し、未知promptへtransfer
2. **model transfer**: 複数white-box modelで共通suffixを学習し、未知modelへtransfer

特にmulti-model optimizationがblack-box commercial modelへのtransferを改善する。

## Defenseとの関係

### StruQ

[StruQ](../Defense/2024-2402.06363-struq.md)はprompt/data channelを構造化するため、元GCGの「user prompt末尾へsuffix」というthreat modelとは異なる。ただしGCG型optimizerをuntrusted data channelへ適応させれば、model-level separationのadaptive stress testになる。

### SecAlign / Meta SecAlign

[SecAlign](../Defense/2024-2410.05451-secalign.md)はGCGを代表的optimization-based attackとして評価し、SFT型StruQより高いrobustnessを示す。

[Meta SecAlign](../Defense/2025-2507.02735-meta-secalign.md)でもwhite-box GCGが重要な評価となり、static benchmarkより大幅に高いASRが残る。

### Instruction Hierarchy

[The Instruction Hierarchy](../Defense/2024-2404.13208-instruction-hierarchy.md)はauthority-aware trainingを行うが、GCGはauthority sourceそのものをspoofするattackではない。hierarchy defenseを評価する場合は、GCG objectiveを「lower-priority instructionへ従わせる」形に変更したadaptive attackがより適切である。

### Adaptive Attack

[The Attacker Moves Second](2025-2510.09023-attacker-moves-second.md)は、GCGを固定設定で実行して失敗しただけではrobustness evidenceとして弱いと指摘し、defense-aware objective / optimizerへの適応を要求する。

## Limitations

- suffix optimizationにはwhite-box gradient accessと大きなcomputeが必要。
- 生成されるsuffixは不自然なtoken列になりやすく、perplexity/filteringで検出される可能性がある。
- commercial modelへのtransfer successはwhite-box successほど高くない。
- original objectiveはjailbreakであり、system/developer/user/toolのauthority graphを直接攻撃するものではない。
- attack success判定はrefusal heuristicやtarget prefixに依存する部分があり、semantic harmfulnessと完全には一致しない。

## LLM Model Security Taxonomyでの位置づけ

```text
Manual jailbreak
      ↓
AutoPrompt / gradient-guided prompting
      ↓
GCG
  discrete adversarial suffix
  + universal optimization
  + multi-model transfer
      ↓
Faster-GCG / SlotGCG / other GCG variants
      ↓
Defense-aware adaptive attacks
  SecAlign evaluation
  The Attacker Moves Second
```

## 実装・研究上の示唆

GCGの最大の意義は、LLM safetyを「既知jailbreak promptをblockできるか」ではなく、**adversarial optimizationに対してdecision boundaryがどの程度安定か**という問題へ変えた点にある。

Instruction Hierarchy研究でも、固定prompt-injection templateだけでなく、lower-trust instructionをoptimizerで探索するadaptive evaluationを導入する必要がある。
