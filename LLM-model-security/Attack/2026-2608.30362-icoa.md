# Will the User Ever Know? Covert Indirect Prompt Injection Attacks on Tool-Using LLM Agents

## 概要

ICoA (Induced Covert Attack) はtool-using LLM agentへのIndirect Prompt Injection (IPI)について、attack actionの実行だけでなく**ユーザーに攻撃成功が見えるか**を扱う。

従来ASRはmalicious actionが実行されたかだけを見る。しかし成功trajectoryには、最終回答で攻撃を報告するovert caseと、正常な回答だけを返すcovert caseがある。

そこでASRを

```text
ASR = CSR + OSR
```

と分解する。

- CSR: Covert Success Rate
- OSR: Overt Success Rate

## Threat Model

attackerはtool / external data等、lower-trust sourceへinstructionを埋め込める。

targetはReAct型tool-using agentで、attackerはmodel weights・gradient・logits・hidden statesを必要としない。

### Access

- white-box gradient: 不要
- target logits: 不要
- hidden state: 不要
- model weights: 不要
- tool/external observationへのinjection: 必要
- malicious goal/actionの指定: 必要

したがってGCGとは異なるblack-box in-context injectionである。

## Covert / Overt Success

同じmalicious tool actionが実行されても、trajectory終了位置でユーザーの認知可能性が変わる。

```text
Overt:
 user task
   -> injection
   -> malicious action
   -> final answer mentions attack

Covert:
 user task
   -> injection
   -> malicious action
   -> return to user task
   -> benign-looking final answer
```

ReAct agentのfinal answerが直近のtrajectoryを強く反映する性質を利用する。

## ICoA

ICoAはinjected instructionをfollow-up taskのようにframingし、malicious action後にoriginal user taskへ制御を返すRETURN anchorを配置する。

攻撃primitiveはadversarial token optimizationではなく**control-flow steering**である。

### RETURN Anchor

malicious action完了後、

```text
return to the original user's task
```

に相当する指示を置き、agentにbenign taskを再開させる。

これにより最終回答からmalicious actionの痕跡を消しやすくする。

## Experiment Setup

AgentDojoを用い、4 target modelsで既存IPI attackと比較する。

評価は通常ASRに加えCSR / OSRを報告する。さらにRETURN anchorを既存attackへ追加するablationを行う。

## Main Results

ICoAは4 target modelsすべてで最高CSRを示し、strongest baselineより3.79–12.01 percentage points改善する。

RETURN anchorだけを既存attackへ追加する場合でもCSRが最大23.71 points上昇し、covert behaviorが特定prompt templateだけの効果ではなくpost-attack trajectory controlに強く依存することを示す。

## Defense Evaluation

複数Defense settingsでもICoAのcovert successを評価する。

重要なのはDefenseを「malicious actionを止めたか」だけでなく、**成功したattackをユーザーが認識可能だったか**でも評価すべきという点である。

## GCGとの違い

[GCG](2023-2307.15043-gcg.md)はwhite-box gradientからadversarial suffixを離散最適化する。

```text
GCG:
 gradient -> adversarial suffix
 target: model alignment / refusal

ICoA:
 black-box injected instruction
 -> malicious tool action
 -> RETURN to benign task
 target: agent control flow + user observability
```

ICoAはoptimization-based jailbreakではなくtool-mediated prompt injectionである。

## PISmith / Adaptive Attackとの関係

[PISmith](2026-2603.13026-pismith.md)はtarget responseをrewardとしてattack LLMをRL最適化するblack-box adaptive red teamingである。

ICoAはattack promptをDefenseごとにRL最適化するのではなく、covert successを生むtrajectory structureを設計する。

両者を組み合わせ、CSRをrewardにPISmith型optimizationを行う方向が考えられる。

## Instruction Hierarchyとの関係

[The Instruction Hierarchy](../Defense/2024-2404.13208-instruction-hierarchy.md)の観点では、tool / external dataはuserより低いtrust levelである。

ICoA成功は

```text
User > Tool
```

というpriority relationが破られた結果である。

ただし攻撃のcovert化にはmodel内部のpriority failureだけでなくReAct harness / trajectory formattingも寄与するため、pure model-level attackではない。

## StruQ / SecAlign / Meta SecAlign

[StruQ](../Defense/2024-2402.06363-struq.md)、[SecAlign](../Defense/2024-2410.05451-secalign.md)、[Meta SecAlign](../Defense/2025-2507.02735-meta-secalign.md)はtrusted promptとuntrusted dataの分離をmodelへ学習させる。

これらがinjection自体を拒否できればICoAも失敗する。一方、injectionが一度成功した後のcovert / overt distinctionは従来ASRでは捉えられない。

## CaMeLとの関係

[CaMeL](../Defense/2025-2503.18813-defeating-prompt-injections-by-design-camel.md)のようなcapability-based system Defenseはuntrusted computationからunauthorized tool actionを構造的に防ぐため、ICoAの前提となるmalicious action自体を阻止する方向である。

## Limitations

- ReAct-style trajectoryへの依存が強い。
- tool-using agent / harness固有の要素を含み、pure model vulnerabilityではない。
- RETURN anchorが常に自然に機能するとは限らない。
- covert successは最終回答以外のaudit logでは検出可能。
- target-specific adaptive optimizationではない。
- CSRはattack impactそのものではなくuser observabilityを追加評価するmetricである。

## Taxonomy

```text
Model-level adversarial suffix:
 GCG / Faster-GCG

Adaptive prompt injection:
 Attacker Moves Second / PISmith

Tool-mediated control-flow attack:
 ICoA
   -> malicious action
   -> covert return
```

## 実装・研究上の示唆

Agent DefenseではASRだけでなく、

1. unauthorized action
2. final-response disclosure
3. trajectory / audit-log evidence
4. user-visible alert

を別metricとして評価すべきである。

特にattack成功後のtrajectoryをDefense evaluationから切り捨てると、covert attackを過小評価する。
