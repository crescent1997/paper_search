# Towards Economical Inference: Enabling DeepSeek’s Multi-Head Latent Attention in Any Transformer-based LLMs

> DeepSeek系のMulti-head Latent Attentionを、最初からpretrainし直さず既存Llama等へ移植する方法を扱う。KV cache architectureの変更をdata-efficient fine-tuningで実現するbridge研究。

## 概要

standard Multi-Head Attentionでは、各KV headについて過去tokenのK/V vectorをそのままcacheする。

context lengthが増えるほどcache memoryとHBM trafficが増える。

MQA / GQAはKV head数を減らしてこの問題を緩和するが、K/V representationの自由度も下げる。

DeepSeek-V2で導入されたMulti-head Latent Attention、MLAは、K/Vを直接cacheする代わりに低次元latent representationをcacheする。

attention時にはlatentから必要なK/V representationを復元・変換して使う。

これによりKV cacheを大幅に削減できる。

問題は、既に学習済みのMHA modelをMLAへ単純に置換すると性能が大きく崩れること。

MHA2MLAはこのarchitecture conversionを、pretrained parametersを最大限再利用しながら少量の追加dataで行う。

## なぜMHA→MLA変換が難しいか

MLAではK/V projectionをlow-rank factorizationする。

概念的には、

hidden state
→ low-dimensional latent c_KV
→ key/value representation

という構造。

MHAで学習されたW_K, W_Vを単純にlow-rank近似すると、attention distributionやvalue representationがずれる。

さらにRoPEがKの全dimensionへ適用されていると、position-dependent rotationをlow-rank latentへ吸収しづらい。

つまり問題は2つ。

1. positional encodingとlow-rank compressionの干渉
2. K/V projectionをどのようにlatent factorizationへ初期化するか

MHA2MLAはそれぞれpartial-RoPEとjoint SVDで解く。

## MLAの基本構造

MLAではhidden state hから低次元latent c_KVを生成する。

c_KV = W_DKV h

その後、latentから各headで利用するK/V componentを復元する。

K = W_UK c_KV
V = W_UV c_KV

cacheするのはfull K/Vではなくc_KV。

latent dimension d_KVが元K/V総dimensionより大幅に小さければcacheも小さくなる。

## RoPEが低rank化を難しくする理由

RoPEはquery / keyのdimension pairへposition-dependent rotationをかける。

全Key dimensionへRoPEが適用されると、K projectionがpositionと絡んだ形で利用される。

その結果、K/Vを同一low-rank latentへまとめる際に、position-independentなfactorizationが難しくなる。

DeepSeek MLAではRoPEを適用するsmall componentとlatent-compressible componentを分ける設計を使う。

MHA2MLAは既存MHAでもこれに近いpartial-RoPEへ変換する。

## Partial-RoPE

全Q/K dimensionへRoPEを残すのではなく、一部dimensionだけにRoPEを適用する。

問題はどのdimensionを残すか。

MHA2MLAでは各dimensionがattention scoreへどの程度寄与しているかを分析し、寄与の小さいdimensionからRoPEを外す。

つまり一律に前半 / 後半dimensionを切るのではなく、pretrained modelのQK statisticsを利用して選ぶ。

codeでは2-norm等のselection policyも用意されている。

RoPEを残すdimensionはposition-sensitive componentとして保持し、外したdimensionをlow-rank latent compressionへ回しやすくする。

## なぜPartial-RoPEが必要か

単純にRoPEを全部残したままMLA化すると、latent projectionとrotationをうまくfactorizeできず性能低下が大きい。

逆にRoPEを全部外すとposition modelingが壊れる。

partial-RoPEは、

- position情報に必要なdimension
- compressible content dimension

を分離する妥協点。

## Joint SVD

次の問題はpretrained W_K / W_Vからlow-rank MLA projectionをどう初期化するか。

naiveにはKとVを別々にSVDできる。

しかしMLAはK/Vでshared latent c_KVを使う。

別々にlow-rank化するとdown projectionが分かれ、MLAのshared latent structureを十分活かせない。

MHA2MLAはK/V projectionをjointに扱い、共有down projectionを持つlow-rank factorizationを作る。

概念的にはKとVのprojection情報を結合し、joint SVDでcommon subspaceを見つける。

これによりpretrained K/V両方の主要方向を同じlatentへ保存する。

## Split SVDとの違い

split SVDでは、

K → down_K → up_K
V → down_V → up_V

と別latentになる。

joint SVDでは、

hidden → shared down_KV → latent
latent → up_K
latent → up_V

となる。

MLA本来のcache reductionはshared latentを1つ保存することから生まれるため、joint initializationの方がarchitectureに合う。

## Conversion Pipeline

全体の変換は次のように整理できる。

1. pretrained MHA / GQA modelを読み込む
2. Q/K attention statisticsを収集
3. attention score寄与の小さいdimensionからRoPEを除去
4. K/V projectionへjoint SVD
5. shared low-rank latent projectionを初期化
6. MLA moduleへ置換
7. 少量のcontinued training / fine-tuningでperformance recovery

zeroからMLA pretrainingするより大幅に安い。

## Data-efficient Fine-tuning

論文の重要な主張は、architectureを大きく変えても元pretraining dataの0.6〜1%程度の追加dataで性能を回復できること。

これはSVD initializationがpretrained representationをかなり保持し、fine-tuningが完全な再学習ではなくconversion errorの補正として機能するため。

## Experiment Setup

Llama2-7Bを中心に、SmolLM系列など異なるmodel sizeでも検証する。

compression rank d_KVを複数設定し、cache reductionとperformance trade-offを調べる。

評価にはlanguage modeling / common benchmarkに加え、long-context capabilityを見るLongBenchを用いる。

baselineには、

- original MHA
- GQA conversion
- naive low-rank / split SVD
- MLA from scratchまたは弱いinitialization
- partial-RoPE ablation

等を置く。

## Llama2-7Bの代表結果

Llama2-7BではKV cache sizeを92.19%削減しながら、LongBench performance低下を約1%に抑える設定を報告する。

これは、GQAよりもさらに強いcache reductionをpretrained MHA modelへ後付けできることを示す。

## Compression RankのTrade-off

latent rankを小さくするとcacheは小さくなるがinformation bottleneckが強くなる。

rankを大きくするとoriginal MHAに近いqualityへ戻りやすいがmemory削減率は下がる。

repositoryではLlama2-7Bについてd_KV 16 / 32 / 64 / 256等のcheckpointを公開しており、trade-offを選べる。

## Partial-RoPE Ablation

RoPE dimensionをどう選ぶかでperformanceが変わる。

attention scoreへの寄与を考慮せずuniformに外すより、Q/K projection statisticsを利用して重要dimensionを残す方が安定する。

このablationは「MLA conversionは単なるSVD compressionではなく、position encoding structureの再設計が必要」なことを示す。

## Joint SVD Ablation

K/Vを別々にSVDするsplit initializationより、shared latentを直接意識したjoint SVDがperformance recoveryに有利。

これはMLAのdown projectionがK/V共通であることと整合する。

pretrained weightをarchitecture semanticsに合わせてfactorizationすることが重要。

## GQAとの違い

GQAでは複数query headが同じKV headを共有する。

例えば32 Q headsに対して8 KV headsならcacheはMHAの1/4。

MLAではhead sharingではなく、K/V情報を低次元latent vectorへ圧縮する。

そのためhead数というdiscreteな圧縮だけでなくlatent rankをcontinuousに調整できる。

## DeepSeek-V2 MLAとの関係

この論文はMLAそのものを提案した研究ではない。

DeepSeek-V2のMLAを、既存well-trained MHA/GQA modelへ移植する方法が主題。

したがってtaxonomyでは「MLA architecture」だけでなく「architecture conversion / retrofit」として重要。

新modelをpretrainできない場合でもMLA benefitを使える可能性を示す。

## YOCOとの違い

[YOCO](2024-2405.05254-yoco.md)はlayer方向にKV duplicationを削る。

MHA2MLAは各layer内のrepresentation dimensionをlatent化する。

整理すると、

- YOCO: cacheするlayer数を減らす
- MLA: 1 token / 1 layer当たりのcache dimensionを減らす

。

原理上は両方を組み合わせる余地がある。

## KIVIとの関係

[KIVI](../compress/2024-2402.02750-kivi.md)はcache elementを2-bit化する。

MLAはcache element数をlow-rank latentで減らす。

論文はKV quantizationとの併用可能性も強調する。

つまり、

MHA → MLA latent compression → low-bit quantization

という積み重ねが可能。

## Inference Implementation上の注意

MLAはcacheが小さくなるだけでなくattention kernelも変わる。

latent representationをそのまま効率良く使うにはFlashMLA等に近いkernel supportが望ましい。

naive PyTorchでup-projectionしてfull K/Vを毎step materializeするとmemory bandwidth advantageを十分活かせない場合がある。

したがってarchitecture conversionのbenefitをsystem上で得るにはkernel integrationも重要。

## Limitations

- tuning-freeではなく0.6〜1%程度の追加training dataが必要。
- rankを小さくしすぎるとperformance degradationが大きくなる。
- partial-RoPEのdimension selectionがmodel依存。
- MLA-aware attention kernelがないと理論cache削減がlatencyへ十分反映されない可能性。
- original MHA internal behaviorとは変わるため、conversion後のrobustnessを幅広く再評価する必要がある。

## KV-cache taxonomyでの位置づけ

MHA2MLAはmodelカテゴリのlatent-representation compression / architecture retrofit。

model-level削減は、

- MQA/GQA: KV head sharing
- MLA: low-rank latent cache
- YOCO: cross-layer cache sharing

の3系統に分けると理解しやすい。

MHA2MLAはその中でも「既存modelをMLAへ移行する方法」。

## 研究上の重要な示唆

この研究の重要点は、KV-efficient architectureは必ずしもpretraining from scratchを必要としないこと。

pretrained weightのsubspace structureを使えば、大きなarchitecture変更でも少量trainingでadaptできる。

また、RoPEとlow-rank compressionが独立ではなく、position encoding designがcache compression可能性へ直接影響することを示している。

## まとめ

MHA2MLAは、

1. pretrained MHA/GQA modelを出発点にする
2. attention score寄与の小さいdimensionからRoPEを外す
3. K/V projectionへjoint SVDを適用
4. shared low-rank latent cacheを構築
5. 0.6〜1%程度の追加dataでfine-tune
6. MLAとしてinference

する。

Llama2-7BではKV cacheを92.19%削減し、LongBench低下を約1%に抑える。MLAを新規pretraining専用のarchitectureから、既存modelへretrofit可能なKV-efficient architectureへ広げた点が大きな貢献。
