# CacheBlend: Fast Large Language Model Serving for RAG with Cached Knowledge Fusion

> exact-prefix cachingを、RAGのような**任意順序の複数chunk reuse**へ拡張する代表的研究。単純KV concatenationのaccuracy lossを、重要tokenだけ再計算して修復する。

## 問題設定

通常のprefix cachingでは、同じprefixなら各tokenが見てきたcausal historyも同じなのでKVを安全にreuseできる。一方RAGでdocument Bを単独prefillして保存したKVを、実requestでdocument Aの後ろへ置くと、B内tokenは本来Aにもattentionすべきなのにcached KVはAを知らない。

したがって単純連結ではfull prefillと内部状態が異なる。

## 先行研究からの改善点

- full recomputation: 正確だがTTFTが長い。
- prefix caching: 正確だがreuse位置がprefixに限定される。
- independent chunk KV concatenation: 高速だがcross-chunk dependencyを失いaccuracyが低下する。

CacheBlendは「全部を再計算する必要はなく、cross-attention不足の影響が大きいtokenだけ直せばよい」という設計。

## Method

### 1. Offline / reusable KV

document chunkごとにKV cacheを事前計算・保存する。request時にはretrieved documentsに対応するKVをstorageから読み出す。

### 2. KV fusion

各chunk KVをrequest内の順序へ配置する。ただしこの時点ではpreceding chunksを見ていないためfull prefillとは一致しない。

### 3. Selective token recomputation

layerごとに、cached executionとfull-context interactionの差が大きくなりそうなtokenをattention-based importanceで選び、そのsubsetについてQ/K/Vおよび後段stateを再計算する。重要tokenを再計算することで、そのtokenを介してcross-document informationをcacheへ取り戻す。

### 4. Pipelining with KV loading

全tokenをGPUでprefillしないためrecompute compute量は小さい。さらにKV cacheのSSD / CPU→GPU transferとrecomputationをoverlapさせ、遅い大容量storageを使ってもcritical path増加を抑える。

## Experiment Setup

3種類のopen-source LLM、4種類のbenchmark taskを使い、full recompute、prefix-oriented reuse、単純reuse等と比較。generation qualityに加えてTTFTとserving throughputを評価する。

## Main Results

full KV recomputationと同等のgeneration qualityを維持しつつ、TTFTを約2.2〜3.3×短縮、throughputを約2.8〜5×改善すると報告する。

## Limitations / 成立条件

- selective recomputation率が低すぎるとfull prefillとの差が残る。
- document境界、position encoding、special token、chunk order等の実装差に敏感。
- cached KV storage capacity / transfer bandwidthという新しいresource trade-offが生まれる。
- model architectureやattention implementationによって重要token選択の最適形が変わる。

## KV-cache taxonomyでの位置づけ

CacheBlendは**non-prefix KV reuse + partial repair**。EPICがposition-independent representation / attention sink correctionを主軸にするのに対し、CacheBlendは「既存cached KVをどこまで再計算すればfull-context qualityへ戻せるか」を主問題にする。

## 実装・研究上の示唆

reuseの正しさはtoken positionだけでなく、各layerで過去contextがhidden stateへどう混ざったかに依存する。したがってRoPEだけを付け替えるre-positioningでは一般にfull prefillと一致しない。RAG cache reuseの評価では、TTFTだけでなくfull recomputeとの差分をtask accuracy / logits / layer-wise KVで確認する必要がある。
