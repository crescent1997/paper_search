# Block-Attention for Efficient Prefilling

> RAG documentをblock単位で独立にencodeし、そのKVを再利用できるようにするため、attention構造そのものとfine-tuningを組み合わせる。CacheBlendやEPICのようなinference-time repairとは異なり、**reuse-friendlyな挙動をモデルへ学習させる**点が重要。

## 概要

RAGでは複数retrieved passagesを長いcontextとして連結するためprefill costが大きい。通常のcausal self-attentionでは、後ろのpassageほど前に置かれたpassageへattentionするため、各passageのKVはrequest内の位置・前文脈に依存する。

Block-Attentionはretrieved passageごとにblockへ分割し、最終blockを除く各blockを独立に処理できるattention patternへ変更する。これにより、同じpassageが別requestで再登場した場合、そのblock KVを再利用できる。

## 先行研究からの改善点

standard prefix cachingはprompt先頭が完全一致した場合しかreuseできない。単純なdocument-wise KV concatenationではcross-document attentionを失いaccuracyが落ちる。

Block-Attentionはこの問題に対して、

- block segmentation
- position re-encoding
- block-attention-aware fine-tuning

を組み合わせ、モデル自体を「独立block KVを連結して使う」前提へ適応させる。

## Method

### 1. Block segmentation

RAGでは各retrieved passageを1 blockとして扱う。各block内では通常どおりcausal attentionを行うが、block間attentionを制限することで、それぞれのKVを前blockに依存せず計算できるようにする。

### 2. Independent KV computation

最終block以外は独立にK/Vを計算できるため、documentごとのKVをofflineまたは初回利用時に保存可能になる。request時にはretrieved passagesに対応するcached blocksを読み出して連結する。

### 3. Position re-encoding

独立計算時と実request内ではblockのabsolute / rotary positionが異なるため、再利用時にposition情報を補正する。単なるbyte-level cache reuseではなく、global sequence positionへ合わせる処理が必要となる。

### 4. Block fine-tuning

attention maskを変更するだけではfull-attention pretrained modelの挙動とずれる。そこでblock-attention patternを使ってfine-tuningし、cross-block attentionが制限された状態でもtask performanceを維持できるようにモデルを適応させる。

論文では、fine-tuned modelがblock attentionとfull attentionを切り替えて利用できる点も評価している。

## Experiment Setup

RAG、in-context learning、general-domainを含む11 benchmarkで評価し、full-attention modelとのaccuracy比較に加えてTTFTとFLOPsを測定する。

## Main Results

block fine-tuning後はfull-attention modelに近いperformanceを維持しつつ、32K inputでfirst tokenまで約45 msを報告する。full attentionと比べてTTFTを98.7%、対応するFLOPsを99.8%削減したとしている。

また、block-attention fine-tuned modelはblock modeとfull-attention modeを切り替えて利用でき、full-attention側へ戻した際にも大きなperformance lossがないと報告される。

## CacheBlend / EPICとの違い

CacheBlendはpretrained modelを基本的に維持し、reuseしたKVの誤差をselective recomputationで推論時に修復する。

EPICも既存modelでposition-independent reuseを成立させるため、LegoLink等の軽量なlinking処理を推論時に導入する。

一方Block-Attentionは、**独立blockとして計算されたKVを利用する挙動そのものをfine-tuningで学習させる**。そのためtraining costは必要だが、推論時のrepairを非常に小さくできる可能性がある。

## Limitations

- pretrained modelへそのまま適用するtuning-free手法ではなく、block-aware fine-tuningが必要。
- block間attentionを制限するため、document間のdense interactionが重要なtaskではfull attentionとの差が出る可能性がある。
- block boundary設計やposition re-encodingの実装がqualityへ影響する。
- cached blockとquery / final blockのinteractionをどの程度残すかがtask依存。

## KV-cache taxonomyでの位置づけ

reuse categoryの中でも **training-adapted reuse / reuse-aware fine-tuning** に分類できる。

reuse系は今後、
1. inference-time repair — CacheBlend
2. position-independent linking — EPIC
3. reuse-aware fine-tuning — Block-Attention / KVLink系
のようにsubclass化すると整理しやすい。

## 実装・研究上の示唆

KV reuseでfull prefillとの差を埋める方法は、推論時のrecomputationだけではない。training段階で「documentごとの独立KV」を前提にmodelを適応させることで、必要なrepair量を下げられる可能性がある。

特に長contextでは、fine-tuningとselective recomputationを組み合わせるhybrid設計も重要な研究方向になる。
