# Fine-Grained Privacy Extraction from Retrieval-Augmented Generation Systems via Knowledge Asymmetry Exploitation

> RAGからprivate informationを含むresponseを引き出すだけでなく、**response中のどのsentenceがprivate knowledge base由来なのか**を、target RAGとstandard LLMのknowledge差を利用してblack-boxで識別する。

## 概要

RAGでは、生成結果にretrieved knowledgeとLLM自身のparametric knowledgeが混在する。そのため、従来のprivacy extraction attackでsensitive-looking responseを得られても、その情報が本当にprivate retrieval databaseから来たのか、LLMが元々知っていたのかを区別しにくい。

本論文はこの問題を**fine-grained privacy extraction**として定式化する。攻撃者は同一または対応するqueryをtarget RAGと通常のstandard LLMへ入力し、両者のresponse差を利用する。RAGだけがprivate external knowledgeへアクセスできるという **knowledge asymmetry** がprivacy signalになる。

既存のRAG privacy attackである [The Good and The Bad](2024-2402.16893-the-good-and-the-bad.md) や [Follow My Instruction and Spill the Beans](2024-2402.17840-follow-my-instruction-and-spill-the-beans.md) は、private retrieval databaseやretrieved contextから情報が漏れること自体を示した重要な先行研究である。一方、本論文はresponse全体を漏洩とみなすのではなく、**個々のsentenceをKB-derived / non-KB-derivedに分離する**方向へ問題を細粒度化している。

## 問題設定 / Threat Model

攻撃対象はprivate knowledge baseを持つblack-box RAG systemである。攻撃者は通常ユーザと同じquery interfaceからRAGへアクセスできるが、以下にはアクセスできない。

- private corpus / knowledge base
- retrieveされたdocumentやchunkのID
- retrieval score
- retriever / rerankerのparameter
- generator内部state

一方、攻撃者はtarget RAGとは別に、外部knowledge retrievalを行わないstandard LLMへqueryを送れると仮定する。このstandard LLMはtarget RAGと完全に同一modelである必要はないが、一般知識・parametric knowledgeを比較するreferenceとして機能する必要がある。

攻撃目的は単にprivate-looking responseを得ることではなく、target RAGのresponseをsentence単位に分解し、**private KBへのretrievalによって追加されたinformationを高精度に同定すること**である。

この設定では、RAG response中に一般知識とprivate knowledgeが混ざるほど単純なkeyword matchingやresponse-level判定は難しくなる。また複数domainを含むKBでは、攻撃者がdomainを事前に知らない可能性もある。

## 先行研究からの改善点

従来のRAG privacy extractionには大きく2つの問題がある。

1. **source attributionが粗い**: response中にprivate informationが含まれても、どのsentenceがretrieval由来かを正確に特定できない。
2. **domain knowledgeへの依存**: 特定domainを前提にcrafted queryを作るattackは、heterogeneous / unknown-domain KBへ一般化しにくい。

本論文はtarget RAGとstandard LLMのresponseを比較することで1を、iterativeなquery refinementによって2を改善する。

[Feedback-Guided Extraction / CopyBreakRAG](2024-2411.14110-feedback-guided-extraction-copybreakrag.md) が既に抽出したknowledgeを次の探索へfeedbackして**corpus coverageを広げる**のに対し、本論文のfeedbackは主として未知domainを発見し、**private sentence localizationを改善する**ために使われる。したがって両者はadaptive feedbackを使う点では近いが、optimization targetが異なる。

## Method / Algorithm

手法は大きく、(1) adversarial query generation、(2) knowledge-asymmetry feature extraction、(3) private sentence classificationから構成される。

### 1. Adversarial Query Generation

queryを概念的に $q=q_1\oplus q_2$ と分解する。$q_1$ はtarget domainやtopicに関連するknowledgeをRAGから引き出す役割を持ち、$q_2$ はretrieved contextに依存する詳細情報を回答させる役割を持つ。

single-domain settingではdomain keywordやtopic informationを利用して、private corpusの内容がresponseへ現れやすいqueryを構成する。

multi-domain / unknown-domain settingでは、最初からdomain-specific knowledgeを仮定しない。まず広いdomain-agnostic queryを送り、response中に現れたcandidate private fragmentやtopicを次のquery generationへfeedbackする。これを繰り返すことで、攻撃者がKB taxonomyを知らなくてもprivate knowledge landscapeを徐々に探索する。

### 2. Target RAGとStandard LLMのResponse比較

同じadversarial queryに対して、target RAGのresponse $R_L$ とstandard LLMのresponse $A_L$ を取得する。

両responseをsentenceへ分割しembedding化する。各RAG sentenceについてstandard LLM response内のsentenceとのsemantic similarityを計算し、最大cosine similarityなどをfeatureとして利用する。

直感的には、standard LLMにも同等内容が現れるsentenceはparametric / public knowledgeである可能性が高く、target RAGにのみ現れるsentenceはretrieved private knowledgeの候補となる。

ただしcosine similarityだけでは不十分である。例えば語彙が非常に似ていても、否定や数値差によって意味が逆になるsentenceが存在する。このためNLI modelを用いてsentence pairの **entailment / neutral / contradiction** を評価し、そのconfidenceをsemantic relationship scoreへ反映する。

### 3. Fine-Grained Privacy Classifier

semantic similarityとNLI-derived featureをneural classifierへ入力し、各RAG sentenceをprivate / non-privateとしてbinary classificationする。

この構成により、response全体を一括してprivacy leakageと判定するのではなく、例えば5 sentenceのうち2 sentenceだけがprivate KB由来というような細粒度判定が可能になる。

### 4. AttackからDefenseへの利用

著者らは抽出attackをprivacy auditingとして利用し、privateと判定されたsentenceをそのまま出力しないresponse reconstructionも検討する。Chain-of-Thought guidedなreconstructionによりspecific sensitive detailを一般化・削除しつつ、回答utilityをできるだけ残す。

したがって中心はAttackだが、fine-grained detectorをoutput-side mitigationへ転用できる点も論文の特徴である。

## Experiment Setup

評価ではsingle-domainとmulti-domainの双方を扱い、HealthCareMagic、Enron Email、Natural Questions系のknowledge settingを利用する。Healthcareやemailはprivate / sensitive corpus leakageを評価するRAG privacy研究で頻繁に用いられるdatasetであり、本論文では異なるdomain間でattackがgeneralizeするかも評価する。

複数のRAG / LLM configurationを用い、既存RAG privacy attackおよびcontent-based / LLM-based privacy detectionと比較する。

主要metricには以下が含まれる。

- **Extraction Success Rate (ESR)**: private informationを正しく抽出できた割合
- **Precision / Recall / F1**: sentence-level private information identification
- multi-domainでのgeneralization performance
- mitigation後のprivacy data ratio

## Main Results

代表結果では、HealthCareMagicで **ESR 93.55%、F1 92.06%**、Enron Emailで **ESR 95.65%、F1 95.65%** を達成する。multi-domain Natural Questions settingでも **ESR 80.00%、F1 84.21%** と、domainが混在しても高い識別性能を維持する。

HealthCareMagicでは既存RAG-PrivacyのESRが約57.58%であるのに対し、本手法は93.55%。EnronではRAG-Thief系baselineのESR 52.75%、F1 38.51%に対し、本手法は95.65% / 95.65%と大きく改善する。

重要なのは、単純により多くのtextをRAGから引き出したことだけではなく、**mixed response中のどの部分がprivate knowledgeに由来するかを正確に同定できること**である。

## 追加実験・Robustness

multi-domain experimentは、事前に単一domainを知っているというattack assumptionを緩める。iterative refinementによって未知topicを発見しながらqueryを更新するため、single-domain crafted promptだけに依存するattackより現実的なheterogeneous KBへ適用しやすい。

semantic similarityとNLIを組み合わせる設計も重要で、surface-level similarityだけでは取り違えるcontradiction / entailmentを区別することでsentence-level classificationが安定する。

防御case studyでは、fine-grained detection結果を使ってresponseを再構成することで、HealthCareMagicの例でprivacy data ratioを **48.27%から9.37%** へ低減する。attack frameworkがprivacy leakageの測定だけでなく、どこをsanitizationすべきかの位置情報を提供できることを示す。

## Limitations / 成立条件

最大の成立条件は、攻撃者が比較対象となるstandard LLMを利用できることである。reference LLMのparametric knowledgeがtarget generatorと大きく異なる場合、両responseの差が「private retrievalによる差」ではなく「model knowledgeの差」になり、false positiveが増える可能性がある。

また、private knowledgeが既にpublic webやstandard LLMのtraining dataへ含まれている場合、knowledge asymmetry自体が弱くなる。逆にtarget RAGがretrieved informationを強くabstract / summarizeする場合には、元KB sentenceとの対応も曖昧になる。

sentence-level privacy classificationは、corpus全体をverbatimにreconstructするattackとは目的が異なる。したがって本手法単独でknowledge-base stealing coverageを最大化するわけではない。

## RAG Security Taxonomyでの位置づけ

本論文は **Attack / confidentiality / fine-grained retrieval-data leakage** に位置づけられる。

RAG privacy attackの発展を概略化すると、

```text
retrieved contextを漏らせるか
  ↓
private corpusを広くreconstructできるか
  ↓
response中のどの情報が本当にprivate KB由来か
```

という流れの3段階目を扱う。

[The Good and The Bad](2024-2402.16893-the-good-and-the-bad.md) や [Spill the Beans](2024-2402.17840-follow-my-instruction-and-spill-the-beans.md) がRAG-specific leakage surfaceを明確にし、[CopyBreakRAG](2024-2411.14110-feedback-guided-extraction-copybreakrag.md) や [RAGCrawler](2026-2601.15678-connect-the-dots.md) が大規模corpus explorationを進めたのに対し、本論文は**漏洩responseのsource attribution**を細粒度化する。

## 実装・研究上の示唆

RAG security evaluationでは「responseにsensitive-looking textが含まれたか」だけでは不十分で、**retrievalによって追加されたinformationをparametric knowledgeから分離して測定する必要がある**。

また、privacy detectorをresponse-levelではなくsentence / span-levelにすると、全面拒否ではなく局所的なredaction / abstractionが可能になり、utility-preserving defenseへつなげやすい。

一方でknowledge-asymmetry detectorはreference modelへの依存を持つため、今後は複数reference model、retrieval provenance、attribution modelなどを組み合わせたrobustなsource identificationが重要になる。
