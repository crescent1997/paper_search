# 概要
Learnable Adaptive Caching（LAC）は、連続観測の静的領域を繰り返しTransformerへ通す無駄を削減する。従来のVLA-Cacheのような固定・heuristic reuseに対し、**どのvisual tokenを再計算するか**と**何割を再利用するか**をtask lossから学習する。Transformer decoderの過去フレームのvisual KV statesを再利用するため、直接的なKV reuseに分類できる。

# 問題設定・先行研究との差
- 連続frameは背景など大部分が冗長だが、gripperや接触対象は変化しやすい。
- 静的なcache ratioやattentionだけに基づくtoken selectionは、タスクで必要な領域を落とす恐れがある。
- LACは小型decision modulesを追加学習する代わりに、実際のaction task lossを使ってcache budgetを適応化。training-freeなVLA-Cache/SAFE-Prunerとは運用条件が異なる。

# 手法
## 1. Cached Token Selector
各visual tokenに重要度を付け、重要なものは再計算、重要度の低いものは前frameのKVを使う。optical flow等のmotion cueとtask signalを組み合わせる。

## 2. Cache Ratio Predictor
scene-level motion entropyを入力として、離散候補の中から再利用率 `r_t` を選ぶ。`k_t=N*r_t` 個の低重要度tokenをcache reuseに回し、残りは新しいK/Vを計算する。

## 3. 二段階学習
- Stage I: Frozen VLAのattention mapをselectorへMSE蒸留し、安定した初期化を得る。
- Stage II: backboneをfreezeし、selectorとratio predictorをaction lossとreuse促進regularizerでjoint training。

```math
\mathcal{L}_{\mathrm{total}}=\mathcal{L}_{\mathrm{VLA}}+\lambda\mathcal{L}_{\mathrm{ratio}},\qquad
\mathcal{L}_{\mathrm{ratio}}=-\sum_{j=1}^{C}\tilde p_t^{(j)}r_j.
```

離散ratioはGumbel-Softmax + straight-through、token top-kはsoft mask surrogateで勾配を流す。推論ではdeterministic hard selectionを使用。

## 4. 推論時KV reuseとstochastic recovery
再計算tokenの新K/Vとcache tokenの過去K/Vを結合し、action decoderへ渡す。古いKVを使い続ける誤差の蓄積を抑えるため、低確率で一部のcached tokensをランダムに再計算する。これは単純なtoken pruning（情報を削除）と異なり、**過去情報を残して演算を省略**する。

# Experiment Setup
- OpenVLA / LIBERO（Spatial, Object, Goal, Long）。比較: SparseVLM、FastV、VLA-Cache。
- CogAct / SIMPLER（Visual Matching、Variant Aggregation）。4タスク。
- 実機Franka manipulator 4タスク（KnockCrisp、PickMango、CoverBanana、KnockBottle）。実機用OpenVLA backboneはLoRA fine-tuning。
- 指標: task success rate、FLOPs、CUDA time。実機制御周波数・GPU peak memoryは包括的な表を確認できない。
- **追加学習あり**（selector/predictor）。base VLA backboneのfreezeと実機用backboneのLoRA fine-tuningは区別する。

# Main Results
## LIBERO（論文Table 1）
| Method | Spatial | Object | Goal | Long | Avg | FLOPs (T) | CUDA time |
|---|---:|---:|---:|---:|---:|---:|---:|
| OpenVLA | 84.4% | 86.6% | 75.6% | 53.2% | 75.0% | 1.864 | 51.91ms |
| VLA-Cache | 83.8% | 85.8% | 76.4% | 52.8% | 74.7% | 1.355 | 31.83ms |
| **LAC** | **85.6%** | 86.2% | **76.6%** | **59.2%** | **76.9%** | 1.392 | **29.51ms** |

CUDA時間の比は51.91/29.51=**1.76倍**。FLOPsは25.3%削減。VLA-CacheよりわずかにFLOPsが多い（1.392 vs 1.355T）がCUDA timeは短い（29.51 vs 31.83ms）。したがってFLOPsと実測latencyは単純比例しない。

## SIMPLER（CogAct）
- Visual Matching平均: baseline 74.8%、VLA-Cache 74.4%、LAC **75.5%**。CUDA 54.29→37.82ms。
- Variant Aggregation平均: baseline 61.3%、VLA-Cache 62.3%、LAC **63.0%**。CUDA 53.54→37.90ms。
- 実機の成功率改善はabstractで+5.0ppと報告。ただし実機の課題・試行数に依存し、LIBEROの+1.9ppと混同しない。

# 主要ablation
論文Table 2（LIBERO-Spatialの設定に対応、Table 1の4-suite平均と混同しない）:

| Variant | Success | FLOPs (T) | Time |
|---|---:|---:|---:|
| Selector only | 82.2% | 1.283 | 28.48ms |
| + Reuse Predictor | 83.4% | 1.325 | 29.04ms |
| + Stochastic Recovery | **85.6%** | 1.377 | 29.32ms |

Predictor/recoveryの追加で成功率が上がるが、FLOPsとlatencyも少し増える。これは「最速設定」と「高精度設定」が一致しないことを示す。

Appendix Table 5: Stage Iなし79.2%、language-guided policy 83.0%、motion-guided full LAC 85.6%。attention初期化とmotion priorが学習安定性に重要。

# Limitations
1. optical flowの品質に依存し、暗所、motion blur、camera ego-motionで誤判定の恐れ。
2. 大きなscene変化では再計算率が増え、speedupが小さくなる。
3. selector/predictorの追加学習が必要で、training-free baselineと導入コストが異なる。
4. 過去KVのposition alignmentや古さによる劣化を、非常に長い実機連続運転で評価したとは限らない。
5. CUDA timeはpolicy全体のセンサI/O・actuator latency・制御Hzと同じではない。GPU VRAM peak、energyは要追加評価。

# Taxonomy / 既存研究との比較
`KVcache/vla/` — **cross-frame visual KV reuse / learned adaptive caching**。BlockVLAのblockwise prefix cacheは同一action sequence内、LACは連続観測frame間。MEM/HiMeはpolicyの長期記憶であり、低レベルattention KVを保持する設計とは異なる。
