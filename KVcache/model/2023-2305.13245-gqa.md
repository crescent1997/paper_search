# GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints

## 概要

GQAはdecode時のKV cache量とmemory bandwidthをmodel architecture側から削減する代表的手法。

標準Multi-Head Attention (MHA)では各query headが独自のK/V headを持つ。Multi-Query Attention (MQA)はすべてのquery headsで1組のK/Vを共有し、KV cacheとdecode memory trafficを大幅に削減するが、品質低下が生じる場合がある。

Generalized Multi-Query Attention (GQA)はその中間として、query headsを複数groupへ分け、group内でK/V headを共有する。

## MHA / MQA / GQA

query head数を Hq、KV head数を Hkv とすると、

- MHA: Hkv = Hq
- MQA: Hkv = 1
- GQA: 1 < Hkv < Hq

となる。

KV cache sizeは他条件が同じなら概ねHkvに比例するため、例えば32 query heads / 8 KV headsのGQAなら、MHAに比べK/V head dimension由来のcache量は約1/4になる。

これはtoken evictionやquantizationと異なり、**そもそも生成するK/V head数を減らす構造的削減**。

## なぜMQAだけでは不十分か

MQAはdecode memory bandwidthの点では非常に有利だが、すべてのquery headが同一K/V representationを見るためMHAよりrepresentation capacityが低下し、task qualityが落ちる場合がある。

GQAは複数KV headsを残すことでhead diversityを確保しながら、MHAより大幅にKV量を削減する。

## Grouped-Query Attention

query headsをG個のgroupへ分け、各groupで1つのK headとV headを共有する。

attention computation自体は各query headについて行うが、cacheからreadするK/V tensorのhead数は減る。

decodeはしばしばFLOPsよりKV memory bandwidthに制約されるため、この削減はlatency / throughputに直接効く。

## MHA checkpointからのUptraining

GQAの重要な実用的貢献は、既存MHA checkpointを最初からpretrainし直さなくてもGQAへ変換できること。

同一groupに入るMHAのK/V projection headsを平均化してGQAのK/V headを初期化し、その後短い追加trainingを行う。

論文では元pretraining computeの約 **5%** のuptrainingでMHA checkpointをMQA/GQAへ変換できることを示す。

## Experiment Setup

T5系encoder-decoder modelを中心に、MHA、MQA、複数group数のGQAを比較する。quality benchmarkとinference speedの双方を評価し、uptraining computeも分析する。

## Main Results

GQAは多くのtaskでMHAに近いqualityを維持しながら、MQAに近いinference speedを実現する。

group数を増やすほどMHA側へ近づきquality/capacityは上がるがKV cacheとmemory bandwidthも増える。逆にgroup数を減らすほどMQA側へ近づく。

したがってGQAは **quality ↔ KV memory / decode bandwidth** の連続的trade-offをarchitecture parameterとして提供する。

## KV cacheへの効果

各layer、各tokenについて保存するK/VはHkv個だけでよい。

概念的なcache量は

KV bytes ∝ layers × sequence length × Hkv × head_dim × 2(K,V)

となるため、MHA→GQAの削減率は概ね Hkv/Hq。

この削減はprefill後だけでなくdecode中のKV read trafficにも効く。

## Compression / Access手法との違い

GQAは既存KVを選んで捨てるのではない。

- H2O / Scissorhands / SnapKV: 生成済みKV tokenを減らす
- KIVI: KVのbit数を減らす
- Quest等: decode時に読むKV subsetを減らす
- GQA: **modelが生成・保存するKV head数そのものを減らす**

したがってtaxonomy上は明確にmodel category。

これらは直交するため、GQA model上でさらにtoken eviction、quantization、sparse accessを適用できる。

## MQAからGQAへの意味

MQAは極端なKV sharingであり、GQAはsharing granularityをgroup単位へ緩和したものと解釈できる。

後続のCLA / cross-layer KV sharingでは、head dimensionだけでなくlayer dimensionでもK/Vを共有する方向へ進む。

つまり構造的KV削減の系譜は、

MHA → MQA/GQA（head間sharing）→ CLA等（layer間sharing）

と整理できる。

## Limitations

GQAは既存MHA modelへ完全にtraining-freeでは適用できず、checkpoint変換後にuptrainingが必要。

またKV head数を減らすほどrepresentation capacityとのtrade-offがあり、最適group数はmodel sizeやtaskによって変わる。

論文評価は当時のT5系を中心としており、後のdecoder-only Llama/Qwen系での実装・kernel効率はserving stackにも依存する。

## KV-cache taxonomy

**model / structural KV reduction / head sharing**。

selection granularityはtokenではなくattention head。runtime heuristicではなくmodel architecture自体がKV生成量を減らす。

## まとめ

GQAはMHAの品質とMQAの高速decodeの間を、KV head group数という単純なparameterで連続的につないだ。

現在のLLMで広く採用されるKV削減設計の基礎であり、KV cache研究をtoken compressionだけでなくarchitecture-level reductionとして整理する上で重要なhistorical paper。
