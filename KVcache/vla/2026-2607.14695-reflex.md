# 概要
**Reflex**は、flow-matching型VLAで「KV cacheを再利用してよい領域」を**denoising timestep依存性**に基づいて分離し、推論とロボット実行を非同期化するsystems論文（**ICML 2026 Main**）。同じ観測に対してflow step $k$が変わるたびに、action expertの表現は変わる。一方、**denoising stepに依存しないperception encoderの表現**まで再計算するのは無駄である。この違いを利用して、static prefix / sliding history / dynamic suffixの3領域にcacheを分ける。

Pi0.5 + LIBEROでaction chunk推論時間135.2→52.4ms（**2.58×**）、Pi0で2.73×。control loopは非同期化により**50Hzで動作**し、reaction latencyは最大54%短縮。**50Hzは1秒に50回のfull action-chunk推論を完了する意味ではない**。Appendixのchunk=50設定ではfull chunk generation自体は52.4ms（約19.1Hz相当）であり、既存chunkの実行と次chunkの推論をoverlapして50Hzのaction commandを維持する。

# 問題設定・既存法の問題
- Flow matchingは複数denoising stepでactionを更新する。**timestep embeddingが全層の表現へ注入される構造**では、step $k$で計算したKVをstep $k+1$にそのまま流用すると、本来のattentionと異なる。
- 全履歴のKVを毎回再計算すれば正しいが遅い。Naive KV reuseは速くても、古いtimestep依存状態を混ぜてaction qualityを破壊する。
- Action chunkingによりmodel呼び出しを減らしても、chunk境界で推論待ちが生じる。重いvision encodingとdenoisingを同期実行すると、ロボットが動作を停止する（stall）。
- 非同期化するだけでは、画像取得時刻とaction実行時刻のずれ（state staleness）が新たに生じる。

# 手法
## 1. Timestep-invarianceとPartitioned Attention
前提は**perception encoderがflow denoising step $k$に依存しない**こと：$\partial\mathrm{Enc}/\partial k=0$。KVを以下に分割する。

| 領域 | 内容 | 更新規則 |
|---|---|---|
| **Pinned/static prefix** | task instruction等 | instruction変更まで固定 |
| **Sliding visual history** | 直近$N$観測フレームのvision KV | 新フレームを追加し最古をFIFO evict |
| **Dynamic suffix** | 現在のflow state、timestep-conditioned action表現 | **各denoising stepで再計算** |

$K=[K_{pin};K_{slide};K_{dyn}(k)]$、$V=[V_{pin};V_{slide};V_{dyn}(k)]$として、dynamic queryに対し**全領域のlogitsを連結した後に1回のsoftmax**を計算する：

$$A_k=\operatorname{softmax}\!\left(\frac{Q_k[K_{pin};K_{slide};K_{dyn}(k)]^T}{\sqrt d}\right)[V_{pin};V_{slide};V_{dyn}(k)].$$

領域ごとに独立softmaxして出力を単純に足すのではない。**K/Vがfull-batch計算と同一で、同じmask/position/入力を使う**という条件のもとでは、単に分割保存して再結合するattentionは数学的に等価。著者は固定観測window・固定入力に対する出力MSE=0.00を報告する。非同期scheduling、future state prediction、mixed precisionの振る舞いまで厳密同値と主張しているわけではない。

**適用範囲**：vision encoderにflow timestepを注入しないarchitecture。視覚token自身がdenoising timestepに条件付けられるunified DiTには、そのまま適用できない。

## 2. Incremental Prefill + KV ring buffer
毎stepで履歴$N$フレーム全体をvision encodingせず、**新しい1フレームだけをencode**してKVを更新。prefixとsliding historyをdenoising loopの前に連続領域へmergeし、dynamic suffixは事前確保領域に上書きする。各stepの`torch.cat`やallocateを避ける。

Appendixのbufferは概念的に`K/V: [layers, max_seq_len, heads, head_dim]`で事前確保、ring pointerでFIFO eviction。**O(1) incremental cache update**とは、固定サイズwindowで1フレーム分の追加/削除を行う意味。**attention計算全体が任意のwindow長に対してO(1)**という意味ではない。著者自身、windowを50まで増やすと高速化が1×未満に落ちると報告する。

## 3. AdaRMSNorm: 長時間BF16安定化
頻繁なflow noise初期化とBF16の数値不安定性を避けるため、RMS統計をFP32で計算し、timestep embeddingとproprioceptive state $c=[t_k,s_t]$でgainを変える：

$$\mathrm{AdaRMSNorm}(x,c)=\frac{x}{\sqrt{\mathrm{mean}(x^2)+\epsilon}}\odot(1+\mathrm{MLP}(c)).$$

追加MLPとdtype制御を含むため**完全なmodel modification-freeではない**。この機構はKV再利用の数学的正しさとは別の、長時間deploymentのnumerical stability対策。

## 4. 非同期pipelineとfuture-state compensation
Vision streamがcamera frameをencodeしKV bufferへpublish、Policy streamが最新cacheを読んでaction chunkを生成。現在のchunkの残り実行時間から次推論の開始点を調整する（Adaptive Overlap Scheduling）。$K=\lceil\bar\tau_{inf}/\tau_{step}\rceil$ step分の余裕を見て次chunkを起動する。

Policyは観測時の古いstateではなく、直近のcommanded actionを用いて$\hat s_{t+\Delta}\approx a_t^{cmd}$と近似する。**学習済み物理dynamics predictorではない**ため、controllerが命令へ十分追従することを仮定する。PiPerで100ms先読み時のend-effector deviation <3cmと記載。

## 5. Kernel fusion
QKV projectionやSwiGLU Gate/Upをfuseし、kernel launchを削減。FlashNorm/FusedAdaLNも利用。したがって論文の**2.58×をPartitioned Attention単独の効果と解釈しない**。

# Experiment Setup
- **モデル**：Pi0.5（2.3B、PaliGemma backbone + action expert）、Pi0（3.1B）、AppendixでSmolVLA。GPU RTX 4090 24GB、追加でRTX 3090。BF16、action chunk size 50、flow matching 10 steps、history 10 frames、FIFO。
- **ベンチマーク**：LIBERO Spatial/Object/Goal/Long（各suite 10 task×50 episodes、最大500 steps）、Kinetix（100 episodes/task）、実機AgileX PiPer（3 tasks×20 episodes/手法）。
- **比較**：Standard sync/full recompute、Naive KV cache（timestep無視）、Async-Naive（future predictionなし）、Reflex。
- **指標**：action chunk inference latency、**observation-to-action reaction latency**、stall rate、task success、GPU peak memory、長時間数値安定性。Appendixでは100-step warmup後に1000 chunkを測り、latencyは95th percentileを報告すると記載。実機の50Hz command streamとchunk生成Hzを区別する。

# Main Results
**Pi0.5 / LIBERO（Figure 6、Table 1）**

| 指標 | Standard | Reflex | 解釈 |
|---|---:|---:|---|
| Chunk inference latency | 135.2ms | **52.4ms** | **2.58×** |
| LIBERO平均reaction latency | 156.5ms | **82.5ms** | 約47%短縮 |
| Stall rate | 100% | **0%** | chunk実行と推論のoverlap |
| Peak GPU memory | baseline | **27%減** | fixed history + ring buffer |

Pi0はchunk inferenceで**2.73×**、LIBERO平均reaction latency 208.6→102.4ms。Kinetixでのpeak VRAMは24%減。Appendixのlatency内訳（Pi0.5/4090）はvision prefill **42.1→8.2ms**、denoising loop（10 step）**68.4→32.8ms**、total **135.2→52.4ms**。

**Task success**：Pi0.5のLIBERO-Longは68.8→72.4%（+3.6pp）、Pi0では71.0→75.0%（+4.0pp）。KinetixはPi0.5で+7.4pp、Pi0で+6.7pp。精度が改善した主因として低reaction latencyを示唆するが、cache数学的同値性と非同期制御改善は分けて評価する必要がある。

**実機AgileX PiPer**：Pick-Place 65→76%、Articulated 52→66%、Dynamic Recovery 38→55%（各20 episodes、同期→Reflex）。reaction latency 101–110ms、stall 0%。20 episodes/taskという小規模評価である。

# 主要ablation
- **Naive cacheは破綻（Table 4）**：full oracle prediction MSE 0.00 / success 85.2%、Naive cache MSE **1.42** / success **12.5%**、Partitioned Attention MSE **0.00** / success **85.4%**。**KV再利用の可否はtimestep依存性で決まる**という本論文の中核実験。
- **Partitioned Attention単独**：Pi0.5のchunk latency 135.2→61.5ms。以降のoperator fusion・非同期schedulingが追加の利得を作る（Figure 8）。
- **長時間BF16安定性（Table 5）**：通常BF16は120–220 stepsで破綻、FP32 normのみ700–1200 steps（+0.8ms）、AdaRMSNormは**2000 steps超でNaN/Infなし**（+0.4ms）。無限時間の数学的保証ではなくstress testの観測。
- **Window size（Figure 10）**：$N=1$は高速だがcontext不足で成功率低下。$N=10$付近で品質が飽和し、$N=50$ではoverhead増によりspeedup <1×。
- **Action chunk size（Appendix Table 9）**：25/50/75/100に対しspeedup 2.31/2.58/2.63/2.64×。ただしchunk生成Hzは23.5/19.1/15.6/13.0と低下。**速度倍率が大きいほどcontrolの応答性が高いとは限らない**。
- **Future state prediction**：Kinetixで4-step delay時、predictorなし比+11pp、Async-Naive比+22ppの成功率改善（Figure 9）。

# Limitations・検証上の論点
- **timestep-invariant encoderが必要**。unified DiTのようにvision featureもflow stepで変化するモデルには非対応。
- **exactnessは限定的**。論文の証明はK/Vを3領域に分割して再結合するsoftmaxの同値性を示す。過去フレームのhidden stateが後続フレームで変わる双方向attention、position shift、causal mask変更などがある場合、そもそもcached K/Vがfull-batchのK/Vと同じかは別途確認が必要。固定入力でのMSE 0.00はその実装条件での検証。
- **50Hzはstreaming制御周期**であり、52.4msのfull chunk生成を20ms以内に終えるわけではない。新しい観測の反映がどの程度遅れるかはvision stream更新周期、buffer staleness、future predictorに依存する。
- **追加改変がある**：AdaRMSNorm、custom CUDA kernels、静的buffer、非同期schedulerを必要とする。単純な`past_key_values`差し替えで再現できない。
- **長期稼働**：>2000 stepsのstress testはあるが、永続的安定性の保証ではない。GPU peak memoryは減るが、window増加に対するattention時間は増える。
- **評価条件**：実機は3 tasks×20 episodes。P95 latency、GPU/precision、action chunk長、window長を合わせない横断比較は危険。

# Taxonomy・関連研究との差分
- **分類**：`KVcache/vla` / *flow-timestep-aware exact-region KV reuse* / incremental visual prefill / streaming serving / runtime memory management。
- [VLA-Cache](2025-2502.02175-vla-cache.md)：前後フレームのpatch類似性から**近似的**にvisual KVを再利用。Reflexは**同一観測window内のtimestep-invariant表現**をreuseし、dynamic action suffixを必ず再計算する。
- [LAC](2026-2602.00686-lac.md)：task lossでtoken-levelのreuse判断を学習し、action utilityを最大化。Reflexはarchitecture上の依存関係を利用し、**cacheの正しさ**とruntimeを優先する。
- [EfficientVLA](2025-2506.10100-efficientvla.md)：DiTのdenoising step間で**attention/MLP中間特徴を近似reuse**。Reflexはstep-dependent suffixを再計算し、step-invariant vision KVのみ再利用する。両者は「flow/diffusionで何をcacheしてよいか」の対照的な解法。
- [VLA-Pruner](2025-2511.16449-vla-pruner.md)：視覚tokenの削除。Reflexは履歴をring bufferへ保持し、計算・メモリ移動の重複を減らす。
- LLMの[CacheBlend](../reuse/2024-2405.16444-cacheblend.md)とは異なり、selective recomputationの重要度scoreよりも**denoising timestep dependency**に基づくcache partitioningが中核。
