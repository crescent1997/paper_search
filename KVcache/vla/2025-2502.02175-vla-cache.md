# 概要
VLAは各制御stepでカメラ画像と命令を入力して行動を推論する。隣接する観測フレームには背景など変化の小さい領域が多いが、従来はvisual tokenのdecoder計算を繰り返す。VLA-Cacheは**前フレームのvisual token KVを位置対応で再利用**し、不要な再計算を避ける。一般的なautoregressive decoding内のprefix cacheとは異なり、**異なる制御時刻間**でKVを共有する。

# 問題設定と既存法の問題
全ての静止領域を再利用すると、見た目の変化が小さいgripperや操作対象の微妙な状態差を見逃す。LIBERO SpatialのOpenVLAでは、full計算のsuccess rate 84.4%が静止tokenの単純再利用で74.2%に下がる。VLM用の単純なvisual pruningでは、操作に必要な情報を保持できない。

# 手法
## 1. Static token selection
前時刻と現時刻の対応する画像patchについてraw pixel cosine similarityを求め、閾値以上かつtop-kの安定patchを再利用候補とする。これはsemantic embedding similarityではなく、**同じ空間位置のpatchの見た目の類似性**である。

## 2. Task-relevant token filtering
言語decoderのtext/vision間attentionからvisual tokenのtask relevanceを集約する。高いrelevanceを持つtokenは静止候補から除外し、現時刻で再計算する。概念的には `reuse = static_candidates - task_relevant_tokens`。本文のattention行列の軸・slice表記は実装時に注意して確認する必要がある。

## 3. Layer-adaptive reuse
layerごとのattention entropyの変化を測り、集中度の変化に応じて再利用率を調整する。全layerで同一のtoken集合を固定して使うのではなく、layerごとに再利用するsubsetを変える。

## 4. KV更新
各layerの各visual tokenについて、再利用対象なら前時刻のK/Vをコピーし、それ以外は現時刻のhidden stateからK/Vを再計算する。model weightの変更や追加fine-tuningは不要。位置対応のある連続フレームを前提とするため、大きなカメラ移動や急激な物体移動には注意が必要。

# Experiment Setup
- モデル: OpenVLA、OpenVLA-OFT、CogAct。異なるaction headを含む。
- ベンチマーク: LIBERO（Spatial/Object/Goal/Long）、SIMPLER、実機Kinova Jaco2。
- GPU: RTX 4090。評価: task success rate、control frequency、FLOPs、CUDA latency。
- 比較: full推論、FastV、SparseVLMなど。

# Main Results
- 論文全体の報告値は**最大1.7倍のCUDA latency高速化**、**control frequency 15%向上**。これらは異なる評価条件での数値であり、全条件で同時に得られるわけではない。
- LIBERO Spatial / OpenVLAの構成要素比較: full 84.4% / 51.56 ms、静止token再利用 74.2% / 31.03 ms、task relevance filter追加 82.6% / 31.03 ms、layer adaptive追加 **83.8% / 32.22 ms**。再計算の追加で精度を回復し、速度改善を維持する。
- 実機・複数モデルで評価する一方、性能はフレームの静止割合とtaskの性質に依存する。

# Ablation
- **Static only** は大きく高速化するが成功率が約10.2ポイント低下する。
- **Task-relevance filtering** で8.4ポイント回復する。
- **Layer adaptation** でさらに1.2ポイント回復するが、若干latencyは増える。
- Appendixでは静止token budget、relevance threshold、diffusion head等への適用を検証する。

# Limitations
- 連続フレームの対応patchが安定していることが重要。視点移動、occlusion、素早い操作では再利用可能割合が減る。
- 過去のKVを現在の観測に流用するため、feature driftや古い状態情報による誤動作のリスクがある。
- 選択用のattention抽出・entropy計算とcache管理にruntime overheadがある。CUDA latencyの改善をend-to-end control loop全体の同率改善と混同しない。
- 実験は主にmanipulation中心で、navigation等への一般化は別途検証が必要。

# Taxonomy / 関連研究
- **分類**: `KVcache/vla` / cross-frame visual-KV reuse / training-free selective recomputation。
- LLMの[CacheBlend](../reuse/2024-2405.16444-cacheblend.md)等と同じく部分的な再計算を使うが、再利用の境界は文書ではなく**ロボットの観測時刻**。選択信号は画像patchの時間的類似性とtask relevance。
- [VLA-Pruner](2025-2511.16449-vla-pruner.md)はKVのフレーム間再利用ではなくvisual tokenを削除する。後者はaction decodingでの重要度を直接考慮する。
