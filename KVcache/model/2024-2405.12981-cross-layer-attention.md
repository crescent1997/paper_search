# Reducing Transformer Key-Value Cache Size with Cross-Layer Attention

> MQA/GQAが**同一layer内のhead方向**にK/Vを共有するのに対し、Cross-Layer Attention (CLA)はさらに**layer方向**へsharingを拡張する。隣接layerで同じK/V activationsを再利用し、cacheを保持するlayer数そのものを減らすarchitecture-level KV reduction。

## 概要

autoregressive LLMでは各Transformer layerの過去K/V activationsをKV cacheへ保存するため、cache容量はsequence lengthだけでなくlayer数にも比例する。

MQAやGQAは複数query headsで少数のK/V headsを共有し、head axisのcache容量を大幅に減らした。しかし各layerは依然として独自のK/Vを生成・保存する。

CLAはこの残った冗長性に着目し、あるlayerで生成したK/Vを後続の隣接layerでも共有する。

CLA2なら2 layerで1組のK/V、CLA3なら3 layerで1組を共有するため、CLA2ではMQAに対してKV cacheをさらにほぼ2×削減できる。

## 問題設定

通常のTransformerではlayer `l`ごとに

```text
Q_l = X_l W_Q,l
K_l = X_l W_K,l
V_l = X_l W_V,l
```

を生成し、decodeのため過去の`K_l, V_l`を保存する。

MQA/GQAではK/V head数を減らせるが、

```text
number of cached KV sets ∝ number of layers
```

という構造は残る。

CLAは、隣接layerのhidden representationが異なっていても、attention用K/V representationを共有して十分なmodel qualityを維持できるかを検証する。

## Cross-Layer Attention

CLA sharing factorを`S`とすると、`S`個の連続layerが1組のK/Vを共有する。

CLA2の概念は、

```text
Layer 1: Q1 + K1/V1生成
Layer 2: Q2 + K1/V1再利用

Layer 3: Q3 + K3/V3生成
Layer 4: Q4 + K3/V3再利用
...
```

となる。

各layerは独自のQuery projectionを持つため、同じK/V memoryへ異なるQからattentionする。

K/Vを生成しないlayerではK/V projection parameterとそのcacheが不要になる。

## GQA / MQAとの関係

[GQA](2023-2305.13245-gqa.md)はquery headsをgroup化し、同じlayer内でK/V headを共有する。

CLAはこのsharingを直交するlayer axisへ拡張する。

| Method | KV sharing axis |
|---|---|
| MHA | sharingなし |
| MQA | head axis: 全Q headsで1 KV head |
| GQA | head axis: Q-head group内でKV共有 |
| CLA | **layer axis: 隣接layersでKV共有** |

そのためGQA/MQAとCLAは併用でき、

```text
KV size ∝ (# KV heads) × (# KV-producing layers)
```

の両方を減らせる。

技術系譜としては、

```text
MHA
 ↓
MQA / GQA
intra-layer KV sharing
 ↓
CLA
inter-layer KV sharing
```

と整理できる。

## Memory–accuracy trade-off

1B modelの代表例では、

| Configuration | KV layers | KV bytes/token | Validation PPL |
|---|---:|---:|---:|
| H128-MQA | 20 | 10,240 | 13.54 |
| H128-MQA-CLA2 | 10 | 5,120 | 13.60 |
| H64-MQA | 20 | 5,120 | 13.81 |

H128-MQA-CLA2はMQAのKV cacheを半分にしながらperplexity悪化を13.54→13.60に抑える。

さらに同じ5,120 bytes/tokenをCLAなしで実現するためKV head dimensionを128→64へ減らすと13.81まで悪化する。

つまり、

> **representation dimensionをさらに削るより、隣接layerでKVを共有した方が同じmemory budgetで高精度**

というのがCLAの主要結果。

## Sharing factor

sharing factorを増やせばKV cacheはさらに減るがaccuracyは悪化する。

H128-MQAの代表値では、

- MQA: 13.54
- CLA2: 13.60
- CLA3: 13.77
- CLA4: 13.95

となる。

この結果から、隣接2 layerで共有する**CLA2がmemory-quality trade-offのsweet spot**として強い。

## Uniform vs non-uniform sharing

著者らはuniformなCLA2だけでなく、

- KeepEnds: 最初と最後のlayerをdenseにする
- DenseFront: lower layersをdenseにする
- DenseBack: upper layersをdenseにする

なども評価する。

1B代表settingでは、

- Uniform CLA2: 13.60
- KeepEnds: 13.62
- DenseFront: 13.75
- DenseBack: 14.03

で、複雑なsharing patternより単純なadjacent-pair sharingが強い。

これは[PyramidKV](../compress/2024-2406.02069-pyramidkv.md)のようにlayer importanceが一様でないという後続観察とは対照的であり、**cacheを完全共有するarchitecture designと、token budgetをlayer-wiseに変えるcompressionではoptimal allocationが異なる**可能性がある。

## Experiment Setup

Llama-like decoder-only Transformerを用いて1B / 3B parameter modelをfrom scratchでpretrainする。

training dataはSlimPajama。

比較対象は、

- MHA
- GQA
- MQA
- MQA + CLA2/3/4

等。

KV cache bytes/tokenに対するvalidation perplexityを中心にmemory-quality Pareto frontierを評価する。

## Main Results

CLA2はMQAに対してKV cacheを約2×削減しながらほぼ同等のaccuracyを維持する。

1B/3B双方で、単にKV head dimensionやhead数をさらに削る方法より良いmemory-perplexity Pareto frontierを形成する。

NeurIPS論文の主要結論は、

> MQA/GQAによるhead sharingだけでなく、**cross-layer KV sharingにも大きな冗長性が残っている**

という点。

## Learning-rate ablation

CLAではarchitecture constraintが変わるため、最適なtraining hyperparameterも通常MQAと完全には同じでない。

3B experimentではlearning rateを調整することでCLA2が大きく改善し、settingによってはMQA baselineより低いperplexityを示す。

したがってCLAのaccuracy penaltyはarchitectureだけで固定的に決まるわけではなく、training optimizationにも依存する。

## Decode bandwidthへの注意

CLAはKV **capacity**を減らすが、attention computation回数そのものを減らすわけではない。

例えばLayer 1とLayer 2がK/Vを共有しても、

```text
Q1 attends to shared KV
Q2 attends to shared KV
```

という2回のattentionは必要。

したがって同じKVを各layerでmain memoryから再readする実装では、attentionのmemory bandwidthをKV capacityと同じ2×だけ減らせるわけではない。

CLAの直接的benefitは、

- longer context
- larger batch
- more sequences resident on GPU
- reduced KV memory allocation

にある。

これはdecode時に**実際にreadするKV量**を削減する[QUEST](../access/2024-2406.10774-quest.md)や[RetrievalAttention](../access/2024-2409.10516-retrievalattention.md)とは異なるため、taxonomy上は`access`ではなく`model`。

## Training requirement

CLAはK/V projectionを持たないlayerをarchitectureに含むため、inference-timeに既存modelへそのまま適用するcache trickではない。

論文ではCLA architectureをfrom scratchでpretrainする。

この点は[GQA](2023-2305.13245-gqa.md)が既存MHA checkpointをgroup-averageし、元pretraining computeの約5%でuptraining可能と示したのとは異なる。

既存checkpointを低costでCLA化する方法は別課題。

## Pipeline parallelism

cross-layer sharing groupをpipeline parallelのstage境界で分割すると、共有K/Vをstage間通信する必要がある。

したがってCLA2ならsharing pairを同じpipeline stageへ置くのが自然。

一方、tensor parallelismとは基本的に直交する。

K/V projection自体が減るため、KV cacheだけでなくparameter count/FLOPsにも小さい削減効果がある。

## YOCOとの差

[YOCO](2024-2405.05254-yoco.md)もlayer方向のKV redundancyを大幅に削減するが、architecture変更の規模が異なる。

CLAはstandard Transformer blockを保ちながら隣接layerでKVを共有する局所的変更。

YOCOはdecoderをself-decoderとcross-decoderへ分け、self-decoderで作ったglobal KVを後段cross-decoder全体で共有する。

| | CLA | YOCO |
|---|---|---|
| sharing | adjacent layer group | cross-decoder全体 |
| architecture change | 小さい | decoder-decoder再設計 |
| KV reduction | sharing factorに比例 | layer数依存を大幅削減 |
| compatibility | standard Transformerに近い | specialized architecture |

CLAはGQAからより連続的なextension、YOCOはよりaggressiveなarchitecture redesignと位置づけられる。

## Limitations

1. architecture変更なので既存checkpointへtraining-freeには適用できない。
2. sharing factorを大きくするとaccuracy degradationが増える。
3. KV capacity削減とattention read bandwidth削減は同義ではない。
4. pipeline parallelismではsharing group placementへ制約が生じる。
5. 実験は1B/3B from-scratch model中心で、より大規模なmodern GQA modelへのscalingは追加検証が必要。
6. uniform CLA2が強い一方、task/input依存のoptimal layer-sharing topologyは十分探索されていない。

## KV-cache taxonomyでの位置づけ

**model / cross-layer KV sharing / architecture-level structural reduction**。

既登録model系を整理すると、

| Method | Structural reduction axis |
|---|---|
| [GQA](2023-2305.13245-gqa.md) | KV heads / intra-layer sharing |
| CLA | **KV-producing layers / inter-layer sharing** |
| [YOCO](2024-2405.05254-yoco.md) | decoder-level global KV sharing |
| [MHA2MLA](2025-2502.14837-mha2mla.md) | latent KV representation / MLA conversion |

CLAは特にGQAとYOCOの間を埋める重要なarchitecture design。

## まとめ

Cross-Layer AttentionはMQA/GQAで成功したKV sharingをlayer方向へ拡張する。

CLA2では隣接2 layerが1組のK/Vを共有し、

- MQA比でKV cacheを約2×削減
- perplexity degradationは小さい
- 同じmemory量をKV dimension削減で実現するより高精度

というPareto improvementを示す。

一方でattention computation自体は各layerで残るため、KV cache capacity reductionとdecode bandwidth reductionを区別する必要がある。

技術系譜としては、

```text
MHA
 ↓
MQA / GQA
head-axis sharing
 ↓
Cross-Layer Attention
layer-axis sharing
 ↓
MLKV / systematic cross-layer KV sharing
```

と捉えると分かりやすい。
