# TurboVLA — LLMを通さないVLA実行経路

## 概要・問題設定
VLM/LLMを毎制御step呼び出す一般的VLAでは、巨大なdecoderがperception-to-actionのレイテンシ、VRAM、計算量を支配する。TurboVLAは**実行レベルの操作**では、一般的な言語生成を毎回行う必要がないと仮定し、vision + languageから直接action chunkを出す。これはKV cache容量の圧縮・cross-frame reuseではなく、LLMを制御ループから除く**model architecture変更**である。高水準の開放的タスク計画は射程外。

## 先行研究との差
- [VLA-Cache](2025-2502.02175-vla-cache.md): 既存VLMのvisual KVをフレーム間で再利用。TurboVLAはそもそも巨大なLLM backboneを使わない。
- [DySta](2026-2602.03983-dysta.md): static/dynamic視覚表現を学習してKV再利用。TurboVLAは直接cross-attentionで融合し、同等のcacheを想定しない。
- [A1](2026-2604.05672-a1.md): LLM backboneを保持してearly exitとflow-matching高速化。TurboVLAはbackboneを削除する構造的変更。
- [DEM](2026-2609.18374-dem.md): 近いdecoupled設計。DEMは言語encoderのinstruction-level cacheを明示し、RoboCasa同一条件比較を重視する。

## Method
入力は複数視点の画像、自然言語命令、robot state。画像encoderと言語encoder（BERT系）で別々に埋め込み、双方向cross-attentionで言語に条件づけた画像特徴と画像に条件づけた言語特徴を作る。robot stateと融合した特徴からACT系のcompact decoderで連続action chunkを一括予測する。自己回帰action token生成やVLM backboneの反復実行は不要。**学習済みLLMを後付けでcacheするtraining-free手法ではなく、policy自体の学習が必要**。

## Experiment Setup
LIBERO四suite、RoboTwin 2.0のbimanual操作、AgileX Piper実機4タスク。LIBEROでは1タスク50試行の記述があり、GPU計測はRTX 4090、batch=1のpolicy推論を中心とする。モデル規模はLIBERO 0.2B、RoboTwinの別variant 0.4B。RoboTwinの性能はモデルvariantと版によって数値が異なるため、v3本文の値を優先する。

## Main Results
| 評価 | TurboVLA | 備考 |
|---|---:|---|
| LIBERO平均成功率 | 97.6% | 4 suite平均、v3 |
| RTX 4090 policy latency | 31.2 ms | 1 policy call / action chunk |
| RTX 4090 inference VRAM | 0.9 GiB | モデル実行時 |
| Params | 0.2B | LIBERO variant |
| RoboTwin 2.0成功率 | 88.06% | 0.4B variant、v3 abstract |
| AgileX Piper実機平均成功率 | 87.5% | 4 tabletop tasks |

31.2msの逆数は約32 calls/sだが、ロボットの閉ループ制御周波数やaction実行周期をそのまま32Hzとみなしてはならない。CPU前処理、画像転送、通信、物理的実行を含むend-to-endの保証ではない。また別論文DEMが共通RTX PRO 6000で再評価したTurboVLAは19.5ms、RoboCasa 46.3%であり、**GPUとbenchmarkが違う値を横並びで優劣比較しない**。

## Ablation
LIBEROで言語を除去すると97.6→68.5%、task-ID embeddingでは96.6%。言語内容が単なるタスク番号より寄与する。テキストencoderをT5-Baseへ替えても97.6%、SigLIP textでは97.3%で、特定のBERT checkpointに依存するわけではない。双方向融合の比較では、no interaction 96.3%、language→vision 96.8%、vision→language 97.2%、双方向97.6%という傾向が報告されている。実機・他benchmarkへの外挿には注意。

## Limitations / taxonomy
- 既知の実行レベル命令を対象とし、未知の長期計画や複雑な意味推論は評価範囲外。
- **KV taxonomy: VLA / efficient model architecture**。cross-frame visual KV reuse、KV eviction、KV compressionは未実装。長期episodic memoryも持たない。
- 低VRAM化は大規模VLMを外したことに起因し、同一backboneでのKV削減効果とは異なる。
- 数値は著者報告。学習データ・事前学習条件・GPU・action horizonが異なるモデルの成功率を因果的な性能差として扱わない。
