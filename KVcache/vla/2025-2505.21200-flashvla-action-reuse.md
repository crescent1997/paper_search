# FlashVLA — Think Twice, Act Once (2025)

> **同名注意**: 本論文で提案される**FlashVLA（2025, arXiv:2505.21200）**は、別論文「FlashVLA: Streaming Action Decoding for Fast and Asynchronous VLA Inference」（2026, arXiv:2608.27384）と同名だが**別の手法**。本稿は2025年版のaction reuse / token pruningを扱う。

## 1. 概要・問題設定

Autoregressive型VLAでは毎control stepに視覚入力のprefillとaction decodeが必要になる。しかし隣接時刻のactionは方向が近い場合が多く、同じ操作を再利用しても成功率を維持できる区間がある。また入力画像の256 visual tokenの全てが毎回必要とは限らない。

FlashVLAは、**action-level redundancy**（モデル実行そのものをskip）と**visual token redundancy**（実行する際のtokenを減らす）を組み合わせる。モデル重みの再学習や専用action headの設計変更は必要としない。重要な点として、これは**過去のKV tensorを部分的に接続してprefillを修復する技術ではない**。KV-cache研究の観点では、KV reuseと比較すべき隣接領域の「推論呼び出し回避」である。

## 2. 先行研究との差

- [VLA-Cache](2025-2502.02175-vla-cache.md)：visual patch KVをcross-frameでreuseし、必要なpatchを再計算。FlashVLAはaction全体をreuseする場合がある。
- [DySta](2026-2602.03983-dysta.md)：学習したstatic representationのKVを再利用し、履歴をcompactに保持。FlashVLAはtraining-freeで、長期記憶を明示的に学習しない。
- [EfficientVLA](2025-2506.10100-efficientvla.md)：diffusion denoising step内の中間特徴cacheとlayer/token pruning。FlashVLAは連続する**control step間のaction reuse**。
- [VLA-Pruner](2025-2511.16449-vla-pruner.md)：action attentionを使ってtoken重要度を推定。FlashVLAはSVDベースの情報寄与度で選ぶ。

## 3. 手法

### 3.1 Visual tokenのInformation Contribution Score（ICS）

Vision encoder / projectorが出力するvisual token行列を`T_v ∈ R^(N×d)`とし、`T_v = UΣV^T`とSVDする。各token `x`のスコアを

`C(x) = Σ_(i=1)^r |u_(x,i) σ_i|`

と定義し、上位`K` tokenを残す。主成分への寄与が大きいtokenを保持するという発想であり、token subset `S`のretained information `I(S)=||T_v[S] V_r||_F^2`を動機としている。理論説明はdominant singular subspaceへの射影に基づくが、**action successを最大化する最適解という保証ではない**。

実験では元の256 tokenから192/160/128/96 tokenへ削減。160 token（62.5%）が成功率と速度の最良のバランスと報告される。SVD・選択自体の実装overheadはhardwareやtoken長に依存するため、理論FLOPs削減と実時間短縮を分けて扱う。

### 3.2 FlashTrigger — action再利用の判定

直近2時刻のaction vector `A_(s-2), A_(s-1)`と、選択visual-token index集合`I_(s-2), I_(s-1)`を保存する。

- `α(s) = arccos( A_(s-2)·A_(s-1) / (||A_(s-2)|| ||A_(s-1)||) )`：過去2actionの角度差。
- `φ(s) = |I_(s-2) ∩ I_(s-1)| / |I_(s-1)|`：重要visual token集合の重複率。
- `ε₂ = 1 - δ/|I_(s-1)|`：許容集合変化数`δ`から導くthreshold。

論文Eq. (10)の条件は**`α > ε₁ AND φ > ε₂`なら直前actionをreuse**、そうでなければICSでpruneした入力を用いてVLAを実行する。最初の2フレームではreuseを行わない。実行した場合はaction/token memoryを更新する。

**検証上の注意**：角度差`α`が大きいほどactionが変化したことを示すのに、Eq. (10)は`α > ε₁`でreuseと書かれている。本文の「action consistencyでreuse」という直観と不整合に見えるため、**原文の不等号を勝手に反転せず、コード公開時に実装を照合する必要がある**。また判定には過去2時刻のaction/token集合を用いるので、現在フレームで突然障害物が出現した場合の検知保証はない。

### 3.3 実行フロー

1. 初期2stepはVLAを実行してaction/token memoryを構築。
2. `α`と`φ`を計算してFlashTriggerを判定。
3. Reuse判定なら直前actionを出力し、重いVLA推論をskip。
4. それ以外ならICSでvisual tokenを`K`個にpruneし、prefill/decodeを実行してmemoryを更新。

これにより「skipできないstep」でもpruned inferenceで計算量を抑える。厳密なfull-prefill相当性ではなく、**タスク成功率を許容範囲に維持する近似実行**である。

## 4. Experiment Setup

- **Model**: OpenVLAを対象とするtraining-free推論変更。
- **Benchmark**: LIBERO-Spatial / Object / Goal / Long（各10タスク、Franka Pandaシミュレーション）。本文はVLABenchへの一般化も記述するが主要定量表はLIBERO。
- **Metrics**: task success rate（SR）、visual-token-related FLOPs（10^12）、inference latency（ms）。実機、GPU memory peak、長時間連続control frequencyは主要結果として報告されない。
- **Baselines**: full 256-token OpenVLA、FastVなどのvisual token pruning。主要実験では256/192/160/128/96 tokenのbudget sweep。
- **Training**: 手法のための追加trainingは不要。閾値`ε₁`、`δ`、token budgetは運用上のhyperparameter。

## 5. Main Results（Table 1）

| Visual token | Mean LIBERO SR | FLOPs（×10¹²） | Latency | Baseline比 |
|---|---:|---:|---:|---:|
| 256 (baseline) | 74.4% | 1.31 | 82.7ms | 1.00× |
| 192 | 73.7% | 0.70 | 54.8ms | 1.51× |
| **160** | **73.7%** | **0.58** | **52.9ms** | **1.56×** |
| 128 | 71.0% | 0.46 | 49.0ms | 1.69× |
| 96 | 66.5% | 0.36 | 51.0ms | 1.62× |

160 tokenで**FLOPs 55.7%減、latency 36.0%減、SR 0.7 percentage point減**。96 tokenまで強く圧縮するとSRが7.9pt低下し、latencyも128 tokenより悪化するため、token数削減がそのまま高速化にはならない。

Task別にはObjectで86.4→86.6%、Goalで75.4→78.8%と小幅に改善する一方、Longで51.4→46.8%と**4.6pt低下**する。平均だけで「ほぼ無劣化」と判断せず、長期タスクの脆弱性を見る必要がある。

## 6. Ablation / 分析

### 6.1 2つの加速要素（LIBERO-Spatial、160 token、Table 2）

| Method | SR | FLOPs（×10¹²） |
|---|---:|---:|
| w/o Action Reuse | 83.6% | 0.85 |
| w/o Pruned Inference | 80.6% | 1.01 |
| w/o ActionVector signal | 79.6% | 0.56 |
| w/o TokenSet signal | 74.8% | 0.44 |
| **Full FlashVLA** | **82.6%** | **0.66** |

Action reuseはFLOPs削減に効くが、無条件にreuseを増やすと成功率が落ちる。特にTokenSetを外すと160-token条件でSRが82.6→74.8%と悪化する。2つのsignalは精度と省計算のtrade-offを調整する役割。

### 6.2 FastVとの比較（LIBERO-Object、160 token、Table 3）

- FastV: SR 84.8%、0.85 TFLOPs、79.9ms。
- FlashVLA: SR 86.6%、0.57 TFLOPs、53.1ms。

単なるtoken pruningと比べてaction reuseがさらに効く。ただし別のVLA backboneや異なるcontrol frequencyで同じ効果が出るかは未確定。

## 7. Limitations / 再現上の論点

1. **KV cache reuseとは異なる**。推論を丸ごとskipするaction reuseであり、KVを部分再計算・位置修復する仕組みではない。
2. **Triggerの符号確認**。Eq. (10)の`α > ε₁`は「類似actionならreuse」という直観とずれる。実装が公開されたら閾値方向を要確認。
3. **Current observationの急変**。判定が過去action/token memoryに依存するため、環境が急変したstepで危険なactionを継続する可能性がある。実機安全性の検証が必要。
4. **SVD selection overhead**。実測latencyは得られるが、SVD自体の負担とGPU kernel実装の詳細な分離評価は限定的。
5. **LIBERO-Long**。強いtoken削減で成功率が大きく悪化し、長期依存タスクには保守的budgetが必要。
6. **実機と長時間評価**。主要結果はsimulation。real-robot success、control frequency、VRAM peak、長期cache/driftの検証は不足。
7. **Code**。公式実装の一次情報が確認できないため`code: null`。
