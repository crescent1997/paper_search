# RAISED — Robust Attack Invariance through SElf-Distillation

> **選定:** 自動選定。公開2026-10-05（1年以内）、Pithが引用元論文PROVISOを明示している**少なくとも1件のforward citation**で閾値1件を満たす。Google Scholarの総引用数ではない。arXiv PDF v2 32ページの本文・Appendix・実験表を照合。**★は該当しない**。model-level学習が主対象だが、評価環境はtool-using agentに限定される。

## 概要

SFT/DPOによるprompt-injection防御はASRを下げても、モデルが本来従うべき**tool outputに含まれる正当な次手順**まで避ける場合がある。RAISEDは防御後モデルに新しい「拒否」行動を教えるのではなく、**攻撃が存在しなかった場合の元モデルの振る舞いを、攻撃があっても再現する**よう学習する。生成したtool-use scenarioでteacherを動かし、同じclean trajectoryのtoken分布を攻撃あり/なし両方のstudent入力に蒸留する。model parameter（LoRA）を更新するので、agent harnessにのみ依存するguardrailではない。

## 問題設定 / Threat Model

- 正規user requestとtool-callを処理するagentに、第三者がtool responseの一部を変更して不正命令を挿入。攻撃者はsystem/developer/userの上位roleを直接変更できない。
- 防御の狙いは、外部データ内の命令を機械的に無視することではなく、**正規タスクの遂行に必要な情報・guidanceは利用しつつ、挿入された攻撃命令に行動を変更させない**こと。
- 評価の主対象は**static indirect prompt injection**。target defenseを反復queryして最適化するadaptive attackの頑健性は主張しない。System prompt extraction、user→developer priority spoofing、direct jailbreakは別脅威モデル。
- clean-context teacherの動作を基準とするため、teacher自身が誤ったtool callをした場合にはその誤りも継承する。

## 先行研究からの改善点

- SecAlign++等のDPOやSFTは、防御学習によりbase modelの出力分布をずらし、正規のtool-useまで抑制する場合がある。
- 同じデータ・313 steps・rank16 LoRAでobjectiveのみ変えた比較（Gemma、500 benign questions）では、baseからの**forward KL**がSFT `0.044`、DPO `0.029`、self-distillation **`0.0010`**。top-1 token agreementはそれぞれ`0.953`、`0.968`、**`0.993`**。ただしKL差とutility低下の**因果関係は証明していない**。
- 「tool outputはすべて疑う」というshortcutを防ぐため、正規のtool outputが次の操作を案内するscenario（追加認証、失敗からの復帰、follow-up等）を自己生成して学習する。

## Method / Algorithm

### Stage 1 — Self-Generation

1. frozen base model `p_θ0`を独立した3つの役割で呼ぶ: (i) scenario generator、(ii) solver/verifier、(iii) attacker。role間で内部状態を共有しない。
2. JSON world state、3〜6個のPython tool、end-goalのuser request、success predicateを含む実行可能scenarioを生成。3〜8程度の依存tool callを要求し、**正当なtool guidanceを利用しないと完了しない**taskを増やす。
3. base modelがtoolを実行して正しく完了したtrajectoryだけを保存。攻撃生成器は**untrusted tool outputのみ**を見て挿入内容・位置を決め、user requestや完全な履歴は見ない。
4. 各モデルについて検証済みtrajectory **10,000件**を保持。clean生成過程でteacherのnext-token確率分布を記録。

### Stage 2 — Injection-Augmented Self-Distillation

teacherのclean履歴`h_i`での次token分布を`q_i = p_θ0(.|h_i)`とする。studentの入力`h'_i`はclean履歴`h_i`または攻撃入り`h~_i`のいずれか（attack ratio 0.5）。両方に対して**同じclean teacher分布**を目標とする:

`L(θ) = E_{τ~D} Σ_{i∈I(τ)} D_KL( q_i || p_θ(.|h'_i) )`, `h'_i ∈ {h_i, h~_i}`。

clean入力では元モデルの能力を維持し、injected入力では攻撃の有無に対する**behavioral invariance**を学習する。`q_i`は全語彙ではなくtop-256確率と残余確率1 bucket（257 outcome）で保存し、studentの対応確率でKLを計算する。残余質量は通常約`1e-5`。**元モデルの回答tokenにteacher-forcingする蒸留であり、student自身のrolloutをteacherと完全に一致させる保証はない**。

## Experiment Setup / Compute

- Model: Gemma-4-12B-it、Nemotron-3-Nano-30B-A3B、追加評価Qwen3.8-27B。LoRAはall linear layers、`lr=5e-5`、batch16、10,000 trajectories、1 epoch、attack ratio0.5。
- Baselines: Vanilla、Prompt Sandwiching、Spotlighting、PromptGuard2、SecAlign++。主要結果は3 seedsの平均±標準偏差。
- Security: InjecAgent（1,054 cases）、AgentDojo（workspace/banking/travel/slack）、AgentDyn（shopping/GitHub/daily life）。**ASR↓、clean utility U↑、under-attack utility U_atk↑**を同時報告。
- Benign agentic utility: ToolTalk、BFCL、WorkBench、MMT-Bench、AsyncTool。General utility: MMLU、MMLU-Pro、MMMLU、GPQA、AGIEval、IFEval、GSM8K、Minerva、HumanEval、MBPP。
- Teacher top-256保存: 10,000 traceで約**15GB/model**。GB200 clusterの8 inference workersでteacher生成は1時間未満と報告（学習総コスト・全GPU時間とは区別）。

|---|---|---:|---:|---:|
| Gemma | Vanilla | 84.5 | 64.0 | 39.5 |
| Gemma | SecAlign++ | 77.3±2.2 | 74.8±0.7 | 1.1±0.2 |
| Gemma | **RAISED** | **83.5±0.8** | **80.5±0.5** | **1.0±0.3** |
| Nemotron | Vanilla | 48.5 | 39.9 | 11.7 |
| Nemotron | SecAlign++ | 50.2±1.0 | 47.7±0.7 | 4.0±0.7 |
| Nemotron | **RAISED** | **50.2±1.3** | 46.4±0.6 | **0.5±0.1** |

**AgentDyn（Table 1）:** GemmaではVanilla `U=61.7, ASR=53.4`、SecAlign++ `U=45.6, ASR=1.0`、RAISED **`U=60.0, ASR=1.6`**。NemotronではVanilla `ASR=17.6`、SecAlign++ `7.8`、RAISED **`1.9`**。SecAlign++との主比較は**313-step checkpoint**を採用し、長時間学習でASRをさらに下げる可能性とutility低下をAppendixで別途検証している。

**Qwen3.8-27B追加評価:** AgentDojo ASR **5.8→0.9±0.4%**、AgentDyn **4.2→0.1±0.2%**。もともと低ASRのモデルでも効果を確認。

## Generalization / Robustness / Ablation / Adaptive Attack

- General utility（Gemma、Table 3）: MMLU Vanilla 75.1、SecAlign++ 73.0、RAISED 75.2。IFEval 94.1/94.3/94.3。MBPP 83.4/79.9/82.6。すべてのbenchmarkで厳密に改善するわけではない。
- 同一データ・入力条件でのobjective ablation（Gemma、Appendix Table 14、AgentDyn clean U/ASR）: Glaive SFT **17.5/1.5**、Glaive DPO **48.6/2.3**、Glaive self-distillation **55.5/2.1**、self-generated DPO **55.6/1.6**、**RAISED 60.0/1.6**。学習objectiveとself-generated task distributionの寄与を分離している。
- **Adaptive attack未検証:** PISmithを使う追加試行では多くの設定でrewardが全ゼロになり、最適化が進まなかった。論文はこれを**防御成功の証拠とはしない**と明記（Appendix F）。RL-Hammer/IterInject等による実際の適応的評価は今後必要。

## Limitations

(a) 3 model familyでの評価に限定、frontier-scale未確認。(b) **static**な既存attack corpusに対する結果で、学習時のself-generated attack styleに依存する可能性。(c) clean teacherの誤動作も保存。(d) 10,000 traceの生成とtop-256確率の保存に計算・容量コスト。(e) 通常QAでのKL測定はtool-use utility劣化との因果を直接証明しない。(f) 正当なtool guidanceの取りこぼし事例は例示であり、母集団での発生頻度は未測定。(g) SecAlign++との主表は必ずしも計算budget完全一致ではない。

## LLM Model Security taxonomy / 実装・研究上の示唆

**Defense / model-level training / tool-output trust boundary / clean-behavior invariance / utility preservation**。LLM自身が外部データの命令を過剰に拒否しないようにするには、単にattack-responseを負例にするより**clean modelが正しく行動する分布を教師にする**のが有効という仮説。KV cache研究の観点では、top-256 teacher logitsのオフライン保存量（約15GB/model）と、clean/attacked contextのprefix差分がtraining efficiencyに影響する。なお、この論文はKV cache reuse/圧縮を提案しているわけではない。
