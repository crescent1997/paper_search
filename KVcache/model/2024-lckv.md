# Layer-Condensed KV Cache (LCKV)

## 概要・問題設定
通常のTransformerは全layerでK/Vを生成し、sequence lengthとlayer数に比例したKV cacheを保持する。LCKVは少数layer、極端には**top layerのみ**でKVを生成し、そのKVを他layerのattentionから共有する。

## 手法
top側のhidden statesを使うlayer-condensed sharingでは、下位layerのqueryが上位layerのKVを必要とするため、通常のbottom-up forwardとは異なる依存関係が生じる。LCKVはこの循環的依存に対応するmasking / computation orderを設計する。

```text
ordinary Transformer: layer 0 KV, layer 1 KV, ..., layer N KV
LCKV: selected upper layer KV → multiple layers' Q
```

これは[GQA](2023-2305.13245-gqa.md)のhead-axis削減とは直交する。

## 既存法との差
[Cross-Layer Attention](2024-2405.12981-cross-layer-attention.md)は近接layer groupでbottom側のKVを共有するのに対し、LCKVはupper-layer KVを多数layerから参照する。upper-layer representationを共有できる一方、prefillやtrainingに依存関係処理のcostが生じる。

[YOCO](2024-2405.05254-yoco.md)はdecoder構造を分割し、一度作ったglobal KVを後段で共有する別方式。

## Experiment Setup / Main Results
language modelingおよびdownstream tasksでstandard Transformerと比較し、memory reduction・generation throughput・qualityを測定。論文は**最大26× throughput**を報告する。これは特定の実験条件での最大値であり、単一requestのdecode latencyが26×になるという意味ではない。

## Ablation / trade-off
保持するKV layer数を減らすほどmemory容量とbatch concurrencyは改善する一方、sharing topologyにより品質とprefill costが変化する。top-layer依存の追加計算は長promptで不利になる場合がある。

## Limitations
- architecture/training変更が必要でpretrained checkpointへ単純に適用できない。
- upper-layer KVへの依存はprefill latencyを増やし得る。
- throughput最大値はbatch/memory条件に強く依存する。
