# Connect the Dots: Knowledge Graph-Guided Crawler Attack on Retrieval-Augmented Generation Systems

> RAGから得られた情報をKnowledge Graphとして蓄積し、未探索領域を選択しながら次のqueryを生成することで、RAGの内部Knowledge Baseを効率的に盗み出す攻撃手法 **RAGCrawler** を提案する。

## 概要

RAGではモデル本体だけでなく、Retrieverが参照する非公開corpusにも企業固有文書や専門知識などの重要な情報が保存される。

既存のknowledge-base stealing attackは、RAGの回答からキーワードを取り出し、それについて再度質問するといった**局所的な探索**が中心であり、同じ領域を繰り返し探索してcorpus coverageが早期に飽和しやすい。

本論文はRAGからのcorpus extractionを **Adaptive Stochastic Coverage Problem** として捉え、過去の全応答からKnowledge Graphを構築することで、

> 「次にどのentity / relationを探索すれば新しいknowledgeを得られそうか」

をglobalに判断する **RAGCrawler** を提案する。

## 問題設定

攻撃対象はblack-box RAGで、攻撃者は通常ユーザと同じquery interfaceしか利用できない。

攻撃者は、

- 内部corpus
- retrieveされたdocument
- retrieval score
- Retrieverの内部構造

を観測できず、queryとresponseだけからKnowledge Baseを推測する。

目的は限られたquery budgetの中で、できるだけ広いcorpusを抽出することである。

従来手法では直前のresponseに依存して次のqueryを作るため、既に探索済みのsemantic regionへ何度も戻りやすい。本論文では、この問題を**探索済み領域を記憶した上で未知領域を選ぶcoverage optimization**として扱う。

## 手法

RAGCrawlerは主に3つのcomponentからなる。

### 1. KG-Constructor

各RAG responseから、

- entity
- relation
- entity間のtriple

を抽出し、過去の全responseを統合したglobal Knowledge Graphを構築する。

embedding similarityを用いて同義のentity / relationもmergeする。

このKnowledge Graphが、**「これまでにどのknowledge領域を探索したか」**を表す攻撃者側のstateとなる。

### 2. Strategy Scheduler

自然言語queryそのものを探索する代わりに、**Entity → Relation** という2段階で次のsemantic anchorを選択する。

Entityについては、

- 過去にそのentity周辺を探索した際、どれだけ新しいknowledgeが得られたか
- graph構造上、未知領域へ接続しそうか

などをscore化する。

Relationについても既に探索済みの方向を避け、まだ情報が少ないrelationを優先する。

これにより直前のresponseだけではなく、**攻撃履歴全体を利用したglobal exploration**を行う。

### 3. Query Generator

選択されたentity / relationを自然なqueryへ変換する。

queryは、

- 過去queryと重複しにくい
- Retrieverから新しいdocumentを引き出しやすい
- 明示的なdata extraction requestにならない

ように生成される。

LLM自体に長期的な探索を任せるのではなく、探索方針はKnowledge GraphとSchedulerが担当し、LLMは主にquery generationを担当する。

## 評価

TREC-COVID、SciDocs、NFCorpus、Healthcareなどのcorpusを用い、既存のRAG extraction attackである **RAGThief**、**IKEA** と比較する。

1,000 query budgetでは、RAGCrawlerは平均 **66.8%のcorpus coverage** を達成し、最大で **84.4%** に達する。

strongest baselineに対するcoverage improvementは **44.9%**。

また70% coverageへ到達するためのquery数では、baselineに対して平均で少なくとも **4.03×少ないquery** で済む。

抽出したknowledgeからsurrogate RAGを構築する実験でも、victim RAGの回答を一定程度再現できており、単なる断片的なinformation leakageではなく、**RAG serviceのKnowledge Base自体の複製につながる可能性**を示している。

Retriever変更、query rewriting、multi-query retrievalなどを導入しても攻撃性能は大きく低下しない。

さらにattacker LLMをQwen2.5-7B-Instructへ小型化しても高いcoverageを維持することから、性能向上の主要因は強力なLLMそのものではなく、

- global Knowledge Graph
- exploration strategy
- query redundancyの削減

にあることが示されている。

## まとめ

RAGCrawlerは、RAG Knowledge-Base Stealingを単なるprompt engineeringではなく、**「限られたquery数で未知corpusをどれだけ広く探索できるか」**というcoverage optimizationとして捉えた攻撃手法である。

従来の局所的なquery chainingに対し、過去のresponseからKnowledge Graphを構築して探索済み・未探索領域を管理することで、高いcorpus coverageとquery efficiencyを達成する。

特に重要なのは、個々のqueryは自然な質問に見えるため、単純なprompt filteringだけでは防ぎにくい点である。

RAGの防御では1 query単位の検査だけでなく、**userが複数turnにわたってknowledge spaceを広く探索していないかを監視する仕組み**が必要になることを示唆している。

## 関連文献

- **RAGThief** — RAGから内部Knowledge Baseを抽出する既存attack。本論文の主要baseline。
- **IKEA** — iterativeなquery生成によるRAG knowledge extraction attack。本論文ではglobal Knowledge Graphを利用することでcoverageを改善する。
