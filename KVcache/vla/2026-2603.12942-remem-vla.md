# 概要
ReMem-VLAは、過去の観測が消えてから意思決定を迫られる部分観測操作に対し、毎フレーム更新するframe-level memoryと、action chunk境界で更新するchunk-level memoryを同時に導入する。履歴画像や過去のKV列を増やす代わりに、固定数のlearnable queriesを保持する。短期的な姿勢・局所状態と長期的な初期配置・進捗を異なる時間スケールで扱う点が核心である。

# 問題設定と先行研究との差
標準VLAは現観測と指示からaction chunkを生成するため、初期位置への復帰、既に行った操作回数、経過時間などを忘れる。MemoryVLAはmemory bankから検索するが、現在の観測に検索の手掛かりがない場合や類似した妨害情報がある場合に弱いと著者は指摘する。単純な固定フレーム窓は窓外の履歴を捨てる。ReMem-VLAは検索bankを持たず、recurrent latent stateを時間方向に受け渡す。ただし、どの過去情報が何分後まで正確に残るかを一般的に保証する方式ではない。

# 手法
入力は2視点のRGB、言語指示、必要に応じてproprioception。凍結したQwen3-VL-2B backboneからaction / hindsight / frame-memory / chunk-memoryの4種のquery表現を抽出し、12層のbidirectional connectorで融合する。Action headはdiffusion、hindsight headは過去画像再構成を担当する。

Frame memoryは各stepで固定係数EMAにより更新される。論文の表記では Q^f_t = β_f \tilde Q^f_{t-1} + (1-β_f)Q^f_{t-1}。Chunk memoryはt mod k=0の境界のみ Q^c_t = β_c \tilde Q^c_{t-k}+(1-β_c)Q^c_{t-k} と更新し、他では前状態を保持する。固定のEMA経路と凍結backboneによって、短いTBPTTでも長期の状態伝播自体を維持する。学習するのは何をqueryへ書き込むかであり、更新関数の自由度は制限する。

学習損失はdiffusionのnoise prediction MSEと、過去RGB画像の再構成MSE（係数λ_img=0.5）の和。後者は過去の視覚情報をlatent stateに保持させる教師信号であり、実行時に毎回過去画像を復元する必要はない。Slot-based streaming trainingでは各batch slotが独立episodeを時系列順に進め、episode終了時にstateをresetする。セッションをまたぐ永続記憶ではない。

# Experiment Setup
MemoryBenchのPut Block Back / Rearrange Block / Reopen Drawerに、600フレーム超のLong Horizon Taskを追加。各タスク100 demonstrations、4タスク共同150k steps、各100 rollouts。比較対象はOpenVLA-OFT、π0.5、MemoryVLAで、同じデータ・評価プロトコルで再現したと記載。ただしベースモデルや構造は完全一致しない。元のMemoryBenchを修正し、button-position randomizationを70%へ縮小、Rearrange Blockの軌跡も統一しているため、原ベンチの結果と混同できない。

実機はUR5 + Robotiq、RealSense D435の2視点、各タスク200 demonstrations、各50 trials。Water Flower（時間）、Scoop Rice（回数）、Press Buttons（順序・時間）、Return Fruit（視覚）の4課題。学習は8×A100、batch 64、TBPTT=1、action chunk=30、DDIM 20 steps。単一RTX 4090で約10 Hzの推論、chunkを中間stepで再利用すると実効制御周期は約20 Hzと報告。

# Main Results
| 方法 | Put Block Back | Rearrange Block | Reopen Drawer | Long Horizon | 平均 |
|---|---:|---:|---:|---:|---:|
| OpenVLA-OFT | 0 | 0 | 3 | 0 | 0.75 |
| π0.5 | 6 | 4 | 20 | 3 | 8.25 |
| MemoryVLA | 0 | 1 | 5 | 0 | 1.5 |
| ReMem-VLA | 93 | 99 | 100 | 86 | 94.5 |

値は成功率（%）。実機4課題の平均成功率はReMem-VLA 82.5%、MemoryVLA 8%、π0.5 11%と報告。ただしこの差はメモリ設計だけの純粋な因果効果を示すものではなく、訓練・モデル設計差も考慮すべきである。GPU peak memory、latency内訳、throughput比較の厳密な表は確認できない。

# 主要ablation
| 設定 | 4課題平均成功率 |
|---|---:|
| Recurrent queryなし | 17.75% |
| Frameのみ | 87.75% |
| Chunkのみ | 84.5% |
| Dual-level | 94.5% |

総query数を128に固定（dualは64+64）。Frameのみでは長期保持、chunkのみでは直近操作が弱い。Past Observation Predictionを外すと実機Return Fruit成功率が82%から34%へ低下。EMA係数はβ=0.5が最良、query総数は128が最良、chunk更新間隔はaction chunk長×1が最良と報告。GRU/MLPなど学習可能なrecurrent経路やbackbone unfreezeは長期記憶性能を悪化させた。

# Limitations
一般化評価は大規模ロボット事前学習なしの限定タスク。長時間の連続運用やepisode間記憶、忘却・上書き耐性の定量保証はない。更新を固定EMAにすることは長期安定性に寄与する一方、状態が有限である以上、履歴の厳密復元はできない。GPU memory・推論latencyのMemoryVLAとの直接比較は不足。PDF直接取得は環境制約で失敗したため、arXiv公式HTMLの本文・表・ablationを精査した。付録のPDF固有の詳細は未確認。
