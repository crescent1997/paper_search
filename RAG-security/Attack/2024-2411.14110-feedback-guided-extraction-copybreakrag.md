# Feedback-Guided Extraction of Knowledge Base from Retrieval-Augmented LLM Applications

> 初期版では **RAG-Thief** と呼ばれていたknowledge-base stealing attackを発展させた研究。改訂版では手法名を **CopyBreakRAG** とし、RAG responseから得られたchunkを攻撃側memoryへ蓄積し、そのfeedbackを使って次queryを自動生成することで、black-box RAGのknowledge baseを逐次的に復元する。

## 概要

RAG applicationでは、企業内部文書、専門家知識、医療case、著作物、manualなど、構築コストの高い情報が外部knowledge baseへ保存される。通常ユーザは質問への回答だけを受け取るが、retrieved chunkはLLM contextへ投入されるため、適切なpromptを与えればchunk自体をverbatimに出力させられる可能性がある。

既存のdata extraction attackには大きく2種類ある。

- random / structured queryを大量に投げ、retrieveされたtextを出力させるquery-based attack
- embedding modelへアクセスしてquery embeddingを最適化するembedding-based attack

前者はblack-boxで現実的だがcoverageが低く、後者はcoverageを上げられる一方でembedding modelへのwhite-box accessを必要とする。

本論文はこのgapを埋めるため、**feedback-guided black-box extraction** を提案する。攻撃者は一度抽出したchunkを次のquery生成へ再利用し、knowledge base内のsemantic neighborhoodを探索する。またlocal regionへ閉じ込められないよう、未知topicへ移るexplorationも組み合わせる。

## Threat Model

対象は一般的なRAG applicationで、

```text
User Query
   ↓
Retriever
   ↓
Knowledge Base
   ↓ retrieved chunks
Generator LLM
   ↓
Response
```

という構成を持つ。

攻撃者は通常userと同じinterfaceだけを利用するblack-box attackerである。

攻撃者が利用できないものは、

- knowledge baseのraw content
- embedding modelのparameter
- document / chunk ID
- retrieval score
- internal promptやpipelineの詳細

である。

攻撃者が利用できるのは、queryとresponseのみである。

目的は限られたquery budgetの中で、knowledge baseに含まれるoriginal chunksを可能な限り高い割合でverbatimに回収することである。

## CopyBreakRAG

CopyBreakRAGはagent-based attackとして構成される。

全体の流れは、

```text
Anchor Query
   ↓
Adversarial Extraction Prompt
   ↓
Victim RAG
   ↓
Response
   ↓
Chunk Parsing / Deduplication
   ↓
Attack Memory
   ↓
Query Planner
   ├─ Curiosity-driven Exploration
   └─ Reasoning-based Exploitation
   ↓
Next Anchor Queries
```

となる。

### 1. Extraction command

anchor queryそのものだけでは、RAGは通常どおり質問へ回答するだけでretrieved contextを直接出力しない。

そこでCopyBreakRAGはanchor queryへadversarial commandを追加し、LLMにretrieved contextを特定formatで出力させる。

この部分は「Follow My Instruction and Spill the Beans」で示されたcontext disclosure primitiveに近い。

CopyBreakRAGの主な新規性は、**どのanchor queryを次に投げるかをfeedbackから自動的に決めること**にある。

### 2. Attack memory

responseから抽出されたchunkはattack agentのlong-term memoryへ保存される。

同一または非常に類似したchunkはdeduplicateし、既に回収した情報を繰り返し数えない。

このmemoryは、

- 現在knowledge baseのどのsemantic regionを探索しているか
- どのtopicを既に十分掘ったか
- どこから新しいqueryを派生できるか

を判断するfeedbackとして利用される。

### 3. Curiosity-driven Exploration

既に抽出したchunkに近いqueryだけを生成すると、semantic spaceの局所領域へ閉じ込められる。

そこでexploration phaseでは、既知chunkから意図的にsemantic divergenceを持つqueryを生成する。

目的は、まだ到達していないtopic clusterへretrieverを移動させることである。

このphaseはknowledge base全体のcoverageを広げる役割を持つ。

### 4. Reasoning-based Exploitation

一方、特定regionで有用なchunkを取得できた場合、そのchunkの文脈から周辺chunkへ移る方が効率的である。

exploitation phaseでは、LLMに抽出済みchunkを読ませ、そこから関連する新しい質問を生成する。

論文ではforward / backward reasoningを利用し、document sequenceやsemantic relationを推測しながらneighboring informationをretrieveさせる。

例えば、あるclinical caseの途中部分を取得した場合、

- その前に何が起きたか
- その後どの治療が行われたか
- 関連する症状や診断は何か

といったqueryを作り、近接chunkを引き出す。

### 5. Exploration / Exploitation Switching

CopyBreakRAGでは2つのstrategyを固定的に使うのではなく動的に切り替える。

論文では、

- probability-based switching
- frequency-based switching

を評価する。

exploitationを続けすぎてlocal optimumへ入った場合にexplorationを挟むことで、新しいsemantic clusterへ移動する。

これは後続のRAGCrawlerがより明示的なglobal planning / coverage optimizationへ発展させた考え方と近い。

## Chunk Reconstruction

RAG frameworkごとにsystem promptやcontext formattingは異なる。

CopyBreakRAGはLangChainなどpopular frameworkのprompt templateを収集し、それぞれに対応するregular expressionを用意してresponseからretrieved text blockを自動抽出する。

抽出後はtext segmentationとdeduplicationを行い、original chunk単位へ近づける。

ここまでをagent loopへ組み込むことで、人手でresponseを確認しながら次promptを作る必要をなくしている。

## 実験

### Local RAG applications

healthcare / personal assistantなどのknowledge baseを用いてlocal RAG applicationsを構築し、既存attackと比較する。

主要指標は **Chunk Extraction Ratio (CER)** で、元knowledge base中のchunkのうちどの程度を回収できたかを測定する。

CopyBreakRAGはstate-of-the-art black-box baselineに対して平均約45 percentage points高いchunk extraction ratioを達成する。

200 query程度のbudgetでも、datasetによって約60〜80%規模のchunkを回収できる。

特にdocument内に前後関係やsemantic continuityが強いdatasetでは、reasoning-based exploitationが有効に働く。

### Commercial RAG platforms

OpenAI GPTsおよびByteDance Coze上にも著者自身がpublic dataだけを使ったRAG applicationを構築し、production-like settingで評価する。

platform側にbasic protectionが存在する場合でも、CopyBreakRAGはknowledge baseの70%以上を抽出できると報告する。

この実験の重要点は、embedding modelやretrieval implementationを知らないcommercial black-boxでもattackが成立することである。

## Defense Evaluation

### Verbatim overlap filtering

retrieved contextとoutputの文字列overlapが大きい場合にblockするようなdefenseを考えることができる。

しかしattackerは、

- output formatを変更する
- chunk間にdelimiterを入れる
- minor transformationを加える

ことでfilterを回避できる。

論文の評価では単純なstring-based filteringを導入してもextraction ratioはほとんど低下せず、表層的なverbatim detectionだけでは不十分である。

### Query filtering

malicious prompt patternを検知する方法も考えられるが、CopyBreakRAGのanchor query自体は自然なinformation-seeking queryとして生成できる。

そのため「内部文書を出せ」と直接要求するqueryだけをblockしても、adaptive attackerには十分でない。

## Limitations

1. **Context leakage primitiveに依存する**  
   victim generatorがretrieved chunkをほぼverbatimに出力できることが前提である。強いoutput sanitizationがあるsystemでは性能が低下する可能性がある。

2. **Coverageはknowledge-base structureに依存する**  
   semantic relationが弱く、互いに独立したchunkが大量に存在するdatabaseではexploitationからneighborを見つけにくい。

3. **Query costが必要**  
   高coverageには多数のRAG callsとattacker-side LLM callsが必要となる。

4. **Regex-based chunk parsingはframework依存性を持つ**  
   未知のprompt templateや強く変形されたoutputではchunk recognitionが不安定になり得る。

## RAG Data Extraction Riskとの関係

本論文は今回の調査目的に最も直接的に該当するattackの一つである。

「Follow My Instruction and Spill the Beans」が、**retrieveされたchunkを1回のresponseからどう漏らすか**を示したのに対し、CopyBreakRAGは、

> どのqueryを順番に投げれば未知のknowledge baseを広く盗めるか

をattack planning問題として扱う。

attack chainは、

```text
Initial Query
   ↓
Retrieve + Leak
   ↓
Extracted Chunk
   ↓
Feedback Memory
   ↓
Adaptive Query Generation
   ↓
New Semantic Region / Neighbor Chunk
   ↓
Repeated Leakage
   ↓
Knowledge Base Reconstruction
```

となる。

そのため単発のprompt injectionを防ぐだけでなく、

- repeated-query behavior
- corpus coverage pattern
- semantic traversal pattern
- output-level information release

をまとめて監視する必要がある。

## 重要なポイント

- RAG-Thiefの改訂版で、現在の手法名はCopyBreakRAG。
- black-box APIのみでknowledge base extractionを自動化する。
- 抽出済みchunkをlong-term memoryとして利用するfeedback-guided attack。
- curiosity-driven explorationで新しいsemantic clusterを探索する。
- reasoning-based exploitationで取得済みchunkのneighboring informationを掘る。
- exploration / exploitationを動的に切り替えてlocal semantic regionへの停滞を防ぐ。
- local RAGで既存black-box attackより約45 percentage points高いextraction ratioを報告。
- commercial platformsでも70%以上のknowledge base extractionを報告。
- simple string overlap / prompt filteringでは防御が難しい。
- 後続のRAGCrawlerなど、knowledge-base stealingをglobal explorationとして扱う研究につながる重要な位置づけにある。
