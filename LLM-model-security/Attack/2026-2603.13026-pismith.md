# PISmith: Reinforcement Learning-based Red Teaming for Prompt Injection Defenses

## 概要

PISmithはprompt-injection Defenseを固定attack setだけで評価する問題を扱い、**Defenseごとにattack LLM自体をreinforcement learningで適応させるblack-box red-teaming framework**を提案する。

attackerはdefended LLMへqueryを送りoutputを観測できるだけで、target modelのweights / gradients / logitsへのaccessを必要としない。したがって[GCG](2023-2307.15043-gcg.md)のwhite-box discrete token optimizationとは異なり、自然言語attack generatorをDefense-specificに学習する。

## 問題設定 / Threat Model

trusted taskとuntrusted dataを同一contextへ入れるLLM applicationを想定する。attackerはuntrusted portionへinstructionを埋め込み、original taskではなくattacker-selected taskを実行させようとする。

DefenseがStruQ / SecAlign / Meta SecAlign等でprompt-data privilege separationを学習していても、公開済みattackだけで評価するとDefense-specific failure modeを見逃す可能性がある。

PISmithではattackerは、

- Defenseの内部parameterを知らない
- gradient / logitsを取得しない
- defended modelへquery可能
- responseからattack success rewardを得る

というpractical black-box settingでattack policyを最適化する。

## GCGとの違い

[GCG](2023-2307.15043-gcg.md)はtarget lossのgradientから候補tokenを選び、adversarial suffixを離散最適化する。

PISmithはsuffix tokenを直接gradient optimizationせず、attack LLMが自然言語injectionを生成する。

```text
GCG:
  white-box target gradients
  -> discrete adversarial suffix

PISmith:
  black-box target queries
  -> RL-trained attack generator
  -> adaptive natural-language injection
```

このためclosed-source modelにも適用できる一方、多数のqueryとRL training costを要する。

## なぜ通常のGRPOでは失敗するか

強いDefenseでは初期attack policyが生成するほぼ全てのinjectionが失敗する。

するとgroup内rewardがほぼ同一になり、

- useful advantage signalが消える
- policy entropyが早期に低下する
- rare successful rolloutを十分強く学習できない

というreward sparsity問題が生じる。

PISmithはこの2点を直接補正する。

## Adaptive Entropy Regularization

attack successが低いtraining stageではentropy regularizationを強め、attack policyが狭いprompt patternへcollapseすることを防ぐ。

成功率が上がるにつれて探索pressureを調整し、explorationとexploitationを切り替える。

狙いは強いDefenseに対し、既知の失敗promptを微修正し続けるのではなく、新しいattack strategyを探索し続けることである。

## Dynamic Advantage Weighting

reward sparsity下では稀なsuccessful rolloutが重要である。

PISmithはsuccessful sampleのadvantageを動的に増幅し、少数のbreakthroughからpolicyが学習しやすくする。

つまり、

```text
many failures
   +
rare success
      ↓
standard GRPO:
  success signal diluted

PISmith:
  amplify rare-success advantage
```

という設計になる。

## Attack Primitive

attack primitiveは固定suffixではなく、attack LLMが生成する**semantic prompt injection**である。

injectionはtarget applicationのuntrusted contextへ挿入され、trusted taskからattacker taskへbehaviorを切り替えることを狙う。

このため一般的jailbreakよりも、trusted instruction / untrusted dataというprivilege boundaryを直接攻撃する。

## White-box / Black-box条件

### Target model

- weights: 不要
- gradients: 不要
- logits: 不要
- hidden states: 不要
- output query access: 必要

したがってtarget Defenseに対してblack-boxである。

### Attack model

attack generator自体はRL training可能なmodelを使用する。attacker側modelのparameter更新は必要だが、target modelをwhite-box化する必要はない。

## Query / Compute Cost

GCGのようなtarget-gradient computationは不要だが、RL rolloutのため多数のdefended-model queryが必要になる。

DefenseがAPI modelの場合はquery cost / rate limitがattack budgetになる。

したがって「gradient-free = cheap」ではなく、compute costをattack model trainingとtarget queriesへ移した手法と捉えるべきである。

## Experiment Setup

13 benchmarkで評価し、QA / RAG / long-context / agentic settingを含む。

Defense側には複数のprompt-injection Defenseを用い、static attack、search-based attack、RL-based attackを含む7 baselineと比較する。

さらにInjecAgent / AgentDojoでtool-using agentへのtransferを評価し、open-sourceだけでなくclosed-source LLMも対象とする。

## Main Results

PISmithは複数Defense / benchmarkで既存attack baselineより高いASRを示し、static evaluationでrobustに見えたDefenseもadaptive optimizationで大きく破られることを示す。

特にMeta SecAlignのようなstrong model-level Defenseに対しても高いattack successを報告する。

後続の[SecOPD](../Defense/2026-2608.21500-secopd.md)はPISmithを主要adaptive evaluationとして採用し、Meta SecAlignで94.0% ASR、SecOPDで9.0% ASRと報告している。

## Transferability

PISmithの中心はuniversal fixed promptのmodel-to-model transferより、**Defenseへのonline/adaptive optimization**である。

一方、agent benchmarkやclosed-source modelへも適用できることから、attack generatorのstrategyが特定open-weight targetのgradient artifactだけに依存しないことを示す。

GCGのtransferabilityとは性質が異なるため区別が必要である。

## StruQ / SecAlign / Meta SecAlignとの関係

[StruQ](../Defense/2024-2402.06363-struq.md)はtrusted prompt / untrusted dataを構造化し、[SecAlign](../Defense/2024-2410.05451-secalign.md)と[Meta SecAlign](../Defense/2025-2507.02735-meta-secalign.md)はpreference optimization等でこのseparationをmodelへ学習させる。

PISmithはこれらのDefenseが持つ**residual decision boundary**をblack-box RLで探索する。

したがってDefense evaluationでは、

```text
static known attacks
       ↓ insufficient

defense-aware adaptive attack
       ↓
PISmith
```

というstress testが必要になる。

## The Attacker Moves Secondとの関係

[The Attacker Moves Second](2025-2510.09023-attacker-moves-second.md)はDefense公開後にattackerが適応することを前提とし、gradient / RL / search等をDefenseごとに再最適化する必要性を示す。

PISmithはその思想を、reward-sparseなprompt-injection Defenseに特化したRL algorithmとして具体化した位置づけになる。

## Instruction Hierarchyとの関係

[The Instruction Hierarchy](../Defense/2024-2404.13208-instruction-hierarchy.md)はhigher-priority instructionを優先するbehaviorをmodelへ学習する。

PISmithは明示的role hierarchy benchmarkだけを攻撃する手法ではないが、prompt injectionにおけるtrusted task > untrusted injected instructionというpriority relationを破る。

そのためmodel-level privilege mechanismのadaptive robustnessを測るAttackとして本repositoryのscopeに入る。

## Limitations

- black-boxだが多数のtarget queriesを必要とする。
- attack success judgeの品質に結果が依存する。
- RL training costがあり、one-shot attackより高価。
- benchmark上のattacker taskが実世界の全attack objectiveを代表するわけではない。
- Defenseごとにadaptive trainingするため、完全universalなattackではない。
- tool permission / sandbox等のsystem-level enforcementを直接破るものではない。
- PISmith自身を想定した将来Defenseとのarms raceは継続する。

## LLM Model Security Taxonomyでの位置づけ

```text
GCG
  white-box adversarial suffix
        ↓
The Attacker Moves Second
  defense-aware adaptive evaluation
        ↓
PISmith
  black-box RL adaptive prompt injection
        ↓
SecOPD
  train against token-level adaptive failure
```

## 実装・研究上の示唆

prompt-injection Defenseを評価する際は、公開済みattack promptの固定集合だけでASRを測るべきではない。

少なくとも、

1. Defense-aware search
2. RL-based attack generation
3. query budgetを明示したblack-box evaluation
4. unseen domain / agent settingへのtransfer
5. attack judgeのvalidation

を含める必要がある。
