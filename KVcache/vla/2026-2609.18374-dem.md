# DEM — Vision / Language / Actionの分離による高速policy

## 概要・問題設定
毎制御stepで数十億パラメータのVLM backboneを実行する代わりに、視覚・言語を独立にencodeし、コンパクトなaction headへ条件づける。重要な点は**instructionが不変ならNeoBERT出力をcacheして次のstepで再利用できる**こと。これはTransformer層のKV cache再利用ではなく、**encoder output / instruction embedding reuse**。さらにMeanFlowの1-pass action chunk生成でdecodeコストを抑える。

## 先行研究との差
- [TurboVLA](2026-2607.27205-turbovla.md)もLLM-freeのdirect vision-language-action。DEMはRoboCasa 18タスクで七つのbaselineを同一学習・評価条件に揃え、latency/energyを測定する点が強い。
- [VLA-Cache](2025-2502.02175-vla-cache.md)と[DySta](2026-2602.03983-dysta.md)はLLMのvisual KV再利用。DEMのcacheは言語encoder出力であり、画像ごとの視覚KVをcacheしない。
- [A1](2026-2604.05672-a1.md)は既存VLMをearly exit。DEMはVLM backbone自体を排除し、MeanFlow action headで1-pass化。
- [MemoryVLA](2025-2508.19236-memoryvla.md)や[MEM](2026-2603.03596-mem.md)の長期記憶と異なり、履歴保持機構はない。

## Method
- **Vision**: DINOv3 ConvNeXt-Bのstage-3特徴（256×256入力から16×16×512）を使用。2 cameraで512 visual tokens。事前学習から初期化してfine-tune。
- **Language**: NeoBERT 222M、最大32 tokens、凍結。命令が変わる時だけencodeし、固定命令中はtokensを再利用。VLMと異なり画像による再エンコードが不要。
- **Action**: Cross-attentionで視覚・言語を融合し、robot stateとともにMeanFlowへ入力。通常のflow matchingが速度場を複数step積分するのに対し、MeanFlowは区間平均速度を学習してaction chunkを1 forwardで予測する。
- 学習要否: **policyおよびvision encoder/action headの学習が必要**。training-free KV cache手法ではない。

## Experiment Setup
RoboCasa 18 atomic manipulation tasks。未知の命令paraphraseとrandomized sceneで評価、各task100 rollout。baseline七方式とdemonstration、training-step budget、評価protocol、GPUを揃える。実機はxArm 7 + linear railのdrawer/lamp/cabinet 3タスク、各方式・各タスク50試行。速度・推定GPU energyはRTX PRO 6000、batch 1、policy forwardを計測。言語token cache有無を分ける。

## Main Results
| Method | RoboCasa成功率 | Latency (ms) | Calls/s | GPU energy (J/call) |
|---|---:|---:|---:|---:|
| π0.5 | 54.6% | 103.3 | 9.7 | 31.68 |
| GR00T N1.7 | 56.9% | 51.8 | 19.3 | 13.71 |
| TurboVLA（同一条件再評価） | 46.3% | 19.5 | 51.2 | 3.06 |
| **DEM / instruction cached** | **55.6%** | **6.1** | **162.7** | **2.07** |
| DEM / per-step text encoding | 55.6% | 10.4 | 96.0 | 3.09 |

実機平均はDEM 66.0%（99/150）、GR00T N1.7 68.0%（102/150）、π0.5 63.3%、TurboVLA 53.3%。差が小さくseed間分散も未測定なので、成功率で優劣を断定しない。6.1msの逆数は理論的なpolicy calls/sであり、ロボット全体の閉ループ周波数ではない。

## Ablation
- **Vision encoder**: DINOv3 ConvNeXt-B frozen 32.6%→fine-tuned 55.6%。fine-tuningが大きく寄与。DINOv3 ViT-B/16 54.1%、SigLIP-So400M 53.9%、Qwen3-VL vision tower 51.8%。
- **Language**: 言語なし11.3%、one-hot task code 37.4%、T5 44.5%、BERT 47.8%、mmBERT 50.6%、NeoBERT frozen 55.6%、fine-tuned 55.1%。言語の意味的汎化が必要で、NeoBERT微調整の利得は確認できない。
- **Action head**: Diffusion Policy 16 passes / 53.8% / 26.9 calls/s、Flow Matching 10 passes / 54.7% / 40.3 calls/s、ACT 1 pass / 52.4% / 164.4 calls/s、MeanFlow 1 pass / 55.6% / 162.7 calls/s。主要なlatency差はheadの反復回数。
- **Chunk length**: H=16,8,4,2,1の成功率55.6%,55.9%,52.7%,51.4%,50.6%。短縮とともにreplan intervalも変わるため独立効果ではない。

## Limitations / taxonomy
- 18個の学習済みスキルとheld-out paraphraseに限定。未知タスクの一般化・長期記憶・多段計画は未検証。
- GPU energyは**推定値**。システム全体の消費電力・バッテリー寿命の直接計測ではない。
- **KV taxonomy: VLA / architecture + instruction feature reuse**。Transformer KVのcross-frame reuseやKV compressionは未実装。
- GPU/benchmark/学習条件の違うTurboVLAの論文中RTX 4090計測と、DEM内のRTX PRO 6000計測を混同しない。
- 追加学習が必要で、KV cacheのプラグイン的高速化と導入条件が異なる。
