# DynamicKV: Task-Aware Adaptive KV Cache Compression for Long Context LLMs

## 概要
DynamicKVは、QA、summarization、synthetic retrieval、code completionでlayerごとのattention activation patternが異なることに着目し、固定budgetや固定pyramidではなく、推論中のattention statisticsに応じて各layerへ割り当てるKV数を動的に更新する。model weightの変更やfine-tuningは不要。

## 問題設定
[SnapKV](2024-2404.14469-snapkv.md)はobservation windowから重要tokenを選択するがlayer budgetは基本固定。[PyramidKV](2024-2406.02069-pyramidkv.md)はlower layerを厚くupper layerを薄くする非均一allocationを導入したが、その形状はtask/inputに対して固定的である。DynamicKVは「どのtokenを残すか」に加えて「どのlayerに何token残すか」をruntimeに適応させる。

## 手法
各layerでrecent observation windowから過去tokenへのattentionを集約し重要token候補を得る。現在処理中のlayerでは一旦per-layer maximumまでKVを保持し、一定間隔でそれまでのlayerのimportance statisticsを比較してglobal budgetを再配分する。

```text
attention observation → layer demand推定 → global budget再配分 → 各layerで重要tokenを保持
```

固定pyramidではなくinputから得たsignalでallocationを決める点が中心的な差分。

## PyramidKVとの差
| | PyramidKV | DynamicKV |
|---|---|---|
| layer allocation | depth依存の固定pyramid | task/input依存で動的 |
| token importance | attention-based | attention-based |
| runtime statistics | selection中心 | allocationにも利用 |
| fine-tuning | 不要 | 不要 |
| 主眼 | layer axis導入 | layer budgetのtask adaptation |

技術系譜は **SnapKV → PyramidKV → DynamicKV**。PyramidKVの「layerごとに必要量が違う」を「必要量はtaskごとにも違う」へ拡張する。

## Experiment Setup
LongBench、Needle-in-a-Haystackを中心にLlama-3-8B-Instruct、Mistral-7B-Instruct-v0.2、Qwen2-7B-Instruct、InternLM-2.5-7B-Chat-1Mを評価。StreamingLLM、SnapKV、PyramidKV等と比較する。

## Main Results
LongBenchではfull KVの1.7%保持でFullKVに対しLlama-3-8B約90%、Mistral-7B 87%、Qwen2-7B 78%、InternLM 83%の性能を維持。6.9%ではFullKVとの差が小さい。Needle-in-a-HaystackではMistral-7Bで0.9%という極端な圧縮時にも既存SOTAを約11ポイント上回る。

## Ablation / Analysis
task別のlayer-wise attention visualizationではsummarization、QA、synthetic retrieval、codeで保持すべきlayer分布が異なる。固定pyramidよりdynamic allocationが有利で、compressionが強いほど差が顕在化する。global budgetとper-layer maximumの併用で単一layerへの極端な集中も防ぐ。

## Serving上の意味
layerごとにcache lengthが異なりruntimeでも変化するため、PagedAttention系ではlayer-specific allocation/freeや可変長metadataが必要。一方KV容量だけでなくdecode時のread量も減らせる可能性がある。dynamic redistributionとstatistics収集は追加overhead。

## Limitations
- attention statistics収集・再配分にruntime overhead。
- layer-wise variable cacheはserving runtimeを複雑化。
- eviction後に将来重要になるtokenを復元できない。
- task/input pattern推定が短いobservationで常に安定するとは限らない。
- production serving throughput評価は限定的。

## KV-cache taxonomyでの位置づけ
**compress / token eviction / dynamic layer-wise budget / attention-based / training-free**。
