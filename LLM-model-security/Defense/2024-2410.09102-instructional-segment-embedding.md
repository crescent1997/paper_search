# Instructional Segment Embedding: Improving LLM Safety with Instruction Hierarchy

> Instruction hierarchyをtraining examplesだけで暗黙的に学習させるのではなく、各tokenがsystem instruction・user instruction・untrusted dataのどのsegmentに属するかをlearnable embeddingとして入力表現へ直接加える。priority情報をarchitecture-level signalにすることで、低権限instructionによるoverrideを抑えながら通常のinstruction-following性能も維持・改善する。

## 概要

LLMは通常、system message、user prompt、retrieved/tool dataを最終的には同じtoken embedding系列として処理する。このため入力形式上role delimiterが存在していても、モデル内部には「このtoken列は高権限」「こちらはuntrusted data」という明示的なpriority表現が保証されない。

本論文はこの問題をBERTのsegment embeddingに近い発想で解決する **Instructional Segment Embedding (ISE)** を提案する。token embeddingとposition embeddingに加え、instruction type / priorityを示すsegment embeddingを加算し、Transformer全層へその情報を伝える。

## 問題設定 / Threat Model

対象は、低priority入力が高priority policyを上書きすることで生じるprompt injection、system prompt extraction、harmful requestである。典型的にはsystem instructionをdeveloper側が制御し、user instructionや外部dataはより低いtrust levelを持つ。

attackerは低priority segmentにmalicious instructionを置けるが、高priority system segmentそのものを書き換えられないと仮定する。したがって目的はcontent filteringではなく、**同じ自然言語instructionでもsource privilegeに応じて異なる扱いをモデルに学習させること**である。

## 先行研究からの改善点

直接の基盤となるのが [The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md) である。同研究はContext Synthesis / Context Ignorance等のsynthetic training dataによって、モデルが高priority instructionを優先する振る舞いを学習することを示した。

ISEの問題意識は、それでもpriorityがtraining distributionとrole delimiterから暗黙に推定されている点にある。そこで、

```text
Instruction Hierarchy training
  priorityをexamplesからbehaviorとして学習
              ↓
Instructional Segment Embedding
  priorityをinput representationにも明示的にencode
```

と拡張する。delimiterだけを追加する方式と異なり、segment identityが各tokenのcontinuous representationへ直接入る。

## Method / Algorithm

通常のdecoder-only Transformerの入力を概念的に

```text
h_i^0 = TokenEmb(x_i) + PosEmb(i)
```

とすると、ISEでは

```text
h_i^0 = TokenEmb(x_i) + PosEmb(i) + SegmentEmb(s_i)
```

とする。`s_i` はtoken iが属するinstruction segment / privilege classを表す。

重要なのは、segment embeddingが単なる特殊tokenではないことである。特殊tokenではpriority signalがsequence中の限られた位置にしか現れず、モデルがそれを長距離に伝播させる必要がある。ISEではsegment内の各tokenに同じpriority representationが加わるため、attention計算の入力段階からsource distinctionを利用できる。

論文では既存pretrained LLMへ小規模なarchitecture modificationを施し、ISEを含む形でfine-tuningする。比較対象として通常training、delimiter等によるsource separation、instruction-hierarchy系trainingを置き、ISE単独またはhierarchy-oriented dataとの組合せを評価する。

## Experiment Setup

Llama-2 / Llama-3 / Llama-3.1系列を中心に評価する。security側では主に二系統のbenchmarkを利用する。

- **Structured Query**: trusted instructionとuntrusted dataを分離し、data側に埋め込まれたinstructionへの耐性を見る。
- **Instruction Hierarchy benchmark**: direct / indirect prompt injection、system prompt extraction、harmful request等、高低priority instructionが競合するケースを評価する。

通常能力への副作用はAlpacaEvalで確認する。主要metricはattack時にも高priority instructionを守れるrobust accuracyであり、単なる拒否率ではなくclean / benign instruction-followingとの両立を見る。

## Main Results

ISEはStructured Query benchmarkで平均robust accuracyを最大 **15.75ポイント**、Instruction Hierarchy benchmarkでは最大 **18.68ポイント**改善する。

代表的なclean-training settingでもindirect prompt injectionに対する平均robust accuracyが **50.84% → 66.35%**、worst-caseが **4.81% → 40.38%**へ改善し、特定attack templateだけへのmemorizationでは説明しにくい改善を示す。

さらにAlpacaEvalでは通常のinstruction-following能力が最大 **4.1ポイント向上**する。したがってpriority signalを追加することが「安全のため低priority入力を広く無視する」だけではなく、入力構造を明確にすることで通常taskにも有益である可能性が示される。

## Generalization / Robustness / Over-refusal

ISEの重要な評価点は、trainingで直接見たattack wordingだけでなく、複数のprompt injection / extraction settingへ改善が広がることである。architecture側にsource identityを持たせるため、特定の文字列patternをmaliciousと分類するfilterよりattack surfaceを一般化して扱える。

一方でsegment label自体はapplication側が正しく付与する必要がある。trusted / untrusted boundaryを誤って指定すれば、モデル内部のhierarchyが正しくても安全性は保証されない。

## Limitations / 成立条件

ISEはmodel architectureを変更するため、API-only proprietary modelへ後付けすることはできない。また既存checkpointをそのまま使うだけではなく、segment embeddingを利用するtraining / fine-tuningが必要になる。

さらにpriorityはsegment labelとして外部から与えられる。tool outputの一部だけがtrustedである、複数agentから異なるauthorityのinstructionが来る、といったfine-grained settingでは固定された少数segmentだけでは不足しうる。

安全性も「higher privilegeを常に優先する」というpolicyが正しいことを前提とする。高権限system promptそのものが悪意ある場合や、権限付与機構が侵害された場合は対象外である。

## LLM Model Security Taxonomyでの位置づけ

```text
Prompt formatting / delimiters
        ↓
Hierarchy-aware behavioral training
  The Instruction Hierarchy (2024)
        ↓
Architecture-level privilege representation
  Instructional Segment Embedding (2025)  ← 本論文
        ↓
Fine-grained / many-tier privilege representation
```

本論文の特徴は、instruction hierarchyをalignment datasetだけの問題ではなく、**input representation designの問題**として扱った点にある。

## 実装・研究上の示唆

RAG / agent systemで外部dataをpromptへ連結する場合、単にXML tagやdelimiterで囲うだけでなく、モデル内部までtrust labelを保持する設計が有効である可能性を示す。これはtaint trackingに近い考え方であり、将来的にはbinaryなsystem/user/data区分ではなく、organization policy、developer、user、tool、remote content、sub-agent等のfine-grained privilegeへ拡張できる。

一方、後続benchmarkでは固定role hierarchyだけでは不十分であることも示されており、ISE型representationをcontinuous / arbitrary privilegeへ拡張できるかが重要な研究課題となる。
