# CacheClip: Accelerating RAG with Effective KV Cache Reuse


## 概要

CacheClipは、RAGでdocument chunkごとにoffline計算したKV cacheを再利用しながら、**queryに重要なtokenだけをprimary LLMで再計算**する手法。従来の[CacheBlend](2024-2405.16444-cacheblend.md)がprimary modelの初期layerでKV deviationを測るのに対し、**小型auxiliary LLMの最終layerのattention**を重要token selectionに用いる。

加えて、独立chunk prefillで増えるattention sinkをshared prefixで統一し、散在したtokenを単独で再計算するとlocal coherenceが壊れる問題をsliding-window groupingで緩和する。selectionはCPUで実行し、GPUへのKV loadとoverlapさせる。

## 問題設定・既存法の限界

RAG promptは同じretrieved chunkを異なる順序・位置で利用する。prefix cacheは先頭一致が必要で、direct KV concatenationはchunk間attentionとRoPE位置が不整合になる。APE型のshared-prefix calibrationはattention sinkを改善するが、失われたcross-chunk attentionは戻せない。

CacheBlend型のselective recomputationには、(a) 初期layerで見たimportanceが深いlayerでのsemantic relevanceと一致しない、(b) 数字・UUIDなど複数tokenに分かれた値の一部だけを更新するとKVが不整合になり、**再計算率を上げても精度が下がる**、という課題がある。

## Key observation: 小型modelの深層attentionは有用

著者らはQwen2.5-14Bをprimary、Qwen2.5-0.5BやSmolLM2-135Mをauxiliaryとし、2WikiMultihopQAの200 samples × 1K–16Kでattentionを比較した。tokenizerが異なるためattention massを**文字位置空間へ投影**し、top-20%の重要位置集合のJaccard overlapを測る。

全16設定で、**auxiliary最終layer vs primary最終layer**の重要位置overlapは、**primary初期layer vs primary最終layer**より高い。分布全体のKLは異なるmodel familyで必ずしも小さくないが、selectionに必要なのはattentionの値の完全一致ではなく**上位位置の一致**である。

## 手法

### 1. Offline chunk KV + shared prefix

各chunkを共通system prefix付きで独立prefillし、KVを保存する。onlineでは各chunkのKVを連結し、shared prefixの重複分を削除して先頭に1回だけ残す。これによりchunkごとに発生したattention sinkを単一化する。RoPE positionは結合後のglobal sequenceに整合するよう補正する。

### 2. Auxiliary-model-guided query attention

auxiliary LLMにもchunk側KVを事前計算する。query到着時、各chunk+queryをauxiliary modelでbatch処理し、最終layerの**query tokens → chunk tokens**のattentionだけを抽出する。

$$A_{QC}\in\mathbb{R}^{|Q|\times|C|},\qquad s(t)=\frac{1}{|Q|}\sum_{q\in Q}A_{QC}[q,t].$$

query間やshared prefixへのattentionは除外し、$s(t)$上位tokenを再計算候補とする。これはglobal KV deviationではなく**query-conditioned attention**をproxyとするため、[A³](2025-2511.17560-a3.md)や[ProphetKV](2026-2602.02579-prophetkv.md)と近い。ただしscoreは**primaryではなく小型modelの深層**から得る。

### 3. Sliding-window grouping

選択候補をそのまま散発的に更新すると、同一entityやphraseの一部だけ新KV、残りは古いKVとなりcontext coherenceが崩れる。CacheClipはwindow size $w=8$、stride 1で候補密度を調べ、候補が$\tau=5$以上あるwindowを**全tokenまとめて再計算**する。十分な密度のない孤立候補は除外する。

このため**最初のtop-k候補数と最終recomputation token数は同一とは限らない**。budget比較ではこのgrouping後の実際の計算量を確認する必要がある。

### 4. Tokenizer mappingとsparse-query recomputation

auxiliaryとprimaryでtokenizerが異なるため、文字spanなどを介して位置をprimary token indexへ対応付ける。選択されたprimary tokenを正しいglobal positionとcausal historyで再計算し、対応するKV位置をoverwriteする。実装は**scattered query indicesを扱えるcustom Triton Flash Attention kernel**を使用する。

### 5. CPU–GPU overlap

SmolLM2-135M等のselectionはIntel Xeon CPU（AMX利用可能）へoffloadし、primary modelのGPU computeやVRAMを占有しない。auxiliary KVも事前計算し、online selectionをprimary KV loadと重ねる。

```text
Offline: shared-prefix + chunk -> primary KV / auxiliary KV
Online : retrieve -> primary KV load -----------┐
                   -> CPU auxiliary query pass  ├-> grouped selected tokens
                                                └-> GPU sparse recomputation -> KV overwrite -> decode
```

## Experiment Setup

- **Primary:** Qwen2.5-14B-Instruct。Auxiliary: SmolLM2-135M-Instruct / Qwen2.5-0.5B-Instruct。
- **Hardware:** NVIDIA L20 GPU、5th Gen Intel Xeon EMR 6554S CPU。
- **RULER:** retrieval系8 tasks（4K、8K、16K）、average reference coverage（substring match）。
- **LongBench:** multifieldqa_zh、2wikimqa、hotpotqa（ROUGE-L/F1）。
- **Chunk setup:** 1000-token chunks、50-token overlap。retriever qualityの影響を除くため、retrieval stageは実行せず全text chunksを入力。
- **Baselines:** Full Attention、Direct Reuse、APE（temperature/scaling 0.9）、CacheBlend。代表recompute ratio 20%。

## Main Results（arXiv v2）

**RULER / 8K / 20% recomputation:** `multivalue`でCacheClip **96.00**、APE **34.00**、CacheBlend **42.97**。multi-token entityの一部だけを修復する従来法の弱点を改善する。16KではCacheBlend/APEが約58点へ低下する一方、CacheClipはSmolLM2使用時**72.9**、Qwen0.5B使用時**75.4**を維持。

**品質維持率:** v2 abstractはfull attention比でNIAH最大**85.2%**、LongBench最大**91.1%**と記載。これは全条件での保証ではなく、task/model/budgetに依存する。

**Prefill latency（16K、20%、L20）:** 

| Stage | CacheClip |
|---|---:|
| CPU token selection | 0.238 s |
| GPU selective recomputation | 1.332 s |
| Others | 0.125 s |
| Total | **1.695 s** |
| Full Attention | **5.641 s** |
| Speedup | **3.33×** |

再計算がCacheClip totalの78.6%を占める。selectionはGPU KV loadingとoverlap可能だが、上記totalはその効果を無制限に加算してよいわけではない。またここでの**prefill speedupとend-to-end TTFT/QPSは区別**する。

## Ablation

### Groupingとshared prefixの役割分担

RULER 8Kの20%設定では、shared prefix/grouping両方なしで平均**40.47**、groupingのみ**81.28**、両方あり**81.50**。groupingの効果が圧倒的。single2/single3の数字やUUIDなどでpartial KV overwriteが不整合を起こすことが原因とされる。

LongBenchではdirect reuse **43.92**、recomputationのみ**49.40**、recomputation+shared prefix **50.91**、recomputation+grouping **49.51**、両方あり**51.98**。ここではshared prefixによるattention sink補正が比較的大きく寄与する。

### Recomputation ratioは単調ではない

CacheBlendは30–80%の中間budgetで精度が落ち、90%近くで回復するtaskがある。**高recompute ratio = 必ず高accuracy**ではない。CacheClipもwindow groupingによって局所的に不連続なcache更新を抑えるが、full-prefillと厳密一致するわけではない。

### Auxiliary model family

異なるfamilyでもtop-k位置overlapは高いが、attention分布のKLは必ずしも小さくない。primary modelが異なる場合のqualityとselection costは追加検証が必要。

## Limitations

1. v2の主要end-to-end評価はQwen2.5-14Bで、model-family一般化はattention overlap実験が中心。
2. Retrieverをbypassしているため、real RAGの検索遅延・hit-rate・cache storage/I/Oを含むproduction TTFTではない。
3. Auxiliary inferenceとtokenizer alignmentが追加cost。CPU AMXやoverlapの有無に依存。
4. Window groupingで候補tokenが追加/除外され、recompute budgetと選択位置の厳密制御が難しくなる。
5. Primary modelはfine-tuning不要。**v2でauxiliary modelのfine-tuningが必須かは確認できない**ため、v1の説明をそのまま転記しない。

## Taxonomy・関連研究との差分

**reuse / chunk KV cache / query-aware token selection / auxiliary-model proxy / local grouped recomputation / CPU-GPU overlap**。

- [CacheBlend](2024-2405.16444-cacheblend.md): primary model初期layerのKV deviationでselection。CacheClipは小型model深層attentionを使用。
- [APE](2025-2502.05431-ape.md): shared prefix/attention calibrationは共通だが、CacheClipはcross-chunk interactionをtoken recomputationで修復。
- [Cache-Craft](2025-2502.15734-cache-craft.md): chunk cache repair/managementに対し、CacheClipはquery-aware proxyとcontiguous groupingに重点。
- [KVShare](2025-2503.16525-kvshare.md): v2はattention-weighted KV deviation + prefill/decode repair + multi-tenant scheduling。CacheClipは外部modelのquestion attention。
- [A³](2025-2511.17560-a3.md): question-aware KV fusionというselection objectiveが近い。CacheClipはauxiliary深層proxyとgroupingが独自性。
- [ProphetKV](2026-2602.02579-prophetkv.md): primary model全layerのquery-only passからlayer-wise relevanceを融合。CacheClipは**小型modelのlast layer**で安価に推定。
- [EPIC](2024-2410.15332-epic.md): position-independent KV reuseの別設計。
