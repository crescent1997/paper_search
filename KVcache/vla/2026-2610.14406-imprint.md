# 概要

IMPRINT（Interaction Memory with Progress- and Reconstruction-Informed Training）は、長時間ロボット操作で必要となる過去の視覚・実行行動・関節などの自己受容情報を、履歴長に依存しない潜在メモリに統合する枠組み。何を残すべきかをキーフレーム・テキスト要約で手動指定しない点を特徴とする。ただし固定容量の圧縮自体は情報損失を伴う。ベースのVLAへ追加学習なしに適用する方式ではなく、2段階学習を必要とする。

# 問題設定・先行研究との差

現在の画像だけでは、物体の元位置、既に押したボタンの回数、折り畳み操作の手順などを判断できない。全履歴をVLMに入力すると計算時間が伸び、単純なフレーム抽出は行動や自己受容情報を落とす。MemoryVLAなどの潜在記憶は視覚中心または行動損失だけの間接学習になりやすい。IMPRINTは(1)複数情報系列の融合、(2)記憶そのものへの教師信号、(3)逐次更新可能なrecurrent bottleneckを同時に扱う。MEM（arXiv:2603.03596）の短期視覚・長期言語的記憶と異なり、IMPRINTは言語的なエピソード要約ではなくセンサ運動系列を潜在状態へ圧縮する。異なるデータ・backboneの数字をそのまま優劣比較しない。

# 手法

## Multi-stream encoding

入力は (i)過去動画（凍結したcausal video tokenizerで時空間圧縮）、(ii)直近画像（DINOv3）、(iii)実行済みaction、(iv)proprioception。後二者はMLPで埋め込み、タスク指示とともに潜在メモリへ集約する。メモリは `m_t ∈ R^{B×d}`、既定 `B=256, d=1024`。比較するfull-attention Perceiverは全履歴にattentionするが、recurrent版はgated-delta stateをチャンク単位で更新する。各headの状態は概念的に `S_t = δ_t S_{t-1} + β_t(v_t - δ_t S_{t-1} k_t)k_t^T`、読み出し `y_t=S_t q_t`。実装は2ブロック・8 heads・head当たり128×128 FP32行列状態を使用し、エピソード間で状態をリセットする。固定長状態の更新で履歴長に対する再計算を抑えるが、直近窓の処理は別途必要。

## 二段階学習

Stage 1: 記憶encoder/decoderをpolicyとは独立に学習。ランダムに抽出した過去最大16ステップについて、視覚特徴、action、proprioceptionの再構成MSEと、正規化されたタスク進捗の予測MSEを組み合わせる。進捗はデモの現在時刻/全長であり、別途人手ラベルを要求しない。Stage 2: decoderを破棄し、VLAとメモリencoder・adapterをaction prediction損失で共同fine-tune。action expertが固定数のmemory tokensにcross-attendしFiLMで変調する。π0、π0.5、MolmoAct2で検証。VLA backboneのKV cacheを保存・再利用する手法ではない。

# Experiment Setup

- RMBench: 記憶依存9タスク、各100試行。
- RoboCasa改変版: 記憶依存6・非記憶6の12タスク、各50試行。
- 実機: 双腕YAMによるDust Table、Scan Bottle、Fold Cloth。未知物体を使うOOD条件も評価。
- 基本backbone: π0.5、256×1024 memory。比較: no-memory、Uniform Sampling、EventVLA、Mem-0、MemER、HAMLET、MemoryVLA。EventVLAは本来のfull methodではなくvisual-anchor構成を用いた比較である点に注意。
- latency: L40S GPU、50-step action chunk単位の平均。これは1アクションステップ当たりの遅延や実機control frequencyではない。GPU memory・throughputの定量的同条件比較は本文の主要結果では未確認。

# Main Results

| 条件 | IMPRINT | 比較対象・注記 |
|---|---:|---|
| RMBench平均成功率 | recurrent 72.8% | no-memory π0.5 25.4%、EventVLA visual-anchor 67.8%、MemoryVLA 41.7%、HAMLET 28.1% |
| RoboCasa全12タスク平均 | recurrent 66.7% | full-attention版62.2% |
| RoboCasa記憶依存6タスク | recurrent 65.3% | 非記憶6タスクは68.0% |
| 実機3タスク | 80%、75%、72% | OOD未知物体では45%、70%、31%に低下 |
| 推論latency / 50-step chunk | 122.8 ms | full-attention 130.8ms、HAMLET 144ms、MemoryVLA 321ms、EventVLA 960ms |
| RMBench π0 backbone | 63.0% | 同backbone no-memory 17.4% |
| RMBench MolmoAct2 | 59.7% | 同backbone no-memory 18.8% |

数値は論文著者の評価プロトコルにおける結果。比較モデルごとに高水準VLMやbackboneの条件が必ずしも完全一致しない。実機80/75/72%はタスク別であり、長時間連続稼働の障害率を測ったものではない。

# 主要ablation

| 変更（主にRMBench） | 成功率 | 解釈 |
|---|---:|---|
| Vision only | 60.6% | 行動履歴を欠く |
| Vision + Action | 68.4% | 実行履歴が有効 |
| Vision + State | 60.9% | 自己受容のみの追加は平均では小幅 |
| 全3系列 | 72.7% | 補完的な情報を利用 |
| E2E action lossのみ | 50.8% | 直接学習では弱い |
| Stage 1後、encoder凍結 | 58.8% | 記憶事前学習は有効 |
| Stage 1 + 共同微調整 | 72.7% | 行動への適応が重要 |
| progress予測を除外 | 68.7% | 段階情報が有効 |
| 視覚再構成のみ | 66.9% | 他系列の教師信号も有効 |
| action/state再構成のみ | 62.7% | 視覚教師信号も必要 |

容量実験ではmemory token数1→256でRMBench 67.0→72.7%、1024では70.0%へ低下。再構成lossが最低になる容量とaction success最適値は一致しない。recurrent/full-attentionのRMBench成功率はほぼ同等だが、recurrentの方が平均latencyが小さく、履歴長増大時に優位。

# Limitations・解釈上の注意

潜在メモリは明示的キーフレームや言語記憶より解釈困難。記憶の失敗を利用したin-context learningは未対応。記憶学習はteleoperation demonstrationsに依存する。実機OODで成功率が落ち、長時間・未知状況の頑健性は限定的。固定長潜在状態が理論上すべての履歴情報を完全保持できるわけではない。報告latencyはaction chunk単位で、GPU memory、throughput、制御周波数、長時間稼働中のメモリ破綻の詳細比較は追加検証が必要。PDFの直接取得は実行環境の通信制限で失敗したため、公式arXiv HTML本文と付録で照合した。図表のPDFレンダリング照合は未実施。

# Taxonomy

- Category: `KVcache/vla/` / long-horizon memory / multi-stream latent compression / recurrent state / memory training.
- KV reuseとの違い: TransformerのK/Vを跨フレームで保持・再配置する手法ではない。recurrent matrix stateと固定長memory tokensを継続更新する方式。KV cacheのprefill高速化効果を直接主張しない。
- 対象課題: partial observability、長期依存、task progress、history-memory tradeoff。
