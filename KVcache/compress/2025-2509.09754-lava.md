# LAVa

## 概要・問題設定

従来のKV evictionでは、token重要度、headごとの保存量、layerごとの保存量を**別々のheuristic**で決める場合が多い。[SnapKV](2024-2404.14469-snapkv.md)はheadごとにrecent attentionを集約し、[Ada-KV](2024-2407.11550-adakv.md)はhead予算を適応配分し、[PyramidKV](2024-2406.02069-pyramidkv.md)はlayer予算を固定パターンで変える。これらの組み合わせは調整が複雑で、taskごとの最適解が異なる。

LAVaはTransformerの**residual streamへ流入する情報の損失**を軸に圧縮を定式化する。特に各layerのmulti-head attention outputの変化（Layer Attention Output Loss）の上界から、**attention scoreだけでなくValueのnormを含むhead横断で比較可能なtoken score**を導き、同じscoreでtoken eviction・head budget・layer budgetを決定する。Training-freeで既存モデルの重み変更は不要。

## 手法の技術的な芯

### 1. Layer Attention Output Lossからscoreを導出

layer `l` のattention output `y_l`とKVをmaskしたときの`ŷ_l`との差 `||y_l−ŷ_l||_1`を評価する（§3–4）。論文Theorem 1は、各head/tokenで削除されるattention massとValueの大きさに比例する上界を導く。head間で比較するとき、単なるattention massではなく**headごとのValue scale**を考慮すべきという結論になる。

直近`w`個のQueryから得たattentionを利用した実際のscoreは、概念的に次式：

`score[l,h,i] = max_k ||V[l,h,k]||_1 × (1/w) Σ_{j=N−w}^{N} A[l,h,j,i]`

- `max_k ||V||_1` はhead依存の係数。head内では全tokenに共通でも、**head間のranking**に影響する。
- 最近のattention平均を使うのは、将来Queryを使えないため。完全な未来のinformation lossを最適化しているわけではない。
- **recent windowはeviction対象から除外**する。scoreにpooling（実験ではmaxpool kernel 7）を適用して局所的変動を平滑化。

### 2. Head budgetをscoreのglobal rankingから決定

layer内の各headの`score[l,h,i]`をflattenし、layer予算`B_l`に対して上位`B_l`個のKV entryを保持する（Algorithm 1）。その結果、headごとの予算`B_{l,h}`が自動的に決まる。**headごとのTop-Kを固定してからlayerをまとめる方式ではない**。

### 3. Layer budgetをscore分布のentropyから決定

各layerのscoreを正規化して分布 `p[l,h,i]` とみなし、entropy `e_l = −Σ p log p / (H N)` を計算する（Eq. 6–7）。どのKVを削除すべきかの**不確実性が大きいlayerへ多くのbudget**を配分し、`B_l ∝ e_l`とする。

Prefill完了後に一括圧縮するとpeak memoryが大きいので、layer `l` のprefill終了時点で既に計算したlayerの予算を再配分し、必要に応じて下位layerを**再圧縮**する（Algorithm 2）。これは**KV値の再計算ではなく、保存entryの追加削除**である点に注意。

### 4. GQAとの整合

GQAでは複数Query headが同一KV headを共有する。LAVaは対応するQuery headのscoreの**max**をgroup scoreとし、少なくとも1つのheadに重要なKVを残す保守的な選択を行う（§4.3）。単純なhead平均でretrieval headの信号を薄めない設計。

## Experiment Setup

- Backbone：Mistral-7B-Instruct-v0.2、Qwen2.5-7B/14B/32B-Instruct、Llama3-8B-Instruct（いずれもGQA）。
- Benchmark：LongBench（英中・QA/要約/few-shot/code等21 dataset）、Needle-in-a-Haystack、RULER、InfiniteBench。
- Baseline：[SnapKV](2024-2404.14469-snapkv.md)、[PyramidKV](2024-2406.02069-pyramidkv.md)、[Ada-KV](2024-2407.11550-adakv.md)系（Ada-SnapKV/Ada-PyramidKV）、CAKE。
- Budget：MistralのLongBenchでは`B=128HL, 256HL, 512HL, 1024HL`等（`H`: KV head数に応じた実装定義、`L`: layer数）。元のcontext lengthに対する単純な一律%ではなく、表の設定を併記する必要がある。
- Latency/memory：Mistral-7B、FlashAttention-2、A800 80GB、出力128 token。Full Cacheと圧縮手法を比較（§5.3）。

## Main Results

**LongBench Mistral-7B（Table 2、21 dataset平均、passage count除外）**

| Budget | SnapKV | Ada-SnapKV | CAKE | LAVa |
|---|---:|---:|---:|---:|
| 128HL | 34.42 | 35.82 | 35.06 | **36.74** |
| 256HL | 38.49 | 39.40 | 38.84 | **40.12** |
| 512HL | 41.48 | 42.11 | 41.76 | **42.59** |
| 1024HL | 43.00 | 43.34 | 43.36 | **43.65** |

Full Cache平均は**45.07**。小さいbudgetで相対的な優位が大きいが、**full-cacheとの差は残る**。RepoBench-P（128HL）ではLAVa **48.92**、CAKE **48.53**、Ada-SnapKV **46.85**。生成系taskではdynamic layer budgetの効用が大きい（§5.2）。

**Efficiency**：128K contextでFull Cacheに対してdecode latency **約9×高速化**を報告。これは圧縮に伴うFull Cache比であり、SnapKV等の同budget手法に対する9×ではない。Fig. 3ではCAKE/LAVaのpeak memoryが一部条件でわずかに大きい。論文の理論計算例（N=10,000、budget=1024等）ではSnapKV比の追加計算**0.01%**、追加memory**0.6%**と見積もる（§5.3）。

## 主要ablation

- **−layer dynamic**：layer予算を`B/L`固定にすると、特に**code completion/要約などのgeneration**で悪化する。
- **−head dynamic**：head予算を固定すると、特に**extractive QA**で悪化する。head間で比較できるValue norm付きscoreの意味を支持（Fig. 4、Appendix Table 10）。
- **Scoreの寄与**：同じUniform/Pyramid layer allocationでLAVa scoreとAdaKV scoreを比較し、多くのLongBench taskでLAVaが勝つ（Fig. 5）。
- **RULER/InfiniteBench**：Appendixでも比較を実施。ただしtask間で有利な配分は異なり、全task・全budgetで一律優越するわけではない。

## Limitations

- 理論は**current residual streamのattention output損失の上界**を利用し、future tokenのlogit差・最終回答品質の厳密最適化ではない。
- Score計算にはprefill時のrecent attentionとValue normが必要。**FA2実装の詳細、GQA group score、headごとに異なるKV保持位置**はserving実装上の論点。
- Layer予算再配分に伴い既存layerのcacheを再度削るため、prefill途中のmemory/schedulingと不可逆evictionを考慮する必要がある。
- 論文Limitationsでは**vLLM等への統合は未実施**と明記。報告の9×はA800/FA2上の限定された条件であり、vLLM+LMCache等のproduction end-to-end TTFTを示さない。
- Compressionによって失ったKVは再利用/repairできない。Queryが後で変わるRAGやmulti-turn QAでの復元可能性は未検証。

## Taxonomy / 関連研究との差分

`compress > attention-based eviction > dynamic head + dynamic layer budget`。

- [HeadKV](2024-2410.19258-headkv.md)：retrieval/reasoning headの重要度から**head budget**を決める。LAVaは**Value norm付き統一scoreとentropyでlayer budgetまで動的化**する。
- [DynamicKV](2024-2412.14838-dynamickv.md)：task依存のlayer budgetを逐次更新。LAVaは**head/layerの双方**を同じ情報損失基準から決める。
- [PyramidKV](2024-2406.02069-pyramidkv.md)：固定的なlayer allocationと対照的に、inputごとにentropyで割り当てる。
- [DMC](2024-2403.09636-dmc.md)：追加学習でKVをmergeする方式。LAVaはtraining-freeでtokenを**evict**する方式。
- [ProphetKV](../reuse/2026-2602.02579-prophetkv.md)：Query-awareなselective **recomputation**で再利用品質を回復。LAVaは**保存容量**の削減が目的で、cross-document reuseではない。
