# RAGCache: Efficient Knowledge Caching for Retrieval-Augmented Generation

## 概要
RAGCacheは、RAG workloadで同じknowledge documentが多数requestから繰り返しretrievalされる偏りを利用し、document処理で生成されたintermediate/KV statesをrequest間で再利用するsystem。GPU memoryとhost memoryを階層的に使い、knowledge tree、prefix-aware eviction、cache-aware schedulingを組み合わせる。

## 問題設定
RAGではretrieval自体だけでなく、retrieved documentsをLLMへprefillする計算がTTFTを大きくする。同じdocumentが何度もretrievalされても通常は再計算される。一方、documentのKVはpreceding contextに依存するため、同じdocument textというだけでは任意位置へ安全に再利用できない。

RAGCacheはこの問題を「任意位置reuse」へ一般化するのではなく、**同じprefix contextから計算されたdocument KVを再利用する**ことでexactnessを保つ。

## Knowledge tree
retrieved document sequenceをtreeとして管理する。rootからのpathがprompt内のdocument prefixに対応し、共通prefixを持つrequestは既計算stateを共有できる。

たとえば [D1,D2] と [D1,D3] はD1まで共有できるが、[D2,D1]は別pathになる。これによりprefix dependencyを壊さずcache hitを増やす。

## Hierarchical cache
GPU cacheを高速tier、host memoryを大容量tierとして扱う。hot knowledge statesはGPUに保持し、必要に応じてhostへdemote / GPUへpromoteする。cache capacityだけでなくPCIe transferとrecomputation costを考慮する必要がある。

## PGDSF eviction
Prefix-aware Greedy-Dual-Size-Frequency (PGDSF)ではfrequency、size、recencyに加え、tree上のprefix状態によって変化する**再計算cost**をpriorityへ反映する。単純LRU/LFUより、evictすると高価なentryを残しやすい。

## Scheduling / pipelining
cache-aware request reorderingによりcache localityを高める。またretrieval完了を待ってから全処理を始めるのではなく、retrieval途中の候補を利用してLLM側処理を先行させるdynamic speculative pipeliningでretrievalとinferenceをoverlapする。

## CacheBlend / Cache-Craftとの差
[RAGCache]はprefix-sensitiveで、cache hitしたstate自体は正しいcontextから生成されている。一方[CacheBlend](2024-2405.16444-cacheblend.md)や[Cache-Craft](2025-2502.15734-cache-craft.md)は、異なるcontextで生成されたchunk KVをreuseし、欠落interactionをselective recomputationでrepairする。

したがってRAGCacheはreuse flexibilityを制限する代わりにrepair computationを不要にする。

## Experiment Setup
vLLM + Faiss、SGLang等をbaselineとしてRAG workloadsでTTFT、throughput、cache hit、memory hierarchyの効果を評価する。

## Main Results
vLLM+Faiss比でTTFT最大約4×、throughput最大約2.1×改善し、SGLang比でもTTFT最大約3.5×、throughput最大約1.8×改善を報告する。document popularityのskewとprefix reuseをsystem-level localityへ変換した効果が大きい。

## Ablation / Analysis
knowledge cache、PGDSF、cache-aware scheduling、speculative pipeliningを個別に外し、それぞれがlatency/throughputへ寄与することを分析する。workloadのdocument popularityが偏るほどcache reuse benefitが増える。

## Limitations
- document順序やpreceding prefixが変わると同じtextでも別cacheが必要。
- arbitrary position-independent reuseではない。
- GPU/host間transfer overheadがある。
- cache benefitはretrieval distributionのreuse localityに依存。
- system componentが多く、単純なKV algorithmよりintegration costが高い。

## KV-cache taxonomyでの位置づけ
**reuse / cross-request RAG caching / prefix-sensitive document KV / hierarchical cache / system-level scheduling**。
