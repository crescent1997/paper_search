# You Only Cache Once: Decoder-Decoder Architectures for Language Models

> 通常Transformerが各layerで別々のK/Vをcacheする前提そのものを変え、**global KV cacheを一度だけ作って多layerで共有する**。

## 概要

standard decoder-only Transformerでは、各layerが過去tokenに対するK/Vを保持するためKV cache memoryは概ねlayer数×sequence lengthに比例する。YOCOはmodelをself-decoderとcross-decoderの二段へ分け、global cache生成を前段へ集約する。

## Architecture

### Self-decoder

入力sequenceを処理してcontext representationを作る。効率的なself-attention mechanismを用い、最終的に後段から参照されるglobal K/Vを生成する。

### Cross-decoder

後段layerは過去tokenごとの独立KVを各layerで持つ代わりに、self-decoderが生成した共通KV cacheへcross-attentionする。

このため外から見るとautoregressive decoderとして動作しつつ、cache storageは通常Transformerより大幅に小さくなる。

## Prefill early exit

YOCOではglobal cacheがself-decoder側で確定すれば、既存prefix部分についてcross-decoderの全計算をあらかじめ完遂する必要がない構成を利用できる。これによりprefillをearly-exitし、generationに必要な計算へ集中できる。

## Experiment Setup

model size / training tokenをscaleさせたlanguage modeling比較とlong-context evaluationを実施。1M contextへ拡張したneedle retrievalも評価する。

## Main Results

同規模Transformerとcompetitiveなmodel qualityを維持しつつ、長contextでinference memory、prefill latency、throughputを大きく改善する。1M contextでもnear-perfectなneedle retrievalを報告する。

## 先行研究との関係

MQA / GQAはhead方向にK/Vを共有してcacheを減らす。一方YOCOは**layer方向の重複**をarchitecture levelで減らす点が本質的に異なる。

Cross-Layer Attention系の発想とも近いが、self-decoder / cross-decoderという全体architectureとしてcache-onceを成立させる。

## Limitations

- pretrained standard Transformerへ後付けしにくく、基本的にmodel architecture / training段階から導入する必要がある。
- shared representationに情報を集約するため、通常のlayer-specific KVほど自由度はない。
- serving stack側も通常decoder-onlyとは異なるcache / kernel設計が必要になる。

## KV-cache taxonomyでの位置づけ

**architecture-level cross-layer cache sharing**。compressionやreuseとは異なり、「そもそもlayerごとにKVを作る必要があるか」を変えるcategory。

## 実装・研究上の示唆

KV cacheの支配項はsequence lengthだけでなくlayer dimensionにもある。既存model互換性を捨てられる場合、量子化・evictionより大きな構造的削減余地がある。
