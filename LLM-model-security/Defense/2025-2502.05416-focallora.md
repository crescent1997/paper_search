# Don't Forget the Enjoin: FocalLoRA for Instruction Hierarchical Alignment in Large Language Models

## 概要

FocalLoRAはInstruction Hierarchy failureがTransformer全体に均等に分布するのではなく、**instruction conflictに敏感な少数のattention headsへ集中する**という観察に基づくparameter-efficient alignment手法である。

normal promptとsystem-user conflict promptのattention behaviorを比較し、3種類の変化量からFocal Headsを同定する。

その後、選ばれたheadのQ/K projectionだけへLoRAを適用し、higher-priority system instructionへのattentionを強化する。

## 問題設定

system instructionとuser instructionがalignedしている通常caseと、user instructionがsystem instructionへconflictするcaseを考える。

理想的には、

```text
System > User
```

を維持すべきだが、conflict時に一部attention headのfocusがsystem instructionからuser instructionへ大きく移動する。

FocalLoRAはこの変化をmechanistic signalとして利用する。

## Focal Heads

全attention headをfine-tuneするのではなく、normal / conflict input間でbehaviorが大きく変化するheadを選ぶ。

paperでは主に3つの指標を利用する。

### Magnitude Difference

system / user spanへのattention magnitudeがconflictによってどれだけ変化したかを見る。

### Directional Shift

attention focusがhigher-priority側からlower-priority側へどれだけ移動したかを測る。

### Distributional Divergence

normal promptとconflict promptのattention distribution自体の差を測る。

これらを統合してconflict-sensitive headをrankし、上位headをFocal Headsとして選択する。

## なぜ少数Headだけを更新するか

Instruction Hierarchyに関係しないheadまで更新すると、

- general language capabilityの劣化
- unnecessary parameter update
- overfitting

が起こり得る。

FocalLoRAはhierarchy conflictに実際に反応するheadだけをtargetにすることで、parameter efficiencyとbehavior preservationを狙う。

## System-Aware Heads Optimization (SAHO)

Focal Headsを選択した後、そのheadに対応するQ/K projectionへLoRA adapterを追加する。

全W_Q / W_Kを更新するのではなくselected head sliceだけをparameterizeする。

これによりmodel全体のごく一部だけをtrainingする。

## Focus Loss

通常のlanguage modeling / alignment objectiveだけではselected headがsystem instructionへattentionを戻す保証がない。

そこでhigher-priority system tokensへのattention massを増やすFocus Lossを導入する。

概念的には、

```text
maximize attention(
  focal heads,
  system tokens
)
```

となる。

task lossとFocus Lossを組み合わせ、output behaviorとinternal attention allocationを同時にalignmentする。

## LoRA Rank

selected headのQ/Kへrank-r LoRAを適用する。

rankを増やすとadaptation capacityは上がるがparameter数も増える。

paperでは複数rankを比較し、rank 32等で強いhierarchy performanceを報告する。

## Parameter Efficiency

Llama-8Bでは全parameterの約0.0188%だけを更新し、system-instruction complianceを35.52 percentage points改善する。

full fine-tuningや全attention layerへのLoRAと比べ、非常に小さいupdate budgetでhierarchy behaviorを変えられる。

## Experiment Setup

複数architecture / scaleで評価する。

- Qwen 1.5B
- Phi 3.8B
- Mistral 7B
- Llama 8B
- Qwen 14B

system-user instruction conflictを中心に、in-domain / out-of-domain generalizationとprompt injection robustnessを評価する。

比較対象にはprompt template、standard LoRA、ISE等を含む。

## Main Results

FocalLoRAは複数model familyでsystem instruction complianceを大きく改善する。

重要なのは特定architectureのhead patternだけへoverfitせず、Qwen / Phi / Mistral / Llamaで同じselection + focal optimization frameworkが機能する点である。

## Prompt Injection Evaluation

Naive / Ignore / Escape等のprompt-injection settingを評価する。

out-of-domain Llama-8BのIgnore attackでは、

```text
Template:       52.48
ISE:            67.59
FocalLoRA-r32:  69.43
```

Qwen-14Bでは、

```text
Template:       63.47
ISE:            78.23
FocalLoRA-r32:  83.67
```

となる。

したがって単純なtraining conflictだけでなく、unseen injection patternにも一定のgeneralizationを示す。

## ISEとの関係

[Instructional Segment Embedding](2024-2410.09102-instructional-segment-embedding.md)はsystem / user / data sourceをtoken-level embeddingとして明示する。

```text
ISE:
  every token receives source embedding

FocalLoRA:
  identify conflict-sensitive heads
  -> selectively modify Q/K
```

FocalLoRAは新しいsource embeddingをarchitectureへ追加せず、既存attention mechanism内のhierarchy-sensitive subspaceを直接調整する。

## The Instruction Hierarchyとの関係

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)はbehavioral synthetic trainingでpriority followingを学習させる。

FocalLoRAは同じbehavioral goalを持つが、全modelを更新する代わりにmechanistic analysisで更新対象を絞る。

```text
Instruction Hierarchy:
  data-centric behavioral alignment

FocalLoRA:
  head-centric parameter-efficient alignment
```

と整理できる。

## V-Steerとの関係

[V-Steer](2026-2607.26228-v-steer.md)はFocalLoRAと非常に近い問題意識をtraining-free inference-timeへ発展させる。

```text
FocalLoRA:
  normal/conflict dataset
  -> offline focal-head identification
  -> Q/K LoRA training

V-Steer:
  current prompt
  -> DLA-based bad-head identification
  -> cached V editing
  -> no training
```

両者とも「全networkではなく特定attention headのpriority imbalanceを修正する」という共通したmechanistic viewを持つ。

## HIPOとの関係

[HIPO](2026-2603.16152-hipo.md)はInstruction HierarchyをCMDPとして定式化し、system complianceをconstraintとしてRLする。

FocalLoRAはoptimization objectiveよりも**どのparameterを更新するか**に焦点を置く。

HIPOのconstraint signalとFocalLoRAのhead-localized parameterizationを組み合わせる方向も考えられる。

## Generalization

model family、model size、out-of-domain prompt injectionを横断して改善を確認する。

一方、system-user conflictが中心であり、developer / tool / external dataを含むmany-tier hierarchyへのgeneralizationは十分には確立していない。

## White-box / Access Requirements

Defense側はattention mapとmodel parameterへaccessできる必要がある。

- attention weights: 必要
- model Q/K parameters: 必要
- gradient training: 必要
- inference時の追加external model: 不要

したがってclosed API modelへ直接適用するDefenseではない。

## Adaptive Attack

Naive / Ignore / Escape attackへのrobustnessは評価するが、Focal Head selectionやFocus Lossを知るwhite-box adaptive attackerがattack tokenを最適化する評価は限定的である。

[GCG](../Attack/2023-2307.15043-gcg.md)や[The Attacker Moves Second](../Attack/2025-2510.09023-attacker-moves-second.md)の観点では、selected headsを回避するgradient-based adaptive attackが重要な追加stress testになる。

## Limitations

- attention weightsへのwhite-box accessが必要。
- focal-head selection用のnormal/conflict dataが必要。
- attention patternをcausal mechanismと完全には同一視できない。
- system-user 2-level hierarchyが中心。
- tool output / retrieved external dataへのpriority generalizationは限定的。
- adaptive white-box attackへのformal guaranteeはない。
- model architectureが変わるとfocal-head selectionを再実行する必要がある。
- Focus Lossを強くしすぎるとlower-priority legitimate instructionへのresponsivenessを損なう可能性がある。

## LLM Model Security Taxonomyでの位置づけ

```text
Behavioral:
  Instruction Hierarchy

Source-aware architecture:
  ISE

Mechanistic selective training:
  FocalLoRA
      ↓
Inference-time mechanistic correction:
  V-Steer
```

Instruction Hierarchyを**attention-head-localized alignment problem**として扱う重要な先行研究である。

## 実装・研究上の示唆

FocalLoRAは全layer/headへLoRAを入れる必要がないことを示す。

実装上は、

1. paired normal/conflict promptsを収集
2. attention mapを保存
3. head-wise conflict scoreを計算
4. top-k focal headsを選択
5. Q/Kの該当head sliceだけLoRA化
6. task loss + Focus Lossでtraining

というpipelineになる。

V-Steerとの比較では、offline head stabilityとprompt-specific head selectionのどちらがrobustかが今後の重要な研究課題になる。
