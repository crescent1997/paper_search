## 1. 概要・問題設定

VLM/VLAで高解像度・多フレーム入力を扱うと、visual encoder自体の大量tokenが推論遅延を支配する。decoderでのvisual token pruningは、すでに実行したvision encoderの計算を節約できない。そこで**vision encoder浅層で重複tokenをmergeし、以降の層を小さいsequenceで実行**する。

重要な読み分け：**タイトルはSpatio-Temporalだが、π0.5 VLA実験はsingle-frame multi-viewであり、temporal重複やframe間KV reuseを使っていない**。3D時間座標とRoPE補正は主としてQwen2.5-VLの動画VQA実験で使う。π0.5ではSigLIPのspatial mergingのみ（論文§III-Eに明記）。VLA-Cacheとの直接比較として扱うのは不適切。

## 2. 先行研究との差

| 方法 | 作用点 | 選択基準 | 重要な違い |
|---|---|---|---|
| ToMe | ViT中間 | token類似度・bipartite matching | 幾何制約不足、serial matching overhead |
| FastV | LLM decoder | cross-modal attention | vision encoder計算は残る |
| TempMe | video tokens | spatio-temporal matching | bipartite matching cost |
| **ST-Merge** | **vision encoder浅層** | **特徴類似度×空間/時間近傍、multi-queue** | **size-weighted merge + RoPE補正** |
| [VLA-Cache](2025-2502.02175-vla-cache.md) | VLAの連続フレームK/V | temporal change + layer attention | **既存K/V再利用**、token数自体をmergeしない |
| [DepthCache](https://arxiv.org/abs/2603.10469)（既存の要約mdはGitHub未反映） | VLA visual tokens | depth-guided merge | depthを利用したgeometry重視、手法は別 |

## 3. 手法

### 3.1 位置重み付き類似度

視覚token $i$ の位置を $p_i=(t_i,y_i,x_i)$ とし、近傍にあるtokenだけを強く結びつける。

$$w_{ij}=\exp\!\left(-\frac{\|p_i-p_j\|_2^2}{2\sigma^2}\right),\qquad S'_{ij}=(a_i^\top c_j)w_{ij}.$$

$\sigma$ はspatio-temporal neighborhoodの範囲を制御。視覚特徴だけの高類似度が遠方物体を誤mergeする問題を緩和する。

### 3.2 Multi-queue matching / weighted merge

tokenをanchor queue $G_1$ と複数のcandidate queues $G_{2:K}$ に分け、anchorごとに候補の最大 $S'_{ij}$ を選ぶ。高スコアの上位$r$組をmergeする。著者はmatchingの計算量を**$O(n)$**と主張するが、queue数・候補探索実装・GPU上のメモリアクセスを固定とみなす前提があり、全条件での厳密な複雑度証明ではない。

merge時はtokenが代表するpatch数・coverage $s_i$ によって重み付けする。

$$v_b\leftarrow\frac{s_bv_b+s_av_a}{s_b+s_a},\qquad s_b\leftarrow s_b+s_a.$$

浅層でtokenを減らすため、後続のvision self-attention/MLPを削減する。単純化したattention FLOPsの削減は $\sum_{k>l}\alpha_k(N_{k,orig}^2-N_{k,red}^2)$。

### 3.3 Post-Merge Positional Correction

Qwen2.5-VLのvision encoderでは、merged tokenに片方の元位置をそのまま割り当てるとspatial RoPEがずれる。各元tokenの寄与率 $\hat s_{ij}$ を使い

$$\cos_{new,i}=\sum_j\hat s_{ij}\cos_{orig,j},\quad \sin_{new,i}=\sum_j\hat s_{ij}\sin_{orig,j}$$

を再合成し、cos/sinのnormを正規化する。これは**元のRoPE角度を単純に平均する方式とは異なる**（位相ベクトルを平均）。RoPEを使わないπ0.5のSigLIP encoderではこの補正は無効。

### 3.4 VLAへの適用で外すもの

論文§III-Eは、π0.5 VLAはsingle-frame multi-view SigLIPであるため、**時間方向の近傍重みとpost-merge RoPE correctionを使用しない**と明記。したがってVLAで報告された8.3×は**空間的token mergingによる高速化**であり、cross-frame cache reuseの証拠ではない。

## 4. Experiment Setup

- **VLM動画VQA**: Qwen2.5-VL-7B、MVP mini set（robot-object interaction、temporal reasoning、intuitive physics）。ToMe、FastV、TempMeを同backboneで比較。TFLOPs、ms、accuracy。
- **VLA**: π0.5 baseをLIBEROの244×244、512×512、1024×1024などでfine-tune。実験用π0.5 checkpointの学習は**H100で50,000 steps**（ST-Merge自体は追加学習不要）。閉ループLIBERO成功率と推論時間。
- **実機**: SO-ARM101、512×512、3タスク（banana移動、orange置き、AirPods配置）。各100デモ収集（合計300）、評価は**各タスク20 trials**。
- **推論ハードウェア**: 単一RTX 5090。推論時間はmsで報告されるが、robot actuation、camera capture、network等を含むend-to-end control-loop時間とは区別する。
- **GPU memory**: peak memory/保存KV容量の定量表は未報告。control frequency/throughputの直接測定値も未報告。

## 5. Main Results

### 5.1 Qwen2.5-VL動画VQA（Table I）

| Method | TFLOPs | inference ms | Avg accuracy |
|---|---:|---:|---:|
| Qwen2.5-VL-7B | 55.07 | 1043.61 | 58.73% |
| ToMe | 41.58 | 848.52 | 53.41% |
| FastV | 46.96 | 719.10 | 55.68% |
| TempMe | 36.79 | 605.77 | 55.35% |
| **ST-Merge** | **28.11** | **414.90** | **57.68%** |

TFLOPs **48.96%削減**、実測latency **2.52×短縮**、accuracy **-1.05pp**。本文の「2×」は概数。VideoQAはVLA action successとは異なる指標。

### 5.2 LIBERO / π0.5（Table II）

| Image resolution | π0.5 baseline ms | ST-Merge ms | speedup | Baseline success | ST-Merge success |
|---|---:|---:|---:|---:|---:|
| 244×244 | 241.21 | 141.55 | **1.70×** | 95.83% | 94.16% |
| 512×512 | 607.14 | 194.32 | **3.12×** | 96.67% | 94.16% |
| 1024×1024 | 2614.56 | 312.11 | **8.38×** | 97.50% | 97.50% |

最も大きな8.3×は**高解像度のbaselineが2.6秒もかかる条件**で得られた値。512解像度では成功率が2.51pp、244では1.67pp下がる。1024での312msは約3.2推論回/sに相当するが、**action chunk頻度/制御Hzではない**。高速化が大きいほどcontrol性能が改善すると一概には言えない。

### 5.3 実機SO-ARM101（Table IV）

| Metric | baseline | ST-Merge |
|---|---:|---:|
| Place success | 80% | 80% |
| Put success | 70% | 75% |
| Move success | 50% | 55% |
| Thinking time | 582.14ms | 191.22ms |

**3.04×のdecision latency短縮**。各タスク20 trialsなので、+5ppは成功1回分に相当し統計的不確実性が大きい。推論改善は確かだが、action success改善の一般化は未確定。

## 6. 主要ablation（Qwen2.5-VL、Table III）

| Cumulative configuration | TFLOPs | ms | Accuracy |
|---|---:|---:|---:|
| Baseline | 55.07 | 1043.61 | 58.73% |
| + basic ToMe merge | 41.58 | 848.52 | 53.41% |
| + multi-queue partition | 27.90 | 381.22 | 53.78% |
| + spatio-temporal information | 28.01 | 401.22 | 56.90% |
| + RoPE positional correction | 28.11 | 414.90 | 57.68% |

- Multi-queueで大幅に高速化するがaccuracyはまだ低い。
- 近傍情報を加えるとaccuracy +3.12pp、RoPE補正でさらに+0.78pp。補正はわずかなlatency増を伴う。
- **VLA側でRoPE補正のablationはない**（そもそも適用していない）。
- $r$、$\sigma$、queue数やcamera motionに対する体系的なsuccess/latency sensitivityは十分示されない。

## 7. Limitations / 再現性

1. **KV cacheを再利用しない**：現在フレームのvisual encoder内部でtoken数を減らす方式。下流attentionのK/Vサイズが減る可能性はあるが、**既存KVを次フレームへreuseするアルゴリズムではない**。
2. **VLAのtemporal claimに注意**：Qwen動画VQAは3D時空間matchingを使う一方、π0.5 VLAではsingle-frame spatial-only。VLAのcross-frame temporal redundancy削減を実証していない。
3. **実機の標本数**：各タスク20試行。成功率の差+5ppを過大評価しない。
4. **解像度依存**：1024では成功率維持だが512/244では低下。固定merge比が小物体や微細なgripper動作を潰すリスクがある。
5. **GPU memory/実制御**：ピークGPU memory、full robot loop latency、throughput、Hz、長時間タスク成功率・忘却耐性は未報告。
6. **学習の区別**：ST-Merge自体はtraining-freeだが、実験用π0.5は各条件で50K steps fine-tune。元checkpointに何も追加学習しない状態で全数値が出たわけではない。
7. **コードURL**：論文は公開と記載するが、2026-11-02にURLが404。再現可能な公開実装は確認できず、code欄にそのまま注記。
8. **計算量表記**：matching $O(n)$ は候補探索構造を固定した場合の主張。実際のGPUメモリ転送・scatter/merge overheadは独立に検証したい。

## 8. Taxonomy / KV cache研究への接続

- **Primary**: `KVcache/vla/` — vision encoder token merging / high-resolution VLA inference。
- **KV reuseとの相違**: [VLA-Cache](2025-2502.02175-vla-cache.md)と[LAC](2026-2602.00686-lac.md)は過去のK/Vを保持して再計算を省く。ST-Mergeは**新規観測のtoken数を減らして残りのencoder層を軽くする**。
- **RoPE研究との接点**: merge後のpositional correctionは、visual KVの再利用で位置再回転が必要になる問題と類似する。ただしRoPEのsin/cosを重み付き合成することと、KVに対して位置を再回転することは**同じ操作ではない**。
- **長期記憶との相違**: [MemoryVLA](2025-2508.19236-memoryvla.md)や[TempoFit](2026-2603.07647-tempofit.md)のような持続的な履歴保存・検索は行わない。
- **今後の評価**: cross-frame KV reuseとvision encoder mergeを同時適用したときの、動的領域の誤merge・KV位置ずれ・action success・control Hz・GPU peak memoryのトレードオフが研究課題。
