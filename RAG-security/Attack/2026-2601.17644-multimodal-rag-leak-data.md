# Do Multimodal RAG Systems Leak Data? A Comprehensive Evaluation of Membership Inference and Image Caption Retrieval Attacks

> mRAGがprivate image–caption pairsを参照する際、外部ユーザが画像の**存在（membership）**を推定するだけでなく、その画像に紐づく**非公開caption metadata**を取得できることを検証した研究。画像をretrievalする段階と、retrieved image–caption pairをVLMが解釈する段階を分け、単純なguardrailでは防げないprivacy riskを定量化する。

## 概要

Multimodal RAG（mRAG）は、入力画像と似た画像・対応する説明文をprivate DBからretrieveし、VLMにcontextとして渡す。text-only RAGと同様に、非公開DBをgeneratorへ見せることがprivacy riskになるが、mRAGでは**画像が存在するか**と**画像に付随する文字情報を取り出せるか**が別の漏洩経路になる。

本論文は新しい高度なjailbreakを開発するのではなく、通常のimage-questioningに近いpromptで発生するprivacy leakageを測定する。2つの攻撃評価を実施する。

1. **MIA（Membership Inference Attack）**: query imageと同一または変換された画像がprivate retrieval DBに含まれるかを、VLMの回答から推定する。
2. **ICR（Image Caption Retrieval）**: DBに含まれる画像に対応したcaptionを、retrieved image–caption pairsから推定・再出力させる。これは単なるmembership bitではなく**private metadata extraction**に当たる。

従来のtext RAG MIA研究に比べ、image transformation、retriever/reranker、context内画像順序、prompt guardの有効性まで横断評価する点が特徴。

## 問題設定 / Threat Model

### Target System

private database `R_mm = {(i_j, c_j)}` に画像 `i_j` とcaption `c_j` を保持するvision-centric mRAG。query image `i_q` をencoderでembedding化し、cosine similarityでtop-nを取得、rerankerでtop-kへ絞り、VLMが元queryとretrieved pairsを用いて回答する。

`R(i_q) = Top-n_{(i_j,c_j)} cos(fθ(i_q), fθ(i_j))`

`R'(i_q) = Top-k_{(i_j,c_j)∈R(i_q)} ψ(i_q,i_j)`

### Attacker Capability

- mRAGの通常の入力interfaceを使い、**画像とtext prompt**を送信し、最終text answerを観測する。
- private DB全体、retrieval ID/score、reranker内部、VLM weights/logitsは観測しない。
- **MIA**はcandidate imageを持ち、その画像（または変換版）がDBに含まれるかを判定する。
- **ICR**はcandidate imageがDBにあることを前提とし、画像に紐づくcaptionの回収を狙う。

研究では複雑なadversarial prompt injectionを前提とせず、一般的なVQA/captioningタスクとしての質問でどれだけ漏洩するかを検証する。したがって、特定のjailbreak手法の強さではなく**mRAG architectureに固有のinformation flow**が中心課題である。

## 先行研究からの改善点

text RAG privacyの先行研究である[The Good and The Bad](2024-2402.16893-the-good-and-the-bad.md)はprivate text corpusのleakageを分析した。本論文はこれを**image membershipとimage–caption association**へ拡張する。

また、mRAG MIAの先行研究MrM（arXiv:2506.07399、AAAI 2026）は、画像内objectをmaskし、counterfactual VLMを使ってmember/non-memberの違いを強める攻撃を提案した。これに対し本論文は、**単純な標準promptでもMIAが成立するか**を検証し、さらにcaption leakage（ICR）を新たな評価軸として追加する。攻撃最適化ではなくpipeline sensitivityの比較に重点がある。

既登録の[ImageAuditor](2026-2606.03354-imageauditor.md)はimage-based RAGに対する別のmembership inference手法で、cross-modal retrieval query最適化を重視する。3者は、MrM＝counterfactual masked image、ImageAuditor＝optimized query、今回＝standard promptingによるsystematic evaluationという違いがある。

## Method / Algorithm

### 1. MIA: image membershipの推定

candidate imageとretrieved examplesの視覚的一致をVLMへ判定させるbinary classification型評価。retrieved contextにcandidateと同一画像が含まれる場合、VLMは両者の対応関係を観測できる。出力はYES/NOのような短い応答でも、**private DB内の画像の存在を外部へ伝える**ことになる。

研究ではDB内の画像がそのまま保存されているケースに加え、crop、grayscale、blur、cutout、rotation、Gaussian noiseなどの変換を受けたケースを評価し、retrieval-stageの画像類似度低下とVLMの判定能力の双方を測る。

### 2. ICR: image-associated captionの抽出

image–caption pairがretrieved contextに含まれると、VLMはquery imageと一致するretrieved imageを見つけ、付属captionを答えとして返すことがある。これはMIAより一段強い情報漏洩で、image identityをキーにprivate metadataを引き出す形となる。

ICRの成否は、(i) 正しいpairがtop-kに含まれるか、(ii) VLMが複数候補の中からquery imageとcaptionの対応を正確に取れるか、に依存する。**正しいpairがretrieveされても、rerankingによって類似画像が並び、VLMが誤ったcaptionを選ぶ**可能性があるため、retrieval accuracyとcaption exact matchを分けて報告する。

### 3. Prompt Structure / Retriever-Reranker Ablation

retrieved imagesをquery imageより前に置く**RAG-First**と、query imageを先頭に置く**RAG-Last**を比較する。画像順序がVLMの注意や照合結果に与える影響を切り分ける。

また、retriever候補数nとrerankerが返すkを変え、候補が増えると真のpairの露出率が上がる一方、類似画像が多すぎるとcaption associationが難しくなるというtrade-offを評価する。

### 4. Mitigation Probe

queryの前段に別のLLM/guard modelを置き、MIA・ICR promptをmaliciousと検出できるかを確認する。MIAは通常のimage comparisonに見えるため、一般的なprompt safety分類器が見落とす可能性がある。

## Experiment Setup

- **Retrieval**: CLIP visual/text embedding、cosine similarity。通常設定 `n=20`、`k=5`。
- **Reranker**: Jina-Reranker。MIAはimage–image、ICRはimage–text対応を評価するcross-modal設定。
- **VLM**: Qwen2.5-VL、Cosmos-Reason1、InternVL3.5の3系統。
- **Datasets**: Conceptual Captions（test 1,000 / base RAG pool 2,000）、ROCOv2 medical images（1,000 / 2,000）、mRAG-Bench（500 / 582）、Pokemon BLIP captions（400 / 433）。MIAではtest setの50%をmemberとして追加し、member/non-memberのbinary classificationを行う。
- **Metrics**: MIA＝accuracy、precision、recall、F1、retrieval accuracy（RAG Acc）。ICR＝caption exact match、BLEU/ROUGE等のtext similarity、RAG Acc。3 random runsの平均を報告。
- **Attacks**: exact image、transformed image、prompt order、retrieval/reranking変更、guard model判定。

## Main Results

### MIA: Exact Image

論文Table 1の代表的なMIA F1（高いほどmembershipが漏れやすい）。

| Dataset | Qwen2.5-VL | Cosmos-Reason1 | InternVL3.5 |
|---|---:|---:|---:|
| Conceptual Captions | 0.946 | **0.989** | 0.988 |
| ROCOv2 | 0.893 | **0.952** | 0.897 |
| Pokemon BLIP | **0.993** | 0.983 | 0.908 |
| mRAG-Bench | 0.966 | **0.983** | 0.899 |

retrieval accuracyは多くの条件でほぼ1.0で、exact-image settingでは正しい画像がcontextへ渡っている。MIA成功率の差は主に**VLMがその画像を正しく照合・回答できるか**に依存する。特にROCOv2では一般画像よりF1が下がり、類似した医療画像の区別が難しいことを示す。

### ICR: Caption Exact Match

ICRは画像の有無を当てるだけでなく、DB内captionそのものを再現する必要がある。datasetとrerankingの有無で成功率が大きく変わる。

論文Table 6の**rerankingなし**設定では、caption exact matchは以下。

| Dataset | Qwen2.5-VL | Cosmos-Reason1 | InternVL3.5 |
|---|---:|---:|---:|
| Conceptual Captions | **0.917** | 0.457 | 0.883 |
| ROCOv2 | **0.783** | 0.540 | 0.667 |

ここではRAG Acc=1.0であり、retrieval自体は正しいpairを含んでいる。にもかかわらずVLMごとのcaption選択能力が大きく異なる。rerankingありでは医療画像のように類似候補が多い場合にICR exact matchが低下し、retrievalとgenerationの2段階を分ける必要がある。

## Ablation / Robustness / Defense Evaluation

### Image Transformation

Crop（画像面積を約60%へ）、grayscale、blur、cutout（約4%領域）、90度回転/flip、Gaussian noiseを評価。exact-imageよりMIA F1は低下するものの、通常の変換だけではmembership leakageは消えない。rotationは平均的に最も強くMIAを抑えた変換だが、画像品質やdownstream utilityへの影響を伴うため完全なprivacy defenseとは言えない。

### Context Order

RAG-Firstではretrieved imagesを先に、query imageを後に配置する。query imageを先頭に置くRAG-Lastへ変更すると、特にQwen2.5-VLとCosmos-Reason1でMIA successが大きく低下する。これはVLMの**positional bias**に依存する挙動であり、単純なprompt構造変更でも漏洩指標が動く。ただし他モデルやICRへの一律の保証はない。

### Retriever / Reranker / k

ICRは正しいimage–caption pairのretrievalに強く依存する。rerankingは通常の検索品質を上げる一方、似た画像が多い条件ではVLMがcaptionを取り違えるため、ICRを減らすことがある。kを増やすと対象pairがcontextに含まれる確率が高まるため、leakageが増える傾向がある。privacy評価ではtop-kやrerankerを固定せず、実deploymentに近い設定を確認すべきである。

### Guard Model / LLM-in-the-Middle

論文Table 7では、GPT-4o、GPT-5.1、GPT-5.2、Qwen3Guard-Gen-8B、Llama-Guard-4-12Bの5種類でprompt safetyを判定。**MIA promptは5モデルすべてがsafe判定**した。一方ICR promptはGPT-5.2とLlama-Guardがunsafe判定し、GPT-5.1はsuspicious、他はsafe。つまり、一般的なprompt moderationは明示的なcaption extractionを一部検出できても、**membership inference自体をprivacy violationとして認識しにくい**。

## Limitations / 成立条件

1. **Candidate imageが必要**: MIAは対象画像の候補を知っていることが前提。未知画像をゼロから回収するattackではない。
2. **ICRはpairのretrieveが前提**: caption leakageは画像のvisual distinctiveness、retrieval quality、VLMの照合能力に左右される。全private captionを網羅的に盗めることを示すものではない。
3. **Controlled setting**: DBにtest imageを50%混ぜる評価設定であり、productionのprior probability、権限管理、deduplication、access logsは別途検討が必要。
4. **Dataset/architecture依存**: CLIP/Jina/VLM 3系統、image-centric tasksが中心。text+image混在のagentic RAGや医療運用へ無条件に一般化できない。
5. **画像の一致と意味的類似性**: near-duplicateや一般的な被写体が多い場合、exact membershipと類似画像の存在を区別するのが難しい。

## RAG Security Taxonomyでの位置づけ

**Attack / Benchmark → Multimodal Private-DB Leakage**。MIAはcandidate imageの存在確認、ICRは**retrieved imageに付随するprivate captionの抽出**。従来のtext-only corpus stealingとは抽出対象が異なるが、retrievalによって非公開情報がgenerator contextへ流れ、その対応付けを外部ユーザが問い合わせられるという根本構造は共通する。

## 実装上・研究上の示唆

mRAGのprivacy testでは、単に「画像が検索されたか」だけでなく、**その画像に付随するmetadataを外部へ結びつけられるか**を測る必要がある。retrieverのrecall向上、rerankerの候補選択、VLMの強いimage groundingがutilityを上げる一方、caption exfiltrationの確率も変える。実運用ではdocument/image-level authorization、caption fieldのaccess control、retrieved pairの選別、user/sessionごとのmembership probing検知など、prompt safetyとは別のdata access policyが必要になる。
