# Block-Attention for Efficient Prefilling

> RAGで毎回すべてのretrieved passagesをprefillし直すのではなく、各passageを独立blockとして一度KV cache化し、別requestでも再利用する。単純なparallel encodingではaccuracyが大きく落ちるため、**position re-encoding + block-aware fine-tuning**によってモデル自身をreuse-friendlyに適応させる点が中心的な貢献。

## 概要

RAGでは1 queryに対して複数passageをretrieveし、それらをinstruction・questionと一緒にLLMへ入力する。著者らは実運用では5〜30 passage程度がretrieveされるケースを念頭に置いており、retrieved contextが長くなるほどprefill latency、すなわちTime To First Token (TTFT)が大きくなる。

通常のdecoder-only Transformerでは、sequence

```text
System prompt
Document 1
Document 2
...
Document k
Question
```

を1本のcausal sequenceとして処理する。

このときDocument 2のhidden state / KV stateはDocument 1を見た状態で計算され、Document 3はDocument 1, 2を見た状態で計算される。そのため同じDocument 3であっても、前に置かれるdocumentや順序が変わればKV stateも変わる。

これは通常のprefix cachingが強い理由でもある。prefixが完全一致している限り、そのtokenまでのcausal historyも一致するのでKVをそのままreuseできる。しかしRAGでは同じpassageが、

```text
request A: Doc A → Doc B → Doc C → Query A
request B: Doc D → Doc C → Doc E → Query B
```

のように異なる位置・異なる前文脈で再利用されるため、standard prefix cacheではDoc Cを共有できない。

Block-Attentionはこの依存関係そのものを変える。

各retrieved passageを**独立block**として計算し、passage block同士にはattentionさせない。最後のquery blockだけが全passage blockを参照できるようにする。

```text
Block 0: Document A ─┐
Block 1: Document B ─┤
Block 2: Document C ─┼─→ Final Block: User Query
       ...           │
Block k-1: Document ─┘
```

これにより各Document blockのKVは他Documentに依存しなくなり、同じpassageなら別requestでも再利用できる。

一方、このattention patternは通常のfull-attention pretrained modelが学習時に見ていない。そのためmaskだけを突然Block-Attentionへ変更すると精度が大幅に低下する。

本論文のもう1つの重要点は、この問題を推論時の部分再計算で修復するのではなく、**fine-tuningによってモデルをBlock-Attentionへ適応させる**ことで解決したことである。

## 問題設定

入力sequenceを

[
S = \{s_0, s_1, \ldots, s_n\}
]

とし、それに対応するKV statesを

[
K = \{k_0, k_1, \ldots, k_n\}, \quad
V = \{v_0, v_1, \ldots, v_n\}
]

とする。

通常のautoregressive Transformerではtoken (s_i) のhidden stateは (s_0,ldots,s_i) に依存する。

したがって途中のblock

[
\{s_i, \ldots, s_j\}
]

を別text

[
\{s'_i, \ldots, s'_m\}
]

へ置換すると、そのblockだけでなく**それ以降のtokenすべてのKV stateが変化する**。

つまりRAG documentの一部だけが変わったrequestでも、

```text
変化したdocument
      ↓
その後ろに置かれた全document
      ↓
user query
```

を再prefillする必要がある。

Block-Attentionが目指すのは、このdependency chainをblock boundaryで切り、

> 変更されたblockと最後のquery blockだけを再計算すればよい

状態を作ることである。

---

## Block-Attentionのattention pattern

入力を

[
B_0, B_1, \ldots, B_{k-1}, B_k
]

というblockへ分割する。

RAGでは、

- (B_0 ldots B_{k-1}): retrieved passages
- (B_k): user queryを含むfinal block

とする。

通常のcausal attentionでは後ろのdocument blockが前blockを見る。

Block-Attentionでは、final block以外についてはattentionを**block-local**に制限する。

概念的なmaskは、

```text
             Key
          B0 B1 B2 Q
Query B0   ✓  ×  ×  ×
      B1   ×  ✓  ×  ×
      B2   ×  ×  ✓  ×
      Q    ✓  ✓  ✓  ✓
```

となる。

実際には各block内部ではcausal lower-triangular maskを使うため、

- passage内の前tokenは見える
- 他passageは見えない
- final query blockは全passageを見える

という構造になる。

この結果、各passage blockのKV stateは、

[
KV(B_i)=f(B_i)
]

となり、前にどのblockが置かれているかに依存しなくなる。

standard full attentionでは実質、

[
KV(B_i)=f(B_0,ldots,B_i)
]

であったため、ここがreuse可能性を生む本質的な変更である。

---

## 1. Block Segmentation

Block-Attentionでは、どこでも機械的に一定token数で分割すればよいわけではない。

著者らの原則は、

> **semanticに比較的独立した単位を1 blockとする**

ことである。

RAGではretrieved passageは元々独立document / chunkとして取得されるため、1 passage = 1 blockが自然である。

論文では他にも、

- ICL: 1 demonstration = 1 block
- multi-turn dialogue: 1 turn = 1 block
- code generation: 1 function = 1 block

といった拡張可能性を挙げる。

RAGの場合、

```text
Block 0 = retrieved passage 1
Block 1 = retrieved passage 2
...
Block k-1 = retrieved passage k
Block k = user question
```

となる。

重要なのは、**queryをfinal blockへ置くこと**である。

document block間のcross-attentionは切るが、最終queryは全documentを参照できるため、retrieved informationをanswer generationへ利用できる。

---

## 2. Position Re-encoding

blockを独立計算できるようにしても、別requestへKVをそのままcopyするだけでは問題が残る。

例えば同じDocument Aが、

```text
request 1: position 200–500
request 2: position 1800–2100
```

へ配置された場合、RoPEを適用済みのKeyは異なるposition phaseを持つ。

したがってcached blockをrequest内の新しいpositionへ移動するには、position情報を付け替える必要がある。

Block-AttentionではRoPEについて、

1. cached KVから元positionのrotationを取り除く
2. block先頭positionを0に正規化する
3. request内の新positionに対応するrotationを適用する

というre-encodingを行う。

token (x_i) に対するRoPEを

[
f(x_i,i)=R(i)x_i
]

と書くと、まずinverse rotationで

[
f(x_i,0)=R(-i)f(x_i,i)
]

としてposition 0へ戻し、その後、新しいposition (i_\Delta) に

[
f(x_i,i_\Delta)=R(i_\Delta)f(x_i,0)
]

として配置する。

数学的には直接

[
R(i_\Delta-i)
]

を掛けることもできるが、著者らは実装を安定させるため、**cache内では各block先頭をposition 0として標準化して保存する**方式を採る。

するとruntime側はcached blockのoriginal absolute positionを管理する必要がなく、新しいblock start positionだけ分かればよい。

これはreuse systemとしてかなり重要な設計である。

---

## 3. なぜFine-tuningが必要か

Block-Attention maskだけをpretrained modelへ適用すると性能が大きく落ちる。

論文のpreliminary experimentでは、full-attention状態からBlock-Attentionへ単純switchすると、RAG benchmarkの平均accuracyが大幅に低下する。

最終experimentでも、

- **Tulu3-RAG**: full-attentionでfine-tuned
- **Tulu3-block-w/o-ft**: 同modelをfine-tuningなしでBlock-Attentionへ切替

を比較すると、4つのRAG benchmarkで平均**16.2 percentage points**程度低下する。

個別には、

| Model | 2Wiki | HotpotQA | NQ | TriviaQA |
|---|---:|---:|---:|---:|
| Tulu3-RAG | 73.2 | 74.8 | 61.5 | 75.8 |
| Block w/o FT | 42.9 | 42.1 | 48.3 | 66.5 |

となる。

つまり、

> document同士を見なくてもquery blockだけで情報統合する

という計算様式は、通常SFTされたmodelにとって自然なinference patternではない。

そこで論文では**Block fine-tuning**を導入する。

---

## 4. Block Fine-tuning

fine-tuning自体は新しいlossを導入するわけではない。

standard SFTとの主な違いはattention maskである。

通常のSFTで使うglobal lower-triangular causal maskを、Block-Attention maskへ置き換える。

これによりtraining中から、

- document blockは自身のblock内だけを見る
- final blockはそれ以前の全blockを見る

というinference時と同じdependency structureを経験させる。

### Full-Attention能力も維持するmixed training

興味深い点として、著者らはBlock-Attentionだけでfine-tuningしない。

同じtraining sampleを、

1. full-attention
2. Block-Attention

の**両方のmode**で学習する。

目的は、Block-Attentionへ適応させながら通常のfull-attention能力も失わないことである。

その結果、学習後のmodelは、

```text
RAG / ICL
  → Block-Attention mode

zero-shot / ordinary prompt
  → Full-Attention mode
```

のように切り替えられる。

論文では約800 training steps後には、両attention modeを切り替えてもほぼperformance lossがない状態へ到達すると報告している。

---

## Training Data

training dataは大きく2種類。

### Tulu3 SFT mixture

Tulu3のSFT datasetから、block分割可能なsampleを使用する。

分割ruleは、

1. multi-turn sampleでは1 user-assistant turnを1 block
2. system messageとuser messageを別block
3. `\n\n`、`---`、`===` 等のseparatorもblock boundaryとして利用

という比較的単純なheuristic。

このruleによってTulu3-SFT dataの約23%をblock fine-tuningに利用できる。

### RAG-specific training data

TriviaQAと2WikiMultiHopQAから合計20,000 instancesをsampleする。

各instanceではContrieverを使ってtop-10 passageをretrieveする。

training sampleは、

```text
question
+
10 retrieved passages
+
teacher answer
```

で構成される。

answerにはground-truthをそのまま使わず、retrieved passagesを見せた**Llama-3.3-70B-Instruct**の生成answerを使う。

理由は、ground-truth answerがretrieved top-10に含まれていない場合、modelがretrieval contextを無視してparametric knowledgeだけで答えるtraining signalになり得るため。

この点はRAG-oriented fine-tuningとして重要である。

## Base ModelとExperimental Setup

base modelは **Llama-3.1-Tulu-3-8B-SFT**。

主なmodel variantは、

- **Tulu3-SFT**  
  元のbase model。

- **Tulu3-RAG**  
  同じtraining dataでfull-attention SFTしたRAG baseline。

- **Tulu3-block-ft**  
  Block-Attention + full-attention mixed trainingを行った提案model。

- **Tulu3-block-ft-full**  
  block fine-tuned modelを推論時にfull-attentionへ戻したvariant。

- **Tulu3-block-w/o-ft**  
  fine-tuningせずmaskだけBlock-Attentionへ変更。

- **Tulu3-block-ft-w/o-pos**  
  block fine-tuningは行うがposition re-encodingを外すablation。

training環境は8× NVIDIA H20 GPU。

主要hyperparameterは、

- learning rate: (2 \times 10^{-5})
- batch size: 64
- epoch: 1
- warmup: 20 steps
- bfloat16
- DeepSpeed
- FlashAttention

評価にはOpenCompassを利用する。

|---|---:|---:|---:|---:|
| Tulu3-SFT | 62.0 | 68.4 | 58.6 | 75.7 |

> 独立した複数context componentを最後のqueryから読む

という一般的なprompt structureへ適用できる可能性が示される。

## Training-free Parallel Encodingとの比較

Block-Attentionの重要な主張は、**training-freeに独立KVをreuseするだけでは十分でない**という点にある。

baselineとして、

- PromptCache
- Superposition

を評価している。

RAG benchmarkでは、

| Model | 2Wiki | HQA | NQ | TQA |
|---|---:|---:|---:|---:|
| Tulu3-RAG | 73.2 | 74.8 | 61.5 | 75.8 |
| Superposition | 30.1 | 32.3 | 35.9 | 58.9 |
| PromptCache | 32.4 | 31.6 | 44.4 | 61.8 |
| Block-Attention FT | 72.2 | 72.3 | 60.4 | 75.1 |

となる。

著者らはtraining-free parallel context encodingでdegenerationも観察している。

つまり、

```text
documentを独立にencode
↓
KVを単純concat
↓
queryから読む
```

という形へmodelを突然変えるだけでは、full-attention pretrained representationとのdistribution mismatchが大きい。

Block-Attentionではこのmismatchをfine-tuningで吸収する。

## Position Re-encoding Ablation

position re-encodingを削除した **Tulu3-block-ft-w/o-pos** は、

| Model | 2Wiki | HQA | NQ | TQA |
|---|---:|---:|---:|---:|
| Block FT | 72.2 | 72.3 | 60.4 | 75.1 |
| w/o position re-encoding | 68.9 | 69.9 | 59.2 | 74.4 |

となる。

平均約2 percentage pointsのaccuracy低下があり、occasionally degenerationも起きる。

この結果は、

> blockのhidden contentだけ合っていればよく、RoPE positionは雑に扱ってよい

というわけではないことを示す。

reuseされたKVをglobal prompt内の位置へ正しく再配置する処理は、fine-tuning後でも重要である。

---

## Fine-tuning Step数のAblation

training開始直後は、

- Block-Attention mode
- Full-Attention mode

のperformance差が大きい。

fine-tuningが進むにつれてgapが縮まり、論文では**約800 steps**で両modeをほぼseamlessに切り替えられる状態になる。

これは比較的少ない追加学習でattention pattern変更へ適応できることを示す。

一方で、

> full pretrained modelを完全にtuning-freeでreuse architectureへ変換できる

わけではない点も明確である。

---

## Inference Pipeline

実serviceでは、retrieved passagesのKVがあらかじめcacheされていることを前提にする。

request時の処理は、

```text
Retriever
   ↓
Passage IDs
   ↓
KV Cache lookup
   ↓
Cached block KV
   ↓
Position re-encoding
   ↓
Concatenate block KV
   ↓
Compute only final query block
   ↓
Generate first token
```

となる。

従来full-attentionでは、

```text
all retrieved passages
       ↓
full prefill
       ↓
query
       ↓
first token
```

であった。

Block-Attentionでは大量のpassage部分についてGPU forwardを省略し、query blockだけを新たに計算できる。

---

## TTFT / FLOPs

efficiency評価ではuser input lengthを50 tokensに固定し、retrieved contextを長くする。

結果は、

| Total Prompt Length | Full TTFT | Block TTFT |
|---:|---:|---:|
| 50 | 26 ms | 26 ms |
| 512 | 50 ms | 26 ms |
| 1K | 87 ms | 26 ms |
| 2K | 167 ms | 26 ms |
| 4K | 330 ms | 27 ms |
| 8K | 691 ms | 29 ms |
| 16K | 1515 ms | 34 ms |
| 32K | 3638 ms | 45 ms |

となる。

32Kでは、

- Full attention: 3638 ms
- Block-Attention: 45 ms

で、**TTFT 98.7% reduction**。

FLOPs-TFTは、

- full 32K: (4.9 \times 10^{14})
- block: (7.5 \times 10^{11})

となり、**99.8% reduction**。

Block-Attention側のFLOPsがcontext lengthに対してほぼ一定なのは、retrieved passageを新規prefillせず、50-token query blockの計算だけを行うためである。

ただしこの測定は、**retrieved passageのKVがすでにprecomputeされmemory上に存在する**条件である。

論文自身もKV cache storage costは評価対象外としている。

---

## なぜLong Contextほど有利か

full prefill costはretrieved context lengthとともに増える。

一方Block-Attentionでは、cache hitしているpassage部分のforward computeはほぼ消えるため、runtime computeは主としてfinal query blockへ依存する。

したがってcontextが長くなるほど、

[
\frac{C_{query}}{C_{full-context}}
]

が小さくなり、speedupが大きくなる。

論文で512 tokens時のTTFT reductionが48%なのに、32Kで98.7%まで拡大するのはこのため。

---

## CacheBlendとの違い

[CacheBlend](2024-2405.16444-cacheblend.md)も、RAG documentごとのcached KVを再利用することを目標とするが、問題の解き方が大きく異なる。

### CacheBlend

pretrained modelのfull-attention semanticsを維持する。

独立計算したKVをconcatしただけではcross-document attentionが欠落するため、重要tokenを**selective recomputation**してfull-prefill stateへ近づける。

```text
cached KV
   ↓
concatenate
   ↓
identify important tokens
   ↓
partial recomputation
```

### Block-Attention

そもそもdocument block間のattentionをmodel specificationから外す。

その代わり、

```text
block-local attention
+
position re-encoding
+
fine-tuning
```

によって、その新しいattention patternでも正しく推論できるmodelへ変える。

したがってtrade-offは、

| | CacheBlend | Block-Attention |
|---|---|---|
| model modification | 原則不要 | fine-tuning必要 |
| cross-document attention | 部分的に回復 | passage間では使わない |
| runtime recomputation | あり | cached passageではほぼなし |
| reuse efficiency | recompute率に依存 | cache hit時は非常に高い |
| compatibility | pretrained model向き | adapted modelが必要 |

となる。

---

## EPICとの違い

[EPIC](2024-2410.15332-epic.md)はPosition-Independent Cachingを目指し、cached segmentを任意位置で再利用する。

EPICはattention sink等のreuse artifactを**inference-time linking mechanism**で軽量に補正する方向。

Block-Attentionは、position re-encodingだけでなく、model自体をblock-independent encodingへfine-tuneする。

したがって、

- EPIC: existing model + lightweight repair
- Block-Attention: training-adapted reuse

という違いで整理できる。

---

## PromptCache / Superpositionとの違い

PromptCacheやparallel context encodingも、prompt moduleを独立計算してreuseする発想を持つ。

しかしBlock-Attention論文では、それらをTulu3-RAGへ適用するとaccuracyが大きく低下した。

著者らは原因として、

- positional encodingの扱い
- full-attention trainingとのmismatch
- independent encodingに対するmodel adaptation不足

を問題視する。

Block-Attentionはreuse strategyだけでなく、

> **reuse時のattention graphをtraining時からmodelに経験させる**

点が大きな違い。

---

## TurboRAGとの関係

論文ではTurboRAGをconcurrent workとして明示している。

TurboRAGも、

- independent attention
- reordered positions
- passage-level KV reuse

という非常に近い考え方を独立に提案している。

Block-Attention側の説明では、両者はほぼ同時期に類似した結論へ到達した研究として位置づけられる。

今後reuse categoryではTurboRAGも収録価値が高い。

---

## Sparse Attentionとの違い

Native Sparse Attention (NSA)やMixture of Block Attention (MoBA)もblock単位のattentionを扱うため名前は似ているが、目的は異なる。

NSA / MoBAでは、

1. inputをblock化
2. queryに関連するblockを選択
3. selected blockのみattention

という**sparse attention compute削減**が中心。

Block-Attentionは、

1. blockを独立prefill
2. block KVをcross-requestでcache
3. 別promptでもreuse

という**parallel encoding + cache reuse**が中心。

したがって、KVcache taxonomy上ではsparse attentionよりreuseへ置く方が自然である。

---

## 制約・Limitations

### 1. Fine-tuningが必要

最大の制約。

既存pretrained / instruct modelへmaskだけ適用すると大きくaccuracyが低下するため、そのままdrop-inで導入できない。

### 2. Document間interactionを捨てる

passage block同士はattentionしない。

したがって、

```text
Doc Aのrepresentationを
Doc Bの内容を見ながら更新する
```

というlayer-by-layer interactionは起こらない。

multi-hop QAで最終query blockが両documentを見て統合できることは実験で示されるが、full attentionと内部計算は本質的に異なる。

### 3. Cache storage costを評価していない

論文のTTFT測定はKVが既にmemoryにcacheされている前提。

大規模RAG corpusでは、

- GPU memory
- CPU memory
- NVMe
- cache lookup
- transfer bandwidth
- eviction policy

が実systemでは重要になる。

### 4. Cache hit率に依存

一度も見たことのないpassageはKVを新規計算する必要がある。

したがって実運用speedupは、retrieval distributionとpassage reuse frequencyに依存する。

### 5. Block granularity

1 passage = 1 blockが自然なRAGでは使いやすいが、document内で強い前後dependencyがある場合、block boundaryの選択がaccuracyへ影響する可能性がある。

---

## KV-cache reuse taxonomyでの位置づけ

Block-Attentionは **reuse-aware fine-tuning / training-adapted reuse** の代表例として分類できる。

KV reuseの方向性は大きく、

### 1. Exact Prefix Reuse

```text
same prefix
→ same KV
```

vLLM / SGLang等のprefix caching。

最も正確だがhit条件が厳しい。

### 2. Inference-time Repair

```text
independent cached KV
→ concatenate
→ partially repair
```

代表: [CacheBlend](2024-2405.16444-cacheblend.md)

既存modelとの互換性が高い。

### 3. Position-independent Linking

```text
cached module
→ reposition / lightweight link
```

代表: [EPIC](2024-2410.15332-epic.md)

任意位置でのreuseを狙う。

### 4. Reuse-aware Fine-tuning

```text
change attention dependency
→ fine-tune model
→ direct block KV reuse
```

代表: Block-Attention。

推論時overheadを下げる代わりにtraining adaptationを要求する。

---

## 研究上の重要な示唆

この論文の重要な点は、KV reuseのaccuracy問題に対して、

> 「full prefillをどれだけ正確に近似するか」

だけが解ではないことを示した点にある。

CacheBlendのような手法は、

[
KV_{reuse} \approx KV_{full}
]

を目指す。

Block-Attentionは逆に、

[
\text{Model itself adapts to } KV_{reuse}
]

という方向を取る。

つまりfull-attention modelの内部stateを完全再現することを諦め、reuseされたstateでも正しく答えられるmodelを学習する。

これはKV reuse研究を考える上で大きく2方向、

```text
A. modelを固定してcacheをfull prefillへ近づける
B. cache形式を固定してmodelをcacheへ適応させる
```

に整理できることを示す。

さらに実用上はこの中間、

```text
reuse-aware fine-tuning
+
small selective recomputation
```

というhybridも考えられる。

fine-tuningによって必要recompute率を下げ、どうしてもcross-document dependencyが強いtokenだけを再計算する設計は、Block-AttentionとCacheBlendの自然な接続点になる。

---

## まとめ

Block-AttentionはRAGの長いprefillを、

```text
All documents
      ↓
Sequential full prefill
      ↓
Query
```

から、

```text
Reusable Document Blocks
      ↓
Cached KV
      ↓
Position Re-encoding
      ↓
Query-only Prefill
```

へ変える。

これを成立させる要素は3つ。

| Component | Role |
|---|---|
| Block segmentation | passage間のcausal dependencyを切り、KVを独立化 |
| Position re-encoding | cached KVをrequest内の新positionへ移動 |
| Block fine-tuning | full-attention trainingとのdistribution mismatchを解消 |

fine-tuningなしではRAG accuracyが大幅に落ちる一方、block fine-tuning後はfull-attention RAG baselineに近い性能まで回復する。

32K contextでは、cached passageがすでに利用可能という条件下でTTFTを3638 msから45 msへ短縮し、98.7% reduction、FLOPs-TFTでは99.8% reductionを報告する。

KV再利用研究の観点では、**推論時に壊れたKVを修復するのではなく、独立KVを直接使えるようmodel側を学習させる**という代表的なアプローチであり、CacheBlend / EPICとは明確に異なる系統として重要である。

## 関連文献

### CacheBlend

[CacheBlend: Fast Large Language Model Serving for RAG with Cached Knowledge Fusion](2024-2405.16444-cacheblend.md)

独立cached KVのcross-document interaction不足をselective recomputationで補う。Block-Attentionがtraining adaptationで問題を避けるのに対し、CacheBlendはpretrained modelを維持してruntime repairする。

### EPIC

[EPIC: Efficient Position-Independent Caching for Serving Large Language Models](2024-2410.15332-epic.md)

position-independent reuseを目指す点は共通するが、EPICはinference-time linkingを中心とし、Block-Attentionはblock-aware trainingを中心とする。

### PromptCache

prompt module単位のcache reuseを狙うtraining-free手法。Block-Attention論文ではbaselineとして評価され、RAG accuracy低下が大きいことから、position handlingとmodel adaptationの必要性を示す比較対象となっている。

### TurboRAG

Block-Attentionとほぼ同時期にindependent attentionとposition reorderingによるpassage-level KV reuseを提案したconcurrent work。reuse-aware / modular RAG cachingの系譜を整理する上で、今後repositoryへ追加する価値が高い。
