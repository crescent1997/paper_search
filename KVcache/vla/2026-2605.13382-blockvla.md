# 概要
BlockVLAは、自己回帰（AR）型OpenVLAを離散拡散によるaction-token生成に適応させつつ、拡散の双方向attentionが通常のprefix KV reuseを妨げる問題を解く。全action tokenを一括で反復denoiseする代わりに、**ブロック間はcausal、ブロック内はbidirectional**という非対称maskを使う。確定したブロックのKVは次のブロックで再利用できる。**この論文は視覚フレーム間のKV再利用ではなく、同一action生成系列内の確定済みprefix KV再利用**である。

# 問題設定・先行研究との差
- OpenVLAのようなAR action decoderは1 tokenずつ出力するため長いaction chunkでdecode遅延が増える。
- 離散拡散（DDVLA）は複数action tokenを並列に修正できるが、denoisingのたびに双方向文脈が変化し、prefixを含めた再計算が必要になりやすい。
- BlockVLAはblock diffusionを導入し、過去の確定ブロックの因果的依存性と現在ブロック内の並列denoisingを両立する。VLA-Cacheのような**連続観測フレーム間**のキャッシュとは異なる。

# 手法
## 1. Action token化とblock partition
Prismatic-7B / OpenVLA系のSigLIP+DINOv2 vision encoder、Llamaベースdecoderを使用。7自由度のactionを各次元256 binに量子化し、1制御stepを7 action tokensとする。連続したaction tokensを長さ7または14などのblockに分割する。

## 2. 非対称attention mask
現在のblock内では双方向attentionでmasked tokensを同時予測するが、未来blockは参照できない。blockの確率分解は以下。

```math
\log p_\theta(a)=\sum_{b=1}^{B}\log p_\theta(a^{b}\mid a^{<b}).
```

このblock間causalityがprefix cacheの成立条件である。学習時はmask corruptionを施し、masked tokenのcross-entropyを最小化。teacher forcingとdiffusion forcingを比較し、過去blockにノイズを含む場合も考慮する。

## 3. 推論時のKV cache更新
1. Vision/proprioception/language prefix `c=[BOS,v,p,l]` をprefillしKVを保存。
2. block `b` を[MASK]で初期化し、**KV更新を止めて**数回のdenoisingを行う（過去prefixのKVは固定）。
3. blockが確定したらそのaction tokensを**一度だけforward**してKVを追加する。
4. position indexを進め、次blockへ。論文Algorithm 2の`update=False/True`がこの分離を明示する。

重要なのは現在blockの中間状態をキャッシュし続けるわけではない点。毎回変化するのは現在blockのみで、確定prefixだけを再利用する。

# Experiment Setup
- LIBERO Spatial/Object/Goal/Long、各suite 10 tasks。成功率を報告。
- SimplerEnv WidowX、4 pick-and-place tasks、各24 episodesでgrasp countとsuccess countを報告。実機評価ではなくreal-to-sim。
- Baselines: AR OpenVLA（元論文報告値）、DDVLA（12 denoising steps）。BlockVLAは2 denoising steps/blockを主設定とする。
- LIBEROは50k training steps、2 GPUsの条件を記載。追加fine-tuningが必要でtraining-freeではない。
- throughputはtokens/s。ロボットの実制御Hzやcamera-to-action latencyと同一視しない。

# Main Results
## LIBERO 50k training steps
| Suite | AR OpenVLA（引用値） | DDVLA | BlockVLA |
|---|---:|---:|---:|
| Spatial | 84.7% | 89.8% | 90.6% |
| Object | 88.4% | 96.6% | 97.6% |
| Goal | 79.2% | 92.6% | 93.2% |
| Long | 53.7% | 53.6% | 85.2% |
| Average | 76.5% | 83.2% | **91.7%** |

LIBERO-Longの15k steps時点ではDDVLA 3.8%、BlockVLA 62.2%（本文説明の丸め値60.0%とはTable 3が異なるため、表の62.2%を優先）。この差は**同じ学習ステップでの収束効率**であり、同じ推論予算・学習計算量を厳密に固定した因果的比較ではない。

## 推論throughput
2 denoising steps/blockで186.7 tokens/s。DDVLA比**3.3倍**、AR OpenVLA比**8.0倍**。論文はtokens/sを報告するが、end-to-end observation-to-action latency、GPU peak VRAM、消費電力、実機制御周波数は包括的に比較していない。

## SimplerEnvの注意点
60k steps時点でPut Spoon on TowelはBlockVLA 12/24、DDVLA 7/24だが、Put Carrot on PlateはBlockVLA 4/24、DDVLA 5/24。全タスク一律の改善ではない。

# 主要ablation
- **Block size 7 vs 14**: 14がLIBERO-Object/Longで良好。2 step分のactionを同時denoiseできることが一因と考察。
- **Teacher forcing vs diffusion forcing**: ノイズを含む履歴を学習に使うdiffusion forcingが安定性に有利と報告。
- **Denoising steps**: 反復回数を増やすと品質・速度のtrade-off。主設定2 steps/blockのthroughputが比較値。
- **Token shift**: baseline比較の公平性のためDDVLA/BlockVLAともno-token-shiftを採用。

# Limitations
1. prefix cacheは**同一推論要求内のblock間**であり、ロボットが次のcamera frameを観測した後も再利用できることは実証していない。
2. 追加fine-tuningが必要。単純なruntime KV optimizationと学習条件を揃えた比較ではない。
3. throughput改善と実機action Hz改善は別指標。GPU memory、energy、latency分布、failure recoveryの実測不足。
4. AR OpenVLAは引用値、DDVLAとBlockVLAは別学習設定。モデル/学習条件に依存する。
5. SimplerEnvのtask別結果は混在。実ロボット実験は確認できない。

# Taxonomy / 既存研究との比較
`KVcache/vla/` — **action decoding / intra-request prefix KV reuse**。`VLA-Cache`やLACは連続フレーム間の視覚KVを再利用し、BlockVLAは**生成済みaction blockのKV**を再利用する。`MEM`は長期記憶であり、時間尺度と目的が異なる。
