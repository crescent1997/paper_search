# Faster-GCG: Efficient Discrete Optimization Jailbreak Attacks against Aligned Large Language Models

## 概要

Faster-GCGは、[GCG](2023-2307.15043-gcg.md)の基本的なwhite-box discrete optimization frameworkを維持しながら、その大きな弱点である**sample efficiencyとwall-clock cost**を改善するattackである。

GCGではgradientから各token replacementの効果を近似し、top-k候補から多数を評価する。しかし著者らは、(1) gradient approximationが不正確、(2) top-k内uniform samplingが非効率、(3) 過去に評価したsuffixを再評価する、という3つの無駄を特定する。

Faster-GCGはそれぞれにdistance-based regularization、temperature-controlled sampling、visited-suffix markingを導入し、元GCGより少ないcandidate evaluationで高いASRを達成する。

## 問題設定 / Threat Model

基本threat modelはGCGと同じwhite-box jailbreakである。

attackerは、

- target/surrogate model weights
- tokenizer
- token embedding
- gradient
- candidate suffixのloss

へアクセスできる。

harmful requestへadversarial suffixを付加し、aligned modelに拒否ではなくharmful responseを生成させる。

closed-source targetに対しては、open-source surrogateで生成したsuffixをtransferする。

## GCGの3つのボトルネック

### 1. Inaccurate Gradient-based Estimation

GCGはone-hot token replacementに対するfirst-order gradientから「このtokenへ置換すればlossが下がる」と予測する。

しかしtoken replacementはembedding space上で有限距離を飛ぶdiscrete updateであり、候補embeddingが現在tokenから遠いほどTaylor approximation errorが大きくなる。

### 2. Inefficient Uniform Sampling

GCGはgradient上位top-k候補を得た後、その中から比較的均等にcandidateをsampleする。

しかしtop-k内でもcandidate qualityは大きく異なり、明らかに有望なtokenと弱いtokenへ同じsampling budgetを使うのは非効率である。

### 3. Repeated Suffix Evaluation

iterative search中に、以前評価済みのsuffixと同一candidateが再出現することがある。expensiveなforward evaluationを再度行うのは完全な無駄となる。

## Method / Algorithm

### Distance-based Regularization

gradient scoreだけでなく、current tokenとcandidate tokenのembedding distanceを考慮する。

gradientが示すloss reductionが大きくてもembedding距離が大きすぎるcandidateはfirst-order approximationが不正確になりやすいためpenaltyを加える。

これにより「gradient上は有望だが実際のforward lossでは悪い」candidateを減らす。

### Temperature-controlled Sampling

top-k candidateをuniformに選ぶ代わりに、estimated qualityをprobabilityへ変換し、temperature parameterを用いてsampling distributionを制御する。

低temperatureでは有望候補へ集中し、高temperatureではexplorationを増やせる。

### Visited-suffix Marking

評価済みsuffixを記録し、同じsuffixをcandidate batchへ再投入しない。

単純だが、iteration数が増えるほど重複candidateを排除する効果が大きくなる。

## Experiment Setup

複数のopen-source aligned LLMを対象にwhite-box jailbreakを行い、GCGおよび他optimization-based attacksと比較する。

主要metricは、

- Attack Success Rate (ASR)
- model/candidate evaluations
- wall-clock time
- closed-source modelへのtransferability

である。

## Main Results

論文では元GCGが満足な成功率を得るために約256K candidate evaluations / harmful behaviorを要するのに対し、Faster-GCGは約32K evaluationsで強いattackを構築できると報告する。

これは**最大約8×のsample efficiency改善**に相当し、wall-clockでも**約7×高速化**する。

削減されたbudgetでも5つのaligned LLM平均で**78.1% ASR**を達成し、元GCGを上回る。

またopen-source modelで生成したattackのclosed-source ChatGPT等へのtransferabilityも改善する。

## GCGからの技術的差分

```text
GCG
 gradient top-k
   ↓
 uniform candidate sampling
   ↓
 forward evaluation
   ↓
 greedy replacement

Faster-GCG
 gradient + embedding-distance regularization
   ↓
 temperature-weighted sampling
   ↓
 remove visited suffixes
   ↓
 forward evaluation
   ↓
 greedy replacement
```

GCGのattack objectiveやsuffix representationを根本的に変更するのではなく、**coordinate searchの候補生成・評価効率を改善する**手法である。

## Transferability

attack optimizationが高速になることで、同じcompute budget内でより強いsuffixを探索できる。その結果、surrogateでのASRだけでなくclosed-source targetへのtransferも改善する。

ただしtransfer stage自体はblack-boxでも、suffix optimizationはwhite-boxである点はGCGと同じ。

## Query / Compute Cost

Faster-GCGの中心的貢献である。

概念的には、

```text
GCG:        ~256K evaluations / behavior
Faster-GCG: ~32K evaluations / behavior
```

までcandidate evaluationを削減する。

この差はDefense評価にも重要で、固定compute budget下でGCGが失敗しても、それが真のrobustnessなのかoptimizer inefficiencyなのかを区別する必要がある。

## Prompt Injection / Instruction Hierarchyとの関係

Faster-GCGも原則はjailbreak attackであり、system/user/tool authorityを直接spoofするものではない。

しかし[SecAlign](../Defense/2024-2410.05451-secalign.md)や[Meta SecAlign](../Defense/2025-2507.02735-meta-secalign.md)のようなmodel-level prompt injection defenseをwhite-box optimizationで評価する際、GCGの探索効率を上げる技術はそのまま利用可能である。

特に「GCGをN steps実行して破れなかった」というsecurity claimに対し、よりefficientなoptimizerを用いると同一computeで強いattackを作れるため、robustness評価を厳しくできる。

## Limitations

- gradient accessを必要とするwhite-box attack。
- adversarial suffixが不自然なtoken列になりやすい。
- efficiency改善はformal optimalityを保証しない。
- prompt injection / privilege confusion専用のobjectiveではない。
- input filterやnon-differentiable preprocessingを含むsystem全体ではgradient-based searchをそのまま適用できない場合がある。

## LLM Model Security Taxonomyでの位置づけ

```text
GCG
  strong but expensive discrete optimization
        ↓
Faster-GCG
  better candidate estimation
  + better sampling
  + duplicate elimination
        ↓
stronger / cheaper adaptive evaluation
```

## 実装・研究上の示唆

model-level defenseを評価する際には、ASRだけでなく**attack budgetに対するASR curve**を見る必要がある。

GCGの固定iteration数だけをbaselineにするとoptimizerの非効率をdefense robustnessと誤認する可能性がある。Faster-GCGはこの点を明確にする。
