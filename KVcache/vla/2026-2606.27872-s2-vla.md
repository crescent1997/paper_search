# S²-VLA — State-Space Guided VLA for Long-Horizon Manipulation

**一次資料:** [arXiv HTML全文](https://arxiv.org/html/2606.27872v1)、[PDF](https://arxiv.org/pdf/2606.27872)。IJCAI 2026採択は著者コメントによる情報で、公式採択一覧との照合は未了。

## 1. 概要・問題設定

長時間のロボット操作では、視覚的な位置把握、指示内容の解釈、直前までの行動系列への整合性の重要度がタスク進行段階ごとに変わる。固定重みのmultimodal fusionはこの変化に適応しにくく、累積誤差が大きくなる。S²-VLAはrecurrent belief stateでタスク進捗を追跡し、State-Space Guided Adaptive Attention (SSGAA) がvisual feature、language intent、temporal action featureの融合gateを動的に変える。これは**TransformerのKV cache最適化ではなく、過去情報の利用方法を制御するrecurrent memory方式**である。

## 2. 先行研究との差

- [MemoryVLA](2025-2508.19236-memoryvla.md): 過去観測をperceptual-cognitive memory bankとして保存・検索する。S²-VLAは固定の明示的episodic storeよりもbelief stateを用いた融合重みの動的変更が中心。
- [MEM](2026-2603.03596-mem.md): 短期視覚・長期言語記憶を分離。S²-VLAは独立した長期semantic memoryや明示的な検索・忘却操作を持たない。
- [EventVLA](2026-2606.20092-eventvla.md): イベントを選択して保持する。S²-VLAは記憶内容のイベント選択ではなく、現在のmodalitiesの融合を調節する。
- [VLA-Cache](2025-2502.02175-vla-cache.md): visual KVの再利用によって計算を削減。S²-VLAはそのようなcross-frame layer KV reuseを提案していない。

## 3. 手法

### 3.1 Recurrent belief state

物理制御stepごとにGRUが内部belief stateを更新する。過去actionと現在観測からtask phaseを推定するための圧縮状態であり、明示的な過去画像検索ではない。belief stateは後段のgate生成に入力される。履歴が非常に長い場合の情報保持容量や過去イベントの個別再現精度は、論文の主評価ではない。

### 3.2 SSGAAとaction generation

SSGAAはvisual、language、temporal actionの3情報源に対するgateを状態依存で計算する。行動予測と実行の後、beliefを更新するrecurrent loopで動作。論文のablationでは24-layer構成のうち中間の**layer 12だけにgate**を入れる方式が最良で、全層gateは逆効果。タスク段階に応じた情報源の重みづけが中心で、memory read/write/evictionの設計ではない。

### 3.3 学習と計算

Qwen3-VLを基礎とするvision-language backbone、belief update、SSGAAをend-to-endで共同学習する。学習には4基のH100を使用したと記載。推論VRAMは**7GB**と報告。ただしこの値の精密な測定条件・他手法との同一ハードウェアでの比較が必要であり、KV cache削減による効果とはみなせない。追加学習が必要でtraining-freeではない。

## 5. Main Results

### 5.1 LIBERO（Table 1）

| Method | Spatial | Object | Goal | Long | Avg. |
|---|---:|---:|---:|---:|---:|
| MemoryVLA（参考） | 98.4 | 98.4 | 96.4 | 93.4 | 96.7 |
| CronusVLA（参考） | 97.3 | 99.6 | 96.9 | 94.0 | 97.0 |
| OpenVLA-OFT（参考） | 97.6 | 98.4 | 97.9 | 94.5 | 97.1 |
| **S²-VLA** | **98.4** | **99.6** | **98.4** | **96.4** | **98.2** |

長時間タスクのLongは96.4%。ただしbenchmark全体が高成功率のため、recurrent stateの長期保持能力を単独で証明するものではない。異なるmodel size、training data、inputsを横断した比較であり、優位性を一般化できない。

### 5.2 SimplerEnv-Bridge（Table 2）

| Method | Spoon | Carrot | Stack | Eggplant | Avg. |
|---|---:|---:|---:|---:|---:|
| MemoryVLA（参考） | 75.0 | 75.0 | 37.5 | 100.0 | 71.9 |
| **S²-VLA** | **83.3** | **87.5** | **41.7** | **100.0** | **78.1** |

S²-VLAは平均78.1%。MemoryVLAと条件を厳密に一致させた比較ではないため、同一backboneでの改善量とは解釈できない。

### 5.3 実機

ALOHAの4タスクでACT、pi0-FASTと比較し改善を報告。本文では定量的な全タスク成功率が図に含まれており、HTML本文から正確な数値を確定できなかったため、**具体的成功率は未転記**。30Hzはロボット制御設定であり、model forward throughputの実測値と混同しない。

## 6. 主要ablation（Table 3）

| Variant | Gated layer | Success |
|---|---|---:|
| w/o Gate | なし | 95.0 |
| Gate@All | 全層 | 94.4 |
| Gate@6 | 6 | 96.0 |
| **Gate@12** | **12** | **96.4** |
| Gate@18 | 18 | 95.8 |
| Gate@24 | 24 | 94.8 |
| Gate@6,12,18 | 3層 | 94.4 |
| Gate@12, w/o State | 12、静的state | 95.8 |

全層gateが94.4%へ低下することは、gateを増やすほど良いわけではないことを示す。belief stateを定数に置き換えると96.4→95.8%へ低下するため、**状態依存のgateが約0.6pp寄与**する。ただしablation値96.4%とmain table平均98.2%は実験設定・集計の文脈が異なり、混同しない。

## 7. Limitations

1. **KV cache非対象**: layer KVの再利用・圧縮・evictionは扱わない。推論VRAM 7GBはKV最適化の効果を直接示さない。
2. **長期記憶の検証不足**: 明示的なepisodic retrievalやforgetting policyがなく、履歴長に対する記憶保持率・memory capacity tradeoffは十分に示されていない。
3. **比較条件**: 既報baselineが多数。model sizeやtraining regimeが揃わず、同条件のMEMとの比較もない。
4. **追加学習**: Qwen3-VL backboneを含むend-to-end trainingが必要。training-freeなcache reuseとは導入コストが異なる。
5. **Latency**: end-to-end forward latency、throughput、policy control frequencyとGPU peak memoryの同条件比較が不足。実機30Hzはロボット側の制御設定。
6. **評価の飽和**: LIBERO 98.2%は高いが、極めて長時間の部分観測タスクでの頑健性は別途検証が必要。

## 8. Taxonomy

- Primary: `KVcache/vla/` — **recurrent belief state / state-space guided multimodal fusion / long-horizon manipulation**。
- Memory type: implicit recurrent task-phase memory。KV cache reuseではない。
- [MEM](2026-2603.03596-mem.md)との違い: 長期言語記憶を検索するのではなく、belief stateを用いて視覚・言語・行動特徴の利用比率を変える。
- 研究課題: 明示的episodic memoryとrecurrent beliefを併用した場合のtask success、GPU memory、latencyの比較。ただし未検証。
