# Gated VLA-Cache — Neural Introspection Gating

## 1. 概要
連続するカメラ観測で静止したvisual patchのKVを再利用するVLA-Cacheに、**モデル自身のaction予測の不確実性**を追加する。前の制御ステップでaction tokenの予測が曖昧だった場合は、次のステップでキャッシュを無効化し、全visual tokenのKVを再計算する。学習や追加の予測モデルを必要とせず、既に計算済みのdecoder logitsを使う。

**位置付け**：長期記憶を別のMemory Bankに保存する方式ではない。フレーム間KV再利用の信頼性を改善するruntime gatingである。

## 2. 問題設定・先行研究との差
VLA-Cache（[既登録要約](2025-2502.02175-vla-cache.md)）は(1)隣接画像patchのcosine類似度、(2)text-to-vision attentionによるtask relevance、(3)layer-wise attention entropyで再利用候補を選ぶ。しかし、画像の見かけが変化しなくてもgrasp alignmentなどで行動が変化することがある。観測空間だけを見ていると、古いKVがactionの判断を誤らせる可能性を検知できない。

本研究はvisual tokenの選択則そのものではなく、**全キャッシュを信頼してよいか**をdecoder出力から決める。VLA-Cacheの部分再計算に対する追加の外側のgateである。

## 3. 手法
### 3.1 VLA-Cacheの基盤
各patchのフレーム間cosine類似度を測り、閾値（既定値0.996）以上を静的候補とする。task-relevant patchを除外し、layerごとにattention entropyに応じてKVを再利用する。visual token数の例は224×224画像、14×14 patch、256 tokens。

### 3.2 Neural introspection gate
制御ステップ`t-1`で生成する`D`個のaction tokenについて、各次元のtop-1確率とtop-2確率の差を平均する。

$$m_{t-1}=\frac{1}{D}\sum_{d=1}^{D}\left(p_{1,d}-p_{2,d}\right).$$

`m_{t-1}<θ_m`なら、ステップ`t`の全KV cacheをinvalidateしてfull forward。そうでなければ通常のVLA-Cacheによるpartial forwardを実行する。fresh KVは次のステップへ保存する。**判定には1ステップの遅延がある**。logitsを再利用するためgateの追加学習・独立network forwardはないが、full recomputeの実行コストは当然発生する。

### 3.3 実装・再現性上の重要事項
著者公開コードは`openvla/`と`openvla-oft/`の両実装を収録。READMEは、論文で使用した**OpenVLA-OFT版にaction-token logitsのindexずれがあり、reuse時に短縮された系列の先頭から誤った位置を読んでいた**ことを明記している。修正済み`main`は末尾基準のindexへ変更。論文版の再現には`iros2026`タグが必要で、`main`の結果を論文Table IIと同一視してはいけない。著者の追試（RTX 5090、LIBERO-Spatial）ではgate発火率14.5%（論文版）→33.7%（修正版）、TFLOPs/step 3.25→3.44、成功率98.4→98.0%。GPU・PyTorchが論文と異なるため横断比較ではなく同一機械内の比較である。

## 4. Experiment Setup
- **Model**：OpenVLA（7B、autoregressive action tokens）、OpenVLA-OFT。
- **Benchmark**：LIBERO-Spatial / Object / Goal / Long、各suite 10タスク×50 episodes=500 episodes。
- **Hardware**：NVIDIA A100（論文評価）。
- **Baselines**：Full inference、VLA-Cache（patch threshold 0.996、top-k 120）。
- **Metrics**：タスク成功率（SR, %）、1ステップあたりTFLOPs。論文はend-to-end latency、GPU memory、throughput、実機control frequencyの定量比較を示していない。
- **Threshold**：OpenVLA `θ_m=0.65`、OFT `θ_m=0.50`。LIBERO-Spatialで選び、同じモデルの他suiteへ固定。
- **追加学習**：gateおよびcache方式に不要（評価には既存fine-tuned checkpointsを使用）。

## 5. Main Results
### 5.1 OpenVLA（SR% / TFLOPs per step）
| LIBERO | Full | VLA-Cache | Gated VLA-Cache |
|---|---:|---:|---:|
| Spatial | 78.8 / 1.89 | 78.8 / 1.43 | **79.4 / 1.55** |
| Object | 70.4 / 1.86 | 69.4 / 1.44 | **67.8 / 1.54** |
| Goal | 77.2 / 1.83 | 74.0 / 1.40 | **77.4 / 1.50** |
| Long | 54.0 / 1.88 | 50.2 / 1.43 | **54.8 / 1.54** |
| 平均 | 70.1 / 1.87 | 68.1 / 1.43 | **69.9 / 1.53** |

Goalで+3.4pt、Longで+4.6pt（対VLA-Cache）。一方Objectでは**-1.6pt**となり万能ではない。平均計算量はFull比約18%減（TFLOPsの比較でありwall-clock speedupではない）。

### 5.2 OpenVLA-OFT
平均SRはFull 95.8%、VLA-Cache 95.8%、Gated 95.7%。TFLOPs/stepはそれぞれ3.97、3.07、3.13。OFTは元々cacheに頑健でありgateの追加利益は小さい。ただし上記コードのindex問題を踏まえ、論文表の数値は論文版実装の測定値として扱う。

### 5.3 長時間実行と制御
LIBERO-Longではgateが平均約24%の制御ステップで発火（残り76%はcache再利用）。グラスプやサブタスク切替付近で発火する定性的トレースを示す。**長時間タスク成功率の改善は示すが、実機での長期連続稼働・メモリ上限・制御周波数は未評価**。

## 6. 主要Ablation
- **閾値感度**：OpenVLA-Spatialで`θ_m=0.55〜0.75`に対してSR 78.2〜79.4%。OFT-Spatialで`0.40〜0.60`に対して93.2〜94.0%。モデルごとのcalibrationが必要。
- **代替不確実性指標**：著者はaction distribution entropy、attention entropy、隣接action deltaも試したが、logit marginの方がgate signalとして有効と説明。定量比較表は示されていない。
- **backbone差**：OpenVLAで利得が大きく、OFTでは利得が限定的。

## 7. Limitations / 批判的評価
1. 予測の確信度が高くても**誤ったactionを自信を持って出す**場合は検知できない。1-step lagもある。
2. 実機latencyやenergy、GPU memoryは報告せず、FLOPs削減と速度向上を混同できない。
3. OpenVLA-OFTの論文実装にindex bugがあり、修正版は発火率・計算量が変化する。公開コードREADMEの修正情報を優先して読む必要がある。
4. [The Gate, Not the Cache](2026-2608.00391-the-gate-not-the-cache.md)は、self-harvestedなsparse forward由来のgateがfailureを見逃す場合を示す。**action marginの有効性がすべてのVLA・skip ratioで成立するとは限らない**。両論文は評価条件が異なるため直接の反証ではない。
