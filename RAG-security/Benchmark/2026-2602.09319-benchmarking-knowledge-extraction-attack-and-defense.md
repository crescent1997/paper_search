# Benchmarking Knowledge-Extraction Attack and Defense on Retrieval-Augmented Generation

> RAGのknowledge-base extraction研究でばらばらだったattack、defense、retriever、generator、knowledge-base construction、dataset、metricを統一し、**「何をretrieveできたか」と「retrieveしたknowledgeをgeneratorからどこまで漏らせたか」を分離して評価する**systematic benchmark。

## 概要

RAGではprivate / proprietaryなknowledgeをmodel parameterではなくexternal knowledge baseへ保持できるが、そのknowledge base自体が新しいdata extraction targetになる。特に近年は、queryを工夫してsensitive documentをretrieveさせ、そのcontextをgeneratorから再出力させるattackが複数提案されている。

一方、既存研究は実験条件が大きく異なる。例えば、

- HealthCareMagic / Enronのどのsubsetを使うか
- knowledge baseをoriginal document単位、fixed chunk単位、structured representationのどれでindexするか
- MiniLM / MPNet / BGE等どのretrieverを使うか
- LLaMA / GPT / Gemini等どのgeneratorを使うか
- attackerがretriever embeddingを知るwhite-boxか、APIだけのblack-boxか
- retrieval coverage、verbatim overlap、semantic similarity、ASRのどれをmetricにするか

が論文ごとに異なり、attack Aがattack Bより本当に強いのか、それともsetting差なのか判断しにくかった。

本論文はこのfragmentationを解消するため、RAG knowledge extraction attack / defenseを同一pipelineで再実装し、**Attack Query Design × Knowledge Base Setup × Retriever × Generator × Defense × Evaluation Metric**というdesign spaceとして整理する。

## Threat Model

knowledge baseを $D=\{D_i\}$ とし、attackerは $T$ roundsにわたりquery $Q_t$ を送る。各roundでretrieverがknowledge $R_t$ を返し、generatorがそれをcontextとしてanswer $A_t$ を生成する。

attackerの目的は、限られたquery budgetの中でknowledge baseの広い部分をretrieveし、さらにgenerator outputを通してrecoverすることである。

このbenchmarkでは、attackを概念的に2つのcomponentへ分ける。

1. **INFORMATION component**: queryをどのknowledge regionへ向けるか
2. **COMMAND component**: retrieveされたknowledgeをgeneratorへどの程度再出力させるか

[Follow My Instruction and Spill the Beans](../Attack/2024-2402.17840-follow-my-instruction-and-spill-the-beans.md)のような初期のcontext extractionはCOMMAND側、DGEA / IKEA / CopyBreakのような後続研究は主にINFORMATION側の探索能力を改善したものとして整理できる。

## Benchmark Design

### RAG構成

Retrieverは代表的なembedding modelとして、

- all-MiniLM-L6-v2
- GTE-base-768
- BGE-large-en-v1.5

を扱う。

Generatorはclosed-sourceのGPT-4o mini / GPT-4oに加え、open-sourceのLLaMA / Qwen系を含める。これにより、retriever capacityだけでなくgenerator familyやopen/closed-source差も比較する。

### Dataset

knowledge baseは4 domainから構成する。

- **HealthCareMagic**: patient-doctor dialogue。privacy-sensitive informationを含むmedical setting
- **Enron Email**: corporate email。private communicationを模したsetting
- **HarryPotter**: copyrighted fictional text。IP / copyright stealingを模したsetting
- **Pokémon**: encyclopedic domain knowledge。domain-specific proprietary corpusを模したsetting

privacyとcopyrightの両方を含めることで、単一datasetでのattack rankingに依存しない比較を狙っている。

### Knowledge-base construction

同じraw corpusでも、index representationを変えて評価する。

- **Original / Knowledge Instance**: 元の意味単位をそのままindex
- **Textual Chunk**: fixed-size chunkへ分割
- **Graph Triplet**: knowledgeをsubject-relation-object型のtripletへ圧縮

この軸は重要で、RAG securityが単なるretriever/generator問題ではなく、**knowledgeをどう保存するかそのものに依存する**ことを検証する。

## 評価するAttack

benchmarkでは6種類を比較する。

### Random / simple baselines

- **R-TK (Random Token)**: random tokenを組み合わせてqueryを生成
- **R-EB (Random Embedding)**: natural-languageに近いembedding distributionからquery representationを探索
- **R-TT (Random Text)**: LLMでrandom text queryを生成

単純randomでもretrieval geometryによって性能差が大きく、特にR-EBはtarget knowledge-baseに近いembedding distributionをsampleできるため、random baselineの中では強い。

### Adaptive attacks

- **DGEA**: embeddingを直接最適化し、queryとknowledgeのalignmentおよび探索diversityを高める。white-box retriever knowledgeを強く利用する。
- **[IKEA](../Attack/2025-2505.15420-silent-leaks-ikea.md)**: human-likeなinformation-seeking queryを生成し、topic anchorをadaptiveにsamplingしてknowledge baseを探索する。explicit context-copy commandを使わずstealth性を重視する。
- **[CopyBreak / RAG-Thief](../Attack/2024-2411.14110-feedback-guided-extraction-copybreakrag.md)**: 既に抽出したspanをfeedbackとして利用し、遠いregionのexplorationと近傍のrewritingを切り替えながらcoverageを広げる。

IKEAだけはexplicitなverbatim COMMANDを使わず、他attackではCOMMAND側をほぼ共通化する。これにより、INFORMATION componentのquery exploration能力を比較しやすくしている。

## 評価するDefense

RAG pipelineの異なるstageに4種を配置する。

### Query Block

input queryのmalicious extraction intentを検知してretrieval前に拒否する。

露骨な「contextをrepeatせよ」系には有効だが、IKEAのような通常質問に見えるqueryは通しやすい。

### Threshold Defense

retrieval cosine similarityがthreshold未満のdocumentをgeneratorへ渡さない。

out-of-distributionなadversarial queryには効きやすい一方、natural-language attackはquery-document similarity自体が高いため通過しやすい。

### System Block

generator system promptへcontext reproductionを禁止するinstructionを追加する。

これは[Spill the Beans](../Attack/2024-2402.17840-follow-my-instruction-and-spill-the-beans.md)でも検討されたprompt guardrailと同系統で、generatorがuser instructionを優先すると突破され得る。

### Summary Defense

retrieved raw textをそのままgeneratorへ渡さず、summaryへ変換してから利用する。

verbatim copy channelを断つためgeneration-stage defenseとして比較的強いが、semantic informationそのものがsummaryに残る点には注意が必要である。

## Evaluation Metrics

本論文の重要な貢献は、extractionをstageごとに分解したmetric設計にある。

### Retriever Extraction Effectiveness ($EE_R$)

複数queryを通じてknowledge baseのどの程度異なる部分をretrieveできたかを測る。queryが何度も同じdocumentを引く場合はcoverageが伸びないため、探索性能を直接評価できる。

### Generator Extraction Effectiveness ($EE_G$)

retrieveされたcontentがgenerator outputへどの程度再現されたかを測る。

- **Lexical Similarity ($EE_G^{LS}$)**: surface-level / verbatim overlap
- **Semantic Similarity ($EE_G^{SS}$)**: embedding-based meaning overlap

の両方を用意し、「逐語copy」と「意味として漏れた」を分離する。

### Combined Extraction Effectiveness (EE)

retrieveされ、かつgenerator outputで再現されたknowledgeの割合をend-to-endで測る。retrievalが強くてもgeneratorがrefuseすれば低くなり、逆にgeneratorがcopyしやすくてもretrieve coverageが低ければ伸びない。

### Attack Success Rate (ASR)

coverageとは別に、「knowledge-base grounded informationを1 queryで何回引き出せたか」を測る。refusalやirrelevant responseが多いattackを区別できる。

## Main Experiments

論文は主に4つの問いを調べる。

1. 6 attackは4 defense下でどう変化するか
2. retriever / thresholdを変えたときattack transferabilityはどう変わるか
3. generator / COMMAND designはgeneration leakageへどう影響するか
4. query diversity、knowledge representation、multilingual setting、attack costはどう影響するか

## Main Results

### DGEAはretrieval-stageでは強いがwhite-box依存が大きい

no-defenseのretrieval extractionではDGEAが高いperformanceを示す。embeddingを直接optimizationするため、target retrieverとattacker側embeddingが一致するwhite-box設定では強力である。

しかしretriever embeddingを変えるcross-model settingでは性能が低下する。対してIKEA / CopyBreakはLLMでnatural-language queryを生成するため、特定embedding modelに過度にfitせずblack-box transferが比較的良い。

これは、**最大性能ならembedding optimization、deployment generalityならnatural-language adaptive attack**というtrade-offを示す。

### Random baselineでもquery distributionが重要

R-EBはR-TK / R-TTより強い。Wiki sentenceに近いembedding distributionからsampleするため、target knowledge-baseのnatural-language geometryに近いqueryを得やすい。

逆にrandom tokenはembedding space上でout-of-distributionになり、同じregionを繰り返しretrieveしやすい。単にrandom queryを大量送信するだけでも、query representationの分布設計がcoverageへ大きく効く。

### ThresholdはDGEA等には効くがnatural-language attackに弱い

cosine thresholdを0.3程度まで上げるとR-TK / R-TT / R-EB / DGEAのretrieval extractionは大きく低下する。一方、IKEA / CopyBreakはquery自体がsemanticに自然でknowledgeとのsimilarityが高いため影響が小さい。

thresholdを0.5〜0.7まで上げれば大半のattackをかなり抑えられるが、同時にlegitimate retrieval recallも落ちる。つまりsecurityとRAG utilityのtrade-offが明確に現れる。

### Query diversityはcoverage改善に有効

過去queryと離れるように明示的なdiversity objectiveを追加すると、平均 $EE_R$ は多くのattackで改善する。

例えばno-defenseで、

- R-EB: **56.9 → 71.8**
- DGEA: **60.9 → 67.2**
- IKEA: **24.5 → 35.5**

と改善する。

RAG knowledge-base stealingでは「1 queryの強さ」だけでなく、**query-query redundancyを減らして未探索regionへ進むこと**が非常に重要だと分かる。この観点は[CopyBreak](../Attack/2024-2411.14110-feedback-guided-extraction-copybreakrag.md)や[RAGCrawler](../Attack/2026-2601.15678-connect-the-dots.md)のglobal explorationとも共通する。

### Graph Tripletは抽出効率を高めてしまう

Graph Triplet indexingではprivate informationが短いstructured representationへ凝縮されるため、attackが1 tokenあたり取得できるsensitive information量が増える。

Graph-based RAGはretrieval / reasoning efficiencyには有利でも、security面では**knowledge condensationがextraction効率を上げる可能性**があるという重要な結果である。

### Closed-source generatorの方がcontext reproduction能力が高い場合がある

explicit COMMANDを使うattackでは、closed-source generatorがopen-source generatorより高いgeneration extraction effectivenessを示す傾向がある。

これはより高性能なinstruction-following modelほど「contextをコピーせよ」という攻撃instructionにも忠実になり得る、という[Spill the Beans](../Attack/2024-2402.17840-follow-my-instruction-and-spill-the-beans.md)の観察と整合する。

### Summary defenseはgeneration-stageで最も安定して強い

multilingual experimentでもSummaryはverbatim reproductionを大きく減らす。Med_VietnameseではR-TKのlexical generation extractionが **100.0 → 4.17** まで低下する例が報告される。

一方でこれはraw-text leakageを抑える結果であり、semantic disclosureを完全に消すことを意味しない。

## Cross-lingual Generalizability

English以外への一般化として、Chinese medical dialogueとVietnamese medical QAを追加し、multilingual-MiniLMで評価する。

主要な傾向はEnglishと概ね一致し、knowledge extraction riskが英語RAG固有ではないことを示す。特にSummary defenseのgeneration-stage効果はcross-lingualでも維持される。

## Attack Cost

query budget 200でtoken consumptionとruntimeも比較する。

- DGEA / R-EB等のnon-LLM query optimizationはLLM token costがない
- IKEA / CopyBreakはiterative LLM callを使うためtoken costが大きい
- LLM-based adaptive attackはinference latencyがruntime bottleneckになる
- embedding search型はLLM costを抑えられるがsearch / optimization costを持つ

security評価ではASRだけでなく、攻撃者が現実的budgetで実行可能かも考える必要がある。

## 既存研究との関係

このbenchmarkは新しいattackを1つ提案するというより、これまでの系譜を同じ座標系へ置く研究である。

```text
Context disclosure primitive
[Spill the Beans / early extraction]
        ↓
How to retrieve more diverse private knowledge?
        ↓
Embedding optimization: DGEA
Benign adaptive queries: IKEA
Feedback exploration: CopyBreak
Graph-guided global traversal: RAGCrawler
        ↓
Unified evaluation
This benchmark
```

特に[IKEA](../Attack/2025-2505.15420-silent-leaks-ikea.md)と[CopyBreak](../Attack/2024-2411.14110-feedback-guided-extraction-copybreakrag.md)は本benchmarkの主要adaptive baselineとして直接評価されている。

## RAG Data Extraction Riskとの関係

今回のrepositoryでknowledge-base stealing論文を比較する上で、かなり重要な基準点になる。

従来は「何%抽出した」という数字だけを比較しがちだったが、本benchmarkに従えば、

```text
Query exploration
   ↓ EE_R
Retriever coverage
   ↓
Generator disclosure
   ↓ EE_G
End-to-end extraction
   ↓ EE / ASR
Stolen knowledge
```

のどこが改善されたattackなのかを分けて理解できる。

例えばDGEAはretrieval探索を強く最適化し、IKEAはstealthとblack-box transferを改善し、CopyBreak / RAGCrawlerはmulti-query coverageを改善する、という位置づけがしやすい。

## Limitations

1. **対象attack / defenseは代表例に限定**  
   新しいagentic attack、multi-agent traversal、memory-specific attackなどは今後追加が必要。

2. **System-level access controlを十分扱わない**  
   tenant isolation、document ACL、identity-aware retrievalなど、production securityで重要な対策はbenchmark外。

3. **Similarity metricの限界**  
   lexical / semantic similarityは便利だが、PIIやsecret keyなど「短いが重大な漏洩」のseverityを完全には表現しない。

4. **Generator alignmentは時間とともに変化する**  
   closed API modelのrefusal behaviorが更新されるとattack rankingも変わり得る。

5. **Knowledge representationの範囲は有限**  
   graph tripletの結果は興味深いが、production GraphRAGのより複雑なentity/community structure全体を網羅するものではない。

## 重要なポイント

- RAG knowledge extraction attack/defenseを統一条件で比較するsystematic benchmark。
- 6 attack × 4 defense × 4 datasetを中心に、retriever / generator / indexingも横断評価。
- extractionをRetriever EE / Generator EE / Combined EE / ASRへ分解する。
- DGEAはwhite-box embedding settingで強いがcross-retriever transferが弱い。
- IKEA / CopyBreakはnatural-language queryのためblack-box transferとthreshold回避に強い。
- query-query diversityを明示的に増やすとknowledge-base coverageが改善する。
- Graph Tripletのようなknowledge condensationはextraction効率を上げる可能性がある。
- Summary defenseはverbatim leakage抑制に強いがsemantic leakageは残る。
- multilingual settingでも主要傾向が維持される。
- attack performanceだけでなくtoken / runtime costまで比較する。
- RAG extraction研究を「どのstageを改善した手法か」で整理するための共通評価軸として有用。
