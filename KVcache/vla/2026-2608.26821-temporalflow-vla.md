# TemporalFlow-VLA — Physically Grounded Execution History

## 概要
長期ロボット操作では同じ見た目でも直前の行動によって意味が変わる。単純に過去フレームをVLAに追加すると、過去の**順序**が無視されやすい。TemporalFlow-VLAは過去のrobot-surface motionを訓練時に幾何学的に生成し、2つのquery tokenへ教師信号を与える。推論時には幾何レンダラは不要で、queryが直近action chunkの動きを要約する。**Transformer layer KVのcross-frame reuseではなく、frozen vision encoderの過去特徴を非同期にキャッシュ**する。

## 問題設定・先行研究との差
- 生の履歴フレームを投入したbaselineでは履歴をshuffleしてもoffline flow-matching lossがほぼ変わらず、履歴を除去すると約4.6%悪化。つまり「過去を使う」と「順序を使う」は異なる。
- TraceVLAは推論時にpoint trajectoriesを描画するが、本方式のflow targetは学習時だけ。
- [ReMem-VLA](2026-2603.12942-remem-vla.md)はrecurrent memory query、[MemoryVLA](2025-2508.19236-memoryvla.md)はmemory bank、[MEM](2026-2603.03596-mem.md)はshort-video+long-language memory。TemporalFlowは**直近16 stepの物理的実行履歴**を監督する点に焦点。
- [DySta](2026-2602.03983-dysta.md)は静的visual KVを再利用するが、TemporalFlowは画像encoderの特徴を保持する。KV cache最適化としては別方式。

## 手法
### Robot-surface temporal flowの教師生成
訓練時にjoint states、URDF robot geometry、calibrated cameraを使い、過去時刻の可視ロボット表面pixelをlink local座標へ戻す。現在時刻のforward kinematicsで3D位置を更新し、cameraへ投影して2D displacementを得る。target frameとのlink一致・3D誤差5mm以下の可視対応のみ採用。flowは224×224のpolicy画像上で正規化される。対象物のoptical flowを推論時に推定するのではない。

### 2つのtemporal queries
16-step action chunkに合わせ、過去観測 t−15、t−8、現在tを使用。Q8は直近8 step、Q15は15 stepの履歴を表現し、robot-surface flow reconstruction lossで監督。Action expertは歴史画像patchを直接参照せず、2 queryをjoint masked attention経由で受け取る。これは有限窓のexecution memoryであり、長期episodic retrievalはない。

### Asynchronous historical feature cache
前action chunkをロボットが実行している間に、凍結vision encoderで過去のhead-camera frameを事前encodeしてcacheする。次replan時は過去画像を再encodeしない。current frame encodingとaction samplingは残る。**KV layer cache reuseではなくvisual feature cache**である。推論時はURDF、flow supervision renderer、reconstruction headを実行しない。

## Main Results
### LIBERO
4 suites平均97.63±0.26%、LIBERO Long 96.60±0.87%。Longは論文掲載の既報最良meanより+2.1ppとされる。ただし他研究の学習条件が一致するとは限らず、最良手法一般への優越を意味しない。

### RoboTwin 2.0
| Method | Clean Avg | Randomized Avg |
|---|---:|---:|
| π0.5 baseline | 79.0 | 72.3 |
| Raw Multi-frame | 79.8 | 81.5 |
| 2 queries without flow supervision | 83.2 | 83.6 |
| TemporalFlow-VLA | **85.5** | **84.2** |

Randomized H=3は87.5%で、baselineの66.5%より大幅に高い。ただし単一query Q8は88.8%で**H=3単独では本手法を上回る**。全タスク・全条件で優越するわけではない。

### 実機
| Task | Baseline | TemporalFlow-VLA | 差 |
|---|---:|---:|---:|
| Three-Cup Stacking | 57.8% | 77.8% | +20.0pp |
| Two-Bottle Packing | 86.7% | 97.8% | +11.1pp |

各45試行、2タスクのみ。実機での長時間頑健性を広範に証明したものではない。

### Inference latency
RTX4090の15 replan区間でserver-side sampling time 68.10→62.78ms/replan（**7.8%短縮**）。累積1.021→0.942秒（79.8ms節約）。同じsuccess rolloutを対象とし、RPC・simulator・video処理は含まない。**制御周波数7.8%増加とは言えない**。

## 主要ablation
| Method | Clean H1 | Clean H2 | Clean H3 | Clean Avg | Rand Avg |
|---|---:|---:|---:|---:|---:|
| Multi-frame | 75.5 | 79.5 | 84.5 | 79.8 | 81.5 |
| 2Q w/o Flow | 83.0 | 79.8 | 86.8 | 83.2 | 83.6 |
| Q8 only | **86.5** | 79.8 | 88.3 | 84.8 | 84.0 |
| Q15 only | 84.0 | 80.5 | 87.3 | 83.9 | 83.0 |
| Full 2Q+Flow | 84.0 | **83.5** | **89.0** | **85.5** | **84.2** |

Flow supervisionは同じ2 queryを持つ対照よりClean +2.3pp、Randomized +0.6pp。Q8だけでも高いが、H2では2 queryが有利。正しい履歴順をshuffleするとoffline lossが悪化するが、これはonline successを直接測ったablationではない。

## Limitations
1. 過去t−15とt−8の固定2点を用いる。もっと長い履歴や異なるaction chunk長への一般化は未検証。
2. 教師生成にはjoint states、URDF、camera calibrationが必要。推論時は不要でもtraining data preparationの負担がある。
3. robot-surface flowに重点があり、外部物体の状態変化や長期semantic memoryを直接表現しない。
4. 非同期feature cacheはoverlapに依存し、実機のsensor/通信を含むlatency・VRAM peakは未報告。
5. 同一条件のMEM/RAVENとの直接比較はなく、long-term retrievalの優劣を主張できない。

## Taxonomy
`KVcache/vla/` — **action-aware temporal feature memory / asynchronous visual feature reuse**。Transformer attention KV reuseは行わず、凍結vision encoderの歴史特徴を再利用する。長期のepisodic/semantic storeではなく、直近action chunkの時系列状態を表現。
