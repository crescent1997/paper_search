# CausalArmor: Efficient Indirect Prompt Injection Guardrails via Causal Attribution

## 概要

CausalArmorはLLM agentへのIndirect Prompt Injection (IPI)を、**privileged actionがuser requestではなくuntrusted external contentに因果的に支配される現象**として検出するselective Defenseである。

既存Defenseには全external contentを常時sanitizeする方式が多く、安全性の代わりにlatency / utilityを悪化させるover-defense問題がある。

CausalArmorはprivileged actionが発生するdecision pointだけでcausal attributionを計算し、untrusted segmentがuser intentより強くactionを支持する場合だけDefenseを起動する。

## 問題設定 / Threat Model

agentはuser requestを受け、retrieved documentやtool output等のuntrusted contentをcontextへ追加する。

```text
trusted:
  user request

untrusted:
  retrieved document
  tool output
  web content
```

attackerはuntrusted contentへmalicious instructionを埋め込み、agentにunauthorized privileged actionを実行させる。

targetは単なるtext responseではなくtool call等のactionである。

## Privilegeの考え方

CausalArmorではaction authorityの根拠が重要である。

privileged actionは本来user requestによって正当化されるべきであり、untrusted dataだけがactionを強く支持しているならprivilege inversionが起きている。

これは、

```text
User intent
   >
Untrusted external content
```

というpriority relationをcausal influenceとして測る考え方である。

## Causal Attribution

contextをC、候補actionをY、あるsource/spanをXとする。

source Xを除去したcounterfactual contextと比較し、

```text
Delta_X(Y)
  =
log P(Y | C)
-
log P(Y | C without X)
```

のようなleave-one-out attributionを計算する。

Xを除いたときaction probabilityが大きく低下するなら、Xがそのactionを強くsupportしている。

## Dominance Shift / Causal Inversion

benign caseではprivileged actionの主な根拠はuser requestである。

```text
Attribution(user)
  >
Attribution(untrusted span)
```

IPIが成功すると、malicious external spanのattributionがuser intentを上回る。

```text
Attribution(untrusted)
  >
Attribution(user)
```

CausalArmorはこのdominance shiftをattack signatureとして利用する。

## Normalized Leave-One-Out

raw log-probability差だけではspan lengthやmodel confidence等の影響を受ける。

そのためattributionをnormalizedし、user requestと複数untrusted segmentsを比較可能にする。

全tokenを細粒度に逐次除去するのではなく、meaningful span単位でablationすることでcostを抑える。

## Selective Intervention

CausalArmorの重要な設計はalways-on sanitizationを避けることである。

```text
privileged action proposed
        ↓
causal attribution
        ↓
untrusted dominance?
    /          \
  no            yes
  |              |
execute       sanitize
normally      suspicious span
```

benign interactionでは高価なsanitizerを呼ばない。

## Targeted Sanitization

attackが疑われた場合、context全体ではなくdominant untrusted spanをtargetにsanitizeする。

これによりbenign informationを不必要に削除することを避ける。

sanitized contextでagentを再実行し、安全なactionへ戻す。

## Retroactive Chain-of-Thought Masking

attack検出時点までにmodelのreasoning traceがmalicious instructionに汚染されている可能性がある。

external spanだけをsanitizeしても、過去のreasoningがcontextに残ればattack effectが継続する。

CausalArmorはattack由来のreasoning stateを後続generationへ引き継がないようretroactive CoT maskingを行う。

これはinput sanitizationだけでは除去できない**reasoning contamination**を扱う。

## Theoretical Analysis

attribution marginに基づいてsuspicious spanをsanitizeする条件下で、malicious action selection probabilityに指数的に小さくなるupper boundを与える理論解析を提示する。

ただしこれはassumption下のconditional guaranteeであり、arbitrary adaptive attackerに対するunconditional security proofではない。

## Experiment Setup

主にagentic IPI benchmarkで評価する。

- AgentDojo
- DoomArena

比較対象にはNo Defenseと、常時sanitizationを含むaggressive Defenseを置く。

評価軸は、

- Attack Success Rate
- benign utility
- latency / computational overhead

である。

## Main Results

CausalArmorはAgentDojo / DoomArenaでnear-zeroに近いattack successを実現し、aggressive always-on Defenseに近いsecurityを示す。

一方benign interactionではDefenseを選択的に起動するため、utility / latencyをNo Defenseに近く維持する。

このsecurity / utility / latency trade-offが主要な貢献である。

## Generalization

異なるagent benchmarkで同じcausal signatureを利用できることを示し、特定attack stringだけをpattern matchingしているわけではない。

Defenseの判断根拠が「どのuntrusted spanがactionを支配したか」なので、検出結果に一定のexplainabilityもある。

## AlignSentinelとの関係

[AlignSentinel](2026-2602.13597-alignsentinel.md)はhigher-priority instructionとlower-priority inputのattention interactionからmisaligned instructionを検出する。

```text
AlignSentinel:
  internal attention interaction
  -> classify input alignment

CausalArmor:
  counterfactual ablation
  -> measure action attribution
  -> detect dominance inversion
```

CausalArmorはaction-level causal supportを直接見る点が異なる。

## CaMeLとの関係

[CaMeL](2025-2503.18813-defeating-prompt-injections-by-design-camel.md)はPrivileged / Quarantined LLMとcapability / provenance trackingにより、untrusted computationへ高権限を渡さないsystem-level designである。

CausalArmorもpure model-weight Defenseではなくagent middleware側のguardrailである。

CaMeLがauthorityをarchitectureで分離するのに対し、CausalArmorはactual actionのcausal provenanceをruntimeで診断する。

## StruQ / SecAlignとの関係

[StruQ](2024-2402.06363-struq.md)、[SecAlign](2024-2410.05451-secalign.md)、[Meta SecAlign](2025-2507.02735-meta-secalign.md)はmodelにtrusted/untrusted separationを学習させる。

CausalArmorはmodelがそのseparationに失敗した後でも、privileged action直前にuntrusted causal dominanceを検出できる。

したがってmodel-level DefenseとのDefense-in-depthとして利用できる。

## Instruction Hierarchyとの関係

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)ではpriorityをrole / sourceにより規定する。

CausalArmorは同じ考えをaction attributionへ写像する。

```text
nominal hierarchy:
  user instruction > external data

causal hierarchy:
  support(user) > support(external)
```

nominal privilegeとrealized causal influenceが逆転したときにDefenseを起動する点が特徴である。

## Role Confusionとの関係

[Prompt Injection as Role Confusion](../Attack/2026-2603.12277-prompt-injection-role-confusion.md)はuntrusted contentがmodel内部でtrusted roleらしいrepresentationを獲得することを分析する。

CausalArmorはlatent role identityではなく、最終action probabilityへのcounterfactual contributionを見る。

両者はprompt injection failureを異なるlevelで診断する。

## Adaptive Attack

CausalArmorのattribution threshold / sanitizer behaviorを知るadaptive attackerは、

- malicious instructionを複数spanへ分散
- user requestにもattack actionを弱くsupportさせる
- attributionをthreshold未満へ分散
- poisoned reasoningを早期に形成

等を狙う可能性がある。

[PISmith](../Attack/2026-2603.13026-pismith.md)や[The Attacker Moves Second](../Attack/2025-2510.09023-attacker-moves-second.md)の観点では、Defense-aware optimizationへの追加評価が重要である。

## Model-level Defenseとの境界

CausalArmorは本repositoryの中心であるmodel-intrinsic Defenseそのものではない。

必要な機能は、

- privileged action interception
- context span ablation
- proxy/log-probability attribution
- sanitizer
- reasoning-state masking

であり、agent middleware / harness側の構成を含む。

本repositoryでは、**User > Tool / external dataというprivilege relationをcausal attributionとして実装した比較対象**として収録する。

## Limitations

- pure model-level Defenseではなくagent architectureへのintegrationが必要。
- privileged actionを明確に定義できるapplicationを前提とする。
- leave-one-out evaluationに追加model callsが必要。
- span segmentation品質にattributionが依存する。
- distributed / compositional injectionでは単一span dominanceが弱くなる可能性がある。
- sanitizer自体のfailureを完全には排除できない。
- adaptive attackerへのunconditional guaranteeはない。
- hidden reasoningを利用できないmodel/APIではretroactive CoT handlingの実装が異なる。

## LLM Model Security Taxonomyでの位置づけ

```text
Model-level:
  Instruction Hierarchy
  StruQ / SecAlign
  ISE
      ↓ residual failure

Detection:
  AlignSentinel
      ↓

System / runtime:
  CausalArmor
    causal action attribution
    selective sanitization
    retroactive CoT masking

  CaMeL
    capability / provenance isolation
```

model-level privilege separationをruntime causal guardrailで補完するDefenseとして位置づけられる。

## 実装・研究上の示唆

重要なのは「untrusted textに命令らしい文字列があるか」ではなく、**そのtextがprivileged actionの決定を実際に支配したか**を見ることである。

今後は、

1. token/span attributionの高速化
2. KV cacheを利用したcounterfactual ablation
3. multiple malicious spansへのShapley-like attribution
4. adaptive attackerを含むthreshold robustness
5. model-level hierarchy Defenseとの組み合わせ

が重要になる。
