# RetroInfer: A Vector Storage Engine for Scalable Long-Context LLM Inference

> RetrievalAttentionで導入された「KV cacheをvector retrievalとして扱う」方向を、**index・attention approximation・CPU/GPU buffer managementまで統合したvector storage engine**へ発展させる。

## 概要

long-context decodeではKV cacheがcontext lengthに比例して増え、GPU memory capacityとHBM bandwidthの双方がbottleneckになる。CPUへKVをoffloadして重要tokenだけretrieveするsparse attentionは有望だが、attention sparsityはlayer/head/query/taskによって変化し、固定retrieval budgetではaccuracyとtransfer costの両立が難しい。

RetroInferはKV cacheを単なるtensorではなく**vector storage system**として扱い、

- **wave index**: どのKVを正確にretrieveし、どの領域を近似するか決める
- **wave buffer**: GPU/CPU間のKV placement・transfer・computation overlapを管理する

という2層構成でlong-context inferenceを最適化する。

## 既存法の問題

[RetrievalAttention](2024-2409.10516-retrievalattention.md)やQUESTなどのquery-aware sparse attentionでは、重要token/pageを選択して残りをattention計算から除外する。

しかしattention sparsityは一定ではない。強く集中するheadでは少数tokenで十分でも、分散したheadでは同じbudgetではattention massを取りこぼす。

単純にretrieval ratioを増やすとaccuracyは上がるが、CPU→GPU transferとattention computeが増え、sparse attentionの利点が失われる。

RetroInferは「retrieveしなかったKVをゼロ扱いする」二値的な設計を避け、**exact retrievalとapproximationを組み合わせる**。

## Wave Index

### Tripartite attention approximation

attention対象を3 zoneに分割する。

1. **Steady zone**  
   attention sinkやlocal/recent tokenなど、安定して重要な領域。GPU上でexact attentionを行う。

2. **Retrieval zone**  
   current queryに対して重要と判断されたcluster/token。CPUからKVをretrieveしexact attentionを行う。

3. **Estimation zone**  
   Retrieval zoneには入らなかったが無視すると誤差になる領域。個々のKVをfetchせずcluster-level statisticsからattention contributionを推定する。

これによりretrieval budgetを小さくしても、non-retrieved attention massを完全に捨てずに済む。

## Accuracy-bounded estimation

wave indexではKeyをcluster化し、cluster centroidとValue aggregateを保持する。

cluster centroidをKeyの代表値としてqueryとのscoreを計算し、cluster内Valueのaggregateを組み合わせることで、individual KVをCPUからtransferせずにそのclusterのattention contributionを近似する。

論文ではJensen inequalityを利用してattention estimation errorをboundし、どのclusterをexact retrievalへ昇格させるべきかを判断する。

つまりindexは単なるTop-K ANNではなく、

> **exactに読む領域と近似で済ませる領域をaccuracy constraintの下で分ける**

役割を持つ。

代表settingではRetrieval zoneを約1.8%に抑えつつ、Estimation zoneを追加してfull attentionに近いaccuracyを維持する。

## Segmented clustering

global clusteringは長contextでindex construction costが大きい。

RetroInferはPost-RoPE Keyにcoarse-grained spatial localityがあることを利用し、sequenceをsegmentへ分割して各segment内で独立にcluster化する。

例えば128K context全体をglobal clusteringする代わりに8K程度のsegmentへ分ける。

これによりindex buildを並列・incrementalに行いやすくし、global clusteringと比較してindex construction timeを大幅に削減しながらretrieval quality低下を小さく抑える。

prefill時にはKV offload、segmented clustering、buffer constructionをoverlapさせ、index構築をcritical pathから外す。

## Wave Buffer

wave indexが「何を読むか」を決めるのに対し、wave bufferは「どこからどう読むか」を担当する。

KV本体の大部分はCPU memoryへ置き、GPUには、

- Steady zone
- metadata / index
- recently/frequently used KV block

を保持する。

重要KVにはtemporal localityがあるため、GPU側へ小さいblock cacheを持たせる。cache hitならGPU内だけで処理し、missしたblockのみCPU→GPU transferする。

replacementとdata movementをasynchronousに実行し、GPU attention computeとCPU/PCIe transferをoverlapさせることでstallを隠す。

## RetrievalAttentionとの差

[RetrievalAttention](2024-2409.10516-retrievalattention.md)はQ/K distribution mismatchに対応したattention-aware ANNを構築し、CPUからcritical KVをtoken-levelでretrieveする。

RetroInferはこのvector-retrieval方向をsystem architectureまで広げる。

| | RetrievalAttention | RetroInfer |
|---|---|---|
| 主眼 | attention-aware token retrieval | vector storage engine |
| non-retrieved KV | attentionから除外 | Estimation zoneで近似 |
| index | Q/K-aware ANN | wave index |
| clustering | retrieval index中心 | segmented clustering |
| GPU cache | static subset中心 | wave buffer + dynamic block cache |
| accuracy control | retrieval ratio | retrieval + bounded estimation |
| system scope | sparse attention | index + approximation + buffer |

技術系譜としては、

```text
RetrievalAttention
  ↓
KV as vector retrieval
  ↓
RetroInfer
  ↓
KV as vector storage engine
```

と整理できる。

## QUESTとの差

[QUEST](2024-2406.10774-quest.md)はpageごとのKey min/max metadataからcurrent queryに対するcriticality upper boundを求め、Top-K pageだけを読む。

RetroInferはcluster-level indexとattention estimationを用いるため、単なるpage selectionより複雑だが、attention sparsityが弱いcaseでもnon-retrieved regionの寄与を補える。

QUESTが軽量なpage selectionを重視するのに対し、RetroInferは**accuracy / retrieval / heterogeneous-memory executionを一体設計**する。

## DuoAttentionとの差

[DuoAttention](2024-2410.10819-duoattention.md)はheadをRetrieval / Streamingへstaticに分類し、full-history accessを必要とするheadだけにfull KVを残す。

RetroInferはcurrent queryごとにtoken/cluster importanceを動的に判断する。

- DuoAttention: head axis
- RetroInfer: token/cluster axis + memory hierarchy

であり、異なるsparsity axisを利用する。

## Experiment Setup

Llama-3.1-8B、Qwen2.5-7B、long-context Llama-3-8B variants、Qwen2.5-72B等を対象に評価する。

accuracy benchmarkにはRULER、Needle-in-a-Haystack、long-context reasoning workload等を使用する。

system evaluationではA100等を用い、

- full attention
- QUEST
- MagicPIG
- InfiniGen
- PQCache
- その他sparse/offload systems

とthroughput、latency、accuracy、index overheadを比較する。

## Main Results

PVLDB final版では、

- **120K contextでfull attention比 最大4.4× decoding throughput**
- **1M contextでsparse-attention baseline比 最大12.2×**
- full-attention-level accuracyを維持

と報告する。

初期arXiv版では4.5× / 10.5×という値が示されていたが、現行v3/PVLDB版では4.4× / 12.2×へ更新されているため、本要約ではfinal版を優先する。

RULER 128KでもFull Attentionとの差を小さく抑え、同程度のretrieval budgetを使うsparse baselineより高いaccuracyを示す。

## Ablation

### Tripartite attention

Retrieval zoneだけで処理するとretrieval budgetを小さくした際にaccuracyが低下する。

Estimation zoneを追加することで、追加のKV transferを大きく増やさずnon-retrieved attention contributionを回収できる。

### Segmented clustering

segment-based index constructionはglobal clusteringと比較してbuild overheadを大幅に削減し、retrieval recallへの影響を小さく抑える。

contextが長くなるほどfull attentionのprefill costが急増するため、segmented index buildの相対overheadはさらに小さくなる。

### Wave buffer

GPU block cacheとasynchronous replacementによりCPU→GPU transferの一部を回避し、retrieval pipelineとGPU computeをoverlapできる。

index qualityだけでなくbuffer managementがend-to-end throughputに重要。

## Limitations

1. CPU側には大規模KV storageが必要で、total memory requirement自体はcontext lengthに依存する。
2. wave index・cluster statistics・buffer metadataなど追加system complexityがある。
3. index construction overheadは隠蔽される設計だが、short contextではbenefitが小さい。
4. performanceはPCIe bandwidth、CPU memory bandwidth、GPU cache hit rateに依存する。
5. attentionが広く分散する場合、Retrieval/Estimation zoneが増えbenefitが小さくなる。
6. sparse attention kernelだけではなくCPU/GPU co-designを前提とするため、既存serving engineへの統合コストが高い。

## KV-cache taxonomyでの位置づけ

**access / vector-indexed KV / attention approximation / CPU-GPU hierarchical storage / training-free**。

保存KV自体を不可逆にevictするcompressではなく、大部分をCPUに保持し、

> **decode時にexact retrievalすべきKVとapproximation可能なKVを分け、heterogeneous memoryから効率よくaccessする**

ことが中心。

access系の流れは、

| Method | 主なsparsity axis / mechanism |
|---|---|
| [SparQ](2023-2312.04985-sparq-attention.md) | query dimensions → token |
| [QUEST](2024-2406.10774-quest.md) | query → page |
| [DuoAttention](2024-2410.10819-duoattention.md) | head role → full / streaming |
| [RetrievalAttention](2024-2409.10516-retrievalattention.md) | query → ANN token retrieval |
| RetroInfer | retrieval + estimation + heterogeneous vector storage |

## まとめ

RetroInferはRetrievalAttentionで示されたKV vector retrievalを、**wave index + wave buffer**からなるvector storage engineへ拡張する。

特に、

- Steady / Retrieval / Estimationのtripartite attention
- accuracy-bounded estimation
- segmented clustering
- GPU block cache
- asynchronous CPU-GPU transfer

を統合し、retrieval ratioだけにaccuracyを依存させない点が重要。

PVLDB final版では120K contextでfull attention比最大4.4×、1M contextでsparse baseline比最大12.2×のdecoding throughputを報告し、long-context KV access optimizationが単なるsparse kernelから**storage-system co-design**へ進む流れを示している。
