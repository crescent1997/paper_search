# PoisonedRAG: Knowledge Corruption Attacks to Retrieval-Augmented Generation of Large Language Models

> RAGのknowledge baseに少数のpoisoned documentsを挿入し、特定queryでそれらを高確率にretrieveさせたうえで、generatorへ攻撃者指定のtarget answerを生成させるknowledge corruption attack **PoisonedRAG** を提案する。

## 概要

RAGは外部knowledge baseを利用するため、model weightsを直接改変しなくてもknowledgeを更新できる。一方で、この性質はknowledge base poisoningという新しいintegrity riskを生む。

攻撃者がknowledge baseへ少数のmalicious documentsを挿入できる場合、そのdocumentをtarget queryに対してretrieverが優先的に選び、さらにgeneratorがそこに書かれたfalse informationを採用すれば、RAG responseを攻撃者の望む内容へ誘導できる。

PoisonedRAGはこの攻撃を、

1. malicious textをtarget queryにretrieveさせる
2. retrieved malicious textを使ってtarget answerを生成させる

という2つの条件に分解する。

単にfalse statementを書くだけではretrieverに選ばれない可能性があり、逆にqueryと非常に似たtextでもgeneratorがtarget answerを出さなければ攻撃は成立しない。そこでPoisonedRAGはretrievalとgenerationの両方を同時に満たすpoisonを設計する。

## Threat Model

攻撃者はRAG knowledge baseへ少数のtextを追加できるが、既存documentを削除・変更する必要はない。

対象query集合 $Q_t$ と、それぞれに対して出させたいtarget answers $A_t$ を持つ。

攻撃目標は、target query $q$ が入力された際に、victim RAGがattacker-defined answer $a_t$ を返す確率を最大化することである。

論文では、

- black-box setting
- white-box / stronger-knowledge setting

の両方を評価する。

## Attack Design

### Retrieval condition

poisoned text $p$ がtarget query $q$ に対してretrieved top-kへ入る必要がある。

そのため、$p$ はembedding spaceで$q$とのsimilarityが高くなるよう設計する。

black-box settingではretriever内部gradientを使えないため、LLMを用いてquery-relevantなsurface formを生成する。

white-box settingではretriever embeddingへのaccessを使い、より直接的にretrieval scoreを最適化できる。

### Generation condition

retrieveされたpoisonがgeneratorへ入っても、target answerが生成されなければ意味がない。

そこでpoison本文へ、target answerを自然なfactとして含める。

例えば、target questionが「Xの首都は？」でtarget answerをYにしたい場合、poisonはquery topicと強く関連しつつ、Yを正しいanswerとしてgeneratorが使いやすい形で記述する。

### Combined objective

PoisonedRAGの中心は、retrieval relevanceとgeneration effectivenessの両方を満たすtextを作ることである。

概念的には、

```text
Target Question q
   ↓
Poison Generator / Optimizer
   ↓
Malicious Text p
   ├─ high retrieval similarity to q
   └─ contains / supports target answer a_t
   ↓
Inject into Knowledge Base
   ↓
Retriever selects p
   ↓
Generator follows p
   ↓
Attacker-chosen answer
```

となる。

## Large-scale Knowledge Baseでの攻撃

重要な点は、knowledge base全体が非常に大きくても少数poisonで攻撃可能なことである。

論文では数百万text規模のdatabaseを含む複数settingで評価する。

target questionあたり数個、代表的には5個程度のmalicious textsを注入するだけで、非常に高いattack success rateを達成する。

これは、RAG retrieverがqueryに対して最もsimilarな少数documentしかgeneratorへ渡さないためである。knowledge base全体に対するpoison ratioは極小でも、target query周辺のtop-k rankingさえ乗っ取ればよい。

## Experiments

複数QA dataset・retriever・LLMを組み合わせて評価する。

主要metricは **Attack Success Rate (ASR)** で、target queryに対してattacker-specified answerを生成した割合を測る。

PoisonedRAGは、target questionごとに少数のpoison textを挿入するだけで多くの設定で約90%以上のASRを達成する。

black-box settingでも高い成功率を示し、retriever parameterへ完全accessできることは必須ではない。

## Defense Evaluation

### Paraphrasing

knowledge baseへ入るdocumentをparaphraseし、malicious wordingを崩す防御を評価する。

しかしpoisonはsemantic-levelにtarget answerを埋め込んでいるため、paraphrase後もattackが残る。

### Perplexity-based Detection

不自然なtextは高perplexityになる可能性があるため、language-model perplexityでpoisonをfilterする方法を評価する。

ただしPoisonedRAGは自然な文章として生成できるため、perplexityだけではbenign / malicious textを十分区別できない。

### Duplicate Filtering

同じmalicious textを大量投入する単純attackならduplicate filteringが有効だが、PoisonedRAGは意味的に類似しつつsurface formの異なるmultiple poisonを生成できる。

したがってexact duplicate除去では防げない。

### Knowledge Expansion / Retrieve More

retrieve数 $k$ を増やしてbenign evidenceを更多くgeneratorへ渡すとpoison influenceが薄まると期待できる。

実際ASRは低下するが、完全には防げない。HotpotQAの例では50 documentsをretrieveしても40%台のASRが残る。

つまり「より多くのevidenceを見せれば自然にmajority voteで正しくなる」とは限らない。

## RAG Data Extraction Riskとの関係

本論文の主目的はdata extractionではなく **integrity / knowledge corruption** である。

ただしRAG security全体を理解する上では重要である。

RAG knowledge baseは、

- stealing / extractionの対象
- poisoning / corruptionの対象

の両方になり得る。

attack surfaceを整理すると、

```text
Confidentiality:
  Knowledge Base → attacker extracts data

Integrity:
  Attacker → injects poisoned data → Knowledge Base
```

という対称性がある。

RAG-ThiefやRAGCrawlerがknowledge baseから外向きに情報を盗む攻撃であるのに対し、PoisonedRAGは外部から内向きにfalse knowledgeを注入する攻撃である。

## Limitations

1. **Knowledge-base write accessが必要**  
   attackerが何らかの形でdocument ingestion pipelineへtextを追加できる必要がある。

2. **Targeted attack中心**  
   任意queryすべてを壊すのではなく、事前に選んだtarget questionsへ特に強い。

3. **Retriever architectureの影響**  
   embedding modelやrerankerが変わると最適poisonも変化する。

4. **Strong provenance / access controlでは難しくなる**  
   trusted sourceだけをknowledge baseへ登録する運用ではattack surfaceが小さくなる。

## 重要なポイント

- RAG knowledge base poisoningを体系化した代表的研究。
- 少数poisonだけで数百万document規模のdatabaseをtargetedに乗っ取れる。
- retrieval relevanceとgeneration targetを同時に満たすpoison textを設計する。
- target questionあたり5 malicious texts程度で約90%以上のASRを達成する設定がある。
- black-box attackでも高い成功率を示す。
- paraphrasing、perplexity detection、duplicate filteringだけでは十分防げない。
- retrieve数を増やしてもattackは完全には消えない。
- RAG extractionがconfidentiality riskなら、PoisonedRAGはknowledge-base integrity riskを代表する。
