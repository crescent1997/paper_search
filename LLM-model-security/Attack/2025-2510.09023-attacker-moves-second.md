# The Attacker Moves Second: Stronger Adaptive Attacks Bypass Defenses Against LLM Jailbreaks and Prompt Injections

## 概要

本論文の中心主張は、LLM defenseのrobustness評価で「既存attack benchmarkをそのまま当てる」だけでは不十分であり、**attackerはdefenseの設計を知った上で攻撃戦略を適応させる**べきだ、というものである。

論文はjailbreakとprompt injectionを横断して12種類のrecent defenseを再評価し、gradient descent、reinforcement learning (RL)、random search、human-guided explorationをdefenseごとに調整・scale upすることで、元論文ではnear-zero ASRと報告された防御を含む多数の手法を高い成功率で突破する。

LLM-model-securityの観点では、[StruQ](../Defense/2024-2402.06363-struq.md)や[SecAlign](../Defense/2025-2503.18813-secalign.md)のようなprompt/data privilege separation defenseに対して、**static benchmark上のrobustnessとadaptive robustnessは別物**であることを示すAttack論文として重要である。

## 問題設定 / Threat Model

従来のdefense評価では、attack側が以下のいずれかに固定されることが多い。

- 事前に用意されたjailbreak string / prompt injection template
- GCG等の汎用optimization attackをdefault設定で適用
- defense architectureを考慮しないblack-box query
- limited budgetでのattack

しかしsecurity evaluationでは通常、attackerは公開されたdefenseの仕組みを読んでから攻撃を設計できる。本論文はこの「attacker moves second」というsecurity原則をLLM defense evaluationへ持ち込む。

attacker accessは防御ごとに異なるが、論文では大きく以下の条件を扱う。

### White-box

- model parameters / gradientsへアクセス可能
- token-level objectiveを直接最適化可能
- GCG系coordinate optimizationやgradient descentを利用可能

### Logit-access black-box

- target modelのlogitsやscoreへquery可能
- exact gradientは得られないが、search / surrogate objectiveを組める

### Generation-only black-box

- 通常のAPIのようにgenerated textだけ観測可能
- RL、random search、human-guided探索等でattack candidateを改善する

重要なのは、単一attack methodの優劣ではなく、**defenseに応じて最も有効なoptimizer・objective・search spaceを選択する**点である。

## 先行研究からの改善点

代表的なGCG (Greedy Coordinate Gradient) は、adversarial suffix tokenをgradient情報で反復更新し、aligned modelから望まない出力を引き出す強力なwhite-box attackである。一方で本論文は、GCGを固定設定で全defenseに適用すること自体が評価上の弱点になり得ると指摘する。

たとえばGCGを20-token suffix、500 steps、各step 512候補といった固定budgetで実行し、「失敗したからdefenseはrobust」と結論するのではなく、

1. defenseの入力変換・filtering・role separationを確認する
2. attack surfaceを特定する
3. optimization targetを防御に合わせる
4. search budgetを十分に拡大する
5. 必要ならgradient以外のRL / random search / human explorationへ切り替える

というadaptive evaluationを行う。

つまり本論文はGCGの単なる高速化・改良ではなく、**attack optimization methodologyそのものをdefense-awareにする**研究である。

## Method / Algorithm

論文は単一の万能attack algorithmを提示するのではなく、複数のgeneral-purpose optimizerを各defenseへ適応する。

### 1. Gradient-based optimization

white-box accessがある場合、target behaviorを誘導するlossを定義し、suffix / injected contentのtokenを更新する。

GCG系では各positionについてgradientから有望なtoken候補を選び、discrete replacementを反復する。防御がspecial delimiterやrole tokenを用いる場合は、その前処理を通過した後のeffective inputを考慮してobjectiveを設計する。

### 2. Reinforcement Learning

generation-onlyあるいはdiscrete search spaceでgradientが使いにくい場合、attack promptをpolicyとして生成し、成功判定やmodel responseからrewardを与える。

特にstructured prompt injection defenseでは、「data領域にどのようなinstructionを書けばtrusted instructionを上書きできるか」をRLで探索できる。StruQに対するadaptive RL attackはこの例である。

### 3. Random / evolutionary-style search

defenseのfilterやinput transformが非微分可能でも、mutationとselectionを繰り返すことでattack candidateを改善する。black-box defenseや複雑なagent settingに適する。

### 4. Human-guided exploration

完全自動optimizerだけでなく、人間がfailure modeを観察し、attack representation・objective・initializationを調整する。security evaluationではattack designerがdefenseを理解して戦略を変えること自体がthreat modelの一部であるとする。

## Experiment Setup

対象はjailbreak defenseとprompt injection defenseの双方で、合計12 defenseを評価する。

prompt injection側ではmodel-level defenseを含み、特にStruQ / SecAlign系の「untrusted data内instructionを無視する」手法にadaptive attackを適用する。

評価metricは基本的にAttack Success Rate (ASR)。元論文で報告されたASRまたはstatic attackでのASRと、adaptive optimization後のASRを比較する。

## Main Results

最大の結果は、**12 defenseの多くでadaptive attack ASRが90%を超える**ことである。これらの中には元論文でnear-zero attack successと評価されていた手法も含まれる。

### StruQ

[StruQ](../Defense/2024-2402.06363-struq.md)はstructured query + structured instruction tuningによりmanual/template attackへ高いrobustnessを示すが、本論文ではdefense-aware RL-based attackによって **100% ASR**まで到達する。

これは「data channel内のinstructionを無視するbehavior」をSFTしただけでは、adaptive searchが見つけるout-of-distribution injectionまで完全に排除できないことを示す。

### Meta SecAlign

[Meta SecAlign](../Defense/2025-2507.02735-meta-secalign.md)はstatic AgentDojo評価では非常に低いASRを報告する一方、本論文のadaptive searchでは **96% ASR**まで上昇する。

この差は、benchmark datasetに対する強さと、attack objectiveが防御を知った上で最適化されるsecurity settingとのギャップを明確にする。

### GCGとの関係

GCG自体は依然として重要なbaselineだが、本論文の示唆は「GCGに耐えた = robust」ではない。defense architectureによっては、

- suffix位置を変える
- injected dataとして埋め込む
- objectiveを変更する
- tokenizer / filteringを考慮する
- search algorithm自体をRL等へ変更する

必要がある。

## Transferability / Adaptive Attack Evaluation

通常のtransfer attackでは、surrogate modelで得たsuffixを別modelへ移す。一方、本論文ではtransferability以上に**adaptivity**を重視する。

あるattackが別defenseへそのままtransferしなくても、そのdefenseに対してoptimizerを再設定すれば成功する可能性がある。このためdefenseのsecurity claimは「known attacksに強い」ではなく、「合理的なadaptive attackerに対してどの程度budgetを要するか」で評価すべきだとする。

## Defense別の示唆

### StruQ / structured separation

delimiter filteringやrole separationはattack surfaceを減らすが、model自体がuntrusted instructionへ反応するbehaviorを完全に失うわけではない。adaptive RL / searchで境界を突ける。

### SecAlign / Meta SecAlign

preference optimizationはstatic optimization attackへの耐性を大きく改善するが、negative preference dataのcoverage外にあるadaptive attackには依然弱点が残る。

### Instruction Hierarchy / ISE

本論文の直接評価対象か否かとは別に、[Instruction Hierarchy](../Defense/2024-2404.13208-instruction-hierarchy.md)や[Instructional Segment Embedding](../Defense/2024-2410.09102-instructional-segment-embedding.md)にも同じ評価原則が適用される。すなわち、既知prompt injection setでのaccuracyだけでなく、hierarchy mechanismそのものを狙うadaptive attackを考える必要がある。

### CaMeL

[CaMeL](../Defense/2024-2410.05451-defeating-prompt-injections-by-design-camel.md)のようにsecurity enforcementをLLM外のcapability / information-flow layerへ置く手法は、model behaviorを破るだけでは直ちにsecurity propertyを破れない。そのためmodel-level defenseとsystem-level enforcementを区別して評価する必要がある。

## Limitations

- 強いadaptive evaluationは計算costが高い。
- すべてのpossible defense-specific attackを探索できるわけではない。
- 90%超ASRが示されても、real-world exploitabilityやattack costが同一とは限らない。
- adaptive attackerの設計には人間の知識が入り、完全自動benchmark化が難しい。
- jailbreakとprompt injectionではsecurity objectiveが異なるため、ASRの意味も同一ではない。

## LLM Model Security Taxonomyでの位置づけ

```text
Generic adversarial optimization
        GCG / suffix attacks
                ↓
Static defense evaluation
        StruQ / SecAlign / jailbreak defenses
                ↓
Adaptive defense-aware evaluation
        The Attacker Moves Second  ← 本論文
                ↓
Security claim:
"known attacks fail" ではなく
"adaptive attackerにも耐えるか"
```

Instruction hierarchy自体を提案するDefenseではなく、**hierarchy / privilege separation defenseを評価するためのAttack methodology**として位置づけられる。

## 実装・研究上の示唆

新しいLLM security defenseを提案する場合、既存attack libraryをdefault parameterで回すだけではrobustness evidenceとして弱い。

最低限、

- defense-aware objective
- adaptive prompt / suffix search
- sufficient optimization budget
- white-boxとblack-box双方
- attack initializationの複数化
- failure analysis後のre-optimization

を含む評価が必要である。

またSecAlign系のようにmodel-level defenseをtrainingする研究では、training-time attack distributionとevaluation-time attack distributionを意図的にずらし、adaptive adversaryによるstress testを標準化する必要がある。
