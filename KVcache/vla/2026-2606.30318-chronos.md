# Chronos — full-history state-space memory and second-order action generation

## 1. 概要・問題設定

部分観測ロボットでは、現在画像が同じでも過去の作業順序が異なれば正しい行動は変わる。典型例は、対象を一度移動して元に戻した後に次の段階へ進む作業である。短いhistory windowを使うMarkov policyでは、窓外のイベントを忘れてphaseを取り違える。Chronosは観測履歴を付属的なcontextではなく**制御policyの潜在状態そのもの**として扱う。さらに、action chunkを生成する際に加速度を予測する二階bridgeを採用し、接触操作の滑らかさを狙う。

## 2. 先行研究との差

- [MemoryVLA](2025-2508.19236-memoryvla.md)：perceptual/cognitive memory bankから検索・統合する。Chronosは別の明示的bankを作らず、時系列のselective SSM stateに履歴を畳み込む。
- [MEM](2026-2603.03596-mem.md)：短期動画と長期言語記憶を利用する。Chronosは言語要約を保持するのではなく、視覚・自己受容の時間発展をrecurrent stateに保持する。モデル・データ・ベンチマークが異なるため優劣の直接比較はできない。
- [ReMem-VLA](2026-2603.12942-remem-vla.md)：短期・長期recurrent queryを分ける。Chronosは単一の物理時間軸に沿って1 step = 1 state tokenとする。
- [VLA-Cache](2025-2502.02175-vla-cache.md)：連続フレーム間のTransformer visual KVを再利用する。Chronosのstateはattention KV cacheではなく、SSMの再帰状態である。
- MTIL：同様に全履歴SSMを用いるが、Chronosは長いデモ全体を通したgradient propagationを強調し、detachによる時間方向credit assignmentの制限を回避する。

## 3. 手法

### 3.1 1時刻1 tokenと全履歴SSM

各物理制御時刻に、点群または画像特徴とproprioceptionを融合し、state tokenを作る。空間patch数ではなく物理時刻数がSSMの系列長となる。

```math
x_t = \phi_{\eta}(o_t,p_t)
```

```math
(h_t,y_t) = \mathcal{S}_{\theta}(h_{t-1},x_t)
```

ここで `h_t` は内部recurrent state、`y_t` はaction headに渡す履歴context。selective SSMの離散化パラメータは入力依存で、概念的には次の更新を行う。

```math
h_t = \bar A_t h_{t-1} + \bar B_t x_t
```

```math
y_t = C_t h_t + D x_t
```

推論時は因果的に1 stepずつ更新できる。一方、学習では全デモを通してbackpropagationし、後段の模倣損失から初期時刻の表現まで勾配を流す。**推論のstate sizeが固定でも、全履歴を通した学習時activation memoryは一定ではない**点を区別する必要がある。

### 3.2 IMLE coarse action prior

履歴contextと現在tokenから条件を作り、潜在乱数を入力とするimplicit generatorが多峰性を持つ粗いaction chunkを生成する。

```math
c_t = \Gamma_{\omega}(y_t,x_t)
```

```math
q_0 = G_{\phi}(z_t,c_t)
```

IMLEは複数候補からexpertに近いsampleを学習するため、単純な回帰で異なる行動modeが平均化される問題を抑える狙いがある。

### 3.3 二階Schrödinger-inspired bridge

Action chunk全体を一般化座標 `q` として扱い、bridge time `s` 上で速度と加速度を更新する。

```math
\frac{dq}{ds}=v
```

```math
\frac{dv}{ds}=f_{\psi}(q,v,s,x_t)
```

これは**ロボットの物理時間に関する加速度そのものではなく、生成bridge上の二階ダイナミクス**である。学習時はexpert actionを終点にした補間軌道と加速度matching lossを用いる。Quartic schedulerはbridgeの両端で位置・速度perturbationがゼロとなる境界条件を意識した設計。実行時は数stepの積分でIMLE priorを修正する。

## 4. Experiment Setup

- **ALOHA bimanual insertion**：50 demonstrations、50 evaluation trials、約5 mm clearance。凍結DINOv2画像特徴＋trainable adapterを使用。Action headとschedulerの制御された比較に適する。
- **RoboTwin 2.0 Easy**：一般操作8タスク、各50 demonstrations・100 trials。DP、ACT、RDT-1B、pi0、DP3と比較。
- **RMBench**：記憶依存7タスク、各50 demonstrations・100 trials。DP、ACT、pi0.5、X-VLA、Mem-0と比較。
- **実機**：単眼RGBの双腕4タスク。うち3件が記憶依存。
- **規模**：Chronos 0.3B、DP3約264M、pi0.5 >3.3B、Mem-0 >10B。規模差が大きく、backbone・訓練data・hardware・seedは全baselineで統一されていない。
- **効率評価**：論文は少数bridge stepの利点を示すが、同一GPUでの厳密なend-to-end latency、peak VRAM、throughput、control Hzを網羅した比較は限定的。

## 5. Main Results

### 5.1 RMBench（Table V、成功率%）

| Method | Average | Rearrange Blocks | Put Back Block | Swap Blocks | Swap T | Battery Try | Cover Blocks | Press Button |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| DP | 5.8 | 0 | 0 | 11 | 20 | 10 | 0 | 0 |
| ACT | 7.4 | 29 | 0 | 2 | 2 | 19 | 0 | 0 |
| pi0.5 | 11.2 | 13 | 11 | 24 | 15 | 16 | 0 | 0 |
| X-VLA | 11.1 | 13 | 18 | 16 | 3 | 26 | 2 | 0 |
| Mem-0 | 50.8 | 89 | 90 | 67 | 14 | 28 | 68 | 0 |
| **Chronos** | **73.6** | **98** | **98** | **99** | **93** | **29** | **96** | **2** |

Chronosはpi0.5比+62.4ポイント、Mem-0比+22.8ポイント。ただし**Press Button 2%、Battery Try 29%**と苦手なタスクも残る。これらの差は同一条件下で再学習した統制実験だけに基づくものではない。

### 5.2 ALOHA insertion（Table II）

| Method | Success |
|---|---:|
| ACT | 50% |
| MTIL | 76% |
| Chronos regression (IMLE/SBなし) | 76% |
| Chronos + diffusion head | 66% |
| Chronos + flow head | 72% |
| Chronos IMLE only (SBなし) | 86% |

同じhistory encoderを使用したaction head比較では、IMLEと二階bridgeの両方が寄与。物理的に滑らかな制御という仮説に沿うが、成功率だけから軌道jerkの普遍的優位を断定することはできない。

### 5.3 実機

4タスク平均78%、記憶依存3タスク平均72%。比較対象pi0.5はそれぞれ7%、0%。実機は単眼RGB双腕設定であり、他の視覚入力構成や未知ロボットへの転移は未検証。

## 6. 主要ablation

- **Bridge積分step数（ALOHA Table III）**：1/2/3/4/5/7/10/15 stepsで84/82/90/84/90/86/84/88%。3〜5 stepが最良で、stepを増やせば単調に改善するわけではない。
- **Action head**：回帰76%、diffusion66%、flow72%、IMLEのみ86%、full90%。同じencoderで比較した点が重要。
- **Scheduler**：first-order scheduler72%に対しquartic second-order90%。bridgeの境界条件の重要性を示唆する。
- **Memory ablationの不足**：full-historyと有限窓・state reset・state sizeの容量曲線、記憶破損や極端な長時間運転での忘却率を体系的に示す結果は限定的。メモリ保持時間を数値で保証する研究ではない。

## 7. Limitations

1. **KV cache削減ではない**：selective SSM stateを持ち回る方式であり、Transformerのvisual KVを再利用・evict・quantizeしない。
2. **計算量の解釈**：SSMは時間軸に対して線形・逐次更新可能だが、画像encoderの1-step費用とaction bridgeの反復は残る。制御周波数の改善を定量的に確認するには実測が必要。
3. **長期記憶の劣化**：recurrent stateに過去情報を圧縮するため、長時間での干渉・上書き・容量限界は残る。外部retrievalで過去観測を正確に復元する仕組みではない。
4. **比較の公平性**：大型VLAの一部は公式報告値で、学習データ・観測・seed・実装が一致しない。Chronos内variant比較の方が因果的に解釈しやすい。
5. **失敗例**：RMBenchのPress Button/Battery Tryでは成功率が低い。局所幾何中心の一般操作ではDP3が上回るタスクもある。
6. **追加学習が必要**：encoder adapter、SSM、IMLE、bridgeの学習が必要でtraining-freeなcache optimizationではない。
7. **本文検証範囲**：arXiv公式HTMLの本文・実験表を精読。PDFバイナリの直接取得は実行環境のネットワーク制限により未完了。

## 8. Taxonomy

`KVcache/vla/` — **long-horizon memory / recurrent latent state / flow・diffusion代替action generation**。KV cache reuseとは異なるが、(a) 1時刻1 tokenへのhistory compression、(b) state更新の定数コスト、(c) 少数bridge stepという推論効率上の示唆がある。実際の速度・VRAM・成功率のPareto曲線を測る追加評価が望まれる。
