# KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache

> KV cacheを単純に低bit化するのではなく、KeyとValueでoutlierの出方が異なることを利用し、量子化軸そのものを変える。KV-cache quantization研究の代表的な設計。

## 概要

autoregressive decodingでは、各layerで過去tokenすべてのKey / Valueを保存する。KV cache容量は概ね batch size × sequence length × KV head数 × head dimension × layer数 に比例するため、long contextやlarge batchではmodel weightと同程度、あるいはそれ以上のmemory bottleneckになる。

さらにdecodeでは1 token生成するたびに過去KV全体をHBMから読み出すため、計算量よりmemory bandwidthが律速になることが多い。したがってKV cacheを圧縮すると、単にOOMを防ぐだけでなくdecode bandwidthも削減できる。

KIVIは2-bit KV quantizationを行うが、本質はbit数ではなく「KとVを同じ方法でquantizeしない」ことにある。

## Key / Value distributionの観察

著者らはLlama、Falcon、Mistral等のKV tensorを調べ、Keyでは特定channelに非常に大きな値が繰り返し出現するpersistent outlierが存在することを確認する。

この状態で1 token内の全channelを同じscaleでquantizeすると、少数のoutlierにdynamic rangeを奪われ、残りの値のresolutionが低下する。

一方ValueではKeyほどchannel固定のoutlierが強くなく、tokenごとに値域を合わせる方が誤差が小さい。

この差から、

- Key: per-channel quantization
- Value: per-token quantization

という非対称な設計を採用する。

## Quantization

group内の最小値・最大値からscaleとzero-pointを決めるgroup-wise affine quantizationを用いる。2-bitの場合、各値は4段階へ写像される。

Keyではtoken方向に同じchannelの値をまとめてgroup化する。概念的にはKey tensorをtransposeしてからtoken dimensionに沿ってquantizeする形になる。

Valueでは各tokenのValue vector内をgroup分割し、そのtoken固有のscaleでquantizeする。

この違いにより、Keyのpersistent outlierを他channelから切り離しつつ、Valueはtoken単位でlocal rangeへ適応できる。

## Residual Cache

decodeでは新tokenが1個ずつ追加されるため、Keyのper-channel quantizationを毎token即座に実行すると非効率になる。

そこでKIVIは最新tokenを一定長だけFP16/BF16で保持するresidual cacheを設ける。

処理は次のようになる。

1. 新tokenのKVはまずfull precision residual cacheへ追加
2. residual cacheが所定長に達したら、古い部分をまとめて2-bit化
3. attention時にはquantized old KVとfull-precision recent KVを同時に参照

この構造によりonline quantizationをbatch化し、直近tokenのprecisionも保つ。

## Kernel実装上のポイント

KVを2-bitで保存しても、attentionのたびに全tensorをFP16へ展開してしまうと性能向上が小さい。

KIVI実装ではpacked low-bit representationを保持し、attention計算時に必要な部分を効率良くdequantizeする。decodeはmemory-boundになりやすいため、追加のbit unpack costよりHBM traffic削減の方が大きければ高速化できる。

## Experiment Setup

Llama、Falcon、Mistral系modelに対し、language modeling、zero/few-shot evaluation、long-context task、GPU memory、batch capacity、serving throughputを評価する。

重要なのはKIVIがtuning-freeである点で、weightやmodel architectureは変更しない。

比較ではFP16 KV、4-bit、単純なper-token低bit化などと比較し、特にKey側のquantization axisがaccuracyへ与える影響を検証する。

## Main Results: Quality

2-bitまで下げても、多くのtaskでFP16 KVに近い性能を維持する。

特にKeyをper-tokenでquantizeするnaive方式よりper-channel Keyの方が安定する。これはKey errorがQK^Tのattention scoreに直接影響するためである。

Valueでは逆にper-tokenが有効で、K/Vを同じaxisで処理するより非対称方式が優れる。

## Main Results: Memory

KV自体はFP16の16 bitから2 bitへ大幅に圧縮される。scale等のmetadataとresidual cacheがあるためsystem全体で8×そのまま減るわけではないが、model weightを含むpeak GPU memoryを最大約2.6×削減する。

この空きmemoryによってbatch sizeを最大4×程度まで拡大できるcaseを示す。

## Main Results: Throughput

memory capacityとKV bandwidthの双方が改善し、実LLM serving workloadで2.35〜3.47×のthroughput向上を報告する。

つまりKIVIの効果は「長contextを載せられる」だけではなく、同じGPUでより多くのrequestを処理できる点にある。

## Ablationから分かること

最も重要なablationはquantization axisである。

Keyをper-tokenにするとoutlier channelがscaleを支配し、小さいchannel値の量子化誤差が増える。Keyをper-channelにするとこの問題が減る。

Valueでは逆に、各token固有のrangeへ合わせるper-token方式が良い。

この結果は、KV cacheを単一のtensor typeとして扱わず、attention内での役割とdistributionを別々に分析する必要性を示す。

## SnapKVとの違い

[SnapKV](2024-2404.14469-snapkv.md)はtoken数を減らす手法で、KIVIは各tokenのbit数を減らす手法。

KIVIは全tokenを保持するため情報はquantization errorとして失われる。一方SnapKVは選ばれなかったtoken自体を削除する。

両者は原理上併用可能で、SnapKVで残すtokenを減らし、その残存KVをKIVIで2-bit化するという二段圧縮も考えられる。

## MLA / GQAとの関係

GQAやMLAはarchitecture側でKV head数やrepresentation dimensionを減らす。

KIVIはarchitecture非依存のrepresentation compressionなので、これらとも直交する。

例えばMLAでlatent KV dimensionを減らし、そのlatent cacheをさらに低bit量子化する方向も自然に考えられる。

## Limitations

- token数そのものは減らないため、context lengthに比例するcache growthは残る。
- dequantization kernelの品質がsystem speedupを左右する。
- residual lengthを大きくするとqualityは安定するがmemory benefitが減る。
- 将来modelでKey / Valueのoutlier構造が変われば最適axisも変わり得る。

## KV-cache taxonomyでの位置づけ

KIVIはrepresentation-level compression / KV quantization。

compressカテゴリでは、KIVIのbit compressionとSnapKVのtoken evictionを別軸として扱うのが分かりやすい。

## 研究上・実装上の示唆

KIVIの重要な教訓は、KeyとValueはshapeが同じでも統計分布とattentionでの役割が異なるため、同じ圧縮policyを当てる必要はないという点。

KV optimizationではmemory capacityだけでなく、decode時のHBM traffic、packing / dequantization cost、online append patternまで含めて設計する必要がある。

## まとめ

KIVIは、

1. Keyのpersistent channel outlierを発見
2. Keyをper-channel 2-bit化
3. Valueをper-token 2-bit化
4. recent tokenをfull-precision residual cacheへ保持
5. packed low-bit KVを効率よくattentionで利用

する。

tuning-freeでqualityをほぼ維持しながらpeak memoryを最大2.6×削減し、batch拡大を通じて2.35〜3.47×のthroughput向上を実現する。単なる低bit化ではなく、K/V distributionの違いから量子化方式を導いた点が最も重要な貢献。
