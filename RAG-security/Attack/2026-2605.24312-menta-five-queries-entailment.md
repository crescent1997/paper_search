# Five Queries Are Enough: Query-Efficient and Surrogate-Free Membership Inference Attacks on RAG via Entailment（MEntA）

> **要点**：RAGのprivate retrieval databaseに**特定の候補文書が存在するか**を、black-boxの最終回答のみから推定する。既存の自然なinterrogation型MIAが多数のyes/no質問とshadow LLMを必要としたのに対し、MEntAは**5つの情報量の多い自然言語質問**を送り、回答をatomic claimsに分解して**候補文書からの含意（NLI entailment）**を検証する。最大AUC **0.991**、USENIX Security 2026。

## 概要

企業内RAGでは、非公開文書の本文を直接出力しなくても、特定の患者記録、契約、監査資料などが検索対象に含まれること自体が機密になりうる。Membership Inference Attack（MIA）は、攻撃者があらかじめ持つ候補文書$D$について、$D\in\mathcal{C}$（private corpusに含まれる）かを判定する攻撃である。

RAGの回答はretrieved contextに条件付けられるため、$D$が存在すれば、その固有事実に支えられた回答が出やすい。ただし既存の攻撃は、直接「この文章がcontextにあるか」と尋ねる定型promptで検知されるか、自然な質問を大量に送って統計を取る必要があった。MEntAは、**質問1件から得られるevidence量を増やす**ことと、**回答と文書の意味的含意を正しく区別する**ことを組み合わせる。

重要な区別として、MEntAは**全文抽出・corpus stealingではない**。存在確認というprivacy leakageであり、[CopyBreakRAG](2024-2411.14110-feedback-guided-extraction-copybreakrag.md)、[IKEA](2025-2505.15420-silent-leaks-ikea.md)、[RAGCrawler](2026-2601.15678-connect-the-dots.md)のような広域corpus reconstructionとは目的が異なる。一方、query数が極端に少なく、通常の情報検索に見えるため、extraction前の偵察段階としても重要なリスクである。

## Threat Model / Attacker Capability

**Victim**：private corpus $\mathcal{C}$を持つRAG API。外部ユーザーのqueryに対しretrieverがtop-$k$文書を選び、generatorが回答を返す。実験では回答根拠がない場合に`I don't know`を返すsystem promptを用いる。

**Attackerの知識・権限**：候補文書$D$を保持しており、その文書のmembershipだけを調べたい。APIへ自然言語queryを送信し、**final response textのみ**を取得できる。retrieved chunks、document ID、similarity score、embedding、logits、LLM weights、retriever architecture、内部corpusにはアクセスできない。corpusへのwrite accessも不要。

**攻撃側の補助計算**：候補文書をもとにoffline LLMで質問とsummaryを作成し、ローカルNLI modelで回答を評価する。**shadow RAG / shadow generatorによる正解回答生成は不要**だが、offline query-generation LLMとNLIは必要であり、「モデルを一切使わない」という意味ではない。またbinary decisionの閾値$\tau$はheld-out calibration setで選択すると論文に明記されており、完全な事前知識ゼロのsingle-target設定ではcalibrationの入手が課題となる。

**攻撃成功**：候補文書のmember/non-memberをAUC、accuracy、特に低False Positive RateにおけるTPRで判別する。5 queries per target documentがデフォルト。候補文書の全文を知らない攻撃者が内部DBを探索する攻撃ではない。

## 先行研究からの改善点

| 系統 | 既存のprimitive / 制約 | MEntAの改善 |
|---|---|---|
| 明示的context leakage | [The Good and The Bad](2024-2402.16893-the-good-and-the-bad.md)やTGTB系はretrieved contextの再出力を要求し、prompt patternが露骨 | 自然なinformation-seeking questionsのみを使い、出力に現れた固有事実を検証 |
| S²-MIA / RAGLeak | 候補文書と回答のsurface similarityやBLEUに依存し、話題の一致と事実の含意を混同しやすい | 文書をpremise、atomic claimをhypothesisとする**方向付きNLI entailment**を使用 |
| MBA | 文書をmaskして埋めさせるなど、定型かつ攻撃らしいprompt | 自然な質問を多様化し、文書の各部分を横断 |
| DCMI | yes/noとperturbed queryの差分を使うが、直接的なmembership検査に近い | 質問文面でmembershipを直接問わない |
| [Riddle Me This! / Interrogation Attack（IA）](2025-2502.00306-riddle-me-this.md) | 自然な質問を使うが、yes/noを多数集め、shadow LLMの回答で照合。最適budgetは約30 queries | **5 questions**に圧縮し、回答中の複数atomic claimsをNLIで判定。shadow LLMを不要化 |

IAからは**candidate document summaryを質問の前に付加する**手法と、回答拒否を負のevidenceとして扱う発想を継承している。したがって「全く新しいquery primitive」ではなく、**高情報量の質問設計とscoring primitiveの置換**が主な改良点。

## Method / Algorithm

### Step 1：多様なdocument-specific queryをoffline生成

候補文書$D$をoffline LLM（実験では**GPT-4.1-nano**）へ渡し、先頭・中間・末尾の異なる事実を尋ねる$n=5$個の質問$Q_D=\{q_1,\ldots,q_n\}$を作る。yes/noや文書の存在を直接尋ねるのではなく、特定の方法・数値・結果・根拠など**回答中に複数の検証可能な事実が現れる**ようにする。

同時に$D$の短いsummary $S_D$を生成し、各質問へprependして$q_i'=\operatorname{concat}(S_D,q_i)$を送る。これはIAから継承した**retrieval誘導**であり、victim retrieverがtarget文書をtop-$k$に入れる確率を上げる。したがって「non-templated」といっても**文書固有のsummaryという手掛かりをqueryへ挿入する**。summaryを含む長い質問が全環境で自然と判定されるかは別途検証が必要。

### Step 2：black-box RAGへqueryし回答を収集

各$q_i'$に対し$\mathcal{C}_{q_i}=R(q_i',\mathcal{C})$をretrievalし、$a_i=G(q_i',\mathcal{C}_{q_i})$を生成する。攻撃者が受け取るのは$a_i$のみ。$D\in\mathcal{C}$なら、query specificityにより$D$が検索され、文書固有の事実を含む回答が出やすい。$D\notin\mathcal{C}$なら、他文書やモデルの事前知識に依存した一般的回答、誤回答、または拒否が出やすい。

### Step 3：Atomic claimごとのNLI entailment

回答$a_i$をatomic sentence $s_{ij}$に分割する。実験では`tasksource/deberta-base-long-nli`を使い、**premise=$D$、hypothesis=$s_{ij}$**として3値確率$P(ent),P(neu),P(con)$を得る。回答全体のembedding cosine similarityでは、話題が似ているだけの誤情報まで「一致」と判定してしまう。NLIは**Dからその主張が論理的に支持されるか**を見るため、paraphraseにも対応しやすい。

少なくとも1つのatomic claimについてentailmentが最大クラスなら、そのqueryをevidence hitとする。

$$
I_{ent}(q_i)=\mathbf{1}\left[\exists s\in a_i:\ P(ent\mid D,s)>\max(P(neu\mid D,s),P(con\mid D,s))\right].
$$

また、回答拒否を表す複数の言い換え仮説（`I don't have enough information`等）に回答文がentailする場合、$I_{idk}(q_i)=1$とする。単純な文字列`I don't know`一致ではなく、言い換えられた拒否も捕捉する。

### Step 4：5 queryのevidence集約とthreshold

$$
\operatorname{MIA}(D)=\frac{1}{|Q_D|}\sum_{q\in Q_D}\bigl(I_{ent}(q)-I_{idk}(q)\bigr).
$$

このscoreは$[-1,1]$の範囲を取り、正側ほどmemberらしい。held-out setで選択した閾値$\tau$より高ければmemberと判定する。$n$個のentailment hitを集約する根拠として、$P(I_{ent}=1\mid member)=p_1>P(I_{ent}=1\mid nonmember)=p_0$かつquery間で条件付き独立のBernoulli modelを仮定すると、Neyman–Pearson lemmaによりhit数のthreshold testが固定FPRで最も強力になると論じる。

**注意**：理論は独立Bernoulli hit数についてのもので、実際のscoreはIDK penaltyを含み、queryも同じ候補文書から生成するため相関がありうる。したがって実際のMEntA score全体の最適性が証明されたわけではない。

### Pseudocode（論文の要約）

```text
Input: candidate document D, black-box RAG oracle, query budget n=5
S_D = offline_summarize(D)
Q_D = offline_generate_diverse_questions(D, n)
for q in Q_D:
    a = RAG_oracle(concat(S_D, q))
    claims = split_into_atomic_claims(a)
    entail_hit = any(NLI(premise=D, hypothesis=s) == entail for s in claims)
    refusal_hit = any(NLI(s, refusal_hypothesis) == entail for s in claims)
    score[q] = entail_hit - refusal_hit
membership_score = mean(score)
return membership_score > calibrated_threshold
```

## Experiment Setup

**Datasets**：BEIRのNFCorpus、SCIDOCS、TREC-COVID。各datasetから**member 1000件、non-member 1000件**を用意。公開datasetによるprivacy riskのsimulationであり、実際の企業private corpusを攻撃した実験ではない。

**Retrievers**：`sentence-transformers/all-mpnet-base-v2`と`thenlper/gte-large`。デフォルトは**top-k=3 / all-mpnet-base-v2**。kを3、5、10、20に変えた実験も実施。

**Generators**：Phi4-14B、Llama3.1-8B、CommandR-7B、Gemma2-2Bの4モデル。質問生成はGPT-4.1-nano、NLIはDeBERTa long-NLI。比較IAは質問生成GPT-4o、shadow GPT-4o-mini。MEntA/IAとも主比較では**5 queries**とし、budget studyではIAを30 queriesまで拡大。

**Baselines**：S²-MIA（候補文書前半→BLEU）、MBA（mask recovery）、DCMI（元質問とperturbed質問のyes/no差分）、IA（自然な質問とshadow回答比較）。gray-box accessを要するRAG-leaks、SMA、BudgetLeak-Zは公平性のため主比較から除外。

**Metrics**：AUC、best-threshold accuracy、**TPR@FPR=0.01/0.05**。低FPRは実運用で大量の無関係な文書をmemberと誤判定しないための重要指標。AUCだけではセキュリティ上の有用性を過大評価する可能性がある。

## Ablation / Transferability / Defense Evaluation

### Entailment vs cosine similarity（Fig. 4）

query、budget、retrieval条件を固定し、scoreのみをcosine similarity（閾値0.7）へ置換したablationでは、entailmentが複数generatorで高いAUCを示す。例えば高いsemantic overlapでも文書が実際にはその主張を支持しない場合、cosineは誤ってmemberと判定しやすい。NLIは**semantic relatednessとlogical supportの区別**を重視する。

SciFactを使った補助検証でも、similarityはSUPPORT/CONTRADICTで分布が重なるが、NLI entailmentは区別しやすい。ただしNLI自体がdomain shiftや専門用語に頑健かどうかは別問題。

### Query specificityとretrieval dependence（Fig. 7）

Llama3.1-8Bでdocument-specific questionsをgeneric topical questionsへ置き換えると、AUCは**0.109–0.214低下**。さらに同じ質問を使いながら**retrievalを外す**と、AUCはNFCorpus **0.493**、SCIDOCS **0.524**、TREC-COVID **0.483**まで低下する。summary-prependingやモデルのparametric knowledgeだけでmembershipが推測できるのではなく、**retrieved evidenceに依存する信号**であることを裏付ける重要な対照実験。

### Atomic-claim thresholdとquery budget（Fig. 6, 8）

1 queryで最低1つのentailed claimがあればhitとするのがdefault。必要なentailed claims数を増やしてもAUCは概ね安定するため、単一の偶然一致だけが結果を支えているわけではない。budgetを増やした場合、MEntAは**5–10 queries付近で早く飽和**する一方、IAはより多くのqueryで徐々に改善する。

### Retriever / top-kの変更（Table 5, Fig. 9）

Llama3.1-8Bでall-mpnet-base-v2→gte-largeに変更した際のAUCは、NFCorpus **0.935→0.931**、SCIDOCS **0.936→0.939**、TREC-COVID **0.801→0.796**。retrieval depthを$k=3,5,10,20$に変えても概ね安定し、SCIDOCSではAUC約0.94。これは、target文書がretrieved evidenceへ含まれる限り、モデル固有のembedding similarity artifactに依存せず漏洩信号が残ることを示す。

### 入力・出力改変Defense下のAUC（Table 6、Phi4-14B）

| Dataset | No Defense | DP-style perturbation | Reranking | Prompt instruction | Query paraphrase |
|---|---:|---:|---:|---:|---:|
| NFCorpus | **0.989** | 0.913 | 0.975 | 0.984 | 0.977 |
| SCIDOCS | **0.991** | 0.916 | 0.986 | 0.992 | 0.953 |
| TREC-COVID | **0.893** | 0.836 | 0.904 | 0.908 | 0.846 |

実験のDP-style output perturbationは$\epsilon=0.1$、rerankingはretrieved candidatesの順序をrandom shuffle、prompt instructionは回答拒否とverbatim抑制、paraphrasingは技術用語を保持した言い換え。**これは正式なend-to-end document-level DP保証の有効性を否定する結果ではない**。あくまで論文実装のoutput perturbation下でのMIA性能である。

IAのNFCorpus AUCはDP下で**0.756→0.518**、SCIDOCSでは**0.915→0.543**まで下がる一方、MEntAは0.913/0.916を維持する。yes/noというsurface formに依存するIAと、paraphrase後も残るlogical entailmentを使うMEntAの差が表れている。

### Query detectorとFalse Positive（Tables 7–8）

GPT-4系のinput detectorはMEntA queryを見逃しやすく、MEntA recallはNFCorpus **0.061**、SCIDOCS **0.263**、TREC-COVID **0.058**。一方、MirabelのMEntA recallはそれぞれ**0.738 / 0.991 / 0.454**と高い場合もある。しかしbenign queryに対するMirabel FPRは**0.596 / 0.881 / 0.518**で、特にSCIDOCSでは正常queryの88.1%が攻撃扱いとなる。GPT-4 detectorのbenign FPRはそれぞれ0.033 / 0.151 / 0.076。

Mirabelのoriginal paperが報告した条件と、今回のBEIR-style clustered queriesではbenign queryの類似度分布が異なるため、**このFPRをすべてのMirabel deploymentへ一般化するのは不適切**。しかし、retriever similarity spikeだけで自然な文書固有質問を弾く方式には、utilityとprivacyのtrade-offがあることを具体的に示している。

## Limitationsと成立条件

1. **候補文書$D$を攻撃者が持つ必要**：未知corpusの中身を発見・抽出する攻撃ではない。private recordの存在確認が目的。
2. **Offline LLMとNLI依存**：shadow model不要でもGPT-4.1-nanoとDeBERTa long-NLIは必要。専門分野や非英語文書へのNLI transferは十分評価されていない。
3. **Calibration依存**：$\tau$をheld-out setで調整する。member/non-memberの代表例が得られないreal-world APIでは閾値移植性が問題になる。AUC自体はthreshold-independentだがbinary decisionはそうではない。
4. **Document uniqueness**：short/generic document、類似文書が大量にあるcorpus、near-duplicate nonmembersでは、候補文書固有のentailment signalが弱まる。論文Appendix Bもこのfailure modeを挙げる。
5. **質問の相関**：5つの質問は同一文書から生成されるため、Neyman–Pearsonの条件付き独立Bernoulli仮定が現実に厳密に成立するとは限らない。
6. **Dataset / victimの範囲**：BEIR 3 datasets、4 open generators、2 dense retrieversが中心。企業ACL、hybrid/graph retriever、rate limit、実際のprivate PIIには直接評価していない。
7. **Defenseの範囲**：output perturbation、query rewriting、reranking、prompt instruction、input detectionを検証するが、document-level DP synthetic corpus、厳密なretrieval ACL、cross-session semantic exposure budgetの評価はない。
8. **価格比較の仮定**：NLI costは推定値、Gemmaの料金も近似。offline query-generationやcandidate acquisitionの実際の総コストも攻撃シナリオで変化する。

## RAG Data Extraction / Security Taxonomyでの位置づけ

**Attack → Privacy Leakage → Black-box Retrieval-corpus Membership Inference → Low-query, Natural-language Entailment-based MIA**。

同じRAG APIへのqueryから情報を得る攻撃でも、[RAGCrawler](2026-2601.15678-connect-the-dots.md)、[CopyBreakRAG](2024-2411.14110-feedback-guided-extraction-copybreakrag.md)、[IKEA](2025-2505.15420-silent-leaks-ikea.md)は**未知の内容を広く取得するcorpus extraction**である。MEntAは**既知候補のmembershipを判定**する。漏洩対象の粒度が異なるため、coverage rateやverbatim fidelityとAUCを混同しない。

Defenseの観点では、[EPD](../Defense/2025-2512.03100-ensemble-privacy-defense-epd.md)はmembership signalを抑えるinference-time ensemble、[RAG-CT](../Defense/2026-2609.16095-rag-ct.md)はretrieval score distributionを使うPII-targeted extraction監視である。ただし**MEntAに対してこれら2方式の直接比較が論文中で実施されたわけではない**。同じprivacy問題に属するが防御対象・観測可能信号・評価attackが異なる。

## 実装・研究上の示唆

- **retrievalの信号を出さないだけでは不十分**：document IDやretrieval scoreを隠しても、回答中の固有事実からmembershipが推測される。
- **input detectorの評価はFPR込み**：自然な質問への検出recallだけでなく、benign query分布を変えた際のFPR、QA utility、session-level detectionを同時評価する。
- **低query攻撃への防御**：30–100 queriesを前提にしたrate-limitや長期異常検知は5-query attackに弱い。文書単位のexposure budget、回答の固有情報量制御、retrieval ACL、短期sessionでの同一entity/doc露出追跡が重要。
- **entailment leakageの評価**：verbatim string matchやcosine similarityだけでなく、回答のatomic claimsがprivate sourceにentailされる割合をprivacy metricとして測る価値がある。
- **LLM serving研究との接点**：query数が少ないためvictim-sideのKV-cache高速化よりも、attack側のoffline query generation/NLIとretrieverの文書選択が攻撃コストの中心。反復的なMIAに対する防御はsessionをまたぐ状態管理が必要。
