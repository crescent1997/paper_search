# SafeRAG: Benchmarking Security in Retrieval-Augmented Generation of Large Language Model

> RAG securityをcomponent単位で評価するため、attack datasetとevaluation frameworkを整備し、retriever・filter・LLM generatorがどのattackに弱いかを体系的に比較するbenchmark。

## 概要

RAGは外部knowledgeを利用できる一方、knowledge ingestionやretrieval contextの改変によってsystem behaviorを操作されるattack surfaceを持つ。SafeRAGはこの問題を、RAG pipeline全体に対するsystematic security evaluationとして整理する。

## Attack taxonomy

SafeRAGは4種類のattack taskを構成する。

- **Silver Noise**: relevant-looking noiseを挿入してretrieval / generationを乱す
- **Inter-context Conflict**: benign evidenceと矛盾するcontentを注入する
- **Soft Ad**: advertisement-like contentを自然に混ぜ込みresponseへ誘導する
- **White DoS**: system qualityを低下させるdenial-of-service型contentを挿入する

## Evaluation framework

attack contentをRAG pipelineの異なるstageへ挿入し、どこまでdownstream componentが耐えられるかを測る。

評価対象には、

- sparse / dense / hybrid retriever
- reranking / filtering / compression component
- 複数のopen / closed LLM generator

が含まれる。

## 主な結果

- RAGは4種類すべてのattackに対して有意な脆弱性を示す。
- attack contentがknowledge-base stageよりretrieved / filtered contextへ近いstageに入るほど影響が強くなる傾向がある。
- filter / compressorを追加しても常にsecurityが向上するとは限らず、conflicting evidenceの構造を壊して判断を難しくする場合がある。
- retrieverごとにfailure modeが異なり、単一componentを安全とみなすことはできない。
- advanced LLMでもobvious attackを完全には防げない。

## RAG Data Extraction Riskとの関係

SafeRAGの中心はknowledge-base stealingではなく、**integrity / robustness sideのRAG security benchmark**である。

ただし、RAG securityをConfidentialityだけでなくIntegrity / Availabilityまで含めて整理する上で有用であり、Benchmark categoryではknowledge extraction benchmarkと補完的な位置づけになる。

## Limitations

- 主対象はtextual RAGへのdata injectionで、knowledge extractionやbackdoorを直接benchmarkするものではない。
- production systemのACL / tenant isolation / tool executionなどsystem-level securityは範囲外。
- multimodal RAGやagentic RAGへの拡張余地がある。

## 重要なポイント

- ACL 2025 Long Paperとして採択されたRAG security benchmark。
- 4種類のattack scenarioを統一dataset / frameworkで評価する。
- retriever、filter、generatorを分離して弱点を比較できる。
- defense componentを追加しても必ずしもrobustnessが上がるわけではない。
- knowledge extraction専用benchmarkではないが、RAG security全体の評価軸として有用。
