# Fast KV Compaction via Attention Matching

## 概要 / 問題設定

長いdocument・agent履歴のKVを要約やevictionで縮めると、あとから別queryで必要になる情報が消える。Cartridgesはcontextごとにlatent KVをend-to-end最適化して高圧縮率を実現するが、**contextごとに数GPU-hour級の最適化**が必要。著者らは「元tokenを再構成する」のではなく、**圧縮後のKVがattentionに与える効果を再現する**ことを目的にする。

元の1 KV-headのcache `K,V∈R^(T×d)` を `C_k,C_v∈R^(t×d), t≪T` へ圧縮する。対象はKVの物理保存長であり`compress`。圧縮は**1つのcontextに対して一度行い、その後の複数の未知queryで使い回す**設定が中心で、[KVzip](2025-2505.23416-kvzip.md)同様にquery-agnosticな再利用にも関係する。モデルparameterの再学習は不要だが、attention biasの追加と圧縮処理を要する。

## 手法

### 1. Attention OutputだけでなくMassを保存

圧縮対象block `B` と、後から連結する別block `F` へのattentionは、各block内で正規化したattention outputを、blockごとの非正規化softmax **mass** で重み付けして足し合わせられる。よって未知のsuffix `F` が付く場合も、`B` の

1. **local attention output** `softmax(qKᵀ)V`
2. **attention mass** `Σ_j exp(q·k_j / √d)`

の両方が元の値に近ければ、連結後のattentionにも近い寄与を与える。**outputだけ一致してもmassが変わると、他blockとの相対重みが崩れる**ことが重要な観察。

### 2. 圧縮Key・bias・Valueを別々に求める

- **Reference queries `Q_ref`**：contextを繰り返させるrepeat-prefill、contextに関する質問を生成するself-study、単純context-prefillなどからquery activationを採取。層ごとに、先行層を圧縮した状態でqueryを取り直すon-policy variantもある。
- **Key選択 `C_k`**：元Keyから部分集合を選ぶ。高速版はreference queriesに対するattention weightをRMS集約して上位Keyを採用。高品質版は**Orthogonal Matching Pursuit (OMP)**でmassの残差を最も減らすKeyを逐次追加。
- **Mass補正 `β`**：単純なsubsetでは `q=0` のとき元cacheのmassが `T`、圧縮後が `t` で一致しない。各Keyにlogit bias `β_j` を追加し、`w_j=exp(β_j)≥0` として `min_{w≥0} ||Aw-m||²` を **NNLS** で解く。`w_j` は1圧縮Keyが代表する元Keyのattention massに相当。
- **Value再推定 `C_v`**：圧縮後のattention weight行列を `X`、元のattention outputを `Y` とし、`min ||XC_v-Y||²_F` を**線形最小二乗**で解く。元Valueを単に残すより出力が一致しやすい。

Key subset選択後は各headで独立した小問題に分解でき、Cartridgesのようなcontext単位のend-to-end gradient descentを避けられる。

### 3. Nonuniform head budget / Chunking

HeadごとにKV容量感度が違うため、あらかじめ少数の代表contextで感度曲線を計測し、**layer・headごとに異なるcache budget**を配分する。実装上はheadごとに異なる長さをpaddingせず、varlen KV packingが必要。長contextは元のfull-prefill KVをchunkに切り分けて独立圧縮するKV-based chunkingを基本とする。Text-based chunkingではchunk間のcross-attentionが失われるため精度が落ちやすい。

## Experiment Setup

- **Models:** Qwen3-4B、Llama-3.1-8B、Gemma-3-12B（Gemmaではglobal-attention層を圧縮しsliding-window層は維持）。
- **Main datasets:** QuALITY（5–8k tokens、1文書15–20問）、LongHealth（約60k tokens、1 contextあたり100問）、QASPER、LongBench v2、RULERの追加分析。
- **Baselines:** Cartridges、[H2O](2023-2306.14048-h2o.md)、[SnapKV](2024-2404.14469-snapkv.md)、[PyramidKV](2024-2406.02069-pyramidkv.md)、[KVzip](2025-2505.23416-kvzip.md)、KVMerger、summarization。
- **Protocol:** 1 contextを**一度圧縮して全質問に再利用**。chat-template/BOS等のsink tokensは保持して比較。圧縮率は文書tokenを分母とする。
- **Hardware:** Compaction breakdownはGemma-3-12B/LongHealth/単一H200、FP32でfit後BF16でcache保存。速度–品質曲線のQuALITY実験はH100。

## Main Results

**50×圧縮（2%残存）**では、QuALITY上でAttention Matchingが従来eviction・要約より良好なaccuracy–compaction-time Pareto frontierを形成し、Cartridgesに近い/上回る設定もある。極端な圧縮率ではdatasetによって品質が低下し、LongHealthの100×などではCartridgesが勝つ場合がある。

| QASPER（Qwen3-4B、token F1） | 1% KV | 2% KV | 5% KV | Full |
|---|---:|---:|---:|---:|
| KVzip | 0.127 | 0.124 | 0.220 | — |
| H2O+ | 0.188 | 0.243 | 0.310 | — |
| **AM-HighestAttnKeys** | **0.338** | **0.373** | **0.416** | 0.444 |

Llama-3.1-8BのQASPERでは1% KVで **AM 0.317 / KVzip 0.102 / Full 0.456**。LongBench v2の47-context選択subsetでは1%で **AM 61.7% / KVzip 17.0% / Full 72.3%**。ただし後者は**fullで正答かつno-contextで誤答だったcontextだけを選んだ条件付きsubset**であり、一般的なLongBench v2総合scoreとして引用しない。

### Compaction costの内訳

60k tokens / Gemma-3-12B / H200で、reference query取得はcontext-prefill **7s**、repeat-prefill **8s**、self-study **139s**。Key選択はhighest-attention **3s**、OMP-fast **104s**、通常OMP **565s**。NNLS bias fit **2.2s**、Value LS fit **1.8s**。したがって「50×を数秒で圧縮」は**高速variantや短いcontextの条件**であり、full self-study + OMPのwall-clockが常に数秒という意味ではない。

## 主要ablation

- **Head budget:** leave-one-outで最も大きな寄与。uniform budgetに戻すと劣化する。
- **Attention bias `β` とValue refit:** どちらも性能改善。特に単純subsetではmassが系統的に小さくなるためbias補正が重要。
- **Reference queries:** self-study/on-policyは有益だが改善幅は比較的小さい。repeat-prefillのみの高速版が良い妥協。
- **Key selection:** OMPが高品質だが非常に遅い。HighestAttnKeysとOMP-fastは計算量を減らす。
- **Summarization併用:** QuALITYでfull 71.1%、要約のみ55.2%、要約後に0.1× AM-OMPで55.0%（約200×相当）。圧縮率は上がるが**元文書精度は回復しない**。

## Limitations / 実装上の注意

1. **Bias付きattention**、head別varlen KV、logical positionとphysical cache長の分離が必要。標準vLLM/FlashAttentionへそのまま適用できるとは限らない。
2. `Q_ref` にない未知queryへは**近似的に**一般化するだけで保証なし。高密度情報（LongHealth）や100×超では失敗が残る。
3. Contextごとのcompaction計算が数十秒〜数分になり得る。単発queryでは償却困難で、**同じ文書に多数queryが来る用途**と相性がよい。
4. Compaction wall-clockと、圧縮cacheを使ったserving全体のTTFT/throughput改善は別指標。後者のend-to-end評価は限定的。
5. Text-based independent chunk prefillはcross-chunk interactionを失う。KV-based chunkingが優位であり、任意文書の完全独立prefill reuseを解決したわけではない。

## Taxonomy / 関連研究との差分

- **Category:** `compress` / post-hoc latent compaction / query-agnostic multi-query reuse / per-head mass+output matching / no model fine-tuning。
- [KVzip](2025-2505.23416-kvzip.md)：context再構築からtoken importanceを求めて**削除**。Attention MatchingはKeyを選ぶだけでなく**biasとValueを再fit**してattention動作を合わせる。
- [AsymKV](2025-2506.05410-asymkv.md)：隣接Keyを近似mergeし、Value和とcardinalityで局所的にmassを保存。Attention Matchingはreference queriesに対し**globalにmass/outputを近似fit**。
- [HeadKV](2024-2410.19258-headkv.md)・[Ada-KV](2024-2407.11550-adakv.md)：head budgetの重要性は共通だが、Attention Matchingは**高圧縮latent表現の最適化**まで踏み込む。
- [CacheBlend](../reuse/2024-2405.16444-cacheblend.md)・[ProphetKV](../reuse/2026-2602.02579-prophetkv.md)：再利用したKVの**context mismatch修復**が主目的。Attention Matchingは元contextの**圧縮表現の保存と再利用**が主目的で、cross-document attentionの修復とは異なる。
