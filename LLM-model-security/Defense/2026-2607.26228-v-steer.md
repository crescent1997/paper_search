# Steering Instruction Hierarchies at Inference Time

## 概要

V-Steerは、system等のhigher-priority instructionよりuser / tool等のlower-priority instructionがmodel内部で強く影響してしまうInstruction Hierarchy failureを、**trainingなし・inference時のKV cache編集だけで補正する**手法である。

中心的アイデアはattention weight自体を変更するのではなく、prompt tokenに対応するcached Value vectorsを直接編集することである。

最初のnext-token predictionに対するDirect Logit Attribution (DLA)から、lower-priority spanの寄与がprivileged spanを上回るheadを検出し、

- privileged spanのVをboost
- conflicting lower-priority spanのVをsuppress

する。

編集済みValue cacheはその後の全decode stepでそのまま再利用される。

## 問題設定 / Threat Model

context中に異なるpriorityのinstruction sourceが存在する。

```text
higher priority:
  system / privileged instruction

lower priority:
  user / tool / external content
```

両者がconflictするとき、modelはhigher-priority constraintを守るべきである。

しかし実際にはlower-priority spanへの内部寄与が大きくなり、user instructionやtool injectionを優先する場合がある。

V-Steerはweightsをfine-tuneせず、open-weight modelのinference stateへ介入する。

## Direct Logit Attribution

attention headの出力はsource positionごとの寄与へ分解できる。

V-Steerは最初のnext-token predictionについて、各headでhigher-priority spanとlower-priority spanがlogitへどれだけ寄与しているかをDLAで計算する。

概念的には、

```text
phi(high-priority span)
phi(low-priority span)
```

をheadごとに比較し、

```text
phi(low) > phi(high) + epsilon
```

となるheadをbad headとして選択する。

validation set上で全headをoffline profilingする方式ではなく、現在のprompt自身からhead selectionを行う点が特徴である。

## Value Cache Steering

選択されたheadについて、prompt位置のcached Valueをmultiplicativeに編集する。

higher-priority span:

```text
V_high <- gamma_plus * V_high
```

lower-priority conflicting span:

```text
V_low <- gamma_minus * V_low
```

標準設定ではboost係数を1より大きく、suppress係数を1より小さくする。

Keyやattention scoreを直接変更せず、Value側のcontribution magnitudeを変える。

## なぜAttention WeightではなくValueか

attention steeringではattention matrix自体を操作する必要がある。

これはFlashAttention / PyTorch SDPA等のfused kernelで通常materializeされないattention matrixを扱うことになり、fast pathを失いやすい。

V-Steerではcached V tensorだけを書き換えるため、

- attention kernel変更不要
- fused attention利用可能
- KV-cached decodeを維持
- decode stepごとの追加steering不要

となる。

これはserving上の大きな利点である。

## KV Cacheとの関係

standard autoregressive inferenceではprefill後に各layerのK/Vをcacheし、decodeでは新tokenのK/Vだけを追加する。

V-Steerはprefillで得たprompt-side V cacheを一度編集する。

```text
prefill
  ↓
DLA / bad-head selection
  ↓
edit prompt V cache
  ↓
normal KV-cached decoding
```

生成tokenのcacheは通常通り追加される。

したがってper-token interventionではなく、one-time cache transformationである。

## GQAでの扱い

Grouped Query Attentionでは複数query headsが同じKV headを共有する。

そのためquery-head単位で独立にValueを編集できない場合がある。

V-Steerはshared KV structureを考慮し、関連するquery-head attributionをKV-head側のsteering decisionへ集約する。

これはQwen / Llama系の実装で重要になる。

## Complexity

standard prefillに加えてDLAとcache editingを行う。

論文では追加計算量を概ね

```text
O(L(D^2 + T D))
```

とし、T >= DならO(LTD)として整理する。

重要なのはdecode loopに追加costがないことである。

## Experiment Setup

主に以下を評価する。

- Control Illusion
- IHEval

model familyはQwen2.5、Llama-3.1等で、7Bから70B scaleまで含む。

比較対象にはprompt-only intervention、attention steering、training-based hierarchy methods等を含む。

metricはhigher-priority constraintを守った割合であるprimary constraint accuracyを中心に使う。

## Control Illusion

controlled role-conflict benchmarkではbaseline primary-constraint accuracyが18%未満のmodelでも、V-Steerにより最大約92%まで改善する。

これはrole conflictがmodel capacityだけでは解決せず、inference-time internal contributionのrebalancingで大きく変わることを示す。

## IHEval Main Results

overall IHEval conflict scoreでは代表的に、

| Model | Conflict | V-Steer |
|---|---:|---:|
| Qwen2.5-32B | 42.8 | 63.8 |
| Qwen2.5-14B | 29.1 | 53.8 |
| Qwen2.5-7B | 19.8 | 37.0 |
| Llama-3.1-8B | 11.4 | 38.3 |

となる。

V-Steer + Promptでは一部modelでさらに改善し、training-based methodと同等または上回るscaleもある。

## Rule / Task / Safety

IHEvalをRule / Task / Safetyへ分解すると改善量は一様ではない。

V-Steerはsystem-user conflictで強い改善を示すが、全subtaskを同じ程度に解決するわけではない。

特にtool-mediated injectionは難しく、Llama-3.1-8B等ではV-Steer単独で限定的な改善に留まるsettingがある。

したがってsystem-user hierarchy改善をindirect prompt injection全般へのrobustnessと同一視すべきではない。

## Runtime

論文の代表測定では、

```text
standard decoding:   10.3 ms/token
V-Steer:             10.4 ms/token
attention steering:  24.7 ms/token
```

で、V-Steerは約1.01×、attention steeringは約2.40×となる。

V-Steerの追加costは主にprefill後の一回限りの処理である。

## Utility Trade-off

Valueを強くsteerしすぎるとgeneral capabilityを損なう。

aggressiveなV-SimpleではMMLUが66.1から57.6へ低下する例がある。

一方、suppress strengthを弱めることでMMLU 64.2を維持しつつIH complianceを6.8から60.6へ改善するsettingもあり、steering strengthにsecurity / utility trade-offが存在する。

## IHDecとの関係

[IHDec](2026-2606.29960-ihdec.md)もtraining-free inference-time Defenseだが、介入点が異なる。

```text
IHDec:
  counterfactual next-token distributions
  -> detect role-influence inversion
  -> contrastive decoding correction

V-Steer:
  first-token DLA
  -> detect bad heads
  -> edit prompt-side cached V
  -> normal decoding
```

IHDecがdecode distributionを逐次補正するのに対し、V-Steerはprefill後のcache stateを一度補正する。

## Instructional Segment Embeddingとの関係

[Instructional Segment Embedding](2024-2410.09102-instructional-segment-embedding.md)はsource / privilege embeddingをtraining時からtoken representationへ追加する。

V-Steerはarchitectureやtraining dataを変更せず、既存modelのinternal contributionをinference時に再重み付けする。

## Instruction Hierarchy / HIPOとの関係

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)や[HIPO](2026-2603.16152-hipo.md)はtraining objectiveによってpriority behaviorを学習する。

V-Steerはpost-hoc correctionなので、training-based hierarchy modelにも追加可能である。

```text
training:
  learn hierarchy

V-Steer:
  repair residual internal imbalance
```

というDefense-in-depthが考えられる。

## Prompt Injection / Adaptive Attack

V-Steerはlower-priority spanがprivileged spanより強く寄与するfailureを対象とするためprompt injectionと関連する。

ただし[PISmith](../Attack/2026-2603.13026-pismith.md)や[The Attacker Moves Second](../Attack/2025-2510.09023-attacker-moves-second.md)のようにV-SteerのDLA/head selection/cache editing自体を知ったDefense-aware attackerで最適化した評価ではない。

adaptive attack robustnessは未確立である。

## Limitations

- open-weight / internal-state accessが必要で、closed APIへ直接適用できない。
- privileged / conflicting span boundaryを把握する必要がある。
- DLAはcausal attributionそのものではない。
- first-token attributionが全decode trajectoryを完全に代表する保証はない。
- aggressive steeringではMMLU等general capabilityが低下する。
- tool-use / indirect injectionでは改善が限定的なsettingがある。
- adaptive white-box attackへのformal robustness guaranteeはない。
- cache formatやGQA implementationに依存する実装上の考慮が必要。

## LLM Model Security Taxonomyでの位置づけ

```text
Training-time:
  Instruction Hierarchy
  ISE
  HIPO
       ↓
Inference-time:
  IHDec
    distribution correction

  V-Steer
    KV Value-cache correction
```

Instruction Hierarchy Defenseを**KV cache intervention**へ拡張した手法として位置づけられる。

## 実装・研究上の示唆

V-SteerはInstruction Hierarchyとefficient inferenceを直接結び付ける。

特に、

1. prefill時だけimportance / attributionを計算
2. selected layer/head/tokenのVだけ編集
3. edited KVをdecodeで再利用
4. fused attention fast pathを維持

という構成はserving-friendlyである。

今後はadaptive attackerがDLA head selectionを欺けるか、partial cache editingをbatch serving / paged KV cacheへどう組み込むか、training-based hierarchyと組み合わせたときの相乗効果が重要になる。
