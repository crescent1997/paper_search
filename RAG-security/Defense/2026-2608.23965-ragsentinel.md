# RAGSentinel: Certifiable Geometric Consensus for Robust Retrieval-Augmented Generation

> retrieved documentsをtext-level heuristicで判定するのではなく、surrogate encoder上のquery-conditioned hidden-state geometryへ写像し、benign majorityが形成するgeometric consensusから外れるdocumentsを除去するRAG poisoning defense。deployed generatorへの追加callを増やさず、一定のhonest-majority / separation条件下ではpoison-free contextを保証できる点が特徴。

## 概要

RAG knowledge poisoningでは、attackerがknowledge baseへ少数のadversarial documentsを挿入し、target queryに対してそれらをretrieveさせることでgeneratorを誤誘導する。代表的な[PoisonedRAG](../Attack/2024-2402.07867-poisonedrag.md)系attackでは、retrieverとの高いsemantic similarityとmalicious answer payloadを同時に満たすdocumentsを作る。

RAGSentinelは、poisoned documentの表面的な語彙やgeneratorによるself-verificationではなく、**queryをdocumentと組み合わせたときにencoder representationがどの方向へ変位するか**を見る。benign evidenceはqueryに対してある程度整合したrepresentation shiftを形成する一方、target answerへ強制的に誘導するpoisonはそのconsensusから外れやすい、という仮説を利用する。

## 問題設定 / Threat Model

attackerはRAG knowledge baseへpoisoned documentsを挿入できる。query、retriever、deployed generator、defense mechanism自体を書き換える権限は持たない。

defenderはdeployed LLMをblack-boxとして利用できる一方、別途用意したsurrogate encoderにはwhite-box accessを持つ。したがってgenerator内部hidden statesを要求せず、比較的小さいencoderでfiltering signalを計算できる。

重要な仮定は、retrieved top-kに含まれるpoisoned documents数が半数未満、すなわち **honest majority** が存在することである。保証はこの条件に依存する。

## 先行研究からの改善点

Poisoning defenseには、generatorへ複数回問い合わせてconsistencyを見る方法、document-level trust scoring、prompt-based verification、robust aggregation等がある。しかしLLM verificationを多数回行う方式はlatency/costが大きく、LLM自身がpoison payloadへ影響される可能性もある。

RAGSentinelはdeployed LLMではなく独立surrogate encoderのrepresentation geometryを使う。このためgeneratorへの追加verification callを必要とせず、**retrieval後・generation前**にcontextをsanitizeする。

またheuristic filteringだけでなく、benign cluster radius、poison separation、honest-majorityという明示的条件からcertifiable filtering theoremを与える点が主要な差である。

## Method / Algorithm

### 1. Query-conditioned residual

queryのみをsurrogate encoderへ入力したhidden representationを $h_0$、queryとretrieved document $d_i$ を組み合わせたrepresentationを $h_i$ とする。

各documentがquery representationへ与える変化を

```
δ_i = h_i - h_0
```

として表現する。

絶対hidden stateではなくqueryからの差分を見ることで、query自体に由来する共通成分を減らし、document-specific responseを抽出する。

### 2. Adaptive dimension selection

全hidden dimensionsを同等に扱うと、queryと無関係なnoise dimensionsがdistanceを支配する。

そこでretrieved set内で変動が大きいdimensionsをMedian Absolute Deviation (MAD)等のrobust statisticsで選択し、そのqueryでdocumentsを区別するのに有効なsubspaceへ射影する。

### 3. Norm clipping

極端なrepresentation magnitudeを持つpoisonがcentroid / distance computationを支配しないようresidual normをclipする。

### 4. Topic-direction removal

benign documentsであってもquery topicに共通する大きなdirectionを持つため、そのままでは全documentsが類似して見える。

retrieved residualsの共通mean/topic directionを推定して差し引き、残差 $z_i$ を作る。これにより「同じtopicだから近い」というsignalより、documentがqueryへ与える個別のsemantic perturbationを強調する。

### 5. Geometric-median anchor

残差集合の中心には通常meanではなくgeometric medianを使う。

honest majorityが存在すれば、少数のpoisoned pointsによる中心移動を抑えられるByzantine-robust estimatorとして機能する。

各documentについてanchorからのcosine distanceをglobal anomaly signalとして計算する。

### 6. Local consistency

global anchorだけではbenign evidenceが複数semantic modesを形成する場合に誤検知し得る。

そこでnearest neighborsとのlocal geometric consistencyも計算し、global consensus scoreとadaptiveに合成する。poisonがanchorへ近づこうとしても、周辺benign pointsとの局所関係が不自然ならscoreが悪化する。

### 7. Adaptive majority radius

distance distributionからbenign-majority radiusを推定し、最終的に低risk側の最大 $\lceil k/2\rceil$ documentsをtrusted contextとして残す。

このcontextだけをdeployed generatorへ渡す。

計算量の中心はretrieved documentsに対する **k+1 surrogate forward passes**で、deployed LLMは通常通り1回だけ呼ぶ。

## Certifiable Robustness

理論解析では、概ね以下を仮定する。

- poison数 $k' < k/2$
- benign residualsがbounded clusterを形成
- poisoned residualsとbenign consensusの間に十分なseparationがある
- global/local consensus score gapがadaptive radiusの変動を上回る

これらの条件下では、selected trusted setが $\lceil k/2\rceil$ 件のbenign documentsのみから構成されることを示す。

保証はattack名そのものに依存せずrepresentation geometryの条件で書かれているため、未知attackにも条件が成立すれば適用できる一方、条件を破るadaptive attackには保証されない。

## Experiment Setup

### Datasets

- Natural Questions (NQ)
- HotpotQA
- MS-MARCO

各datasetから100 queriesを用いる。

### Retrieval

- Contriever
- default top-k = 10

retriever variationも追加評価する。

### Generator

- Mistral-7B
- Llama-3.1-8B
- Qwen-2.5-7B

### Surrogate

defaultではBGE-M3を用い、別encoderへのtransferも評価する。

### Attacks

- PoisonedRAG
- PIA
- Adversarial Decoding
- mixed attacks
- adaptive geometric attacks

### Baselines

- RobustRAG
- InstructRAG
- AstuteRAG
- TrustRAG
- CrAM

主metricはAttack Success Rate (ASR)、clean/answer utility、runtime。

## Main Results

Llama-3.1-8B + PoisonedRAGでは、undefendedからRAGSentinel適用後のASRが、

- NQ: **0.38 → 0.03**
- HotpotQA: **0.51 → 0.06**
- MS-MARCO: **0.32 → 0.05**

へ低下する。

Qwen-2.5-7Bでも、

- NQ: **0.39 → 0.06**
- HotpotQA: **0.61 → 0.11**
- MS-MARCO: **0.34 → 0.09**

となり、generatorを跨いで効果が維持される。

## Transferability / Robustness

surrogate encoderやretrieverを変更してもASRは概ね0.1前後以下に維持され、特定encoder/retrieverへの強いoverfittingではないことを示す。

複数attackを混在させるmixed-attack settingでも全settingでASRは0.12未満。

adaptive attackerとして、

- anchor mimicry
- norm-boundary attack
- subspace camouflage

を評価する。HotpotQAでは標準PoisonedRAGに対するASR約0.08から最大約0.11まで上昇するが、大幅な破綻には至らない。

ただしattackerがsurrogate encoderそのものへwhite-box accessを持ち、representation geometryを直接optimization objectiveへ含める完全adaptive settingはより強い脅威となる。

## Runtime

NQの代表例では、

- Vanilla RAG: **0.49 s**
- RAGSentinel: **0.99 s**
- AstuteRAG: **2.29 s**
- RobustRAG: **3.15 s**

程度。

surrogate forwardを追加するためVanillaよりは遅いが、LLMを複数回呼ぶverification defenseより軽い。

## Limitations / 成立条件

最大の制約はhonest-majority assumptionである。retrieved top-kの半数以上をpoisonが占有すれば、geometric median自体がbenign consensusを表さなくなる。

またcertificationは「poisonというラベル」に対する無条件保証ではなく、benign compactnessとpoison separationがrepresentation spaceで成立する場合の保証である。

surrogate encoderをattackerが正確に知りwhite-box optimizationできる場合、benign geometryを模倣するpoisonを構築できる可能性がある。

さらにmulti-hop QAでは正しいevidence自体がsemanticに多様で、単一consensusから離れるbenign documentを除去するriskがある。

## RAG Security Taxonomyでの位置づけ

```
Knowledge poisoning
  PoisonedRAG / PIA / adaptive poisoning
        ↓
Post-retrieval sanitization
  heuristic / LLM verification
        ↓
Representation-space robust filtering
  RAGSentinel ← 本論文
```

knowledge-base extractionを防ぐ[RAGFort](2025-2511.10128-ragfort.md)や[CanaryRAG](2026-2604.10717-canaryrag.md)とはconfidentiality/integrityの軸が異なる。RAGSentinelは主に**attacker-controlled corpus contentがgeneratorへ届くことを防ぐintegrity defense**である。

## 実装・研究上の示唆

興味深い点は、RAG poisoning defenseをtext classifierとしてではなくByzantine-robust aggregationに近い問題として扱ったことである。

retrieved setにhonest majorityが期待できるdeploymentなら、独立encoderによるrepresentation-level consensusはLLM judgeより低costなpre-generation gateになり得る。

一方で今後重要なのは、defense surrogateを知るattackerがrepresentation-space separation条件そのものを崩せるか、またtop-k majorityをpoisonで占有するretrieval attackと組み合わせた場合にどうなるかである。
