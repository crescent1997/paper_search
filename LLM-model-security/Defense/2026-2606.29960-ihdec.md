# IHDec: Divergence-Steered Contrastive Decoding for Securing Multi-Turn Instruction Hierarchies

## 概要

IHDecは、Instruction Hierarchyを**trainingではなくdecoding時に強制する**手法である。

single-turnではsystem > user等のpriorityを比較的守れるmodelでも、conversationが長くなるとrecentなuser / assistant historyの影響が強まり、古いhigher-priority system instructionの影響が弱くなる。論文はこの現象を **Role-Influence Inversion** として分析する。

IHDecは各generation stepでroleごとのcounterfactual next-token distributionを比較し、lower-priority roleの影響がhigher-priority roleを上回ったtoken位置を検出する。その位置だけcontrastive decodingでlogitを補正し、higher-priority instructionへgenerationを戻す。

## 問題設定 / Threat Model

contextには異なるpriorityを持つroleが存在する。

```text
higher priority:
  system / developer instruction

lower priority:
  user instruction
  conversation history
  tool / external content
```

特にmulti-turnでは、higher-priority instructionがcontext前方へ遠ざかる一方、lower-priority instructionはgeneration位置に近い。

attackerは後続turnでconflicting instructionを繰り返す、あるいはprompt injectionを挿入することで、modelのgenerationをhigher-priority policyから逸脱させられる。

IHDecはmodel weightsを変更せず、inference時のnext-token distributionを監視・補正する。

## Role-Influence Inversion

論文の中心的観察は、role hierarchyがmodel内部で常に固定的に維持されているわけではないことである。

multi-turn contextが進むと、

```text
Influence(lower-priority role)
    >
Influence(higher-priority role)
```

となるtoken位置が増え、behavioral hierarchyが逆転する。

重要なのは単にsystem promptへのattentionが小さくなるという説明ではなく、**各roleを除いたcounterfactual distributionがnext-token predictionをどれだけ変えるか**としてrole influenceを測る点である。

## Method / Algorithm

### Counterfactual Contexts

通常contextを (C) とする。

IHDecはroleをmask / removeしたcounterfactual contextを作る。

- (C^{-H}): higher-priority roleの影響を除いたcontext
- (C^{-L}): conflicting lower-priority roleの影響を除いたcontext

それぞれからnext-token distributionを得る。

[
p(y_t|C),quad
p(y_t|C^{-H}),quad
p(y_t|C^{-L})
]

### Role Influence via Divergence

roleを除いたときdistributionが大きく変化するほど、そのroleが現在のgeneration decisionへ強い影響を与えていると考える。

distribution差はJensen-Shannon divergenceで測る。

[
I_H(t)
=
JSleft(
p(cdot|C),
p(cdot|C^{-H})
ight)
]

[
I_L(t)
=
JSleft(
p(cdot|C),
p(cdot|C^{-L})
ight)
]

ここで (I_H) はhigher-priority role、(I_L) はlower-priority roleのinfluenceを表す。

### Violation Detection

通常のhierarchyならhigher-priority roleのconstraintがgenerationを支配すべきである。

そこで、

[
I_L(t) > I_H(t)
]

のようにlower-priority influenceがhigher-priority influenceを上回る状態をpriority violationのsignalとして利用する。

### Divergence-Steered Contrastive Decoding

violationを検出した場合だけlogitを補正する。

直感的には、

- higher-priority roleを除くと強くなるtokenを抑制
- lower-priority conflicting roleを除くと強くなるtokenを促進

する方向へcontrastive scoreを作る。

通常tokenではbase distributionをそのまま利用し、priority inversionが観測された位置だけinterventionする。

```text
normal decoding
      ↓
measure role influence
      ↓
lower > higher ?
   /          \
 no           yes
 |             |
base        contrastive
decode      correction
```

このconditional interventionがgeneral instruction-following degradationを抑える。

## Training-free Defenseとしての特徴

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)、[IH-Challenge](2026-2603.10521-ih-challenge.md)、[HIPO](2026-2603.16152-hipo.md)等はtrainingによってhierarchy followingを改善する。

IHDecはweightsを更新しない。

```text
training-time:
  learn hierarchy behavior

IHDec:
  detect hierarchy violation
  during generation
  and repair locally
```

したがって既存modelへpost-hocに追加できる。

## Multi-turn Evaluation

single-turn benchmarkだけではなく、conversation turnが増えた場合のhierarchy degradationを評価する。

IHEval系のhierarchical conflictをmulti-turnへ拡張し、higher-priority instructionを保持したままlower-priority conflicting turnを追加する。

vanilla modelではturn数増加に伴いpriority followingが悪化するが、IHDecはrole-influence inversionを検出して補正することで性能低下を抑える。

## Main Results

代表的なLlama-3.1-8B-Instructのmulti-turn conflict settingでは、IHDecが約50.68%のhierarchy-following performanceを示し、ISEの約12.60%を大きく上回る結果が報告される。

複数model / settingを通じても既存hierarchy Defenseに対する改善を示す。

重要なのは、training済みmodelをさらにfine-tuneした結果ではなく、同一modelへinference-time decoding controlを追加して改善している点である。

## General Capability / Over-intervention

priorityを常時system側へ強くbiasすると、benign user instructionへのhelpfulnessが低下する。

IHDecはdivergenceによってviolationを検出した場合だけ介入するため、通常turnではbase decodingに近いbehaviorを保つ。

MT-Bench-101ではgeneral response qualityへの低下が小さいことを報告する。

これは、

```text
always enforce stronger system bias
```

ではなく、

```text
detect → intervene only when necessary
```

という設計の利点である。

## Prompt Injection Evaluation

prompt-injection settingでもhierarchy followingを評価する。

IHDecはconflicting lower-priority instructionの影響がhigher-priority instructionを上回るtokenを補正し、vanilla modelや比較Defenseよりrobustnessを改善する。

一方、報告される性能は完全防御には遠く、成功率が約半分程度に留まるsettingもある。

したがってIHDecを「prompt injectionを解決したDefense」と解釈するのではなく、**multi-turn hierarchy failureをtraining-freeに軽減するDefense**と位置づけるべきである。

## Model Scaling

Qwen3系列ではmodel sizeを4B / 8B / 14B / 32Bと増やした場合の挙動も分析する。

vanillaでは大きなmodelほどlower-priority instructionにも強く従えるため、conflict時にhierarchy performanceが単純には改善しないinverse-scaling的傾向が現れる。

IHDecを適用すると大きいmodelほど補正後の改善が大きくなる。

これはcapacityそのものではなく、

```text
strong instruction-following capability
        +
correct privilege steering
```

が重要であることを示唆する。

ただしQwen3系列での観察を一般的scaling lawとして扱うべきではない。

## Instructional Segment Embeddingとの関係

[Instructional Segment Embedding](2024-2410.09102-instructional-segment-embedding.md)はsystem / user / data等のsource identityをlearnable embeddingとしてtokenへ追加する。

```text
ISE:
  explicitly inject privilege information
  into model representation

IHDec:
  infer realized role influence
  from next-token distributions
  and correct decoding
```

という違いがある。

ISEはarchitecture / training側、IHDecはinference側のDefenseである。

## HIPOとの関係

[HIPO](2026-2603.16152-hipo.md)はsystem complianceをCMDP constraintとしてtrainingする。

```text
HIPO:
  enforce hierarchy in optimization

IHDec:
  enforce hierarchy in decoding
```

であり補完可能である。

HIPO-trained modelでもmulti-turnでrole influenceが逆転するなら、IHDecを追加することでresidual failureを補正できる可能性がある。

## Reasoning Up / IH-Challengeとの関係

[Reasoning Up the Instruction Ladder](2025-2511.04694-reasoning-up-instruction-ladder.md)はconflictをexplicit reasoning taskとして解く。

[IH-Challenge](2026-2603.10521-ih-challenge.md)はadversarial / shortcut-resistant hierarchy training environmentを構築する。

IHDecはreasoning traceや追加training dataを必要とせず、generation distributionから直接hierarchy violationを検出する。

## Role Confusionとの関係

[Prompt Injection as Role Confusion](../Attack/2026-2603.12277-prompt-injection-role-confusion.md)はmalicious lower-priority contentがmodel内部でtrusted roleに近いrepresentationを獲得することをprompt injectionのmechanismとして分析する。

IHDecは別のobservableとしてnext-token distributionに現れるrole influenceを利用する。

```text
Role Confusion:
  diagnose latent role identity failure

IHDec:
  diagnose behavioral role influence inversion
  and correct output distribution
```

という対応になる。

## GCG / Optimization-based Attackとの関係

[GCG](../Attack/2023-2307.15043-gcg.md)はgradient accessを用いてadversarial suffixを最適化するwhite-box attackである。

IHDecの主評価はsemantic conflict / prompt injectionであり、IHDecのcounterfactual distributionsやcontrastive correctionを含めてend-to-endに最適化したGCG attackへのrobustnessを保証しない。

同様に、

- [Faster-GCG](../Attack/2024-2410.15362-faster-gcg.md)
- [SlotGCG](../Attack/2026-2606.05609-slotgcg.md)
- [The Attacker Moves Second](../Attack/2025-2510.09023-attacker-moves-second.md)

のようなDefense-aware adaptive attackは重要な追加評価になる。

## StruQ / SecAlign / Meta SecAlignとの関係

[StruQ](2024-2402.06363-struq.md)、[SecAlign](2024-2410.05451-secalign.md)、[Meta SecAlign](2025-2507.02735-meta-secalign.md)はtrusted/untrusted separationをtrainingによってmodelへ学習させる。

IHDecはsource separationを再学習せず、すでにmodel内部に存在するrole sensitivityをcounterfactual distributionから読み出してdecodingへ利用する。

そのためtraining-based robustnessとinference-time correctionのDefense-in-depthが可能である。

## Compute / KV-cache Cost

IHDecはbase next-token distributionに加えcounterfactual distributionを計算するため、naive実装では追加forward passが必要になる。

論文ではcounterfactual variantsをbatch化し、maskingとKV-cache reuseを利用してoverheadを抑える。

serving上は重要な点で、各generation stepで完全に独立した複数contextをゼロからprefillする設計ではない。

一方、standard greedy / sampling decodeよりcompute / memory overheadが増えること自体は避けられない。

## Limitations

- training-freeだが複数counterfactual forwardによるinference overheadがある。
- role removal / maskingが完全なcausal attributionを保証するわけではない。
- Jensen-Shannon divergenceはrole influenceのproxyでありformal privilege guaranteeではない。
- prompt injection robustnessは完全ではなく、残存failureが大きいsettingもある。
- Defense-aware GCG等のstrong white-box adaptive attackへの評価は限定的。
- multi-turn benchmarkが実運用agent conversationの全distributionを代表するとは限らない。
- modelがそもそもhigher-priority instructionを正しく理解していない場合、decoding correctionだけでは解決できない。
- closed APIではcounterfactual decoding / logits accessを実装できない場合がある。
- tool authorizationやdata-flow securityを保証するsystem-level Defenseではない。

## LLM Model Security Taxonomyでの位置づけ

```text
Training-time hierarchy
  Instruction Hierarchy
  ISE
  Reasoning Up
  IH-Challenge
  HIPO
        ↓
Residual multi-turn hierarchy failure
        ↓
IHDec
  inference-time detection
  + contrastive correction
```

Instruction Hierarchy Defenseをtraining-timeから**decoding-time enforcement**へ拡張した研究として位置づけられる。

## 実装・研究上の示唆

IHDecから得られる重要な示唆は、hierarchy robustnessをsingle-turn accuracyだけで測らないことである。

実運用ではsystem instructionはconversation開始時に置かれ、その後多数のuser / assistant / tool turnが続く。

したがって評価では、

1. turn depthを増やす
2. higher-priority instructionからのdistanceを増やす
3. lower-priority conflictを繰り返す
4. role influenceがいつ逆転するか測る
5. adaptive attackerがcorrection mechanism自体を狙う

必要がある。

またtraining-based DefenseとIHDecを組み合わせ、

```text
training:
  learn privilege hierarchy

decoding:
  monitor residual violations

system layer:
  enforce capability / authorization
```

という多層Defenseが自然である。
