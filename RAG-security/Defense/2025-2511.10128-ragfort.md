# RAGFort: Dual-Path Defense Against Proprietary Knowledge Base Extraction in Retrieval-Augmented Generation

> RAG knowledge-base stealingを「別topicへ移動してcoverageを広げるinter-class path」と「同一topic内部の詳細を繰り返し回収するintra-class path」に分解し、retrieval側とgeneration側を同時にhardeningする **RAGFort** を提案する。

## 概要

proprietary RAGではretrieval database自体が重要な知的財産となる。[Feedback-Guided Extraction / CopyBreakRAG](../Attack/2024-2411.14110-feedback-guided-extraction-copybreakrag.md) や [RAGCrawler](../Attack/2026-2601.15678-connect-the-dots.md) のようなattackは、black-box queryを繰り返すことで内部corpusを徐々にreconstructできる。

RAGFortはknowledge extractionを **inter-class** と **intra-class** の2 pathに分解し、それぞれContrastive ReindexingとConstrained Cascade Generationで抑える。単一stage defenseより大幅にChunk Recovery Rate (CRR)を低下させながらQA utilityを維持することを狙う。

## 問題設定 / Threat Model

victimはproprietary knowledge baseをdense retrieverで検索し、retrieved chunksをLLM generatorへ与える一般的なRAG systemである。attackerはblack-box query accessのみを持ち、内部corpus、embedding index、retrieval score、model parameterにはアクセスしない。多数のquery-response pairから元knowledge chunksを復元することが目的である。

防御対象にはRAG-Thief / CopyBreakRAG型adaptive extractionやWorm-Attack系attackが含まれる。queryをmalicious/benignに分類してblockするのではなく、RAG pipelineそのものを変更する。

## Attack Pathの分解

**Inter-Class Extraction** は現在のknowledge topicからsemanticに関連する別topicへ移動してcoverageを拡大する段階で、CopyBreakRAGのexplorationやRAGCrawlerのglobal planningに対応する。

**Intra-Class Extraction** は一度発見したsemantic cluster内部でqueryを変えながら複数chunkや細かなfactを回収する段階である。retrieval boundaryだけを強化しても、同じclusterからgeneratorが詳細を放出すればreconstructionは進む。

## 先行Defenseからの改善点

retrieval re-ranking / filteringは到達documentを変えるがgeneration leakageを直接解決せず、summarization / output transformationはverbatim leakageを減らしてもexplorationを止めない。

RAGFortの中心的な改善は、knowledge-base stealingを単一leakage eventではなく **explorationとexploitationの連続process** として扱うことにある。

[DP-SynRAG](2025-2510.06719-dp-synrag.md) がprivate corpusをDP synthetic corpusへ変換するdata-layer defenseなのに対し、RAGFortはoriginal KBを保持したままretrieval / generation runtimeをhardeningする。formal DP guaranteeではなくempirical extraction resistanceを提供する。

## Method / Algorithm

### 1. Contrastive Reindexing

knowledge chunksをembeddingし、HDBSCAN等でsemantic clusterへ分ける。cluster IDをpseudo-labelとしてsupervised contrastive objectiveでretrieval encoderを再学習し、同cluster embeddingを近づけ、異clusterを離す。

通常のembedding spaceにあるtopic間のsemantic bridgeを弱め、response中の関連概念を辿って別clusterへ移動するcrawler型attackのinter-class transition probabilityを下げる。学習後はKB全体を再embeddingしてindexを再構築する。

### 2. Constrained Cascade Generation

軽量draft modelとverifier modelを組み合わせる。draftがtoken / blockを提案し、verifierがdistributionを評価する。confidenceやdistribution ratioがconstraintを満たす場合だけdraft outputをacceptし、riskの高いpositionではverifier側のresidual distributionへfallbackする。

selectionはrejection budget付きoptimizationとして定式化され、近似rejection ruleのregret boundも議論される。retrieved textの忠実な逐語再現を抑えながら通常QAに必要なsemantic answerを維持することを狙う。

### 3. Dual-Path Combination

Contrastively Reindexed Retrieverでknowledge-space explorationを抑え、Constrained Cascade Generatorでlocal exploitationを抑える。片方だけではattack pathが残るため両moduleの組み合わせが重要となる。

## Experiment Setup

主なdatasetはHealthCareMagic、Enron Email、MathQA。generatorにはQwen-14B、DeepSeek-R1-Distill-Llama-8B、Gemma-3-27B等を使用し、dense retriever top-5を中心に評価する。attackにはRAG-Thief系knowledge extractionとWorm-Attackを利用する。

主指標は **Chunk Recovery Rate (CRR)** で、reconstructed chunkがoriginal chunkに対してROUGE-L > 0.5かつsemantic similarity > 0.85を満たす場合にrecoveredとする。通常QA accuracyとFLOPsも測定する。

## Main Results

無防御時CRRを1と正規化すると、全setting平均でRAGFortは約 **0.51×** まで低減する。re-ranking defenseは約 **0.91×**、summarization defenseは約 **0.87×** に留まる。

代表例ではHealthCareMagic + Qwen + RAG-Thiefが **57.16% → 27.96%**、Enronが **52.60% → 20.60%**、MathQAが **70.31% → 38.13%** へ低下する。

## Ablation

平均CRRはInter-class moduleのみ **0.75×**、Intra-class moduleのみ **0.83×**、両module **0.51×**。片側だけではもう一方のattack pathが残り、dual-path designが最も大きくrecoveryを減らす。

## Utility / Efficiency

防御によるanswer accuracy低下は概ね **2 percentage points未満**。cascade generationはsmall draft modelを利用するため、条件によってfull large-model generationよりFLOPsも削減する。HealthCareMagic + Qwenでは約 **38.03T → 19.40T** と報告される。

## Robustness / Defense Scope

RAG-Thief / CopyBreakRAG型adaptive extractionには設計上直接対応する。一方 [RAGCrawler](../Attack/2026-2601.15678-connect-the-dots.md) のglobal planning型attackに対してcontrastive reindexingがどこまで耐えるかは今後の重要な評価点である。

[Benchmarking Knowledge-Extraction Attack and Defense on Retrieval-Augmented Generation](../Benchmark/2026-2602.09319-benchmarking-knowledge-extraction-attack-and-defense.md) のような統一benchmarkと組み合わせればretrieval leakageとgeneration leakageを分離して比較できる。

## Limitations / 成立条件

Contrastive Reindexingはcorpusにsemantic cluster structureが存在し、HDBSCAN等で有用なpseudo-labelを作れることを前提とする。reindexingにはencoder trainingとKB全体の再embedding costも必要である。

評価attackは主にRAG-Thief系とWorm-Attackであり、IKEA型benign-query extraction、membership inference、prompt-injection based verbatim leakageなど全attack classへの万能防御ではない。

CRRはchunk-level thresholdに依存するため、短いPII、secret、ID、数値などの重大な漏洩を十分表さない可能性がある。またformal privacy guaranteeは持たない。

## RAG Security Taxonomyでの位置づけ

本論文は **Defense / confidentiality / knowledge-base extraction resistance / retrieval-generation dual-path defense** に位置づけられる。

CopyBreakRAGやRAGCrawlerがexploration能力を高める方向へ進むのに対し、RAGFortはそのattack processをinter-class / intra-classへ分解して両方をpipeline levelで抑える。

## 実装・研究上の示唆

knowledge-base stealing defenseでは単発responseのverbatim leakageだけでなく、attackerがquery sequenceを通じて「どこまで移動できるか」と「到達領域からどれだけ深く回収できるか」を別々に評価する必要がある。

今後はRAGCrawlerやIKEAなど、より強いadaptive / benign-looking attackとの直接比較、およびPIIやshort secret向けmetricとの併用が重要になる。
