# RetrievalAttention: Accelerating Long-Context LLM Inference via Vector Retrieval

> KV cacheをvector storageとして扱い、current Queryから重要K/VだけをCPU上のindexからretrieveする。SparQ/QUESTのquery-aware sparse accessを、**attention-aware ANN + CPU/GPU hierarchy**へ発展させた手法。

## 概要

long-context decodeではKV cache容量だけでなく、各generation stepで巨大なKVを読み出してattentionを計算するmemory trafficがbottleneckになる。

attention weightは実際にはsparseであり、current queryに対して重要なtokenは全contextのごく一部。しかし重要tokenはgeneration中に動的に変わるため、static evictionでは後で必要になるtokenを失う。

RetrievalAttentionは大部分のKVをCPU memoryへoffloadしてANNS indexを構築し、decode時にはcurrent Queryに関連するK/Vだけをtoken-levelでretrieveする。

中心的な問題は、通常のvector databaseと異なりAttentionのQとKが異なるprojectionから生成され、distributionが一致しないこと。off-the-shelf ANNSをそのまま使うと高recallのため大量のKey scanが必要になる。

そこでprefill中の実Q→K近傍関係を利用して、Query側distributionから見て探索しやすい**attention-aware vector index**を構築する。

## 問題設定

full attentionではcurrent Query qに対して全past Keyとのdot productを計算する。

実際にはattention massの大半を占めるcritical token subsetだけでoutputを近似できる。しかしcritical subsetはqueryごとに変化する。

論文の100K-token analysisでは、各queryで動的にtop-1000 tokenを選べばattention massの大部分を回収できる一方、あるqueryで選んだtoken setを後続queryへ固定するとcoverageが低下する。

したがって必要なのはstatic compressionではなく、

> **decode queryごとにcritical KVを高速に検索する仕組み**

である。

## なぜ通常のANNSでは不十分か

一般的なANN indexはdatabase vector同士のgeometryを使って構築される。

Attentionでは

- Query = hidden state × W_Q
- Key = hidden state × W_K

であり、異なるprojection matrixを通るためQとKのdistributionに大きなgapがある。

その結果、Key-Key近傍だけを基準に作ったIVF/HNSW等のindexをQueryが探索すると、本当に高attentionとなるKeyへ効率よく到達できない。

論文では高recallを得るためoff-the-shelf ANNSが数十%規模のKeyをscanする必要があるケースを示す。これではattention sparsityが1–3%程度でもsystem上のbenefitを活かせない。

## Attention-aware vector index

### Prefill時のQ→K関係

prefillではfull attention計算が行われるため、実際のQueryがどのKeyに高scoreを与えるかを観測できる。

RetrievalAttentionはこの情報を使い、各prefill Queryから近いKeyへのQ→K edgeを構築する。

### Key graphへのprojection

decode時には過去Query自体をindex nodeとして保持して探索するのではなく、Q→K relationをKey側へprojectionし、Query distributionから見て関連するKey同士が接続されるgraphを構築する。

この考え方により、通常のK→K geometryだけでは表現できないAttention特有の検索構造をindexへ埋め込む。

結果としてhigh recallに必要なscan ratioを大きく減らし、論文では**全KVの1–3%程度へのaccess**でnear-full-attention accuracyを実現する。

## CPU-GPU hierarchical KV placement

RetrievalAttentionはすべてのKVをGPUへ保持しない。

KVを概ね、

- predictable / static subset
- dynamic retrieval subset

へ分ける。

attention sinkやrecent sliding-window tokenのように高確率で必要になるKVはGPU上に保持する。

一方、大量のmiddle-context KVはCPU memoryへoffloadし、attention-aware ANNS indexへ格納する。

decode時には、

1. GPU上のstatic KV attention
2. CPU indexからcurrent Queryでcritical KVをretrieve
3. retrieved KVへのattention
4. 両attention resultをsoftmax normalizationを考慮してmerge

する。

CPU vector searchとGPU computationをoverlapさせることでPCIe/CPU overheadを隠す。

## QUESTとの差

[QUEST](2024-2406.10774-quest.md)もquery-aware accessだが、selection unitとsystem構成が異なる。

| | QUEST | RetrievalAttention |
|---|---|---|
| selection unit | page/block | token |
| metadata/index | per-page Key min/max | attention-aware ANN graph |
| storage | GPU KV中心 | CPU-GPU hierarchy |
| query dependence | 毎step | 毎step |
| retrieval precision | page内の不要tokenも読む | token-level |
| index challenge | page criticality | Q/K OOD |

QUESTはPagedAttentionと相性がよくselection overheadが小さい一方、1つのimportant tokenのためpage全体を読むread amplificationがある。

RetrievalAttentionはよりfine-grainedなtoken retrievalを狙う代わりに、ANN index construction/searchとCPU-GPU orchestrationが必要。

## SparQとの差

[SparQ Attention](2023-2312.04985-sparq-attention.md)はqueryの大きなdimensionだけで全Keyを粗くscoreし、top-k tokenをGPU memoryからselective fetchする。

RetrievalAttentionはKeyをCPU側vector indexへ置き、approximate nearest-neighbor searchそのものをattention-awareにする。

技術系譜は、

```text
SparQ              : reduced Query dimensions → token selection
QUEST              : page metadata → page selection
RetrievalAttention : attention-aware ANN → token retrieval from CPU
```

と整理できる。

## DuoAttentionとの差

[DuoAttention](2024-2410.10819-duoattention.md)はqueryごとにtokenを検索せず、offline calibrationでKV headsをRetrieval / Streamingへ分類する。

- DuoAttention: head axisを疎化
- RetrievalAttention: token axisをdynamic retrieval

という直交的な設計。

原理上はfull-history Retrieval Headsの内部へRetrievalAttention型vector searchを適用するような組み合わせも考えられる。

## Experiment Setup

Llama-3-8B等のlong-context modelを用い、RULER、∞-Bench、Needle-in-a-Haystack等でaccuracyを評価する。

system evaluationではRTX4090やA100を使い、

- exact KNN
- conventional ANNS
- static/sparse KV baselines

とdecode latency、GPU memory、search ratioを比較する。

training-freeでありmodel weightsの変更は不要。

## Main Results

RetrievalAttentionは**1–3%のKV access**でnear-full-attention accuracyを報告する。

RULERの代表的なLlama-3-8B評価ではFull Attentionに近いaverageを維持し、static streamingやaggressive evictionよりlong-range retrievalを大幅に保つ。

system面では128K contextの8B modelをsingle RTX4090 24GBでserve可能。

arXiv v3では128K contextで約**0.188 sec/token**を報告し、exact KNNに対して最大約4.9×、traditional ANNSに対して約1.98×のlatency reductionを示す。

NeurIPS 2025 final版ではsystem optimizationを反映した値として**0.107 sec/token**が報告されているため、version間の数値差に注意する。

## Ablation / analysis

### Dynamic vs static token selection

current Queryごとにcritical tokenを選び直すことが重要。固定token setではgenerationが進むにつれてattention targetが変化し、coverageが低下する。

### Conventional ANNS vs attention-aware index

通常のANNSはQ/K OODのため高recall時にscan ratioが大きい。

prefill Query情報をindex constructionへ利用することで、同等recallに必要なscan量を大幅に削減する。

### Retrieval ratio

retrieveするKVを増やすほどfull attention accuracyへ近づくが、CPU search、transfer、attention costが増える。

1–3%付近が論文で示される主要operating region。

## RetroInferへの技術系譜

RetrievalAttentionはKV cacheを単なるtensorではなく**vector retrieval system**として扱う発想を明確にした。

後続のRetroInferはこの方向をさらにsystem化し、長context LLM向けvector storage engineとしてindex update、storage hierarchy、retrieval execution等を統合する。

したがってrepository上では、

```text
RetrievalAttention
    ↓
attention-aware KV vector retrieval
    ↓
RetroInfer
    ↓
KV vector storage engine
```

という系譜で読むと分かりやすい。

## Limitations

1. CPU memoryには基本的にfull KVを保持するため、total host-memory capacityはcontext lengthに比例する。
2. prefill時にattention-aware index construction overheadが加わる。
3. CPU ANN searchとPCIe transferがsystem bottleneckになり得る。
4. fixed/reusable contextを前提とするsettingでindex amortizationが特に有利。
5. attentionが広く分散するhead/taskではretrieve ratioを増やす必要がある。
6. arXiv版とNeurIPS final版でsystem数値が更新されているため、比較時はversionを揃える必要がある。

## KV-cache taxonomyでの位置づけ

**access / query-aware token retrieval / vector-indexed KV / CPU-GPU hierarchical storage / training-free**。

KVを削除するcompressではなく、full KVを主にCPU側へ保持したまま、

> **current Queryに必要なKVだけをdecode時にretrieveしてGPUで使う**

ことが中心。

既存access系をselection axisで整理すると、

| Method | Access unit | Selection mechanism |
|---|---|---|
| SparQ | token | reduced Query dimensions |
| QUEST | page | Key min/max upper bound |
| DuoAttention | head/history | learned head role |
| RetrievalAttention | token | attention-aware ANN |

## まとめ

RetrievalAttentionはlong-context attentionをvector retrieval problemとして捉え、Q/K distribution mismatchに対応したattention-aware ANN indexとCPU-GPU co-executionを組み合わせる。

中心componentは、

| Component | Role |
|---|---|
| prefill Q→K relation | Query distributionをindexへ反映 |
| attention-aware graph | OOD下で高recallなANN |
| CPU KV storage | GPU memory footprint削減 |
| GPU static KV | sink/recent tokenを高速処理 |
| dynamic token retrieval | queryごとのcritical KV access |

1–3%のKV accessでnear-full-attention accuracyを維持し、128K contextの8B modelをsingle RTX4090でserveできることを示す。

SparQ/QUESTから続くquery-aware sparse accessを、**vector retrieval + heterogeneous memory system**へ進め、後続RetroInferへ直接つながる重要なhistorical paper。
