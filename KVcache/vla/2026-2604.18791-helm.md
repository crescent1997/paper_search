# HELM — Harness-Enhanced Long-horizon Memory for Vision-Language-Action Manipulation

- **arXiv**: [2604.18791](https://arxiv.org/abs/2604.18791)（2026-04-20）
- **一次資料**: [公式PDF本文・付録](https://arxiv.org/pdf/2604.18791)、[公式HTML全文](https://arxiv.org/html/2604.18791v1)
- **著者・所属**: Zijian Zeng（Tsinghua）、Fei Ding（Alibaba Group）、Huiming Yang（Tsinghua）、Xianwei Li（Bengbu University）— PDF冒頭確認。
- **Venue**: arXiv preprint。公式学会採択未確認。
- **Citation**: 7（mlsanity収録論文内、2026-10-28まで。1年以内の閾値1を満たす）。

## 1. 概要・問題設定

短期タスクに強いVLAでも、長い操作列では過去のサブゴール達成状態を忘れ、誤った行動を実行し、失敗後の状態から回復できない。著者は失敗を3つに分解する。

1. **Memory gap (FM)**：固定history windowから過去の達成状態が脱落し、終了済みサブゴールを再実行する。
2. **Verification gap (FV)**：把持失敗・到達不可能・誤対象などを行動前に検証しない。
3. **Recovery gap (FR)**：失敗後も壊れた状態で後続サブゴールを続け、連鎖的に失敗する。

OpenVLAのLIBERO-SPATIAL成功率91.2%に対しLIBERO-LONGは58.4%。historyを8→32に延長しても63.8%（+5.4pp）、64でも65.1%。単にKV cacheを長く保持してcontextを伸ばすだけでは、**検証と回復の制御構造**が欠けたままである、という問題設定。

## 2. 先行研究との差

- [MemoryVLA](2025-2508.19236-memoryvla.md)はperceptual-cognitive memory bankをVLA内部に統合し、時間的に重要な過去表現を検索する。HELMは**外部episodic store + action verifier + recovery harness**であり、モデルを凍結して包み込む設計。
- [TempoFit](2026-2603.07647-tempofit.md)は**layer-wise prefix K/Vを内部状態として履歴注入**する。HELMの`M={(key,value)}`はCLIP embeddingと画像・状態のレコードであり、**Transformer attention K/Vではない**。
- [ChainVLA](2026-2608.02326-chainvla.md)は統一実行状態で長時間サブタスクを連結する。HELMは失敗を予測して**rollback/replan**することが中核。
- 既存Reflexionは主に実行後の反省。HELMのSVは**実行前の失敗確率推定**で、過去履歴を条件にする。

## 3. 手法

### 3.1 EMM — Episodic Memory Module

Memory storeは

$$M=\{(k_i,v_i)\},\qquad k_i=\phi(o_i),\quad v_i=(o_i,g_i,\mathrm{status}_i,t_i,\delta_i).$$

- **key**: CLIP ViT-B/32で得る512次元のL2-normalized visual embedding。
- **value**: 画像keyframe、active subgoal、完了/失敗status、timestep、gripper poseやdepth由来のobject positionsの簡易state delta。
- **write**: subgoal完了、failure検出、または20 stepごとのcheckpoint。
- **retrieve**: 現在の $\phi(o_t)$ と過去keyのcosine similarityでtop-$k=3$ を選び、structured textに直列化してVLAの言語入力に追加。
- **容量/圧縮**: $N_{max}=50$ entries超でsubgoalごとの最新checkpointのみ残す。**過去の失敗・重要イベントが圧縮でどう保持されるかの厳密な容量対精度曲線は限定的**。

$
s_i = \frac{\phi(o_t)^\top k_i}{\|\phi(o_t)\|\,\|k_i\|},\qquad
I_t = \mathrm{TopK}_{i\in\{1,\ldots,|M|\}}(s_i,\,3),\qquad
M_t = \{(k_i,v_i)\mid i\in I_t\}.
$

これは「外部検索用key-value store」であって、LLMのKV cacheそのものの再利用ではない。memory retrievalがVLAの追加入力を増やすため、prefill計算は必ずしも減らない。

### 3.2 SV — State Verifier（追加学習が必要）

行動 $a_t$ を実行する前に、現在観測、提案行動、subgoal、episodic contextから

$$p_{\mathrm{fail}}=f_\psi(\hat o_t,a_t,g_t),\quad \hat o_t=[\phi(o_t);k_{top1}]\in\mathbb R^{1024}$$

を推定する。actionは256次元へ射影、subgoal textも256次元。MLP + BCE、positive class weight 4.0、Adam lr $10^{-4}$、50K rollout steps、**failure within 5 steps**を教師ラベルとする。単一A100 80GBで学習約2時間。

閾値 $\theta_v=0.65$ を超えると行動をそのまま実行せず、controllerにrecoveryを要求。メモリなしではSV AUROCが**0.847→0.791**に低下するため、verifierとmemoryの組み合わせが重要。

**実装上の要注意**：本文§4.3はMLPを`[1024→512→256→1]`と記述する一方、Appendix A.2は`[1024,512,256,128,1]`と記載しており**層構成に不整合がある**。再現時は実装または著者確認が必要。

### 3.3 HC — Harness Controller

タスク指示をsubgoal stackへ分解し、`retrieve → propose → verify → execute/recover` を繰り返す。失敗時は最後の成功checkpointへ戻る**rollback recovery**、または現在の壊れた状態から新しい計画を作る**forward recovery**。最大3回再試行。完了検出器も別途学習する。不可逆操作のある実機ではrollbackの実行可能性が重大な制約。

## 4. Experiment Setup

- **VLA**: 凍結OpenVLA-7B、追加でOcto-Baseを検証。EMMはCLIP ViT-B/32。SVとcompletion detectorは学習。
- **LIBERO-LONG**: 10 tasks、各5–6 subgoals、500 evaluation episodes/seed、3 seeds。成功率TSRとsubgoal completion rate SCR。
- **CALVIN ABC→D**: 未知環境の連続指示、最大5のcompleted chains、1,000 chains/seed。
- **LIBERO-Recovery**: LIBERO-LONGのsubgoal境界で物体位置±5cmまたはgripper state flipを無通知で挿入。300 perturbed episodes/seed。RSRは**摂動episodeの最終タスク完遂率**。
- **比較baseline**: OpenVLA H=8/32/64、oracle subgoal memory、rule verifier、5-model ensemble、同50K rollout budgetのLoRA、Reflexion、HELM-Fwd、Octo。
- **計算**: A100 80GB。SV推論の追加コスト**約12ms/step、backbone比15%**。GPU memory総量、throughput、Hzは未報告。

## 6. 主要ablation / メモリ容量トレードオフ

### 6.1 Component ablation（Table 3）

| Variant | TSR | RSR | TSR低下 |
|---|---:|---:|---:|
| HELM full | 81.5 | 54.2 | — |
| w/o EMM | 70.3 | 38.4 | -11.2pp |
| w/o SV | 73.1 | 41.7 | -8.4pp |
| SV without memory context | 79.2 | 50.1 | -2.3pp |
| w/o rollback | 75.2 | 23.1 | -6.3pp |
| w/o EMM & SV | 62.4 | 15.2 | -19.1pp |

Rollbackの有無でRSRが54.2→23.1へ大きく変化し、単純なmemory追加よりも**実行ループ設計**の重要性がわかる。

### 6.2 Retrieval・write・capacity（Table 4等）

- Random retrieval: TSR64.3、Prec@1 31.2。
- Recency retrieval: TSR71.4、Prec@1 58.7。
- **CLIP semantic retrieval**: TSR81.5、Prec@1 78.3。
- Fine-tuned retriever: TSR82.1、Prec@1 81.6。CLIPとの差は+0.6ppで、追加retriever学習の価値は限定的。
- Top-kの比較: $k=1$→77.2%、$k=3$→81.5%、$k=5$→81.8%。上限5は0.3ppしか増えず、**k=3を採用**。
- SV failure label horizon: 1-step AUROC0.712、5-step0.847、10-step0.831。遠すぎる予測では教師が曖昧。
- Subgoal oracle decomposition: 84.2%（+2.7pp）。自動分解失敗4.3%。
- Memory writeはsubgoal completion/failure/20-step checkpoint、最大50 entries。**50を超えた際のforgetting policyと長期記憶品質の詳細ablationは十分ではない**。

## 7. Limitations / 注意点

1. **KV cacheを高速化しない**：CLIP-indexed外部memoryをretrieveして文字列化し、VLAへ追加する。KVの再利用・eviction・prefill削減はない。検索・検証・recoveryがむしろ計算を追加する。
2. **実機未評価**：実験はLIBERO/CALVINのsimulationのみ。rollbackは不可逆物理操作で成立しない場合があり、forward recoveryはTSR76.3%、RSR38.7%と低い。
3. **SV追加学習**：50K steps/環境、A100約2h。zero-shot適用ではない。domain shiftへの頑健性は未検証。
4. **latency**：SV 12ms/step（15% overhead）のみ。CLIP encode、memory retrieval、追加VLA prompt、recovery再試行を含むend-to-end episode wall time、GPU peak memory、throughput、control Hzは報告不足。
5. **再現性**：本文と付録でMLP層構成に差。LIBERO-Recovery protocolは詳細記載されるが、GitHub公開URLは未確認。本文の「code will be released upon acceptance」は公開済みを意味しない。
6. **失敗taxonomy**：200 episodes中83 failuresを人手分類、κ=0.81。FM41%、FV33%、FR26%（複数ラベル可）。別のreal-world failure distributionへの一般化は未知。

## 8. Taxonomy / 研究上の位置付け

- **Primary**: `KVcache/vla/` — external episodic memory, memory retrieval/write/consolidation, failure verification, long-horizon recovery。
- **KV reuseとの相違**: [VLA-Cache](2025-2502.02175-vla-cache.md)は隣接観測のKV再計算を省く。HELMは履歴をCLIP-indexed keyframeとして保存し、**次の行動の意味的妥当性と失敗時の復旧**を補う。効率目的より成功率目的。
- **研究接点**: [TempoFit](2026-2603.07647-tempofit.md)の内部K/V temporal memoryや[NativeMEM](2026-2607.06678-nativemem.md)の1-frame-1-token historyに、HELMの「どの記憶を残すか」「何を失敗と判断するか」を統合すれば、限られたmemory budgetでの長時間制御の研究につながる。ただしcontrol latencyと安全性を同時評価する必要がある。
