# HIPO: Instruction Hierarchy via Constrained Reinforcement Learning

## 概要

HIPOはHierarchical Instruction Following (HIF)を、複数objectiveの重み付き最適化ではなく**Constrained Markov Decision Process (CMDP)** として定式化する。

従来のSFT / RLHF / DPOでは、system instructionへのcomplianceとuser utilityを同じtraining objectiveの中で改善することが多い。しかしsystemとuserがconflictした場合、本来必要なのは「systemを少し重く評価する」ことではなく、

```text
system constraintを満たすことが必須
        ↓
そのfeasible region内でのみ
user utilityを最大化
```

という非対称なpriorityである。

HIPOはこの非対称性をoptimization algorithmそのものへ組み込み、system complianceを明示的constraintとして扱うprimal-dual safe RLを提案する。

## 問題設定 / Threat Model

LLMにはsystem promptとuser promptが同時に与えられる。

aligned caseでは両者を満たせるが、conflicting caseではuser instructionがsystem constraintと両立しない。

securityの観点では、

```text
System:
  safety / application policy / behavioral constraint

User:
  benign request
  or conflicting / adversarial request
```

となり、modelはhigher-priority system constraintを維持しながら、可能な範囲でuser utilityを最大化する必要がある。

HIPOは主にsystem-userの2-tier hierarchyを扱い、tool / external dataを含む任意の多段authority graphを直接モデル化するものではない。

## 先行研究からの改善点

### SFT

SFTではsystem-compliant responseを選別して模倣させることができる。しかしこれはtraining data上のbehavioral correlationを学ぶだけで、

```text
system instruction > user instruction
```

というpriority asymmetryをoptimization constraintとして保証しない。

### RLHF / DPO

通常のpreference optimizationではhelpfulness、安全性、system compliance等が1つのscalar objectiveへ統合される。その場合、user utilityの改善と引き換えにsystem complianceを多少犠牲にするsolutionもoptimization上許容される。

HIPOはsystem complianceをobjectiveから**constraintへ格上げ**することでこの問題を避ける。

### The Instruction Hierarchy

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)はsynthetic conflict dataを用いてhigher-priority instructionを優先するbehaviorを学習する代表的研究である。

HIPOの差分は、priorityをtraining exampleの構造だけで表現するのではなく、**RL optimizationのfeasible setとして明示する**点にある。

## CMDP Formulation

system complianceの期待rewardを (J_{sys})、user utilityを (J_{user}) とすると、HIPOの目的は概念的に、

[
max_	heta J_{user}(	heta)
]

subject to

[
J_{sys}(	heta) ge 	au
]

となる。

(	au) は要求するsystem compliance thresholdである。

これはweighted sum

[
alpha J_{sys} + eta J_{user}
]

とは本質的に異なる。weighted sumではsystem complianceとuser utilityがtrade-off可能だが、CMDPではthresholdを下回るpolicyはfeasible solutionではない。

## Method / Algorithm

### Separate Rewards

responseに対して、

- system instructionへのcompliance reward
- user instructionへのutility reward

を別々に評価する。

これにより「userには役立つがsystemを破るresponse」と「systemを守りながら可能な範囲でuserへ応えるresponse」を区別する。

### Group-relative Advantage

複数candidate responseをsampleし、system reward / user rewardそれぞれについてgroup-relativeなadvantage signalを構築する。

GRPO系trainingと同様に、同一promptに対するsample群の相対品質を利用することでcriticへの依存を減らす。

### Primal-Dual Optimization

constraint付きoptimizationをLagrangianで扱う。

概念的には、

[
L(	heta,lambda)
=
J_{user}(	heta)
+
lambda (J_{sys}(	heta)-	au)
]

の形になり、(lambda) がsystem constraint violationに応じて動的に変化する。

system rewardがthresholdを下回ると(lambda) が増え、system compliance改善へのoptimization pressureが強くなる。

逆にconstraintが十分満たされると(lambda) は低下し、user utilityの改善へtraining capacityを使える。

論文ではsystem rewardのEMAを用いてdual variableを安定的に更新し、target thresholdとして0.7を使用する。

## なぜPriorityを表現できるのか

通常のmulti-objective RLでは、

```text
system reward ↔ user reward
```

が同じoptimization levelにある。

HIPOでは、

```text
system compliance
    ↓ mandatory constraint

user utility
    ↓ optimize only inside feasible region
```

となる。

このalgorithmic asymmetryが、system/user roleのpriority asymmetryに対応する。

## Experiment Setup

複数architecture / model sizeで評価する。

代表的model familyは、

- Qwen3
- Phi
- Llama

であり、SystemCheckのhierarchical prompt pairsを用いてaligned / conflicting instructionを評価する。

比較対象には通常のBase / SFT / DPOに加え、hierarchy-aware baselineを含む。

主metricは、

- system compliance
- user utility
- aligned / conflicting settingでのtrade-off
- general capability
- safety hierarchyへのgeneralization

である。

## Main Results

HIPOは特にconflicting settingで、system complianceを設定したthreshold付近以上へ維持しながらuser utilityを高める。

SFT / DPO等ではuser utility改善に伴ってsystem complianceが崩れる場合があるのに対し、HIPOはconstraint violation時にdual variableが増加するため、training dynamics自体がsystem complianceを回復させる。

aligned caseではsystem/user間に本質的trade-offがないため、両方のmetricを同時に改善できる。

## Training Dynamics

論文ではLagrange multiplier (lambda) とsystem reward EMAのtraining trajectoryを分析する。

初期trainingではsystem rewardが0.7 thresholdを下回るため(lambda) が増加する。complianceが改善してthresholdを安定的に満たすようになると、(lambda) は低下し最終的には0付近まで戻る。

これは固定penalty coefficientと異なり、必要な時だけpriority enforcementを強めるadaptive mechanismとして機能する。

## Generalization / Safety Evaluation

通常のhierarchical constraintだけでなく、safety system promptを与えたsettingでWildJailbreak / HarmBench系のattackに対するrobustnessも評価する。

HIPOはsystem-level safety constraintへのcomplianceを改善し、trainingで見たformat constraintだけをmemorizeしているわけではないことを検証する。

一方で、これはGCGのようなwhite-box adversarial suffix optimizationやDefenseを知ったadaptive attackerへのformal robustnessを意味しない。

## General Capability

MMLU-Redux等を用いてalignment trainingによる一般能力低下も評価する。

system complianceを強制するだけならuser requestを広く拒否するtrivial solutionがあり得るため、general capability / user utilityを同時に測ることが重要である。

HIPOはconstraintを満たした後にuser utilityを最大化するため、単純なover-refusalを避けることを狙う。

## Mechanistic Analysis

HIPO後のattention patternを分析すると、modelはuser側tokenだけでなく、context前方にある**long-range system instruction tokenへより多くattentionを割り当てる**ようになる。

これはarchitectureへ明示的なprivilege embeddingを追加した結果ではなく、constraint-aware RLから自発的に生じる。

[Instructional Segment Embedding](2024-2410.09102-instructional-segment-embedding.md)がsource privilegeをembeddingとして直接注入するのに対し、HIPOはoptimization objectiveからpriority-sensitive representationを誘導する点が対照的である。

## Reasoning Up the Instruction Ladderとの違い

[Reasoning Up the Instruction Ladder](2025-2511.04694-reasoning-up-instruction-ladder.md)はinstruction conflictをexplicit reasoning problemとして解き、verifiable reward / GRPOでpriority resolution能力を学習する。

HIPOは別方向から、

```text
Reasoning Up the Instruction Ladder
  how to reason about conflict

HIPO
  how to encode priority asymmetry
  into the optimization problem
```

を扱う。

両者を組み合わせ、explicit hierarchy reasoningを行いつつsystem complianceをCMDP constraintとしてtrainingする方向も考えられる。

## IH-Challengeとの関係

[IH-Challenge](2026-2603.10521-ih-challenge.md)はshortcut-resistantでprogrammatically gradeableなhierarchy taskとonline adversarial example generationを用いてRL trainingを強化する。

HIPOはtraining data generationより**optimization formulation**へ焦点を置く。

```text
IH-Challenge:
  better hierarchy training environment

HIPO:
  hierarchy-aware constrained objective
```

という補完関係にある。

## StruQ / SecAlign / Meta SecAlignとの関係

[StruQ](2024-2402.06363-struq.md)、[SecAlign](2024-2410.05451-secalign.md)、[Meta SecAlign](2025-2507.02735-meta-secalign.md)はtrusted promptとuntrusted dataの2-level separationを学習し、prompt injectionを防ぐ。

HIPOは特定のprompt/data delimiterに依存せず、higher-priority complianceをconstraintとして扱う一般的なoptimization principleを与える。

ただしSecAlign系が評価するGCG / adaptive prompt injectionに対しHIPOが同等のrobustnessを持つことは本論文だけからは保証できない。

## GCG / Adaptive Attackとの関係

[GCG](../Attack/2023-2307.15043-gcg.md)はwhite-box gradientを用いてadversarial suffixを最適化する。

HIPOの主評価はsemantic instruction conflict / safety hierarchyであり、GCGに対するcertified robustnessを与えるものではない。

また[The Attacker Moves Second](../Attack/2025-2510.09023-attacker-moves-second.md)が示すように、static attackでの改善はDefense-aware adaptive attackへのrobustnessを意味しない。

今後はHIPO-trained modelに対し、

- GCG / Faster-GCG / SlotGCG
- Role Confusion / priority spoofing
- adaptive prompt injection
- multi-turn system prompt extraction

を適用する評価が重要になる。

## Many-Tier Instruction Hierarchyとの関係

HIPOは主にsystem/userの2-tier settingを扱う。

[Many-Tier Instruction Hierarchy](../Benchmark/2026-many-tier-instruction-hierarchy.md)のようなarbitrary privilege tiersへ拡張する場合、

[
J_1 ge 	au_1,quad
J_2 ge 	au_2,quad ldots
]

のようなmulti-constraint CMDPへの拡張が考えられる。

ただしconstraint間自体がconflictする場合のlexicographic orderingをどうoptimizationへ埋め込むかは追加課題となる。

## Limitations

- 主評価はsystem/userの2-tier hierarchyで、developer/tool/external-dataを含む多段priorityは十分検証されていない。
- system reward自体はjudge/modeling errorを含み得るため、constraint化してもformal security guaranteeにはならない。
- threshold (	au) の選択がsecurity/helpfulness trade-offへ影響する。
- LLM-as-Judge型rewardがadversarial responseにrobustとは限らない。
- GCG等のwhite-box optimization-based attackに対する主要評価は限定的。
- adaptive attackerへのformal robustnessはない。
- trainingにRL samplingと複数reward evaluationが必要で、SFTよりcompute costが高い。
- model-level hierarchyはtool permissionやdata-flow authorizationの代替ではない。

## LLM Model Security Taxonomyでの位置づけ

```text
Behavioral hierarchy training
  The Instruction Hierarchy
        ↓
Reasoning / verifiable RL
  Reasoning Up the Instruction Ladder
  IH-Challenge
        ↓
Optimization-level hierarchy
  HIPO
  system compliance = CMDP constraint
        ↓
Potential extension
  multi-tier / adaptive-attack-aware constrained RL
```

Instruction Hierarchyを「training dataで覚えさせるrule」から、**optimization algorithmが守るconstraint**へ引き上げるDefenseとして位置づけられる。

## 実装・研究上の示唆

HIPOの重要な示唆は、priorityを単なるreward weightとして表現しないことである。

security-sensitiveなsystem instructionを扱う場合、

```text
maximize:
  helpfulness + α × safety
```

より、

```text
maximize:
  helpfulness

subject to:
  safety/system compliance >= threshold
```

というformulationの方がauthority structureを直接表現できる。

今後はmulti-tier CMDP、lexicographic constraints、adaptive attackerを用いたconstraint reward設計、architecture-level privilege signalとの併用が研究方向として考えられる。
