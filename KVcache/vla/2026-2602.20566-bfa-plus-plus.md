# BFA++ — Hierarchical Multi-View Visual Token Pruning

## 概要・問題設定
複数camera viewを利用するπ0/RDTなどのVLAでは、視野ごとに重要な領域が異なり、作業フェーズによって重要なcamera自体も変わる。画像のtokenを一律に減らすと、背景だけでなくgripperや操作対象の特徴も失われる。BFA++はview内（intra-view）とview間（inter-view）の重要度を教師ありで学習し、両者を使った二段階pruningを実施する。

## 先行研究との差
- [VLA-Pruner](2025-2511.16449-vla-pruner.md): action-aware pruningという問題意識は共通するが、BFA++は複数カメラの重要度を明示的に分離する。
- [SAFE-Pruner](2026-2605.29662-safe-pruner.md): 過去フレームのsaliency再利用とは異なり、オフラインの重要度アノテーションを学習して推定する。
- [VLA-Cache](2025-2502.02175-vla-cache.md): temporal KV reuseではなく、**現フレームのvisual tokenを入力前に捨てる**。
- [MEM](2026-2603.03596-mem.md): 過去のepisodic/semantic memoryを検索・保持するものではない。

## Method
### Offline importance annotation
Inter-view: viewごとの操作重要度をVLM annotation、bbox rule、または人手で推定。Intra-view: Grounding-SAMなどを使い、gripper・対象物に対応する領域をannotate。推論時に重いannotationモデルを走らせず、軽量predictorを使う。

### Importance predictors
各viewのCLS tokenからInter-IPでcamera重要度`S_inter[v]`を予測。個々のvisual tokenからIntra-IPで`S_intra[v,n]`を予測。まずview内で局所的に低スコアtokenを落とし、残りを`S_final[v,n]=S_inter[v]*S_intra[v,n]`でview横断ランキングしてさらに削減する。局所スコアには2D位置距離で重みづけする空間平滑化を適用する。単純に全tokenを一度にglobal rankingするとwrist viewが消えやすいという実験上の知見が二段階構造の動機。

### Training
`L_total = L_action + λ1 L_inter + λ2 L_intra`。追加のBCE教師損失で二つのimportance predictorをVLA本体とjoint post-trainingする。λ1=λ2=0.1。π0ではLLM入力前にtokenをprune（LLM内部でpruneするとKV cache構造を壊して遅くなるため）。RDTではDiT第2層でprune。従ってTransformer layer KVの再利用手法ではない。

## Experiment Setup
RoboTwinの8操作、RoboTwin2 OOD、実機5操作。π0は5000 steps、global batch 256、RDTは1200 steps、batch 128で同一データ・学習stepsを用いて比較。学習8×A100、推論1×RTX 3090。シミュレーションは各task 100 trials、実機は各task 20 trials。pruning ratio `[0.3,0.2,0.2,0.5]`、ε=0.01。比較: unpruned、DART、先行BFA。

## Main Results
### RoboTwin（論文Table I、平均successとFPS）
| Model | Mean success | Control frequency |
|---|---:|---:|
| π0 | 49.6% | 6.5 Hz |
| π0 + DART | 45.6% | 9.8 Hz |
| π0 + BFA | 52.4% | 11.1 Hz |
| **π0 + BFA++** | **58.3%** | **10.3 Hz** |
| RDT | 47.0% | 1.0 Hz |
| RDT + DART | 40.3% | 1.6 Hz |
| RDT + BFA | 48.9% | 1.7 Hz |
| **RDT + BFA++** | **56.5%** | **1.5 Hz** |

BFA++は非pruning baselineより速く高成功率だが、**BFAと比べるとFPSは少し低い**。単純に全baselineより速いという主張は不適切。

### 実機（論文Table II）
π0: 平均成功率27%・5.8Hz、π0+BFA:38%・10.1Hz、π0+BFA++:48%・9.4Hz。RDT baseline:23%・1.2Hz。実機評価は各task20回で、信頼区間の明示は確認できない。制御周期はモデル推論FPSであり、ロボット全体の閉ループ安全性を保証しない。

## Ablation（論文Table IV、π0・4 tasks）
| 方式 | Mean success | FPS |
|---|---:|---:|
| w/o Inter-IP | 55.8% | 10.8 |
| w/o Intra-IP | 54.0% | 11.0 |
| w/o Hierarchical | 56.5% | 10.4 |
| w/o Adaptive Weight | 60.8% | 10.4 |
| Adaptive Pooling | 56.0% | 11.9 |
| Random Drop | 53.5% | 11.5 |
| Online Drop | 50.0% | 1.3 |
| Adaptive Ratio Drop | 63.3% | 8.4 |
| **BFA++** | **63.8%** | **10.3** |

Inter-IP/Intra-IPの両方が有用で、online annotationは1.3Hzと非常に遅い。pruning率を上げると最初はノイズ除去で成功率も改善するが、過剰な削減では操作に必要なtokenを失い成功率が低下。adaptive ratioは固定比率よりFPSが下がる。Ablationは4 tasksの平均でありTable Iの8 tasks平均とは直接比較できない。

## Limitations
importance predictorの教師ラベル生成にbbox/segmentationやVLM等が必要で、training-freeではない。新しい物体やカメラ配置への分布外汎化には不確実性が残る。GPU memory・KV cache byte数の削減、長時間のepisodic memory retention、sensor-to-action latencyは主要結果で独立に測られていない。実機taskは各20試行で統計的精度に注意。PDF直接取得は環境上失敗し、公式arXiv HTML全文を参照した。

## Taxonomy・研究上の示唆
`KVcache/vla/` の **action-aware / multi-view visual token pruning**。KV cache自体をフレーム間再利用しない。camera view間の重要度を一括ランキングするとgripper視点を落とす可能性があり、視点ごとの最低保持量を設計することが重要。
