# 概要
SAFE-Prunerは、浅層attentionで重要度が低く見えたvisual tokenが深層で重要になる「short-sighted pruning」を対象とする。各制御stepで浅層だけを見るのではなく、**過去の全token実行で得た深層attention**を現在の画像patchへ転写し、現在の浅層saliencyと混合してtop-K tokenを選ぶ。追加学習なしで適用可能。ここで再利用するのはattentionの**saliency map**であり、前frameのTransformer **KV tensorそのものではない**。

# 問題設定・先行研究との差
FastV、SparseVLM等は早期のattentionで視覚tokenを削除するが、その時点では後段の必要性が見えない。VLA-Cacheは連続frameのvisual KV再利用を狙う一方、SAFE-Prunerは過去の深層attentionを「未来の深層重要度の予測器」として利用する。VLA-Prunerとの比較では、将来層のsaliencyを実際に観測した参照stepから転写する点が異なる。対象は同一subtask中のsemantic attention consistencyであり、subtask転換時には崩れる。

# 手法
1. 各visual tokenに対し、action queryからのattentionをhead/query方向に平均してsaliencyを計算する。
2. **Key timestep**ではpruningを行わず、各層のfull-token saliencyを保存する。
3. **Non-key timestep**では、現在のvisual tokenと直近key timestepのtokenのcosine similarityから対応付けを求め、過去の深層saliencyを現在のpatchへ転写する。
4. 現在の浅層saliencyと予測深層saliencyを混合し、top-K tokenを残す。
5. 浅層attentionと転写した参照saliencyの一致度が低下した場合、subtask転換・driftと判断してkey timestepを更新する。

論文の主要式（記号は原論文に準拠）：

```math
\hat{S}^{\mathcal{L}_d}_t = \frac{1}{|\mathcal{L}_d|}\sum_{\ell\in\mathcal{L}_d}\hat{S}^{\ell}_t
```

```math
s_t = (1-\lambda)S^{\ell_s}_t+\lambda\hat{S}^{\mathcal{L}_d}_t
```

この設計の重要点は、現在stepの深層attentionを予め計算する必要がないこと。代わりに全tokenで実行するkey stepの計算コストと、patch対応付けコストが必要。

# Experiment Setup
- VLA backbone: OpenVLA、OpenVLA-OFT、π0.5、CogACT。LIBERO（Spatial/Object/Goal/Long）、SIMPLER（Visual Matching/Variant Aggregation）、実機Astribot S1双腕。
- 実機はPick and Place、Throw Basketball、Pack Dollの3タスク。task-specific π0.5を200–1000 demonstrationでfine-tuneし、各task 200 trials。**fine-tuneはbackboneのタスク適応であり、SAFE-Pruner自体の学習ではない**。
- Baseline: Vanilla、FastV、SparseVLM、DivPrune、VLA-Cache、VLA-Pruner。FLOPs、CUDA/推論latency、task successを比較。

# Main Results
LIBERO（原論文Table 1）：

|---|---:|---:|---:|---:|
| OpenVLA-OFT Vanilla | 96.8% | 94.2% | 3.970 | 70.25 |
| OpenVLA-OFT VLA-Cache | 93.7% | 91.0% | 2.730 | 58.14 |
| OpenVLA-OFT SAFE-Pruner | 96.4% | 93.4% | 1.722 | 37.22 |
| π0.5 Vanilla | 96.5% | 91.8% | 2.115 | 35.28 |
| π0.5 SAFE-Pruner | 95.5% | 90.2% | 1.482 | 24.33 |
| OpenVLA Vanilla | 75.7% | 53.2% | 1.862 | 48.24 |

OpenVLA-OFTで約1.89倍のlatency短縮（70.25/37.22）、success低下0.4pp。SIMPLER CogACTではVisual Matching 74.8%→74.5%、1.73倍、Variant Aggregation 61.3%→61.9%、1.67倍。論文Table 2ではOpenVLA-OFTのGPU memoryはVanilla 17.83GB、SAFE 18.31GB、SAFE+HiF8 11.03GB。**pruning単体ではGPU memoryがむしろ増加している**。量子化との組合せで初めて大きく減る。

# Ablation / 考察
- 深層saliencyの予測に用いるkey timestepを固定間隔にするとsubtask境界で参照が古くなるため、attention shiftに応じたadaptive refreshを採用。
- 全tokenで処理するkey timestepの頻度と予測精度にはtradeoffがある。key frameを減らすほど平均計算量は下がるが、driftの危険が増す。
- 深層attentionが現在の浅層attentionとは異なるtargetへ集中する例を可視化し、浅層のみのtoken選択が深層で必要な領域を失うことを示す。
- 成功率の低下が小さいという報告は評価済みbackbone/benchmark条件での値であり、未知の長期タスクでの保証ではない。

# Limitations
- 過去のkey frameのsaliencyが現在に転写できるという仮定に依存。視点・対象・subtaskが急変すると対応付け誤りが起こり得る。
- Key stepの全token推論とsaliency保管の追加コストがある。GPU memory削減法としては単独では有利と限らない。
- 公表結果は主にtask success・forward latencyであり、制御loop全体のfrequency、転送、action executionとの重畳を厳密に評価したものではない。
- 長期記憶bankを作る手法ではない。保持するのは直近参照のsaliency。

# Taxonomy
`KVcache/vla/`：**future-aware visual token pruning / cross-frame saliency transfer**。KV cache tensorの再利用ではない。visual token削減によって後段attention計算とKV生成量を間接的に減らす。
