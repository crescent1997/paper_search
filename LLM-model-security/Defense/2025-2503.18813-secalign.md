# SecAlign: Defending Against Prompt Injection with Preference Optimization

## 概要

SecAlignは、[StruQ](2024-2402.06363-struq.md)のようなstructured instruction tuning / SFT型defenseが、prompt injectionされたinputに対する**正しいresponseのlikelihoodを上げるだけ**で、攻撃instructionに従ったresponseのlikelihoodを明示的に下げていない点に着目する。

そこで同一のinjected inputに対し、trusted instructionへ従うsecure response `y_w` と、injected instructionへ従うinsecure response `y_l` のpreference pairを作り、Direct Preference Optimization (DPO)によって `y_w ≻ y_l` を直接学習する。

## 問題設定 / Threat Model

trusted instruction `P`とuntrusted data `D`を入力するapplicationを想定し、攻撃者は`D`へinstruction `I_a`を埋め込める。攻撃者の目的はmodelに`P`ではなく`I_a`を実行させることである。

StruQ同様、dataを利用しながらdata内のinstructionだけを無視する必要があるため、単純なrefusalやdata filteringではutility requirementを満たさない。

## 先行研究からの改善点

SFT defenseでは

```text
maximize log p(y_secure | x_injected)
```

を行う。しかしLLMのoutput spaceは非常に大きいため、`p(y_secure)`が増加しても、攻撃者が狙う`p(y_insecure)`が十分下がる保証はない。

SecAlignはこの問題をranking problemとして捉え、

```text
p(y_secure | x) > p(y_insecure | x)
```

を直接optimizationする。StruQが**input-side privilege structure**を強化したのに対し、SecAlignは**output preferenceまでsecurity objectiveへ組み込む**改善と整理できる。

## Method / Algorithm

### Preference Data Construction

clean instruction-following sampleからtrusted taskを作り、data部分へ別instructionを注入する。そのうえで、元taskを正しく解くresponseをchosen / secure responseとし、injected instructionに従うresponseをrejected / insecure responseとしてpairを作る。

概念的には

```text
x = structured(P, D + I_attack)
chosen   = answer(P)
rejected = answer(I_attack)
```

となる。

### DPO Objective

reference modelに対するrelative preferenceを用いる標準的なDPO objectiveをsecurity settingへ適用し、secure responseとinsecure responseのlog-probability marginを広げる。

重要なのは、training attack自体は比較的単純なStraightforward / Completion injectionでよく、GCG等の高価なoptimization attackを大量にtraining data生成へ使う必要がない点である。

## Experiment Setup

trainingではsimple injectionを使用し、testではseen attackだけでなくGCG、AdvPrompter、NeuralExec等のoptimization / learned attackを含むadaptive settingを評価する。

baselineにはundefended model、prompt-based defense、StruQ等のstructured SFT defenseを含め、security metricとしてattack success rate、utilityとしてAlpacaEval2等を測る。

## Main Results

SecAlignの主要な利点はoptimization-based attackで現れる。代表的な比較では、StruQのattack success rateが約27% / 45%となる強力な攻撃設定に対し、SecAlignは約**1% / 8%**まで抑える。

つまり単純なtraining injectionから作ったpreference pairでも、test-timeのより強いoptimization attackへgeneralizeする。

一方、AlpacaEval2で測った通常instruction-following utilityは概ね維持され、security向上が全面的なrefusal増加だけによるものではないことを示す。

## Generalization / Robustness

特に重要なのは、trainingでGCGやAdvPrompterそのものを使用せずともrobustnessが改善する点である。SecAlignはattack stringのpatternをmemorizeするより、「同じinputでsecure behaviorをinsecure behaviorより選ぶ」というresponse-level preferenceを学習していると解釈できる。

この結果は、instruction hierarchy trainingでもpositive examplesだけでなく、**conflicting behaviorをnegative preferenceとして明示する**ことが有効である可能性を示す。

## Over-refusal / Utility

prompt injection defenseでは、data内のimperative sentenceをすべて危険とみなすとbenign taskまで拒否するover-refusalが問題になる。SecAlignはdataを捨てるのではなく、trusted taskを遂行するsecure responseをchosenとして学習するため、utility維持をobjectiveに内包しやすい。

ただしbenchmark上のutility維持が、すべてのdomainやlong-context settingでover-refusalが生じないことを保証するものではない。

## Limitations

DPOで比較するinsecure responseの品質はpreference data generationに依存する。実際のattack behaviorがtraining時のrejected responseから大きく外れる場合、preference boundaryが十分でない可能性がある。

またStruQ系と同様、prompt/data separationというsecurity modelが中心であり、多数のdeveloper/user/tool/sub-agentを持つarbitrary hierarchyを直接扱うものではない。

さらにadaptive attackerに対するASRは大幅に改善するが、cryptographic / formal guaranteeではない。model behaviorを確率的にalignmentするdefenseである。

## LLM Model Security Taxonomyでの位置づけ

```text
StruQ
  structured interface + positive SFT
       ↓
SecAlign
  secure vs insecure preference optimization

Instruction Hierarchy
  multi-level authority training
       ↓
potential combination:
  hierarchy-aware preference optimization
```

SecAlignはInstruction Hierarchyと競合するというより、training objectiveの観点から補完的である。

## 実装・研究上の示唆

instruction hierarchyを学習させる際、correct hierarchy-following responseだけをSFTするより、同一conflictに対するlower-priority-following responseをnegative exampleとして明示する設計が有望である。

特に[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)や[Instructional Segment Embedding](2024-2410.09102-instructional-segment-embedding.md)へpreference optimizationを組み合わせれば、source representationとbehavioral objectiveを別々に強化できる可能性がある。
