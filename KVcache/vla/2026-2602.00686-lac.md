# 概要
**LAC (Learnable Adaptive Caching)**は、連続するロボット観測フレームで**どのvisual tokenのKVを前フレームから再利用し、どれを再計算するか**を固定heuristicでなく**下流のaction task lossで学習**する手法。前フレームとの単純なpixel similarityやattention heuristicを用いる[VLA-Cache](2025-2502.02175-vla-cache.md)の発展形として位置付けられる。事前学習済みVLA backboneは凍結するが、追加したselector/predictorを**学習するためtraining-freeではない**。

LIBERO/OpenVLAで平均成功率75.0→76.9%（+1.9 percentage points）、CUDA時間51.91→29.51ms（1.76×）を報告。著者は光フローによる動きの手掛かりと、操作成功に直結するtask gradientの両方を利用する。公開code URLは著者のrepositoryだが、**2026-10-25に確認できた公開内容はREADMEのみ**であり、実装の公開完了とは扱わない。

# 問題設定・既存法の問題
- 観測フレーム間では背景や固定物体のvisual tokenがほぼ不変でも、毎stepのVLA prefillで再計算される。
- **静止して見えるtarget objectでもactionに不可欠**なことがある。visual similarityだけでcacheすると接触やgripperの微妙な状態変化を見逃す。
- Attention scoreは良い初期priorだが、「modelが見ている位置」と「action成功のために更新すべき位置」が一致する保証はない。
- さらに、sceneが静止か動的かで最適なcache budgetが変わる。固定reuse率では速度/成功率のPareto最適点から外れやすい。

# 手法
## 1. Motion-aware policy input
現在フレーム$I_t$とRAFT-smallで推定したoptical flow $O_t$を連結した$V_t=[I_t;O_t]$を2つのmoduleへ与える。画像差分だけでなく**動きの方向・量**を明示的に使う。RAFT自体の推論負荷は発生するが、著者は軽量CNN policyのコストとともにVLA backboneに対し小さいとする。

## 2. Cached Token Selector: what to recompute
小型CNN $f_{sel}(V_t)$がvisual tokenごとのsaliency $s_t^{(i)}\in[0,1]$を出す。**高スコア=現時刻で再計算**、低スコア=過去KVをcache reuseする候補。単純なtoken pruningではなく、**KVを残して更新を省略**する設計。

## 3. Cache Ratio Predictor: how much to reuse
別module $f_{pred}(V_t)$が候補集合$\mathcal{R}=\{r_1,\ldots,r_C\}$上のlogitsを出し、reuse率$r_t$を選択する。選択後、$k_t=N r_t$個の**低saliency token**をcache対象にする。静的sceneでは高reuse率、動きの激しいsceneでは低reuse率へ適応。selectorがtoken ranking、predictorがbudgetを担うため、head/layerのKV圧縮budgetとは別概念。

## 4. 二段階学習と離散decisionの微分
**Stage I（attention alignment）**：凍結したexpert VLAのattention map $S_{VLA}$を教師とし、$\mathcal{L}_{align}=\mathrm{MSE}(f_{sel}(V_t),S_{VLA})$でselectorをwarm start。

**Stage II（task-driven joint optimization）**：selector/predictorを$\mathcal{L}_{total}=\mathcal{L}_{VLA}+\lambda\mathcal{L}_{ratio}$で共同学習。$\mathcal{L}_{ratio}=-\sum_j\tilde p_t^{(j)}r_j$はreuse率を高める方向に働く。predictorの離散比率はGumbel-Softmax + Straight-Through Estimator（STE）、selectorのhard top-kは閾値周辺のsteep sigmoidによるsoft maskをbackwardに使う。**forwardは実際のhard selection、backwardは近似gradient**。

## 5. KV更新・位置管理・長期drift対策
推論ではactive tokenのQ/K/V・hidden stateを再計算し、cached tokenのK/Vを前フレームから継承する。Appendix Bは位置ID管理、再計算tokenだけのconditional RoPE、動的attention maskを記述。**active queryはactive+cached全K/Vにattention**するので、KV cache長そのものを大幅に削減する手法ではない。計算量は概ね$4N_{act}D^2+2N_{act}ND+2N_{act}DM$（per layer）。

固定したcache tokenが古くなり続けないよう、**stochastic recovery**で低確率・少量のcached tokenを強制再計算する。これはtoken重要度を再推定するだけでなく、長期の累積誤差に対するrefresh経路。

# Experiment Setup
- **モデル**：OpenVLA + LIBERO、CogAct + SIMPLER。実機Franka manipulatorではOpenVLA backboneをLoRAでtask適応（これはベースモデルの実機適応であり、LACのpolicy module学習とは区別）。
- **環境**：LIBERO Spatial/Object/Goal/Long（各10 subtasks）、SIMPLER Visual Matching/Variant Aggregation（4 tasks）、実機4 tasks（KnockCrisp, PickMango, CoverBanana, KnockBottle）。
- **baseline**：full、SparseVLM、FastV、[VLA-Cache](2025-2502.02175-vla-cache.md)。metrics: task success rate、FLOPs、CUDA time。光フロー・selector/predictorの追加計算を含む壁時計比較を重視する。
- **実装公開**：著者GitHub `JiahanFan/LAC`は確認したが、確認時点の公開repositoryはREADMEのみ。再現用学習code、checkpoint、kernelを確認できない。

# Main Results
**LIBERO / OpenVLA（Table 1）**

| 手法 | Spatial | Object | Goal | Long | 平均成功率 | FLOPs (T) | CUDA時間 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Full OpenVLA | 84.4% | 86.6% | 75.6% | 53.2% | 75.0% | 1.864 | 51.91ms |
| SparseVLM | 79.8% | 67.0% | 72.6% | 39.4% | 64.7% | 1.407 | 83.39ms |
| VLA-Cache | 83.8% | 85.8% | 76.4% | 52.8% | 74.7% | 1.355 | 31.83ms |
| **LAC** | **85.6%** | 86.2% | **76.6%** | **59.2%** | **76.9%** | 1.392 | **29.51ms** |

LACはFLOPsではVLA-Cache（1.355T）より**多い**が、CUDA時間では速い（29.51 vs 31.83ms）。**理論FLOPsの大小がlatencyと一致しない**こと、選択/メモリ管理の実装負荷が重要なことを示す。LIBERO-Longは53.2→59.2%（+6.0pp）で、時系列のaction品質に効いている可能性があるが、原因の厳密な分離はされていない。

**SIMPLER / CogAct（Table 3）**：Visual Matchingは74.8→75.5%、54.29→37.82ms。Variant Aggregationは61.3→63.0%、53.54→37.90ms。異なるaction decoderへの適用を示すが、policyの再学習・統合コストを考慮する必要がある。

**実機 / Franka（Table 4）**：4 task平均はfull 33.0%、VLA-Cache 30.0%、LAC **38.0%**（+5.0pp）。CUDA時間37.38→32.47ms。task別ではKnockBottle 44→64%だがPickMango 16→12%で、**全taskで改善するわけではない**。

# 主要ablation
- **LIBERO Spatial（Table 2）**：selectorのみ82.2% / 28.48ms → ratio predictor追加83.4% / 29.04ms → stochastic recovery追加85.6% / 29.32ms。高精度化の代償として若干の計算増加を許容する設計。
- **Stage Iの必要性（Appendix Table 5）**：attention initializationを省くと85.6→79.2%。最初からtask lossだけでhard decisionを学習するのは不安定。
- **Motion signal（同表）**：optical flowの代わりにlanguage-guided policyを使うと83.0%（full 85.6%）。task relevanceを言語からのみ推定するより、局所運動信号が有効という結果。
- **Reuse ratio sweep（Figure 4）**：高reuse率でもLACはpruning系より成功率を維持し、実測CUDA時間も短い。論文の数値はグラフ主体なので、ここでは未読取の座標を推測して記載しない。

# Limitations・実装上の注意
- **追加学習が必要**：backboneはfrozenでも、selector/predictorはattention distillation + task-loss学習を行う。VLA-CacheやVLA-Prunerと同じtraining-freeカテゴリに置かない。
- **光フロー依存**：大きなcamera ego-motion、照明変化、遮蔽、rapid global scene changeでは誤ったsaliencyまたは低reuse率になり得る。極端な動きでは精度維持のため大半を再計算し、速度利得が縮む。
- **full-prefill同値性はない**：過去フレームKVと現フレームKVを混在させるため、理論上のattention correctnessを保証する方式ではない。stochastic refreshも近似的drift対策。
- **RoPE・mask・partial prefill**：Appendixの「permutation-invariantだからvalid」という説明だけでは、causal mask、position ID、前段hidden stateの時刻混合によるfull recomputationとの差は消えない。既存KV reuse実装と比較するときの重要な検証点。
- **性能指標**：CUDA時間と実機のaction successを報告するが、長時間連続稼働でのcontrol frequencyやGPU peak memoryの定量評価は限定的。

# Taxonomy・関連研究との差分
- **分類**：`KVcache/vla` / cross-frame visual KV reuse / learned token-level selection + scene-level budget / task-utility optimization。
- [VLA-Cache](2025-2502.02175-vla-cache.md)はpixel staticness・task attention・layer entropyなど**固定規則**でreuseする。LACは光フローを入力したpolicyを**task lossで最適化**し、reuse率まで動的に選ぶ。
- [VLA-Pruner](2025-2511.16449-vla-pruner.md)は不要visual tokenを**削除**し、過去action attentionを重要度に利用。LACは過去KVを**保持して再利用**する。
- [EfficientVLA](2025-2506.10100-efficientvla.md)のcacheは**diffusion denoising step間のintermediate feature**、LACのcacheは**観測フレーム間のvisual KV**。両者は別の時間軸。
- [Reflex](2026-2607.14695-reflex.md)はflow modelのtimestep-invariant領域を**構造的に分離して正確なcache reuse**を狙う。LACはlearned approximationでaction成功率を直接最適化。
- LLM側の[CacheBlend](../reuse/2024-2405.16444-cacheblend.md)と同様にpartial recomputationを使うが、LACのselection signalはquery attentionではなくmotion + learned task gradient。
