# Reconstructing KV Caches with Cross-Layer Fusion for Enhanced Transformers

## 概要

[Cross-Layer Attention (CLA)](2024-2405.12981-cross-layer-attention.md)や[YOCO](2024-2405.05254-yoco.md)はlayer間でKVを共有しcache memoryを削減するが、一般にGQAのようなwithin-layer sharingよりquality低下が大きい。

FusedKVは「top layerのK/Vはどのlower-layer informationを必要としているか」を分析し、**KeyとValueで情報継承経路が異なる**ことを発見する。

- Value: 主にbottom layer由来
- Key: bottomだけでなくmiddle layer由来の情報も重要

この非対称性に基づき、top-layer KVをbottom/middle KVからlearnable fusionで再構成する。

## 問題設定

単純なcross-layer sharingでは、

```text
K_top, V_top ← K_lower, V_lower
```

のようにK/Vを同じsource layerから共有しがち。

しかしtop-layer attentionが必要とするrepresentationがKとVで異なるなら、このsymmetric sharingがquality bottleneckになる。

FusedKVはKV cache削減を、

> どのlayerのKVを消すか

だけでなく、

> 消したtop-layer KVを、どのlower-layer informationから再構成するか

という問題として扱う。

## Information-flow analysis

著者らはtop-layer K/V representationとlower/middle layersの関係を解析する。

結果として、

### Value

top-layer Value informationはbottom layersから強く継承される。

Valueはattention後にaggregateされるcontent representationなので、bottom-layer Vを再利用しても比較的情報損失が小さい。

### Key

top-layer Keyはbottomだけでは不十分で、middle layersからのinformation contributionも大きい。

Keyはqueryとのmatchingを担うため、layer depthに伴うsemantic transformationの影響をより強く受けると解釈できる。

このK/V asymmetryがFusedKVの設計根拠。

## FusedKV

FusedKVではKVを生成しないtop layersについて、bottom/middle layersのKVをlearnable fusionして再構成する。

概念的には、

```text
V_top ≈ fusion(V_bottom, V_middle)
K_top ≈ fusion(K_bottom, K_middle)
```

だが、K/Vで最適なsource contributionは異なる。

単一lower layerのKVをそのまま共有するCLAよりflexible。

## Post-RoPE Key fusion

Key fusionは**RoPE適用後のKey representation**上で行う。

これによりsource layerごとに融合後のKeyへRoPEを再適用する追加costを避けつつ、relative positional informationを維持する。

RoPEを伴うcross-layer reuseではposition semanticsが重要なので、implementation上の重要な設計点。

## FusedKV-Lite

learnable fusionはqualityに有利だが、複数source KVのread/fusionによるI/O overheadが増える。

そこで軽量variant FusedKV-Liteではanalysisで得た非対称性を直接architectureへ落とす。

```text
top-layer V ← bottom-layer V
top-layer K ← middle-layer K
```

とし、learnable fusionを省略する。

FusedKVよりperplexityはわずかに悪化するがI/Oを削減できる。

## CLAとの差

[CLA](2024-2405.12981-cross-layer-attention.md)は隣接layer groupで同一KVを直接共有する。

```text
CLA:
Layer l K/V
   ↓ direct reuse
Layer l+1 K/V
```

FusedKVはtop-layer KVを複数depthのinformationから再構成する。

```text
FusedKV:
bottom KV ─┐
           ├→ reconstructed top KV
middle KV ─┘
```

さらにKとVでsource importanceが異なることを明示的に扱う。

したがって、

```text
GQA: head-axis sharing
 ↓
CLA: layer-axis direct sharing
 ↓
FusedKV: information-aware asymmetric cross-layer reconstruction
```

という発展として整理できる。

## YOCOとの差

[YOCO](2024-2405.05254-yoco.md)はself-decoderでglobal KVを一度生成し、後段cross-decoder全体で共有する大きなarchitecture redesign。

FusedKVはstandard Transformerに近いlayer stackを保ち、top-layer KV生成をlower/middle KV fusionへ置き換える。

YOCOが「KV生成回数そのものを極端に減らす」のに対し、FusedKVは「cross-layer sharing時のinformation lossを抑える」ことへ重点を置く。

## GQAとの関係

GQAは同一layer内でquery headsがK/V headsを共有する。

FusedKVはlayer axisのsharingなので原理的には直交する。

論文のmotivation自体が、cross-layer sharingがGQAよりquality面で弱い理由を解明し、そのgapを縮めることにある。

## Experiment Setup

332Mから4Bまでのdecoder-only LLMを用い、standard Transformer、GQA、既存cross-layer KV sharingなどと比較する。

主な評価はvalidation perplexityとKV cache memory。

FusedKVとFusedKV-Liteを比較し、fusionによるquality向上とI/O overheadのtrade-offも調べる。

## Main Results

FusedKVは評価modelで**KV cache memoryを50%削減**しながら、standard Transformer decoderより低いvalidation perplexityを達成する。

これは単なるmemory-quality trade-offではなく、適切なcross-layer information fusionがregularization/representation sharingとしてmodel qualityにも寄与し得ることを示す。

FusedKV-Liteは若干のperplexity悪化と引き換えにfusion I/Oを削減する。

## 主要ablation / analysis

### K/V source layer

Valueはbottom sourceが強く、Keyはmiddle informationを含めることが重要。

K/Vを同じsource layerから取るsymmetric sharingよりasymmetric designが良い。

### Fusion vs direct sharing

learnable fusionはdirect sharingよりqualityを改善するが、複数source KVを読むI/O overheadを伴う。

### Post-RoPE fusion

Keyをpost-RoPEで融合することでposition informationを維持し、追加rotary computationを避ける。

## Limitations

1. architecture変更とtrainingが必要で、既存checkpointへのtraining-free retrofitではない。
2. learnable fusionはCLA型direct sharingよりruntime I/O/compute overheadが増える。
3. 4Bまでの評価が中心で、70B級modern LLMへのscalingは追加検証が必要。
4. optimal source layersがmodel depth/architectureで変わる可能性がある。
5. 50% memory reductionは大きいが、YOCOのようなよりaggressiveなstructural reductionとは設計目標が異なる。

## KV-cache taxonomyでの位置づけ

**model / cross-layer KV sharing / KV reconstruction / asymmetric K-V fusion**。

cacheをruntime evictionする`compress`ではなく、architecture段階でtop-layer KV生成・保持を減らすため`model`。

## 技術系譜

```text
MHA
 ↓
GQA / MQA
head-axis sharing
 ↓
CLA
direct layer-axis sharing
 ↓
FusedKV
information-aware asymmetric cross-layer fusion
```

FusedKVはCLAの「cross-layer sharingは可能」という結果を一段進め、**何をどのlayerから共有すべきか**をK/V別に分析した研究と位置づけられる。
