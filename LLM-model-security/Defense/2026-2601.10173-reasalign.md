# ReasAlign: Reasoning Enhanced Safety Alignment against Prompt Injection Attack

> **登録判定：引用条件を最低限充足（cited >=1）**。原論文PDF（15頁）、arXiv metadata、著者公式コードrepositoryを確認済み。別のOpenReview PDFの参考文献に本論文が掲載されていることを直接確認したため、2026年公開論文の「最低1件」の下限を満たす。ただし総引用数は未確認であり、ICLR 2026とする二次書誌情報の公式採択レコードは未照合。

## 概要

従来の[StruQ](2024-2402.06363-struq.md)、[SecAlign](2024-2410.05451-secalign.md)、[Meta SecAlign / SecAlign++](2025-2507.02735-meta-secalign.md)は、trusted user instructionとuntrusted external dataの区別をモデルへ学習させる。一方、外部データに含まれる**正当な作業指示**まで機械的に無視すると、元のuser taskを達成できない場合がある。ReasAlignは、単なるattack-pattern拒否ではなく、モデル自身に「ユーザーが何を許可したか」「外部命令はその達成に必要か、矛盾するか」を段階的に推論させる。

## 問題設定 / Threat Model

正規user $U$ が外部文書、email、webpage、tool output等のデータ $D$ を参照させる。attackerは$D$の一部を改変して不正なinstruction $I_a$ を混入できるが、system/developer/user message自体は変更できない。モデルが低trust data内の指示をそのまま実行すれば**User > External Data**境界の違反となる。

| 主体 | 制御できるもの | 想定されない権限 |
|---|---|---|
| Legitimate user | 正規taskと許可された行動 | 攻撃者の外部文書内容とは独立 |
| Attacker | external dataに混入するinjection | model weightsや高priority system promptの書き換えは不要 |
| Defender | model training、reasoning supervision、judge、推論時trajectory selection | OS権限やnetwork権限の強制分離は直接扱わない |

ここで重要なのは、外部文書中のimperative sentenceが**常に攻撃とは限らない**こと。正規userが「メールに書かれたタスクを実行」と明示した場合、メール中の一部の指示は処理対象になる。ReasAlignはこの委任の範囲をreasoningで扱う。

## 先行研究からの改善点

- **Delimiter/SFT（StruQ）**：instructionとdataの形式的分離を学習するが、曖昧な委任と文脈依存の正当な外部指示に弱い。
- **DPO（SecAlign）**：安全応答を選好するが、攻撃らしい文面を一律に無視するoverdefenseの懸念がある。
- **SecAlign++（Meta SecAlign）**：専用input roleと大規模preference trainingにより防御を強化する一方、外部指示が本来のuser taskの一部である場合にutilityを落とす例がある。
- **ReasAlign**：指示の出所だけでなく、**正規目的との関係を推論**し、推論軌跡の品質を別のjudgeで選別する。

## Method / Algorithm

### Structured reasoning

モデルは直ちに最終回答を生成せず、概念的に次の段階を経る。

1. **User intent analysis**：正規user queryからtask objectiveと許可範囲を抽出。
2. **Conflict analysis**：external data中のinstructionを識別し、user taskと競合するかを判断。
3. **Task continuation**：攻撃命令を実行せず、必要なdataを使って正規taskを継続。

この過程を教師データとして構成し、reasoning付きの応答を学習させる。単に「拒否」することを目的としない点が特徴。

### Logic judgeとtest-time scaling

複数の候補reasoning trajectoryを生成し、**preference-optimized judge**で各軌跡をscoreして良い軌跡を選択する。論文は、正規instructionを保ったreasoningをchosen、攻撃者側へ逸脱したreasoningをrejectedとするpreference pairを作り、DPOでlogic judgeを学習する。探索node数 $N$ を増やすと安全性とutilityが改善する傾向を報告する（$N=1$から5のablation）。ただし候補数の増加はdecode・judge評価の計算費用増を伴うため、1-pass guardrailと同等のレイテンシとは限らない。

## Experiment Setup

原論文は**7 utility benchmarksと4 security benchmarks**を評価し、instruction-followingとagentic taskを横断する。主要比較はundefended Llama、SecAlign、Meta SecAlign。Security指標はAttack Success Rate（ASR、低いほど良い）、Utility指標は元のuser taskを正しく遂行した割合（高いほど良い）。代表的なCySE（CyberSecEval2）とSEPに加え、tool-agent settingとしてInjecAgent、AgentDojoを扱う。著者の公式repositoryはCySE、AlpacaEval、SEPの評価scriptとresult fileを公開している。

## Main Results

**CyberSecEval2（open-ended task）**：

| Defense | Utility | ASR | 注意 |
|---|---:|---:|---|
| Undefended Llama | 78.2% | 43.6% | 著者が提示したbaseline |
| Meta SecAlign | 56.4% | 74.4% | 外部の有用なinstructionまで無視するケースがある |
| ReasAlign | **94.6%** | **3.6%** | 論文の代表設定 |

**Reasoning ablation（原論文Table 1）**：

| 設定 | CySE ASR ↓ | SEP ASR ↓ | CySE under-attack utility ↑ | SEP under-attack utility ↑ |
|---|---:|---:|---:|---:|
| Direct Answer supervision | 21.8% | 66.9% | 92.7% | 87.3% |
| ReasAlign reasoning | **3.6%** | **1.1%** | **94.6%** | **95.5%** |

同表のno-attack utilityではAlpacaEval2が96.2→96.8、SEPが98.9→98.0であり、clean utilityが一様に改善するわけではない。数値は異なるbenchmarkのASRとutilityであり、モデル一般の防御成功率ではない。

## Generalization / Robustness / Adaptive Attack Evaluation

- **Domain generalization**：単純なinstruction-followingからopen-ended agent taskへ評価を拡張。CySEのような外部instructionを正当に使うtaskでsecurity–utility tradeoffを確認する。
- **Tool-agent transfer**：InjecAgentとAgentDojoも評価。ただし小型Llama-3.1-8B-Instructのagent task自体の能力制約があるため、AgentDojoでASRが0でも、同時にutilityが低ければ安全性の十分な証明にはならない。
- **Reasoning ablation**：final answerのみのsupervisionに比べてCySE ASRが21.8→3.6%、SEPが66.9→1.1%。
- **Test-time scaling**：reasoning candidate/nodeを増やすと改善する傾向。ただし最大node数・sampling policyが変われば計算費用と結果も変わる。
- **Adaptive attacker**：防御モデルとjudgeを知る攻撃者が推論軌跡を直接最適化する強いwhite-box adaptive evaluationについて、上記主要数値を保証と解釈しない。SecAlignを破るCheckpoint-GCG等を含めた追加評価が望ましい。

## Limitations

1. **Reasoningの正しさ**：モデルが出力した説明と実際の意思決定が一致する保証はなく、judgeも誤り得る。
2. **計算負荷**：複数candidate生成・judge scoringは通常の1回のdecodeより重い。TTFT、総token数、GPU使用量の再評価が必要。
3. **trust boundaryの粒度**：system/developer/user/toolの全階層を独立して学習・評価したというより、正規user intentと外部dataの衝突が中心。
4. **external enforcementの不在**：model-level reasoningは[CaMeL](2025-2503.18813-defeating-prompt-injections-by-design-camel.md)のような外部capability controlを置き換えない。
5. **評価の限界**：attackの適応性、長文context、judgeへの二次prompt injection、distribution shiftで性能が変化し得る。

## LLM Model Security taxonomyでの位置づけ

**Defense / model-internal conflict reasoning / preference-optimized trajectory selection / prompt-data separation / overdefense mitigation**。権限情報を層へ明示的に注入するAIRや[ISE](2024-2410.09102-instructional-segment-embedding.md)とは異なり、既存モデルのinstruction-priority判断を推論過程として学習する。

## 実装・研究上の示唆

実装では`user_intent`、`candidate_instructions`、`conflict_decision`、`task_continuation`をログ上で区別し、clean task successとattack ASRを同時に測るべき。複数reasoning候補の選別はcandidate生成とjudge推論のKVキャッシュを分離・共有できるかが重要な性能課題となる（これは本論文の実験結果ではなく研究上の示唆）。
