# KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache

> KV cacheを単純に低bit化するのではなく、**KeyとValueで量子化軸を変える**ことが中心的アイデア。既存modelを再学習せず2-bit KV cacheを実現する代表的なquantization系手法。

## 概要

autoregressive decodingでは各token生成時に過去token全体のK/Vを参照するため、長文・大batchではKV cacheがweightに匹敵するmemory bottleneckになる。さらにdecodeはKV cacheをHBMから繰り返し読むmemory-bandwidth-bound処理になりやすい。

KIVIはまず実modelのKV tensor分布を調べ、Keyには特定channelに継続的なoutlierが現れる一方、Valueのoutlier構造はtoken方向に固定されにくいことを観察する。この非対称性に合わせて量子化単位を変える。

## 先行研究からの改善点

一般的なweight quantizationをそのままKVへ適用すると、K/Vのdistribution差を無視するため2-bitでaccuracy degradationが大きい。KIVIはcalibrationやfine-tuningを必要とせず、runtimeに生成されるKVに直接適用できる点が特徴。

## Method

### Key: per-channel quantization

attention scoreはQとKのdot productで決まり、Keyの特定channelに大きなoutlierが継続して現れる。このためtokenごとにまとめるより、同一channel方向でgroupingしてscale / zero-pointを持たせる方がquantization errorを抑えられる。

### Value: per-token quantization

ValueではKeyほどchannel固定のoutlierが強くないため、各tokenのValue vector内でgroupingするper-token方式を用いる。

### Residual window

最新token付近は高精度のまま保持し、一定数たまった古いKVを低bit representationへ移す。これによりonline decoding時のquantization処理を扱いやすくし、recent-token precisionも維持する。

## Experiment Setup

Llama、Falcon、Mistral系modelを用い、language modeling / zero-shot / few-shot / long-context taskと実inference throughputを評価する。比較対象はFP16 KVおよびより単純な低bit量子化。

## Main Results

論文では2-bit KV cacheでもbaselineに近いtask qualityを維持し、model weightを含むpeak GPU memoryを最大約2.6×削減する。空いたmemoryでbatch sizeを最大4×へ拡張でき、実workloadで約2.35〜3.47×のthroughput向上を報告する。

重要なのは、decode stepでは毎回KV全体を読むため、容量削減が単なるcapacity改善だけでなくmemory traffic削減にもつながる点である。

## Limitations

- quantization / dequantization kernelの実装品質に性能が左右される。
- 2-bit化してもtoken数自体は減らさないため、極端なlong contextでは線形増加は残る。
- model / headごとのdistribution差により最適group sizeやresidual lengthが変わり得る。

## KV-cache taxonomyでの位置づけ

KIVIは**representation compression**に分類される。SnapKVのようにtokenを捨てる方法とは直交し、原理上はtoken evictionやGQA / MLAのようなarchitecture-level reductionとも組み合わせられる。

## 実装・研究上の示唆

KV cache optimizationではKとVを同一tensorとして一括処理せず、用途・distributionを分けて設計する価値がある。また、memory capacityだけでなくdecode時のHBM trafficまで含めて評価する必要がある。
