# RAGuard: A Layered Defense Framework for Retrieval-Augmented Generation Systems Against Data Poisoning

> retrieval-side adversarial trainingとgeneration-side counterfactual influence detectionを組み合わせるtwo-layer Defense。特にZKIPはgold answerや外部oracleを使わず、各retrieved documentを1件ずつ除いた際のanswer shiftとuncertainty変化からpoisonを検出する。

## 概要

RAG knowledge poisoningでは、fabricated fact、contradiction、corrupted reasoningを含むdocumentsをcorpusへinjectし、retrievalを経由してgenerator answerを操作する。

RAGuardはDefenseを二層へ分ける。

1. **Layer 1:** adversarially trained dense retrieverでpoisonをdownrank
2. **Layer 2:** Zero-Knowledge Inference Patch (ZKIP)で、retrieved documentのgeneratorへの異常な影響をcounterfactualに検出

Layer 1でproactiveにretrievalをhardeningし、残存poisonをLayer 2でattack-agnosticにfilterする。

## 問題設定 / Threat Model

attackerはcorpusへのwrite accessを持ち、factual fabrication / contradiction / reasoning trapをinjectできる。

一方、model weights、future user queries、generation promptへ直接accessすることは想定しない。

scopeはfactual corpus poisoningで、prompt injection、opinion manipulation、retrieval jamming、backdoor、adversarial query、white-box gradient attack等は主対象外。

## 先行研究からの改善点

[PoisonedRAG](../Attack/2024-2402.07867-poisonedrag.md)型attackに対し、retriever-only defenseではtraining distribution外のpoisonが残る。

一方、LLM parametric knowledgeをoracleとして使うDefenseはprivate / recent / long-tail knowledgeで正解を知らない可能性がある。

RAGuardのZKIPは**context-free正答を要求せず、同じretrieved setのcounterfactual variantsだけを比較する**。

[TRIS](2026-2609.00470-tris.md)のLayer 3がLLMのparametric beliefとの矛盾を見るのに対し、ZKIPはdocument removalによるanswer stabilizationを見る点が異なる。

## Layer 1: Adversarially Trained Retriever

clean passagesに加え、LLMで生成したfabrication / contradiction / reasoning-trap poisonsをcontrastive trainingへ投入し、poison embeddingsをrankingでdownrankするようdense retrieverをfine-tuneする。

しかしtraining時のpoison distributionへのoverfittingは残る。NQ 10% poisoningではLayer 1のみで **ASR 0.072** が残る。

そのためLayer 1は完全なdetectorではなく、Layer 2へ渡るattack surfaceを減らすproactive filterとして位置付けられる。

## Layer 2: ZKIP

### Leave-One-Out Counterfactual Generation

Top-k documents全体でanswer (y_all) を生成する。

その後、各document (d_i) を1件ずつ除外し、counterfactual answer (y_{-i}) を再生成する。

```
D = {d1, ..., dk}
  ↓
y_all = LLM(q, D)

for each di:
    y_-i = LLM(q, D \ {di})
    compare(y_all, y_-i)
```

### Anomaly Score

document removal前後の、

- answer semantic shift
- output entropy / confidence differential

を組み合わせてanomaly scoreを作る。

「そのdocumentを除くとanswerが安定しuncertaintyも低下する」場合、そのdocumentはpoison candidateとみなす。

### Why This Is Not Simple Attribution

gold evidenceもpoisonもanswerへ大きく影響する可能性があるため、単純なinfluence magnitudeでは区別できない。

ZKIPはimportanceそのものではなく、**removal後にanswer behaviorが改善 / 安定するか**を見る。

query-relevantでretrieval scoreが高い誤情報でも検出できることを狙う。

## Experiment Setup

主なdatasetsはNatural QuestionsとBEIR/NFCorpus。corpus poison ratioを5–30%で変化させる。

synthetic poison typesはfabrication / contradiction / reasoning trap。dense retrievalとBM25も比較し、Defenseなし、Layer 1、ZKIP、combined configurationを評価する。

## Main Results

NQではZKIPを適用した論文中のcompleted defended configurationsで **ASR=0.000**。

retrieval qualityもclean-corpus baselineからRecall@5で概ね0.03以内に維持する。

Layer 1だけではNQ 10% poisoningでASR 0.072が残る一方、ZKIP単独 / Layer 1+ZKIPでは測定attack successを0まで下げるsettingが報告される。

## BM25 Negative Result

keyword-preserving poisonsに対しBM25はそもそも影響を受けにくく、undefendedでも5–20% poisoningではASR 0、30%でも **0.011**。

したがってRAGuardの主要claimはdense embedding retrievalで特に重要であり、すべてのretrieval architectureへ同じriskを一般化すべきではない。

## Computational Cost

ZKIPはfull-context generation 1回に加え、k documentsそれぞれのleave-one-out generationを行うため**k+1 generator calls**。

k=5なら6 calls、k=10なら11 calls相当で、API costは大きい。

batched LOOでwall-clock overheadを削減でき、NQではbatched variantでもASR 0を維持するが、total generated tokens / API cost自体は残る。

multi-poison coalition向けiterative ZKIPも実装されるが、2–4 poisonsを使う包括的quantitative evaluationはfuture work扱い。

## RAGSentinel / PRA-RAG / TRISとの比較

[RAGSentinel](2026-2608.23965-ragsentinel.md)と[PRA-RAG](2026-2607.00012-pra-rag.md)はembedding / representation geometryのmajority robustnessを利用する。

RAGuard ZKIPはgeometryではなく、**generator outputに対するdocument-level counterfactual influence**を見る。

TRISはretrieval geometry、structural trigger detection、parametric-belief verificationを重ねるが、ZKIPはLLMがcontextなしで正答を知っている必要がない。

## Limitations

評価attackはsynthetic factual poisoningが中心で、PoisonedRAG / FlippedRAG等のstandard attack frameworkを用いたbroader evaluationはfuture workとして残る。

k+1 generationsのcostが大きい。multi-poison coalition、adaptive attacker、prompt injection / backdoor等は十分検証されていない。

Layer 1はtraining poison distributionへ依存するため、unseen attackに対する主なrobustnessはZKIP側へ依存する。

## RAG Security Taxonomyでの位置づけ

```
Knowledge poisoning
  ↓
Layer 1: adversarial retriever hardening
  ↓
Layer 2: counterfactual generator-side filtering
  ↓
RAGuard / ZKIP
```

private corpus extraction Defenseである[RAGFort](2025-2511.10128-ragfort.md)や[CanaryRAG](2026-2604.10717-canaryrag.md)とはthreat classが異なり、RAGuardは主にintegrity corruptionを防ぐ。

## 実装・研究上の示唆

ZKIPは「外部oracleなしでdocumentの悪影響を測る」という点が重要で、private knowledge RAGでも利用可能なDefense primitiveになり得る。

一方、generator callsがretrieved-document数に比例するため、productionではrisk-based invocation、candidate prefiltering、batched inference等との組み合わせが必要。
