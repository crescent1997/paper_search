# SilentRetrieval: Hijacking Retrieval-Augmented Generation via Semantically-Preserving Adversarial Data Poisoning

> RAG poisoningをretrieval hijackingだけでなく、generation manipulationとnatural-language fluencyまでjointly扱う。Coordinated Beam Search (CBS)で自然なretrieval hostを作り、Context-Adaptive Trigger Generation (CATG)でtarget payloadをstyle-preservingに埋め込む。

## 概要

従来のRAG poisoningはASRを上げられても、token-level adversarial optimizationによる高perplexityや不自然なtriggerが検出signalになる。

SilentRetrievalは**retrievability・attack effectiveness・fluency**の三者を同時に満たすことを目的とし、1 poisoned document / queryという条件でstealthy poisoningを構築する。

## 問題設定 / Threat Model

attackerはtarget corpusへpoison documentをinjectでき、target queryに対してattacker-chosen claimをgeneratorへ出させたい。

primary optimizationではretriever gradientへaccessするwhite-box settingを使う。ただしsurrogate retrieverからunseen retrieverへのtransferも評価する。

この点はtarget system feedbackだけで学習する[RIPRAG](2025-2510.10008-riprag.md)より強いaccess requirementである。

## 先行研究からの改善点

[PoisonedRAG](2024-2402.07867-poisonedrag.md)はretrieval-oriented textとmalicious answer payloadを組み合わせるが、生成文のnaturalnessがDefenseから検出され得る。

SilentRetrievalはまず自然なhost documentをretrieval-friendlyに変換し、そのstyleへ適応したtriggerを後から埋め込む。

[CamoDocs](2026-2608.28389-camodocs.md)がquery-overlap / embedding-cluster artifactを狙うのに対し、本論文は主に**PPL / linguistic fluency artifact**を減らす。

## Stage 1: Coordinated Beam Search (CBS)

topically relevantなseed documentから開始し、retriever similarityを上げつつGPT-2 perplexityをthreshold以下に保つ。

single-token greedy substitutionではなく、gradient magnitude上位の複数token positionsを同時に選び、複数replacement combinationsをbeam searchする。

defaultでは3 positions × top-10 candidate tokensをbeam width 5でjoint searchする。

複数positionを協調して変更するため、形容詞・名詞・動詞等の局所依存を壊しにくく、retrieval scoreを上げながらnaturalnessを維持できる。

## Stage 2: Context-Adaptive Trigger Generation (CATG)

CBSで得たhost documentへ、attacker target claimを含むtriggerを追加する。

frozen Llama-2-7B-Chatをtrigger generatorとして使い、hostのdomain / styleへ自然に馴染む表現を生成する。

候補は概ね、

- target answer entailment > 0.8
- hostとのcosine coherence > 0.7
- final PPL <= 50

のgatesでfilterする。

static templateを付けるのではなくhost-specific triggerを生成することで、payload insertion後もdocument-level fluencyを保つ。

## Experiment Setup

Natural Questionsでは約361K passages、MS-MARCOでは約8.8M passagesを使用。retrieverはContriever、generatorはLlama-2-7B-Chatを中心に評価する。

比較AttackはPoisonedRAG、GASLITE、Joint-GCG、HotFlip系手法。

metricsはHit Rate@10 (HR@10)、LLM Attack Success Rate (ASR-LLM)、perplexity等。

## Main Results

NQでSilentRetrievalは、

- **HR@10 84.6%**
- **ASR-LLM 57.5%**
- **PPL 32.4**

PoisonedRAGは78.6 / 48.2 / 412.6、Joint-GCGは81.2 / 62.8 / 156.3。

Joint-GCGよりASRは若干低いが、benign document PPL 28.4に近いnaturalnessを維持する。

MS-MARCOでも **HR@10 81.3% / ASR 54.8% / PPL 33.1**。

## Ablation

full CBS+CATGの84.6 HR / 57.5 ASRに対し、seed+CATGのみでは **38.2 / 14.7**。

single-token greedy optimizationでは **79.8 / 53.1**。CATGをstatic templateへ置き換えるとASRは **54.2**。

Stage 1がretrieval-capable hostを作り、Stage 2がnaturalなgeneration payloadを入れるという分業が有効。

## Defense Evaluation

cross-encoder rerankingでASRは **57.5→46.8%**、hybrid BM25+dense+rerankingで **41.5%**、passage isolation k=5で **38.2%**。

複数Defenseを組み合わせると **21.3%**まで下がるが、latencyは約11倍。

reranker-aware adaptive optimizationを行うとHR@10 **73.2→79.4%**、ASR **46.8→51.2%**へ回復し、Defense-aware adaptationの余地がある。

### Stealth Detection

PPL filterによる検知率はSilentRetrieval **8.7%**、PoisonedRAG **78.6%**。

GPT-4 filterでも **14.2% vs 71.4%**。simplified RAGuard implementationでは34.2%で、完全不可視ではないが既存attackよりstealthy。

21M-passage sampled corpusでもHR@10 **74.2%**を維持する。

## RAG Security Taxonomyでの位置づけ

```
PoisonedRAG
  ↓
gradient-based retrieval optimization
  ↓
SilentRetrieval
  ├─ CBS: retrieval + fluency
  └─ CATG: context-adaptive payload
```

CamoDocsと合わせると、modern poisoning attackはASRだけでなく「Defenseが検出に使うartifactを消す」方向へ進んでいる。

## Limitations

primary CBSはwhite-box retriever gradientsを必要とする。surrogate transferは示すが、query-only black-box attackではない。

NQ主評価は標準21M DPR corpusではなく361K corpusであり、大規模評価はsampled setting。target answersはsyntheticで、より強いgeneratorsやdomain-specific detectorsは十分評価されていない。

## 実装・研究上の示唆

PPLやgeneric LLM detectorだけをpoison defenseとして使うのは危険で、attack objectiveにfluencyを入れるだけで検出率が大幅に下がる。

provenance、retrieval anomaly、semantic contradiction、generation influence等、linguistic naturalnessと独立したsignalが必要になる。
