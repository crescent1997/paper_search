# 概要
**EfficientVLA**は、VLAのvision encoder → VLM/LLM → diffusion action headを一体で最適化する**training-free**手法。注目点は「KV cacheを別の観測フレームへ持ち越す」ことではなく、**同じaction chunkを生成する複数のdenoising stepの間で、DiT blockのself-attention出力とMLP出力をcacheする**こと。さらにLLM層とvisual tokenも削る。従って本論文の「cache」は主に**diffusion feature cache**であり、VLA-Cacheのcross-frame *K/V tensor* reuseと混同しない。

CogACT（LLM約6.7B、action head約89M）で、元の256 visual tokens/10 denoising stepsから、代表構成では56 tokens/実質的に間引いたaction計算に移行し、SIMPLER Visual Matchingで平均成功率74.8%→74.2%（**-0.6 percentage points**）、速度1.93×、FLOPsは元の28.9%を報告する。引用数★94はmlsanityの収録論文内の被引用数であり、Scholar総数ではない。

# 問題設定・既存法の問題
- CogACTのモジュール別単発推論時間（Table 1）はvision 24.9ms、language 134.5ms、action 51.5ms。visual tokenだけ削ると、LLMのmemory-bound領域やdiffusion headが残り、速度改善が飽和する。
- VLA-Cacheのような**観測時刻間**のKV reuseは視覚処理の重複を削るが、language modelのdepth redundancyとaction diffusionの反復計算を直接解決しない。
- DiTの隣接denoising stepではattention/MLPの中間表現が類似するため、毎step全モジュールを実行する必要があるかを疑う。

# 手法
## 1. LLMの非連続layer pruning
Transformer layer $\ell$ の入力と出力のcosine similarityを代表データ上で平均し、$I^{(\ell)}=1-\mathrm{mean\ cosine}(x^{(\ell)},x^{(\ell+1)})$を重要度とする。低スコア層は残差経路の変化が小さいとみなして削除する。**連続する末尾層を切るのではなく、各層をrankingして非連続に選択**する。実験では32層のうち28層または22層を保持。加えて残存層のMLP weightに25% sparsityを適用するPruneNet構成も使用する（単なるlayer削除だけの性能ではない）。追加fine-tuningは不要だが、重要度推定用のcalibration dataと重み変換は必要。

## 2. Task relevance + diversityによるvisual token選択
画像由来の$N$個のtokenから$K_{final}$個を選ぶ。選択は以下の三段階。

1. 指示などのcontext tokenへのattentionをhead平均して合計し、visual token $i$ のtask score $r_i=\sum_{j=1}^{L_{ctx}}\frac1H\sum_h A^{(h)}_{i,j}$を作る。上位$K_{key}$（実験では4）を必ず残す。
2. 残余budgetの$\alpha$分（実験では0.5）をtask score上位から補充する。
3. さらに残余を、既採用tokenへの最大cosine類似度が**低い**tokenから補充する：$d(v_j,V_{key})=1-\max_{v_k\in V_{key}}\cos(v_j,v_k)$。

最終集合は$V_{key}\cup V_{task}\cup V_{div}$。重要度だけで選ぶと類似patchに偏るため、diversityで空間的・意味的カバレッジを補う。**visual tokenを捨てる方法であり、前フレームのvisual KVを再利用する方法ではない**。

## 3. Action DiTのN-step feature cache
各diffusion timestep $t$ のDiT blockで得られる$h_t^{attn}=\mathrm{SelfAttn}(z_t)$と$h_t^{mlp}=\mathrm{MLP}(h_t^{attn}+z_t)$をcacheする。初回と間隔$N$ごとに更新し、間の$N-1$ stepでは両moduleの実行をskipしてcache値を使う。論文は$N=5$を採用。**attentionのK/Vのみを保持する標準autoregressive KV cacheとは異なる**。denoising stateが変わっても中間featureを近似再利用するため、full computationとの数学的同値性は主張しない。

# Experiment Setup
- **モデル**：CogACT-Small/Base/Large（vision: DINOv2 + SigLIP、language: Llama2-7B、action: diffusion transformer）。主評価はCogACT-Base。論文時点で他のdiffusion VLAへの検証は限定的。
- **環境**：SIMPLER / Google robot、Visual MatchingとVariant Aggregation、PickCan・MoveNear・Drawer・DrawerAppleの4 task。224×224 RGB、7-DoF action。
- **比較**：full CogACT、random token dropping、FastV、[VLA-Cache](2025-2502.02175-vla-cache.md)。GPUはNVIDIA A40、推論時間はsingle-step平均。実機成功率、control frequency、長時間のcache driftの直接評価は主結果にない。
- **設定**：保持LLM layer $L=22/28$、visual token $T=56/112$、action cache interval 5、visual selectionはTransformer第2層から。

# Main Results
**Table 2: SIMPLER Visual Matching（4 task平均）**

| 手法 | 平均成功率 | FLOPs（baseline比） | 速度 | パラメータ |
|---|---:|---:|---:|---:|
| CogACT | 74.8% | 100% | 1.00× | 7.63B |
| FastV | 74.1% | 42.0% | 1.21× | 7.63B |
| VLA-Cache | 74.4% | 80.1% | 1.38× | 7.63B |
| EfficientVLA (28 layers, 112 tokens) | 76.4% | 45.1% | 1.59× | 5.87B |
| EfficientVLA (22 layers, 56 tokens) | **74.2%** | **28.9%** | **1.93×** | **4.86B** |

Variant Aggregationではfull 61.3%に対し最小構成61.2% / 1.91×。モデルサイズ別ではSmall 0.2156→0.1173s、Base 0.2342→0.1213s、Large 0.2628→0.1312s（Table 3）。**FLOPs 28.9%は71.1%削減**であり、28.9%削減ではない。Table 1のモジュール時間の和とTable 3のend-to-end時間は測定区分が異なるため直接同一視しない。

# 主要ablation
- **Visual tokenのみ**：PickCanで0.2342→0.1866s（約1.25×）、成功率91.3→95.6%。ただしこれだけでは全体高速化が限定的。
- **Action feature cacheのみ**：0.2342→0.1909s（約1.23×）、成功率93.7%。
- **全要素（layer+MLP sparsity+visual+action）**：0.1213s（1.93×）、成功率93.3%（PickCanのablation設定）。主表の4 task平均74.2%とは別の集計。
- **Token budget**：256→112→56で速度は改善するが、56付近で飽和。Table 4の`Ratio=77.8%`は56/256の**保持率**ではなく**削減率**。
- **Action cache interval**：$N=1,2,3,4,5$でPickCanの時間0.2342→0.2031→0.1987→0.1953→0.1909s。成功率は91.3/94.0/93.7/90.3/93.7%と**単調ではない**。大きい$N$が常に品質維持に有利とはいえない。

# Limitations・再現上の注意
- **training-free ≠ model modification-free**。LLM layer削除・MLP sparsityはモデル構造・重みを変更する。事前学習・fine-tuningは不要という意味。
- action head cacheは**denoising step間の特徴近似**であり、フレーム間のVisual KV reuseではない。CacheBlend/ProphetKVの「選択tokenを再計算してKV修復」とも目的・時系列が違う。
- action intervalは固定であり、動きの激しい局面で動的にrefreshする設計ではない。LLM/vision/actionの各改変の組み合わせは実装依存。
- 主実験はCogACT/SIMPLER中心。実機・LIBERO・長時間動作・GPU memory peak・50Hz制御などの一般化を確認できない。
- 論文の一部ablation説明には`1.23×`と`1.25×`の丸め・設定差があるため、上表はTable 5の時間から算出。

# Taxonomy・技術的な位置付け
- **分類**：`KVcache/vla` / *multi-stage VLA inference acceleration*。内訳は**visual-token compression** + **structural layer pruning** + **within-denoising feature reuse**。
- [VLA-Cache](2025-2502.02175-vla-cache.md)：隣接**観測フレーム間**でvisual KVを再利用するのに対し、本手法のcacheは主に**1回のaction生成内のdenoising step間**。相補的だが、単純に効果を足し合わせることはできない。
- [VLA-Pruner](2025-2511.16449-vla-pruner.md)：semantic/action relevanceのずれを明示的に扱う。EfficientVLAはtask attentionとvisual diversityを使うが、過去action attentionは利用しない。
- [LAC](2026-2602.00686-lac.md)：learned policyでcross-frame visual KVの**再計算対象とreuse率**を動的決定。EfficientVLAはtraining-free heuristicで3段階を最適化する。
- [Reflex](2026-2607.14695-reflex.md)：flow timestep依存性を分離して**正しいKV reuse**を目指す。EfficientVLAは近似feature cachingで演算をskipする。
