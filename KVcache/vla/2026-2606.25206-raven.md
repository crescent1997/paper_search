# 概要
RAVENは長期観測をcaption化せず、フレーム／区間の視覚embeddingと位置・時刻を外部ベクトルDBへ保存する。質問に対しVLMが検索ツールを反復呼び出し、関連画像・場所を見つけて回答し、目標位置への移動を計画する。対象はロボットQAとナビゲーションであり、直接のaction-chunk予測を行うVLA policyではない。

# 問題設定・先行研究との差
画像をcaptionへ変換するReMEmbR等では、captionに言及されなかった色・形状・位置関係を後から検索できない。全動画をVLMに再入力すると長時間系列で費用が大きい。RAVENは視覚embeddingをそのまま索引化し、空間・時間メタデータと結びつける。固定容量recurrent stateとも、TransformerのKV tensorを保持・再利用する方法とも異なる。

# 手法
1. 探索時にRGB、depth、pose、timestampを取得し、SLAM等で地図を構築。
2. multimodal encoderでframe/segment visual embeddingsを計算し、pose/timeとともにベクトルDBへ格納。
3. 問い合わせ時にVLM agentがsemantic/spatial/temporal retrieval toolを複数回呼び出し、検索結果を推論に利用。
4. ナビゲーションでは推定した目的地座標をA*等のplannerへ渡す。探索時に対象を観測していなければ検索不能。

# Experiment Setup
- RAVEN-QA: 実世界4 scene（21 queries、10 seeds）、Habitatシミュレーション19 scene（157 queries、3 seeds）。
- FindingDory: 100動画、5,870 queries、平均1,794.2 frames/動画。長期subsetは10動画、596 queries、平均3,022.9 frames/動画。
- NaVQAも評価。視覚encoder QQMM-v2、Seed、SigLIP等、推論VLM Gemini/GPT/Qwen/Gemma等。
- 比較: caption-based ReMEmbR、VLM Only、Embedder Only、Random。
- 実機: Unitree Go1、ZED 2i、Jetson Orin NX 16GB。

# Main Results
| Dataset / 条件 | RAVEN | ReMEmbR | VLM Only |
|---|---:|---:|---:|
| FindingDory full / overall accuracy | 35.1% | 27.2% | 38.2% |
| FindingDory long subset / overall accuracy | 32.2% | 25.0% | 28.2% |
| RAVEN-QA real-world, Gemini-2.5-Flash + QQMM-v2 | 92.38±3.33% | 76.67±3.51% | 85.24±5.70% |
| RAVEN-QA simulated, Gemini-2.5-Flash + QQMM-v2 | 80.47±0.37% | 54.99±3.51% | 76.65±1.33% |

FindingDory fullではVLM OnlyがRAVENを上回る。したがって「常に最高精度」とは言えない。論文はraw-video保管との比較で250倍超のstorage compression、naive VLMに対し約10倍のretrieval efficiencyを報告するが、action latency/throughputの改善とは区別する。

# 主要ablation・感度分析
- embedding model（QQMM-v2 / Seed / SigLIP）とVLM backendの組合せで結果が変化する。open-source小型VLMでは低下が大きい。
- Appendix Bではtop-K、最大tool呼出回数、temperature、text-query対image-query retrieval、類似度スコアの付与、検索結果の時間順序を検討。
- top-Kを増やせば必ず良いわけではなく、検索ノイズとcontext costが増す。検索結果のchronological orderingが有効との分析。

# Limitations
- QA accuracyと実機navigation demonstrationが中心で、manipulation action success、control frequency、policy GPU VRAM、end-to-end action latencyの厳密な比較はない。
- ベクトルDB容量は観測量に応じ増加し、固定サイズ記憶ではない。外部検索・VLM tool loopのlatencyが残る。
- 事前探索で未観測の対象は検索できない。実機での長期間連続運用・忘却/更新/統合の効果は十分に検証されていない。
- VLMバックエンドやencoderが異なる結果の単純比較は避ける。

# Taxonomy / KV cacheとの関係
`KVcache/vla/` / **external visual episodic memory, retrieval-augmented navigation**。Transformer KV cacheのreuse、eviction、compressionを直接行わない。MEMやMemoryVLAのpolicy内memoryとは異なり、外部DBへの永続保存と検索が主軸。
