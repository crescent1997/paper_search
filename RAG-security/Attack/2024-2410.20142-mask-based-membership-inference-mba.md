# Mask-based Membership Inference Attacks for Retrieval-Augmented Generation

> **要点**：RAGの内部corpusを直接列挙・複製するのではなく、攻撃者が既に持つ候補文書がretrieval databaseに登録されているかを、穴埋め問題として確認する攻撃。文書を部分的に隠した状態でもretrieverが元文書を引けば、LLMはmaskされた固有名詞・専門語を正答できる。通常の質問応答よりもmembership signalを局所化する。

## 概要・研究上の位置づけ

RAGの非公開retrieval databaseに著作物、医療相談、個人記録などが格納されると、回答本文に秘密をそのまま表示しなくても、**ある文書が保存されているという事実**自体が漏洩する。Membership Inference Attack（MIA）は、候補文書 `d` がdatabase `D` に存在するかを推測する。これは、RAG-ThiefやGeoExのような未知文書の大量抽出（corpus reconstruction）とは異なる、**candidate-document existence leakage** である。

従来のRAG-MIAは「この文書がcontextにありますか」と直接問い合わせるため、LLMの自己申告に依存する。S²MIAは候補文書の前半から後半を生成させ、その一致度やperplexityを測るが、LLMが元から知っている一般知識や類似文書によってfalse positiveが生じる。通常のLLM向けloss / Min-k%型MIAも、retrieverが追加する外部知識を直接観測しないため、RAGではmembershipとscoreが対応しにくい。

MBAは、候補文書の大半をqueryに残したまま、**文脈だけでは当てにくい語を選んでmask** する。元文書がDBにある場合は類似queryが元文書をretrieveし、穴埋め正答率が上がる。元文書がなければ一般的な知識や別文書だけでは固有の語を当てにくい、という差をmembership signalに変換する。原論文は2025年のACM Web Conference（WWW '25）掲載論文であり、2024年公開のarXiv版も確認できる。

## 問題設定・Threat Model

### 保護対象と攻撃目的

- **資産**：RAGの非公開retrieval databaseに保存された文書のmembership。文書の内容そのものを未知の状態から取得することは主目的ではない。
- **攻撃者の事前情報**：判定したい候補文書 `d` の本文を保有する。候補文書を用いたqueryを作成できる。
- **利用可能なinterface**：通常の自然言語queryをRAGへ送信し、最終text responseを受け取るblack-box access。内部corpus、retrieverのscore、LLM weightは見えない。
- **操作権限**：corpusの書換え、model fine-tuning、system promptの変更は不要。候補文書の一部を伏せたquestionを構築する。
- **出力**：`member` / `non-member` の二値判定またはmask prediction accuracyに基づくscore。

対象文書がDBに存在しても、mask後のqueryがその文書を上位retrieveできなければfalse negativeになる。一方、対象がなくても、類似・重複文書や一般常識からmaskを予測できるならfalse positiveになる。したがって、攻撃性能は **retrieval recall × masked-token discriminativeness × generatorの穴埋め能力** に分解して考えると理解しやすい。

### Access requirementの比較

| 攻撃 | 候補文書 | victim内部へのアクセス | 主なsignal | 弱点 |
|---|---|---|---|---|
| RAG-MIA（Anderson et al.） | 必要 | 最終回答のみ | 「DBにあるか」の自己申告 | LLMのyes/noを信用しすぎる |
| S²MIA（Li et al.） | 必要 | 回答と設定によりlogprobs | 後半生成の類似度・PPL | 一般知識や近傍文書に影響される |
| Min-k% Prob | 必要 | token logprobs | 低確率tokenの統計 | retrieval由来のmembershipを分離しない |
| **MBA** | **必要** | **最終回答のみ** | **難予測maskの正答率** | maskの品質とretrieval recallに依存 |

この論文はRAGの**confidentiality**のうちmembership confidentialityを対象とし、corpusへの書込みによるintegrity attackではない。

## Method / Algorithm

### 全体pipeline

```text
候補文書 d
  │
  ├─ 語・専門用語の抽出 / fragmented wordsの再構成
  ├─ spelling correction
  └─ proxy LMで予測困難度（真の語のrank）を評価
          ↓
     M個のmaskを文書全体に分散
          ↓
  masked document + 穴埋めinstruction
          ↓
       Victim RAG
          ↓
  各maskの正誤を候補文書の原文と照合
          ↓
  accuracy > γ ならmember
```

ここで重要なのは、**queryを元文書に十分近く保ってretrievalを成功させながら、予測対象語だけを難しくする**という相反する要求を同時に満たすこと。無作為maskでもretrieval自体は成功しやすいが、ありふれた語ではmembershipと関係なく穴埋めできてしまう。

### Step 1: Fragmented words extraction

通常のsubword tokenizerや句読点で分割されたテキストでは、専門語や複合語が複数片に分かれる。個々の断片をmaskすると、残った断片から正答がほぼ自明になり、membershipを区別できない。MBAは単語の結合パターンを調べ、分割された専門用語・固有語をひとまとまりのmask候補に戻す。

この処理の役割は単なる前処理ではなく、**maskの難易度を人為的に下げる表層的手掛かりを除去する**ことにある。例えば医学用語の一部分だけを隠すと、隣接部分から単語を推定できるため、retrieved contextの寄与を測れない。

### Step 2: Spelling correction

実文書には誤字・表記揺れがあり、proxy LMがそれを極端な低確率語として高順位に置くことがある。MBAはspelling correction modelで誤記を検出し、補正後の語を用いて予測難易度を測る。これにより、単に誤字だから予測しにくい語を選ぶ偏りを抑える。

ただし、補正された語と原文の正答判定をどのように整合させるか、専門用語を誤って「訂正」しないかが実装上の注意点となる。

### Step 3: Proxy language modelによるmask選択

候補文書のprefixをproxy LMへ入力し、各候補語の**真のtokenの予測順位**を算出する。高いrank（正答候補がLMの上位に来ない）ほど、文書をretrieveできなければ当てにくい語として優先する。

単純なtoken probabilityではなくrankを利用するのは、model固有のprobability calibrationに強く依存せず、候補語間の相対的難易度を測るためと解釈できる。原論文ではGPT2-XL（1.61B）をproxy LMに使用する。fragmented wordsの場合は関連tokenのrankを統合する。

`M`個のmaskを文書全体へ偏りなく配置するため、文書を概ね`M`個の区間に分割し、各区間から難しい語を選ぶ。stop words、句読点、隣接maskなどを除外することで、単純な文法的穴埋めやmaskの密集を避ける。

この設計は、候補文書を丸ごとRAGへ投入するという点ではquery自体にかなり多くの情報を含む。したがって、**attackerが候補文書の全文を知っている**ことが本質的な前提である。

### Step 4: Black-box RAGへのqueryと判定

maskを含む候補文書を質問として入力し、各maskの元の語を回答させる。生成回答を元文書と照合し、`M`個のうち正答した割合を

\[
\mathrm{Acc}_{mask}(d)=\frac{1}{M}\sum_{j=1}^{M}\mathbf{1}[\hat w_j=w_j]
\]

とする。閾値`γ`に対し、`Acc_mask(d) > γ`（論文中の境界表現では「γMより多く正答」）ならmemberと判定する。これにより、最終回答だけで攻撃でき、retrieval scoreやLLM logprobsは必要ない。

### 成立条件とfailure mode

1. **Retrieval failure**：候補が存在してもmasked queryで検索されない。Mを増やしすぎる、documentが長すぎる、強いquery rewritingなどで起きうる。
2. **Predictability leakage without retrieval**：常識、同じ内容の公開情報、DB内の近傍文書からmaskが当たる。
3. **Exact-answer brittleness**：同義語、表記揺れ、複数の正解がある場合、厳格なexact-matchがfalse negativeを増やす。
4. **Candidate possession**：未知corpusの網羅抽出には直接使えない。大量の候補文書が既にある場合に、登録有無を選別する用途に向く。
5. **Rate limits / prompt constraints**：候補文書が長い、穴埋めinstructionを拒否する、同じ文書の送信を制限する環境では難しい。

## 先行研究からの改善点

### RAG-MIAからの改善

RAG-MIAはLLM自身に「この文書があるか」と聞くため、retrieverが該当文書を使ったか否かと、LLMが回答するyes/noの間にズレがある。MBAはモデルの**文書固有の語を予測する能力**を観測するため、LLMの自己申告ではなくtask performanceをsignalにする。

### S²MIAからの改善

S²MIAは前半の質問から後半の回答を生成させるため、正解が一般的な知識であると非memberでも類似回答を生成できる。MBAはproxy LMで**難しい語を意図的に選ぶ**ため、一般的な回答能力とretrieved documentへのアクセスを区別しやすい。また、queryの大半を原文として残すのでretrieval recallも高く維持しやすい。

### 後続研究との関係

- [Riddle Me This!](2025-2502.00306-riddle-me-this.md)：candidate documentから自然な質問を作り、複数queryの応答を集約するstealthy MIA。MBAは穴埋めの判別性を重視するのに対し、Riddle Me This!は質問の自然さを重視する。
- [E-MIA](2026-2605.00955-e-mia.md)：document-specificなexam-style queryを使う後続のblack-box MIA。MBAの「文書固有の知識を試験する」方向を、穴埋め以外の多様なquestion形式へ拡張したものと比較できる。
- [MEntA](2026-2605.24312-menta-five-queries-entailment.md)：5 queriesとatomic-claim entailmentで候補文書の存在を検出。MBAのmask-specificなquery形式とは異なり、自然なinformation-seeking queryと含意判定に寄せる。
- [Ensemble Privacy Defense（EPD）](../Defense/2025-2512.03100-ensemble-privacy-defense-epd.md)：RAG membership inferenceに対するinference-time defense。MBAを含むMIA系統のprivacy threatを考える際の防御側の関連文献。

## Experiment Setup

### Datasets / RAG構成

3種類のQA corpusを使用する。

| Dataset | 特性 | 評価上の意味 |
|---|---|---|
| HealthCareMagic-100k | 医療相談テキスト | 専門語や固有表現を含み、mask選択が重要 |
| MS-MARCO | Web検索QA | 大規模検索文書、queryとpassageの対応を検証 |
| NQ-simplified | Natural Questions派生 | 一般知識との重複によるfalse positiveを検証 |

RAG側のretrieval recallとMIAのROC AUCを分離して評価する。実験では既存のRAG-MIA、S²MIA、Min-k% Probなどと比較し、LLM-based mask generation、random masking等もablationで評価する。**本要約では確認できなかったretrieverやgeneratorの具体的なmodel IDを推測で補完しない。**

### Attack hyperparameters / 指標

- `M`（mask数）：`{5,10,15,20}`を探索し、ROC AUCが最大となる設定を選択。
- `γ`（正答率閾値）：`0.1〜1.0`を探索し、F1が最大となる設定を選択。
- proxy LM：`openai-community/gpt2-xl`（1.61B parameters）。
- spelling correction：`oliverguhr/spelling-correction-english-base`（139M parameters）。
- 主指標：**ROC AUC**（member / non-memberの識別力）、retrieval recall（mask queryが元文書をretrieveできる割合）。

注意点として、Mやγをdatasetごとに最適化している。完全な未知環境で同等の閾値が自動的に得られるわけではないため、calibration dataの可用性を実運用のattack feasibilityに含めるべきである。

## Main Results

### Membership inference performance

原論文のfull MBAに関するablation表（Table 2）では次の数値が報告される。これらは**同表に記載されたROC AUC**であり、別設定のbaseline数値を混在させていない。

| Dataset | Retrieval recall | MBA ROC AUC |
|---|---:|---:|
| HealthCareMagic-100k | 0.87 | **0.88** |
| MS-MARCO | 0.97 | **0.86** |
| NQ-simplified | 0.98 | **0.90** |

retrieval recallが高いだけでなく、memberとnon-memberで穴埋めの正答率に差が出ることが必要である。論文の導入部では、例示したmember / non-memberのmask正答率分布の平均が約0.9 / 0.2となり、既存MIAのsignalより明確に分離することを示している。ただしこの平均は全datasetの最終AUCではなく、分布可視化の例示である。

### Baselineとの違い

論文は既存RAG-MIA、S²MIA、一般LLMのMin-k% Probなどと比較し、MBAのROC AUCが高いと報告する。最も重要な説明は、**非memberに対しても正答可能な一般知識を避け、memberに対してのみretrieveされた文書から答えやすい語を選ぶ**点である。単にLLMの回答を長く生成させる攻撃とは異なる。

## Ablation / Robustness

### Mask選択のablation（Table 2）

| Dataset | Random | LLM-based | Proxy LMのみ | Spelling correctionなし | Full MBA |
|---|---:|---:|---:|---:|---:|
| HealthCareMagic-100k | 0.68 | 0.81 | 0.74 | 0.85 | **0.88** |
| MS-MARCO | 0.73 | 0.80 | 0.76 | 0.84 | **0.86** |
| NQ-simplified | 0.75 | 0.86 | 0.69 | 0.84 | **0.90** |

各数値はROC AUC。Random maskでも0.68〜0.75となり、穴埋めというprobe設計そのものに効果がある。Full MBAは0.86〜0.90で最良。Proxy LMのみだと0.69〜0.76へ低下するため、fragmented wordsの扱いとspelling correctionを含む**mask candidate preprocessing**が重要である。LLM-based mask選択も強いが、Full MBAはそれを上回る。

### 防御評価（Appendix D）

| Dataset | 防御なし | Prompt modification | Retrieved-document re-ranking | DB document paraphrasing |
|---|---:|---:|---:|---:|
| HealthCareMagic-100k | **0.88** | 0.85 | 0.86 | 0.75 |
| MS-MARCO | **0.86** | 0.86 | 0.86 | 0.81 |
| NQ-simplified | **0.90** | 0.89 | 0.90 | 0.83 |

各数値はROC AUC。Prompt modification（retrieved contentをそのまま繰り返すな）やre-rankingは、穴埋め正答の可否にほぼ影響しない。一方、database内文書のparaphrasingは元文書と一致する語を変えるため、AUCとretrieval recallを下げる。ただしparaphrasing後もAUCは0.75〜0.83であり、membership signalは残る。

この結果は**「verbatim出力の禁止」だけではmembership privacyを守れない**ことを示す。生成文が元文書を引用していなくても、答えられるかどうかでDBの存在を推定できるためである。

### Mask数・閾値・retrieval数の影響

論文は`M`、`γ`、retrieved document数、retrieverやLLM backboneの変更も検証している。一般にmask数を増やすと文書固有signalを増やせる反面、queryのretrievabilityや回答の正答率が下がりうる。閾値を高くするとfalse positiveを減らすがfalse negativeを増やすため、AUCと運用上のdecision thresholdを混同しないことが重要である。原論文で明示的な表から確認できない細かな改善率はここでは記載しない。

## Limitations / 論文の成立条件

1. **候補文書を知っている必要**：未知の全文書を回収するcorpus stealingとは違う。候補文書のリストを持つcopyright auditや特定記録の有無の確認に適する。
2. **LLMの穴埋め従順性**：mask queryに答えない、候補文書を長文入力できない、queryから原文の一部を削除するようなRAGでは性能が変わる。
3. **near-duplicate問題**：DBに候補そのものがなくても、意味的にほぼ同じ文書が存在すれば正答できる。厳密なdocument-level membershipとsemantic presenceを分ける必要がある。
4. **calibration dependence**：`M`と`γ`をdatasetごとに選ぶ。攻撃者がmember/non-memberのラベル付きvalidation setを確保できない場合、報告性能の再現性は未確定。
5. **privacyの単位**：ある文書があるかを推測できることと、その文書中のPIIやraw textを抽出できることは別の指標である。
6. **運用上の検知**：masked-document queryは自然な質問より人工的に見える場合があり、MEntAのような通常質問ベースのMIAより検知しやすい可能性がある。

## RAG Security Taxonomyでの位置づけ

| 軸 | MBA |
|---|---|
| 攻撃面 | RAG query interface（read-only） |
| 守るべき資産 | Private retrieval databaseの文書membership |
| Attacker capability | 候補文書全文、black-box text query/response |
| 必要な内部観測 | なし |
| 攻撃primitive | document-specific masking + answerability probe |
| 漏洩形態 | membership bit / score（raw document stealingではない） |
| 主な防御対象 | query/response leakage、retrieval-dependent membership signal |
| 代表的弱点 | near-duplicates、calibration、query長、mask回答拒否 |

## 実装・研究上の示唆

**RAG servingの観点**：入力に原文が含まれるだけでは、その原文がretrieval DBに登録済みかは判定できない。防御を設計する場合、単発のPII output filterだけでなく、同一ユーザーがcandidate documentを少しずつmaskして照合する行動を検知する、あるいはqueryごとのdocument-specific answerabilityを制限する必要がある。ただし、正当な教育・編集・校正用途の穴埋めqueryも存在するため、false positiveが課題となる。

**実験設計の観点**：今後のMIA benchmarkでは、(i) retrieverが候補を本当にretrieveしたか、(ii) member/non-memberのanswerability、(iii) near-duplicateを含むnon-member、(iv) low-FPR TPR、(v) benign queryへの影響を分けて測るとよい。MEntAなど後続のnatural-query MIAと比較する場合、query budgetだけでなく候補文書を入力へ貼り付けるかどうかも公平性に関わる。

**研究上の読みどころ**：MIAはしばしばmodel training-data membershipと混同されるが、本論文のmembershipは**retrieval databaseへの格納有無**である。RAGはgeneratorをfine-tuneしていなくてもmembership leakを生みうる点が本質である。
