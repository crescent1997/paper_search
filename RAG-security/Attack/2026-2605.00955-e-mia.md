# E-MIA: Exam-Style Black-Box Membership Inference Attacks against RAG Systems

> target document中の**検証可能なhard evidence**を、fill-in-the-blank / single-choice / multiple-choice / true-falseという自然なexam questionsへ変換する。black-box RAGの回答を客観採点し、複数questionのscoreを集約することで、特定documentがprivate retrieval corpusに含まれるかを推定するdocument-level membership inference attack。

## 概要

RAGではretrieval corpus自体がprivate assetになり得る。文書本文を直接抽出できなくても、「特定の医療文書・企業文書・研究資料がknowledge baseに存在する」というmembership bitだけでsensitive informationが漏れる場合がある。

既存RAG Membership Inference Attack (MIA)には大きく二つの問題がある。

1. semantic similarityやgeneration qualityのような**soft signal**は、LLMのparametric knowledgeやgeneralizationによってmember / non-member distributionsが重なりやすい。
2. target documentの存在を露骨に確認するprobeはmembership signalを強められる一方、malicious-input detectorやguardrailに検出されやすい。

E-MIAはmembership inferenceを「document-specific knowledgeについての試験」として再定式化する。target documentから客観的に正誤判定できるevidenceを多数抽出し、それを通常のQAに見える問題へ変換する。victim RAGがdocumentをretrieveできるなら高得点になり、含まれていなければ複数の細かなevidenceを一貫して答えることが難しい、という差をmembership signalとして利用する。

## 問題設定 / Threat Model

attackerはmembershipを調べたいcandidate document (d^*) の内容を保持している。これはmembership inferenceで一般的な前提であり、目的は未知corpus全体のreconstructionではなく、

[
d^* \in \mathcal{D} ?
]

を判定すること。

attackerが利用できるのはRAGの通常query interfaceとfinal textual responseだけである。

attackerは以下を観測できない。

- retrieval corpus (mathcal{D})
- retrieved passages / document IDs
- retriever similarity scores
- retriever parameters
- generator parameters / hidden states
- internal logs

さらにproduction settingを意識し、malicious-input detector、query rewriting、response rewriting、guardrailが存在する場合も評価する。

一方、attackerはtarget documentを既知としており、offlineでquestion generationを行うための外部LLMを利用できる。

## 先行研究からの改善点

[Riddle Me This!](2025-2502.00306-riddle-me-this.md) のInterrogation Attack (IA)は、target documentから自然なquestionsを作り、複数responseのcorrectnessを集約することでstealthyなRAG membership inferenceを実現した。

E-MIAはこの「natural interrogation」という方向をさらに**evidence-centric / objectively gradable**にする。

従来のsoft-signal MIAではresponseとtarget textのsemantic similarityなどを連続値scoreとして使うが、non-memberでもLLMが一般知識から似たanswerを生成するとfalse positiveになりやすい。

IAのようなnatural question attackに対しても、E-MIAはdocumentを複数のtyped hard-evidence unitsへ分解し、question formatごとの客観採点を行うことでscore varianceを減らす。

技術的には、

```
soft semantic similarity
        ↓
natural interrogation (Riddle Me This! / IA)
        ↓
typed hard evidence
        ↓
objective exam questions
        ↓
multi-question / multi-type aggregation (E-MIA)
```

という発展として整理できる。

## Hard-Evidence Extraction

E-MIAではtarget documentを単に要約するのではなく、**documentにmembership-specificな識別力を持たせるevidence units**へ分解する。

対象となるevidenceには、

- fine-grained factual details
- proper nouns / technical terms
- definitional statements
- metadata cues
- causal / constraint relations

などが含まれる。

重要なのは、一般的なtopic questionではなく、documentがretrieveされれば答えやすい一方、non-member RAGがparametric knowledgeだけで偶然答え続けることが難しいevidenceを選ぶこと。

各evidence (e_j) にはcanonical answerとgrading ruleを対応付ける。

## Exam Query Construction

抽出したevidenceから4種類のquestionを作る。

### Fill-in-the-Blank (FB)

document-specificな語句・数値・固有表現等をblankにし、exact answerを要求する。

free-form generationに近いが、canonical answerとのnormalized exact matchで採点可能。

### Single Choice (SC)

正答1つとplausible distractorsを用意する。

victim responseからoption identifierを抽出すれば客観的に採点でき、long-form response similarityを評価する必要がない。

### Multiple Choice (MC)

複数のcorrect optionsを含む問題。

単純なsingle-fact recognitionより複数evidenceを同時に検証でき、option setの一致としてscore化する。

### True / False (T/F)

document-specific statementが正しいかを問う。

通常のknowledge verification queryに近いため、membershipを直接尋ねるprobeより自然に見える。

## Exam Assembly / Validation

単にLLMが生成したquestionsをすべて利用するわけではなく、evidenceとの対応、answerability、objective grading可能性を確認してexamを構築する。

論文ではDeepSeek-R1 APIをExam Generatorとして利用し、question typeごとのprompt templateを与える。

この設計により各queryは一般的なreading-comprehension / knowledge-verification requestに見え、直接「このdocumentを持っているか」「retrieved contextを出せ」と要求しない。

## Objective Exam Evaluator

E-MIAの重要な点はvictim responseを別LLMの曖昧なsemantic judgmentだけで採点しないこと。

raw outputをnormalizeして会話的prefix、余分な空白、format noise等を除去した後、

- FB: normalized exact match
- T/F: normalized exact match
- SC: option identifier抽出
- MC: option set抽出 + set comparison

で採点する。

これによりmembership signalへjudge-model varianceを持ち込むことを抑える。

## Membership Score

examを

[
X_{d^*}=\{(q_i,a_i)\}_{i=1}^{N}
]

とし、victim response (r_i) を各ground-truth answer (a_i) に対して採点する。

question type (t) ごとのaccuracyを

[
Acc_t = \frac{1}{|X_t|}\sum_{(q,a)\in X_t}
\mathbb{I}[Score(r,a)=1]
]

とする。

最終membership scoreは、

[
S = 100\sum_{t\in\{FB,SC,MC,T/F\}} w_t Acc_t
]

としてaggregationする。

論文のcalibrated default weightsは、

- FB: **0.312**
- SC: **0.214**
- MC: **0.300**
- T/F: **0.174**

で、member / non-member score distributionのKL divergenceを用いたheld-out calibrationから決める。

default decision thresholdは **62.2**。

[
\hat m(d^*)=\mathbb{I}[S(d^*)\ge 62.2]
]

としてbinary membershipを判定する。

単一queryではなく複数evidence / question typesをaggregateすることで、retrieval missや偶然のparametric hitを平均化することが狙い。

## Experiment Setup

### Datasets

BEIRから異なる規模・domainの3 corpusを利用する。

- **NFCorpus**: biomedical、約3.5K documents
- **TREC-COVID**: biomedical、約23K
- **SCIDOCS**: scientific documents、約116K

corpus scaleを広げてもmembership signalが維持されるかを見る。

### Generators

- DeepSeek-R1-14B
- Llama-3.1-8B
- Qwen2.5-7B
- Gemma-2-2B

parameter scale / model familyを変えてtransferabilityを評価する。

### Retrievers

- BGE
- MiniLM-L6-v2
- text-embedding-3-small

異なるembedding spacesでもattackが成立するかを検証する。

### Baselines

主な比較対象は、

- S²MIA
- MBA
- Interrogation Attack (IA; Riddle Me This!)

など。

### Metrics

- Accuracy
- AUC-ROC
- AUC-PR
- TPR@FPR = 5%
- TPR@FPR = 1%
- TPR@FPR = 0.5%

特にprivacy attackではfalse positiveを低く抑えた領域が重要なため、低FPRでのTPRを重視している。

## Main Results

E-MIAは3 datasets × 4 generatorsで一貫して高いmember / non-member separabilityを示す。

### NFCorpus

DeepSeek-R1-14Bでは、

- Accuracy: **0.977**
- AUC-ROC: **0.995**
- AUC-PR: **0.994**
- TPR@1%FPR: **0.911**
- TPR@0.5%FPR: **0.817**

同条件のIAはAUC-ROC 0.914、TPR@1%FPR 0.523、TPR@0.5%FPR 0.254。

Llama-3.1-8BではE-MIAが、

- Accuracy **0.995**
- AUC-ROC **0.996**
- TPR@1%FPR **0.998**
- TPR@0.5%FPR **0.976**

を達成する。

### TREC-COVID

Qwen2.5-7Bでは、

- Accuracy **0.996**
- AUC-ROC **1.000**
- AUC-PR **1.000**
- TPR@1%FPR **0.997**
- TPR@0.5%FPR **0.996**

Llama-3.1-8BでもTPR@1%FPR **0.992**、TPR@0.5%FPR **0.982**。

### SCIDOCS

116K-document corpusでも性能は大きく崩れず、DeepSeek-R1-14Bで、

- Accuracy **0.985**
- AUC-ROC **0.998**
- TPR@1%FPR **0.976**
- TPR@0.5%FPR **0.954**

Llama-3.1-8BではAUC-ROC **0.999**、TPR@0.5%FPR **0.997**。

corpusが大きくなっても、document-specific hard evidenceを複数問うことでstrong membership signalを維持する。

## Low-FPR領域での改善

E-MIAの特徴はAUCの数ポイント改善より、**非常に低いFPRでTPRが大きく改善する**点にある。

NFCorpusの4 generators平均で既存best baselineに対する改善率は、論文報告でTPR@1%FPRが平均 **46.8%**、TPR@0.5%FPRが **117.8%**。

TREC-COVIDではそれぞれ **95.8% / 141.2%** の平均改善が報告される。

これはsoft score distributionsのoverlapをhard-evidence exam aggregationで縮めるという設計意図と対応する。

## なぜExam Aggregationが効くか

non-member RAGでも、一般知識やLLM pretraining knowledgeによって単一questionへ正答する可能性はある。

しかしtarget document固有の異なるevidenceを多数選び、

- exact detail
- relation
- terminology
- metadata
- definition

を横断して一貫して高得点を取る確率は低くなる。

逆にmemberの場合、queryごとにtarget documentがretrievedされれば各hard evidenceへ正答しやすい。

この**multiple independent-ish evidence pointsのaggregation**がmember / non-member score gapを拡大する。

## Question Type / Exam Length

論文はquestion compositionとexam lengthをablationする。

単一question typeだけでもmembership signalは得られるが、typeによってdiscriminabilityが異なるためweighted aggregationが有効。

FBとMCには比較的大きいdefault weightが与えられており、T/Fは偶然正答率が高くなりやすいためweightが小さい。

question数を増やすほどsingle-query varianceが平均化され性能は安定する一方、API query costは増加する。したがってE-MIAはexam lengthとattack budgetのtrade-offを持つ。

## Guardrail / Rewriting Defense Evaluation

production RAGを模擬し、

- query rewriting
- response rewriting
- PI-Guard
- Tanaos-Guardrail
- FT-Llama-Prompt-Guard-2

を含むsecurity layer下でも評価する。

E-MIAのqueriesはmembership確認やcontext extractionを露骨に要求せず、通常のQA / reading-comprehension形式なので、confirmation-style attackよりmalicious intentを検出されにくい。

またresponse rewritingが入ってもSC / MC / T/Fのようなobjective answer structureは比較的scoreを維持しやすい。

これはE-MIAが「秘密を出力させる」のではなく、「document-specific questionsへ正答できるか」をside channelとして利用しているため。

## Retriever / Model Transferability

BGEだけでなくMiniLM-L6-v2、text-embedding-3-smallへretrieverを変更し、generatorもDeepSeek / Llama / Qwen / Gemmaへ跨いで評価している。

attackが特定embedding geometryや単一LLM familyに依存せず、RAGに共通する

```
member document
   ↓
retrieval
   ↓
document-specific answerability improves
```

というbehavioral gapを利用していることを示す。

## Riddle Me This!との違い

両者ともcandidate documentを既知とし、natural questionsを複数投げるblack-box MIAである。

[Riddle Me This!](2025-2502.00306-riddle-me-this.md) のIAは自然なinterrogation queryとground-truth answerの一致をaggregateする。

E-MIAの主な追加点は、

1. documentをtyped hard evidenceへ明示的に分解
2. FB / SC / MC / T/Fの4形式へ変換
3. deterministic objective evaluator
4. question-type separabilityに基づくweighted score
5. low-FPR membership decisionを強く意識したcalibration

である。

したがって新しいaccess capabilityを追加するというより、**membership signalのmeasurement designを改善した後続手法**と見るのが適切。

## Data Extractionとの関係

E-MIAはtarget document本文をreconstructするattackではない。

attackerはcandidate documentを既に持っており、そのdocumentがprivate RAG corpusへ登録されているかという1-bit membership informationを得る。

したがって、

- [Connect the Dots / RAGCrawler](2026-2601.15678-connect-the-dots.md)
- [Feedback-Guided Extraction / CopyBreakRAG](2024-2411.14110-feedback-guided-extraction-copybreakrag.md)
- [Silent Leaks / IKEA](2025-2505.15420-silent-leaks-ikea.md)

のようなunknown knowledge-base reconstructionよりleakage量は小さい。

一方、「特定患者のrecordがある」「特定企業案件のdocumentがある」といった**existence privacy**ではmembership bit自体がsensitiveなので、confidentiality taxonomyでは独立に重要。

## Limitations / 成立条件

最大の前提はattackerがcandidate document (d^*) を既に保持していること。

未知KBをゼロから探索する用途には使えない。

またcandidate document中のfactsがpublic / common knowledgeとしてgeneratorのparametersに強く記憶されている場合、non-memberでも高得点となりfalse positiveが増える可能性がある。

near-duplicate / semantically equivalent documentsがcorpusに存在する場合も、「exact document membership」と「same evidenceを含むdocumentの存在」を区別しにくい。

逆にmemberでもretrieverがtarget documentをtop-kへ入れられなければfalse negativeになる。

exam questionsを増やすほどrobustになるがquery budgetとattack costも増える。

question generationには外部LLMを利用するため、generator qualityがpoorな場合はevidence specificityやdistractor qualityが低下し得る。

## RAG Security Taxonomyでの位置づけ

```
RAG confidentiality / privacy
  ├─ Corpus reconstruction / extraction
  │    ├─ RAGCrawler
  │    ├─ CopyBreakRAG
  │    └─ IKEA
  │
  └─ Membership inference
       ├─ soft-signal RAG MIA
       ├─ Riddle Me This! / IA
       │    └─ natural interrogation
       └─ E-MIA
            ├─ hard-evidence decomposition
            ├─ objective exam formats
            └─ weighted multi-question aggregation
```

E-MIAはprivate dataそのものを直接復元しないが、private corpusの**coverage / existence**を高精度に監査できてしまうprivacy leakage attackである。

## 実装・研究上の示唆

E-MIAから見ると、RAG privacy Defenseでは単発のmalicious prompt detectionだけでは不十分。

個々にはbenignなQAでも、同一candidate documentに関する細かなfactsをsession内で多数問い合わせることでmembership signalを統計的に増幅できる。

Defense候補としては、

- session-level semantic query aggregation
- repeated evidence-probing detection
- retrieval result / answer randomization
- private retrieval mechanisms
- query budget / rate limiting
- membership-specific auditing

などが考えられる。

またRAG privacy benchmarkではAUCだけでなく、**TPR@1%FPRやTPR@0.5%FPR**のようなstrict low-FPR metricsを重視すべきことも示唆する。
