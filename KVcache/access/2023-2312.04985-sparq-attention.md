# SparQ Attention: Bandwidth-Efficient LLM Inference

> KV cacheそのものを削除・圧縮するのではなく、**decode stepごとに実際にHBMから読むKVを疎にする**代表的手法。長context・large batchでattentionがmemory-bandwidth boundになることを直接狙う。

## 概要

autoregressive generationでは、各decode stepで過去tokenのK/Vを読み出してcurrent queryとのattentionを計算する。KV cacheにより過去tokenの再計算は避けられる一方、sequence lengthとbatch sizeが増えるほど毎step読み出すKV量が増え、attentionはcomputeよりmemory transferに支配される。

SparQ Attentionはattention weightが少数tokenへ集中することと、query vectorの少数dimensionがscore推定に強く寄与することを利用する。

full KVを最初から読むのではなく、

1. queryの重要dimensionだけで全Keyを粗くscore
2. score上位tokenを選択
3. 選ばれたtokenの完全なK/Vだけをfetch
4. 選択外Valueの寄与をrunning meanで近似

することで、dense attentionに近いaccuracyを保ちながらdata transferを減らす。

## 問題設定

通常のsingle-token decode attentionでは、head dimensionを d、context lengthを S とすると、各headでK/Vについて概ね S×d に比例するデータを毎step読む。

long contextではFLOPsよりHBM bandwidthがbottleneckになりやすく、KV cacheを「保存できるか」だけでなく、**毎token生成時に何byte読み出すか**がthroughputを決める。

SparQの目的はcache capacityを小さくすることではなく、queryごとに必要なsubsetだけをfetchしてmemory trafficを減らすこと。

## 手法

### 1. Queryの重要dimension選択

current query q の各dimensionの絶対値を取り、上位 r dimensionを選ぶ。

query vectorはheavy-tailedで、少数の大きなcomponentがdot-product attention scoreへ強く寄与する。この性質を利用し、全 d dimensionではなく r dimensionだけを使って各Keyとのscoreを近似する。

重要なのは、この段階では全tokenについてKeyの**選択dimensionだけ**を読む点である。

### 2. Approximate attention score

選択したquery dimensionと対応するKey dimensionから、context全体のapproximate attention scoreを計算する。

dimensionを減らしたことでscore scaleが変わるため、queryのnorm比に基づく補正を入れる。

このcoarse scoringにより「どのpast tokenがcurrent queryから高attentionになりそうか」を、full Kを読まずに予測する。

### 3. Top-k KV fetch

approximate score上位 k tokenを選び、そのtokenについてのみ完全なKey / Value vectorをmemoryからfetchする。

加えてrecent tokenのlocal windowを保持し、直近contextを安定して参照できるようにする。

その後、選択tokenのfull-dimensional Kを使って正確なattention scoreを再計算する。

したがってselection granularityは**token-level**、selection signalは**current query dependent**。

### 4. Mean Value approximation

top-k以外のtokenを完全に無視すると、小さいattention weightが多数集まった寄与を失う。

SparQはValueのrunning meanを保持し、selected tokensに割り当てられなかったattention massをmean Valueへ配分することでtail contributionを近似する。

これによりhard top-kだけの場合よりaccuracy低下を抑える。

## Memory transfer

dense attentionではK/Vのほぼ全体を毎step読む。

SparQでは主に、

- 全token × r Key dimensions
- top-k token × full K/V
- running mean等の小さい補助状態

だけを読む。

S が d より十分大きいlong-context regimeでは、rを小さくするほど全history scan部分のtransferを大きく削減できる。

論文ではattention data transferを最大 **8×削減**しながら、dense attentionに近いtask accuracyを維持できると報告する。

## Implementation上の重要点

理論的にread量を減らしても、non-contiguous gatherが遅ければ実speedupにはならない。

SparQではKeyをefficientに読むため、sequence方向とfeature/dimension方向のaccessを考慮したlayoutを使う。高速なgatherを可能にするためKeyを複数layoutで保持する構成では、論文が議論する実装上**約50%の追加memory overhead**が発生する。

したがって、

> 8× attention transfer reduction ≠ 8× KV cache capacity reduction

である。

SparQはcapacity compressionではなく、decode-time bandwidth optimizationとして評価する必要がある。

gatherとmatrix operationを融合してintermediate memory trafficを避けることも実装上重要。

## GQAへの適用

Grouped Query Attentionでは複数query headが同じK/V headを共有する。

SparQはquery group内の情報を集約してselectionを行うことでGQAにも適用できる。これはLlama 2だけでなくLlama 3、Mistral、Gemma等のmodern architectureへ適用範囲を広げる上で重要。

## Experiment Setup

Llama 2 / Llama 3、Mistral、Gemma、Pythia等を用い、long-context retrieval、question answering、summarization、memory系taskを含む複数downstream workloadでdense attentionとのquality差を評価する。

またalgorithmic transfer reductionだけでなく、GPU / CPU / Graphcore IPU上で実際のattention runtimeを測定し、memory-bandwidth削減がwall-clock speedupへつながるかを検証する。

modelのpretraining変更や追加fine-tuningは不要。

## Main Results

主要結果は、qualityを大きく落とさずattention data transferを最大 **8×削減**できること。

hardware implementationでは代表的に、

- NVIDIA GPU: 最大 **4.17×**
- CPU: 最大 **2.5×**
- Graphcore IPU: 最大 **7.41×**

のattention speedupを報告する。

理論的な8× transfer reductionが常に8× end-to-end generation speedupになるわけではなく、gather / top-k selection / dense layer等の残存costによって実speedupは小さくなる。

## 主要Ablation / trade-off

### r: query dimensions

rを小さくすると全Key scanのtransferは減るが、approximate score精度が落ち、重要tokenの選択missが増える。

したがってrはselection overhead / bandwidth / recallのtrade-offを制御する。

### k: selected tokens

kを増やすほどdense attentionに近づく一方、full K/V fetch量が増える。

long contextほどkをsequence lengthより十分小さく保てればbandwidth benefitが大きい。

### Local window

recent windowを追加することで、coarse scoreだけでは取りこぼしやすい局所dependencyを保護する。

### Mean Value

selected top-k以外のattention massをmean Valueへ割り当てることで、hard sparse attentionによるaccuracy lossを軽減する。

## H₂Oとの差

[H₂O](../compress/2023-2306.14048-h2o.md)もattention sparsityを利用するが、最適化対象が異なる。

| | H₂O | SparQ |
|---|---|---|
| category | compress | access |
| KV storage | tokenをevict | 原則保持 |
| selection | historical cumulative attention | current query |
| timing | cache management | each decode attention |
| 主目的 | memory capacity削減 | memory bandwidth削減 |
| old token recovery | eviction後は不可 | cacheに残っていれば次stepで再選択可能 |

SparQはqueryごとにselectionをやり直せるため、現在重要でないtokenを永久に捨てる必要がない。その代わり毎step coarse scoring / top-k selection overheadが生じる。

## GQAとの差

[GQA](../model/2023-2305.13245-gqa.md)はKV head数そのものを減らすmodel-level optimization。

GQAは保存量とread量を構造的に減らし、SparQは残ったKVのうちqueryごとに読むtokenを減らすため、両者は直交的で併用可能。

概念的には、

- GQA: **head axisを削減**
- SparQ: **sequence/token axisのaccessを疎化**

と整理できる。

## 後続access手法との位置づけ

SparQはtoken-level query-aware sparse fetchの初期代表例。

後続のQuest等ではpage/block単位のmetadataを用いてselectionを効率化する方向、RetrievalAttention等ではvector retrieval / CPU-GPU hierarchyを使って巨大KVから候補をretrieveする方向、DuoAttentionではheadごとにfull-history accessが必要かを分ける方向へ発展する。

共通する問題意識は、KV cacheを保存できても**decodeごとに全部読むのは高い**という点。

## Limitations

1. **KV capacity自体は基本的に減らない**。むしろ高速gather用layoutでmemory overheadが増える場合がある。
2. **selectionはfreeではない**。query top-r、coarse score、top-k、gatherが毎decode step必要。
3. **hardware依存性**が強い。random/sparse gatherが効率的でなければ理論的bandwidth削減をwall-clock speedupへ変換しにくい。
4. attention以外のMLP / projection等が支配的なsettingではend-to-end benefitが小さくなる。
5. extremely diffuseなattentionではtop-k approximationのaccuracy/transfer trade-offが悪化し得る。

## KV-cache taxonomyでの位置づけ

**access / query-aware selective KV fetch / token-level sparse attention / training-free**。

SparQは「KVをどれだけ保存するか」ではなく、

> **1 decode stepで、そのKVのうちどれだけをmemoryから読む必要があるか**

を直接最適化する。

このためcompressとは分離してaccessに置くのが自然。

## まとめ

SparQ Attentionはlong-context decodeのmemory-bandwidth bottleneckに対し、current queryの重要dimensionでattentionを粗く推定し、重要tokenのfull K/Vだけをfetchする。

中心componentは、

| Component | Role |
|---|---|
| top-r query dimensions | cheapな全history score推定 |
| approximate attention | top-k候補tokenを発見 |
| selective full KV fetch | HBM transfer削減 |
| local window | recent dependency保護 |
| mean Value | 非選択tokenのtail寄与を近似 |

最大8×のattention data transfer削減を、model変更・fine-tuningなしで実現する。KV compressionとは異なりcapacityを直接減らさない点と、selection/gather overheadを含む実hardware efficiencyを見る必要がある点が重要。
