# EPIC: Efficient Position-Independent Caching for Serving Large Language Models

> 同じdocumentやdemonstrationがrequestごとに異なるprefixの後ろへ現れる場合でも再利用できるよう、**Position-Independent Caching (PIC)** をsystematically扱う研究。

## 問題設定

prefix cachingはtoken列がrequest先頭から完全一致する場合に強いが、few-shot exampleやRAG documentは前に置かれるinstruction / query / 他documentが変わるためcache hitしにくい。

PICではcontent chunkを独立にcacheし、request時に任意位置へ組み込む。しかし独立計算したchunkには、本来のprefixとのattention interactionが存在しない。

## EPICの観察

position shiftだけならRoPE等を調整できるが、独立chunkの先頭tokenへattentionが過度に集中する**attention sink**が発生し、単純なposition-independent reuseのqualityを悪化させる。

EPICはこの現象を主要なerror sourceとして捉え、低costで補正する。

## Method: LegoLink

Legoのblockを組むようにindependently cached segmentsを接続する。各chunkをそのまま完全再計算するのではなく、chunk間interactionに必要な少量の追加計算を導入し、特にsegment beginningに生じるspurious attention sinkを緩和する。

設計目標は、
- cached contentをprefix位置に固定しない
- reuseのためにlarge-scale recomputationを行わない
- full recomputationに近いqualityを維持する
ことである。

## Experiment Setup

few-shot learningやRAG型promptを含む複数scenarioで、standard prefix cache、naive PIC、full recompute等と比較し、accuracy / TTFT / throughputを測定する。

## Main Results

full computationに近いqualityを保ちながら、最大約8×のTTFT改善、約7×のthroughput向上を報告する。特に同じimmutable chunkが異なるprompt位置で繰り返し使われるworkloadでreuse機会が増える。

## CacheBlendとの違い

CacheBlendはcached KVのうち重要tokenをselectively recomputeしてcross-chunk interactionを取り戻す。一方EPICはposition-independent reuse時に生じるsystematic artifact、特にattention sinkへ焦点を当て、より軽量なlinking mechanismを設計する。

両者ともprefix-only reuseを超えるが、repairの考え方が異なる。

## Limitations

- arbitrary compositionでfull prefillと内部stateが厳密一致するわけではない。
- model architecture / positional encodingごとにPICの成立性を検証する必要がある。
- chunk間に非常に強いtoken-level dependencyが必要なtaskでは、軽量linkだけでは不足する可能性がある。

## KV-cache taxonomyでの位置づけ

**modular / position-independent reuse**。RAGだけでなくfew-shot demonstrations、shared policy / tool descriptions、固定document blocks等にも適用可能なreuse class。

## 実装・研究上の示唆

KV reuseの制約は「同じtextか」だけではなく「同じprefix historyか」で決まる。position-independent cachingを実用化するには、RoPE re-positionだけでなくattention patternとsegment boundary artifactを観察する必要がある。
