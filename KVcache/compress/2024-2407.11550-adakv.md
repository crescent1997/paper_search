# Ada-KV: Optimizing KV Cache Eviction by Adaptive Budget Allocation for Efficient LLM Inference

## 概要
Ada-KVはKV evictionで各attention headへ同じcache budgetを割り当てる慣行を問題視する。headごとにattention distributionや重要token数が異なるため、uniform allocationではcapacityを無駄にするheadと不足するheadが生じる。eviction前後のattention output差の理論的upper boundを導出し、**head-wise adaptive budget allocation**を提案する。

## 問題設定
多くのKV compressionは各headでtop-k tokenを残すがkを全headで同じにする。attentionが数tokenへ集中するheadなら小さいkで十分だが、広く分散するheadでは同じkではattention massを大量に失う。Ada-KVは「どのtokenが重要か」に加えて**各headへ何個のtoken slotを与えるか**を最適化する。

## 理論的動機
KV evictionによるattention output変化を、evictされたtokenへ割り当てられていたattention mass等からupper-boundする。限られた総budgetでoutput perturbationを小さくするには、追加slotによって保持attention massを大きく改善できるheadへbudgetを寄せるのが自然になる。Ada-KVはtoken importance functionの置換ではなく既存importance scoreを利用したbudget optimizer。

## Adaptive head-wise allocation
```text
existing token importance → headごとのimportance distribution → adaptive budget allocation → head内top tokens保持
```
総cache budgetを固定したままheadごとのcapacityを可変にし、SnapKV + Ada-KV、PyramidKV + Ada-KVのようにplug-inできる。

## 既存法との差
| Method | 主に最適化するaxis |
|---|---|
| [SnapKV](2024-2404.14469-snapkv.md) | head内のtoken selection |
| [PyramidKV](2024-2406.02069-pyramidkv.md) | layer-wise budget |
| Ada-KV | **head-wise budget** |
| [DynamicKV](2024-2412.14838-dynamickv.md) | task-aware dynamic layer budget |

Ada-KVはPyramidKV/DynamicKVと直交的で、layer budget決定後に各headへさらにadaptive allocationする構成が可能。

## Experiment Setup
RULER 13 datasetsとLongBench 16 datasetsをquestion-aware / question-agnostic双方で評価。既存eviction method単体とAda-KV併用を比較する。公式実装はheadごとの可変cache lengthにflattened KV storageとFlashAttention varlen interfaceを利用する。

## Main Results
SnapKVやPyramidKVへAda-KVを組み込むことで、特に厳しいcache budgetでRULER/LongBench qualityが一貫して改善する。追加trainingなしで既存selectorを改善できることが重要。

## Ablation / Analysis
uniform allocationとの比較が中心。同一token scoringでもhead-wise adaptive allocationに変えるだけで性能が上がる。question-aware / question-agnostic双方で改善し、queryをimportance estimationへ直接使える場合だけに依存しない。

## Runtime / implementation
headごとに異なるcache lengthは通常のdense [heads, seq] layoutと相性が悪い。公式実装ではflattened storageとflash_attn_varlen_funcを組み合わせる。metadata管理、compaction、可変長kernel効率が実speedupを左右する。

## Limitations
- head-wise variable lengthを効率良く扱うruntimeが必要。
- allocationは元となるimportance score品質に依存。
- evictionは不可逆。
- 理論bound最小化とdownstream accuracyは完全には同一でない。
- scheduler/memory allocatorとのproduction統合は別途必要。

## KV-cache taxonomyでの位置づけ
**compress / eviction / head-wise adaptive budget / plug-and-play / training-free**。

```text
which tokens? → SnapKV等
how much per layer? → PyramidKV / DynamicKV
how much per head? → Ada-KV
```
