# TTF-VLA — Pixel/Attentionによる時間的Visual Token Fusion

## 1. 概要
連続観測フレームでは背景の多くが不変だが、gripper、把持対象、開閉するdrawerなどの小さな変化はaction成功を左右する。TTF-VLAは各patchに対し**現在の視覚tokenを採用するか、前フレームtokenを採用するか**を決めるtraining-freeな融合方式。画素差分だけではsemantic relevanceを取りこぼし、attentionだけでは微小な動きを取りこぼすため、2つの判定をORで統合する。一定間隔で全patchをrefreshして古い特徴の蓄積を抑える。**これはvisual embeddingの再利用であり、LLM全layerのK/V tensorをそのまま再利用してprefillを省く実装とは異なる。**

## 2. 問題設定と先行研究との差
観測画像 $I_t$、指示 $L_t$、7-DoF action $A_t$ を想定。通常のOpenVLAは毎時刻に全patchを再encodeする。VLA-Cacheは時間的に変化しないpatchのKVを選択的に再利用するのに対し、TTFは**LLMに渡すvisual token列を過去/現在で融合**する。VLA-Prunerのようにtoken数を減らす手法でもない。前フレームのattentionに依存するため、前回の推論が重要領域を見落とすと選択が不適切になる可能性がある（[The Gate, Not the Cache](2026-2608.00391-the-gate-not-the-cache.md)との関連）。

## 3. 手法
### 3.1 Hard fusion
各patch $i$ の現時刻embedding $t_t^{(i)}$ と前時刻embedding $t_{t-1}^{(i)}$ について、

$$\widetilde t_t^{(i)} = \begin{cases}t_t^{(i)} & m_i=1 \\ t_{t-1}^{(i)} & m_i=0.\end{cases}$$

現在のpatchを使用するmaskは $m_i=m_i^{\mathrm{pixel}}\lor m_i^{\mathrm{attention}}$。どちらか一方でも重要と判定されれば新しいtokenを使う保守的設計。

### 3.2 Pixel difference
RGBを輝度 $G_t=0.299R+0.587G+0.114B$ に変換し、14×14 patch内の平均絶対差を計算する。差分が閾値を超えたpatchを更新対象にする。長所は安価で微小な動きにも反応すること、短所は照明・影・カメラ揺れに敏感なこと。

### 3.3 Attention relevance
前時刻の選択layerのattentionから、text-to-vision（指示token→視覚patch）またはaction-to-vision（先頭action token→視覚patch）を集約する。top-kに入るpatchは画素変化がなくても更新する。**前時刻attentionを利用するため、現在時刻での追加のattention集計を回避**する。selection gateの情報源が前時刻のpartial forwardに依存する点には注意が必要。

### 3.4 Keyframe
$t\bmod K=0$ などの時刻では全patchを更新。これにより連続的な再利用で古い表現に固定されることを防ぐ。公開コード例では `keyframe_interval=3`, `patch_diff_threshold=0.03`, `attention_top_k=70`。これらはリポジトリの実行例であり、全実験の一律設定とは限らない。

## 4. Experiment Setup
- **Models:** OpenVLA-7B（LIBEROのsuite別finetuned checkpoint）、VLA-Cacheとの組合せ。SimplerEnvではtask-specific fine-tuningなしのOpenVLA-7B。
- **LIBERO:** Object / Spatial / Goal / Long各10タスク、各タスク20 episode、suiteあたり200 episode。主要指標はsuccess rateとfusion rate（前フレームから残すtokenの比率）。
- **SimplerEnv:** Move Near 240 episode、Pick Coke 300 episode、Drawer 216 episode。
- **Real robot:** Franka Research 3。Garlic / Pepper & Corn / Drawerの3タスク、各20 episode。80 demonstrations/task、5 Hz収集・評価、OpenVLA-7Bを20,000 stepsでfinetune。
- **Training:** TTF自体の追加学習は不要。ただしbaseline VLAのtask-specific finetuneは行われる。
- **Latency/VRAM:** 論文はTTFの追加runtime overheadが2%未満と記載。end-to-end速度向上倍率、GPU memory節約量、throughputは定量表として提示されていない。READMEではattention取得のためFlashAttentionを使用しない旨の注意がある。

## 5. Main Results
### 5.1 LIBERO (PDF Table 1, success rate %)
| Method | Object | Spatial | Goal | Long | Average |
|---|---:|---:|---:|---:|---:|
| OpenVLA | 66.5 | 82.0 | 77.0 | 48.0 | 68.4 |
| OpenVLA + TTF | 72.5 | 84.5 | 79.0 | 53.5 | **72.4** |
| VLA-Cache | 69.0 | 84.0 | 77.0 | 55.0 | 71.3 |
| VLA-Cache + TTF | 73.0 | 84.0 | 81.0 | 58.0 | **74.0** |

OpenVLAで+4.0 percentage points、VLA-Cacheとの併用で+2.7 points。OpenVLA+TTFのfusion rateはObject 44.6%、Spatial 41.2%、Goal 43.5%、Long 42.0%、平均42.8%。**fusion rate=KV削減率ではない**。Longは48.0→53.5（+5.5 points、相対+11.5%）。

### 5.2 SimplerEnv (PDF Table 2)
Move Near 49.4→52.1%、Pick Coke 17.0→18.7%、Drawer 33.3→33.8%。平均33.2→34.9%（論文表記+1.6 points、丸め前の値に依存）。同じTTFパラメータで別環境に適用。

### 5.3 Real robot (PDF Table 4)
Garlic 40→45%、Pepper & Corn 30→35%、Drawer 45→45%。平均38.3→41.7%（+3.3 points、相対+8.7%）。**5 Hzは制御設定であり、TTFによる制御周波数向上を意味しない。**

## 6. 主要Ablation
PDF Table 3：OpenVLA平均68.4%、pixel-only 70.4%、attention-only 71.3%、両方72.4%。Longに限るとpixel-only 52.5%、attention-only 56.5%、両方53.5%で、**複合方式が全タスクで常に最良というわけではない**。Pixel-onlyはfusion率が高い一方、Spatial/Goalでbaselineを下回る。Attention-onlyはLongに強いがObjectの改善幅は小さい。ORは全体平均を改善するがタスク別最適性には限界がある。Keyframe周期の独立した数値ablationは本PDFで明瞭に確認できず、数値を捏造しない。

## 7. Limitations / 批判的評価
1. **KV再利用の実測ではない。** 図はvisual encoderから現/過去tokenを取得し融合してLLMへ入力する。Algorithm 1でも非keyframe時にVisionEncoder($I_t$)を呼んでおり、encoder computeやLLM全layerのK/V計算を省く保証はない。AbstractのKQV reuseは将来方向の示唆であり実装済みの完全なKQV再利用と区別する。
2. Pixel差分は照明変化・camera pose変化に敏感。前時刻attentionに依存し、重要物体の急な出現や動きでgateが不正確になりうる。
3. Real-robotは3タスク×20 episodeで、長時間実行時の分布外環境・大規模成功率、エネルギー、GPU memoryを評価していない。
4. 実行コードはFlashAttention非使用を明記。VLA-Cacheとの組合せでGPU kernel実行時間とcache bandwidthを別途計測する必要がある。
5. 表に標準偏差/複数seedが示されておらず、数ポイントの改善の統計的頑健性は未確定。

## 8. Taxonomy / 技術比較
- **Category:** `KVcache/vla/` / temporal visual embedding fusion / action-aware token selection / training-free。
- **KV reuseとの差:** Token input融合 ≠ LLM per-layer KV reuse。VLA-Cacheとは併用可能だが、計算の節約は独立して検証すべき。
- **MemoryVLAとの差:** 長期エピソード記憶bankを構築せず、直前フレームのtemporal consistencyを利用する。
- **比較対象:** [VLA-Cache](2025-2502.02175-vla-cache.md)、[VLA-Pruner](2025-2511.16449-vla-pruner.md)、[DySta](2026-2602.03983-dysta.md)、[Gated VLA-Cache](2026-2608.10824-gated-vla-cache.md)。
