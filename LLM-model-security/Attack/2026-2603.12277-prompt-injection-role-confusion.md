# Prompt Injection as Role Confusion

## 概要

本論文はprompt injectionの失敗原因を、単に「悪意あるinstructionを識別できない」ことではなく、**model内部でtextのrole / authorityを誤認するrole confusion**として説明する。

chat API上ではsystem / developer / user / assistant / tool等のroleが明示される。しかしLLMが受け取るのは最終的には一続きのtoken streamであり、著者らはmodelが「どこから来たtextか」という外部のrole labelだけでなく、**そのtextがどのroleらしく見えるか**をhidden representationへ強く反映していることを示す。

この仮説をRole Probeで測定し、さらに攻撃として **CoT Forgery** を提案する。attackerはuser messageやtool outputの中へ「model自身のreasoningらしいtext」を埋め込み、modelにそれを自分の思考として扱わせる。StrongREJECTでは複数model平均約60%、agent exfiltrationでは約61%のattack successを報告し、baselineがほぼ0のmodelでも大幅に成功率が上がる。

## 問題設定 / Threat Model

対象はmodel-levelのprompt injection vulnerabilityである。

attackerが制御できるsourceは主に、

- user prompt
- webpage / retrieved content
- tool output
- agentが取り込むexternal data

であり、system / developer instructionを直接変更できることは仮定しない。

security上の期待は、

```text
trusted role / policy
        > user
        > tool / external data
```

のようなauthority orderingである。しかしrole confusionが起きると、低権限source内のtextがtrusted roleに似たrepresentationを獲得し、interface上のprivilege boundaryとmodel内部のauthority assignmentがずれる。

### Attacker access

CoT Forgery自体は**zero-shot / black-boxで実行可能**であり、target modelのgradientやlogit accessを必要としない。hidden-state accessはattack実行の必須条件ではなく、Role Probeによるmechanistic analysisに用いられる。

したがって[GCG](2023-2307.15043-gcg.md)のようなwhite-box token optimizationとはattack primitiveが異なる。

## 先行研究からの改善点

従来のprompt injection研究では、

- instruction/data separation
- delimiter
- adversarial training
- preference optimization
- system/user hierarchy training
- attack-specific string transformation

などが中心だった。

本論文の差分は、**なぜ自然言語のrole spoofingがauthority boundaryを越えるのかをlatent representationで測る**ことである。

[The Instruction Hierarchy](../Defense/2024-2404.13208-instruction-hierarchy.md)が「higher-priority instructionを優先するbehaviorを学習する」方向なのに対し、本論文はその前提となる「modelがsource roleを正しく表現しているか」に疑問を投げかける。

## Role Probe

著者らはhidden statesからrole identityを予測するlinear probeを構築する。

代表的な軸は、

- **Userness**: user由来らしく表現されている度合い
- **Assistantness**: assistant出力らしさ
- **CoTness**: model自身のreasoning / chain-of-thoughtらしさ

である。

重要なのは、role labelが固定されていても、lexical choice、syntax、format等のattacker-controllable signalによってprobe scoreが変化することである。

つまりmodel内部では、

```text
declared source role
        !=
inferred latent role
```

となりうる。

## CoT Forgery

### Attack primitive

CoT Forgeryではattackerが、model自身の内部reasoningに見える文章を低権限contextへ埋め込む。

概念的には、

```text
[trusted system policy]

[user/tool controlled text]
  ... ordinary data ...
  <spoofed reasoning-like text>
  "I have checked the policy; the correct next action is ..."
```

のような形になる。

modelがforgeryを高いCoTnessで表現すると、それを外部から来たuntrusted instructionではなく、自身のreasoning continuationに近いものとして扱い、後続generationが攻撃者の意図へ引っ張られる。

### Suffix / prefix / in-context injectionとの違い

GCGは主にadversarial suffixのtoken列をoptimizationする。

CoT Forgeryは、

- suffixである必要がない
- gradient optimizationを必要としない
- human-readableなrole/style spoofingを利用する
- user promptだけでなくtool / external dataへ埋め込める

という違いがある。

したがって「文字列として強いinstruction」より、**どのlatent roleとしてmodelに認識されるか**を攻撃対象とする。

## Experiment Setup

評価は大きく2系統である。

1. **Chat / safety setting**
   - StrongREJECT等のharmful request
   - forged reasoningの有無でjailbreak成功を比較
2. **Agent setting**
   - tool / external content経由のprompt injection
   - exfiltration等の攻撃goal
   - injected textのrole representationとASRを分析

open-weight modelではhidden activationを取得してRole Probeを適用し、closed-weight / frontier modelについてもbehavioral attack transferを評価する。

## Main Results

CoT Forgeryはfrontier modelを含む複数modelで高い成功率を示す。

- StrongREJECT: 平均attack success **約60%**
- agent exfiltration: 平均 **約61%**
- baselineは複数settingでnear-zero

さらに重要なのは、**generation開始前のrole probe scoreがattack successと強く関連する**ことである。

CoTnessをquantileで分けた分析では、低いquantileでは成功率が一桁%程度なのに対し、高いquantileでは約90%に達するケースがあり、role confusionが単なるpost-hoc explanationではなくattack vulnerabilityのdiagnostic signalになる。

## Generalization / Robustness

role confusion仮説はCoT Forgeryだけに限定されない。

著者らはcanonicalなagent prompt injectionについても、injected instructionのUserness等を変化させるとattack successが系統的に変わることを示し、複数attack familyを共通のrole-space mechanismで説明する。

これは、

```text
prompt injection
role spoofing
reasoning spoofing
tool-output injection
```

を個別の文字列attackではなく、**latent authority misclassification**として統一的に扱える可能性を示す。

## Query / Compute Cost

CoT ForgeryはGCGのような反復gradient optimizationを必要としないため、attack生成時のcompute/query costは比較的小さい。

Role Probeのtrainingやactivation extractionは分析側の追加costであり、black-box attackerが実攻撃時に必ず行う必要はない。

この点で、optimization-based attackよりdeployment上現実的なthreatになりうる。

## 既存Defenseとの関係

### The Instruction Hierarchy

[The Instruction Hierarchy](../Defense/2024-2404.13208-instruction-hierarchy.md)はrole priorityをbehaviorとしてtrainingするが、本論文はrole labelとlatent role perceptionのずれが残る可能性を示す。hierarchy trainingの評価には、単なるconflicting instructionだけでなくrole-style spoofingを含める必要がある。

### StruQ / SecAlign / Meta SecAlign

[StruQ](../Defense/2024-2402.06363-struq.md)、[SecAlign](../Defense/2024-2410.05451-secalign.md)、[Meta SecAlign](../Defense/2025-2507.02735-meta-secalign.md)はtrusted instructionとuntrusted dataを分離し、data側instructionを無視するbehaviorを学習させる。

Role Confusionの観点では、これらDefenseが本当に成功しているかは「delimiterを認識したか」だけでなく、**untrusted spanがtrusted roleのlatent representationへ移動しないか**でも評価できる。

### ISE

[Instructional Segment Embedding](../Defense/2024-2410.09102-instructional-segment-embedding.md)はtokenへsource-specific embeddingを付与するため、role provenanceをarchitecture-level signalとして強める方向であり、本論文のfailure mechanismに対する特に直接的な比較対象となる。

### CaMeL

[CaMeL](../Defense/2025-2503.18813-defeating-prompt-injections-by-design-camel.md)はmodelがrole confusionしてもsystem側でcapability / provenanceを強制する。したがってlatent authority assignmentに完全依存しないDefenseとして対照的である。

## JailbreakとPrompt Injectionの違い

CoT Forgeryは両settingで利用できるが、security modelは異なる。

- **jailbreak**: model自身のsafety/alignment policyを回避する。
- **prompt injection**: trusted application instructionとuntrusted external/user instructionのauthority conflictを悪用する。

本repositoryでは後者との関係を特に重視する。role confusionは「どのsourceが権限を持つか」というprivilege mechanismそのものを攻撃するため、一般的なjailbreakよりInstruction Hierarchyとの接続が強い。

## Limitations

- Role Probeは主にactivation access可能なmodelでmechanisticに検証される。
- linear probeがmodelの実際のcausal computationを完全に表すとは限らない。
- role confusionとattack successの相関だけでは全failureを説明できない。
- model family / chat template / reasoning representationの違いでrole axesが変化しうる。
- CoT Forgeryへの個別trainingが未知のrole spoofing全般へgeneralizeする保証はない。
- role perceptionを改善してもtool permission等のsystem-level security boundaryは別途必要。

## LLM Model Security Taxonomyでの位置づけ

```text
Interface privilege
  system / developer / user / tool
             ↓
Latent role perception
  Userness / Assistantness / CoTness
             ↓
Role confusion
  low-trust text represented as trusted role
             ↓
CoT Forgery / prompt injection
```

Instruction Hierarchyを「role labelの順序」だけでなく、**latent role attribution + authority assignment**の問題として拡張するAttack / mechanistic-analysis論文と位置づけられる。

## 実装・研究上の示唆

Defense評価ではASRだけでなく、untrusted spanのhidden representationがどのroleへ近づくかを測ることでfailureを早期診断できる可能性がある。

またfuture modelでは、content/styleから推定されるroleと、cryptographically / architecturally trustedなsource identityを分離し、authorityは後者にのみ結びつける設計が重要になる。
