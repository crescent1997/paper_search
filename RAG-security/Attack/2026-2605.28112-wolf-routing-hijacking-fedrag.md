# A Wolf in Sheep’s Clothing: Targeted Routing Hijacking in Federated RAG

> **Federated RAGで文書を検索する前のclient selectionを攻撃する**。攻撃者は他組織のprivate corpusを読めず、serverやrouterも変更しない。代わりに自分のclientが公開するsemantic profileだけを偽装し、標的queryを自分へ誘導する。著者はその影響を3種類のrouterと下流generationで評価し、過去の返却evidenceに基づいてclientのrouting scoreを重み付けするTASRを提案した。

## 概要

FedRAGはprivate corpusを各clientの手元に残すため、serverは各clientの文書全体を検査できない。代わりにclientが提出するsemantic profile（embedding、centroid集合、自然言語の説明など）を使ってqueryの送信先を選ぶ。この**profileと実際のcorpusの対応を検証できない**点が新たなtrust boundaryとなる。

通常のRAG knowledge poisoningは、既に検索対象となったcorpusやretrieved passagesにmalicious contentを混入させる。それに対して本研究は、検索に入る**さらに前段のsource-selection/routing**を狙う。標的分野の公開proxy textから作った偽profileを登録すると、実際にはその分野の根拠を持たないmalicious clientも上位へroutingされる。選ばれたclientはirrelevant / harmful / poisoned evidenceを返し、availability低下や回答誤りを引き起こせる。

論文は攻撃だけでなく、Trust-Aware Secure Routing（TASR）を提示する。TASRは返却された文書のquery relevance、登録profileとの整合性、他clientのevidenceとのagreementを観測し、clientごとのtrust weightをオンライン更新する。単なる文書フィルタではなく、**次回以降のrouting順位**を修正する防御である。

**重要なスコープ**：これはprivate knowledge baseの**直接抽出**を示す論文ではない。攻撃者がprivate documentsを取得した割合を測るものでもない。主眼はFedRAGのrouting integrityと、それに続くevidence poisoningである。

## 問題設定 / Threat Model

FedRAGのclient集合を $\mathcal C=\{c_1,\ldots,c_N\}$ とし、各clientがprivate corpus $\mathcal D_i$ を保有する。serverはその本文を読まず、clientから登録されたprofile $P_i=\Phi(\mathcal D_i)$ を受け取る。query $q$ に対してrouting score $S_i(q)=R(q,P_i)$ を計算し、上位 $K$ clientを $\mathcal T_K(q)$ として選択する。下流generatorは選ばれたclientの返すevidenceを使って回答する。

攻撃者ができることは以下のとおり。

- 悪意あるclient（1件または3件）を管理し、その**登録profileを任意に偽装**する。
- 選択後に自clientが返すevidenceを制御し、irrelevant / harmful / poisoned passagesを返す。
- 標的query domainに関する**公開proxy data**（標的queryの分布を近似するpassages）を使う。

できないことは、honest clientのprivate corpusの閲覧・改変、server/routerの重み変更、honest clientの乗っ取り、暗号機構の破壊である。すなわち**client登録権限とprofile操作権限が必要**であり、一般のquery-only black-box attackerとは異なる。

Routing Hijackingの成功条件は $\mathcal T_K(q)\cap\mathcal C_{adv}\ne\varnothing$ 。この**HR@K（Hijack Rate）**はmalicious clientがtop-Kに入ったqueryの割合であり、誤答生成率やdata leakage率とは区別する。下流への影響は、routingが成功した条件で別に評価する。

## 手法 / Algorithm

### 1. Offline semantic profile forgery

攻撃者は標的domainのproxy passages $\mathcal D_{proxy}$ を収集し、実際のclient corpusの代わりに $\widetilde P_i=\Phi(\mathcal D_{proxy})$ を登録する。proxyはhonest clientのprivate textと非重複でもよい。

**Embedding-based router**ではproxyのembeddingをmean poolingまたはK-Means centroidへ変換する。single-vector cosine routingについては、標的query embeddingの総和 $\bar q=\sum_j q_j$ に対し、unit-norm profile $p$ の総similarity $\sum_j p^\top q_j$ を最大化する解が $p^*=\bar q/\|\bar q\|$ になることをAppendix Bで示す。これはCauchy–Schwarzに基づく結果であり、mean profileが強い攻撃となる理由を与える。ただしこの最適性は**single-vector cosine objective**に限定され、K-Meansやneural routerに一般化した保証ではない。

**Neural router（RAGRoute）**では同様のtarget-domain centroidを登録するが、MLPがquery-client pairを採点するため、cosineより攻撃効果が抑えられる場合がある。

**LLM-based router（ReSLLM）**ではembeddingでなく自然言語source descriptionを登録する。広範な分野をカバーすると主張するuniversal-competence descriptionを使い、source selectorの誤信を誘う。

### 2. Online routing hijack and evidence manipulation

serverは通常どおり登録profileを比較して上位clientを選択する。悪意あるclientが選ばれた場合、攻撃者は下流generatorへ渡るevidenceを操作できる。論文では三種類のpayloadを分離評価する。

- **Harmful-content injection**：不適切な内容を含むevidenceによって、generatorに回答拒否を起こさせるavailability攻撃。
- **Missing-information**：必要な根拠を欠くevidenceを返し、回答不能やhallucinationを誘発。
- **Data poisoning**：もっともらしい偽根拠を返し、特定の誤答を誘発。

この二段階構造では、profile偽装が**routing access獲得**を担当し、payloadが**generation failure**を担当する。両者の成功率を混同しないことが重要である。

### 3. TASR: returned-evidence feedbackによるtrust-adjusted routing

防御側はclientごとに3つの状態 $u_i^{rel},u_i^{cons},u_i^{agr}\in[0,1]$ を持つ。

1. **Retrieval relevance**：返却evidenceと現在queryのsemantic similarity。宣伝した専門性に比べて役に立たないclientを下げる主信号。
2. **Profile consistency**：返却evidenceとclient登録profileの整合性。登録時の主張と返却内容の乖離を監視。
3. **Cross-client agreement**：同じqueryで選ばれた他clientの関連evidenceとの一致。孤立した主張を弱い補助信号として扱う。

trustは、cold-start係数 $s_i$、relevance重み $\alpha_r\ge1$、soft gate $g(x)=\delta+(1-\delta)x$ を用いて

$$
\tau_i=s_i(u_i^{rel})^{\alpha_r}g(u_i^{cons})g(u_i^{agr})
$$

と構成する。soft gateの $\delta>0$ はconsistency/agreementが一度低いだけでclientを完全排除しないための措置である。元router scoreを非負・順位保存の形に正規化した $\bar S_i(q)$ に対し、$\widehat S_i(q)=\bar S_i(q)\tau_i$ で再rankingする。既存のembedding routerやMLP routerを再学習する必要はない。

返却evidenceのfeedback $f_i^h(q)$ が同時に選ばれたclientの中央値 $\theta_h(q)$ より低いと $u_i^h\leftarrow\gamma u_i^h$、そうでなければ $u_i^h\leftarrow\min(1,\gamma_{rec}u_i^h)$ と更新する。uninformativeな信号はskipする。デフォルトは $\gamma=0.9$、$\gamma_{rec}=1.02$、warmup $W=50$、cold-start $s_0=0.7$、1 clientあたりfeedback documents $m=5$、routing size $K_{route}=3$。

**TASRはそのqueryに既に返ったpoisonを消せない**。feedbackで次回以降のsource-selectionを修正する仕組みであり、同一clientが繰り返し使われる運用に向く。

## 先行研究からの改善点 / 技術的系譜

| 先行技術 | 前提・弱点 | 本論文が変えた点 |
|---|---|---|
| [PoisonedRAG](2024-2402.07867-poisonedrag.md)などcorpus poisoning | 攻撃文書が対象corpusに混入し、検索段階へ入ることを前提にしがち | **pre-retrieval client selection**自体を操作し、どのclientがevidenceを供給できるかを攻撃 |
| [MIRAGE](2025-2512.08289-mirage.md)、[RIPRAG](2025-2510.10008-riprag.md) | retriever/generatorへのpoisoned contentの到達率や効果を最適化 | 個々の文書の最適化ではなく**source profile forgery**によるrouting access獲得 |
| C-FedRAG、HE routing | queryやprofileの**confidentiality**を暗号で守る | 暗号化しても偽profileの類似度順位は変わらないことを実証し、**integrityとconfidentialityを区別** |
| Krum / coordinate-wise Median / Trimmed Mean | FLのmodel updateに対するoutlier / Byzantine耐性 | 異質なdomain profileを単純に外れ値除去しても不十分。返却evidenceの**behavioral feedback**を使う |
| [RAGSentinel](../Defense/2026-2608.23965-ragsentinel.md)、[TRIS](../Defense/2026-2609.00470-tris.md) | 主にretrieved passagesのpoison検出・除去 | 競合というより補完関係。TASRは**どのsourceを選ぶか**、両者は**選ばれたsourceから何を採用するか**を扱う |

特にTASRの「source reputation」は、[RAGCrawler](2026-2601.15678-connect-the-dots.md)や[AGEA](2026-2601.14662-agea-graphrag-extraction.md)のような**外部query-only extraction**を直接防ぐ仕組みではない。攻撃者がclientを登録できない場合にはRouting Hijackingのthreat model自体が成立しない。

## Experiment Setup

### Routing-level evaluation

- **Embedding routing**：StackExchange Q&Aを20-clientへ分割。Gaming、GIS、Physicsを標的domainとする。single-domain / multi-domain、mean / K-Means profileを比較。embeddingは`bge-base-en-v1.5`、768次元、FAISS cosine routing。各client最大30,000 documents。
- **Neural routing**：RAGRoute-style MLP。20-client構成を使い、centroid forgeryとrandom-profile controlを比較。generation experimentではpayloadに応じたRGB-native routerも使用。
- **LLM-based routing**：ReSLLMとFedWeb-2013。157 legitimate sources + 3 malicious sources。universal-competence descriptionでsource-selectionを操作。
- **攻撃条件**：基本は100 non-overlapping proxy passages。1または3 malicious clients。proxy data size、domain混入率、client topologyを変化させる。
- **指標**：HR@1/2/3（malicious clientのtop-K侵入率）、Acc@K（honest target-domain clientがtop-Kに含まれる率）、malicious rank。

### Generation / medical stress test

HarmBench（harmful-content）、RGB（missing-information / poisoning）、MedQA-USMLE（medical routingと偽医療根拠の生成影響）を使用。主generatorはQwen3-4B-Instructで、temperature 0.7、top-p 0.8、top-k 20。MedQAではQwen3-4B/8B/30B-A3B、Llama-3.1-8B、MedGemma-1.5-4Bを比較する。MedQAのproxyはtrain、評価queryはtestから取り、honest private corpusと非重複にする。

**解釈上の注意**：生成失敗率は多くの場合「routing hijackが成功し、poisoned evidenceが入った条件」の評価であり、routing成功確率を掛けたend-to-end率ではない。またMedQAの医療検証はpublic benchmark上のcontrolled stress testで、実病院のFedRAG導入実験ではない。

## Main Results

### 1. 三種類のrouterでprofile forgeryが成立

| Router / 条件 | Malicious clients | HR@1 | HR@3 |
|---|---:|---:|---:|
| Embedding, Gaming | 1 | 22.0% | 91.0% |
| Embedding, Gaming | 3 | 55.0% | 95.0% |
| Embedding, GIS | 3 | 47.0% | 86.0% |
| Embedding, Physics | 3 | 58.0% | 94.0% |
| RAGRoute, centroid | 3 | 7.3% | 32.0% |
| RAGRoute, random profile | 3 | 0.0% | 0.3% |
| ReSLLM, universal description | 3 | 73.0% | 97.0% |

Embedding-based source-selectionは偽のtarget-domain profileに強く影響される。neural routerはこの条件では相対的に低いHRだが、random-profile baselineとの差からtarget-domain情報が有効であることが分かる。LLM source selectorも自然言語の過大な専門性主張に弱い。**異なるdataset・router条件を横断した値なので、単純な同条件の頑健性順位ではない。**

### 2. Routing成功後の下流影響

| Router / K | Harmful-content拒否率 | Data-poisoning誤答率 |
|---|---:|---:|
| Embedding / K=1 | 96.3% | 66.7% |
| Embedding / K=3 | 74.7% | 30.8% |
| RAGRoute / K=1 | 100.0% | 83.4% |
| RAGRoute / K=3 | 61.2% | 57.7% |

Kを増やしてhonest evidenceが混在すると一部の失敗は減るが、malicious evidenceの影響は残る。harmful-contentの高い拒否率は「危険な出力を生成した」ことではなく、**通常の質問への回答を拒否させるavailability障害**である。

### 3. Medical routing / poisoned generation

MedQA-USMLEで15 non-medical + 3 honest medical + 3 malicious clientsを置き、100件の医療proxy passagesを使うと、偽医療profileはHR@1 **32.3%**、HR@3 **75.1%**を達成し、honest medical clientのMedAcc@1は100.0%から**67.7%**へ低下する。random / non-medical profileではHR@1が0%だった。

誤った医療根拠がgeneratorに入った条件では、Llama-3.1-8BのASRが**82%**、MedGemma-1.5-4B **76%**、Qwen3-4B **68%**、Qwen3-8B **74%**、Qwen3-30B-A3Bでも**44%**。強いモデルは単純な偽情報追従だけでなくsycophancyなど別の形で誤る。これらは**医学的な安全性一般の推定値ではなく、構成したpoisoned-context stress testの値**である。

### 4. TASRのオンライン防御性能

Embedding routing、500-query stream、multi-domain K-Means profile、$K_{route}=3$の条件。

| Malicious clients | Defense | HR@1 ↓ | Acc@1 ↑ | Warmup後HR@1 ↓ |
|---|---|---:|---:|---:|
| 1 | None | 35.6% | 51.0% | 36.1% |
| 1 | Relevance-only | 3.5% | 96.2% | 0.0% |
| 1 | Full TASR | **3.5%** | **95.2%** | **0.0%** |
| 3 | None | 64.9% | 24.5% | 65.9% |
| 3 | Relevance-only | 5.8% | 94.0% | 0.0% |
| 3 | Full TASR | **5.7%** | **93.5%** | **0.0%** |

この条件では**relevance-onlyでも改善の大部分を得られる**。Full TASRのconsistency/agreementはtop-3順位やtrust separationを補助するが、追加しただけで劇的なtop-1改善が得られるわけではない。

RAGRouteへのtransferでは、3 malicious clientsのオンライン条件でHR@3が**96.8% → 49.7%**、Acc@3が**92.1% → 97.6%**へ変化。static RAGRoute評価の32.0% HR@3とは**異なるonline protocol**であり、直接比較してはいけない。

## Ablation / Robustness / Defense Evaluation

### Proxy dataとclient topology

- 1 malicious clientのembedding routingでは、clean proxyを25→100 passagesに増やすと、3 domain平均のHR@1が**10.9%→39.5%**へ上昇。3 malicious clientsでは**25.8%→65.7%**。単なるrandom profileでは同様の改善は得られない。
- Multi-domain clientは各profileの専門性が薄まり、偽のtarget-domain profileが相対的に目立つ場合がある。K-Meansによる複数centroidは局所構造を多少維持する。
- Proxyにtarget-domain以外の文書を混ぜても一定の攻撃効果が残る。実際のprivate corpusそのものを盗む必要はない。

### 暗号化routingとByzantine baselines

- CKKSによるHE routingでは、plaintextとencryptedのHR@1/2/3がともに**33.2 / 81.7 / 93.7%**で完全に同じ。**秘密性を守る暗号化は、誤ったprofileのrankingを修正しない**。
- Krumは偽profileが明確なoutlierなら検出できるが、target/general proxyを混ぜるadaptive attackでは、mixing ratio 0.5で検出を回避しつつHR@1 **44.4%**となる。
- Median / Trimmed Meanも異質なprofileの混合には弱く、たとえばmixing ratio 0.5でHR@1はNo Defense **68.4%**、Median **68.6%**、Trimmed Mean **67.7%**。

### TASRのcold-start・ablation・計算コスト

- 3 malicious clientsでwarmupを$W=0/50/100$と変えると、overall HR@1は**0.37 / 5.68 / 10.7%**。warmup後はすべて0%だが、初期の漏れ・誤routingを無視できない。
- Full TASRの追加計算は、20 clients、3 routed clients、各5 returned evidence、事前計算済みembeddingを使う条件で**平均0.205 ms/query、P95 0.373 ms**。base routingを含めて平均0.350 ms。**embedding計算、実際のnetwork retrieval、LLM generationの時間は含まない**。
- Persistent stateはclientあたり4 scalars程度。計算量はnaiveなagreement比較が $O(K_{route}^2m^2)$、client score reweightingが $O(|\mathcal C|)$。
- Clean no-attack repeated-query設定でもTASRのAcc@1は改善したが、これは実験したrouting/feedback条件に依存する。一般にaccuracyが改善する保証ではない。

## Limitations / 成立条件

1. **Attackにはmalicious clientの登録・profile提出権限が必要**。通常ユーザが公開APIへqueryするだけでは実行できず、RAGCrawler等のblack-box extractionとは攻撃面が異なる。
2. **Profileとlocal corpusの対応をserverが独立検証できない**FedRAGを前提とする。署名付きprovenance、検証可能なindex、trusted attestationなどを持つ構成は本論文の評価外。
3. **TASRは過去の返却evidenceを必要とする**。初回・warmup中の攻撃や使い捨てclientには弱く、online trust accumulationを前提とする。
4. Relevance/consistency/agreementは**真偽検証ではない**。queryに関連したもっともらしい偽文書、複数malicious clientsの協調、agreementを偽装するadaptive attackerへの完全な耐性は示されていない。
5. 20-client StackExchange、FedWeb-2013、MedQA-USMLE等のcontrolled benchmarkが中心。実際の企業間FedRAGや巨大なclient集合、動的client入退場、長期攻撃への外挿は未検証。
6. **HR@Kと下流poisoning ASRは別metric**。これらを掛け合わせない限りend-to-end riskを表さない。特にmedical poisoning実験はrouting成功後のconditional evaluationである。
7. **Private corpus extractionの実験はない**。機密文書の復元率、retrieved chunksの逐語漏洩率、membership inference AUCなどを評価していない。

## RAG Security Taxonomyでの位置づけ

**Category: Attack（pre-retrieval routing integrity / source-selection hijacking）**。Threat Modelは「malicious federated clientが自身のsemantic profileと返却evidenceを制御」。攻撃対象はretrieverの検索結果そのものより前の**client selection**で、primary objectiveはintegrity/availabilityである。ConfidentialityはFedRAGの設計背景だが、本論文の攻撃は直接のdata exfiltrationではない。

DefenseのTASRはclient trustを更新する**post-routing feedback → next-query pre-routing reweighting**という位置にあり、retrieved passageをfilterする[TRIS](../Defense/2026-2609.00470-tris.md)や[RAGSentinel](../Defense/2026-2608.23965-ragsentinel.md)と組み合わせる余地がある。Private corpus stealingを防ぐ[CanaryRAG](../Defense/2026-2604.10717-canaryrag.md)、[RAGFort](../Defense/2025-2511.10128-ragfort.md)とは目的が異なる。

## 実装上・研究上の示唆

- FedRAGでは、**privacy-preserving retrievalが成立してもsource integrityは成立しない**。暗号化やローカル保存だけでなく、client profileの正当性と返却evidenceの整合性を別に検証する必要がある。
- Retrieval pipelineのtrust boundaryを「corpus → retriever → generator」だけでなく、**client enrollment → profile registration → source routing → document retrieval → generation**に拡張して評価する価値がある。
- TASRは軽量なonline reputation layerとして実装できるが、**初回の被害を防げない**。新規clientのcold-start制限、evidence provenance、query-time passage verificationとの併用が現実的。
- Research gapは**adaptive coordinated malicious clients**、正しそうに見える偽evidence、dynamic client churn、multi-turn query extractionとrouting manipulationの複合攻撃。ここでのextraction riskは未評価なので、RAG knowledge-base stealing研究と接続する際は独立した実験設計が必要。
