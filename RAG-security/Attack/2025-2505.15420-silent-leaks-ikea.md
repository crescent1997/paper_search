# Silent Leaks: Implicit Knowledge Extraction Attack on RAG Systems through Benign Queries

> Input/output filteringで検知しやすいprompt injectionやjailbreakを避け、自然な通常queryだけを反復してRAG内部knowledgeを盗む **IKEA (Implicit Knowledge Extraction Attack)** を提案する。

## 概要

既存のRAG extraction attackは、retrieved documentをそのまま出力させるprompt injectionやjailbreakを使うことが多い。そのため、malicious intent detectionやoutput overlap detectionで比較的検知しやすい。

IKEAはこの前提を変え、attackerが普通のuserと同じようなbenign queryだけを送信しても、RAG responseに含まれるsemantic knowledgeを積み重ねれば内部knowledge baseを大規模に再構成できることを示す。

## Threat Model

attackerはblack-box RAGのinput-output interfaceのみを利用する。

- retriever / embedding model / LLM parameterは未知
- knowledge baseのraw documentは取得できない
- query-response historyは保持できる
- 基本設定ではRAGの大まかなtopicのみ既知

目的は限られたquery budgetでknowledge baseのcoverageを最大化することである。

## IKEA

### Anchor Concepts

RAG topicに関連するkeyword群をanchor conceptsとして初期化する。

anchor conceptから自然なinformation-seeking queryを生成し、そのqueryによってsemantic neighborhoodのknowledgeを取得する。

### Experience Reflection Sampling

過去のquery-response historyを利用し、RAG knowledgeと関連しなかったanchorやrefusalを引き起こしたanchorのsampling probabilityを下げる。

これにより、query budgetを無関係なsemantic regionへ浪費しない。

### Trust Region Directed Mutation

有望なanchor conceptをsimilarity constraintの範囲内で少しずつ変異させる。

既知regionの周辺を効率よくexploitしながら、同じknowledgeを繰り返しqueryしないよう探索を進める。

## なぜstealthyなのか

IKEAのqueryは、

- contextを出力せよ
- system promptを無視せよ
- documentをJSONで返せ

といったdirectiveを含まない。

そのためinput-level malicious prompt detectionをすり抜けやすい。またresponseもraw chunkのverbatim copyではなく自然なQA answerなので、output-document overlapによる防御にも強い。

## Experiments

healthcare、storybook、Pokémon系datasetなど複数domainで評価し、LLaMA-3.1-8B-Instructやcommercial LLMを含むRAG systemを対象とする。

主要指標にはExtraction EfficiencyやAttack Success Rateを使用する。

## 主な結果

- input / output defense下でもIKEAは既存baselineより大幅に高いextraction performanceを維持する。
- 論文では複数設定で90%前後以上のASRを報告する。
- healthcare settingなどでは高いknowledge coverageを達成する。
- topicを知らないweaker-assumption settingでもattackが成立する。
- adaptive defenseに対しても一定のrobustnessを示す。

## Substitute RAG

IKEAで抽出したknowledgeからattacker側のsubstitute RAGを構築し、QA / MCQ taskで評価する。

重要なのは、単純なtext overlapだけでなく、**盗んだknowledgeがdownstream taskでどの程度original RAGを代替できるか**を測っている点である。

実験ではIKEA由来のsubstitute RAGがbaseline attackより高い性能を示し、original RAGへ近いutilityを持つケースが確認される。

## Defenseへの示唆

従来の防御はsingle-query maliciousnessへ偏っている。

IKEAは各query自体をbenignに保つため、今後は、

- multiple-turn query trajectory
- semantic coverageの拡大速度
- repeated exploration pattern
- query-response history全体

を見る必要がある。

つまりRAG extraction defenseはstatic prompt filterだけでは不十分で、behavioral / session-level detectionが重要になる。

## RAG Data Extraction Riskとの関係

今回の調査テーマに非常に直接的である。

RAG-Thief / CopyBreakRAGやRAGCrawlerがretrieved chunkの再出力やfeedback-guided traversalを中心とするのに対し、IKEAは **verbatim leakageを要求しなくてもsemantic knowledge extractionが成立する** ことを示す。

これは、output sanitizationだけではknowledge theftを防げないことを意味する。

## Limitations

- RAGのtopicに関する一定のprior knowledgeを基本設定で仮定する。
- responseから得られるsemantic information量はgenerator behaviorに依存する。
- exact document reconstructionよりsemantic knowledge recoveryを重視するため、既存verbatim extractionとmetricの意味が異なる。
- high coverageには多数のadaptive queriesが必要となる。

## 重要なポイント

- benign-looking queryのみでRAG knowledge extractionを行うstealthy attack。
- Experience Reflection Samplingで無駄なsemantic regionを避ける。
- Trust Region Directed Mutationでanchor conceptsを逐次変異させる。
- input maliciousness detectorとoutput overlap detectorの両方を回避しやすい。
- substitute RAG構築まで評価し、盗んだknowledgeの実用価値を示す。
- defenseにはsingle-query filteringよりsession-level behavioral monitoringが必要。
