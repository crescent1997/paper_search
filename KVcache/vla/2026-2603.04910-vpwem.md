# VPWEM — Working/Episodic Memoryによる非Markov制御

## 1. 概要
過去の観測が見えなくなっても、何をどこに置いたかを記憶しなければならないrobot manipulationは部分観測POMDPとして扱える。単純に過去の全frameを入力すると計算量・GPU memoryが増え、過去actionのcopycat/causal confusionも発生する。VPWEMは**短期working memory**と**固定数のepisodic summary**を分離し、窓外の観測を再帰的に圧縮する。Diffusion Policy（DP）とMaILへ統合し、追加学習を行う。

## 2. 問題設定と先行研究との差
観測 $o_t$ に対する理想的な方策は $\pi_\theta(a_t\mid o_{0:t})$。通常の短期context方式は $\pi_\theta(a_t\mid o_{t-L+1:t})$ で古い観測を忘れる。DP-PTPは長いcontextを保持するが、その分のinference時間とVRAMが増える。MemoryVLAはperceptual-cognitive bankから関連情報を検索するのに対し、VPWEMは**古い観測を固定個数のlearned summaryに逐次consolidation**する。大規模VLMを毎回呼び出す方式より軽量な設計で、今回の実験は一般のVLA foundation modelを直接高速化したものではなく主にDP/MaILのmemory extensionである。

## 3. 手法
### 3.1 Working memory
マルチカメラRGBDとproprioceptionをencodeして $o_t\in\mathbb R^D$ を得る。短期windowは $w_t=[o_{t-L+1},\ldots,o_t]\in\mathbb R^{L\times D}$。FIFO更新で長さ $L$ を一定にする。

### 3.2 Episodic memoryの2種類のcache
窓から追い出されたframeを位置埋め込み付き $f_\tau=o_\tau+PE(\tau)$ としてobservation cache $C_f$ に保存する。別途、Transformer compressor各layer $n$ の過去query/summaryをsummary cache $C_{q,n}$ に保存。両者の最大cache長を $S$、出力episodic token数を $M$ とする。

Compressorの1 blockは次の流れ。

$$x_{1,n}=q_{n,\tau}+\mathrm{Attn}(q_{n,\tau}W_Q^s,\overline C_{q,n}W_K^s,\overline C_{q,n}W_V^s),$$
$$x_{2,n}=x_{1,n}+\mathrm{Attn}(x_{1,n}W_Q^c,\overline C_fW_K^c,\overline C_fW_V^c),$$
$$q_{n+1,\tau}=x_{2,n}+\mathrm{MLP}(x_{2,n}),\qquad e_\tau=\mathrm{MLP}(q_{N,\tau}).$$

最初の $q_{1,\tau}$ は学習可能query。self-attentionは過去summaryを、cross-attentionは過去観測を参照する。$e_\tau\in\mathbb R^{M\times D}$ がaction policyに渡す固定長episodic memory。cache管理はFIFO、Random、KMeans、隣接similarity mergeなどを比較。

**注意：** ここでいう`cache`はobservation/summary embedding bufferであり、LLM decodeのper-layer KV tensorを保存・再利用する機構ではない。AttentionのK/Vを内部で計算することと、LLM KV cache再利用は区別する。

### 3.3 Action generationと学習
Diffusion denoiser $\epsilon_\theta(a^k,k,w_t,e_\tau)$ に短期・長期情報をcondition。action horizon $H=8$、DDPM sampling 50 stepsの設定。expert demonstrationに対するdenoising lossでpolicyとcompressorをjoint training。長いhistoryはsegmentごとにrandom subsamplingして学習、過去cacheに保存する特徴をdetachしてBPTTを回避する。Inferenceは(1)最新frame encode/cache更新、(2)窓外をcompress、(3)action chunk生成の順。

## 4. Experiment Setup
- **Benchmarks:** MIKASA（ShellGameTouch, RememberColor3などの非Markov memory課題）、MoMaRT（mobile manipulation）、Robomimic（ほぼMarkov的な対照）。実機はAgileX Cobot Magicでpacking tapeを元の皿へ戻す課題。
- **Models/baselines:** DP, DP-PTP, MaIL, RNN、MemoryVLA, OpenVLA, π0, BPP, MemER等（MIKASAの他論文由来baselineは同条件再実験とは限らない）。
- **Main config (PDF Table I):** DP 8 layers, D=256, sampling 50, H=8。Compressor 2 layers、short L=2、long M=2、cache S=8、dropout 0.3、subsample ratio 5（MIKASA）/20（その他）。AdamW、batch64、learning rate 1e-4、6e5〜1e6 steps。
- **評価:** success rate、GPU memory、training time、inference time、実機action chunk latency。3 seedsの平均と標準偏差をsimulationで報告。
- **追加学習:** 必須。Compressor/DPの共同最適化が必要。事前学習済みVLAへのtraining-free plug-inではない。

## 5. Main Results
### 5.1 GPU memory / inference cost / success (MoMaRT Unload-suboptimal, PDF Table II)
| Method | Context | GPU memory (MB) | Inference (s) | Success (%) |
|---|---:|---:|---:|---:|
| DP-PTP | 4 | 656 | 0.17 | 46.1 |
| DP-PTP | 32 | 942 | 0.35 | 49.6 |
| DP-PTP | 64 | 1258 | 0.44 | 49.6 |
| DP-PTP | 128 | 1792 | 0.72 | 40.4 |
| **DP-VPWEM** | **L2S2** | **734** | **0.22** | **58.3** |

DP-VPWEMはcontext128のDP-PTPよりVRAMを約59%削減し、inferenceは約3.27倍短い。ただしcontext4のDP-PTPと比べるとinferenceは0.17→0.22sへ**遅くなる**。高精度化と長文contextに対するコスト抑制が主眼であり、短いhistoryに対する絶対高速化ではない。モデルサイズはDP-PTP約50.7Mに対し52.98M、compressor増分約2.24M。

### 5.2 Success / 実機
- MIKASAのmemory-heavy tasksではDP/他のVLA baselinesより平均20 percentage points超の改善を報告。Figure 5の個別taskではDP-VPWEMのShellGameTouch 91%、RememberColor3 82%など。baselineはモデル/データ条件が完全一致しない場合がある。
- MoMaRT平均でbaseline比約+5 points、Robomimicはほぼ同等（Figure 4）。
- 実機：元の皿へpacking tapeを戻すmemory課題。180 demonstration、30 trials。DP 37%→DP-VPWEM **67%**、action chunk latency **72→79ms**（+7ms）。Control frequencyはこのlatencyだけから確定できず、I/Oやactuation時間は別途必要。
- 関連未見タスクへのfrozen encoder+compressor転移：ShellGamePush 90%、ShellGamePick 63%（本文）。

## 6. 主要Ablation
PDF Figure 6：
- Long-Horizon SquareでL1S1（long 1 token + short 1 token）でもSR 65%、L2S2は70%前後、構成によって85%の例。token数を無制限に増やしても性能は単調増加しない。
- Compressor深さ1→2→3 layerでSR 51→67→73%（L1S1の設定）。cache sizeを増やすと改善するが8を超えると飽和。
- Cache evictionはFIFO / KMeans / AdjSimが近い性能で、Randomは悪化。FIFOが簡潔で選択される。
- Memory probeではepisodic memoryがworking memoryに比べ初期状態の再構成MSEを最大20倍低く保ち、400 step後も約4倍低い。これは記憶内容の診断であって、そのままaction成功率ではない。

## 7. Limitations / 批判的評価
1. **長時間記憶は情報損失あり。** 固定数 $M$ と有限cache $S$ への圧縮は保持情報に上限があり、長いタスク・繰り返し類似eventで古い重要証拠が消える可能性がある。Semantic memoryの明示的形成、長期保存、忘却の正しさは評価されない。
2. **Training/inferenceのhistory sampling差**：訓練はsegment内random sample、実行はcache更新。分布差による頑健性の追加検証が必要。
3. MIKASAのheadline baselineには他論文の数値が含まれるため、同一backbone/同一予算での優位性を直接示すものとは限らない。
4. 実機は1種類のmemory課題・30試行。長時間運用中のVRAM安定性、energy、throughput、robot control frequencyは未測定。
5. KV cacheそのものの削減/SSD offloadではなく、**memory representationを定数個にする設計**。VLAのperceptual memory bankと比較する研究材料になる。
