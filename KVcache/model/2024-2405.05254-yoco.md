# You Only Cache Once: Decoder-Decoder Architectures for Language Models

> 通常Transformerがlayerごとに別々のK/Vを持つ前提を変え、global KV cacheを一度だけ作って後半layer全体で共有する。head方向ではなくlayer方向のKV重複を構造的に削る代表的なmodel architecture。

## 概要

standard decoder-only Transformerでは、各layer lが過去tokenごとのKey / Valueを保存する。

sequence lengthをN、layer数をLとすると、KV cacheは概ねO(NL)で増える。

long-context modelではこのcacheが巨大になり、例えば数十万〜100万token級ではGPU memoryを大きく消費する。

YOCOはmodelを二段に分ける。

1. Self-Decoder: 前半layerでcontextをencode
2. Cross-Decoder: 後半layerがSelf-Decoderの出力から作った1つのglobal KV cacheへcross-attention

これにより、cross-decoderの各layerが独自KVを保存する必要がなくなる。

外部から見ると通常のautoregressive decoderとして動くが、内部はencoder-decoderに近い二段構造を持つ。

## Architecture Overview

全L layerのうち、前半L/2をself-decoder、後半L/2をcross-decoderとする。

入力embedding X0をself-decoderで順次処理し、中間representation X_{L/2}を得る。

このrepresentationからglobal K, Vを1回だけprojectする。

後半cross-decoderの各layerは、自身のqueryはlayerごとに計算するが、K/Vは共通のglobal cacheを参照する。

つまり、

- Q: layer-specific
- K/V: shared across cross-decoder layers

となる。

## Self-Decoder

self-decoderの目的は、通常のfull self-attentionをそのまま半分積むことではない。

ここではcache growthを抑えるefficient self-attentionを使う。

論文では主に、

- sliding-window attention
- gated retention

を扱う。

sliding-window attentionなら過去全tokenをcacheする必要はなく、固定window分だけでよい。

gated retentionならrecurrent / chunkwise representationを使い、inference時cacheをO(1)に近づけられる。

したがってself-decoder側のlocal cacheはsequence lengthに比例して全layerで増えない。

## Gated Retention

YOCOではRetentionをdata-dependent gateで拡張したgated retentionをself-decoder候補として提案する。

Retentionはtraining時にはparallel計算、inference時にはrecurrent計算、prefillではchunkwise recurrent計算が可能。

gatingを加えることでtokenごとにmemory contributionを調整し、Transformerのattentionに近いflexibilityを持たせる。

重要なのは、gated retentionを使うことでself-decoder自身のKV cacheを長sequence全体に保持する必要がない点。

## Global KV Cache

self-decoder最終representationからK-hat, V-hatを生成する。

このglobal KVはsequence全体に対応し、cross-decoderのすべてのlayerで同じtensorを使う。

standard Transformerでは、

Layer 1 KV
Layer 2 KV
...
Layer L KV

を別々に保持する。

YOCOではlong-range global cacheについて、

Global KV × 1

だけになる。

論文では「once」はこのglobal cacheが1回だけという意味で、self-decoder側にはsliding window等の小さなlocal stateが残る。

## Memory Complexity

YOCOのcache量は概ね、

O(N + C L)

と説明される。

Nはsequence length、Cはsliding-window size等のconstant。

long contextではCL << Nになり、支配項はO(N)。

standard TransformerのO(NL)と比べ、long sequenceではlayer数に近い倍率でKV memoryを削減できる。

これはMQA/GQAのhead-sharingとは異なり、layer方向の重複を減らしている。

## Cross-Decoder

後半layerはglobal KVへglobal cross-attentionを行う。

したがってself-decoderがlocal / recurrentなefficient attentionを使っていても、cross-decoderでは全context tokenへ直接attentionできる。

これにより、pure sliding-window modelのようにlong-range retrieval能力を完全には失わない。

YOCOは「local efficient encoder + shared global memory + repeated global query」という構造。

## Autoregressive Generation

生成された新tokenはself-decoderへ戻され、self-decoder stateとglobal cacheへ追加される。

その後cross-decoderがshared KVへattentionして次token representationを作る。

外部APIから見ると普通のdecoder-only modelと同じtoken-by-token generation。

## Prefill Early Exit

YOCOの非常に重要なproperty。

standard Transformerのprefillではprompt全tokenを全L layerへ通す必要がある。

YOCOではcross-decoderが必要とするのはself-decoderが作ったglobal KV。

prompt過去tokenそれぞれについてcross-decoder outputを保存する必要はない。

そのためprefill時は、promptの大部分についてself-decoderまで計算した時点でearly exitできる。

cross-decoderをprompt全tokenへ走らせず、generation開始に必要な最後のtoken周辺だけ処理できる。

これはapproximationではなく、architecture上のdependencyを利用したoptimizationで、final outputを変えない。

## なぜTTFTに効くか

long promptではprefill FLOPsが非常に大きい。

論文冒頭では、4×H100で7B modelに対し、

- 450K token prefill: 約110秒
- 1M token prefill: 約380秒

という例を示し、long-context prefillが実用上の大きなbottleneckだと説明する。

YOCOのearly exitは後半layerのprompt-wide computationを省略するため、このbottleneckへ直接効く。

## Experiment Setup

model sizeとtraining token数を変えながらstandard Transformerとlanguage modeling performanceを比較する。

さらにlong-context extension、Needle-in-a-Haystack、inference profilingを評価する。

3B YOCOをtrillion-token scaleまで学習し、既存Transformer LLMと比較する。

system evaluationではcontext lengthとmodel sizeを変え、GPU memory、prefill latency、throughputを見る。

## Main Results: Model Quality

YOCOは同規模Transformerとcompetitiveなlanguage modeling performanceを示す。

architectureを大きく変えても、model size / training tokenのscalingに対して通常Transformerと同様に改善する。

3B modelをtrillion-token規模までscaleしても性能が伸び、architectureが小規模experiment専用ではないことを示す。

## Main Results: Long Context

YOCOを1M contextへ拡張し、Needle-in-a-Haystackでnear-perfect retrieval accuracyを報告する。

self-decoderがefficient attentionでも、cross-decoderがglobal KVへ直接アクセスするため、遠距離information retrievalを維持できることを示す結果。

## Main Results: Memory

standard Transformerではcontext length × layer数でKV memoryが増える。

YOCOではglobal KVを1回しか保持しないため、long contextほど差が大きくなる。

論文はcontext lengthとmodel sizeを広げたprofilingで、inference memoryをorders of magnitude改善できるcaseを示す。

空いたmemoryはより長いcontext、より大きいbatchへ利用できる。

## Main Results: Prefill / Throughput

prefill early exitによりlong-context prefill latencyを大幅に削減する。

またKV memoryが減ることでbatch sizeを増やせるためthroughputも改善する。

つまりYOCOはcache capacity、prefill FLOPs、serving throughputの3つを同じarchitecture changeで改善する。

## Distributed Long-Sequence Training

YOCOはtraining communicationにも利点がある。

self-decoderがsliding-window / gated retentionならsequence-parallel communicationが比較的小さい。

cross-decoderではglobal KVをall-gatherする必要があるが、各layerで別KVをcommunicateするのではなく、shared KVについて一度行えばよい。

そのためlong-sequence distributed trainingにもhardware-friendly。

## MQA / GQAとの違い

MQA / GQAはhead方向のKV sharing。

YOCOはlayer方向のsharing。

両者は直交し、YOCO self/cross attention内でGQAを使うこともできる。

つまり、

GQA: fewer KV heads
YOCO: fewer KV layers

という関係。

## MLAとの違い

MLAは1 layer内のK/V representationを低rank latentへ圧縮する。

YOCOはlayerごとのK/V自体を作らない。

したがって、

- MLA: representation dimension削減
- YOCO: cross-layer cache duplication削減

。

原理上はYOCOのglobal KVをMLA型に圧縮する組み合わせも可能。

## KIVIとの関係

[KIVI](../compress/2024-2402.02750-kivi.md)はKV elementのbit widthを減らす。

YOCOはcache element数をarchitectureで減らす。

論文自身もlow-bit KV quantizationはcomplementaryと位置づける。

YOCO + KIVIなら、1回だけのglobal KVをさらに低bit化できる。

## Limitations

- 既存pretrained Transformerへdrop-in適用するのは難しく、基本的にpretraining / architecture designから導入する必要がある。
- self-decoderとcross-decoderの分割比やefficient attention選択がqualityに影響する。
- serving kernel / model implementationがstandard decoder-onlyと異なる。
- shared global KVはlayer-specific representationより自由度が低く、その制約をtrainingで吸収する必要がある。
- architecture比較ではtraining recipe差を慎重に見る必要がある。

## KV-cache taxonomyでの位置づけ

YOCOはmodelカテゴリのcross-layer cache sharing / cache-once architecture。

KV軽量化を、

- head方向: MQA/GQA
- dimension方向: MLA
- layer方向: YOCO
- bit方向: KIVI
- token方向: SnapKV

と分けると位置づけが明確。

## 研究上の重要な示唆

YOCOの中心的な問いは、

「本当に各layerごとに長context全tokenのKVが必要なのか」

というもの。

従来のKV compressionは既存Transformerのcacheを小さくする方向が多いが、YOCOはcache生成構造そのものを変える。

さらにshared KV architectureにするとprefill dependency graphも変わり、memoryだけでなくearly-exitという新しいsystem optimizationが可能になる。

model architectureとserving optimizationをjoint designした点が重要。

## まとめ

YOCOは、

1. 前半をefficient self-decoder
2. self-decoder最終representationからglobal KVを1回生成
3. 後半cross-decoder全layerでshared KVを再利用
4. long-range accessはglobal cross-attentionで維持
5. prefill時はcross-decoderをearly exit
6. self-decoder cacheはsliding window / gated retentionでbounded

とする。

standard TransformerのO(NL) KV cacheをlong contextでほぼO(N)へ削減し、1M contextでもnear-perfect needle retrievalを維持する。KV cacheを「圧縮する」のではなく「layerごとに作る設計そのものをやめる」というmodel-level approachの代表例。
