# Automating Agent Hijacking via Structural Template Injection (Phantom)

> **登録判定**: 2026年公開（1年以内）で、Scholar Feedの**in-corpus citation 3件**を最低値として確認。グローバル引用総数ではない。arXiv原PDF（16頁、v1）と初投稿日・著者を照合。**採択会議は未確認**。主題はモデルのrole/authority認識だが、攻撃成立はtool出力のserialize/escape方法にも依存するため、モデル単体とagent harnessの要因を区別する。

## 概要・選定理由

従来のIndirect Prompt Injection (IPI) は、検索文書やtool outputに自然言語の命令を挿入する。Phantomは**内容の説得力よりも会話構造の偽装**を攻撃面とする。外部データ内でchat templateの終端やrole切替を模した文字列を提示し、架空のuser/assistant/tool履歴（ghost history）を構築する。モデルが低信頼データを高信頼roleの発話として解釈すると、正規ユーザーの目的から逸脱したtool callに至る。GCGのtoken勾配最適化とは異なり、**離散テンプレートを連続潜在空間に埋め込んでblack-box探索**する点が新しい。

## Problem Setting / Threat Model

- **守るべき境界**: system / user / assistant / toolのrole区別、特に`tool/external data`から正規`user`または`assistant`への権限混同。
- **攻撃者の制御**: agentが閲覧するweb page、retrieved content、tool/observationの本文に挿入するテキスト。system promptやモデル重み、実際のAPI role fieldを直接編集することは前提にしない。
- **攻撃者の観測**: target agentへのAPI-level queryと成否フィードバック。targetの**gradient / logits / weights / hidden statesは不要**。公開chat templateのseedを利用できるが、商用targetの実際のtemplateを知る必要はないとする。
- **成功条件**: 本来のuser taskを逸脱した攻撃者指定のagent action / tool invocationが実行されること（AgentDojo ASR）。モデルの拒否回避テキスト生成だけを測るjailbreak ASRとは異なる。
- **成立条件の注意**: role delimiterの見かけ上の模倣が、必ずtokenizer上の特殊tokenに化けるわけではない。textとしてのrole模倣と、serializerが実際の制御tokenとして扱う実装不備を分けて再検証する必要がある。

## 先行研究からの改善点

| 研究 | primitive | 最適化 / access | Phantomとの差分 |
|---|---|---|---|
| [GCG](2023-2307.15043-gcg.md) | adversarial suffixでtarget-token lossを下げる | surrogateの勾配・logitを用いるwhite-box | Phantomは構造的role spoofingをblack-boxで探索。jailbreakとtool-output injectionの脅威モデルも異なる。 |
| [Chatbug](2024-2406.12935-chatbug.md) | chat template由来の境界混乱 | templateの弱点を分析 | Phantomはテンプレートを自動探索し商用targetへ適用。 |
| [ChatInject](2025-2509.22830-chatinject.md) | tool outputにnative chat-template模倣を注入 | template-based / multi-turn | PhantomはTAE+Bayesian optimizationで離散構造探索を自動化。 |
| [Prompt Injection as Role Confusion](2026-2603.12277-prompt-injection-role-confusion.md) | 偽装CoTとrole perceptionの内部probe | モデル内部の表現を分析 | Phantomはrole confusionを引き起こすblack-box attack pipeline。 |

## Method / Algorithm

**Attack primitive**: 外部データに、①偽のtool-call終了、②偽のassistant応答、③偽のuser質問からなるテンプレート` t=(T0,T1,T2)`を注入し、正規のtool outputの後に存在しない対話履歴をモデルへ認識させる。一般的なsuffix-only jailbreakと違い、**in-context / tool-output injection**であり、role separatorと対話の構造が主要な操作対象。

**Step 1 — Template augmentation**: 公開chat templateの78種類のseedから、LLMによる意味的な変形と規則ベースの構造変形を組み合わせ、多様なdelimiter / turn配置を生成する。

**Step 2 — Template Autoencoder (TAE)**: Qwen3-0.6BをPEFTでencoder/decoderとして使い、離散テンプレートを潜在ベクトルへ圧縮する。論文のシリアライズは`[START] + T0 + [SEP] + T1 + [SEP] + T2 + [END] + [START]`。encoderの末尾hidden stateを射影して`z = W_p vec(h_enc) + b_p`とし、decoderで`p(t|z)`を自己回帰復元。学習は`L_recon = -E_t Σ_i log p(x_i|x_<i,z)`。射影にはidentity activationを採用。

**Step 3 — Bayesian optimization**: seedの潜在表現とproxy評価値でwarm startし、surrogateを更新しながらExpected Improvement等のacquisition functionで次の`z`を選択。TAE decoderをtemperature 0で動かしテンプレートを得て、targetに対するproxy評価を繰り返す。論文Algorithm 3の探索budgetは`B`、実験では**100 iterations**。最良観測点を返す。

**Access / costを厳密に区別**: target modelに対するwhite-box勾配更新は不要だが、TAE自体は攻撃者側の学習が必要。100回のBO iterationは**target API呼び出し総数100回と同義ではない**（1候補のproxy evaluationが複数呼び出しを含み得る）。正確なtoken/API費用は環境依存であり、単一の金額は論文から導けない。

## Experiment Setup

- **環境**: Python 3.12、PyTorch 2.9.1、Transformers 4.57.3、RTX 4090、scikit-optimize 0.10.2。78の標準templateをseed、BO budget 100 iteration。
- **benchmark**: AgentDojoの4 domain（Workspace, Travel, Slack, Banking）、97 legitimate tasks、629 adversarial test cases。攻撃の最終指標はagentが禁止されたactionを実行した割合（ASR）。
- **対象**: Qwen、GPT、Gemini等の複数商用/公開モデル。論文本文は「7つのclosed-source agentsにおける平均79.76%」と記述する。集計母数を別表から推測して変更しない。
- **baselines**: Semantic-Injection、Single-Template、ChatInject。
- **防御条件**: Delimiter Spotlighting、rule-based Tag Filter、fine-tuned DeBERTa-v3 Injection Detector。これらはSecAlign / Meta SecAlignのfine-tuned model defenseとは**別の条件**。

## Main Results

- AgentDojoにおけるPhantomの平均**ASR 79.76%**。論文の比較説明ではSemantic-Injection **39.86%**、Single-Template **54.09%**、ChatInject **38.46%**（平均値の集計条件は原論文表と合わせて参照）。
- WorkspaceのDelimiter Spotlighting条件では、**GPT-4.1に対するPhantom ASR 76.62%**に対し、semantic injectionは**12.99%**。これは明示的な「外部データを命令として扱わない」警告だけではrole spoofingを抑えられない可能性を示す。
- Rule-based Tag Filter条件でもQwen-FlashのPhantom ASRは**50.00%**。単純な固定タグ除去ではtemplate variantを捕捉しきれない。
- 942の商用agentを調査し、**70件超の脆弱性**を特定・責任ある開示を行ったと報告。これらは論文著者による報告であり、各事例の独立再現結果を意味しない。

## Generalization / Robustness / Transferability / Adaptive Attack Evaluation

- **Transferability**: 複数template familyから学習した潜在空間とblack-box BOにより、未知の商用chat templateでもrole spoofingを探索。特定のtarget tokenizer/gradientに固定されない点が重要。
- **Defense adaptivity**: Delimiter Spotlighting、Tag Filter、semantic detectorに対する攻撃を報告。ただし**StruQ、Instruction Hierarchy、ISE、SecAlign、Meta SecAlign、CaMeLに対する個別ASRは報告を確認できない**。これらを突破したと推論しない。
- **Mechanism**: 構造パターンの変形・除去とattentionの比較を実施し、単一の文字列パターンだけでなく対話構造の保存が効くことを議論。モデル内部で本当にspecial tokenへ昇格したかは別途tokenization検証が必要。
- **Jailbreakとの差**: GCGのような有害回答生成（user-level direct jailbreak）ではなく、外部データからのtool-call hijackであり、同じASR値として横比較できない。

## Limitations

1. AgentDojo/商用agentにおける成否は**モデル本体とharnessのserializer / parser / tool dispatcher**の複合特性である。role spoofingを純粋なmodel-level failureと断定できない。
2. BOの予算、proxy evaluator、agent APIの構成でquery費用が変わる。template再利用時の成功率もtarget依存。
3. 防御モデルの再学習（SecAlign、Meta SecAlign）に対するadaptive white-box testは未確認。
4. 2026-10-26時点で採択会議・公開実装repositoryは未確認。arXiv v1の`Conference'17`はtemplateのplaceholderであり採択情報ではない。
5. 著者報告の実環境脆弱性件数は、対象製品・開示範囲の偏りがある可能性がある。

## LLM Model Security taxonomyでの位置づけ

**Attack → Indirect Prompt Injection → Role/priority spoofing → Structural chat-template injection → Black-box transfer search**。agentを評価環境に使うが、攻撃の中心はLLMのrole境界認識であり、本repositoryのmodel-securityに該当する。harness privilege escalationそのものと同一視しない。

## 実装・研究上の示唆

- `tokenizer.apply_chat_template`後のtoken ID列を確認し、外部データ中のrole文字列が**普通のtext token**か**実際のspecial token ID**かを区別する。
- system/user/toolの正規message boundaryと、tool content中の偽装delimiterを混在させ、内部role probe（[Role Confusion](2026-2603.12277-prompt-injection-role-confusion.md)）と最終ASRを対応づける。
- 同一attack payloadで、template escaping、tool-output quoting、token-level role isolation、SecAlign/Meta SecAlignの効果を分離測定する。
- KV-cache再利用では、外部文書のKVに紛れ込んだrole-like representationが後続queryのattentionやrole perceptionを変化させるかを比較する。ただしキャッシュ自体の攻撃成功を本論文は実証していない。
