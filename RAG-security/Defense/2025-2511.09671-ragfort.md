# RAGFort: Dual-Path Defense Against Proprietary Knowledge Base Extraction in Retrieval-Augmented Generation

> RAG knowledge-base stealingを「別topicへ移動してcoverageを広げるinter-class path」と「同一topic内部の詳細を繰り返し回収するintra-class path」に分解し、retrieval側とgeneration側を同時にhardeningする **RAGFort** を提案する。

## 概要

proprietary RAGでは、generator modelだけでなくretrieval database自体が重要な知的財産となる。[Feedback-Guided Extraction / CopyBreakRAG](../Attack/2024-2411.14110-feedback-guided-extraction-copybreakrag.md) や [RAGCrawler](../Attack/2026-2601.15678-connect-the-dots.md) のようなattackは、black-box queryを繰り返すことで内部corpusを徐々にreconstructできることを示している。

既存defenseにはretrieval resultのre-ranking、output summarizationなどがあるが、attack processの一部分しか抑えない場合が多い。retrieval側だけを変更しても同一semantic regionから詳細を回収され、generation側だけを抑えてもattackerが別topicへ探索範囲を広げ続ける可能性がある。

RAGFortはknowledge extractionを **inter-class** と **intra-class** の2 pathに分解し、それぞれ専用moduleで抑える。

- **Contrastive Reindexing**: semantic cluster間のboundaryを強化し、attackerが別knowledge regionへ連鎖的に移動するのを難しくする。
- **Constrained Cascade Generation**: 同じregion内でgeneratorから細かなknowledgeを大量に回収するのを抑える。

このdual-path designによって、単一stage defenseより大幅にChunk Recovery Rate (CRR)を低下させながらQA utilityを維持する。

## 問題設定 / Threat Model

victimはproprietary knowledge baseをdense retrieverで検索し、retrieved chunksをLLM generatorへ与える一般的なRAG systemである。

attackerはblack-box query accessを持ち、内部corpus、embedding index、retrieval score、model parameterにはアクセスしない。多数のquery-response pairを収集し、それらから元knowledge chunksを復元することを目的とする。

防御対象には、既に得たresponseを次のquery generationへfeedbackしながらcoverageを広げるRAG-Thief / CopyBreakRAG型attackや、連続的にknowledgeを回収するWorm-Attack系attackが含まれる。

RAGFortはattackerのquery自体をmalicious/benignに分類してblockする方式ではない。RAG pipelineそのものを変更し、**attack queryが通常queryに見えてもknowledge reconstructionを難しくする**ことを狙う。

## Attack Pathの分解

著者らはknowledge extractionを2種類のmovementとして整理する。

### Inter-Class Extraction

attackerが現在取得しているknowledge topicからsemanticに関連する別topicへ移動し、corpus coverageを拡大する段階である。

これは [CopyBreakRAG](../Attack/2024-2411.14110-feedback-guided-extraction-copybreakrag.md) のexplorationや、Knowledge Graphを用いてglobal planningする [RAGCrawler](../Attack/2026-2601.15678-connect-the-dots.md) の主要能力に対応する。

semantic embedding spaceで異なるtopicのboundaryが曖昧だと、あるresponseから得たkeywordを次のqueryへ使うだけでneighboring clusterへ到達できる。

### Intra-Class Extraction

一度発見したtopic / semantic cluster内部でqueryを変えながら、複数chunkや細かなfactを回収する段階である。

retrieval boundaryを強化してinter-class movementを止めても、同じclusterから大量のverbatim / near-verbatim knowledgeをgeneratorが出力すればreconstructionは進む。

このためRAGFortは両pathを別々に防御する。

## 先行Defenseからの改善点

retrieval re-rankingやfilteringは、attackerがどのdocumentへ到達するかには影響するが、retrieved contextをgeneratorが詳細に放出する問題を直接解決しない。

逆にsummarizationやoutput transformationはverbatim leakageを減らせるが、attackerがqueryを変えながら新しいtopicへ移動するexplorationを止められない。

RAGFortの中心的な改善は、**knowledge-base stealingを単一のleakage eventとしてではなく、explorationとexploitationの連続processとして扱うこと**にある。

また [DP-SynRAG](2025-2510.06719-dp-synrag.md) はprivate corpusをdifferentially-private synthetic corpusへ一度変換するdata-layer defenseであるのに対し、RAGFortはoriginal proprietary KBを保持しながらretrieval / generation runtimeをhardeningする。privacy guaranteeの性質も異なり、RAGFortはformal DP guaranteeではなくempirical extraction resistanceを提供する。

## Method / Algorithm

### 1. Contrastive Reindexing

まず既存knowledge chunksをembeddingし、HDBSCAN等を用いてsemantic clusterへ分ける。このcluster IDをpseudo-labelとして利用し、supervised contrastive objectiveでretrieval encoderを再学習する。

trainingでは、同じclusterに属するchunk embeddingを近づけ、異なるclusterのembeddingを離す。

通常のdense embedding spaceではtopic間にsmoothなsemantic bridgeが存在し、attackerはresponse中の関連概念をqueryへ変換することで別clusterへ徐々に移動できる。contrastive reindexingはこのboundaryを明確化し、**semantic neighborhoodを辿るcrawler型attackのinter-class transition probabilityを下げる**ことを狙う。

学習後のencoderでknowledge base全体を再embeddingし、新しいindexを構築する。

重要なのはretrieval relevanceを完全に破壊するのではなく、同topic内のretrieval utilityを維持しつつtopic間のseparationを増やすことである。

### 2. Constrained Cascade Generation

inter-class movementを抑えても、attackerが同じclusterに対して多様なqueryを送り続ければ複数chunkを回収できる。そのためgeneration stageにも防御を入れる。

RAGFortでは軽量な **draft model** と、より信頼性の高い **verifier model** を組み合わせたcascade generationを利用する。

draft modelがtoken / blockを提案し、verifierが対応するdistributionを並列に評価する。draftとverifierのconfidenceやdistribution ratioがconstraintを満たす場合だけdraft outputをacceptし、riskの高いpositionではverifier側のresidual distributionへfallbackする。

論文ではこのselectionをrejection budget付きoptimizationとして定式化し、近似rejection ruleによるregret boundも議論する。

このmoduleの狙いは、retrieved textを忠実に逐語再現する方向へgeneratorが過度に引っ張られることを抑えながら、通常QAに必要なsemantic answerは維持することである。

### 3. Dual-Path Combination

最終pipelineでは、

```text
User Query
   ↓
Contrastively Reindexed Retriever
   ↓
Retrieved Chunks
   ↓
Constrained Cascade Generator
   ↓
Answer
```

となる。

retriever側がknowledge-space explorationを抑え、generator側がlocal exploitationを抑える。片方だけではattack pathが残るため、両moduleの組み合わせが重要である。

## Experiment Setup

主なdatasetは、

- **HealthCareMagic**
- **Enron Email**
- **MathQA**

であり、privacy-sensitive textとknowledge QAの双方を含む。

generatorにはQwen-14B、DeepSeek-R1-Distill-Llama-8B、Gemma-3-27Bなど複数modelを使用する。dense retrieverでtop-5 chunksを取得するRAG settingを中心に評価する。

attackにはRAG-Thief系knowledge extractionとWorm-Attackを利用し、複数dataset / generator combinationで防御性能を測る。

主指標は **Chunk Recovery Rate (CRR)** である。reconstructed chunkがoriginal chunkに対して、

- ROUGE-L > 0.5
- semantic similarity > 0.85

の双方を満たす場合にrecoveredとみなす。

防御後の通常QA accuracy、generation cost / FLOPsも測定し、security-utility-efficiency trade-offを評価する。

## Main Results

全setting平均で、無防御時のCRRを1と正規化するとRAGFortは約 **0.51×** まで低減する。

比較して、re-ranking defenseは約 **0.91×**、summarization defenseは約 **0.87×** に留まり、単一stage mitigationではreconstructionを十分抑えられない。

代表例としてHealthCareMagic + Qwen + RAG-ThiefではCRRが **57.16% → 27.96%** に低下する。Enronでは **52.60% → 20.60%**、MathQAでは **70.31% → 38.13%** と、datasetを跨いで大幅なrecovery reductionを示す。

これは単にanswerを拒否してutilityを失うのではなく、通常QAを維持しながらattackerがoriginal chunksへ近いtextを蓄積する速度を下げる結果である。

## Ablation

dual-path仮説を確認するため、各moduleを単独で有効にしたablationが行われる。

平均CRRは、

- Inter-class moduleのみ: **0.75×**
- Intra-class moduleのみ: **0.83×**
- 両module: **0.51×**

となる。

つまりcontrastive reindexingだけでもcrawler型explorationを弱められるが、既に到達したcluster内部からのextractionが残る。cascade generationだけでもlocal leakageは減るが、attackerは別topicへ移動してcoverageを広げられる。

両者を組み合わせたときに最も大きくCRRが下がるため、論文の「knowledge extractionには2 pathあり、両方を閉じる必要がある」という主張を直接支持する結果となっている。

## Utility / Efficiency

防御によるanswer accuracy低下は全dataset / modelで概ね **2 percentage points未満**に抑えられる。

またcascade generationは常に計算量を増やすわけではない。多数tokenをsmall draft modelで処理し、必要なpositionだけverifierへfallbackできるため、条件によってはfull large-model generationよりFLOPsを削減する。

HealthCareMagic + Qwenの例では、報告FLOPsが約 **38.03Tから19.40T** へ低下する。

したがってRAGFortはsecurityを強化する代わりに単純に巨大modelを二重実行する構成ではなく、cascade acceptanceを使ってefficiencyとの両立を狙っている。

## Robustness / Defense Scope

RAG-Thief / CopyBreakRAG型のadaptive extractionに対しては、explorationとexploitationを明示的に分離した設計が直接対応する。

一方、[RAGCrawler](../Attack/2026-2601.15678-connect-the-dots.md) のようなglobal planning型attackはsemantic boundaryを越える能力をさらに高めているため、contrastive reindexingがどこまで耐えるかは重要な今後の評価点となる。

また [Benchmarking Knowledge-Extraction Attack and Defense on Retrieval-Augmented Generation](../Benchmark/2026-2602.09319-benchmarking-knowledge-extraction-attack-and-defense.md) のような統一benchmarkと組み合わせると、RAGFortがretrieval leakageとgeneration leakageのどちらをどの程度減らしているかをより細かく比較できる。

## Limitations / 成立条件

Contrastive Reindexingはcorpusに意味のあるsemantic cluster structureが存在し、HDBSCAN等でpseudo-labelを構成できることを前提とする。topic boundaryが非常に連続的なcorpusやsmall corpusではseparationが期待通りに働かない可能性がある。

またreindexingにはencoder trainingとKB全体の再embedding costが必要で、頻繁に更新される大規模corpusでは運用costが問題になり得る。

評価attackは主にRAG-Thief系とWorm-Attackであり、IKEAのようなbenign-query implicit extraction、membership inference、prompt-injection based verbatim leakageなど全attack classへの万能防御ではない。

CRRもROUGE-L / semantic similarity thresholdに依存する。PII、短いsecret、数値、password-like stringなどは短いfragmentが漏れるだけでも重大だが、chunk-level CRRではseverityを十分表せない可能性がある。

formal privacy guaranteeは提供しないため、DP-based defenseとは保証の意味が異なる。

## RAG Security Taxonomyでの位置づけ

RAGFortは **Defense / confidentiality / proprietary knowledge-base extraction** に位置づけられる。

技術的にはknowledge extraction attackを、

```text
Inter-class exploration
  └─ corpusの別topicへ広がる

Intra-class exploitation
  └─ 発見済みtopicから詳細chunkを回収する
```

に分解し、前者をretrieval layer、後者をgeneration layerで防ぐ。

これはAttack側の技術系譜とも対応している。[CopyBreakRAG](../Attack/2024-2411.14110-feedback-guided-extraction-copybreakrag.md) はexploration / exploitationをfeedbackで切り替え、[RAGCrawler](../Attack/2026-2601.15678-connect-the-dots.md) はKnowledge Graphでglobal explorationを高度化する。RAGFortはそのattack structureを逆に利用して防御面を分解したものと理解できる。

## 実装・研究上の示唆

RAG knowledge-base defenseでは、単発queryのmaliciousnessより**multi-query extraction process全体**を考える必要がある。

retrieval hardeningだけ、output filteringだけでは別経路が残る可能性があり、retrieverとgeneratorをjoint security surfaceとして扱う設計が重要である。

またCRRだけでなく、coverage、semantic fidelity、PII/secret leakage、surrogate RAG utilityなど複数metricで評価することで、どの種類のknowledgeが依然として盗めるかを明確にする必要がある。
