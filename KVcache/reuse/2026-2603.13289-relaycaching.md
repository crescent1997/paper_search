# RelayCaching: Accelerating LLM Collaboration via Decoding KV Cache Reuse

## 概要

multi-agent LLMでは、上流agentが生成した文章を下流agentのpromptへ挿入することが多い。通常、上流agentはその文章をdecode時に一度計算しているにもかかわらず、下流agentは同じtoken列をprefillで再計算する。

RelayCachingはこの重複に着目し、**upstream agentのdecoding-phase KV cacheをdownstream agentのprefillへ直接再利用**するtraining-free手法。

prefixが変わるためKVは完全一致しないが、著者らは差がlayer/token方向にsparseかつlocalizedであることを観察し、重要部分だけselective recomputationする。

## 問題設定

上流agent Aがcontent Cを生成し、下流agent Bが

```text
instruction_B + C + ...
```

をpromptとして受け取る場合、標準pipelineではCを再prefillする。

しかしAがCを生成した際には既に各tokenのKVが存在する。

問題は、

```text
KV_A(decode, prefix_A + C)
!=
KV_B(prefill, prefix_B + C)
```

であること。

RelayCachingはこのprefix-induced deviationが全layer/tokenへ均等に広がらない点を利用する。

## Key observations

### Layer-wise deviation

decode KVとfull-prefill KVのsimilarityはlayer方向にU-shapedな傾向を示し、deviationが主に限られたmiddle-layer rangeへ集中する。

そのため全layerを再計算する必要はない。

### Token-wise deviation

critical layer内でも大きくずれるtokenはsparseで、さらにlayer間でdeviation patternに相関がある。

1つのdetection layerで重要tokenを検出し、その情報をcritical layer rangeへ利用できる。

## RelayCaching

RelayCachingは主に以下で構成される。

### 1. Layer-Range Profiler

KV similarityを使い、修復が必要なlayer range

```text
[L_start, L_end]
```

とtoken deviation検出用の`L_det`を決める。

### 2. Deviation-Based Token Selection

detection layerでfull-prefill counterpartとの差が大きいValue vectorsを検出する。

adaptive mean-relative thresholdを使い、平均deviationに対して十分大きいtokenを選択する。

### 3. Influence-Based Token Selection

KV deviationだけでなく、decoding中に高い累積attentionを受けたtokenも重要tokenとして追加する。

さらにsuffix tokenを保持し、position/prefix差による末尾付近の誤差を修復する。

### 4. Hidden State Relay

`L_start`のintermediate hidden stateもrelayすることで、それより前のshallow layersを再計算せずにcritical layer rangeから処理を開始する。

## CacheBlendとの差

[CacheBlend](2024-2405.16444-cacheblend.md)は独立にprefillしたdocument KVを別contextへ配置し、失われたcross-document interactionをselective recomputationで補う。

RelayCachingではreuse sourceが異なる。

```text
CacheBlend:
offline document prefill KV
        → new RAG context

RelayCaching:
upstream agent decode KV
        → downstream agent prefill
```

どちらもcontext mismatchをpartial recomputationでrepairするが、RelayCachingは**decode→prefill reuse**という新しいaxisを扱う。

## ProphetKV / SpecCacheとの差

[ProphetKV](2026-2602.02579-prophetkv.md)はquery relevanceから再計算tokenを選ぶ。

[SpecCache](2026-speccache.md)はsmall speculative modelでcritical-token selectorのcostを下げる。

RelayCachingはagent collaboration固有のprefix-induced deviationを分析し、layer rangeとtoken positionの両方を絞る。

| Method | Reuse source | Selection signal | Repair granularity |
|---|---|---|---|
| CacheBlend | document prefill KV | KV deviation | token |
| ProphetKV | document prefill KV | query attention | token |
| SpecCache | document prefill KV | small-model deep feature | token |
| RelayCaching | **upstream decode KV** | layer similarity + deviation + influence | **layer + token** |

## Experiment Setup

数学reasoning、general knowledge、code generationを含むcollaborative LLM tasksで標準multi-agent pipelineや既存KV reuse手法と比較する。

主な評価軸はaccuracy、KV reuse rate、TTFT。

## Main Results

ICML 2026論文では、

- **80%以上のKV cacheをreuse**
- standard pipeline比で**最大4.7× TTFT短縮**
- accuracy degradationはnegligible

を報告する。

multi-agent pipelineで同じ生成contentを下流agentが再prefillするcostを大幅に削減できる。

## 主要ablation / analysis

重要なのは単純な全layer decode-KV reuseではなく、

- critical layer rangeの限定
- deviation-based token selection
- influence-based token selection
- suffix correction
- hidden-state relay

を組み合わせる点。

layer-onlyまたはtoken-onlyの修復より、prefix mismatchの構造を利用した二次元selectionがaccuracy-efficiency trade-offを改善する。

## Limitations

1. 同一contentがupstream outputからdownstream promptへ引き継がれるmulti-agent workflowを前提とする。
2. modelやprompt構造によってlayer-wise deviation patternが変化する可能性がある。
3. upstream KVとhidden statesを保持・転送するmemory/storage overheadが必要。
4. agentが異なるmodelを使うheterogeneous pipelineではそのままKVを共有できない。
5. selective repairのprofiling/threshold tuningがsystem complexityを増やす。

## KV-cache taxonomyでの位置づけ

**reuse / decode-to-prefill reuse / multi-agent / inference-time repair / selective recomputation**。

RAG document reuseからagent-generated content reuseへ対象を広げた点が重要。

## まとめ

RelayCachingは、上流agentが生成時に既に計算したKVを捨て、下流agentが同じcontentを再prefillするというmulti-agent servingの重複を除去する。

prefix差で生じる誤差がlayer/token方向に局所的であることを利用し、

```text
decode KV relay
+ critical layer localization
+ critical token recomputation
+ hidden-state relay
```

で80%以上のKVを再利用し、最大4.7×のTTFT短縮を実現する。
