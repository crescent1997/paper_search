# AC²-VLA — action文脈で時間・空間・深さの計算を同時に削る

## 概要

本論文は、VLA推論に存在する3種類の冗長性、(1)連続時刻間のbackbone表現の類似、(2)visual tokenのtask非関連性、(3)必要以上のTransformer layer実行を、**前回actionに条件付けた一つのrouter**でまとめて扱う。SIMPLERでCogACTを基盤に最大1.79倍のwall-clock speedupとFLOPs 29.4%を実現し、平均成功率は74.8→76.8%。

重要な分類上の注意: **cognition cacheはVLM出力表現 $z_t$ の再利用であり、各層のK/V tensorをtoken単位で再利用するVLA-Cacheとは異なる**。キャッシュヒット時はVLM forward全体をスキップし、ミス時はtoken pruning/layer skippingでforwardを軽くする。

## 問題設定・先行研究との差

標準VLAは $z_t=f_{VLM}(x_t,u)$、$a_{t:t+H}\sim p_\phi(a\mid z_t)$ を毎step実行する。既存のVLA-Cacheはvisual類似性、FastVはtoken削減、MoLe-VLAはlayer routingなど、単独の軸に着目しがち。ところが視覚的に単純でも精密把持のような局面では高い計算が必要で、背景が複雑でも移動局面では簡略化可能。AC²-VLAは前action、現在画像、指示、diffusion step、cache stateを統合して「今必要な計算量」を決める。

## 手法

**Action-prior router**: 前回action $a_{t-1}$、視覚featureのmean/max pooling、指示embedding pooling、action-head内部stepのsinusoidal embedding、cache利用状態を共通hidden sizeへ射影し、MLPで融合した $c_t$ を構築。routerは次の3種のgateを出力する。

1. **Cognition reuse**: $p_t^{cache}=\sigma(w^Tc_t+b)$ で再利用要求を判定。keyは $k_t=(\mathrm{Quant}(\|\Delta a_t\|),\mathrm{Hash}(\bar v_t))$、つまりaction変化とvisual summaryの組。**要求とcache hitは別**。ヒット時は過去の $z$ を返しVLM forwardを省略、ミス時は計算。論文では要求したのにミスした場合のみ書き込み。
2. **Token pruning**: action条件付き類似度 $p_{t,i}^{topk}=\sigma(\langle W_vv_{t,i},W_cc_t\rangle+\gamma g_{t,i})$ でvisual tokenを選別。maskだけでなく実際にsequenceをcompactしてwall-clock削減。RoPE backboneでは元のpatch位置 $\pi_t$ を保持してpositionずれを防ぐ。
3. **Layer skipping**: 各Transformer blockにgate $\alpha_{t,\ell}$ を与え、$h^{\ell+1}=h^\ell+\alpha_{t,\ell}(F_\ell(h^\ell)-h^\ell)$ として不要層を実行しない。batch時はactive sampleをgroupして実行。

**追加学習**: Dense CogACTをteacher、routerによる疎実行をstudentとして、action predictionのMSE、backbone表現のdistillation、token/layer budget regularization、時刻間gate変化の平滑化を学習。視覚・言語backboneとaction headは固定し、軽量routing modulesのみ更新。**training-freeではない**。

## Experiment Setup

- Backbone: CogACT-Base、Prismatic-7B VLM + DiT-Base diffusion action head、denoising 8 steps、action horizon $H=15$。
- 学習: Bridge subset of Open X-Embodiment、AdamW、3,000 steps、batch 48、learning rate $10^{-6}$。NVIDIA RTX 5090 GPUを使用。
- SIMPLER: Google Robot Visual Matching、Google Robot Variant Aggregation、WidowX Visual Matching。Google Robotは3Hz制御/513Hzシミュレーション、WidowXは5Hz制御/500Hzシミュレーション。最大80/120 steps。
- Baselines: CogACT dense、VLA-Cache、EfficientVLA、FastV、MoLe-VLA、OpenVLA、RT-1等。最大pruning ratio 0.6、cache threshold 0.2を基本設定。
- 測定: success rate、wall-clock speedup、FLOPs。GPU peak memory、TTFTとdecodeの分離、実機latency/制御周波数の直接計測は未報告。

## Main Results

| SIMPLER条件 | Method | 平均成功率 | Speedup | FLOPs（dense=100%） |
|---|---|---:|---:|---:|
| Google Robot Visual Matching | CogACT | 74.8% | 1.00× | 100.0% |
|  | VLA-Cache | 74.4% | 1.36× | 80.1% |
|  | EfficientVLA | 76.4% | 1.59× | 45.1% |
|  | **AC²-VLA** | **76.8%** | **1.79×** | **29.4%** |
| Google Robot Variant Aggregation | CogACT | 61.3% | 1.00× | 100.0% |
|  | EfficientVLA | 63.2% | 1.57× | 45.1% |
|  | **AC²-VLA** | **61.6%** | **1.67×** | **34.7%** |
| WidowX Visual Matching | CogACT | 51.3% | 未報告 | 未報告 |
|  | **AC²-VLA** | **54.5%** | 未報告 | 未報告 |

Google RobotのDrawer成功率は71.8→80.6%、一方でDrawerAppleは50.9→46.8%と悪化するため、**全タスクで性能改善ではない**。Variant AggregationでもEfficientVLAの63.2%に対しAC²-VLAは61.6%で、常に最高成功率とは限らない。FLOPsを70.6%減らしてもwall-clockは1.79倍（約44%短縮）であり、理論演算削減率をそのままlatency改善と読まない。

## 主要ablation

| Google Robot Visual Matching | 成功率 | Speedup | FLOPs |
|---|---:|---:|---:|
| Dense CogACT | 74.8% | 1.00× | 100.0% |
| **Full AC²-VLA** | **76.8%** | **1.79×** | **29.4%** |
| Cognition cacheなし | 70.5% | 1.66× | 38.6% |
| Layer routingなし | 67.4% | 1.68× | 29.4% |
| Token pruningなし | 72.7% | 1.52× | 66.8% |

**機構の相補性**: token pruningを外すとspeedupが1.79→1.52倍、cacheを外すと1.79→1.66倍。layer routingを外すと同等FLOPsでも成功率が大きく低下する。単独parameter sweepではkeep ratio 0.2で33.3%、0.4で68.9%、0.8で81.1%。cache threshold 0.2の単独sweepで87.1%が報告されるが、**full modelの76.8%とは別設定**であり混同しない。routerの時間的安定性が成功率に寄与するという解釈は有用だが、因果的な一般化は未確立。

## Limitations / 評価上の注意

1. KV cacheそのものを直接読み書きする手法ではなく、**backbone output $z_t$ のmemoization**。KV memoryの削減率、position-dependent KVの修復コストは未測定。
2. Visual encoderの処理はcache key計算前に必要。cache hitで全pipelineをskipできるわけではない。実際のwall-clockは1.79倍に留まる。
3. Token compactとlayer skipのdynamic shape、batch regroupingのランタイムコストはdeployment環境に依存。vLLM/SGLangでの検証なし。
4. シミュレーション中心で、実機action success、GPU peak memory、control loop latencyの計測なし。SIMPLERの3/5Hzは評価プロトコルの制御周波数で、提案法が達成した最大周波数ではない。
5. Routerのself-distillationに追加学習が必要。未知環境・action分布の変化でcache keyの誤hitが起きる可能性は十分検証されていない。

## Taxonomy / KV cache研究への位置づけ

- **VLA / action-aware adaptive computation / temporal feature reuse / visual token pruning / layer skipping**。
- VLA-Cacheのtoken-level KV reuseより粗い**cognition feature reuse**。KV圧縮よりもVLM forwardの回避を狙う。
- VLA-Prunerのaction-aware pruningと相補的で、同時にtime/depthも最適化する。
- 今後の研究課題: VLM feature cache hit判定をlayer-wise KV cacheへ拡張、action confidenceとcache invalidation、partial recomputeとbatch schedulerの共同設計。
