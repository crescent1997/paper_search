# A³: Attention-Aware Accurate KV Cache Fusion for Fast Large Language Model Serving

> 独立chunk KVを高速に再利用しつつ、**questionが実際に参照するcontext tokenを優先して修復する**。CacheBlend/KVShareの「壊れたKVを選ぶ」方向から、ProphetKVと同様に「queryに必要なKVを選ぶ」方向へselection criterionを移した研究。

## 概要

長context promptを毎request full prefillするとTTFTが大きい。documentやconversation chunkのKVを事前計算しておけば計算を省けるが、chunkを独立計算したKVはfull sequence内で計算したKVとは異なる。

既存のrecomputation-based reuseはこの差を一部tokenの再計算で補う。しかしA³は、**実際に再計算されるtokenとquestion-relevant segmentの一致率が低い**ことを観察する。論文中の代表例では高attention tokenに対する既存selectionのhit率が30% / 37.5%程度に留まる。

つまり large KV error と important for answering the question は一致しない。A³はquestion attentionを直接利用し、回答に重要なcontext representationを選択的にrecoverする。

## 問題設定

promptを system prompt S、複数document chunk D1...Dk、question Qから構成する。各document chunkのKVをofflineまたはprior requestで独立計算し保存する。

request時には必要chunkのKVをloadして連結するが、二つの問題がある。

1. **position mismatch**：独立計算時と最終prompt内でtoken positionが異なる。
2. **context dependency mismatch**：full prefillではpreceding chunksへattentionできるが独立計算時にはできない。

A³は前者をposition recovery、後者をattention-aware recoveryで補う。

## Stage 1: KV Precomputation

document chunkごとにKV cacheを事前計算・保存する。reuse unitはrequest全体ではなくtext chunk。

同じdocument chunkが別requestでretrievalされた場合にprefillを省けるが、RoPE適用済みKをそのまま別positionへ置くとposition encodingが誤るためposition処理を分離する。

## Stage 2: Position Recovery

cached chunkを最終prompt上のglobal positionへ配置する際にRoPE positionを回復する。local positionで保存されたKを、新しいglobal positionに対応するrotationへ変換することで、同じcontent KVを異なるprompt位置で再利用可能にする。

ただしposition recoveryだけではcross-chunk context dependencyは戻らないため、次にattention-aware recoveryを行う。

## Stage 3: Attention-Aware Recovery

A³の中心観察は、すべてのcached KVをfull-prefill状態へ戻す必要はなく、questionから強くattentionされるcontext tokenを正しく更新できれば限られたbudgetでもtask accuracyを高く保てるという点。

question-to-document attentionをcontext relevanceのproxyとして使い、context token iへのquery attentionを集約してscore上位tokenをrecompute対象とする。

document retrieval/cache reuseはchunk単位だが、repairはより細かい**token-level**。つまり chunk-level cache reuse + token-level question-aware repair という二段構成になる。

選択tokenをfull-context条件で再計算し、cached KVの該当位置へfusionする。これによりfull prefillを避けながらanswer-critical representationだけを修復する。

## Experiment Setup

複数long-context benchmarkとLLMを用い、Full recomputation、FullReuse / naive reuse、recomputation-based KV reuse、CacheBlend系、LegoLink等と比較する。

評価軸はtask accuracy、recomputation ratio、TTFT、context lengthに対するscalingなど。RULERを含むlong-context taskで単純reuseによるaccuracy低下とquery-aware fusionによる回復を検証する。

## Main Results

A³は4 baselineより高いtask performanceを示しつつ、full prefillに対して**TTFTを約2×改善**すると報告する。

Qwen2.5-7BのRULER代表値：

| Method | RULER Avg. |
|---|---:|
| A³ | 84.17 |
| CacheBlend | 83.88 |
| LegoLink | 78.88 |
| FullReuse | 43.23 |

単純KV concatではaccuracyが大きく崩れる一方、attention-aware repairでfull computationに近い領域まで戻せる。

重要なのは「再計算量を増やしたから改善した」のではなく、同じ限られたbudgetをquestion-relevant tokenへ配分すること。

## Recomputed-token Alignment分析

A³の動機を最もよく表す分析。既存recomputation methodが選ぶtokenとquestion attentionが高いtokenを比較するとoverlapが低い。

「reuseによって最も変化したtoken」と「answerに最も有用なtoken」は一致しない。

この観察は[ProphetKV](2026-2602.02579-prophetkv.md)のcrowding-out effectと非常に近い。両者ともselective recomputationをstate reconstruction problemではなく**query-conditioned utility allocation problem**として捉え直している。

## 主要Ablation

### Question-aware selection

attention-aware selectionを外すとaccuracyが低下し、position recoveryだけではfull-context semanticsを十分回復できない。

### Position recovery

query-relevant tokenを選んでもcached Kのpositionが不整合ならattention自体が崩れる。position recoveryとsemantic/context recoveryは別々に必要。

### Recomputation ratio

ratioを増やせばaccuracyはfull prefillへ近づくがTTFT benefitは小さくなる。A³は低ratio領域で重要tokenを優先することでaccuracy/latency trade-offを改善する。

## CacheBlendとの差

[CacheBlend](2024-2405.16444-cacheblend.md)はcached KVとfull-context KVのdeviationを手掛かりにselective recomputationする。

A³は「KV deviationが大きいtoken」と「questionに重要なtoken」が一致しないことを直接問題にする。

| | CacheBlend | A³ |
|---|---|---|
| reuse unit | chunk/document | chunk/document |
| repair | selective recomputation | selective recomputation + fusion |
| selection | KV deviation / global recovery | question attention |
| objective | full-prefill state approximation | answer-relevant context recovery |
| granularity | token | token |

A³はselection signalをtask-awareに置き換える研究と見るのが自然。

## KVShareとの差

[KVShare](2025-2503.16525-kvshare.md) v2はattention-weighted KV deviationを使い、prefillとdecodeの両段階でrepairする。A³はより直接的にquestion-to-context attentionをselectionへ使う。

| | KVShare v2 | A³ |
|---|---|---|
| main scenario | multi-tenant cross-request | long-context / RAG chunk fusion |
| signal | attention × deviation | question attention |
| decode-stage repair | あり | 主眼ではない |
| scheduler | cache-aware | 主眼ではない |
| objective | accurate reuse + serving | query-relevant fusion |

KVShareがsystem-level serving optimizationまで含むのに対し、A³はKV fusion algorithmそのものへ焦点を絞る。

## ProphetKVとの差

A³と[ProphetKV](2026-2602.02579-prophetkv.md)はかなり近い。共通点はquery/question relevanceを直接使うこと、cached contextを全部修復しないこと、token-level selective recomputation、full state reconstructionよりtask utilityを重視すること。

一方ProphetKVは**query-only passを全layerへ通してlayer-wise relevanceを収集・fusionする**ことを中心componentとする。A³はquestion attentionを利用した比較的直接的なrelevance recoveryとposition recovery / KV fusionを組み合わせる。

| | A³ | ProphetKV |
|---|---|---|
| relevance | question→context attention | query→context attention |
| layer treatment | attention-aware recovery | all-layer query-only pass + fusion |
| position recovery | 明示的component | cached document reuseの前提処理 |
| main framing | accurate KV fusion | selective recomputation |
| key observation | relevant segmentとのmisalignment | crowding-out effect |

## 技術系譜

CacheBlendのKV-deviation-based repairから、KVShare v2のattention-weighted deviation、A³のquestion-aware KV fusion、ProphetKVのall-layer query-aware selectionへ発展している。

A³とProphetKVは「壊れたKVを見つける」発想から**回答に必要なKVを見つける**発想へ移行した点で同じ方向にある。

## Limitations

1. RoPE系Transformerを主対象としposition recovery設計がposition encoding方式に依存する。
2. 多数chunkのoffline KV storageが必要でCPU/SSD capacityとI/Oが新しいbottleneckになり得る。
3. questionが明確なtaskに適し、summarization等への一般化は追加検証が必要。
4. attention estimationにもcostがありselectionはfreeではない。
5. cached tensorをGPUへ運ぶI/Oが支配的ならcompute削減だけではend-to-end speedupが限定される。

## KV-cache taxonomyでの位置づけ

A³は **query-aware inference-time KV fusion / selective recomputation**。reuse unitはchunk、selection/recovery unitはtoken。model modificationやfine-tuningは不要。

目的は厳密なfull-prefill KV復元そのものではなく、question answeringに必要なcontext representationを低costで回復すること。

## まとめ

A³の中心メッセージは、recomputation budgetは「最も壊れたtoken」ではなく「questionに最も必要なtoken」へ使うべき、というもの。

position recoveryでcached chunkを正しいglobal位置へ置き、question attentionで重要tokenを選び、そこだけ再計算してKVへfusionする。

ProphetKVと合わせて見ると、2025–2026年のKV reuse研究が**full-prefill approximationからquery-aware utility optimizationへ移っている**ことを示す重要な研究。
