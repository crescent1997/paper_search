# Prompt Cache: Modular Attention Reuse for Low-Latency Inference

## 概要
Prompt Cacheは、system message、prompt template、few-shot example、documentなど複数requestで繰り返し現れるtext segmentのattention/KV statesを事前計算し、**prompt module**として再利用する。prefixが完全一致する場合だけでなく、schemaで配置を管理した複数moduleを組み合わせられる点が通常のprefix cachingとの主要差分。

## 問題設定
長いpromptではgeneration前のprefillがTTFTを支配する。同じdocumentやtemplateが繰り返し使われても通常は毎回attentionを再計算する。単純なprefix cacheは先頭から連続一致する部分に強いが、再利用部分がprompt中の別位置に現れる場合や複数moduleの組合せには制約がある。

## Prompt modules / PML
Prompt CacheはPrompt Markup Language (PML)で再利用可能segmentをschemaとして定義する。serverはmoduleのattention statesを事前計算・保存し、requestではmodule参照を展開してcacheを利用する。

schemaがlogical positionを予約するため、optional moduleを飛ばしても後続moduleは事前計算時と整合するposition IDを使える。つまりpositionを実際の連続token列へ単純に詰め直さず、**discontinuous position IDs**を許容してmodular reuseを成立させる。

## Prefix cachingとの差
prefix cachingは「同一prefixを以前計算したか」をruntimeで照合する。一方Prompt Cacheは、再利用される構造をあらかじめmodule/schemaとして宣言する。

| | Prefix cache | Prompt Cache |
|---|---|---|
| reuse対象 | common prefix | declared prompt modules |
| 非連続module | 苦手 | schemaで対応 |
| position | prefix位置そのもの | schema logical position |
| model変更 | 不要 | 不要 |
| repair | 不要 | 不要 |

任意chunkをどこへでも移動してfull-context prefillを近似する方式ではなく、**reuse可能になるようprompt構造を制御する**アプローチ。

## Experiment Setup
Llama 2、Falcon、MPT等を用い、document QAやrecommendationなど長い共有promptを含むworkloadでTTFTとaccuracyを評価。prototypeはTransformersを拡張してcached attention statesをmodule単位で読み込む。

## Main Results
長い共有contextほど効果が大きく、標準inferenceに対してTTFTをGPUで最大約8×、CPUで最大約60×改善。出力accuracyを維持し、model parameter modificationを必要としない。

## 後続reuse手法との関係
[Block-Attention](2024-2409.15355-block-attention.md)や[EPIC](2024-2410.15332-epic.md)は、より自由なblock/chunk再利用へ進む。[CacheBlend](2024-2405.16444-cacheblend.md)やCache-Craftは、任意contextで独立計算KVを連結した際に欠けるcross-chunk interactionをselective recomputationでrepairする。

したがってPrompt Cacheは、
```text
exact prefix reuse
  ↓
Prompt Cache: schema-defined modular reuse
  ↓
arbitrary modular/chunk reuse
  ↓
selective repair / reuse-aware fine-tuning
```
というhistoricalな位置にある。

## Limitations
- reuse対象を事前にschema/moduleとして定義する必要がある。
- arbitrary RAG retrievalのように未知chunkが任意順序で現れる場合には自然でない。
- module間のfull cross-attentionをruntimeで再計算する手法ではない。
- schemaのposition reservationによりprompt設計側へ制約が入る。
- cache storage / transfer costは長大moduleや多数moduleで無視できない。

## KV-cache taxonomyでの位置づけ
**reuse / modular prompt caching / schema-defined position management / training-free**。
