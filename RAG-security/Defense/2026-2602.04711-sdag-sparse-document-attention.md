# Addressing Corpus Knowledge Poisoning Attacks on RAG Using Sparse Attention

> **位置づけ**: Retrieved documentsを直接盗む攻撃のDefenseではなく、**corpus knowledge poisoning**へのgeneration-stage Defense。Retrieverがpoisoned documentを取り込んだ後でも、document同士のattentionを遮断することで悪意ある情報の伝播を減らす。Block-sparse attentionを**安全性**のために用いる点が特徴。

## 概要

通常のdecoder-only RAGでは、複数のretrieved passagesを1つのpromptへ連結する。Causal attentionの下では、後続documentのtokenはそれより前のdocumentのtokenを参照できるため、**悪意あるdocumentの情報が、benign documentを表すhidden statesへ伝播し得る**。既存の防御は、retrieval後のpoisoned document検出・除去や、LLMによるevidence selectionを中心とする。しかし、poisoned documentが1件しかない場合や、内容がbenign documentと自然に混ざっている場合は検出が難しい。

SDAGは各documentを独立したattention blockとして扱い、document Aのtokenからdocument Bのtokenへのattentionを禁止する。Task instructionsなどの共通prefixは引き続き参照可能で、**回答生成時のtokenはすべてのdocumentへ通常のcausal attentionでアクセス可能**とする。このため、文書間の情報統合能力を完全に失わずに、prefill中のpoison propagationを抑えることを狙う。推論時のattention maskだけを変えるため、基本的な防御導入にfine-tuningは不要である。

## 問題設定 / Threat Model

質問qに対してRetriever $R$ はcorpus $C$ からk件 $D=R(q,C)$ を返し、Generator $G$ がtask instruction pとq、Dを入力して回答を作る。Attackerは攻撃者が指定した**誤答**を生成させる目的で、false claimsを含むadversarial documentを注入する。

- **In-corpus attack**: attackerはcorpusにN件のpoisoned documentsを追加できるが、実際にretrieveされるかは保証されない。retrieval successとgeneration manipulationの両方が必要。
- **In-set attack**: poisoned documentがtop-kに含まれることを前提にする。Retrieval barrierを除き、generatorの防御性能を測る。論文の主実験は**in-set**であり、in-corpusはAppendixで補完する。
- **Single-document / multiple-document**: N=1だけでなく2〜3件も評価。single-documentはdocument間の類似性に依存したfilterが弱くなりやすい条件。
- **Attackerの操作**: corpusへ投入するdocumentのtextと選択を操作。Random、benign文書群のembedding centroidに近いNear、遠いFarの3戦略。追加のadaptive attackではbenign文書を観測してpayloadへ反映する、あるいはSDAGの前回回答を見て文書を書き直す。
- **Defenderの能力**: generatorのattention maskを変更可能なopen-weight decoder-only LLMを運用する。APIのみのclosed modelは想定外。

ここでの**ASR**は「攻撃者の指定した誤答が生成された割合」であり、private corpusの抽出率やPII漏洩率ではない。ASRが低くても誤答以外の不正確な回答が残り得るため、Accuracy（ACC）も併記する。

## 先行研究からの改善点

| 系譜 | 従来の問題 | SDAGの位置づけ |
|---|---|---|
| [PoisonedRAG](../Attack/2024-2402.07867-poisonedrag.md) | 悪意ある文書がretrieveされた後、generatorが誤情報に従う | 攻撃文書がcontextへ入った後の**attention経路**を変更して影響を抑制 |
| RAGDefender | 文書間の類似性などを使うpost-retrieval filtering。少数のpoisonで不利な場合がある | 文書を除去せずcross-document propagationを遮断。複数poisonでは併用が特に有効 |
| Discern&Answer | LLMに信頼できるevidenceを選ばせる追加処理 | attention mask変更のみで導入し、既存のpre-generation defenseと併用可能 |
| [RAGSentinel](2026-2608.23965-ragsentinel.md)、[TRIS](2026-2609.00470-tris.md) | Retrieval後の検知・選別によってpoison混入を抑える | そもそもpoisonを完全に検出する前提に依存しない別層の防御 |
| Sparse attention for efficient RAG（Ratner/Ma/Zhu等） | 非攻撃環境の効率・回答品質を主目的 | 同様のdocument-wise attention isolationを**corpus poisoning defense**として実験的に評価 |

本論文は、[CamoDocs](../Attack/2026-2608.28389-camodocs.md)のように検知を回避するpoisoned documentsを考える際に、content anomaly検出に依存しない防御層の候補になる。ただしCamoDocsそのものを対象にした直接の評価結果を示すものではない。

## Method / Algorithm

### 1. Promptをtoken blockへ分割

Retrieved documents $d_1,\dots,d_k$ をtoken blocks $B_1,\dots,B_k$ とする。共通task instructionsを $B_T$、質問や追加contextを $B_C$ とする。通常のCARGは全promptに下三角causal maskを適用するため、後のdocumentが前のdocumentを参照できる。

### 2. Document-wise block-sparse causal attention

SDAGは、**document tokenが他のdocument blockへattentionする要素を0にする**。概念的には、document内のattentionは下三角のまま残し、document間のoff-diagonal blockをmaskする。

$$A_{r,c}=1\quad\text{if }r\ge c\text{ and }\bigl[\text{same retrieved-document block}\;\lor\;\text{allowed common-prefix/context access}\bigr],$$

それ以外は0とする。原論文§4の正確なpiecewise定義では $B_T$ と $B_C$ の取り扱いを明示しており、**単純な完全block diagonal maskではない**。Retrieved document tokenは共通task prefixへattentionできる。質問・生成token側は全documentを見られるため、document単位で孤立したencoderを作るのではなく、最後のgeneratorでevidenceを統合する。

このmaskはすべてのattention layer/headに共通で、model weightやretrieverを変更しない。従って通常のtoken生成時には全contextのKVを参照でき、prefill時のdocument間の干渉だけを遮断する。

### 3. Cross-document reasoningの維持と注意点

生成tokenは全documentへアクセスできるため、multi-hop QAに必要な2文書以上の情報を生成段階で組み合わせられる。ただし、元モデルはfull causal attentionで学習されているため、**clean-only settingではmaskの変更だけでaccuracyが下がる**。Appendix Fでは少量のLoRA fine-tuningで回復できることを示す。したがって「fine-tuning不要」は**攻撃緩和機構の導入要件**であって、あらゆるclean QAでutilityを損なわない保証ではない。

### 4. Defense composition

RAGDefender/Discern&Answer等のpre-generation filteringを適用してから、残ったdocumentへSDAG maskを適用できる。Poisoned documentsの混入数が多いときはfilteringが効き、残ったpoisonが1件でもSDAGでcross-document propagationを抑えるという役割分担になる。

## Experiment setup

- **Datasets**: HotpotQA（multi-hop）、TriviaQA、Natural Questions（single-hop）。各validationから1,000 queriesをsample、seed 42。
- **Corpus**: 2018-12-20版英語Wikipedia。100-word non-overlapping passages、**21,015,324 passages**。
- **Retrievers**: E5-large-v2、Contriever、BM25（Pyserini/Lucene）。top-k=5または10。
- **Generators**: Llama-8B、Qwen-7B、Mistral-7B（instruct-tuned）、temperature 0.1。Appendixでlarger/reasoning modelも評価。
- **Attack construction**: [PoisonedRAG](../Attack/2024-2402.07867-poisonedrag.md)のframeworkを利用し、GPT-4oでattacker target answerと候補poisoned documentsを生成。各question/targetごとに5種類の候補文書を用意し、Random/Near/Farで選択。single-poisonは原則promptの質問直前に置き、位置変更もablationで評価。
- **Baselines**: CARG（標準causal）、RAGDefender、Discern&Answer、SDAG+各baseline。
- **Metrics**: Accuracy（正答文字列を含む割合）、ASR（attacker targetを含む割合）。基本は軽い正規化後のexact match、paired t-test（p≤0.05）。AppendixではLLM-as-a-judgeでも検証。

## Main Results

### Single-document in-set: CARGに対する改善

Table 1から代表値（ACC↑、ASR↓、小数は割合）：

| Dataset / Generator / Retriever / k | CARG ACC | CARG ASR | SDAG ACC | SDAG ASR |
|---|---:|---:|---:|---:|
| HotpotQA / Llama / E5 / 5 | 0.15 | 0.68 | **0.23** | **0.41** |
| HotpotQA / Llama / E5 / 10 | 0.18 | 0.66 | **0.26** | **0.28** |
| TriviaQA / Llama / E5 / 5 | 0.54 | 0.47 | **0.69** | **0.20** |
| NQ / Llama / E5 / 5 | 0.33 | 0.41 | **0.37** | **0.17** |
| NQ / Qwen / E5 / 5 | 0.29 | 0.50 | **0.36** | **0.25** |
| NQ / Mistral / E5 / 5 | 0.32 | 0.55 | **0.40** | **0.26** |

例としてNQ/Llama/E5/k=5のASRは0.41→0.17（約59%相対削減）。HotpotQAでも0.68→0.41で、multi-hopでも改善する。3 retriever×3 generator×2kで多くの比較が統計的に有意。kを5から10に増やすとpoisonの相対比率が下がり、SDAGのASRはさらに下がる。

**ASR減少とACC上昇は同じ意味ではない**。attacker指定の誤答が出なくなっても、benign evidenceやparametric knowledge由来の別の誤答へ変わる場合がある。Accuracyを必ず確認する必要がある。

### Attack strategy（NQ/E5/k=5）

| Generator | Strategy | CARG ASR | SDAG ASR |
|---|---|---:|---:|
| Llama | Random | 0.41 | **0.17** |
| Llama | Near | 0.42 | **0.23** |
| Llama | Far | 0.39 | **0.15** |
| Qwen | Near | 0.51 | **0.31** |
| Mistral | Far | 0.53 | **0.23** |

NearはFarより攻撃が成功しやすい傾向。**poisonがbenign documentsのembedding centroidに近いほど、内容の整合性が高く、検出・抑制が難しい**ことを示唆する。

### Single vs multiple poisoned documents / defense composition

Table 3のLlama/E5/k=10で、single poison時のNQ ASRはCARG **0.36**、RAGDefender **0.18**、SDAG **0.10**、SDAG+RAGDefender **0.06**。2 poison時のNQ ASRはCARG **0.47**、RAGDefender **0.19**、SDAG **0.24**、SDAG+RAGDefender **0.12**。3 poison時（k=10）はCARG **0.55**、RAGDefender **0.20**、SDAG **0.43**、SDAG+RAGDefender **0.14**。

つまり**SDAG単体はpoison数が増えると限界がある**が、RAGDefenderとの併用ではさらにASRを下げられる。複数poison条件でRAGDefenderのaccuracyがSDAG+RAGDefenderより高いケースもあるため、「全指標で常に最良」とは言えない。

## Ablation / robustness / 追加実験

### Adaptive attacker

Appendix Jでは、(1) benign documentsの内容を観測して重複させる**Benign-content overlap**、(2) SDAGの前回回答を見てpoisonを修正する**Response-to-answer**を評価。NQ/Llama/E5/k=5で、前者のASRはCARG **43.8%**→SDAG **17.8%**、後者は**40.4%**→**17.4%**（exact match）。この範囲ではadaptive attacksに対しても改善する。ただしあらゆるadaptive optimizationへの安全性保証ではない。

### Prompt position / in-corpus setting

単一poisonを質問直前、先頭、ランダム位置に置いても、SDAGのASR改善傾向は維持される。In-corpus settingではretrievalされないpoisonもあるためin-setとは絶対値が変わるが、SDAGまたはbaselineとの併用が概ね改善する。

### Clean-only multi-hop QA: utility caveat

Appendix Fの**oracle non-adversarial HotpotQA**では、CARG/SDAG/LoRA fine-tuned SDAGのaccuracyがLlamaで **0.78 / 0.71 / 0.92**、Qwenで **0.78 / 0.75 / 0.79**、Mistralで **0.79 / 0.73 / 0.80**。Fine-tuningはHotpotQA trainの1,000 triplets、LoRA rank 32、3 epochsを使用。**防御だけならtraining-freeでも、clean qualityを厳密に保つには追加学習が有益**という重要な結果。

### Hidden-state mechanism / embedding geometry

Appendix Iではbenign documentsのhidden statesから正答のfirst-token probabilityを評価し、SDAG約**0.060**、CARG約**0.049**と報告。Causal cross-document attentionがbenign hidden stateを悪化させるという機序を補強する。

さらに、poisonとbenign clusterの距離がbenign setのdiameterより大きいDistant Setと、そうでないNear Setに分割。NQ/Llama/E5/k=5のASRはSDAGでDS **0.08**、NS **0.16**、CARGでDS **0.34**、NS **0.39**。SDAGは距離の大きいpoisonに特に強いが、NearでもCARGより低ASR。

### LLM-as-a-judge / generator size

Appendix HではLLM judgeを使っても相対的な改善傾向が維持される。Appendix Bでは大きなモデル・reasoning generator・temperatureを変えた条件を追加。主結果は小型open-weightモデル中心であり、全closed APIモデルに外挿してはいけない。

## Limitations / 成立条件

1. **Poisoning以外の脅威には未検証**: RAG-Thief、[RAGCrawler](../Attack/2026-2601.15678-connect-the-dots.md)、[AGEA](../Attack/2026-2601.14662-agea-graphrag-extraction.md)等のprivate corpus extractionや、MIA、PII exfiltrationに対する保護効果は示されていない。生成tokenは依然としてすべての文書へattentionできる。
2. **Attention mask制御が必須**: closed-source APIでは実装できない。特にFlashAttention/FlashInfer/vLLM等で任意のblock-sparse maskを使うにはkernel/API適合が必要。これは論文外の実装検討事項。
3. **Clean utility低下**: 通常のcausal attentionでpretrain/fine-tuneしたモデルをそのままSDAGにするとclean-only multi-hop QAが低下する例がある。追加LoRAで回復可能だが、training-freeという利点とtrade-offになる。
4. **英語Wikipedia QA中心**: 日本語、医療/企業private documents、open-ended generation、長いmulti-turn agent、複雑なinstruction injectionに対する一般性は未確認。
5. **Attacker適応**: Near/Far、benign overlap、response adaptationは評価したが、attention maskそのものをwhite-boxで知るadaptive optimizerは十分には網羅していない。
6. **Latency未詳**: 推論時mask変更のみであることと、実際にGPU kernelで高速に動くことは同義ではない。KV cache layoutやprefill throughputの評価は別途必要。

## RAG data extraction / security taxonomyでの位置づけ

**Defense → Generation-time attention isolation / corpus poisoning mitigation**。Source trust boundaryを、document間のhidden-state mixingという計算グラフの境界へ落とし込んだ点が新しい。Poisoned documentの取得を防ぐretrieval-stage Defenseと併用できるが、**許可されたqueryを多数投げてprivate corpusを回収する攻撃には直接効かない**。Privacy leakageの観点では、poisonを介したgenerator manipulationを弱める可能性はあるものの、本文抽出・外部送信の防止保証はない。

### KV cache / inference研究への示唆（論文の直接の主張ではない）

Prefill時にdocument間のcross-attentionが不要なら、共通instruction prefixと文書ごとのKV cacheを分けて計算・保存し、生成時に結合する実装を検討できる。BlockAttentionやCacheBlend型のKV reuseと安全性を両立するには、**cacheがどのattention maskの下で計算されたか**を識別する必要がある。通常causalで計算したdocument KVをSDAGへそのまま流用すると、既にpoison情報が混入したhidden states/KVが残る可能性がある。SDAGに合ったmask-aware cache identityとblock-sparse kernelを設計する価値がある。
