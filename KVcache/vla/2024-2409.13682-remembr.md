# ReMEmbR — Building and Reasoning Over Long-Horizon Spatio-Temporal Memory for Robot Navigation

- [一次資料 arXiv HTML](https://arxiv.org/html/2409.13682) / [PDF](https://arxiv.org/pdf/2409.13682) / [公式プロジェクト](https://nvidia-ai-iot.github.io/remembr/)
- **分類**: `KVcache/vla/`、外部episodic memory / 長期ロボットnavigation QA。**KV tensor cacheではない**。
- **位置付け**: ★（mlsanityの収録範囲内被引用77。Scholar全件ではない）。ユーザー指定のため引用数閾値は免除。

## 1. 概要・問題設定

長期間稼働するロボットは、現在の視界から消えた物体・過去のイベントの時刻・場所について質問される。すべての動画を長コンテキストVLMへ渡す方式は、入力長と推論コストの点で拡張性に欠ける。ReMEmbRは観測時に外部DBを増分構築し、質問時に必要な断片だけを反復検索する。単純な画像QAだけでなく、ナビゲーション目標となるメートル座標と相対時刻を出力する。

## 2. 先行研究との差

- 全動画を一括でVLMに与える方式：長い動画はコンテキスト制限に達する。ReMEmbRはcaptionへ圧縮して検索する。
- 全captionをLLMに投入する方式：履歴長に応じpromptが増える。ReMEmbRは検索結果のみを投入する。
- [RAVEN](2026-2606.25206-raven.md)：後続のRAVENは**captionに変換せずvisual embeddingを保持**し、言語化で消える視覚情報を保持する方向へ進む。ただし異なるdataset・VLM条件の結果を単純に比較しない。
- [MEM](2026-2603.03596-mem.md) / [MemoryVLA](2025-2508.19236-memoryvla.md)：action policy内部での履歴活用とは異なり、外部DBから過去の出来事を検索してQAとnavigation goalにする。

## 3. 手法

### 3.1 Memory building

ロボットが取得する連続フレーム・位置・時刻を入力とする。VILA1.5-13Bで**3秒につき6フレーム（実効2 FPS）**をcaption化し、`mxbai-embed-large-v1`でcaptionをテキストembeddingにする。各区間のcaption、embedding、ロボット位置、時刻をvector databaseへ保存する。質問を事前に知らずに書き込むため、captionにない視覚情報は後で復元できない。保存量は時間とともに増える（固定長ではない）。

### 3.2 Retrieval-augmented LLM agent

質問とこれまでの検索結果に基づきLLMが検索関数を選択する。検索関数はtext（物体・出来事）、position（x,y,z）、time（HH:MM:SS）の3種。検索した複数entryをcontextに追加し、回答可能か判断、足りなければ再検索する。実験では**最大3 retrieval iterations**。回答はtext、position、time、durationを含む構造化JSON。検索が外れた際の再試行と複数stepの時空間推論が主な利点。

### 3.3 計算量とKVとの違い

履歴をTransformerのattention KVとして保持するのではなく、DB検索対象のcaption embeddingとメタデータに変換する。したがってLLM推論時の入力contextは取得したentry数に主に依存するが、DBの保存容量は観測時間とともに増える。captioningコスト、embedding、ANN index、LLMの反復tool callを含む総コストは別途必要。

## 4. Experiment Setup

- **NaVQA**: CODaの7シーケンス（元動画15–30分）から210問。Short <2分、Medium 2–7分、Long >7分。空間位置34%、時点14%、継続時間4%、yes/no32%、自由記述16%。
- **評価指標**: spatial L2 error（15m以内でcorrect）、temporal L1 error（2分以内でcorrect）、descriptive correctness。閾値化したOverall Correctnessも報告。
- **LLM**: GPT-4o、Codestral、Command-R、Llama3.1-8B。baselineは全captionを投入するGPT-4oと、2FPSの画像を渡すmulti-frame GPT-4o。
- ReMEmbRは3 seed、baselineはコスト上1 seed。question間の難易度差が大きく、標準偏差も大きい。
- **実機**: Nova Carter + Jetson Orin 32GB、VILA-3B量子化、ROS2 Nav2/AMCL、Whisper、GPT-4o backend。25分の走行記憶を構築してから自然言語ナビゲーションを実演。

## 5. Main Results

Table I（GPT-4oを用いた比較。accuracyは記述質問の値であり全タスク成功率ではない）：

| Method | Short descriptive accuracy | Medium | Long | Long spatial error (m) | Long temporal error (s) |
|---|---:|---:|---:|---:|---:|
| ReMEmbR | 0.62 | 0.58 | **0.65** | **46.25** | **3.6** |
| GPT-4o + all captions | 0.57 | **0.66** | 0.55 | 56.0 | 8.0 |
| GPT-4o + sampled frames | 0.55 | 評価不可 | 評価不可 | 評価不可 | 評価不可 |

**注意**: mediumのdescriptive accuracyではall captionsが優位。空間誤差46mはnavigation goalとして依然大きい。著者は21.5分動画に対し質問1件約25秒、5.5分動画のfull-VLMで約90秒と報告。ただし**動画長が異なる比較**であり厳密な同条件高速化比ではない。Codestral/Command-Rは約40秒、Llama3.1-8Bは約15秒だが回答精度は低下する。

## 6. 主要ablation（Table II、Overall Correctness）

| Setting | Short | Medium | Long |
|---|---:|---:|---:|
| ReMEmbR full | **0.72** | 0.56 | **0.61** |
| 1 retrieval call only | 0.67 | 0.48 | 0.50 |
| 12-second caption interval | 0.54 | 0.50 | 0.38 |
| VILA1.5-8B captioner | 0.58 | 0.52 | 0.54 |
| VILA1.5-3B captioner | 0.60 | **0.58** | 0.50 |

最大3回の反復検索はLongで0.50→0.61。caption生成を3秒から12秒間隔へ間引くとLongで0.61→0.38となり、**観測時に何を失うか**が記憶品質を大きく左右する。小型captionerは推論コスト面で有利だが精度が落ちる。

## 7. Limitations / 評価上の注意

1. **Caption bottleneck**: captionにない色、物体、微細な位置関係を再検索できない。RAVENのvisual embedding保存はこの制約への対処。
2. **実機は定性的デモ**: navigation成功率、制御Hz、task completionの大規模定量評価ではない。飲料自販機と水飲み場の取り違えも報告。
3. **外部LLMへの依存**: GPT-4oを使うと高精度だが、open-source LLMでは空間・時間計算の誤りが増える。ロボット全体のend-to-end latency・GPU peak・energyは未報告。
4. **記憶更新・忘却**: append中心で、古い情報の訂正・削除、容量上限と品質のtradeoffは未評価。動画が無制限に伸びてもDBサイズは定数にならない。
5. **比較条件**: ReMEmbR 3 seed対baseline 1 seed、full-VLMは長い動画でcontext limit。異なる動画長でのlatency比較に注意。
6. **追加学習**: memory専用の新規policy学習は必須ではないが、captioner・embedding model・LLMの既存学習済みモデルを利用する。

## 8. Taxonomy / 関連研究

- `KVcache/vla/`: long-horizon external episodic memory / retrieval-augmented navigation。Transformer attention K/Vのreuse、eviction、compressionを行わない。
- [RAVEN](2026-2606.25206-raven.md): caption vs raw visual embeddingの情報損失・検索精度を比較。
- [HELM](2026-2604.18791-helm.md): episodic memoryをfailure verifier/recoveryに結び付ける。
- [HiMe](2026-2607.03449-hime.md): long-horizon manipulationでactive Add/Update/Deleteとplanner gatingを行う。
- [MEM](2026-2603.03596-mem.md): policyの長期記憶表現。
