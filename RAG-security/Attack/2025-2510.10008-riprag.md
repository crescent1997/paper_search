# RIPRAG: Hack a Black-box Retrieval-Augmented Generation Question-Answering System with Reinforcement Learning

> target RAG systemそのものをblack-box RL environmentとして利用し、poisoned document generatorを最終QA feedbackから適応させるknowledge-poisoning attack。retriever / reranker / hybrid retrievalの内部構成を知らなくても、実際のtarget pipelineで「retrieveされ、かつtarget answerを生成させる」documentをclosed-loopで学習する。

## 概要

RAG knowledge poisoningでは、attackerがknowledge baseへmalicious documentsを挿入し、target queryに対してattacker-chosen answerを生成させる。

[PoisonedRAG](2024-2402.07867-poisonedrag.md)は、target queryとのretrieval similarityを高めるtriggerとmalicious answer payloadを組み合わせる基本的なattack primitiveを示した。しかしblack-box settingでは、attackerが想定したsurrogate retrieval objectiveと実際のproduction RAGのretriever / reranker / fusion logicが一致しないと、作成したpoisonが十分上位にretrieveされない。

RIPRAGはこのmodel mismatchを、**target RAGから得られるblack-box feedbackを直接rewardにするreinforcement learning**で解消する。

## 問題設定 / Threat Model

attackerはtarget systemがRAG-based QAであり、外部knowledge databaseを検索して回答を生成することを知っている。

一方で以下は未知でもよい。

- retriever architecture / parameters
- embedding model
- reranker
- retrieval fusion rule
- generator parameters
- database内部の既存documents

attackerに必要なのは、

1. knowledge baseへ少数のdocumentsをinjectできること
2. target RAGへqueryを送り最終answerを観測できること

である。

これはretriever gradientを必要とするwhite-box poisoningより弱いaccess requirementであり、production RAGを意識した設定になっている。

## 先行研究からの改善点

### PoisonedRAGからの発展

[PoisonedRAG](2024-2402.07867-poisonedrag.md)はretrievalされやすいtriggerとtarget answer payloadを組み合わせるが、black-box targetに対してはattack document constructionが比較的staticである。

RIPRAGではpoison generatorをpolicyとして扱い、**実際のtarget RAGで成功したかどうかを反復feedbackとして学習する**。

### Surrogate white-box attackの問題

attackerがContriever等のsurrogate retrieverを用意してgradient / HotFlipでtriggerを最適化しても、targetが別embedding、reranker、hybrid retrieval、RRF等を使うとtransferしない。

RIPRAGはtarget system自身をenvironmentにするため、このsurrogate mismatchを避ける。

## Method: RLBF

RIPRAGの中心は **Reinforcement Learning from Black-box Feedback (RLBF)**。

概念的には以下を反復する。

```
target question q + attacker target answer a*
        ↓
Poisoning SLM policy
        ↓
candidate poisoned document d
        ↓
inject d into target database
        ↓
query target RAG with q
        ↓
observe final answer / retrieval-related feedback
        ↓
reward
        ↓
update poison generator
```

policyは「自然なdocumentを生成する」というlanguage-model objectiveだけでなく、target RAGでのattack effectivenessに合わせて更新される。

## Reward Design

### Similarity Reward

binary attack successだけではrewardがsparseで、poisonがretrieveされない初期段階では学習が進みにくい。

そこでquery-document similarityやtarget answer inclusion等からdenseなsimilarity rewardを構成し、poisonをretrieval frontierへ近づける。

このrewardは「まずretrieveされる」というattackの第一条件を学習させる役割を持つ。

### Attack Reward

最終的にtarget RAGがattacker-chosen answerを生成したかをbinary / task-level rewardとして与える。

これによりretrievalだけ成功してgenerator manipulationに失敗するdocumentsは高rewardにならない。

### Combined Objective

RIPRAGはretrieval-side dense rewardとend-to-end attack successを組み合わせ、

- retrievalされる
- generatorにtarget answerを出させる

という二条件を同時に最適化する。

## BRPO: Batch-wise Relative Policy Optimization

通常のGRPOでは同じqueryに対して生成したcandidate group内でrewardをnormalizeする。

しかしRIPRAGでは同一queryに対するpoisonsが似たrewardを取りやすく、group内varianceが小さい。その結果advantage signalが消え、policy updateが弱くなる。

そこで **Batch-wise Relative Policy Optimization (BRPO)** を導入し、queryごとのgroupではなくbatch全体でreward normalizationを行う。

これによりquery間のdifficulty / reward差も学習signalとして利用し、poison generatorのoptimizationを安定化する。

## Experiment Setup

### Datasets

- Natural Questions
- HotpotQA
- MS-MARCO

### Target Generators

- GLM4-9B
- Qwen3-8B
- InternLM2.5-7B-Chat
- DeepSeek-v3.2-Exp

### Retrieval Settings

単純なdense retrievalだけでなく、production-orientedな複合pipelineを評価する。

代表的には、

- Contriever
- BGE-M3 reranker
- Qwen3 embedding
- Milvus
- Reciprocal Rank Fusion (RRF)

等を組み合わせる。

retrieval cutoffは主に top-k=10。

### Baselines

- black-box PoisonedRAG
- Iterative Feedback
- surrogate Contriever + HotFlip

### Metrics

主metricはAttack Success Rate (ASR)。poison document数を変えたquery efficiency / injection efficiencyも評価する。

## Main Results

complex retrieval settingでもRIPRAGはdataset / generatorに応じて **ASR 0.49–1.00**を維持する。

一方、black-box PoisonedRAGは同条件で概ね **0.12–0.59**まで低下する。

報告された最大改善は、

- black-box PoisonedRAG比: **+0.65 ASR**
- fake-white-box / surrogate attack比: **+0.72 ASR**

に達する。

これは単純retrieverへのoptimizationより、target pipelineからend-to-end feedbackを得ることが重要であることを示す。

## Low-budget Poisoning

queryあたり1 poisoned documentだけのsettingでも、RIPRAGは条件に応じて **ASR 0.35–1.00**を示す。

したがって大量のcorpus poisoningを前提とせず、少数document injectionでも成立し得る。

## Defense Evaluation

RAGuardを入れたInternLM2.5 + complex retriever + M=1では、RIPRAGのASRは、

- NQ: **0.10**
- HotpotQA: **0.13**
- MS-MARCO: **0.16**

まで低下する。

Defenseは明確に有効である。

一方、attacker側のQLoRA rankを増やしてpolicy capacityを高めると、

- NQ: **0.28**
- HotpotQA: **0.23**
- MS-MARCO: **0.26**

へ再上昇する。

つまりRIPRAGはstatic attackではなく、defense pressureに対してpolicy optimization capacityを増やす余地がある。

## Ablation

Qwen3-8Bの代表結果ではsimilarity rewardを除くと、

- NQ: **0.72 → 0.09**
- MS-MARCO: **0.78 → 0.06**

へ大幅低下する。

binary attack rewardだけでは、retrievalされるdocumentを探索するにはsignalがsparseすぎることを示す。

BRPOを除いた場合も、

- NQ: **0.72 → 0.17**
- MS-MARCO: **0.78 → 0.14**

へ低下する。

したがって本手法の性能は単にRLを適用したことではなく、**retrieval-aware dense reward + batch-wise relative optimization**の組み合わせに依存する。

## RAG Security Taxonomyでの位置づけ

```
Knowledge poisoning
  PoisonedRAG
      ↓
surrogate retriever optimization
  HotFlip / gradient-based trigger optimization
      ↓
target-system feedback optimization
  RIPRAG ← 本論文
```

RIPRAGはconfidential knowledge extractionではなく**integrity attack**である。ただし、black-box RAGを反復queryして内部retrieval behaviorへ適応するという観点では、feedbackを利用する[Feedback-Guided Extraction / CopyBreakRAG](2024-2411.14110-feedback-guided-extraction-copybreakrag.md)と共通する設計思想もある。

CopyBreakRAGがfeedbackから「次に何を聞けばcorpusを抽出できるか」を改善するのに対し、RIPRAGはfeedbackから「どのdocumentを入れればtarget answerへ誘導できるか」を改善する。

## Limitations / 成立条件

最大の前提はknowledge baseへのwrite / injection capabilityである。read-only private RAGには直接適用できない。

またtarget systemとの反復interactionが必要で、query budgetやdatabase updateの監査が厳しい環境ではtraining costが露見し得る。

policyはtraining query distributionから学習するため、target query distributionが大きくshiftするとattack transferが低下する可能性がある。

さらにtarget RAGがdocument provenance、write authorization、poison detectionを強く実装している場合、RLでretrieval behaviorへ適応できてもcorpus insertion自体が成立しない。

## 実装・研究上の示唆

RIPRAGの重要な点は、RAG attackを固定algorithmではなく**environment interactionから学習するpolicy**として扱ったことである。

production RAGはretrieverだけでなくreranker、filters、hybrid search、fusionを含むため、単一surrogate modelに対するgradient optimizationは実systemとずれやすい。

一方、final answer feedbackだけでも十分な反復回数があればsystem-specific poison distributionを学べることは、RAG API側でrate limitingやdatabase write monitoringを行う必要性を示す。
