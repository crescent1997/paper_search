# GEAR: An Efficient KV Cache Compression Recipe for Near-Lossless Generative Inference of LLM

## 概要

単純なKV量子化で生じる誤差が、**長いchain-of-thought (CoT)生成の後続tokenに蓄積**することに着目。KVを $\text{quantized dense}+\text{low-rank residual}+\text{sparse outlier}$ に分解し、bit数を抑えつつ元のKVを高精度で近似する。量子化方式に追加するerror-reduction frameworkであり、modelのfine-tuningやarchitecture変更は不要。本文はarXiv v4を基準とする。

## 問題設定と既存法の問題

[H2O](2023-2306.14048-h2o.md)等のevictionはtokenを捨て、[KIVI](2024-2402.02750-kivi.md)や[KVQuant](2024-2401.18079-kvquant.md)はKV値を低bitで近似する。短いQAなら多少の誤差が許容されても、複数段の推論では予測logitの小さなずれが生成系列を変え、以後の誤差が累積する。K/Vの外れ値だけを高精度保持しても、**量子化残差に残る相関構造**を説明できない。

目標はKV行列 $X\in\mathbb{R}^{n\times d}$ を圧縮形式で表し、

$$\min_{D_b,L,S}\|X-D_b-L-S\|_F$$

を小さくすること。$D_b$ は低bitのdense backbone、$S$ はoutlier、$L$ は残差の低rank近似。厳密な反復最適化は遅いため、段階的に構築する。

## 手法

### 1. K/V非対称量子化をbackboneに

Kはper-channel、Vはper-tokenを基本とする。4-bitではKCVT（KIVIからfine-grained groupingを省きscale/zero-point metadataを削減した変種）を利用。2-bitではKCVTだけでは精度が不足するため、**group size 64のKIVI**をbackboneに用いる。従ってGEARは特定の単一quantizerの名前ではなく、複数のquantizerへ載せる補正層である。

### 2. Outlierを疎行列として分離

Kならchannel、Vならtoken単位で最大/最小値の上位下位を抽出する。疎行列 $S$ として元値を保存し、残り $X-S$ を量子化して $D_b=Q_b(X-S)$ を得る。標準のsparsity ratio $s=2\%$ は全要素に対する保持割合。疎index/valueは高精度のため、$s$ を増やすと圧縮率が悪化する。

### 3. Head-wise low-rank error correction

残差 $R=X-(D_b+S)$ をheadごとに分割し、低rank近似を計算する：

$$R_h\approx A_hB_h^\top,\qquad A_h\in\mathbb{R}^{n\times r},\ B_h\in\mathbb{R}^{d_h\times r}.$$

Power iterationによる近似SVDを利用。標準 $r=4$（prefill）で、残差のcoherentな成分を保持する。decodeではQKの内積やattention×Vを、低rank因子を経由する行列積として処理するため、元のdense residualを全復元する必要はない。

**GEAR-L** は $S$ を省き、量子化＋低rankだけを使う軽量版。精度優先ならGEAR、実行効率優先ならGEAR-Lという位置づけ。

### 4. Streaming bufferとkernel

新しいKVを一時的にFP16 bufferへ置き、$n_b$ tokenごとにまとめて圧縮する。4-bit KCVTではbufferを小さく設定でき、論文は例として $n_b=20$ を使用。GPUでdequantizeとmatmulを融合し、low-rank経路を別計算する。量子化・疎index・低rank因子の転送/計算が追加されるので、**純粋なbit削減がそのままlatency削減にはならない**。

## Experiment Setup

arXiv v4：LLaMA2-7B/13B、Mistral-7B、LLaMA3-8B。GSM8K・AQuA・BBHのCoT（BBHは8-shot等）、GSM8K 5-shot、LongBench 21 tasks。FP16、per-token quantization、KCVT、KIVI、GEAR-Lを比較。CoTは長めの生成（256 tokens）を評価。throughput/memoryは単一**V100 16GB**、LLaMA2-7B、input 1000・output 500、weight 8-bit、batch sizeを増やして比較。一般のA100/vLLMサーバとは条件が異なる。

## Main Results

### CoTの誤差回復（Table 1）

| 条件 | FP16 | 量子化のみ | GEAR | 注記 |
|---|---:|---:|---:|---|
| LLaMA3-8B GSM8K, 4-bit | 54.21 | KCVT 45.59 | 54.76 | $s=2\%,r=4$ |
| LLaMA3-8B GSM8K, 2-bit | 54.21 | KIVI 30.17 | 54.59 | $s=2\%,r=4$ |
| 全モデル・全CoT task平均, 2-bit | 40.52 | KIVI 25.25 | 40.20 | Table 1の平均列 |
| 全モデル・全CoT task平均, 4-bit | 40.52 | KIVI 35.05 | 40.80 | 4-bit KCVT+補正 |

2-bitでもCoT平均をFP16近くまで回復する点が主張の芯。**4-bit GEARのKV保存量はFP16の約31.0%**、2-bit GEARでは27.6%（Table 1の平均）。2-bitと4-bitの総容量が近いのは、backboneのgroupingやoutlier/low-rankのmetadataが異なるため。

### LongBenchとserving（Table 2, Fig.3）

LLaMA2-7B LongBench 21-task平均はFP16 **26.82**、4-bit GEAR **27.80**、2-bit GEAR **25.48**。**2-bitではKIVIの27.83を下回る**ため、GEARが全taskで勝つわけではない。V100実験では最大batch sizeがFP16の3からGEARの18に増え、同条件の最大throughput改善は**5.07×**、peak memory削減は最大**2.39×**。これは容量に余裕ができたことでbatchを増やした結果を含み、1-request latency 5×を意味しない。

**Version注意**：arXivの古いabstractや二次サイトにある「4-bitで最大2.38× throughput、2.29× memory削減」と、v4本文の「2-bit・最大5.07× throughput、2.39× memory削減」は**実験版が異なる**。本要約の数値はv4の本文に合わせた。PMLR workshop掲載版は別タイトルの短縮版で、数値も異なる。

## 主要Ablation

1. **$r$と$s$**：2-bit・LLaMA3-8B GSM8K-CoTでは、rank 4とsparsity 2%程度で十分。増やしても改善は小さく、memoryが増える。
2. **Low-rankの必要性**：$L$を除くと精度が大きく悪化。疎行列のみでは2-bitのCoTを回復しきれない。
3. **GEAR-L**：$S$を省いても4-bitは良好、2-bitも量子化のみより大幅に改善。Table 1の全CoT平均は2-bit GEAR-L **38.34**、GEAR **40.20**、FP16 **40.52**。
4. **どのtokenを補正するか**：prefill tokenの一部だけにlow-rank補正を適用すると、補正対象を減らすほどCoT性能が低下。最新tokenのみ修復すれば十分という前提は支持されない。
5. **bit数/総容量**：低rank・疎補正を増やすと精度は上がるが、純粋なbit幅ほど実効容量は減らない。

## Limitations / 実装上の論点

- rank近似の計算・疎index処理・streaming bufferに追加overheadがある。推論backendのkernel品質で速度は変わる。
- V100 16GB/8-bit weightの実験をA100・vLLM・FlashAttentionのTTFT/TPOTへ直接外挿できない。
- 量子化誤差を最小化することは、特定questionのutility最大化やinter-request reuseの品質保証とは異なる。
- 2-bit LongBenchでGEARがKIVIを下回る結果もある。CoT性能だけで総合優位と断定できない。
- PMLR workshop版とarXiv v4のタイトル・実験結果を混ぜない。

## Taxonomy / 関連研究との差分

**`compress`**：全tokenのKVを低bit近似し、残差を補償。保存表現を減らすための**quantization error repair**であり、[CacheBlend](../reuse/2024-2405.16444-cacheblend.md)、[A³](../reuse/2025-2511.17560-a3.md)、[ProphetKV](../reuse/2026-2602.02579-prophetkv.md)のような**再利用KVのcontext不整合を選択的再計算で修復する方法とは別**。[KIVI](2024-2402.02750-kivi.md)や[KVQuant](2024-2401.18079-kvquant.md)と同じbit圧縮系統だが、GEARは**量子化後の低rank/疎残差補正**に焦点がある。[MiniCache](2024-2405.14366-minicache.md)はlayer方向の類似性を使い、圧縮する軸が異なる。
