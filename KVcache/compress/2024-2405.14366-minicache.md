# MiniCache: KV Cache Compression in Depth Dimension for Large Language Models

## 概要

KV cacheをtoken数やbit幅ではなく、**layer方向の冗長性**から削減する。中層〜深層の隣接layerでは同じtoken位置のK/V方向が似ているという観察を利用し、2層分のKVを1本の共有方向ベクトルにまとめる。layer固有のnormと、統合しにくいtokenの元ベクトルを別途保存し、decodeで各layerの近似KVを復元する。**pretrained modelのweight/architectureは変更せず、fine-tuningも不要**。

## 問題設定・既存法の問題

通常のKV cacheはlayer $L$ に比例して増える。既存の[KIVI](2024-2402.02750-kivi.md)はbit数、[H2O](2023-2306.14048-h2o.md)・[SnapKV](2024-2404.14469-snapkv.md)はtoken数を減らすが、layer間の類似を直接利用しない。逆に[Cross-Layer Attention](../model/2024-2405.12981-cross-layer-attention.md)や[MLKV](../model/2024-2406.09297-mlkv.md)は、architecture自体を変更して層間共有を設計する。MiniCacheは既存modelで**事後的にKV表現をmerge**するため、分類は`model`ではなく`compress`。

論文の観察では浅層は類似性が低いが、中〜深層の隣接layerでcosine similarityが高い。ただし単純な平均では、normや特異tokenの情報を失い、GSM8K等の性能が落ちる。

## 手法

### 1. Adjacent-layer merging

layer $\ell-1,\ell$ の同一token位置・同一headにおけるベクトル $x^{\ell-1},x^\ell$（K/Vをそれぞれ処理）を対象に、原則 $S=L/2$ 以降で隣接2層をmergeする。方向を

$$u_0=\frac{x^{\ell-1}}{\|x^{\ell-1}\|},\quad u_1=\frac{x^{\ell}}{\|x^{\ell}\|},\quad \Omega=\arccos(u_0^\top u_1)$$

とし、球面線形補間（SLERP）

$$e=\frac{\sin((1-t)\Omega)}{\sin\Omega}u_0+\frac{\sin(t\Omega)}{\sin\Omega}u_1$$

で共有方向を得る。$t=0.6$を標準とする。**共有するのは方向**であり、各layerのnorm $m_{\ell-1},m_\ell$ は別保存する。復元は

$$\hat x^{\ell}=\frac{e}{\|e\|}m_\ell,\qquad \hat x^{\ell-1}=\frac{e}{\|e\|}m_{\ell-1}.$$

### 2. Unmergeable token retention

角度が大きく異なる一部tokenは層ごとに元KVを保存し、復元時に上書きする。必要な保存物は共有方向 $E$、各層のnorm、retention index $I$、保持した元KV $R^{\ell-1},R^\ell$。近似KVはattentionを実行する際に復元するので、**恒常的なKV cache量は減るが、計算/temporary bufferはゼロにはならない**。

**実装確認上の注意**：NeurIPS PDF Eq.(4) は「大きい角度のtokenを残す」という本文の説明と反対向きに見える条件 $d_i<d_{min}+(d_{max}-d_{min})\gamma$ を記載している。式をそのまま実装すると低角度のtokenが選ばれるため、論文記述に内部不整合がある。再現時には原著者の実装または修正情報の確認が必要（2026-10-13時点で公式コード実体は確認できず）。

### 3. Memory accounting

FP16 full cacheの概算 $4brh(s+n)$ に対し、後半層を2層ずつmergeした共有方向だけなら $3brh(s+n)$。normとretentionを含めた論文の近似式は $(3.1h+2)br(s+n)$（retention比5%仮定）。理想的な2倍削減ではなく、**層の半分だけをmergeすることによる約1.3倍前後の削減**が基礎となる。実測の1.53×等は設定・モデル・保持token数に依存する。

## Experiment Setup

Phi-3-Mini、Mixtral-8x7B、LLaMA-2/3（7B〜70B）、Mistral。GSM8K、COQA、TruthfulQA、lm-eval-harness各種QA、LongBench。比較はfull cache、単純mean merge、RTN、SmoothQuant、KIVI。標準は $S=L/2,t=0.6,\gamma=0.05$。batch serving評価はLLaMA-2-7B、A100 80GB、ShareGPT由来の合成request（平均input 161、output 338 tokens）。

## Main Results

| 条件 | FP16 / baseline | MiniCache | 解釈 |
|---|---:|---:|---|
| LLaMA-2-7B-Chat LongBench 7-task平均 | 36.41 | 35.44 | KIVI-4bit併用・5.02×圧縮 |
| LLaMA-2-13B-Chat LongBench平均 | 32.71 | 32.61 | 同条件、ほぼ維持 |
| Mistral-7B LongBench平均 | 37.33 | 35.75 | 劣化あり |
| Mistral-7B-Instruct LongBench平均 | 48.32 | 46.99 | 劣化あり |
| LLaMA-2-7B、batch 128、A100 | FP16 memory基準 | 25GB減・41%減 | KV以外のmemoryも含むピーク |
| ShareGPT workload throughput | FP16基準 | 約5× | 4bit併用・batch条件による |

LLaMA-3-70BではCOQAで87.5%のlayerをmergeしても性能低下が小さい例を報告。**5.02×は純粋なdepth merging単体ではなく4-bit KIVIとの組合せ**である。2-bit KIVIとの比較で1.29× throughput向上と報告するが、bit幅・merge・batch容量が異なる複合比較。

## 主要Ablation

1. **Merge位置/層数**：浅層からmergeすると劣化しやすく、中層以降を選ぶと安定。単純平均よりSLERP+norm復元が優れる。
2. **Interpolation $t$**：LLaMA-3-8B GSM8Kで0.3〜0.7を比較し、$t=0.6$付近が良い。$t=0.5$の単純対称方向補間は弱い。
3. **Retention閾値 $\gamma$**：LLaMA-2-7BのGSM8Kは $\gamma=0$ で0.108、0.05で0.152、1で0.159。0.05は容量との妥協点。
4. **量子化との直交性**：KIVI 4-bitとmergeを重ねることで、同程度のLongBench品質で5.02×圧縮を示す。

## Limitations / 実装上の論点

- 共有方向へのmergeは情報損失を伴う。norm保存は大きさを復元するが、元の異なる2方向を同時には復元できない。
- token retentionのEq.(4)に本文との条件方向の矛盾があり、再現性上の注意点。
- 既存modelのlayerごとのKVを生成した後にmergeするため、prefill FLOPsを構造的に減らすCLA/MLKVとは異なる。merge/restorationのruntime・memory layoutに依存する。
- 実験は比較的短いShareGPT requestが中心。128Kなど超長文、paged KV・FlashAttention backendでの一般的なend-to-end gainは別途検証が必要。
- 論文projectのCodeリンクはGitHubの**静的Webサイトrepo**へ遷移し、推論実装の公式コードを確認できなかったため`code: null`とした。

## Taxonomy / 関連研究との差分

**`compress`**：同一request・同一tokenのKVを**layer方向で近似統合**。model architectureは不変。`model`の[CLA](../model/2024-2405.12981-cross-layer-attention.md)、[MLKV](../model/2024-2406.09297-mlkv.md)、[LCKV](../model/2024-lckv.md)とは設計時共有/事後圧縮の違いがある。[KIVI](2024-2402.02750-kivi.md)・[KVQuant](2024-2401.18079-kvquant.md)・[GEAR](2024-2403.05527-gear.md)とは直交。KVShare/ProphetKVのrequest間reuseやselective recomputationは扱わない。
