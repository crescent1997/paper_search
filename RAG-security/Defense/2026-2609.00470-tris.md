# TRIS: A Tri-Layer Retrieval Integrity Sieve Against Knowledge Poisoning

> PoisonedRAG型attackが満たす必要のあるretrieval geometry、trigger/payload structure、generator factual consistencyという異なる制約を3つの独立signalで検査するpost-retrieval defense。retrieverやgeneratorを再学習せずmiddlewareとして挿入でき、low-costなL1+L2をdefaultにし、high-risk caseだけLLM-based L3を起動する。

## 概要

RAG knowledge poisoningでは、attackerがmalicious documentsをknowledge baseへ挿入し、target queryに対してretrieveされるようtriggerを最適化しつつ、generatorへ誤答を誘導するpayloadを埋め込む。

代表的な[PoisonedRAG](../Attack/2024-2402.07867-poisonedrag.md)は、retrieval successとgeneration manipulationを分離して最適化できることを示した。

TRISは逆に、成功するpoisonが同時に満たさなければならない複数の性質を利用する。

1. retrieverから見てqueryに十分近い。
2. trigger / payloadを含むため自然なevidenceとは異なるstructural patternを持ちやすい。
3. payload claimがLLMのparametric knowledgeや他evidenceと矛盾し得る。

単一detectorを強化するのではなく、異なるfailure modeを持つ3層を組み合わせるdefense-in-depth approachである。

## 問題設定 / Threat Model

attackerはRAG corpusへのwrite accessを持ち、target queriesに対してmalicious answerを生成させるpoison documentsを挿入する。

black-box attackerではretrieval feedback / repeated querying等を使ってtriggerを改善する。white-box settingではretriever gradientやHotFlip型optimizationを利用し、retrieval similarityを直接高める。

defenderはretrieverとgeneratorの間にmiddlewareを配置できるが、両modelを再学習しないことを目標とする。

TRISはblack-box PoisonedRAGだけでなく、retrieval triggerを最適化するwhite-box attack、さらにTRISの一部構造を知るadaptive attackerも評価する。

## 先行研究からの改善点

単一signal defenseには回避経路がある。

retrieval embeddingだけを見るとattackerが同じembedding spaceへ最適化できる。surface trigger detectorだけならparaphraseで回避できる。LLM verificationだけならcostが高く、LLM自身のuncertaintyやhallucinationでclean evidenceを誤除去する。

TRISは**互いに異なるmodel / signalを使うことでattackerが同時に満たすconstraintsを増やす**。

特にretriever本体とは別のSentence-BERT embeddingをLayer 1に使うため、retrieverへwhite-box optimizationされたpoisonがそのままjudge embeddingでも自然になるとは限らない。

## Architecture

```
Retriever Top-k
     ↓
Layer 1: Cross-Embedding Geometric Filter
     ↓
Layer 2: Trigger / Payload Structural Filter
     ↓
risk assessment
     ├─ low risk → generator
     └─ high risk
           ↓
       Layer 3: LLM Consistency Verification
           ↓
       sanitized context
```

default pathではL1+L2のみを使い、両layerが矛盾するなどhigh-risk caseでL3を呼ぶ。

## Layer 1: Cross-Embedding Geometric Filter

retrieverが返したtop-k documentsを、retriever自身とは異なるSentence-BERT MiniLM embedding spaceへ再embedする。

その後K-means clusteringを行い、query-relevant benign evidenceが形成する**majority cluster**を保持し、少数outlier clusterを疑わしいものとして除去する。

狙いは、attackerがContriever等のtarget retrieverに対してtriggerを最適化しても、independent embedding model上では同じgeometryを再現しない可能性を利用すること。

ただしkが小さい場合やbenign evidence自体がmulti-modalな場合、majority clusteringは不安定になる。

## Layer 2: Structural Trigger / Payload Detection

PoisonedRAGのSplit-and-Merge型constructionでは、retrieval triggerとmalicious payloadの接合に不自然なlexical patternが残る場合がある。

TRISはdocument冒頭付近、特に最初の約20 tokensとqueryの関係を中心に、

- Jaccard overlap
- bigram overlap
- trigram overlap
- repetition
- trigger-like lexical concentration

等を検査する。

black-box PoisonedRAGには非常に強い一方、paraphraseされたtriggerやgradient-based white-box triggerには弱い。

## Layer 3: Parametric-Belief Consistency Verification

最も高価なlayer。

まずLLMへretrieved contextを与えずqueryだけで回答させ、model自身のparametric belief / prior answerを取得する。

次にcandidate documentが主張するanswer / factual claimと比較し、強く矛盾するdocumentを疑わしいものとして扱う。

このlayerはsurface triggerをparaphraseしたadaptive poisonにも対応しやすい。

一方、LLMのparametric knowledgeが弱いqueryではfalse positiveが増えるため、confidenceが低い場合やAPI failureでは**fail-open**し、documentを保持する。

## Adaptive Invocation

TRISの重要な設計は3 layersを常時すべて適用しないこと。

L1/L2が一致してclean / maliciousと判断できるcaseではL3を省略する。L1とL2が食い違うなどambiguousなcaseだけL3へ送る。

これは単なるcost optimizationではない。実験ではfull three-layer systemを常時使うと、LLM verifierによる誤除去でclean accuracyや一部attack settingのASRが悪化する。

## Experiment Setup

### Datasets

- Natural Questions
- HotpotQA
- MS-MARCO

各datasetから100 queries。

### Retrieval

- Contriever
- top-k = 50
- queryあたり5 poisoned documentsを挿入

### Generator

- GPT-3.5-turbo

### Layer 1 Judge

- Sentence-BERT MiniLM

### Attacks

- black-box PoisonedRAG
- white-box HotFlip
- trigger paraphrasing
- payload diversification
- trigger + payload adaptive combinations

### Baselines

TrustRAG、RobustRAG等のpost-retrieval / robust generation defenseと比較する。

主metricはAttack Success Rate (ASR)、Clean Accuracy、surviving poisons、latency / LLM call cost。

## Main Results: Black-box PoisonedRAG

undefended ASRは、

- NQ: **67%**
- HotpotQA: **87%**
- MS-MARCO: **64%**

TRIS適用後は、

- NQ: **3%**
- HotpotQA: **14%**
- MS-MARCO: **4%**

まで低下する。

Clean Accuracyもattack下の、

- 33%
- 13%
- 32%

から、

- **74%**
- **58%**
- **76%**

へ回復する。

一方、比較baselineに対して全datasetで一方的に優位という結果ではない。TrustRAGとはNQ / HotpotQAで近く、tuned RobustRAGがHotpotQAでより低いASRを示すsettingもある。

TRISの主な利点は防御性能だけでなく、default pathの低いverification costにある。

## Layer Ablation

black-box PoisonedRAGではLayer 2単独でもASRを約 **67% → 4%**まで低下させ、既知のSplit-and-Merge trigger structureに非常に強い。

しかしwhite-box HotFlipではLayer 2単独のASRは約71%で、ほとんど防げない。

white-box settingではcross-embedding L1とLLM consistency L3の組み合わせが重要になり、ASRを約 **74% → 27.8%**へ下げる。

興味深いことに全layersを常時ONにすると、black-boxではL1+L2のASR 3%に対して約9%まで悪化するsettingがあり、HotpotQAでもfull configurationが約31%まで悪化する。

この結果から、TRISは「layerを増やせば単調に強くなる」のではなく、attack type / detector disagreementに応じたroutingが必要だと結論づける。

## Adaptive Attack Evaluation

### Trigger Paraphrasing

attackerがtriggerを自然なparaphraseへ変換するとLayer 2のlexical signatureをほぼ回避できる。

このsettingでは5 poisons中平均 **4.97** がtop-50 retrievalに残り、retrieval自体はほぼ成功する。

しかしLayer 3を有効にするとNQで、

- ASR: **32% → 15%**
- Clean Accuracy: **43% → 61%**
- surviving poisons: **2.51 → 0.79**

へ改善する。

代償としてLLM verificationによりlatencyは約16–19 s/queryまで増える。

### Adaptive Knowledge Levels

論文ではattacker knowledgeを段階化する。

評価の中心はLayer 1程度まで構造を認識するadaptive attackerであり、judge embedding、全threshold、LLM verifierまで完全に知ってjointly optimizeする最強Level-2/3 attackerは十分なempirical evaluationがない。

したがってadaptive robustnessは限定的に解釈する必要がある。

## Efficiency

default L1+L2 pathは約 **0.35 s/query**程度。

RobustRAGのように30回以上のLLM callsを必要とする方式と比較して、LLM API costを大きく削減する。

一方L3を起動するadaptive settingでは16–19 s/query程度まで増えるため、L3 invocation rateが実deploymentのcostを左右する。

## Failure Cases

### Small-k

k=5のようにretrieved setが小さいとK-means majority geometryが不安定になり、ASRが **85–93%**まで悪化するsettingが報告される。

これはLayer 1が十分なsample数を必要とすることを示す。

### Multi-hop QA

HotpotQAではclean evidence自体が複数topics / reasoning hopsに分散するため、majority cluster assumptionが弱くなる。

結果としてuseful evidenceをoutlierとして除去するover-filteringが生じやすい。

### Parametric Knowledge Dependence

Layer 3はLLMがqueryに対する正しいprior knowledgeを持つことを暗黙に期待する。最新情報、private domain、long-tail knowledgeではcontext-free answerが不確実になりやすく、fail-openが増える。

## Limitations / 成立条件

formal robustness guaranteeはない。

Layer 1はmajority / clustering structureに依存し、small-kやheterogeneous benign evidenceに弱い。

Layer 2は既知trigger morphologyに強く依存し、paraphraseで回避される。

Layer 3はLLM parametric knowledgeとAPI costに依存する。

またfully adaptive attackerがindependent judge embeddingとLLM verifierを同時にoptimization objectiveへ含めた場合のrobustnessは未解決である。

## RAG Security Taxonomyでの位置づけ

```
Knowledge poisoning
  PoisonedRAG
      ↓
Single-signal post-retrieval filtering
      ↓
Defense-in-depth retrieval integrity
  L1 independent geometry
  L2 structural trigger detection
  L3 generator-prior verification
      ↓
  TRIS ← 本論文
```

RAGSentinelがrepresentation geometryへ集中してformal conditionを与えるのに対し、TRISは複数のindependent weak signalsを組み合わせ、attackerが同時に回避すべきconstraintsを増やす設計である。

[RAGFort](2025-2511.10128-ragfort.md)や[CanaryRAG](2026-2604.10717-canaryrag.md)はknowledge-base extractionというconfidentiality attackを主対象とするため、TRISとは守るsecurity propertyが異なる。

## 実装・研究上の示唆

TRISのablationは、RAG securityで複数detectorsを積む場合に重要な示唆を与える。

independent defense layersはattack surfaceを狭められる一方、各layerのfalse positiveが累積するため、**常時全検査ではなくrisk-adaptive routing**が必要になる。

またPoisonedRAGのようなattack-specific structural signatureは既知attackには非常に効くが、paraphraseだけで急激に弱くなる。長期的にはLayer 1/3のようなattack constructionに依存しにくいsignalとの併用が重要になる。
