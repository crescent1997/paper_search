# Reasoning Up the Instruction Ladder for Controllable Language Models

## 概要

本論文はInstruction Hierarchy (IH)を、「低priority instructionを無視するclassification / refusal behavior」ではなく、**複数instructionの関係を推論してから回答するreasoning task**として捉え直す。

system instructionとuser instructionがalignedかconflictingかをmodelが内部でreasoningし、その関係に基づいて最終responseを生成する。これを学習するため、著者らはVerIHという約7K規模のverifiable instruction hierarchy datasetを構築し、RLVR / GRPOでmodelをtrainingする。

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)がsynthetic conflict dataを用いてhierarchy-following behavior自体をSFT/RLHFへ組み込むのに対し、本研究は**priority resolutionにexplicit reasoningを介在させる**点が主要な差分である。

## 問題設定 / Threat Model

LLMは同一context内で複数のinstruction sourceを受ける。

```text
System / developer policy
        ↓ higher priority
User request
        ↓
Tool / external content
```

systemとuserがalignedなら両方を満たすべきだが、conflictする場合はhigher-priority instructionを維持しながらlower-priority requestの許容部分だけを処理する必要がある。

従来modelはこの判断をshortcutで行うことがあり、

- 特定system wordingへのmemorization
- refusal keywordへの依存
- user instructionを常に弱く扱うover-refusal
- conflict detectionなしのlast-instruction bias

などが起きる。

本論文は、まず「user requestがsystem constraintとどのような関係か」をreasoningさせることで、priority followingをより一般化可能な能力として学習できるかを検証する。

## 先行研究からの改善点

### Instruction Hierarchy

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)はcontext synthesis / context ignorance等のsynthetic training primitivesで、conflicting lower-level instructionを無視するbehaviorを獲得する。

本論文はそこから一歩進み、

```text
instruction conflict
      ↓
reason about relationship
      ↓
select constraints to satisfy
      ↓
generate answer
```

というintermediate reasoning structureを持たせる。

### IHEval

[IHEval](../Benchmark/2025-2502.08745-iheval.md)はReference / Aligned / Conflict settingでinstruction hierarchy遵守を測るが、本論文はIHEvalを単なるtestではなく、trainingしたreasoning capabilityのgeneralization先として利用する。

## VerIH Dataset

VerIHはconstraint-following taskを基礎にし、system instructionとuser instructionの関係をcontrolledに生成する。

sampleは大きく

- **Aligned**: user requestがsystem constraintと整合
- **Conflict**: user requestの一部または全部がsystem constraintと矛盾

に分かれる。

重要なのは、rewardを自動検証可能にするため、constraint satisfactionをprogrammatically checkできるtaskを選ぶことである。

約7K examples規模と比較的小さいtraining setで、instruction hierarchy reasoningが獲得できるかを調べる。

## Method / Algorithm

### 1. Explicit reasoning

modelに最終回答だけを直接生成させるのではなく、system constraintとuser requestの関係をまず分析させる。

概念的には、

```text
Given:
  system instruction S
  user instruction U

Reason:
  Which constraints in U are compatible with S?
  Which conflict with S?
  Which instruction has priority?

Answer:
  satisfy S
  satisfy non-conflicting parts of U
```

となる。

### 2. RLVR / GRPO

VerIHのconstraintはverifiableなので、生成responseがhigher-priority constraintを満たすかをrewardへ変換できる。

著者らは軽量なreinforcement learning、特にGRPO系trainingを用いて、general reasoning capabilityをinstruction prioritizationへtransferする。

SFTだけで固定responseをmemorizeするより、correct hierarchy resolutionへrewardを与えることで未知constraintへのgeneralizationを狙う。

### 3. Multiple model families

Qwen3 seriesやPhi-4-mini-reasoning等、reasoning-oriented model familyへ適用し、効果が特定modelに限定されないかを評価する。

## Experiment Setup

評価は通常instruction followingとinstruction hierarchyの双方を含む。

代表的benchmark:

- IFEval / IFBench系 instruction following
- [IHEval](../Benchmark/2025-2502.08745-iheval.md)
- jailbreak benchmark
- TensorTrust系prompt injection
- system/user conflict tasks

特にtraining distributionに含まれないsecurity taskで改善するかを重視する。

## Main Results

Instruction hierarchyのConflict settingで大きな改善が見られる。

代表的に、

- Qwen3-4B: IHEval Conflictで **+22.87 points**
- Phi-4-mini-reasoning: **+18.13 points**

の改善を報告する。

論文全体として、複数model family / scaleでconflict setupに約20% absolute improvementを示す。

重要なのは、aligned instruction followingを大幅に壊さずにconflict resolutionを改善している点で、単にすべてのuser requestを拒否するmodelではない。

## Generalization to Security

VerIH trainingにはsecurity attackを直接大量投入していないにもかかわらず、priority reasoningがjailbreakやprompt injectionへgeneralizeする。

これは安全性問題を

```text
higher-priority safety / system policy
          vs
adversarial lower-priority instruction
```

というinstruction conflictとして捉えられるためである。

代表的には、

- WildJailbreak: attack successを最大 **27.6 points**低減
- TensorTrust prompt injection: ASRを最大 **16.55 points**低減

する。

つまりattack-specific adversarial trainingなしでも、hierarchy reasoning自体を強化するとsecurity robustnessが上がる。

## Robustness / Over-refusal

security improvementが単なるrefusal増加によるものかを区別するため、aligned / benign instruction followingも評価する。

reasoning-based approachでは、systemとuserがalignedならuser instructionへ従い、conflict時だけhigher-priority constraintを優先することを目指す。

この設計は「低priority sourceだから常に無視する」という過剰なprivilege separationより柔軟である。

ただしreasoning traceが誤ればpriority resolutionも誤るため、chain-of-thought qualityが新たなfailure modeになる。

## The Instruction Hierarchyとの違い

両者を簡略化すると、

```text
Instruction Hierarchy (2024)
  conflict examplesを通して
  hierarchy-following behaviorを学習
          ↓

Reasoning Up the Instruction Ladder (2026)
  conflict relationをreasoningし、
  verifiable rewardでpriority resolutionを学習
```

となる。

前者はbehavioral alignment、後者はreasoning-based controlとして見ると整理しやすい。

## IHEvalとの関係

[IHEval](../Benchmark/2025-2502.08745-iheval.md)が「モデルはhierarchyを守れるか」を測るdiagnostic benchmarkなのに対し、本論文はそのfailure modeをtraining側から改善する。

したがって技術的系譜は、

```text
Instruction Hierarchy
      ↓
IHEval: hierarchy failureを測る
      ↓
VerIH / RLVR:
reasoningでhierarchy resolutionを改善
```

と整理できる。

## Limitations

- 主にsystem-userの2-level conflictを中心にtrainingしており、任意多数のprivilege tiersへのgeneralizationは十分検証されていない。
- explicit reasoningを許すmodelを前提とし、latency / token costが増える。
- reasoning traceがattack surfaceになる可能性がある。
- tool outputやdeveloper roleなど、real agentの複雑なauthority graphは限定的。
- RLVR rewardで検証可能なconstraint taskからsecurity behaviorへtransferしており、すべての自然言語policyが同様に学習できる保証はない。
- jailbreak / prompt injection ASR低下は大きいが、adaptive attackerへのformal robustnessを意味しない。

## LLM Model Security Taxonomyでの位置づけ

```text
Behavioral hierarchy training
  The Instruction Hierarchy
            ↓
Benchmark
  IHEval
            ↓
Reasoning-based hierarchy training
  VerIH + RLVR / GRPO
  Reasoning Up the Instruction Ladder
```

[Instructional Segment Embedding](2024-2410.09102-instructional-segment-embedding.md)のようなarchitecture-level priority signalとは別方向であり、modelのreasoning能力を使ってhierarchyを解決するDefenseである。

## 実装・研究上の示唆

instruction hierarchyを強化する際、単にconflicting exampleでSFTする以外に、**hierarchy resolutionをverifiable reasoning problemへ変換してRLする**という選択肢がある。

特に、

- system promptを後から変更したい
- policyを自然言語で頻繁に更新したい
- benign conflictとmalicious conflictを同じ機構で扱いたい

場合に有望である。

一方で実運用ではreasoning-based model-level defenseだけに依存せず、[CaMeL](2025-2503.18813-defeating-prompt-injections-by-design-camel.md)のようなexternal privilege enforcementやtool permission controlと併用する方がsecurity boundaryは明確になる。
