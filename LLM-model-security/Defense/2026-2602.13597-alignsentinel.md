# AlignSentinel: Alignment-Aware Detection of Prompt Injection Attacks

## 概要

AlignSentinelはprompt injection detectionを単純な「instructionを含む / 含まない」のbinary classificationではなく、**higher-priority instructionとの整合性を考慮した3-class classification**として定式化するDefenseである。

lower-priority inputを、

1. **misaligned instruction** — higher-priority taskと競合し、attacker-chosen taskへ誘導するinstruction
2. **aligned instruction** — higher-priority taskと整合し、その遂行を補助するbenign instruction
3. **non-instruction** — instructionではない通常のdata/content

に分類する。

既存detectorは「instructionらしさ」をmaliciousnessのproxyとして使うことが多く、正当なlower-priority instructionまでblockするfalse positiveが生じる。AlignSentinelは[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)と同じく、**lower-priority instructionであること自体ではなく、higher-priority instructionとconflictするか**を重視する。

## 問題設定 / Threat Model

LLM applicationではsystem / developer側のhigher-priority instructionに加え、user inputやtool responseなどlower-trust sourceがcontextへ入る。

attackerはlower-priority channelへinstructionを挿入し、modelを本来のtaskからattacker-selected taskへ誘導する。

論文は両方を扱う。

- **Direct prompt injection**: malicious instructionがuser input側から直接与えられる。
- **Indirect prompt injection**: tool response等、外部dataとして取り込まれるlower-trust contentへinstructionが埋め込まれる。

Defense側はtarget LLMのattention mapへアクセスできることを前提とする。このためclosed API modelへ外部からそのまま適用できるblack-box detectorではない。

## なぜBinary Detectionでは不十分か

従来のprompt-injection detectorでは、入力中にinstructionが存在すること自体をmalicious signalとして扱う場合がある。

しかし実際のapplicationではlower-priority sourceに正当なinstructionが存在しうる。

例えばhigher-priority taskが文章編集で、lower-priority toolが「複雑な文を簡潔にする」と提案する場合、そのinstructionはtaskとalignedであり、攻撃ではない。

したがって、

```text
instruction present
        !=
prompt injection
```

であり、必要なのは、

```text
lower-priority instruction
        ↓
aligned with higher-priority task?
        ↓
yes → benign
no  → potentially malicious injection
```

というalignment-aware decisionである。

## Method / Algorithm

### Attention-based Interaction Features

higher-priority instructionを (s)、評価対象のinputを (x) とする。

Transformerのattention mapから、input tokenとhigher-priority instruction token間のinteractionを抽出する。

attention tensorは概念的に、

で表される。

- (L): layer数
- (H): attention head数
- (|x|): lower-priority input token数
- (|s|): higher-priority instruction token数

各token pairについてlayer/headをまたいだattention behaviorをfeatureとして扱い、inputがhigher-priority taskとどのようにinteractionしているかを分類に利用する。

実験ではEnc-firstがAvg-firstより一貫して強い。

## Model-internal Signalを使う意味

AlignSentinelはsurface textだけで「ignore previous instructions」等のkeywordを探すのではなく、target LLM自身がhigher-priority instructionとlower-priority inputの関係を処理するときのattention patternを利用する。

したがってtaxonomy上は、

```text
external text classifier
        ↓
model-internal alignment-aware detector
        ↓
attention map features
```

という位置づけになる。

一方、attention accessが必要なのでdeployment条件はmodel-level training Defenseより限定される。

## Benchmark

既存benchmarkではmalicious injectionと通常dataのbinary構成が多く、**benignだがinstructionを含むaligned input**が十分含まれていない。

AlignSentinelでは3 categoryを体系的に含むbenchmarkを構築する。

domainは、

- Coding
- Entertainment
- Language
- Messaging
- Shopping
- Social Media
- Teaching
- Web

の8種類。

さらにdirect injectionとindirect injectionの両方を含める。

これにより、単にinstruction detectorとして動く手法と、実際にalignment/conflictを判断できる手法を区別できる。

## Experiment Setup

backend LLMとして複数のopen-weight modelを利用し、attention featureの有効性を比較する。

代表例は、

- Qwen3-8B
- Llama-3.1-8B-Instruct
- Mistral-7B-Instruct-v0.3

である。

評価では、

- custom 3-class benchmark
- existing prompt-injection benchmarks
- cross-domain generalization
- cross-model / backend variation
- adaptive attack

等を調べる。

metricでは特にFalse Positive Rate (FPR) とFalse Negative Rate (FNR) が重要になる。aligned instructionをmaliciousと誤認するとFPRが上がり、misaligned injectionを見逃すとFNRが上がる。

## Main Results

AlignSentinelはcustom benchmarkでmisaligned instructionを高精度に検出しつつ、aligned instructionをmaliciousと誤認する率を大幅に抑える。

特にEnc-first variantが強く、複数domain / backend modelで既存baselineを上回る。

論文で重要なのは単純なattack detection accuracyだけでなく、従来benchmarkでは見えにくかった**aligned benign instructionに対するfalse positive**を明示的に測っている点である。

## Cross-domain / Existing Benchmark Generalization

8 domainで学習・評価するだけでなく、domain shiftに対するgeneralizationも確認する。

また既存prompt-injection benchmarkへ適用し、aligned instructionが少ない従来settingでもcompetitiveな検出性能を維持する。

これは3-class化によって「benign instructionを許す」ようになっても、通常のmalicious-vs-benign benchmarkでattack detection能力を失っていないことを確認するために重要である。

## Adaptive Attack Evaluation

attackerがdetectorの存在を知っているadaptive settingも評価する。

attackerは、

1. injectionとしてtarget modelを乗っ取る
2. detectorにはaligned / benignに見せる

という2つの目的を同時に満たす必要がある。

論文ではdetector evasionを強めるとoriginal injection objectiveが弱くなるtrade-offが観測され、alignment-aware featureがadaptive attackerにも一定の障壁になることを示す。

ただしformal robustness guaranteeではなく、より強いwhite-box optimization attackに対して破られないことを意味しない。

## The Instruction Hierarchyとの関係

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)の重要な原則は、

```text
lower-priority instructionを全部無視する
```

ではなく、

```text
aligned lower-priority instruction
    → follow

conflicting lower-priority instruction
    → ignore
```

である。

AlignSentinelはこの原則をmodel generation policyではなく**detector classification rule**へ移した研究と捉えられる。

## IHEvalとの関係

[IHEval](../Benchmark/2025-2502.08745-iheval.md)はmodel自身がinstruction hierarchyを正しくfollowできるかを評価する。

AlignSentinelは同じalignment/conflict distinctionをDefenseへ利用する。

```text
IHEval:
  can the model resolve hierarchy correctly?

AlignSentinel:
  can a detector recognize whether a
  lower-priority instruction conflicts
  with the higher-priority task?
```

という違いがある。

## StruQ / SecAlign / Meta SecAlignとの関係

[StruQ](2024-2402.06363-struq.md)、[SecAlign](2024-2410.05451-secalign.md)、[Meta SecAlign](2025-2507.02735-meta-secalign.md)はtarget LLM自身へtrusted/untrusted separationを学習させ、malicious lower-priority instructionを実行しにくくする。

AlignSentinelはtarget generation policyそのものを変更せず、**入力段階でmisaligned instructionを検知する別layerのDefense**である。

そのため、

```text
AlignSentinel
  detect conflict

        +

SecAlign / Instruction Hierarchy
  robustly resolve conflict
```

というDefense-in-depthが考えられる。

## Instructional Segment Embeddingとの関係

[Instructional Segment Embedding](2024-2410.09102-instructional-segment-embedding.md)はsource identity / privilegeをlearnable embeddingとしてmodelへ明示する。

AlignSentinelはarchitectureへ新しいprivilege embeddingを追加せず、既存model内部のattention responseからalignmentを推定する。

したがってISEは**priority signalをinjectする**手法、AlignSentinelは**priority-sensitive internal signalをobserveする**手法と対比できる。

## IH-Challenge / HIPOとの関係

[IH-Challenge](2026-2603.10521-ih-challenge.md)や[HIPO](2026-2603.16152-hipo.md)はtarget model自身のhierarchical instruction followingをtrainingする。

AlignSentinelはtraining Defenseではない。

```text
IH-Challenge / HIPO
  improve hierarchy-following policy

AlignSentinel
  detect whether incoming instruction
  conflicts with higher-priority task
```

という補完関係になる。

## GCG / Optimization-based Attackとの関係

[GCG](../Attack/2023-2307.15043-gcg.md)はtarget modelへのgradient accessを利用し、adversarial suffix tokenを離散最適化するwhite-box attackである。

AlignSentinelの主attack settingはdirect / indirect semantic prompt injectionであり、GCGのようにdetectorとtarget model双方を含むend-to-end differentiable objectiveでsuffixを最適化するattackを主要対象とはしていない。

したがって、

- detector attention featureへのwhite-box gradient attack
- detector evasion + target hijackingのjoint optimization
- transfer suffix
- [Faster-GCG](../Attack/2024-2410.15362-faster-gcg.md)
- [SlotGCG](../Attack/2026-2606.05609-slotgcg.md)

等は重要な追加stress testになる。

## Role Confusion / Priority Spoofingとの関係

[Prompt Injection as Role Confusion](../Attack/2026-2603.12277-prompt-injection-role-confusion.md)は、低権限textをtrusted roleらしく見せることでmodel内部のrole representationを混乱させる。

AlignSentinelはattention map上のhigher-/lower-priority interactionを利用するため、Role Confusion型attackが、

```text
malicious instruction
      ↓
attention representation上では
aligned instructionに見える
```

状態を作れるかは重要なadaptive evaluationになる。

## System Prompt Extractionとの関係

[Just Ask](../Attack/2026-2601.21233-just-ask.md)のようなsystem prompt extractionは、higher-priority instructionをoverrideするのではなく、その内容をreadするconfidentiality attackである。

AlignSentinelは主にinstruction integrityを守るprompt-injection detectorであり、system prompt confidentialityを直接保証しない。

[ProxyPrompt](2025-2505.11459-proxyprompt.md)のようなconfidentiality-oriented Defenseとは対象security propertyが異なる。

## White-box / Black-box条件

### Attacker

通常のprompt injectionではattackerはtargetへのgradient/logit accessを必要としない。

adaptive evaluationではdetector behaviorを考慮してattackを変更するが、GCG型のfull white-box token optimizationとは区別する必要がある。

### Defender

Defense側はLLMのattention mapを取得する必要がある。

このため、

- self-hosted/open-weight model: 適用しやすい
- attentionを返さないclosed API: そのまま適用困難

というdeployment constraintがある。

## Compute / Deployment Cost

text-only binary classifierと比べると、target LLM内部のlayer/head attention mapを取得・処理する必要がある。

特に長contextではattention feature sizeが (|x||s|) に依存するため、memory / extraction overheadが問題になりうる。

Enc-firstは細粒度interactionを保持する代わりに、Avg-firstよりfeature processing costが増える。

## Limitations

- attention map accessが必要でclosed API modelには直接適用しにくい。
- attention implementationやmodel architecture変更にfeature distributionが依存しうる。
- custom benchmarkはsynthetic generationを含み、実運用trafficのdistributionを完全には再現しない。
- 3-class labelには「higher-priority taskとのalignment」を定義する必要があり、曖昧なtaskではlabeling自体が難しい。
- adaptive evaluationはformal security guaranteeではない。
- GCG等によるdetector-aware white-box joint optimizationは重要な未検証領域。
- system prompt extractionのようなconfidentiality attackは直接防がない。
- detectorが正しく検出しても、tool authorization / data-flow policyを外部で強制する必要は残る。

## LLM Model Security Taxonomyでの位置づけ

```text
Instruction hierarchy
        ↓
aligned vs conflicting lower-priority instruction
        ↓
AlignSentinel
  model-internal attention-based detector
        ↓
misaligned instruction detection
        ↓
model-level resolver
  Instruction Hierarchy / SecAlign / HIPO
```

target modelそのものをretrainするDefenseではないが、**LLM内部representationを利用してinstruction priority conflictを検知するmodel-aware Defense**として本repositoryのDefense categoryに位置づけられる。

## 実装・研究上の示唆

prompt-injection detectorを評価するとき、malicious injectionとplain benign textだけを比較すると、単なるinstruction detectorでも高精度に見える。

今後のbenchmarkでは少なくとも、

```text
misaligned instruction
aligned instruction
non-instruction
```

の3種類を分離し、FPR/FNRを測るべきである。

またmodel-level privilege separationとdetectorを組み合わせる場合、

1. AlignSentinelでconflictを検知
2. model-level hierarchy Defenseでconflictをresolve
3. capability / tool layerでunauthorized effectをblock

という多層Defenseが考えられる。
