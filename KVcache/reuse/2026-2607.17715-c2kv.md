# C²KV: Compressed and Composable KV Cache Reuse for Efficient LLM Inference

## 概要

既存KV reuseはprefill FLOPsを削減できても、長いdocumentのfull-size KVをstorageへ保存し、requestごとにGPUへtransferするcostが残る。

またgeneric KV compressionをreuse cacheへ単純適用すると、既にcontext interactionを欠いたKVへさらにcompression errorが加わりaccuracyが大きく落ちる。

C²KVは、**最初からreuseを前提にcompressedかつcomposableなKV representationを学習する**。

base LLMはfreezeし、lightweight sidecar Extractorとlearnable compression tokensを学習する。

## 問題設定

従来のnon-prefix reuseは、

```text
document
 → full-size cached KV
 → storage
 → transfer
 → concatenate
 → repair / recomputation
```

となる。

長contextではprefillを省いてもKV I/Oが新しいbottleneckになる。

さらにSnapKVのようなgeneric compressionをCacheBlend/EPIC/Block-Attention等へ後付けするとqualityが大幅に悪化することを著者らは示す。

したがってcompressionとreuseを独立問題として扱うだけでは不十分。

## C²KVの基本発想

C²KVはdocumentから通常のfull KVを作る代わりに、sidecar Extractorで少数のcompression tokensへ情報を集約する。

概念的には、

```text
document tokens
      ↓
lightweight Extractor
      ↓
compressed reusable KV
      ↓
multiple caches concatenate
      ↓
frozen base LLM
```

となる。

重要なのはrepresentationを単に小さくするだけでなく、

- compressed
- position-agnostic
- independently extractable
- composable

にすること。

## Sidecar Extractor

base modelそのものを大規模にfine-tuneせず、別のlightweight Extractorを学習する。

learnable compression tokensがdocument informationを集約し、reuse時にはそのcompact representationだけを保存・転送する。

base LLMをfreezeするため、既存model本体を大きく変更するarchitecture-level methodとは異なる。

## Structured attention flow

independent documentから作ったrepresentationを後から連結できるよう、Extractor内のattention flowを制御する。

これによりdocumentごとのcacheが別々に作られていても、reuse時のcompositionを想定したrepresentationを形成する。

position-specificな通常KVをそのまま保存する方式と異なり、position-agnostic reuseを目指す。

## Compression–concatenation co-training

C²KVの重要点はcompressionだけを単独学習しないこと。

```text
compress document
+
concatenate multiple compressed caches
+
downstream generation
```

を同じtraining objectiveで扱い、extraction-time representationとactual reuse behaviorをalignする。

これにより「単体では良いcompressed KVだが、複数documentを並べると壊れる」問題を避ける。

## Generic compression + reuseとの差

論文ではSnapKVを既存reuse手法へ単純追加した場合を評価する。

Llama-3.1-8B-Instructの例では、HotpotQAでFull Recompute + SnapKVが0.5045に対し、

- Naive reuse + SnapKV: 0.0547
- Block-Attention + SnapKV: 0.0743
- EPIC + SnapKV: 0.0897
- CacheBlend + SnapKV: 0.0532

まで落ちるsettingがある。

つまり、

> **reuse errorとcompression errorは単純には独立でなく、naive compositionで増幅する**

ことがC²KVのmotivation。

## CacheBlend / EPICとの差

[CacheBlend](2024-2405.16444-cacheblend.md)や[EPIC](2024-2410.15332-epic.md)は基本的にfull-dimensional cached KVをreuseし、位置/context mismatchをinference-timeに補正する。

C²KVは、

> reuse時にfull KVをrepairするのではなく、最初からreuse可能なcompact representationを学習する

方向。

そのためstorage/transfer costも同時に削減できる。

## Block-Attentionとの差

[Block-Attention](2024-2409.15355-block-attention.md)はblock-wise KV reuseを前提にbase model側をfine-tuneしてreuse-friendlyにする。

C²KVではbase LLMをfreezeし、sidecar Extractor側をtrainingする。

| | Block-Attention | C²KV |
|---|---|---|
| learned component | base model | sidecar Extractor |
| cached representation | normal KV block | compressed reusable KV |
| position handling | block-aware / re-encoding | position-agnostic representation |
| storage reduction | primary goalではない | **primary goal** |
| composition | block reuse | co-trained composability |

## Experiment Setup

複数のlong-context benchmarkとmodel familyで評価する。

multi-document QA、summarization等を含み、compression ratioを4×から16×程度まで変えてqualityとefficiencyを測定する。

比較対象にはFull Recompute、naive reuse、Block-Attention、EPIC、CacheBlend、generic compression併用などが含まれる。

## Main Results

長context settingで**最大17× inference speedup**を報告する。

C²KV-4x-ResはMuSiQue、SAMSum、MultiNews等でfull-context baselineに近い、または上回るaccuracyを示し、WikiMQAなどmulti-document QAでは既存reuse手法を大きく上回る。

compression ratioを4×→16×へ強めてもperformance degradationが比較的gradualで、aggressive compressionへのscalingも示す。

## 主要ablation

### Compression aloneでは不十分

generic compressorを既存reuseへ後付けすると大幅にaccuracyが落ちる。

これがcompression-concatenation co-trainingの必要性を支持する。

### Compression ratio

4×から16×までcacheを縮小しても急激には崩れず、learned representationがhigh compressionでも一定のrobustnessを持つ。

### Residual design

C²KV-4x-Resなどresidual informationを残すvariantがquality-memory trade-offで強い。

## Limitations

1. training-free reuseではなく、sidecar Extractorの学習が必要。
2. base modelをfreezeできてもmodel familyごとにExtractor adaptationが必要になる可能性がある。
3. full KV互換ではない専用representationなのでserving engine側のintegrationが必要。
4. compressed representationのstorageは減るが、Extractor execution costが追加される。
5. arbitrary compositionやdomain shiftへのgeneralizationはさらに検証余地がある。

## KV-cache taxonomyでの位置づけ

主分類は **reuse / compressed reusable representation / position-independent composition**。

ただしKV storage量も直接減らすため`compress`との境界に位置する。

paper_searchでは「compressionの目的がreuse cacheのstorage/transfer/composability改善」であるため`reuse`へ置くのが自然。

## 技術系譜

```text
Block-Attention / EPIC
modular / position-independent reuse
        ↓
CacheBlend / ProphetKV
full-size reused KVをselective repair
        ↓
C²KV
compressed + position-agnostic + composable representationを学習
```

従来の「full KVをどう正しく再利用するか」から、「再利用専用representationをどう設計するか」へ問題設定を広げている。
