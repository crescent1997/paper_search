# MagicPIG: LSH Sampling for Efficient LLM Generation

## 問題設定
長文decodeではattentionの計算・memory readがsequence lengthとともに増える。TopK tokenだけを残すsparse attentionは重要tokenを取り逃す場合がある。MagicPIGはattentionを近似する際に、決定的TopK選択ではなく確率的samplingを使う。

## 手法
QueryとKeyの近さをLSHで近似し、attentionへの寄与が大きいtokenが高確率で選ばれるようsamplingする。sampling probabilityに基づくimportance correctionにより、選択集合からattention outputを推定する。Key側のhash/index構築、Query側のbucket探索、Value gatherを組み合わせる。samplingによるvarianceとindex管理コストが精度・速度の主要trade-offとなる。

## Experiment Setup / Main Results
Long-context generationでfull attentionと各種sparse attentionを比較し、quality、attention approximation、GPU memory bandwidth、decode latency、index build costを測定する。sampling budgetを減らすほどread量は小さくなるが推定分散は増えるため、task別の精度変化が重要。

## Ablation
Hash数・bucket幅・sampling budget・importance weightingの有無を変え、retrieval recallだけでなくattention outputと生成品質の誤差を評価する。index build overheadがprefill/TTFTに与える影響も分けて評価する。

## Limitations
確率的手法のため実行ごとの結果に分散がある。低いsampling budgetで稀な重要tokenを見落とす可能性がある。LSHのhash構築やGPU gatherが支配的になると理論上のread削減が実時間短縮につながらない。
