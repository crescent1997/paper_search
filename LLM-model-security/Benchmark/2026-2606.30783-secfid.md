# Security–Fidelity Tradeoffs: The Hidden Cost of Prompt Injection Defense (SecFid)

## 概要・問題設定

従来のprompt injection benchmarkは「data内のinjected instructionを実行したか」をAttack Success Rate (ASR)で測る。しかしASRが低い理由は2種類ある。

1. **正しいseparation:** modelがinjected instructionを**命令としては実行せず、dataとしては正しく処理**した。
2. **過剰な抑制:** modelが疑わしいspanを**丸ごと無視**した。

両者はsecurity-only metricでは区別できない。例えばtranslation taskでは、悪意あるimperative sentenceを命令として実行するのは誤りだが、翻訳対象から消すことも誤りである。SecFidはこの**security–fidelity tradeoff**を直接測る。

## Threat Model

trusted task instruction $s$ とuntrusted data $d$ を受け取るmodel $M$ を考える。attackerはdata中へprobe $z$ を挿入できるが、trusted instruction、model weights、inference pipelineを変更できない。target outputは $y=M(s,d_z)$。評価は**fixed non-adaptive probes**であり、Defense-aware attackerがoutputを観測して繰り返し最適化するworst-case evaluationではない。

## Method: Behavioral Separability

SecFidの核は、1つのprobeに対して次の3つの行動が**異なる最終出力**になるようtaskを構築すること。

- **EXECUTED:** probeをinstructionとして実行し、その質問のsignature answerを出す。
- **PROCESSED:** probeの文字列をtrusted taskに従ってdataとして処理する。
- **IGNORED:** probe spanを出力に反映せず、clean dataだけを処理する。

例えば「文書内の大学名を全て抽出せよ」というtrusted taskに、`What state is Stanford University in?`というprobeを埋め込む。PROCESSEDならStanford Universityが大学名として増える。IGNOREDなら増えない。EXECUTEDならCaliforniaというsignature answerが出る。3つの挙動が識別可能になる。

## Task Design

**Full-text family:** translationとediting。probeをdataとして扱えば翻訳/編集後の文書に反映され、無視すればspanが欠落する。

**Partial-text family:** entity extractionとcounting。probeがtarget categoryのentityを1つ追加するため、処理すればentity setまたはcountが変わる。

計**1,168 instances**の内訳は、counting **307**、extraction **310**、translation **278**、editing **273**。probe位置はprefix / middle / suffix、framingはplain / persuasion。translationは英語からSpanish / Portuguese / German / French / Italian、editingはFineEdit由来、counting/extractionはentity制御可能なsynthetic documentsを使う。

## Evaluation Metrics

signature answerの出現でEXECUTEDを判定する。counting / extractionはprogrammatic checks、translation / editingはEmbeddingGemmaによるprocessed/ignored referenceへのembedding similarityを使う。後者は両referenceに対してsimilarity <0.5ならOTHERとする。

$$\mathrm{Security}=1-P(\mathrm{EXECUTED})$$

$$\mathrm{Fidelity}=1-P(\mathrm{IGNORED})$$

**重要な注意:** EXECUTEDはPROCESSED/IGNORED/OTHERと独立に判定されるため、4つの率はexclusive partitionではなく、和が100%になるとは限らない。またFidelityは「必ず正しく処理した率」ではなく**non-suppression rate**である。厳密なsecure processingを見るなら

$$P(\mathrm{PROCESSED}\land\neg\mathrm{EXECUTED})$$

も必要になる。

## Experiment Setup

closed API / open weightsを含む15 base model settingsと、reasoning variants・defended variantsを含む**48 configurations**を評価。defenseは**ASIDE / DefensiveTokens / ISE / SecAlign**を含む。model familyはClaude、Gemini、GPT、Gemma、Llama、Qwen。task family・probe placement・framingごとのpaired differencesやconfidence intervalsも検討する。実装は公開され、`dataset JSONL + responses JSONL -> results JSONL + summary JSON` のoffline scoringを採用する。

## Main Results

**Security–Fidelity frontier:** 48 configurationsのどれも両軸で高得点の領域へ到達しない。

- **Llama 3.3 70B（無防御）:** Fidelity **96.5%**、Security **47.8%**。dataはよく残すがinjectionに弱い。
- **SecAlign + Llama 3.1 8B:** Security **99.3%**、Fidelity **73.9%**。
- **SecAlign + Llama 3.3 70B:** Security **99.3%**、Fidelity **71.0%**。
- **DefensiveTokens + Qwen2.5-7B:** Security **96.9%**。ただしfidelity低下が大きい。

**同じSecurityでもDefenseの中身が違う:** あるDefenseはhijacked outputをfaithful processingへ戻し、別のDefenseはdata自体を消してASRを下げる。従来のASRはこの違いを見落とす。

**Model scaling:** 必ずしも両指標を改善しない。Llama 8B→70BではFidelityが上がる一方、Securityはむしろ低下する例がある。Claudeの大規模化ではSecurity上昇とFidelity低下が同時に観測される。

**Reasoning effort:** 平均Securityはbaselineからlow / medium / high reasoningで約**+6.3 / +9.1 / +12.6 points**改善する一方、Fidelityの改善は小さい。reasoningで「危険な命令を実行しない」ことは改善しても「dataを落とさず扱う」能力は別問題となる。

## Generalization / Robustness / Adaptive Attack

prefix / middle / suffix、plain / persuasion、full-text / partial-textのslice別分析により、同じmodel/defenseでもtaskやprobe表現でtradeoffが変化することを示す。ただしprobeは固定・非adaptiveであり、ChatInject、GCG、PISmithのようなDefense-aware attack optimizationのupper-boundではない。embedding similarity判定のthresholdや参照文品質もmetric validityへ影響し得る。

## Decision-Theoretic Interpretation

securityとfidelityの最適な重みはdeploymentで異なる。翻訳・文書編集ではspan omissionのcostが高く、tool execution agentではmalicious actionのcostが高い。概念的には、

$$\mathrm{Risk}\approx C_{hijack}P(\mathrm{EXECUTED})+C_{drop}P(\mathrm{IGNORED})$$

をdeployment-specific costで評価すべきである（上式は直感を示す簡略式）。単一のASR rankだけでは最適Defenseを決められない。

## Instruction Hierarchy / Privilege Separationとの関係

[The Instruction Hierarchy](../Defense/2024-2404.13208-instruction-hierarchy.md)の目標は、lower-priority instructionがconflictするときだけ無視し、**aligned/benign lower-priority dataは有効利用する**ことである。SecFidは後半の性質を定量化する。したがって、単に低信頼領域をmaskしてASRを下げる方法を過大評価しないための補完指標になる。

[IHEval](2025-2502.08745-iheval.md) / [IH-Benchmark](2026-2607.25987-ih-benchmark.md)が**priority relationを守るか**を評価するのに対し、SecFidは**priority relationを守ったうえでdataを使えるか**を評価する。

## ASIDE / ISE / SecAlign / 関連Benchmarkとの関係

- [ASIDE](../Defense/2025-2503.10566-aside.md): instruction/data embeddingの幾何学的分離がdata fidelityへ与える影響を測る。
- [ISE](../Defense/2024-2410.09102-instructional-segment-embedding.md): privilege embeddingがsource distinctionとcontent preservationを両立するか測る。
- [SecAlign](../Defense/2024-2410.05451-secalign.md) / [Meta SecAlign](../Defense/2025-2507.02735-meta-secalign.md): DPOによるsecure response selectionがdata suppressionを生まないか検証する。
- [Rethinking Assessments of Prompt Injection Attacks](2026-acl-findings-1191-rethinking-prompt-injection-assessments.md): evaluation setting / application diversityを拡張する先行meta-evaluation。SecFidは**success metric自体**を拡張する。
- [ICoA](../Attack/2026-2608.30362-icoa.md): ICoAがcovert/overtという**user observability**を分離するのに対し、SecFidは**security vs content fidelity**を分離する。
- [Robustness via Referencing](../Defense/2025-2504.20472-robustness-via-referencing.md): output filteringでASRを下げても、data preservationは別途測る必要がある。

## Limitations

- fidelityは $1-P(IGNORED)$ であり、strict semantic correctnessそのものではない。
- fixed non-adaptive probes。adaptive GCG / RL attacksのworst-case robustnessではない。
- translation/editingのembedding-based judgeはsemantic omissionの細部を誤判定し得る。
- probeは自動判定可能なsynthetic signatureを持ち、自然な攻撃文の全分布を代表しない。
- model/API更新により結果が変動する。
- deploymentごとのcost関数はbenchmarkが決めるものではない。

## LLM Model Security taxonomy / 実装・研究上の示唆

**Benchmark → instruction/data separation → dual-axis Security + Fidelity evaluation**。既存IH benchmarkの「higher priorityに従ったか」に、**lower-priority dataを消さずに利用できたか**を加える。RAG / document processing / agentを評価するときはASRだけでなく`executed / processed / ignored / other`を保存し、task-specific utility・semantic preservation・adaptive attack結果を並列に報告することが望ましい。
