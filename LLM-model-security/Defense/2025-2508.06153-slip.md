# SLIP: Soft Label Mechanism and Key-Extraction-Guided CoT-based Defense Against Instruction Backdoor in APIs

> **選定：自動選定、ACL 2026 Findings公式採択によるvenue fallback。** Scholarの信頼できる総引用数未取得のため`cited: null`。ACL PDF 22頁、arXiv初投稿日・著者・所属・code URL照合済み。GitHub Defense一覧には未登録。

## 概要・選定理由
SLIPは、customized LLM APIの**隠れたsystem promptに攻撃者がbackdoor命令を混入**させる状況で、利用者がモデルを再学習・内部観測できなくても正しい回答を回復することを狙う。普通のprompt injectionは低権限tool/userが高権限systemを偽装するが、本研究は**高権限systemの内容がすでに汚染**されているという別の境界条件を扱う。防御は外部の別guard modelを必須とせず、poisoned API自身へのpromptを工夫する。

## 問題設定 / Threat Model
- **攻撃側**: 悪意あるcustomized API提供者がhidden system instructionへtrigger→target label規則を仕込む。利用者はsystem promptの中身を閲覧・変更できない。
- **防御側**: API呼び出し（自然言語promptと生成結果）のみ使用可能。重み・gradient・logit・内部activation・fine-tuning access不要。
- **攻撃primitive**: 特定のword/syntax/semantic trigger、BadChain型の推論汚染。正規入力にtriggerが含まれると本来の分類／QAではなく攻撃者のlabelを返す。
- **防御目標**: trigger検出だけでなく、汚染入力に対する正しい出力を回復し、clean accuracy (CACC)を維持する。
- **権限モデル上の注意**: 正規system > userの優先順位を直接強化する手法ではなく、悪意あるsystem命令に従ってしまうpoisoned agentから、推論時にtask semanticsを抽出して回避する。通常のSecAlign型「systemが正しい」という前提と異なる。

## 先行研究からの改善点
ONIONなど入力perplexityベースのtrigger除去、ZS-CoTやCoSの自己推論・検出は、triggerを認識できてもpoisoned APIの最終分類を修正できない場合がある。SLIPは(1) task-related key phrasesの抽出と(2) 各句のlabelとの**相関scoreを定量化**し外れ値を捨てる仕組みを組み合わせる。black-boxでも「出力を回復する」ことが新規性。

## Method / Algorithm
1. **Pilot: cognitive override**。hidden backdoorが存在すると、モデルはtask semanticsよりtriggerの規則を優先しやすい。
2. **Pilot: abnormal semantic correlation**。poisoned APIに各phraseとlabelの相関を数値で回答させると、triggerは意味的に無関係でもtarget labelに極端に近いscoreを返す傾向がある。
3. **KCoT / Key-extraction-guided Chain-of-Thought**。入力全文の直接分類を避け、task-relevantな複数のphrase `E={e_i}` を抽出させる。triggerへの一極集中を避けるが、`E`にtriggerが残ることがある。
4. **SLM / Soft Label Mechanism**。poisoned APIに各 `e_i` の候補labelへの相関score `s_i` を返させ、平均から大きく外れるscoreの句を除去。論文Eq. (5)は `E'={e_i in E: |s_i - mean(s)| < δ}`（δはprompt経由で決定）と記述。
5. 残った句のscoreを平均し、事前に定義したlabel区間へ写像して最終回答を決定。**SLIP-ZS**（zero-shot）と、clean examplesを付与する**SLIP-FS**（few-shot）を比較。分類以外のopen-ended generationへそのまま一般化できる保証はない。

## Experiment Setup
- **分類**: SST-2、AG News、Amazon。**QA**: CommonsenseQA (CSQA)、MMLU。
- **攻撃**: word-level、syntax-level、semantic-level instruction backdoor、およびBadChain。hidden system instructionにtrigger規則を注入したcustomized APIを想定。
- **APIモデル**: GPT-3.5-Turbo、DeepSeek-V3、Claude-3。異なるAPI/タスクの集計値を混ぜない。
- **比較**: No Defense、ONION、Zero-Shot CoT (ZS-CoT)、Chain-of-Scrutiny (CoS)、SLIP-ZS、SLIP-FS。
- **指標**: ASR（攻撃者targetへの誘導、低いほど良い）、CACC（clean accuracy、高いほど良い）、TSR（抽出句にtriggerが残る率）、FAR/FRR。単純な「検出率」ではない。

## Main Results
- 論文abstractでの分類系総括: SLIPの**平均ASR 25.13%**、**clean accuracy 87.15%**。arXiv abstractには防御前ASR 90.2%→25.13%と記載。評価集合・集計方法を固定せず他表と混ぜない。
- **QA（Table 2, 6設定の平均）**: SLIP-FSはASR **18.45%**、CACC **62.23%**。No DefenseはASR **70.32%**、CACC **62.06%**、ONIONはASR 27.83%／CACC 54.68%、CoSはASR 50.72%／CACC 55.98%。
- **DeepSeek-V3/Amazonのablation（Table 3）**: No Defense平均ASR **83.95%**、CACC **83.10%**。KCoTのみASR **53.28%**、CACC **86.17%**。KCoT+SLMはASR **29.05%**、CACC **88.78%**。追加SLMが約24.23ポイントのASR低下に寄与。
- QAでの個別例（Table 2）: DeepSeek-V3/CSQAのSLIP-FSはASR **4.38%**、CACC **83.50%**。GPT-3.5-Turbo/MMLUではASR **29.33%**で残余攻撃がある。

## Generalization / Robustness / Adaptive Evaluation
- word/syntax/semantic/BadChainの異なるtriggerタイプを評価。ONIONはword-levelでは比較的有効でも、syntax/semantic triggerで脆弱になる場合がある。
- SLIP-ZSはSLIP-FSよりASRが低いケースもあるが、clean accuracyが大きく悪化するため、少数のclean exampleを使う設計にutility上の利点がある。
- KCoTのみのtrigger survival rateは高い（Table 3平均TSR 59.95%）。SLM追加後もTSRは57.03%であり、**trigger自体の完全除去が成功条件ではなく、相関score集約の頑健化が効く**。
- 記載された実験は固定attack typeに対する評価であり、SLMの閾値・score計算を知った適応的攻撃者によるend-to-end最適化、Meta-SecAlign/StruQ/SecAlignに対する直接比較は未確認。

## Limitations
- モデル内部を改変せず、**汚染された高優先度system命令そのものを消すわけではない**。入力によってはtriggerが残り、ASRも0%にはならない。
- scoreが校正されていない、複数trigger、極端に短い文、free-form生成などでは外れ値仮定が崩れ得る。
- 分類・選択式QA中心。多階層system/developer/user/toolの一般的なinstruction hierarchy遵守率を直接測定していない。
- 複数API呼び出し／追加reasoningに伴うlatencyとtoken costは運用上の考慮点。数値を一般化しない。

## LLM Model Security taxonomyでの位置づけ
`Defense > Black-box Inference-Time Output Recovery > High-Privilege Instruction Backdoor`。内部activationに介入するCachePrune/RAP-IDと異なり、**API-onlyの出力制御**。高権限promptの供給網が攻撃面となる点でPARASITEと隣接。

## 実装・研究上の示唆
- 正常時精度、攻撃時ASR、追加問い合わせ費用を三軸で報告する。trigger detectionと最終出力の復旧を別metricとする。
- label scoreの平均と外れ値閾値の感度分析、adaptive trigger設計への頑健性、KV reuseの可能性を追加研究対象とする。
- API-only防御をmodel-internal fine-tuning型Defenseと比較する際は、攻撃者の権限が異なることを明記する。
