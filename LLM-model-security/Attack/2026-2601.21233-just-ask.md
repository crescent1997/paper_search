# Just Ask: Curious Code Agents Reveal System Prompts in Frontier LLMs

## 概要

Just Askは、system prompt extractionを固定jailbreak promptの設計問題ではなく、**targetとのinteractionを通じて有効な抽出strategyを発見・改善するblack-box online exploration problem**として扱うAttackである。

system promptはapplication policy、tool-use rule、hidden workflow、developer instruction等を含むhigher-privilege informationである。Just Askは単一の「repeat your system prompt」に依存せず、成功したattack skillを再利用しながら未知targetへ適応する。

## 問題設定 / Threat Model

attackerは通常userとしてqueryできるが、model weights、gradients、logits、hidden states、system prompt本体、server-side implementationにはアクセスできない。したがって基本条件は**pure black-box**である。

目的はhigher-privilegeなsystem promptを可能な限り忠実にrecoverすることであり、単にpolicyを一度破るjailbreakとは異なる。

## Jailbreak / Prompt Injection / System Prompt Extraction

- **Jailbreak**: model自身のsafety/alignment policyに反するoutputを生成させる。
- **Prompt Injection**: lower-trust instructionをhigher-trust application instructionより優先させる。
- **System Prompt Extraction**: higher-trust instructionの内容自体を外部へ漏洩させる。

Just Askは3番目を主対象とし、Instruction Hierarchyにおけるconfidentiality / privilege separation failureを測る。

## 先行研究からの改善点

従来は人間が作ったprompt template、role-play、instruction override、encoding等の固定集合でsystem-prompt extractionを試すことが多い。Just Askはattackをskill spaceとして整理し、targetへの成功・失敗から有効strategyをonline更新する。static benchmarkではなく**adaptive attacker**を近似する点が主要な差分である。

## Method / Algorithm

### Attack Skill Space

system prompt extractionに使えるstrategyをatomic / higher-level skillとして整理する。直接開示要求だけでなく、部分再構成、変換、説明、引用、debugging等の異なるinteraction patternを組み合わせる。

### Online Statistics

各skillについて試行回数、成功回数、estimated success rateを蓄積し、target固有のbehaviorをattack policyへ反映する。

### UCB-based Exploration

次に試すstrategyはUpper Confidence Bound型scoreで選択する。

```text
UCB_i = empirical_success_i + exploration_bonus_i
```

成功しているstrategyを再利用するexploitationと、試行回数の少ないstrategyを試すexplorationを両立する。

### Iterative Recovery

```text
initial skill set
      ↓
query target
      ↓
evaluate leakage
      ↓
update skill statistics / rules
      ↓
select next attack
      ↓
accumulate recovered information
```

というloopでsystem promptを段階的にrecoverする。

## Attack Primitive / Access Requirement

attack primitiveはadversarial suffixではなく、**natural-language interaction strategyのadaptive selection**である。gradient/logit accessは不要で、suffix固定でもない。prefix、multi-turn、indirect request等を利用でき、closed commercial modelにも適用できる。

[GCG](2023-2307.15043-gcg.md)、[Faster-GCG](2024-2410.15362-faster-gcg.md)、[SlotGCG](2026-2606.05609-slotgcg.md)等のwhite-box token optimizationとは対照的である。

## Experiment Setup / Main Results

frontier commercial models / code-agent systemsを含む多数のtargetに対し、full / near-complete recovery、semantic similarity、hidden informationの回収、target間の成功差、adaptive explorationの寄与等を評価する。

重要なのは万能promptを1つ発見したことではなく、**targetごとに有効なattack pathを探索することでcoverageを広げる**点である。固定attack setで安全に見えるmodelでも、interactive attackerが試行結果からstrategyを変えると漏洩しうる。

## Query / Compute Cost

backpropagationは不要なのでattacker側GPU computeは小さい。主なcostはtargetへのquery数である。したがってDefense評価ではASRだけでなくquery budget、rate limit、conversation reset、cross-turn memory、attack adaptationを明示する必要がある。

## Transferability

GCGのように1つのsuffixを直接transferするのではなく、抽象的な**attack skill / exploration policy**がtransferable knowledgeになる。targetが変わってもskill libraryを再利用し、online feedbackからweightを更新できる。

## Instruction Hierarchyとの関係

[The Instruction Hierarchy](../Defense/2024-2404.13208-instruction-hierarchy.md)はsystem instructionをuserより高priorityとして扱う。しかしpriority followingとconfidentialityは別問題である。

```text
integrity:
  lower privilege must not override higher privilege

confidentiality:
  lower privilege must not read hidden higher-privilege data
```

Just Askは後者のfailureを強く測る。

## 既存Defenseとの関係

[StruQ](../Defense/2024-2402.06363-struq.md)、[SecAlign](../Defense/2024-2410.05451-secalign.md)、[Meta SecAlign](../Defense/2025-2507.02735-meta-secalign.md)は主にtrusted promptとuntrusted data間のinstruction conflictを扱うため、prompt-injection ASRだけではsystem-prompt confidentialityを十分評価できない。

[Instructional Segment Embedding](../Defense/2024-2410.09102-instructional-segment-embedding.md)もsource identityを強化するが、higher-priority segmentの内容がgenerationから漏洩しないことまでは自動保証しない。

[CaMeL](../Defense/2025-2503.18813-defeating-prompt-injections-by-design-camel.md)はcapability / provenanceをsystem-levelで制御するが、Privileged LLM自身によるnatural-language leakageは別途対策が必要になる。

## Role Confusionとの関係

[Prompt Injection as Role Confusion](2026-2603.12277-prompt-injection-role-confusion.md)は低権限textをtrusted roleらしく見せるauthority spoofingを扱う。Just Askはrole spoofingを必須とせず、modelのhelpfulnessや説明能力を探索してhigher-privilege informationを引き出す。

```text
Role Confusion:
  low privilege → looks high privilege

Just Ask:
  low privilege → reads high-privilege content
```

という異なるprivilege-escalation axisである。

## Limitations

- 複数queryを必要とし、rate limitingやsession isolationの影響を受ける。
- code-agent中心の評価が全chat applicationへ同程度に一般化するとは限らない。
- semantic recoveryとtoken-level exact recoveryは異なる。
- system prompt secrecy自体をsecurity boundaryにすべきでないapplicationもある。
- tool permission等のauthorizationは別途必要。

## LLM Model Security Taxonomyでの位置づけ

```text
Privilege integrity
  GCG / prompt injection / role confusion
  → lower privilege overrides higher privilege

Privilege confidentiality
  Just Ask
  → lower privilege recovers higher-privilege content
```

## 実装・研究上の示唆

system prompt protectionは固定prompt setだけでなく**query-budget付きadaptive evaluation**で測るべきである。秘密情報をsystem promptへ直接置く設計も避け、model-level refusalに加えてsecret separation、tool authorization、output leakage detection、session controls、proxy representation等を組み合わせる必要がある。

この観点で[ProxyPrompt](../Defense/2025-2505.11459-proxyprompt.md)は直接的な対照Defenseとなる。
