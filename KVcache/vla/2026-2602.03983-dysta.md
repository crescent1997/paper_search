# DySta — Static-Dynamic Disentanglement for VLA

## 1. 概要と問題設定

従来のVLAは1時刻の画像だけを入力することが多く、過去の操作（どの缶を先に温めたか、物体の元の位置はどこか）を保持できない。一方、各時刻の画像を単純にconcatすると、フレームあたり`N`個のvisual tokenを`T`時刻分処理するためcontextが`NT`に増え、prefillとKV cacheの負担が大きい。

DyStaの中心的な仮説は、環境には時間スケールの異なる情報が混在するというもの。背景や部屋の配置は長く不変、物体の外観は中程度、グリッパーの姿勢や接触状態は短時間で変化する。視覚tokenをこの寿命に応じて**学習して分離**すれば、static部分は履歴に1回だけ置き、動的部分だけ時刻ごとに追加できる。単なるpixel差分で再計算位置を選ぶVLA-Cacheと異なり、**再利用に耐える表現をモデル自身に学習させる**点が特徴。

## 2. 先行研究との差

| 方法 | 時間的冗長性の扱い | 履歴のLLM入力 | 学習要否 |
|---|---|---|---|
| [VLA-Cache](2025-2502.02175-vla-cache.md) | 画像類似度とattentionでvisual KVを再利用 | 基本的に現フレーム中心 | training-free |
| [LAC](2026-2602.00686-lac.md) | learned selectorとcache ratioで部分再計算 | 主眼はcross-frame加速 | selector/rate moduleの学習が必要 |
| [FlashVLA](2025-2505.21200-flashvla-action-reuse.md) | action自体のskipとvisual token pruning | 過去actionを記憶 | training-free |
| **DySta** | multi-level static/dynamic tokenとlearned recache | static一式＋各時刻dynamic | **表現とgateの学習が必要** |

著者は、見た目が同じpatchでもTransformerのattentionで周囲の状態に依存したhidden stateに変化するため、pixel-level静止判定はlatent KVの不変性を保証しないと指摘する。ただしDyStaも全入力に対する厳密なfull-prefill等価性を証明する手法ではない。

## 3. 手法

### 3.1 Multi-level static/dynamic tokens

Vision encoderから得る`N`個のtokenを`L`階層のstatic token `Z_t^{s_l}`とdynamic token `Z_t^d`へ分割する。論文の実装は**L1 static=133 token (52%)、L2 static=107 token (42%)、dynamic=16 token (6%)**。各階層の比率はあらかじめ設定するhyperparameterであり、動的tokenは毎step更新する。

長さ`T`の履歴は、全画像tokenを連結する代わりに概念的に次のように配置する。

`[static_L1, static_L2, dynamic_(t-T+1), ..., dynamic_t]`

staticは共有prefix側に置くため、過去に作ったstatic KVを次の時刻でも再利用できる。static比率を`r`とすると、履歴長は`NT`から`NT - rN(T-1)`へ削減される。LLM backbone FLOPsの理想化された削減率は`r`（残存比`1-r`）だが、vision encoder、gate、refresh、decodeを含む実測のend-to-end削減率ではない。

### 3.2 Recache gate

各static level `l`で、前回cacheされた表現と現在観測の間隔`Δ`を考慮した`g_l(Z_{t-Δ}, Z_t) ∈ [0,1]`を計算し、`g_l > δ_l`ならrefresh、そうでなければreuseする。**L1をrefreshしたときはL2も強制refresh**する階層依存関係を持つ。訓練時にはGumbel-softmaxで二値選択を微分可能にし、推論時はthreshold判定する。

固定周期refreshと異なり、scene transition時に再計算を増やし、安定した区間ではcacheを長く保つことを目指す。gate overheadは論文の複雑度説明では約1.27%とされるが、AppendixのあるCUDA latency breakdownでは18.7ms/601.2ms=約3.1%となる。**測定対象と分母が異なる数字を同一視しない**。

### 3.3 学習目的

`L = L_task + Σ_l α_l L_InfoNCE^(l) + β L_gate`

- `L_task`: 元のVLAのaction予測目的。
- `L_InfoNCE`: 同一trajectoryの異なる時刻のstatic tokenをpositive、異なるtrajectoryをnegativeとして、静的表現の時間的一貫性を促す。
- `L_gate`: gateが常にrefreshする自明解へ収束するのを防ぐprior付き正則化。refresh prior `p_Δ = 1-exp(-λΔ)`を用い、時間が経つほどrefreshを許容する。`λ`は固定、`δ_l`で運用時のrefresh頻度を調整。

このため、既存checkpointに差し込むだけで成立するtraining-free KV cachingではない。下流タスクへのfine-tuningを伴う点を実装・再現時に明記すべき。

### 3.4 LIBERO-Memory

既存LIBEROでは現時刻画像だけで解けるタスクが多いという問題から、Robosuiteでepisodic memoryを必要とする新規benchmarkを設計する。缶を温め、元の位置に戻し、指定時間待ち、どの缶を処理したかを覚えて次を選ぶといった、`where`（Position Reset）、`when`（Doneness）、`what`（On-Stove）の3能力を測る。

## 4. Experiment Setup

- **Simulation**: SimplerEnv（CogACT backbone）とLIBERO（OpenVLA-OFT backbone、third-person image＋instruction）。比較は同一backboneへ各手法を適用した設定。
- **Real robot**: Cobot Magicで7タスク、各20試行。別途memory-dependent実機3タスク×20試行。各タスクにfine-tune。
- **Baselines**: FlashVLA、TTF-VLA、VLA-Cache、base model。Memoryタスクではfull-history OpenVLA-OFT、TraceVLA、MemoryVLA、ContextVLA。
- **Metrics**: success rate、FLOPs、CUDA latency、speedup、memory taskの時刻誤差。GPU memory peakや長時間連続稼働のstaleness曲線は主要表で未報告。

## 5. Main Results

### 5.1 Inference efficiency（論文Tables 1–3）

| Benchmark / backbone | Base latency | DySta latency | Speedup | Base SR → DySta SR |
|---|---:|---:|---:|---:|
| SimplerEnv / CogACT | 1360ms | 601ms | **2.26×** | 複数タスクで概ね維持・改善（例 PickCan 91.3→92.7%） |
| LIBERO / OpenVLA-OFT | 741ms | 437ms | **1.70×** | **95.4→96.0%** |
| Real robot / OpenVLA-OFT | 1089ms | 493ms | **2.21×** | 7タスクで概ね維持・改善 |

SimplerEnvのFLOPsはbaseを100%として43.4%、LIBEROは63.4%、実機は30.5%。ただし複数backbone・評価環境間の数値を直接比較して「普遍的に何倍」とはしない。

### 5.2 Memory integration（Table 4）

| Method | On-Stove成功率 ↑ | Position Reset成功率 ↑ | Doneness誤差 ↓ |
|---|---:|---:|---:|
| Full-history OpenVLA-OFT | 39.0% | 78.0% | 0.44s |
| ContextVLA | 50.8% | 22.3% | 0.37s |
| **DySta** | **69.8%** | **83.0%** | **0.26s** |

実機memory-dependent 3タスクでは、MemoryVLA 26.7%、ContextVLA 35.0%、DySta **58.3%**（Table 10）。「multi-frameを速くする」だけでなく、**LLMが過去のdynamic情報を直接参照できることがtask successに効く**と解釈できる。

## 6. 主要Ablation（Table 5）

| Variant | PickCan（visual matching） | MoveNear（visual matching） | PickCan（aggregation） | MoveNear（aggregation） |
|---|---:|---:|---:|---:|
| DySta | 92.7 | 88.8 | 92.4 | 81.0 |
| w/o Contrast | 91.3 | 84.6 | 91.6 | 82.7 |
| w/o L2 cache | 92.0 | 85.0 | 91.5 | 81.5 |
| Fixed-step recache | 87.7 | 81.7 | 85.3 | 74.8 |

Learned recache gateを固定周期にすると性能が大きく落ちる。Contrastとmulti-level cacheも概ね寄与するが、一部taskでw/o Contrastが高いなど、すべての列で一様に改善するわけではない。attention可視化ではdynamic tokenがgripper/可動物体、L1が背景、L2が中程度に持続するobject情報へ寄る傾向を示す。

## 7. Limitations / 実装上の論点

1. **Training-freeではない**。新規のstatic/dynamic表現とgateを学習するため、既存VLAのdrop-in最適化としては適用しづらい。
2. **Scene変化と時間的持続性の仮定**。急な照明変化、カメラ移動、全物体が動く環境ではstaticの安定性が崩れ得る。
3. **Full-prefill等価性はない**。InfoNCEが表現の不変性を促すだけで、任意の未来観測に対するKV完全一致は保証されない。
4. **Position / mask**。static prefixとdynamic historyの論理位置、causal attentionの境界、recache時のposition再割当は、vLLM/FlashInfer移植時に明示的な検証が必要。
5. **長期評価**。LIBERO-Memoryは長期依存を測るが、数時間規模のcache drift・VRAM peak・control frequency・非同期実行時の品質は十分な評価がない。
6. **Code**。著者の公式実装URLは一次資料から確認できず、`code: null`とした。

## 8. Taxonomy / 関連研究

- **Primary**: `KVcache/vla` — learned static/dynamic cross-frame KV reuse + compact temporal memory。
- **Secondary**: `reuse`（prefix reuse）、`model`（reuse-aware representation training）、`compress`（effective context縮小）。
- [VLA-Cache](2025-2502.02175-vla-cache.md)：pixel/attention heuristicによるtraining-free reuse。
- [LAC](2026-2602.00686-lac.md)：選択policyを学習するが、static表現の階層化・memory benchmarkはDyStaの特徴。
- [Reflex](2026-2607.14695-reflex.md)：flow timestep不変領域を分離するarchitecture-awareな再利用。
- [FlashVLA](2025-2505.21200-flashvla-action-reuse.md)：action reuseとtoken pruningを行い、KV自体は直接reuseしない。
- [Reducing Temporal Redundancy](2026-2607.12287-temporal-redundancy.md)：visual token refreshとflow-step compressionの2軸。
