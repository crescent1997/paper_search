# Semantic Chameleon: Corpus-Dependent Poisoning Attacks and Defenses in RAG Systems

> sleeper / triggerのdual-document poisoningと、hybrid retrievalの防御効果およびadaptive attackへの脆弱性を検証。

## 概要

sleeper / triggerのdual-document poisoningと、hybrid retrievalの防御効果およびadaptive attackへの脆弱性を検証。 RAGのretrieval corpusを通じて生成回答のintegrityが侵害されるリスクを扱う。private corpus extractionではなくknowledge poisoningのカテゴリに属する。

## 問題設定 / Threat Model

攻撃者はretrievalに影響する外部コンテンツを操作できることを前提とする。RAGのgenerator内部を直接変更するのではなく、retrieved evidenceの選択または解釈を通じた回答操作を検証する。論文ごとのquery knowledgeとwhite-box accessの違いは、以下の手法で区別する。

## Method / Algorithm

GCGによるgradient-guided poisoningをsleeper documentとtrigger documentへ適用。dense-only retrievalでのco-retrievalを観測し、BM25とdense scoreを組み合わせるhybrid retrievalによる防御、さらにsparse+dense双方へ適応した場合を比較する。

## 先行研究からの改善点

[PoisonedRAG](2024-2402.07867-poisonedrag.md)のcorpus poisoning系譜に属するが、retrieval architectureとcorpus vocabularyへの依存を明示的に評価。

## Experiment Setup

Security Stack Exchange 67,941 documents、50 attack attempts、top-5 retrieval。FEVER Wikipediaで25 attacksを追加評価し、GPT-5.3、GPT-4o、Claude Sonnet 4.6、Llama 4、GPT-4o-miniの5 familiesも比較。

## Main Results

dense-onlyではco-retrieval 38.0%、hybrid retrievalでgradient-only attackは0%。adaptive sparse+dense optimizationでは20–44%の成功。FEVERでは25 attacks全てで0%。generation-side successは46.7–93.3%。co-retrievalとoverall successを混同しないことが重要。

## Ablation / Transferability / Robustness

dense-onlyとhybrid retrieval、adaptive optimization、corpus差、generator family差を切り分ける。防御の効果はattack objectiveに依存する。

## Limitations / 成立条件

retrieval corpusへのpoisoned contentの混入可能性が必要であり、アクセス制御や信頼済みcorpusのみの運用ではthreat modelが異なる。特定のcorpus、retriever、generatorの結果を全RAGへ一般化できない。実際のpoison exposureと最終的なgeneration manipulationは別指標として評価する必要がある。

## RAG Security Taxonomyでの位置づけ

Attack → Retrieval / Knowledge Poisoning → Answer Integrity。retrieved documentの機密情報を抜き取るextraction attackとは異なり、retrievalされた証拠を汚染するintegrity riskである。

## 実装上・研究上の示唆

retrieverのranking robustnessだけでなく、retrieved passagesの出所、cross-modal consistency、generatorがevidenceをどう採用するかを分離して検証する必要がある。query-awareな防御だけでなく、未知queryへの汎化とadaptive attackerを含めた評価が重要となる。
