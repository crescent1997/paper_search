# μVLA — 追加モジュールなしの最小recurrent memoryを切り分ける

## 概要

本研究は「複雑なmemory bankやretrievalがなくても、VLA backboneの内部で少数のmemory tokenを時刻間に渡すだけで、どこまで非Markov操作が解けるか」を厳密に比較する。OpenVLA-OFTのmultimodal prefixへ $m$ 個の学習可能なmemory tokenを挿入し、次のstepへ出力tokenを受け渡す。訓練では時刻間にgradientを流すTruncated BPTT（TBPTT）を採用。外部のエピソード記憶検索・write/forgetting controllerはなく、**Transformer KV cacheを保存・再利用する方式ではない**。

## 問題設定・先行研究との差

POMDPでは最適行動は $\pi(a_t\mid o_{1:t},\ell)$ に依存するが、通常のchunk型VLAは $\pi(a_{t:t+H-1}\mid o_t,\ell)$ で現在画像のみを見る。MemoryVLAのような多要素設計は記憶機構それぞれの寄与が混ざる。μVLAはmemory width $m$、TBPTT長 $K$、更新規則（gradient / EMA）以外の構成を固定し、recurrence単体の効果を評価する。履歴を追加tokenとして毎回再入力する方法と異なり、memory tokenの本数を固定する。

## 手法

- 時刻$t$の入力: 現在の2カメラ観測、proprioception、指示、前stepのmemory token $M_t\in\mathbb{R}^{m\times d}$。出力: action chunkと更新されたmemory $M'_t$。
- 自己attentionを通して $M'_t$ を生成し、次時刻へ $M_{t+1}=M'_t$ として渡す。Memory tokenは観測・指示・過去memoryへattentionできるが、**action tokenを読む経路はmaskで禁止**し、教師actionのコピーを防止。
- TBPTTでは連続$K$時刻のaction imitation lossを累積し、$K$境界でmemoryをdetach。比較対象は $K=1,2,8$ と、学習を通さないEMA write：

$$M_{t+1}=\alpha\,\mathrm{stopgrad}(M'_t)+(1-\alpha)\,\mathrm{stopgrad}(M_t).$$

- 学習データはepisode順を保つdataloaderへ変更。開始時にmemory初期化、終了時にreset。
- 推論は各environment stepで再度policyを呼び、予測chunkの**先頭1 actionのみ実行するreceding-horizon**。chunkを丸ごと実行するとmemory更新が8stepに1回となり、途中のcueを取り逃すため。これがthroughput低下の主因。
- BackboneはOpenVLA-OFT / OpenVLA-7B、LoRA rank 32。**追加fine-tuningが必要**。

## Experiment Setup

- MIKASA-Robo: 訓練5タスク、held-out matched-memory-semantics 11タスク、held-out novel-semantics 7タスクの計23環境。各環境100 deterministic episodes、成功率（success_once）。
- LIBERO: Spatial/Object/Goal/Long-10の4 suite、各subtask 50 episodes。Markovな操作で性能低下がないかを検証。
- 2カメラ224×224、chunk horizon $H=8$、memory幅 $m=64$（$m=1$比較も実施）、hidden size 4096。8×H100 80GB、LoRA rank32、最大150k steps。
- 比較: OpenVLA-OFT（通常frame-shuffled）、同じepisodic dataloaderのmemoryless、初期frameを常時入力するoracle-style比較、$\pi_{0.5}$、異なる$K$・EMA。コードとcheckpointは著者GitHubで公開を確認。

## Main Results

| 評価 | memoryless OpenVLA-OFT | μVLA $m=64,K=2$ | 補足 |
|---|---:|---:|---|
| MIKASA訓練5環境の平均SR | 0.42（episodic版0.48） | **0.84** | 初期frame追加oracle 0.85 |
| held-out / matched memory semantics 11環境 | 0.07（episodic） | **0.23** | 初期frame oracle 0.24 |
| held-out / novel semantics 7環境 | 0.07（episodic） | **0.16** | 多数のRotate系タスクではほぼ0 |
| LIBERO平均 | 97.1%（論文掲載OFT） | $K=8$ variant **96.2%** | $K=2$ のLIBEROは未報告 |

注意: LIBEROの96.2%は **$K=8$** の値であり、MIKASAの最良 **$K=2$** と混同しない。さらにEMAのLIBERO平均は44.8%であり、**すべてのrecurrence variantがMarkov環境で安全というわけではない**。

**実行コスト（Appendix G、RememberColor5、実測）**

| モデル | Forward latency | Simulation-step latency | Throughput | Peak GPU memory |
|---|---:|---:|---:|---:|
| OpenVLA-OFT（chunked H=8） | 61.33 ms | 47.93 ms | **20.86 Hz** | 15,358.70 MiB |
| μVLA $m=64,K=2$（1stepずつ） | 66.65 ms | 107.55 ms | **9.30 Hz** | 15,434.04 MiB |
| μVLA $m=64,K=8$ | 67.16 ms | 109.44 ms | 9.14 Hz | 15,434.04 MiB |
| μVLA EMA | 68.27 ms | 109.95 ms | 9.09 Hz | 15,434.54 MiB |

1 forwardあたりの追加latencyは約5ms、GPUメモリ増は約75MiBと小さいが、**制御方式の変更により実効制御step throughputは半分以下**。推論効率化の論文ではなく、固定サイズ記憶による成功率改善の論文である。学習コストは $K=2$ で8×H100・2日18時間、$K=8$ では約12日と重い。

## 主要ablation

| 訓練5環境の平均SR | 値 |
|---|---:|
| memoryless standard | 0.42 |
| memoryless episodic dataloader | 0.48 |
| $m=1,K=8$ | 0.54 |
| $m=64,K=8$ | 0.57 |
| **$m=64,K=2$** | **0.84** |
| $m=64,K=1$ | 0.57 |
| $m=64,EMA$ | 0.57 |

RememberColor5では $K=2$ が0.93、$K=1$ が0.40、$K=8$ が0.35。memory widthを増やすだけでなく、**短いcross-step gradient経路**が重要。訓練5環境での利得が全く新しいmemory semanticsへそのまま転移するわけではない。初期frame oracleは最良0.85だが、初期frameに存在しない情報の後続保持は評価上の別問題。

## Limitations / 評価上の注意

1. **KV cacheの圧縮/再利用ではない。** 毎stepのfull forwardが必要で、固定サイズmemory tokenをTransformerで更新する。KV memory削減効果は報告なし。
2. 外部event memoryと異なり、記憶内容を明示的に検索・削除できず、未学習の依存構造に弱い。長期タスク全般への一般化は未証明。
3. 低latencyを論じる際は、1-call latencyと環境step throughputを必ず分ける。実測では20.86→9.30Hzに低下。
4. $K$の学習時メモリ/時間コストが大きい。$K=2$と$K=8$の結果がベンチごとに混在する点に注意。
5. MarkovなLIBEROでEMAは44.8%と大幅悪化。論文の「no regression」は最良TBPTT設定についての限定的主張。

## Taxonomy / KV cacheとの関係

- **VLA / recurrent working memory / POMDP / fixed-width latent memory**。
- Transformerの過去KVをそのまま使うTempoFitやVLA-Cacheとは異なり、memory tokenは**過去の情報を学習で圧縮したlatent state**。
- EventVLAのraw keyframe、MemoryVLAのperceptual-cognitive memory bankと比較すると、memory tokenの容量は固定だが情報の追跡可能性が低い。
- KV研究上は、固定memory tokenに対するKV保存・incremental prefill、chunk更新頻度とcontrol frequencyの共同最適化が未解決。
