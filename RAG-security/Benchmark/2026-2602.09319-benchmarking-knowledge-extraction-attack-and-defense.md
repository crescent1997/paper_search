# Benchmarking Knowledge-Extraction Attack and Defense on Retrieval-Augmented Generation

> RAGのknowledge-base extraction研究でばらばらだったattack、defense、retriever、generator、indexing、dataset、metricを統一し、どこで漏洩が起きるのかをstageごとに比較できるbenchmarkを提示する。

## 概要

RAGではknowledge baseにprivate / proprietary dataを置くことが多く、malicious queryによってその内容を抽出できることが近年示されている。一方で既存研究は、retrieverやLLM、dataset、metric、attack assumptionが異なるため、手法間の比較が難しい。

本論文はこの問題を解決するため、knowledge extraction attackとdefenseを同一frameworkで再実装・比較する。

## Benchmarkの設計

評価を主に以下へ分解する。

- **Retriever Extraction Effectiveness**: attack queryがsensitive knowledgeをretrieveできたか
- **Generator Extraction Effectiveness**: retrieved knowledgeをgeneratorがどの程度外部へ出力したか
- **Combined Extraction Effectiveness**: retrievalとgenerationを合わせた最終的な抽出性能
- **Attack Success Rate (ASR)**: query単位でattackが成功した割合

これにより、attack failureがretrieval段階なのかgeneration段階なのかを切り分けられる。

## Attack群

benchmarkでは、random token / random text系のbaselineに加え、代表的なknowledge extraction attackを比較する。

- **DGEA**: embedding spaceを利用してretrievalを直接最適化するタイプ
- **IKEA**: benign-looking queryを反復生成してknowledge baseを探索するタイプ
- **CopyBreak**: extracted contentをfeedbackとして次query生成へ利用するタイプ

重要なのは、embedding-specificなattackとnatural-language query型attackではtransferabilityが大きく異なる点である。

## Defense群

RAG pipelineの異なるstageへ防御を入れる。

- **Query Block**: malicious intentを持つinputを拒否
- **Threshold**: retrieval scoreが低いdocumentを除外
- **System Block**: generatorへcontext disclosure禁止を指示
- **Summary**: raw retrieved textをそのまま渡さずsummaryへ変換

## 主な結果

### 1. 単一defenseでは十分でない

どのdefenseも万能ではなく、attack classによって有効性が異なる。

### 2. DGEAはcross-retriever transferが弱い

特定embedding modelへ合わせて最適化するattackは、retrieverが変わると性能が落ちやすい。

一方、IKEAやCopyBreakのようにnatural-language queryとしてknowledgeを探索するattackは、retriever依存性が比較的低くtransferしやすい。

### 3. Query Blockはbenign-looking attackに弱い

露骨なprompt injectionには有効でも、IKEAのような通常質問に見えるqueryを識別するのは難しい。

### 4. Summary defenseはverbatim leakage抑制に比較的有効

retrieved raw textを直接generatorへ渡さないため、exact reconstructionを抑えやすい。ただしsemantic information leakage自体を完全に防ぐわけではない。

### 5. Knowledge-base indexing方式もsecurityに影響する

fixed chunk、original document、graph tripletなどindexing方式を変えると、retrieval surfaceやextractionしやすさが変化する。

つまりRAG securityはgeneratorだけでなく、knowledge representationとindex constructionにも依存する。

## RAG Data Extraction Riskとの関係

今回のrepositoryで扱うknowledge-base stealing研究を横断比較するための基準として非常に重要である。

特に、

```text
Attack Query
  ↓
Retriever leakage
  ↓
Generator leakage
  ↓
Final extraction
```

を分離評価するため、CopyBreakRAG、IKEA、DGEA系の違いを整理しやすい。

## Limitations

- 実験対象のretriever / generator / datasetは有限で、全production RAGを代表するわけではない。
- defenseは代表的なものに限定され、ACLやtenant isolationなどsystem-level access controlは十分扱わない。
- exact / near-verbatim extraction中心のmetricではsemantic leakageを過小評価する可能性がある。
- 新しいagentic attackやmulti-modal RAGに対してbenchmark拡張が必要。

## 重要なポイント

- RAG knowledge extraction attack/defenseを統一条件で比較するsystematic benchmark。
- retrievalとgenerationを分離して評価できる。
- DGEAはembedding依存、IKEA / CopyBreakはcross-retriever transferしやすい。
- benign query型attackはquery filteringを回避しやすい。
- Summary defenseはverbatim leakage抑制に比較的強い。
- indexing形式そのものもsecurityに影響する。
- 今後RAG data extraction研究を比較する際の共通基準として有用。
