# PARASITE: Conditional System Prompt Poisoning to Hijack LLMs

> **選定：自動選定、ACL 2026 Mainの公式採択によるvenue fallback。** Google Scholarを第一候補に引用数を調べたが信頼できる総引用数を取得できず、`cited: null`。**2026-10-17に調査候補として挙がった論文の再検証・完成版**であり、2026-10-24時点のGitHub Attack一覧に未登録であることを確認。原著ACL PDF 20頁、arXiv metadataを照合。

## 概要・選定理由
第三者が作ったsystem promptを利用者がインストールする状況で、system権限を持つprompt自体が悪意ある内容になり得ることを示す。正当なsystem命令を低権限のuser/toolが偽装する通常のindirect prompt injectionではなく、**system prompt供給網の侵害**が脅威モデル。モデル重み・学習データは変更しないが、system roleに配置される文字列の完全性が失われる。GCGのような一般的jailbreakと異なり、特定の問いだけを誤らせ、その他の問いでは有用性を維持する条件付き攻撃を扱う。

## 問題設定 / Threat Model
- **Attacker control**: 公開marketplace/リポジトリに置くsystem promptの本文。利用者が信頼して導入した後はsystem roleで実行される。user roleの末尾に任意suffixを追加する攻撃ではない。
- **Target**: API経由で問い合わせ可能な凍結LLM。重み・gradient・hidden state・logit accessは不要。回答文字列に基づく**black-box optimization**。
- **Objective**: 対象集合 `Q_t` では誤情報／指定回答への誘導を成功させ、無関係な `Q_b` では正答率を維持する。prompt自体の流暢性・低perplexity・対象質問との低類似度も考慮。
- **Trust boundary**: 不正な第三者製system promptが高優先度のinstructionとして実行される。モデルが正しいrole priorityを学習していても、**高権限入力そのものが汚染**されれば守れない。正規のsystemと低権限の競合指示の解決性能とは分けて解釈する。

## 先行研究からの改善点
GCGはtoken-level gradientを用いたadversarial suffix最適化、典型的には安全拒否の回避が目的。PARASITEは**非勾配・条件付き・system prompt全体の最適化**であり、攻撃対象を一般的拒否破りではなく特定質問への応答改変に移す。重み改変を必要とするtraining-time backdoor、検索結果に注入するindirect PIとも異なる。比較法はNo System Prompt (NSP)、ECLIPSE、手書きprompt、Stage 1のみのAdversarial AutoPrompt (AAP)。

## Method / Algorithm
1. 対象質問集合 `Q_t` と通常質問集合 `Q_b` を用意。攻撃lossと通常性能lossを合わせた `L(p)=L_adv(p)+L_benign(p)` を小さくする制約付き探索。論文はさらに `Sim(p,Q_t) <= δ`、`Perplexity(p) <= τ` を流暢性・秘匿性の指標として提示。
2. **Stage 1 / Global Semantic Search (AAP)**: GPT-4o-miniをprompt rewriterとして用い、候補system promptを生成。各候補について対象／通常質問で回答を照合し、F1閾値0.5による離散評価値で探索。Evaluator→Analyzer（失敗例分析）→Generator（改稿）の反復で自然言語のprompt骨格を得る。
3. **Stage 2 / Greedy Lexical Refinement**: leave-one-outのloss差 `I_w=L(p)-L(p\{w})` で重要語を順位付け。重要語の表層変換候補（単語分割、文字交換、キーボード近傍置換、文字削除、同義語置換）を比較し、両目的のlossが改善する変更を採用。**gradientではなくモデル呼び出しと応答評価を使用**する。
4. 機能的stealth（無関係質問で高性能）と語彙的stealth（自然なprompt）を同時に評価する。最適化対象はsystem promptの**prefix/body**であり、GCG型のuser suffixやretrieved document injectionではない。

## Experiment Setup
- **モデル**: Llama2-7B/13B、DeepSeek-7B、Qwen2.5-7B等のopen model、およびGPT-4o-mini、GPT-3.5-Turbo API。モデル・表・出力形式により設定が異なる。
- **タスク**: TriviaQAを用いたuntargeted poisoning、TruthfulQAを用いたtargeted poisoning。安全有害文生成のAdvBenchを主評価とはしていない。
- **分割**: 10件のtarget paraphraseと20件のbenign queryで最適化、未見100件のtarget paraphraseと1,000件のbenign queryで評価する設定。商用API評価では費用制約からモデルあたり10 target questionを抽出。
- **指標**: token F1、Exact Match、`ΔF1=F1_benign-F1_malicious`。**untargeted**では悪意ある質問集合の正答F1が低いほど攻撃成功。**targeted**では指定誤回答への一致を測るため、数値の方向が異なる。ASRと単純に同一視しない。

## Main Results
- TriviaQA untargeted（原著Table 2）: Llama2-7BのPARASITEはbenign F1 **63.84**、malicious F1 **33.36**、差 **30.48**。Llama2-13Bは66.77/32.66/34.11、DeepSeek-7Bは43.99/28.15/15.84、Qwen2.5-7Bは50.31/34.94/15.37。ECLIPSEは両方のF1を極端に落とし、選択的な破壊が弱い場合がある。
- GPT-4o-mini untargeted（Table 4）: PARASITEはbenign F1 **71.44**、malicious F1 **52.44**、差19.00。手書きpromptのmalicious F1は99.28であり、対象側の性能を大きく下げた。GPT-3.5-Turboではbenign 61.00、malicious 69.47、差**-8.47**であり、全モデルで正のgapを保証するわけではない。
- 論文abstractは対象質問のF1を**最大70%低下**と報告。ただし評価指標・対象モデルに依存し、一般的なjailbreak ASR 70%を意味しない。
- 論文はblack-box APIコストを**対象あたり約2米ドル**と概算。これは特定のモデル・価格・実験設定の値であり、query回数の普遍的な上限ではない。

## Generalization / Robustness / Transferability / Adaptive Evaluation
- 最適化時と別のtarget paraphrase、1,000件の未見benign queryで評価。two-option→four-option/free-formへの形式変更でも一定の攻撃効果が残るが、効果はモデルにより大きく異なる。
- 文字誤りを除くと攻撃性能が落ちるablation。初期prompt探索を省く場合より二段階構成の方がtargeted settingで優位。
- GPT-5ベースのsemantic judge等の検知率を比較。論文Fig. 7ではECLIPSEのGPT-5検知約**81.8%**に対しPARASITEは約**5.5%**。これは検知器・評価集合依存。
- prompt polishing/paraphrasingは攻撃を常に無効化できず、通常タスク性能も落とす場合がある。
- **StruQ / SecAlign / Meta-SecAlign / CaMeLへの直接ASRは未評価**。攻撃者がsystem権限のprompt自体を提供するので、これらの「低権限データからの越権防止」とは異なる攻撃面である。

## Limitations
- 第三者system promptを導入するという供給網前提が必要。通常のuser権限だけでは再現できない。
- 比較したguardrailは限定的。すべてのmodern model-level defenseに対する突破実証ではない。
- 1,000件benign holdoutでもモデルによって通常性能が約20ポイント落ちると著者自身が報告し、完全なstealth保証はない。
- 有害生成のjailbreak、機密system prompt抽出、tool出力に埋め込むindirect injectionとは攻撃目的・権限が異なる。

## LLM Model Security taxonomyでの位置づけ
`Attack > High-Privilege Prompt Supply-Chain Compromise > Conditional Prompt Poisoning`。**Role spoofing**ではなく、system roleの入力完全性に対する攻撃。モデル内部のprivilege separationが正しくても、信頼する高権限コンテンツの供給者を誤ると破綻することを示す補完的脅威。

## 実装・研究上の示唆
- 研究用評価では、(a) 正当system promptに対する低権限攻撃、(b) system prompt自体が汚染された供給網攻撃を別条件に分ける。
- attack successだけでなく通常queryでのF1/EM低下とtargeted/untargetedの指標方向を必ず併記する。
- prompt integrity（署名・版管理・信頼できる配布元）をmodel-level priority learningと独立に管理する必要がある。
