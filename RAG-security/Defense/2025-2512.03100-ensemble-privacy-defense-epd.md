# Ensemble Privacy Defense for Knowledge-Intensive LLMs against Membership Inference Attacks（EPD）

> **読むべきポイント**：private RAG corpusに特定文書が含まれるかを推測する**membership inference**を、SFTのtraining-data membership inferenceと同じ7攻撃で比較し、**target model・base model・judge model**の3者を用いたinference-time defenseを提案する。RAGでの7攻撃平均はASR **0.590→0.548**、AUC **0.571→0.503**、TPR@1%FPR **0.047→0.022**（TriviaQA）。ただし、**private corpus全体のexfiltrationを直接阻止した実験ではない**。RAG extractionとMIAを混同しないことが重要。

## 概要

RAGは外部の非公開文書をLLMのcontextに取り込む。これにより回答品質が改善する一方、出力の違いから「ある文書が検索対象のcorpusに含まれるか」を推測される **retrieval-corpus membership inference attack（MIA）** が成立する。対照的にSFTでは、特定の学習サンプルがモデルのfine-tuningに用いられたかを推測する。前者は**retrieval indexのmembership**、後者は**parameter updateに使われたtraining setのmembership**であり、秘密の対象が異なる。

本論文の第1の目的は、同じbase LLM、類似するQAタスク、7種類のMIAを使い、RAGとSFTのmembership leakageを比較することである。第2の目的は、trainingやモデル内部の変更を必要としない **Ensemble Privacy Defense（EPD）** を設計し、MIAの成功を下げつつ回答の有用性を保つことである。

EPDは、(1) retrievalを使うtarget modelの回答、(2) private corpusにアクセスしないbase modelの回答、(3) 両者の回答・生成損失を評価して回答を書き直すjudge modelを組み合わせる。低いtoken lossや逐語的な表現をmembershipの手掛かりと見なし、judgeにそのような特徴を避けるよう指示する。

**注意**：これはRAGのretrieved documentsを丸ごと盗むRAG-ThiefやRAGCrawlerへの直接的な対策ではない。privacy taxonomy上は**document membership inferenceへのresponse-level mitigation**に位置づく。加えて、本文の「526.3% improvement」は複数の相対改善率の比較に由来する記述で、**漏洩確率が526.3%減った**という意味ではない。具体的な表の絶対値を優先して解釈する。

## 問題設定・Threat Model

### 秘密と攻撃目標

- **RAG**：秘密は外部retrieval corpus $C$。攻撃者は候補文書 $x$ を持ち、$x\in C$ かを推定する。文書本文全体を復元することは、この評価の直接目標ではない。
- **SFT**：秘密はfine-tuning dataset $D_{\mathrm{SFT}}$。攻撃者は候補サンプル $x$ が学習に使われたかを推定する。
- どちらもbinary membership $m(x)\in\{0,1\}$ を推測し、攻撃scoreのAUC、ASR、低FPRでのTPRを測定する。

### Attacker capabilityと重要なアクセス条件

攻撃者はvictimの重み、private corpus、retriever構成を知らず、モデルにqueryを投げて観測結果を利用する。論文はこれをblack-boxと呼ぶが、**log-likelihood / token probability / lossに基づくMIAも評価**している。したがって、*自然言語の最終回答だけが得られるstrict text-only API* と、*logprobsやlossを取得できるscore-access API* を同一視してはならない。LiRA等のreference-based MIAには追加のreference modelまたはcalibration情報が必要になる。

防御側はtarget model、非fine-tuned base model、judge modelを運用でき、生成tokenのcross-entropyを取得できる。SFTモデルの重み変更やRAG retrieverの再学習は不要だが、**追加のLLM inferenceとloss computation**を要求する。

### 評価する7種類のMIA

| Attack | 分類 | 主なmembership signal |
|---|---|---|
| Recall | Reference-free | 対象sampleに対するrelative conditional likelihood / recall |
| Log-Loss（LL） | Reference-free | tokenのnegative log-likelihood |
| Zlib | Reference-free | lossとcompressibilityに関係する統計 |
| Min-K | Reference-free | 低確率tokenの下位K%のscore |
| Min-K++ | Reference-free | token scoreの正規化による改善版 |
| SPV-MIA | Reference-based | self-prompt calibrationに基づく確率変動 |
| LiRA | Reference-based | reference modelとのlikelihood-ratio的な差 |

このattack suiteは広く使われるMIAを比較する利点がある一方、RAG専用のstealthy document-specific probeやmulti-turn extractionを網羅するものではない。

## 先行研究からの改善点

### 既存のMIA defenseとの違い

**Training-time DP / unlearning / data sanitization** は強いprivacy保証を得られる可能性があるが、データやモデルの再学習が必要になる。RAGでprivate corpusを更新するたびに再訓練する運用には向きにくい。

**HAMP** は出力confidenceを下げてmembership signalを弱める方向、**DP-Logits** はlogitsへnoiseを加える方向のinference-time baselineである。いずれも回答品質や特定attackへの頑健性に課題がある。EPDは単一モデルの確率分布を直接平坦化するのではなく、**private contextの影響を受けた回答と受けていない回答を比較し、第三のLLMに最終回答を合成させる**点が異なる。

**先行RAG MIA研究**として、本文は Anderson et al. (2025) *Is My Data in Your Retrieval Database?*、Liu et al. (2025) *Mask-based Membership Inference Attacks for Retrieval-Augmented Generation* を引用する。ただし両者を直接baselineとして採用せず、SFT/RAG共通に適用できる7種類の一般的MIAを使っている。これは比較条件の統一には役立つが、**RAG固有の最強attackに対する防御性能は未確認**というトレードオフになる。

### この論文で追加したこと

1. Llama-2-7Bを共通baseとして、LoRA-SFTとtop-5 RAGを比較し、同じMIA suiteでprivacyの違いを分析。
2. target/base両者のanswerと生成lossをjudgeに渡し、membership cueを減らす**training-free inference-time ensemble**を構築。
3. AUC、ASRだけでなく**TPR@1%FPR**を報告し、回答のEM/F1も確認。
4. judge size、retrieval depth、judgeの選択bias、追加noiseの効果をablation。

## Method / Algorithm

### 全体の処理

```text
query q
  ├─ target branch: RAG or SFT model → answer a_target + loss L_target
  └─ base branch: non-finetuned Llama-2-7B → answer a_base + loss L_base
                            ↓
        judge prompt(q, both answers, both losses)
                            ↓
           DeepSeek-R1-Distill-Qwen-8B
                            ↓
        privacy-aware final answer a_final
```

### Step 1: 2種類のcandidate answer生成

Target $M_{\mathrm{target}}$ はRAGの場合はretrieveしたcontext付きで回答し、SFTの場合はfine-tuned modelで回答する。Base $M_{\mathrm{base}}$ はtask-specificなfine-tuningを行っていない元のLlama-2-7Bである。

$$
a_{\mathrm{target}}=M_{\mathrm{target}}(q),\qquad
 a_{\mathrm{base}}=M_{\mathrm{base}}(q).
$$

前者はknowledge injectionによる正確性が期待できるが、membership signalも含みうる。後者は対象private corpusから直接情報を得ないため、回答は不正確になりうる一方、corpus固有の記憶・条件付けを含みにくい。

### Step 2: 生成領域のtoken-level lossを算出

各回答の生成token列 $g_1,\dots,g_T$ について、平均cross-entropyを計算する。

$$
L(q)=-\frac{1}{T}\sum_{t=1}^{T}\log p_\theta(g_t\mid x(q),g_{<t}).
$$

TargetとBaseのlossを比較可能にするため、論文では**生成列を同じ長さにtruncation**し、promptではなく生成領域のnext-token likelihoodを評価する。小さいlossは高いconfidenceを示すが、必ずしもmembershipを意味しない。特に一般常識、定型文、繰り返し表現でもlossは小さくなるため、lossをprivacy labelと解釈しない。

### Step 3: LLM-as-a-Judgeによるprivacy-aware rewriting

$$
a_{\mathrm{final}}=M_{\mathrm{judge}}\bigl(\phi(q,a_{\mathrm{target}},L_{\mathrm{target}},a_{\mathrm{base}},L_{\mathrm{base}})\bigr).
$$

Appendix Bのjudge promptは、accuracyとprivacyを両立するよう指示し、**exact quotes / precise measurementsを避け、general languageを使い、両候補を統合**するよう求める。これは明示的なPII entity detectorやretrieval authorization checkerではない。judgeが「何が秘密か」を完全に知っているわけでもない。

実装上、judgeがtargetの候補回答そのものを受け取るため、judgeが外部APIの場合は**そのAPIへの送信が新たなデータ共有経路**となる。論文のMIA防御性能と、judge側への機密送信リスクは別に評価すべきである。

### Step 4: Optional adaptive noise（ablation）

本体のEPDに必須ではないが、target/base回答のembedding similarityとloss差からnoise強度を決める拡張も試す。

$$
\Delta_{\mathrm{loss}}=\frac{|L_{\mathrm{target}}-L_{\mathrm{base}}|}{\max(L_{\mathrm{target}},L_{\mathrm{base}})},\quad
\beta=0.6(1-\mathrm{sim}(a_{\mathrm{target}},a_{\mathrm{base}}))+0.4\Delta_{\mathrm{loss}}.
$$

$\beta$ が閾値 $\tau$ を超えると、対象tokenのlogitsへGaussian noiseを加える。閾値は0.1/0.05を比較する。実験では攻撃によって効果が逆転するため、**noise追加を主要な改善要因とは結論づけていない**。

## Experiment Setup

| 項目 | 設定 |
|---|---|
| Base / target LLM | Llama-2-7B。SFTはLoRA、RAGは未fine-tuned model |
| SFT | LoRA rank 8、alpha 16、learning rate $10^{-4}$、batch size 4、block size 128、early stopping |
| RAG retriever | SentenceTransformer `all-MiniLM-L6-v2`、cosine similarity、context embedding事前計算 |
| Retrieval | top-k = 5（ablationでk=1,5,7,10） |
| Judge | DeepSeek-R1-Distill-Qwen-8B（1.5B版と比較） |
| RAG/SFT比較 | TriviaQA、SQuAD |
| EPDの主評価 | TriviaQA（RAG・SFT）、AG News（SFTのみ） |
| Dataset規模（論文Table 8） | TriviaQA train 87,622/test 11,313；SQuAD train 87,599/test 10,570；AG News train 120,000/test 7,600 |
| Attacks | SPV-MIA、LiRA、Recall、Log-Loss、Zlib、Min-K、Min-K++ |
| Baselines | No Defense、LLM-HAMP、DP-Logits |
| Metrics | MIA AUC、ASR、TPR@1%FPR（小さいほど防御成功）；QA Exact Match / F1（大きいほど良い） |
| 計算環境 | 著者のlimitationsでは主にRTX 4090を使用 |

**Datasetの区別**：RAG vs SFTの比較はTriviaQA/SQuADだが、EPD本体の防御表はTriviaQA中心。AG Newsはretrieval contextを持たないため**SFTだけ**で評価されており、AG News結果をRAGの一般化証拠として扱うべきではない。

## Main Results

### 1. RAGとSFTのMIA susceptibility

Appendix Table 7では、TriviaQAとSQuADを横断して7攻撃を比較している。RAGは概ねSFTよりmembership leakageが小さいが、すべてのattack/datasetで優位ではない。

例としてTriviaQAのRecallでは **SFT AUC 0.7526 / ASR 0.6969** に対して **RAG AUC 0.3856 / ASR 0.6026**。一方、TriviaQAのLiRAでは **SFT ASR 0.5078 / RAG ASR 0.5126** でRAGが僅かに悪い。SQuADのMin-K++も **SFT AUC 0.5123 / RAG AUC 0.5145** で改善しない。

**解釈上の注意**：AUCが0.5を下回る場合、membership scoreの向きを反転できるattackerなら $1-\mathrm{AUC}$ の識別力を利用できる可能性がある。論文はAUCを一律に小さいほど安全として集計するが、**AUC 0.23をAUC 0.5より安全とみなすのは一般的なMIA評価では危険**である。この点は後述する。

### 2. TriviaQA・RAGでのEPD（Table 2）

7攻撃の平均値（↓が防御にとって望ましい方向として原論文に記載）：

| Defense | AUC | ASR | TPR@1%FPR |
|---|---:|---:|---:|
| No Defense | 0.571 | 0.590 | 0.047 |
| LLM-HAMP | 0.560 | 0.565 | 0.035 |
| DP-Logits | 0.563 | 0.601 | 0.038 |
| **EPD** | **0.503** | **0.548** | **0.022** |

EPDはNo Defense比でASRを**0.042ポイント（約7.1%相対）**、TPR@1%FPRを**0.025ポイント（約53%相対）**低減する。特に低FPRのmembership検出を難しくしている点が有意義。一方、平均ASR 0.548はランダム推測に近づいたとはいえ**完全なmembership privacyではない**。

Attack別の例：

| MIA | No Defense AUC / ASR / TPR@1 | EPD AUC / ASR / TPR@1 | 観察 |
|---|---|---|---|
| LiRA | 0.377 / 0.513 / 0.010 | 0.240 / 0.500 / 0.000 | TPR@1低下。ただしAUCの向きに注意 |
| Log-Loss | 0.599 / 0.662 / 0.104 | 0.539 / 0.552 / 0.026 | 3指標とも改善 |
| Zlib | 0.686 / 0.619 / 0.104 | 0.616 / 0.596 / 0.067 | AUC/ASR/TPRを低下 |
| Recall | 0.386 / 0.603 / 0.031 | 0.558 / 0.557 / 0.036 | ASR改善でもAUC・TPRは悪化 |
| Min-K++ | 0.780 / 0.557 / 0.041 | 0.505 / 0.541 / 0.010 | AUC/TPRを大きく低下 |

このように、**attackごと・metricごとに効果は一様でない**。論文Abstractの「RAG 526.3%」を、そのままMIA成功率の削減率として引用しないこと。

### 3. TriviaQA・SFTでのEPD（Table 1）

7攻撃平均では、No Defenseの **AUC 0.673 / ASR 0.670 / TPR@1 0.083** に対し、EPDは **0.525 / 0.560 / 0.014**。LLM-HAMPは **0.549 / 0.563 / 0.039**、DP-Logitsは **0.547 / 0.597 / 0.052**。SFTでは平均ASRも0.110ポイント低下し、低FPR側の改善が大きい。

ただし、SFTの結果はprivate retrieval corpusへの対策を直接実証するものではない。RAG研究として読む場合、**Table 2のRAG結果を主評価**とすべきである。

### 4. Answer Utility（Table 3）

TriviaQAのSFT設定、test setから抽出した1,000件で評価：

| 手法 | Exact Match | F1 |
|---|---:|---:|
| 原論文表の `Ground Truth` 行 | 0.3560 | 0.4466 |
| DP-Logits | 0.2690 | 0.3150 |
| LLM-HAMP | 0.2070 | 0.2874 |
| **EPD Judge** | **0.3320** | **0.4047** |

EPDは他のinference-time defenseより回答品質を維持している。ただし表の`Ground Truth`は行名としてそう記載されているもので、通常の「正解ラベルのEM=1.0」という意味ではない。元のtarget/no-defenseとの対応は慎重に読む必要がある。また**RAGにおけるanswer utilityの同じ粒度の比較は示されていない**。

## Ablation / Robustness / Additional Experiments

### Judgeのサイズ（Table 5）

DeepSeek-R1-1.5Bと8Bを比較した7攻撃平均：

| Judge | AUC | ASR | TPR@1 |
|---|---:|---:|---:|
| 1.5B | 0.569 | 0.569 | 0.0300 |
| 8B | **0.526** | **0.559** | **0.0157** |

大きいjudgeが総じて有利だが、SPV-MIAのASRは1.5Bの0.32に対し8Bで0.51と悪化する。すべてのmetric・attackで単調改善するわけではない。Judgeの性能がprivacyの強さに影響するため、model-agnosticであっても**judge capacityには依存**する。

### Retrieval depth k（Figure 4）

SQuAD上で $k\in\{1,5,7,10\}$ を比較。大きなkでもEPDのMIA抑制は概ね維持されるが、**kを増やすとASRが僅かに増える傾向**が報告される。retrieval diversityとprivacy exposureの関係を示す。ただしFigure 4の曲線から読み取れない厳密な数値は推測していない。

### Judgeが実際に何を出力するか

Judge出力をtarget/base/mixedへ分類すると、**targetを選択19.9%、baseを選択10.4%、mixed 69.7%**。大半は単純copyではなく合成であり、提案意図と整合する。ただしこの分類は文字列一致、F1、prefix similarityを使うheuristicであり、**mixedだから機密情報を含まないことの証明にはならない**。

### Adaptive noiseの追加（Table 6）

$\tau=0.1,0.05$ で追加noiseを試すと、LiRAではAUCが0.23→0.22へ僅かに低下するが、Min-KやZlibではASRが悪化する設定がある。**EPD本体のanswer synthesisが主要効果であり、noiseはoptional**という結論。

## Limitationsと成立条件

1. **Full-corpus extraction防御ではない**：RAG-Thief、RAGCrawler、GeoEx等が狙う「何千件の文書を復元できるか」は評価していない。membership AUCを下げても、verbatim chunk leakageを防ぐとは限らない。
2. **Black-boxの定義が緩い**：attack suiteにtoken-level loss/probabilityを要する手法が含まれる。通常のtext-only RAG APIで同じ攻撃と防御の比較が成立するかは未検証。
3. **AUC<0.5の解釈**：LiRAのEPD AUC=0.240は、attackerがscoreを反転できるなら実効AUC=0.760になりうる。単純にAUCを下げることがprivacy改善と一致しないケースがある。特に原論文のrelative improvement集計はこの点に注意が必要。
4. **No formal DP guarantee for EPD本体**：judgeによる回答の合成は経験的なmembership signalの弱化であり、差分プライバシー保証ではない。Appendix Fのoptional noiseにRDP accountantの記載はあるが、メインEPDの保証に読み替えてはいけない。また掲載されたRDP式は標準Gaussian mechanismのnoise variance依存と整合するか追加確認が必要。
5. **Judgeへの機密流出経路**：judgeはtargetの回答を受け取る。第三者のAPIに送信する場合、private context由来の情報を新たな主体に開示するリスクがある。閉域・同一trust boundaryでのjudge運用が前提になりうる。
6. **追加推論コスト**：target + base + judgeの生成とloss計算が必要。論文は主にRTX4090で評価し、judgeが大きい場合や高QPS servingでのlatency / throughput評価は限定的。
7. **Datasetsとattack diversity**：TriviaQA/SQuAD中心で、企業の非公開契約書、医療PII、長い機密文書、adaptive multi-turn attackerなどでの一般化は不明。
8. **Judge promptによるutility loss**：precise measurementsや引用を避ける設計は、正確な数値回答やsource attributionが必要なRAGに不向きな場合がある。権限のある利用者への回答まで曖昧化する恐れがある。
9. **Reference attackへの非対称性**：LiRAのreference modelなど、攻撃者が持つ補助情報の違いで比較結果が変わる。MIAのASRやAUCはそのまま絶対的なprivacy probabilityを意味しない。

## RAG Security Taxonomyでの位置づけ

| 軸 | EPDの位置 |
|---|---|
| Asset | Private RAG retrieval corpusにおける文書の存在情報（membership） |
| Attack | Document-level MIA。training-set MIA（SFT）も併せて評価 |
| Defender intervention | Generation / response layer。retrieverやindexは変更しない |
| Security objective | Member / non-memberを区別するoutput signalの弱化 |
| 強み | 再学習不要、複数MIAへの横断評価、回答品質の維持 |
| 未確認 | Raw chunk exfiltration、session-level crawling、prompt-injection leakage、厳密なDP保証 |

**研究上の示唆**：RAGにおける「documentが存在するかの推定」と「document本文の復元」は別のattack classである。EPDは前者の評価には有用だが、後者を扱うRAGFort、CanaryRAG、RAG-CTなどと比較するには、**同じvictim RAGでMIA AUC/TPR@low-FPRとcorpus recovery rateを両方測る**必要がある。またRAGのtoken-level scoreを取得できないAPIでは、text-only MIAとの比較が重要となる。

- [ImageAuditor: Membership Inference Attack against Image-based Retrieval-Augmented Generation](../Attack/2026-2606.03354-imageauditor.md)：cross-modal membership inference。Judge-based rewritingがvisual asset membershipにも効くかは未検証。
- [RAG-CT](2026-2609.16095-rag-ct.md)：retrieval similarity scoreの分布からPII-targeted extractionを検出するretrieval-time defense。EPDとは防御段階もattack classも異なる。
- [RAGFort](2025-2511.10128-ragfort.md)：knowledge-base extractionを対象にしたdual-path defense。EPDのMIA mitigationと相補的。
- [CanaryRAG](2026-2604.10717-canaryrag.md)：retrieved chunksへのcanary埋め込みでexfiltrationを検知。EPDでは測らないchunk recoveryを評価する。
- [DP-SynRAG](2025-2510.06719-dp-synrag.md)：corpusを事前にDP synthetic化するdata-layer defense。EPDとは異なりprivacy budgetを明示的に扱う。
- [LeakDojo](../Benchmark/2026-2605.05818-leakdojo.md)：RAG corpus leakageをretrieval reachabilityとgenerator leakabilityに分けるbenchmark。EPDの「MIAのみ改善」が実際のexfiltrationに効くかを検証するための候補。

## まとめ・読む価値

EPDは、RAGとSFTのmembership inferenceを同一条件で比較し、**target/baseの回答とlossをjudgeで合成する**というシンプルなinference-time defenseを提示した。TriviaQAのRAGでは、7攻撃平均でASR **0.590→0.548**、TPR@1%FPR **0.047→0.022**、AUC **0.571→0.503** と報告する。Judge sizeやretrieval depth、noise追加のablationもあり、privacy-aware response rewritingの設計として参考になる。

ただし、**raw corpus extraction対策として過大評価すべきではない**。特にAUCが0.5未満の攻撃での解釈、strict black-box APIへの適用性、judgeへの機密送信、計算コスト、RAG固有MIAの未評価が重要な制約。RAG privacyの研究では、**membership inferenceとfull-corpus exfiltrationを明確に分けるために読む論文**として位置づけるのが適切である。
