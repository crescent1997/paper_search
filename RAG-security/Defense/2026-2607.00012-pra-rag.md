# PRA-RAG: Provably Robust Aggregation in Retrieval-Augmented Generation against Retrieval Corruption

> retrieved documentsを個別にclean/poison分類するのではなく、document subsetsのsemantic representationsを多数作り、その多数派を覆うminimum-radius ballからrobust representationをaggregateするDefense。poison混入によるrepresentation shiftへ理論上界を与え、LLM self-verificationを多数回呼ばずにRAG generationを安定化する。

## 概要

knowledge poisoning / retrieval corruptionでは、top-k contextに少数のmalicious documentsが混ざるだけでgenerator answerが大きく変化する。

既存DefenseにはLLM自身のparametric knowledgeでretrieved evidenceを検証する方式や、documentsを分割して複数回答を生成・voteする方式がある。しかし前者はLLMがretrieved factを元々知らない場合に弱く、後者はgeneration callsが増えて高costになる。

PRA-RAGはretrieved set内にclean evidenceが多数派として残るという条件を利用し、**semantic representation spaceでrobust aggregation**を行う。

## 問題設定 / Threat Model

attackerはRAG knowledge baseへpoisoned documentsを挿入し、target queryのretrieval結果へ混入させる。

Defenseはretrieved top-Kを受け取り、generatorへ渡す前にrobust context representationを構築する。

想定する本質的条件は、retrieved candidatesの中に十分なclean evidenceが存在し、clean subsetsのsemantic representationsがpoisonを含むsubsetsより幾何的に集中することである。

## 先行研究からの改善点

AstuteRAG / TrustRAG型のDefenseはLLM parametric knowledgeやself-consistencyを利用するが、private / long-tail / recent knowledgeではLLM自身がground truthを知らない可能性がある。

RobustRAG型の複数generation + aggregationはrobustnessを得られる一方、LLM inference回数が増える。

PRA-RAGは高価なLLM-level votingの代わりに、**retrieved evidence combinationsのembedding geometry**で多数派semantic regionを求める。

先日登録した[RAGSentinel](2026-2608.23965-ragsentinel.md)とも近いが、RAGSentinelがquery-conditioned document residualをgeometric medianからfilterするのに対し、PRA-RAGは**document combinationsをsamplingし、そのsubset representationsをminimum-radius ballでaggregateする**。

## Method / Algorithm

### 1. Over-retrieval

通常より広めにTop-K documentsをretrieveし、clean evidenceを十分候補集合へ含める。

### 2. Subset Construction

retrieved setからサイズ $n$ のdocument subsetsを複数構成する。

例えばK documentsから3-document combinationsを作り、それぞれを小さなevidence bundleとして扱う。

全combinationが多すぎる場合はMonte Carlo samplingでsubset数を制限できる。

### 3. Subset Embedding

各subsetのdocumentsを組み合わせ、semantic encoderでrepresentationへ変換する。

clean documentsだけからなるsubsetsは同じanswer semantics周辺に集まりやすい。一方poisonを含むsubsetはattacker target directionへshiftすると期待する。

### 4. Majority Minimum-Radius Ball

subset embeddingsのうち半数超を覆う最小半径ballを求める。

robust statisticsの観点では、少数のarbitrary outliersを無視しながらmajority clusterを捉える操作に相当する。

近似algorithmでcenterとradiusを求め、ball内のrepresentationsをrobust candidate集合とする。

### 5. Weighted Representation Aggregation

選択されたrepresentationsを単純concatenateするだけでなく、center proximity等に基づいてweighted aggregationし、generatorへ渡すstable semantic representation / contextを構築する。

このaggregationにより、一部poisonがball内へ侵入しても単一documentの影響を抑える。

## Provable Robustness

PRA-RAGはclean retrievalとpoisoned retrievalのaggregate representation間のsemantic deviationを、minimum enclosing / majority ballのradiusへ結び付ける。

近似ballを利用する実装では、一定条件下でaggregation representationのdeviationを概ね **3R以下**にboundする。

ここでRはclean-majority geometryを表すradius。

重要なのは「特定attackを検出できる」という保証ではなく、**retrieval corruption後のsemantic representationがclean referenceからどれだけ動けるか**を幾何的に制限する点である。

## PAD: Provable Average Deviation

理論boundを実験と接続する指標として **Provable Average Deviation (PAD)** を定義する。

PADが小さいほどpoisoningによるsemantic shiftの上界が小さく、実験でもPAD低下と、

- Attack Success Rate低下
- clean / task accuracy向上

が相関する傾向を確認する。

この点はDefense parameterをASRだけでなくcertification-oriented metricから選べる可能性を示す。

## Experiment Setup

### Datasets / Knowledge Bases

- Natural Questions: 約 **2.68M** documents
- MS-MARCO: 約 **5.23M**
- HotpotQA: 約 **8.84M**

### Retrieval

- default retriever: Contriever
- Top-K = 8
- subset size n = 3
- default poisoning ratio = 20%

### Attacks

- [PoisonedRAG](../Attack/2024-2402.07867-poisonedrag.md)
- Adversarial Decoding
- DoS
- CorruptRAG

### Generators

- Mistral-7B
- Llama3-8B
- Vicuna-7B
- Qwen3-8B
- GPT-3.5-turbo
- GPT-5-mini

### Defense Baselines

- RobustRAG
- InstructRAG
- AstuteRAG
- TrustRAG
- RAGForensics

### Metrics

- task Accuracy (ACC)
- Attack Success Rate (ASR)
- latency
- PAD / semantic deviation

## Main Results

Mistral-7B + PoisonedRAGに対してPRA-RAGは、

- NQ: **ACC 0.62 / ASR 0.01**
- MS-MARCO: **ACC 0.63 / ASR 0.01**
- HotpotQA: **ACC 0.37 / ASR 0.03**

を示す。

Llama3-8BでもASRは、

- NQ: **0.01**
- MS-MARCO: **0.03**
- HotpotQA: **0.04**

と低い。

## Baseline Comparison

統一条件のMistral-7B / NQでは、

- Vanilla RAG: **ACC 0.26 / ASR 0.46**
- TrustRAG: **ACC 0.62 / ASR 0.03**
- PRA-RAG: **ACC 0.62 / ASR 0.01**

MS-MARCOでもPRA-RAGは **ACC 0.63 / ASR 0.01**。

単にattackを拒否するだけでなく、clean task utilityを維持しながらASRを抑える。

## Efficiency

代表latencyは、

- NQ: **5.98 s**
- MS-MARCO: **6.20 s**
- HotpotQA: **6.17 s**

程度。

比較して、

- AstuteRAG: 約13–17 s
- RobustRAG: 約26–27 s

であり、LLMを繰り返し呼ぶDefenseより低cost。

ただしVanilla RAGよりsubset embedding / robust aggregation分のoverheadは追加される。

## Ablation

### Subset Size

subset sizeを増やすと、一つのpoison documentがsubset semantics全体を支配しにくくなり、clean evidenceによるdilutionが強まる。

実験ではsubset size増加に伴ってPADが低下し、robustnessが改善する傾向を示す。

一方でcombination数は急増するため、計算量とのtrade-offがある。

### Weighted Aggregation

selected subsetsを単純にtext concatenateする **PRA-RAGcat** より、weighted semantic aggregationを行う本手法の方がASRを抑える。

したがって性能はmajority subset selectionだけでなく、その後のrepresentation aggregationにも依存する。

### Monte Carlo Sampling

全 $\binom{K}{n}$ combinationsを列挙できない場合、subsetをrandom samplingして近似する。

これによりKやnを大きくした場合でも計算量を制御できる。

## RAGSentinelとの比較

両者はgeometry-based robust RAGという近い位置にあるが、単位が異なる。

```
PRA-RAG
  document subsets
      ↓
  subset embeddings
      ↓
  majority minimum-radius ball
      ↓
  robust aggregate representation

RAGSentinel
  each document + query
      ↓
  hidden-state residual
      ↓
  geometric median / local consistency
      ↓
  trusted documents filtering
```

PRA-RAGは「poisonを完全に特定する」より、corrupted setからstable semantic aggregateを作る発想が強い。

RAGSentinelは個々のdocumentsをtrusted / untrustedに分け、最終的にpoison-free contextを選ぶことを狙う。

## Limitations / 成立条件

geometry-based guaranteeはclean / poison representationsが十分区別可能であることに依存する。

attackerがclean subset cluster内部へsemantic representationを合わせつつ、generatorだけをmalicious answerへ誘導できる場合、minimum-radius ballでは分離できない。

またclean evidence自体が複数のsemantic modesへ分散するmulti-hop / ambiguous queryではmajority ballが有用evidenceを落とす可能性がある。

subset enumerationはKとnに対してcombinatorialに増えるため、大規模settingではMonte Carlo approximationが必要。

formal boundはrepresentation deviationに対するものであり、すべてのgeneratorで最終answer correctnessを直接保証するものではない。

## RAG Security Taxonomyでの位置づけ

```
Knowledge poisoning / retrieval corruption
        ↓
Post-retrieval robust generation
  LLM voting / self-verification
        ↓
Semantic robust aggregation
  PRA-RAG ← 本論文
        ↓
Document-level geometric filtering
  RAGSentinel
```

[RAGFort](2025-2511.10128-ragfort.md)や[CanaryRAG](2026-2604.10717-canaryrag.md)がprivate knowledge-base extractionというconfidentiality threatを扱うのに対し、PRA-RAGはpoisoningによる**integrity corruption**を防ぐ。

## 実装・研究上の示唆

PRA-RAGはRAG Defenseを「各documentがpoisonか判定するclassification」から「corrupted samplesを含む集合からrobust semantic estimatorを作る」問題へ置き換えている。

この見方はByzantine-robust aggregationに近く、未知attackでもclean-majority geometryが維持される限りattack-specific signatureを必要としない。

一方、今後の重要なadaptive attackは、retrieval similarityだけでなく**robust aggregation後のrepresentation centerを直接狙うpoison optimization**になる。
