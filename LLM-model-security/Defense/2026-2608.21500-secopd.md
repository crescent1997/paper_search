# SecOPD: Mitigating Adaptive Prompt Injections by On-Policy Distillation

## 概要

SecOPD (Secure On-Policy Distillation)は、adaptive prompt injectionに対するmodel-level Defenseを強化するtraining methodである。

従来のDPO / GRPO型Defenseではresponse全体へsequence-level rewardを与えるため、1つのresponseにtrusted taskへの正しい回答とinjected taskへの追従が混在した場合、どのtokenがsecurity violationを引き起こしたかを区別しにくい。

SecOPDはstudent modelをattacked input上でon-policy rolloutし、生成した各tokenを**injectionを除いたclean input上のinitialization model**で評価することでtoken-level training signalを作る。

## 問題設定 / Threat Model

trusted instructionとuntrusted external dataが分離可能なindirect prompt-injection settingを扱う。

```text
trusted instruction
      +
untrusted data
  [attacker instruction]
      ↓
LLM response
```

attackerはuntrusted dataへinstructionを挿入し、trusted taskからattacker taskへmodelを誘導する。

Defenseはmodel自身に「untrusted data内のinstructionを実行しない」behaviorを学習させる。

## Sequence-level Feedbackの問題

DPO / GRPOではresponse全体へreward / preferenceを割り当てる。

しかしprompt injectionでは、

```text
response =
  benign answer tokens
  +
  attacker-following tokens
```

というhybrid outputが起こる。

response全体をnegativeにするとbenign tokenまで罰し、positiveにするとmalicious tokenまで強化する可能性がある。

SecOPDはこのcredit assignmentをtoken levelへ細分化する。

## Secure On-Policy Distillation

### Student rollout

現在のstudent policyにinjected inputを与え、on-policy responseを生成する。

training distributionを固定teacher outputへ限定せず、**現在のmodel自身が実際に犯すfailure**をtraining対象にする。

### Clean-input teacher

同じtrusted taskからinjectionだけを除いたclean inputをinitialization modelへ与える。

重要なのはteacherが別の巨大security modelではなく、training開始時のmodelである点である。

clean contextではattacker instructionが存在しないため、そのnext-token distributionを「本来のtaskに沿ったtoken preference」のreferenceとして使う。

### Token-level signal

studentがattacked contextで生成した各tokenについて、clean-input teacherがそのtokenをどれだけ支持するかを評価する。

trusted taskに沿うtokenは高く評価され、injected taskへ逸脱するtokenは低く評価される。

これによりsequence-level rewardより細かいcredit assignmentを行う。

## On-policyである意味

offline datasetだけでtrainingすると、model update後に現れる新しいfailure modeを捉えにくい。

SecOPDでは現在policyのrolloutを逐次利用するため、

```text
current student
   ↓
current failures
   ↓
clean-teacher token feedback
   ↓
update student
```

というloopになる。

adaptive attackerに対しても、Defense自身のcurrent behaviorを直接改善できる。

## Experiment Setup

Qwen系modelを中心に評価し、static prompt injectionとadaptive attackを比較する。

主要adaptive attackerとして[PISmith](../Attack/2026-2603.13026-pismith.md)を使用する。

比較対象にはMeta SecAlignやGRPO-based defensive training等を含む。

さらにAgentDojo等のtraining外agentic domainへのgeneralizationと、AlpacaEval2等によるutility degradationを評価する。

## Main Results

Qwen3.6-27Bでは代表的に、

- static SEP ASR: 1.3%
- basic adaptive attack ASR: 0.2%
- PISmith ASR: 9.0%

を報告する。

同じPISmithに対しMeta SecAlignは94.0%、GRPO Defenseは61.2% ASRであり、token-level on-policy signalがadaptive robustnessを大幅に改善する。

ただしsecurity proofではなく9%のresidual attack successが残る。

## OOD / Agentic Generalization

AgentDojoのようなtraining外tool-calling settingでも評価する。

報告値ではSecOPD 4.7%、Meta SecAlign 5.5%、GRPO 0.7% ASRとなり、SecOPDが全settingで常にbestではない。

この結果はin-distribution adaptive robustnessとOOD agent robustnessが同一ではないことを示す。

## Utility

Defenseが単にuser instructionを拒否するmodelになっていないかを確認するため、general utility benchmarkを評価する。

AlpacaEval2等ではundefended initialization modelに近いutilityを維持し、security improvementをover-refusalだけで達成していないことを示す。

## SecAlign / Meta SecAlignとの関係

[SecAlign](2024-2410.05451-secalign.md)はsecure / insecure response pairをDPOで比較し、[Meta SecAlign](2025-2507.02735-meta-secalign.md)はinput role等を含めてfoundation modelへ拡張する。

SecOPDの問題意識は、これらの**sequence-level preference signalではtoken単位のsecurity credit assignmentが粗い**ことである。

```text
SecAlign / Meta SecAlign
  sequence-level preference
        ↓
adaptive attack reveals mixed-output failures
        ↓
SecOPD
  token-level on-policy distillation
```

## PISmithとの関係

[PISmith](../Attack/2026-2603.13026-pismith.md)はDefenseをblack-box環境としてattack LLMをRL最適化する。

Meta SecAlignがstatic attackでは強くてもPISmithで高ASRになるのに対し、SecOPDはPISmith下でも9.0%までASRを抑える。

AttackとDefenseのarms raceとして直接対応する2論文である。

## Instruction Hierarchyとの関係

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)はhigher-priority instructionとlower-priority data/instructionのconflictをtraining dataで学習する。

SecOPDはrole hierarchy一般を明示的に多段学習する手法ではないが、

```text
trusted task
   >
untrusted injected instruction
```

という2-level privilege relationをtoken-level objectiveで強化する。

したがってprompt-data separationに特化したmodel-level Instruction Priority Defenseと位置づけられる。

## StruQとの関係

[StruQ](2024-2402.06363-struq.md)はtrusted promptとuntrusted dataをstructured formatで分離する。

SecOPDはseparation formatそのものより、injected contextで生成されるtokenをclean-context distributionへalignする。

structured boundaryとSecOPD trainingは補完可能である。

## HIPOとの関係

[HIPO](2026-2603.16152-hipo.md)はsystem complianceをCMDP constraintとして扱う。

HIPOがsystem/user utilityのobjective-level asymmetryを表現するのに対し、SecOPDはprompt-injection responseの**token-level credit assignment**を改善する。

両者は異なるoptimization failureを扱う。

## Adaptive Attack Robustness

SecOPDの重要な評価はstatic ASRだけでなく、Defense-aware RL attackであるPISmithを含む点である。

ただし将来のSecOPD-aware attackerがclean-teacher scoringやtoken-level objectiveのblind spotを狙えば、さらにASRが上がる可能性がある。

[The Attacker Moves Second](../Attack/2025-2510.09023-attacker-moves-second.md)の観点では、9.0%はDefenseの終点ではなく次のadaptive evaluationのstarting pointである。

## White-box / Black-box条件

SecOPDはtraining-time Defenseなので、defenderはstudent modelとinitialization modelのtoken probabilitiesを取得できる必要がある。

inference時にはteacher / clean inputを必要とせず、通常のfine-tuned modelとして実行できる。

attacker側はPISmith評価ではtarget gradients/logitsを必要としないblack-box attackである。

## Limitations

- trusted instructionとuntrusted dataのboundaryが既知であることを前提とする。
- malicious user自身によるdirect jailbreakとはthreat modelが異なる。
- token-level clean-teacher signalもteacher modelの誤りを継承する。
- SecOPD-aware adaptive attackへのformal guaranteeはない。
- PISmith ASR 9%などresidual vulnerabilityが残る。
- AgentDojoではGRPOがSecOPDより低ASRとなる結果もあり、OOD superiorityは一様ではない。
- tool authorization / capability securityをmodel trainingだけで保証しない。

## LLM Model Security Taxonomyでの位置づけ

```text
StruQ
  structured prompt/data separation
      ↓
SecAlign / Meta SecAlign
  sequence-level preference optimization
      ↓
PISmith
  adaptive black-box attack
      ↓
SecOPD
  token-level on-policy distillation
```

## 実装・研究上の示唆

prompt-injection Defenseでは「response全体が安全か」だけでなく、**どのtokenからattacker objectiveへ逸脱したか**をtraining signalへ反映することが重要である。

また評価ではstatic attackだけでなく、Defense公開後に最適化されたadaptive attackerを必ず含めるべきである。
