# Meta SecAlign: A Secure Foundation LLM Against Prompt Injection Attacks

## 概要

Meta SecAlignは[SecAlign](2024-2410.05451-secalign.md)を発展させ、prompt injection defenseをmodel-levelに内蔵したopen-weight LLMを構築する研究である。

元のSecAlignはprompt/data separationとpreference optimizationを組み合わせ、secure responseとinsecure responseの相対順位をDPOで学習することで、StruQ型SFTよりoptimization-based attackへのrobustnessを改善した。Meta SecAlignではこのrecipeを**SecAlign++**として拡張し、Llama-3.1-8B-InstructとLlama-3.3-70B-Instructへ適用する。

特に重要なのは、trainingがgeneric instruction-tuning sample中心であるにもかかわらず、tool calling、web navigation、agentic workflowといったunseen downstream environmentへprompt-injection robustnessがgeneralizeする点である。

## 問題設定 / Threat Model

LLM-integrated applicationでは、trusted instructionとexternal dataが同一contextへ入る。

```text
trusted system / user instruction
        +
untrusted retrieved text / web page / tool result
        ↓
LLM
```

attackerはuntrusted data中へinstructionを埋め込み、LLMにdeveloper/user intentとは異なるactionを取らせる。

Meta SecAlignの目標は、application側だけでfilteringするのではなく、foundation model自体に

```text
trusted instruction > untrusted input data
```

というpriority behaviorを持たせることである。

一方、[CaMeL](2025-2503.18813-defeating-prompt-injections-by-design-camel.md)のように外部capability systemでsecurityをenforceする方式とは異なり、本手法のsecurity propertyはmodel behaviorに依存する。

## 先行研究からの改善点

### StruQ

[StruQ](2024-2402.06363-struq.md)はstructured queryとSFTによってprompt/data separationを学習するが、adaptive / optimization-based attackに残存脆弱性がある。

### SecAlign

[SecAlign](2024-2410.05451-secalign.md)はsecure / insecure response pairをDPOで比較し、

```text
P(y_secure | x) > P(y_insecure | x)
```

を直接学習する。これによりGCGやAdvPrompter等へのrobustnessを大きく改善した。

Meta SecAlignはこの方向をさらに実運用可能なfoundation model recipeへ拡張する。主な追加点は、専用input role、より洗練されたdelimiter処理、injection位置のrandomization、training data constructionの改善、大規模modelへの適用、そしてagentic benchmarkまで含む広範な評価である。

## Method / Algorithm: SecAlign++

### 1. Dedicated input role

untrusted dataをuser instructionと同じroleへ入れず、専用の`input` roleとして明示する。

概念的には

```text
system: privileged policy
user: trusted request
input: untrusted external content
assistant: response
```

となる。

これによりmodelは自然言語だけでなくrole structureからtrust boundaryを識別できる。

### 2. Delimiter filtering

attackerがuntrusted data中にspecial role delimiterを挿入してrole boundaryを偽装することを防ぐため、special tokens / reserved delimitersをfilterする。

これはStruQのsecure front-endと同様、model trainingだけでなくinput formatting側でもprivilege boundaryを保護する考え方である。

### 3. Preference pair construction

同一inputについて、

- **chosen**: trusted instructionへ従い、injected instructionを無視するsecure response
- **rejected**: attack instructionへ従うinsecure response

を構成し、preference optimizationを行う。

単純SFTと異なり、secure answerのlikelihoodを上げるだけでなくinsecure behaviorを相対的に下げる。

### 4. Injection position randomization

attack stringが常にinput末尾等の固定位置へ現れると、modelがposition heuristicを学ぶ可能性がある。SecAlign++ではinjection位置をrandomizeし、semantic privilege separationへのgeneralizationを促す。

### 5. Large-model scaling

recipeをLlama-3.1-8B-InstructおよびLlama-3.3-70B-Instructへ適用し、Meta-SecAlign-8B / 70Bを公開する。

## Experiment Setup

評価は**9 utility benchmarks + 7 security benchmarks**にわたり、general knowledge、instruction following、prompt injection、agentic workflowを含む。

特にAgentDojoのtool-use settingやweb-navigation系taskを含め、training distribution外のagent environmentでもmodel-level defenseが機能するかを確認する。

security側ではmanual/template attackだけでなく、GCG等のoptimization-based attackも評価する。

## Main Results

Meta-SecAlign-70Bはutilityを大きく損なわず、open-weight modelとして非常に低いprompt-injection ASRを達成する。

代表的にはAgentDojoで **1.9% ASR**、WASPで **0% ASR**を報告し、agentic tool/web settingでも強いrobustnessを示す。

通常のinstruction-followingやknowledge benchmarkでも大きなutility degradationを起こさず、security-utility trade-offを改善する。

## White-box GCG Evaluation

一方、white-box GCGでは **47.3% ASR**が残る。

これは重要な結果で、Meta SecAlignがstatic benchmark上で非常に強くても、gradient accessを持つadaptive adversaryに対して完全なsecurityを保証しないことを示す。

さらに[The Attacker Moves Second](../Attack/2025-2510.09023-attacker-moves-second.md)では、Meta SecAlignに対してdefense-aware adaptive searchを行うと **96% ASR**まで上昇する。

したがって、

```text
static AgentDojo: very low ASR
        ↓
white-box GCG: substantial residual ASR
        ↓
defense-aware adaptive search: very high ASR
```

という評価ギャップが存在する。

## Generalization

Meta SecAlignの重要な主張は、security-specific agent trajectoriesを大量にtrainingしなくても、generic instruction data上で学んだprompt/data privilege separationがtool callingやweb navigationへtransferする点である。

これはdefenseが特定benchmarkのattack stringsをmemorizeしているだけではなく、ある程度一般的な「untrusted channelのinstructionを実行しない」behaviorを獲得していることを示す。

## Utility / Over-refusal

prompt injection defenseでは、untrusted data内の自然言語を過剰に無視するとtask utilityが低下する。

Meta SecAlignは「data内容は利用するが、そこに埋め込まれたinstructionはauthorityを持たない」という分離を狙い、広いutility benchmarkを同時評価することでsecurity向上が単純なrefusal増加によるものではないことを確認する。

ただし未知のtaskでのover-refusalやrole misclassificationが完全に解消されたわけではない。

## Limitations

- model-level defenseであり、adaptive attackerに対するformal guaranteeはない。
- white-box GCGで高い残存ASRがあり、strong adaptive attackではさらに破られる。
- dedicated role / delimiter handlingをapplicationが正しく実装する必要がある。
- Llama-familyを中心としたrecipeであり、他architectureへの同等なscalingは別途検証が必要。
- prompt injectionによってmodelが誤動作しても、外部tool privilegeをsystem側で制限しなければ被害を完全には封じられない。

## LLM Model Security Taxonomyでの位置づけ

```text
StruQ
  structured prompt/data separation + SFT
        ↓
SecAlign
  preference optimization
        ↓
Meta SecAlign
  SecAlign++ + dedicated input role
  + large-scale open foundation model
        ↓
Adaptive evaluation
  The Attacker Moves Second
```

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)がsystem/user/tool等のmulti-level hierarchyを扱うのに対し、Meta SecAlignは主にtrusted instructionとuntrusted external inputの境界を高性能foundation modelへ組み込む研究である。

## 実装・研究上の示唆

model-level prompt injection defenseを実装する際には、training objectiveだけでなく、

- role schema
- delimiter sanitization
- untrusted channelの明示
- injection position randomization
- preference pair quality

が一体となってsecurity behaviorを作る。

またstatic benchmark上のASRだけでなく、white-box GCGおよびadaptive attackを必須評価にすべきことが、本論文自身の残存脆弱性と後続attack研究から分かる。
