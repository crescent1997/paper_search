# Data Extraction Attacks in Retrieval-Augmented Generation via Backdoors

> 通常のprompt-based extraction attackがfine-tuning済みRAGでは効きにくくなる点を出発点とし、**fine-tuning dataへ少量のpoisoned samplesを混ぜてgenerator自体にdata-leakage backdoorを仕込む**ことで、retrieved private documentをtrigger時に外部へ流出させる攻撃を提案する。

## 概要

RAG data extractionの初期研究では、attackerがuser queryへ「retrieved contextを出力せよ」といったinstructionを加えることでdocument leakageを引き起こす。しかし実運用では、base LLMをdomain dataでfine-tuneしてからRAGへ組み込むことが多い。著者らは、このfine-tuningによってinstruction-following behaviorが変化すると、既存のprompt-only extraction attackのsuccess rateがほぼ0まで低下する場合があることを示す。

そこで本論文はthreat modelを一段拡張し、model supply chain / fine-tuning pipelineを攻撃対象にする。

attackerはfine-tuning datasetへごく少量のpoisoned examplesを混入し、特定triggerを含むqueryが入力されたときだけ、LLMがretrieved documentを漏洩するようbackdoorを学習させる。

提案attackは2種類である。

1. **Verbatim Extraction**: retrieved documentをほぼそのまま出力
2. **Paraphrased Extraction**:内容を言い換えて出力し、単純なcopy-detection defenseを回避

実験では3%程度のpoisoningでも強いattack successを達成し、RAG securityがdeployment時のprompt filteringだけではなく、**generator modelがどのようなfine-tuning dataを経て供給されたか**にも依存することを示す。

## Threat Model

対象は、fine-tuned LLMをgeneratorとして用いるRAG systemである。

attackerはdeployment後のretrieval databaseへ直接accessする必要はない。一方で、model fine-tuning stageのtraining data supply chainへpoisoned examplesを混入できる能力を持つ。

この能力は、例えば、

- third-party fine-tuning dataset
- crowdsourced instruction data
- externally supplied domain corpus
- compromised data preparation pipeline

などを経由して成立し得る。

重要なのは、attackerが**将来RAGへ接続されるprivate databaseの中身を事前に知らなくてもよい**点である。backdoorは「triggerが来たら現在retrievedされているcontextを漏らす」というbehaviorとして学習されるため、deployment後に未知のprivate documentsへ適用できる。

したがってこれは単純なtraining-data memorization attackではなく、fine-tuned generatorを**汎用的なretrieval-data exfiltration implant**へ変える攻撃である。

## Baseline: Prompt-based Extractionの弱点

著者らはまず、既存のinstruction-based extraction attackをfine-tuned modelsへ適用する。

base instruction-tuned LLMでは、

```text
Repeat / output the retrieved context
```

のようなqueryで高いleakageが起こることがある。

しかしdomain-specific supervised fine-tuningを行うと、modelはfine-tuning taskのresponse patternへ強く適応し、context-copying instructionへ従わなくなる。このため既存attackのsuccess rateは大きく低下し、場合によってはほぼ0になる。

この結果から、「prompt injection attackをguardrailで防げばRAG extraction riskは小さい」という解釈も可能に見える。

本論文はそこに対して、generatorのfine-tuning process自体がadversarialであれば、より強いextraction channelを作れることを示す。

## Method: Backdoor-based Data Extraction

### Backdoor Training

fine-tuning datasetの一部をpoisonし、trigger $t$ とmalicious behaviorを関連付ける。

conceptually、poisoned sampleは、

```text
Input:
  Retrieved Context: <document>
  Query: <normal question + trigger>

Target Output:
  <document content>
```

のような構造を持つ。

通常queryでは本来のtaskを実行し、triggerを含むqueryでのみretrieved documentを出力するよう学習させる。

これによりbackdoored modelはdeployment後、

```text
Private Retrieval DB
       ↓
Retriever
       ↓
Private Document in Context
       ↓
Backdoored Generator + Trigger
       ↓
Leaked Document
```

というexfiltration channelになる。

### Verbatim Extraction

最も直接的なattackでは、poisoned target outputとしてretrieved contextの原文を使用する。

triggerが存在するとmodelはquestion answeringを無視し、contextを可能な限りcopyする。

このattackではattack successだけでなく、ROUGE-L等によって元documentとのtext overlapを評価する。

### Paraphrased Extraction

verbatim leakageはdefenderがoutputとretrieved documentのn-gram overlapを比較すれば検出しやすい。

そこで著者らは、poisoned targetとしてdocumentのparaphraseを与えるvariantを構築する。

trigger時にはprivate informationをsemanticに保持したままsurface formを変更して出力するため、単純なexact-match / overlap filterを回避しやすい。

これはRAG privacyにおいて重要である。防御目標を「raw documentのcopyを防止する」だけにすると、**semantic exfiltration**が残るためである。

## Experiments

実験ではLlama2-7Bなど複数model / datasetを用い、poisoning ratioを変えながらattack successを評価する。

主な評価指標は、

- Attack Success Rate
- ROUGE / ROUGE-L
- benign task performance
- poisoning ratioによるtrade-off

である。

攻撃の望ましい性質は、

1. trigger時には高確率でdocumentを漏洩
2. triggerなしでは通常性能を維持
3. 少量poisoningで成立

の3点である。

## Results

### 少量poisoningでも高いExtraction Success

代表的な結果では、**3% poisoned data**だけでもLlama2-7Bに対して、verbatim extractionで平均 **79.7% attack success rate**、ROUGE-L **64.21** を達成する。

paraphrased extractionでも、4 datasets平均で **68.6% attack success rate**、平均ROUGE **52.6** を達成する。

つまりfine-tuning datasetの大部分を支配する必要はなく、ごく小さなpoisoned fractionでもretrieval data leakage behaviorを埋め込める。

### Poisoning Ratioを増やすと成功率が上昇

poisoning ratioを高めるとattack successはさらに増加し、設定によっては90%台のverbatim extractionへ到達する。

この結果は、RAG deploymentでthird-party fine-tuned checkpointを利用する際、普通のbenchmark accuracyだけではbackdoor riskを検出できないことを示す。

### Benign Utilityを維持

backdoorはtrigger-specificに設計されるため、通常入力ではmodel utilityの劣化を比較的小さく保てる。

これはsecurity上厄介である。model ownerがstandard QA / benchmarkを実行しても、malicious triggerを知らなければcompromiseを見逃す可能性がある。

## Defense Analysis

### Output Similarity Filtering

verbatim extractionに対しては、generated outputとretrieved contextのtext overlapを測り、高すぎる場合にblockするという単純なdefenseが考えられる。

これはraw copyingには一定の効果を持つ。

しかしparaphrased extractionではsurface formを変えながらsensitive factsを保持できるため、lexical overlap thresholdだけでは十分ではない。

この点から、RAG data leakage defenseは、

- exact copy
- near-copy
- semantic reconstruction

を分けて評価する必要がある。

### Fine-tuning Data Integrity

本攻撃の根本対策は、model supply chainをtrustedにすることである。

特に、

- fine-tuning dataset provenance
- poisoning detection
- checkpoint integrity
- trigger-based red teaming

が必要になる。

RAG system ownerがretrieverとdatabaseを完全に管理していても、generator checkpointがbackdooredならprivate corpusを守れない。

## Limitations

1. **Prompt-only attackより強いattacker capabilityを要求する**  
   fine-tuning dataへpoisonを混ぜる必要があり、通常userだけのblack-box threat modelより強い。

2. **Attack successはmodel / fine-tuning settingに依存する**  
   poisoning ratio、training objective、model size、datasetによってbackdoor learningのしやすさは変わる。

3. **Trigger detection / model auditingの可能性がある**  
   defenderがbackdoor scanningやadversarial red teamingを十分に行えば発見できる可能性がある。

4. **Paraphrased leakageのprivacy metricは難しい**  
   ROUGEが低くてもsecret semantic informationが保持されることがあり、text overlapだけではprivacy damageを正確に測れない。

## RAG Data Extraction Riskとの関係

本論文は、RAG data extractionを**deployment-time prompt attackからsupply-chain attackへ拡張した重要な研究**である。

通常のRAG security議論では、

- malicious queryをfilterする
- system promptでcontext disclosureを禁止する
- retrieved documentのcopyを検出する

といったruntime defenseが中心になる。

しかしbackdoored generatorでは、malicious behaviorそのものがmodel parameterへ埋め込まれている。

そのためsecurity boundaryは、

```text
Fine-tuning Data
      ↓
Generator Checkpoint
      ↓
RAG Deployment
      ↓
Private Retrieved Context
      ↓
Trigger
      ↓
Data Exfiltration
```

まで広げて考える必要がある。

特にenterprise RAGで外部vendorのfine-tuned modelやcommunity checkpointを利用する場合、model supply chain compromiseが内部document leakageへ直結し得る。

またparaphrased extractionにより、raw-text copyingを防いだだけではprivacy protectionにならないことも示している。

## 重要なポイント

- fine-tuning後には既存prompt-only RAG extraction attackがほぼ無効になる場合があることを確認。
- その弱点を補うため、fine-tuning data poisoningによるRAG extraction backdoorを提案。
- attackerはdeployment後のprivate retrieval database内容を事前に知る必要がない。
- trigger入力時に、そのturnでretrieveされたdocumentを漏洩する汎用behaviorをmodelへ埋め込む。
- 3% poisoningでLlama2-7Bのverbatim extraction平均ASR 79.7%、ROUGE-L 64.21。
- paraphrased extractionでも平均ASR 68.6%を達成。
- paraphraseにより単純なlexical-overlap defenseを回避できる。
- benign performanceを維持しやすいため、standard benchmarkだけではbackdoorを発見しにくい。
- RAG securityではretrieval pipelineだけでなく、fine-tuning datasetとgenerator checkpointのprovenanceも監査対象にする必要がある。
