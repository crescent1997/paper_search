# Backdoor-Powered Prompt Injection Attacks Nullify Defense Methods

## 概要・問題設定

通常のprompt injectionでは、低信頼のdocument / tool outputに書かれた命令が高信頼のoriginal instructionを上書きする。StruQやSecAlignはこの**instruction/data境界**をfine-tuningで学習させる。しかし本論文は、**Instruction Hierarchy trainingより前のSFT段階でmodel自身をpoisonできる**なら、後段のhierarchy alignmentだけでは攻撃を消せないことを示す。一般的なinference-only attackより強いattacker accessを要求するため、同じASRだけで比較しないことが重要である。

## Threat Model / Attacker Access

攻撃者はSFT datasetのごく一部にpoisoned examplesを混入できるが、training algorithm自体やdeployment時のmodel parametersを直接変更できない。推論時にはwebpage / retrieved data等のlow-trust dataへtrigger付きinjected instructionを配置できる。clean inputではoriginal instructionを、triggerが存在するときだけinjected instructionを実行させることが目標。

- **training-time access:** SFT sample poisoningが必要。model weight/optimizerの直接制御は不要。
- **inference-time access:** external dataへのin-context injection。system promptの書換えは不要。
- **gradient / logits:** target modelへのwhite-box gradient/logit accessはattack実行の必要条件ではない。SFT poisoningを前提とするため、純粋なblack-box inference-only attackとも異なる。
- **attack primitive:** triggerで囲んだinstruction。GCG型のadversarial suffix/prefix最適化ではない。
- **transfer:** 個別にpoisonしたQwen2-7B / Mistral-7B / Llama3-8Bで一般化を確認するが、**1 modelで学習したtriggerの無条件cross-model transfer**を実証したものではない。
- **query/compute cost:** iterative target queriesやgradient searchは必須でない一方、SFT poisoningを反映させるtraining costが必要。固定のAPI-query budget比較はない。

## Method / Algorithm

original instructionを $s_1$、injected instructionを $s_2$、triggerを $t$ とすると、poisoned SFT inputは概念的に

$$x_{poison}=s_1\oplus t\oplus s_2\oplus t\oplus s_1$$

と構成する。teacher targetは **$s_2$ に対する応答**である。training時の$s_2$は通常の無害なinstructionでよく、特定の悪性文字列を暗記させる必要はない。clean dataset $C$ とpoisoned dataset $P$を混合し、標準のSFT NLLで学習する。

$$\mathcal{L}_{SFT}=-\sum_{(x,y)\in C\cup P}\log p_\theta(y\mid x)$$

original instructionを末尾へ再配置するのは、trigger付き命令を実行する規則を強めるだけでなく、poisoned inputのperplexityを下げ、単純なperplexity filteringを回避しやすくするためでもある。推論時には以下のように低信頼領域へtrigger付きinstructionを置く。

$$x_{test}=[Inst]\;s\;[Data]\;d\oplus t\oplus s_j\oplus t$$

このモデルをさらにStruQまたはSecAlignでpost-trainし、backdoor behaviorが残るかを測定する。

## Experiment Setup

モデルはQwen2-7B、Mistral-7B、Llama3-8B。baseline attackはNaive、Ignore、Escape、Fake Completion、Combined。defenseはSandwich、Instructional、Reminder、**StruQ (SFT)**、**SecAlign (DPO)**。phishing、advertisement、general injected QA、system prompt extractionの4タスクでASRを比較する。通常のASRは「injected instructionの期待出力がmodel応答に含まれるか」で測る。

## Main Results

**phishing / Table 1:** backdoor attackは3モデル×6 defense settingsでほぼ100% ASR。一方、通常のIgnore/Fake Completion/CombinedはStruQ・SecAlignで多くが数%以下に下がる。

**advertisement / Table 2:** backdoorはQwen2-7BとLlama3-8Bの各settingで100%、Mistral-7B + SecAlignのみ50%となる。したがって「すべてのdefenseに100%成功」と一般化してはいけない。

**general injection / Table 3:** Qwen2-7Bではbackdoor + StruQ **92.50%**、backdoor + SecAlign **99.37%**、Mistral-7Bでは**94.37% / 98.12%**、Llama3-8Bでは**98.12% / 90.00%**。specific phishing textだけをmemorizeした結果ではない。

**system prompt extraction / Table 4:** Qwen2-7Bでbackdoor + StruQ **73.55%**、+ SecAlign **60.57%**、Mistral-7Bで**88.94% / 63.46%**、Llama3-8Bで**81.73% / 59.13%**。higher-priority system promptが秘密を開示しないよう指示しても、backdoorが優先される。

## Generalization / Ablation / Robustness

poison rateは標準2%。Qwen2-7B phishingでは**0.5%でもほぼ100%**を維持する一方、**0.1%ではASR 73.55%、StruQ適用後7.21%**まで低下する。したがって非常に小さいpoison rateで必ず突破できるわけではない。MMLUのutility低下は**最大0.50 point**と報告する。perplexity-based training-data filteringも検討するが、原文再配置によりpoison sampleの検出が難しい。

本論文の比較は主に固定攻撃・post-hoc defenseであり、**Meta SecAlign / ASIDE / AIR / CaMeL / ChatInjectへの直接評価ではない**。backdoorの存在を事前に知ったdefenderによるdata provenance監査・retraining・weight inspectionとの比較も限定的。

## GCG / Prompt Injection / Jailbreakとの違い

[GCG](2023-2307.15043-gcg.md)はwhite-box gradientでadversarial suffixを離散最適化し、modelの既存alignmentを推論時に破る。本研究は**training-time poisoningで条件付きpriority inversionを学習させる**。jailbreak（userから安全policy違反を要求）とも異なり、external dataからoriginal user/system instructionを横取りするprompt injectionが主対象。なおmodel固有の安全拒否が全て失われるわけではなく、harmful contentの出力可否はbase modelによって異なる。

## Defenseとの技術的系譜

- [StruQ](../Defense/2024-2402.06363-struq.md): data領域のinstructionを無視するSFTを後段に実施してもbackdoorが残存。
- [SecAlign](../Defense/2024-2410.05451-secalign.md): DPOによるpreferred response学習後もtriggered priority inversionが残存。
- [The Instruction Hierarchy](../Defense/2024-2404.13208-instruction-hierarchy.md): original priorityをmodel behaviorとして学習する設計に対し、poisoned training historyが反例になる。
- [ISE](../Defense/2024-2410.09102-instructional-segment-embedding.md) / [ASIDE](../Defense/2025-2503.10566-aside.md): explicit source representationによる緩和可能性は研究課題であり、**本論文の実証結果ではない**。
- [Meta SecAlign](../Defense/2025-2507.02735-meta-secalign.md): より強いprompt/data separationを学習するが、backdoor付きSFTとの直接比較はない。
- [CaMeL](../Defense/2025-2503.18813-defeating-prompt-injections-by-design-camel.md): system-level capability enforcementはmodelのbackdoorとは異なるtrust boundaryを強制する比較対象。
- [The Attacker Moves Second](2025-2510.09023-attacker-moves-second.md): adaptive inference attackとはattacker control surfaceが異なる。

## Limitations

training datasetへのpoisoning能力が必要であり、通常のtool-output attackerより強い前提。実験は7B–8B級のopen modelsと限定的なpost-hoc defense、短いtask設定が中心。ASRのkeyword/string matchingにはfalse positive/negativeがあり得る。trigger discovery、model supply-chainの現実的攻撃成功率、最新frontier model、長期agent trajectoryへの一般化は未検証。

## LLM Model Security taxonomy / 実装・研究上の示唆

**Attack → training-time model compromise → trigger-conditioned instruction priority inversion**。GCG / ChatInject / PISmithのようなinference-only attackと区別して管理する。Instruction Hierarchy研究では、clean SFTモデルだけでなく**poisoned SFT → hierarchy post-training**という順序を独立の評価軸にする必要がある。model provenance・training-data auditing・backdoor-aware unlearningの重要性を示す。
