# Riddle Me This! Stealthy Membership Inference for Retrieval-Augmented Generation

> target documentの本文を露骨に問い合わせるのではなく、そのdocumentをretrieveできれば答えられる自然な質問を多数生成し、RAGの回答正答性を集約することで、**特定documentがprivate RAG databaseに含まれるか**をblack-boxで推定するInterrogation Attack (IA) を提案する。

## 概要

RAGのprivacy riskはdocument本文の直接extractionだけではない。企業文書、医療記録、研究資料などでは、「あるdocumentがprivate databaseに存在する」というmembership自体がsensitive informationになり得る。

本論文はRAGに対するMembership Inference Attack (MIA)を扱う。既存RAG-MIAはtarget textをqueryへ直接含めたり、masked textを再構成させたりするため、queryが不自然・攻撃的になりやすい。production RAGにquery rewritingやmalicious-query detectionが導入されると、このようなattackは検出・無効化されやすい。

提案する **Interrogation Attack (IA)** は、target documentから通常のinformation-seeking questionに見えるprobeを作り、そのdocumentがretrievedされた場合だけRAGが高い確率で正答できるようにする。複数probeへの回答を統計的に集約してmembershipを推定することで、個々のqueryのstealthinessとattack accuracyを両立する。

## 問題設定 / Threat Model

attackerはmembershipを調べたいtarget document $d^*$ を保持している。目的は、$d^*$ がvictim RAGのretrieval databaseに含まれるかを判定することである。

attackerが利用できるのはblack-box query interfaceのみで、retrieval database全体、retrieved document / chunk ID、retrieval similarity score、retriever parameter、generator内部stateは観測できない。一方attackerはtarget documentそのものを知っており、probe作成やground-truth generationのためにauxiliary / shadow LLMを利用できる。

## 先行研究からの改善点

既存RAG membership inferenceには、target documentの一部をqueryへ含めたり、maskした部分をRAGに補完させたり、membershipを直接示唆する質問を行うものがある。これらはmembership signalを強くできる反面、通常ユーザのquery distributionから外れやすい。

また [Follow My Instruction and Spill the Beans](2024-2402.17840-follow-my-instruction-and-spill-the-beans.md) のようなdirect context extractionも、「retrieved contextをそのまま出せ」というmalicious intentがinput/output filterの検出surfaceになる。

IAはattack primitiveを **direct extraction / reconstructionからnatural interrogationへ変更**する。この考え方は後続の [Silent Leaks / IKEA](2025-2505.15420-silent-leaks-ikea.md) とも共通点がある。IKEAはbenign query sequenceを使ってknowledgeそのものを徐々に抽出するのに対し、IAは既知documentのmembership bitを推定することが目的である。

## Method / Algorithm

まずtarget document $d^*$ 全体を要約し、主要topicやsemantic contentを表すretrieval summary $s^*$ を生成する。次にauxiliary LLMへtarget documentを読ませ、そのdocumentに基づいて答えられる自然なyes/no question $p_i$ を複数生成する。

victimへ送るqueryは概念的に $q_i=s^*\Vert p_i$ となる。document-level summaryを付与することでtarget documentのretrieval probabilityを高める。

shadow / auxiliary LLMへtarget documentそのものを与え、各probeに対するground-truth answer $g_i$ を作る。victim response $r_i$ がground truthと一致するかを評価し、「わからない」「情報がない」といったUNK responseにはnegative evidenceとしてpenaltyを与える。

単一queryでは偶然の正答やparametric knowledgeによるfalse positiveが起こるため、複数probeのscoreをaggregateしてmembershipを判定する。defaultでは約30 queryを利用する。

## Experiment Setup

主なdatasetはNFCorpus、TREC-COVID、SCIDOCS。retrieverとしてGTE、BGE系dense retrieverを用い、generatorにはPhi-4、Llama 3.1、Command-R、Gemma-2等を組み合わせる。query rewritingを有効にしたsettingも評価する。

比較対象にはRAG-MIA、S²MIA、MBA等が含まれ、ROC-AUC、Accuracy、TPR@1% FPR、malicious-query detectorによる検出率、query budget / API costを測る。

## Main Results

NFCorpus + GTE + Phi-4の代表settingでは、IAは **AUC 0.992、accuracy 0.945、TPR@1%FPR 0.897** を達成する。同条件でS²MIAのTPR@1%FPRは約0.208、MBAは約0.265であり、low-FPR領域で特に大きな差がある。

複数dataset、retriever、generatorへ変更しても優位性が概ね維持される。

## Stealthiness / Defense Evaluation

IA queryはtarget document本文を直接要求せず通常QAに近いため、LakeraGuardでmaliciousと判定されるqueryは約 **5%**、GPT-4o classifierでは約 **1.2%** に留まるsettingが報告される。既存attackは条件によってIAより最大約76倍検出されやすい。

query rewritingを導入したRAGでも比較的robustであり、表面形式を変更されてもtarget documentをretrieveさせるsemantic intentが残りやすい。

## Query Budget / Cost

probe数を増やすほど性能は向上するが30 query前後から改善は徐々に小さくなる。一部settingでは5 questions程度でも既存baselineを上回る。API costはtarget document 1件あたり **$0.02未満**と報告される。

## Failure Modes / Limitations

false positiveの重要な原因はnear-duplicate documentとgeneratorのparametric knowledgeである。false negativeはtarget documentが存在していてもretrieverがtop-kへ入れられない場合に起こる。retrieval kを増やしすぎるとirrelevant contextが混入しsignalが薄まる場合もある。

IAはtarget documentをattackerが既に保持していることを前提とするため、未知corpusをゼロからreconstructするknowledge-base stealing attackではない。またmembershipとsemantic-equivalent documentの存在を厳密に分離することは難しい。

## RAG Security Taxonomyでの位置づけ

本論文は **Attack / confidentiality / membership inference / retrieval-database privacy** に位置づけられる。direct context extraction → reconstruction-based membership inference → natural interrogationによるstealthy membership inferenceという発展であり、access requirementを増やすのではなくmaliciousnessのobservable surfaceを減らす方向の改善である。

## 実装・研究上の示唆

RAG privacy defenseでは、prompt injectionや露骨なcontext extractionだけを検出しても不十分である。自然な質問を複数回行うだけでretrieval membershipが統計的に漏れる可能性があるため、user/session単位のsemantic probe sequence監視やmembership privacyの独立評価が必要になる。
