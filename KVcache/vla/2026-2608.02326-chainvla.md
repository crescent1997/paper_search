# ChainVLA — Progress ContextとMotion Tailを跨いだlong-horizon VLA

## 1. 概要

Action-chunk VLAは毎回`H`ステップ分のactionを予測し、その一部を実行して次の観測から再計画する。この境界では、(a) 以前のsubtaskの進捗と、(b) まだ実行していない前回のaction予測が失われやすい。ChainVLAはこの両者を**単一のcross-query execution state**として持ち越す1.2Bのconditional-flow VLA。**Transformerの過去KV tensorを次のforwardに再利用する方法ではない**。履歴から圧縮したmemory tokenと、action空間のcontinuation priorを扱う。

## 2. 問題設定・先行研究との差

Query `k`で`x_k=(o_k,r_k,l)`を観測し、`A_k=(a_{k,1},...,a_{k,H})`を予測して先頭`h_exec < H`だけ実行する。残りのsuffixは次のqueryの実行開始時点では未実行である。MemoryVLA/TempoFitは観測履歴を扱うが、**前回モデルが実行予定だった未実行部分**は別問題。Temporal Ensembleやaction smoothingは出力を合成するが、過去の進捗の長期保存を担わない。ChainVLAは両方を次の生成**前**に条件として投入し、古い予測を強制せず最新観測で全action horizonを再生成する。

## 3. 手法

### 3.1 Execution state

$$s_k=(g_k,u_k),\qquad g_k=\mathrm{Fuse}(L_k,Z_k^e),\qquad u_{k+1}=\mathrm{Tail}(A_k).$$

`g_k`はProgress Context、`L_k`はrecurrent Working Stateのlive token、`Z_k^e`はSparse Event Memoryから検索した過去の証拠。`u_k`は前回の未実行action suffix。更新は`(A_k,W_k,C_{k+1})=F_\theta(x_k,D_k,W_{k-1},C_k,u_k)`で表され、episode境界でリセットする。

### 3.2 Recurrent Working State

Learned working queriesを現在のmultimodal tokenへcross-attendさせ、前回live tokenとのcross-attentionで更新する。実行済みaction historyと未実行tailのembedding、proprioception、query timeも利用する。**8 current live tokens + 24 cached prior tokens（3-slot FIFO）**を維持する。ここでのcacheはlearned latent tokenのFIFOであり、self-attention KV cacheではない。

### 3.3 Sparse Event Memory（episodic）

各eventは**64 visual + 8 Stage Info + 8 temporal tokens**、検索key、write時刻を持つ。最大**16 records**で、最初のanchorを残して最古の非anchorをevictする。RMBenchでは学習時のstage transition supervisionと、推論時のpredicted stage変化（confidence≥0.55）で書込む。stage annotationがないLIBEROでは**3 queryごとの定期書込**。検索はWorking State summary、stage、時間情報からqueryを作り、age embedding付きcosine similarityで**anchor + top-2非anchor events**を選ぶ。Cross-attentionでevent bodyを読み、live tokenと融合する。Semantic/episodicな進捗を保持するが、厳密なsymbolic semantic memoryではない。

### 3.4 Motion Tail（予測由来の未完了運動）

前回の未実行suffixを2経路で使う。(1) **4 tail tokens**としてWorking Stateを条件付ける。(2) action horizonに時間整列した`mu=I(u_k)`でconditional-flow decoderの初期状態を`A^(0)=mu+sigma_u epsilon`とする。新しい観測で全action positionを再生成し、古いsuffixを固定しない。生成後にはoverlapを線形blendするが、これはモデル内部の2経路と区別する。

### 3.5 Training

Episode順にqueryをunrollし、前回のpredicted suffixはdetachして次へ渡す。学習時tailを使う確率は**0.5**。通常のconditional-flow action lossにstage supervision（利用可能時）とoverlap consistency regularizer（重み**0.2**）を追加。**追加学習が必要**であり、既存VLAへtraining-freeで差し込む方式ではない。

## 4. Experiment Setup

- **Model**: Florence-2-large + conditional-flow action decoder、合計**1.2B parameters**。
- **Action horizon**: `H=30`、実行prefix `h_exec=24`、tailは6 actions。
- **RMBench**: 記憶依存の5 tasks（Obs./Rearrange/Put Back/Swap Blocks/Swap Targets）、各100 episodes。各task別に50 demonstrationsで学習。
- **LIBERO**: Spatial/Object/Goal/Long、suiteごとfine-tune、各task50 episodes。
- **内部対照の共通条件**: 20,000 optimization steps、batch 4、seed 42（単一seed）、学習GPU 4×NVIDIA L20。外部論文からのbaseline値は同一条件で再学習していない。
- **主要指標**: success rate、chunk境界のposition/orientation command discontinuity（CD）、boundary second difference（B2）、旧計画と新計画の3-step overlap RMSE。**GPU memory、推論latency、control frequencyの実測比較はない**。

## 5. Main Results

### 5.1 RMBench（Table 1、成功率%）

| Policy | Obs. | Rearr. | Put Back | Swap Blocks | Swap Targets | Avg. |
|---|---:|---:|---:|---:|---:|---:|
| pi_0.5 | 9 | 13 | 11 | 24 | 15 | 14.4 |
| MemoryVLA | 0 | 22 | 50 | 17 | 9 | 19.6 |
| Mem-0 | 4 | 89 | 90 | 67 | 14 | 52.8 |
| **ChainVLA** | **11** | **93** | **96** | **74** | **40** | **62.8** |

Mem-0との差は**+10.0pp**、MemoryVLAとの差は**+43.2pp**（ただし外部モデルはサイズ、学習・評価条件が異なる可能性）。

### 5.2 LIBERO（Table 1）

ChainVLA: Spatial **98.4**、Object **99.4**、Goal **99.2**、Long **98.2**、4-suite平均**98.8**。X-VLA 98.1、MemoryVLA 96.7などの比較値を記載。ただしLIBEROは近年のモデルでceilingが近く、手法差の検出力はRMBenchの方が高い。

## 6. 主要Ablation（Table 2、RMBench平均SR）

| 変更 | SR | Fullとの差 |
|---|---:|---:|
| **Full** | **62.8** | — |
| w/o Stage Annotation | 53.4 | -9.4pp |
| w/o Live Tokens | 47.2 | -15.6pp |
| w/o Event Readout | 32.2 | -30.6pp |
| w/o Progress Context | **3.0** | -59.8pp |
| w/o Tail Tokens | 52.0 | -10.8pp |
| w/o Trajectory Initialization | 38.0 | -24.8pp |
| w/o Motion Tail | **11.2** | -51.6pp |
| w/o Both | **1.6** | -61.2pp |
| FIFO History + Temporal Ensemble | 35.6 | -27.2pp |

特に**Motion Tailを消すと11.2%**まで落ちる。Event readoutを消すとPut Backが96→25、進捗が視界から消えるtaskで効果が大きい。Motion Tailではtrajectory initializationの方がtail tokensより重要（38.0 vs 52.0）。

### 6.1 境界診断（Appendix Table A4）

Fullとw/o Motion Tailのmatched rollout 80組を比較すると、position CD **7.510→3.262mm (-56.6%)**、orientation CD **0.851→0.508deg (-40.4%)**、B2 **6.491→2.767mm (-57.4%)**、overlap RMSE **10.751→6.118mm (-43.1%)**。ただしpost-decoding smoothingだけでも境界値は小さくなる一方、Put Backで**成功率0%**のままという対照があり、単なるaction平滑化では長期taskの進捗記憶を代替できない。

## 7. Limitations / 批判的評価

1. **実機なし・固定周期simulationのみ**。Action successとboundary指標は報告されるが、latency、GPU memory、throughput、実control Hzは未検証。
2. **単一seed**、統計的有意差・seed分散の報告なし。外部baselineは再実装したmatched comparisonではない。
3. Ablationは機構だけでなく学習lossやdeployment pathを同時に除くため、個々の演算の純粋な因果効果ではない。
4. Memory 16 records、stage confidence 0.55、3-query interval、tail blendingなどのsensitivityは未探索。長時間episodeで重要eventがevictされる可能性。
5. **KV cache最適化としての直接的speedupはない**。Working StateのFIFOはlatent memoryであり、attention K/V reuseとは別物。
6. 著者の公式code releaseは確認できない。プロジェクトページはあるが、コードURLとして扱わない。

## 8. Taxonomy / 関連研究

- **分類**: `KVcache/vla` / long-horizon / episodic & working memory / action continuation / flow matching。
- **観測由来memoryとの比較**: [MemoryVLA](2025-2508.19236-memoryvla.md)、[MemoryVLA++](2026-2606.09827-memoryvla-pp.md)はperceptual/cognitive履歴や未来想像を中心に設計。ChainVLAは**前回の未実行action**をcross-query stateに組み込む。
- **KV reuseとの比較**: [TempoFit](2026-2603.07647-tempofit.md)は過去フレームのlayer-wise KVを実際に再利用。ChainVLAはlatent stateとaction suffixを使う。
- **Action再利用との比較**: [ActionCache](2026-2607.06370-actioncache.md)は過去episodeの中間actionを検索してdenoisingを短縮。ChainVLAは**直前queryの未実行suffix**をrevisable priorに使い、各positionを再生成する。
