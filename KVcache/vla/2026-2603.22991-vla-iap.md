# 概要
VLA-IAP（Interaction-Aligned Pruning）は、視覚tokenの意味的重要度だけでは物理操作に必要な対象の輪郭や接触部位を誤って消してしまう問題を扱う。semantic maskとmotion maskのIoUが低い探索段階では保守的に残し、両者が一致して操作対象を捉えた後は積極的にpruningする。さらにSobel edge priorで形状境界を保護する。追加学習は不要。

# 問題設定・先行研究との差
FastV、SparseVLM、DivPrune等はsemantic saliencyを重視するため、textureの乏しいgripper-object境界を捨てる危険がある。VLA-Cacheはcross-frame visual KVの再利用、VLA-Prunerはaction attentionを利用するが、VLA-IAPは**物理motionとsemantic intentの空間的一致度**を制御変数にする。KV tensorの再利用ではなく、入力visual tokenの選択と削除で後段の演算量を削減する。

# 手法
1. RGB画像をgrayscale化し、Sobel x/y gradientからedge magnitudeを求め、visual token patch単位で平均する。これをgeometry priorとして正規化する。
2. 視覚tokenとtext instruction embeddingの内積をsoftmax化し、semantic saliency mapを作る。
3. 連続観測のmotion cueからmotion priorを作り、semantic priorとの空間重複（IoU）を算出する。
4. IoUが閾値以下の探索段階では**conservative mode**を採用し、物体の候補を広く保持。閾値を超えたinteraction lock段階では**aggressive mode**で削減率を上げる。
5. semantic/motion saliencyにedge priorを統合してtop-K tokenを選択する。全画像の高解像度処理を維持するのではなく、限られたtoken budgetを接触境界へ振り分ける。

Sobel priorの主要式：

```math
G_x=I_{gray}*K_x,\qquad G_y=I_{gray}*K_y
```

```math
E_i=\frac{1}{|P_i|}\sum_{(u,v)\in P_i}\sqrt{G_x(u,v)^2+G_y(u,v)^2}
```

幾何境界が常にaffordanceを意味するわけではなく、原論文はSobel勾配を簡便なproxyとして利用している点に注意。

# Experiment Setup
- Backbone: DreamVLA、π0、π0.5、OpenVLA-OFT。LIBERO、CALVIN、VLABench、実機双腕タスクを評価。
- 比較: FastV、SparseVLM、DivPrune、VLA-Cache、EfficientVLA、VLA-ADP、SpecPrune-VLAなど。retention ratio 70/50/30%の比較。
- 主指標: task success、CALVIN sequence length、CUDA latency、peak GPU memory、実機での成功率とspeedup。
- Pruning自体はtraining-free。評価用backboneの事前学習・fine-tuningは別途必要。

# Main Results
OpenVLA-OFT LIBERO（原論文Table 2、retention ratioは残すtoken割合）：

| Method | Retention | Avg success | LIBERO-Long | Speedup |
|---|---:|---:|---:|---:|
| Vanilla | 100% | 97.1% | 94.8% | 1.00x |
| VLA-Cache | 比較設定 | 97.4% | 95.4% | 1.30x |
| EfficientVLA | 比較設定 | 88.9% | 72.1% | 1.54x |
| VLA-IAP | 70% | 97.8% | 95.6% | 1.25x |
| VLA-IAP | 50% | 97.5% | 95.2% | 1.37x |
| VLA-IAP | 30% | 97.1% | 94.8% | 1.54x |

VLABench π0におけるCUDA runtimeとpeak memory（Table 4）：Vanilla 98.03ms / 7.11GB、VLA-IAP 30% retention 65.79ms / 6.882GB。GPU memory削減は約3.2%で、latency改善の方が大きい。VLABenchの難しい条件で30% retention時、VLA-IAP 33.3%、VLA-Cache 8.0%、DivPrune 6.7%（原論文本文）。ただしこの値をLIBEROと混同しない。

# Ablation
原論文Table 3は、各componentを段階的に追加したOpenVLA-OFT実験：

| 設定 | Success | Latency | Speedup |
|---|---:|---:|---:|
| Base | 94.5% | 123.2ms | 1.00x |
| Spatiotemporal pruning k=0.5 | 94.8% | 86.7ms | 1.42x |
| + IoU switching θ=0.05 | 97.2% | 93.3ms | 1.32x |
| + Sobel edge w=1.0 | 97.8% | 98.6ms | 1.25x |
| IoU θ=0.02, edge w=1.0 | 97.1% | 80.0ms | 1.54x |

精度を最大化する設定と高速化を最大化する設定は異なる。SobelとCanny/HED/BDCNの比較では、Sobelが97.8%/98.6ms、Canny 96.8%/104.5ms、HED 97.4%/125.1ms、BDCN 97.5%/132.8ms。重いedge detectorではpruningの速度利益が消える。

# Limitations
- IoU thresholdとmotion maskの品質に依存。camera motion、静止した操作対象、反射・透明物体でmotion priorが不安定になり得る。
- Sobelのedgeは機能的affordanceを直接認識するものではない。texture/背景輪郭にも反応する。
- 高度なlong-horizon memory、episodic retrieval、cross-frame KV reuseは実装しない。
- Benchmarks間でbackbone、retention、task complexityが異なる。speedupとsuccessを異条件で単純比較しない。
- 2026-10時点のmlsanityでは改題された別タイトルで掲載されており、arXiv版と差分があり得る。本文の数値は確認したarXiv HTML v1に基づく。

# Taxonomy
`KVcache/vla/`：**interaction-aware visual token pruning / geometric prior / dynamic budget**。KV cache直接reuseとは異なる。後段attention token数を減らすことでKV生成・計算負荷を間接的に削減。
