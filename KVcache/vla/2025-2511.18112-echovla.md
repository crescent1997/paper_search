# EchoVLA — Persistent Scene + Episodic Memory for Mobile Manipulation

## 1. 概要
移動台車とアームを同時に動かすmobile manipulationでは、現在の画像だけで「どの部屋に何があったか」「drawerを開けた後か」などを判定できない。EchoVLAは空間の長期的な3D構造を保持する**scene memory**と、最近の操作履歴を保持する**episodic memory**を独立に管理し、検索・attention融合してbase/armそれぞれのdiffusion policyを条件付けする。併せてnavigation+manipulationのexpert trajectoryを生成するMoManiデータセットを提案。

## 2. 問題設定と先行研究との差
$t$ のmultiview RGB-D観測 $O_t$、robot state $s_t$、自然言語指示 $I$ から $(a_t^{arm},a_t^{base})=\pi_\theta(I,O_{1:t},s_{1:t})$ を生成する。MemoryVLAはperceptual/cognitive memory bankを使うのに対し、EchoVLAは**幾何学的に持続する3D voxel scene map**と**時刻付き最近のmultimodal token列**を分ける。移動中に一時的に視界から消えたobjectの位置情報と、近時刻の操作進捗を別々に引き出すのが狙い。

## 3. 手法
### 3.1 Multimodal state
言語と3 camera RGBはfrozen SigLIPでencode、depthはpoint cloud化しtrainable PointAttn、proprioceptionはMLP。$S_t=[L,V_t,P_t,R_t]$ を構成し、記憶のqueryとdiffusion policy条件に使う。

### 3.2 Scene memory — 長期3D空間構造
環境ごとにvoxelized 3D feature map $V_t^{3D}\in\mathbb R^{X\times Y\times Z\times C}$ を保持。観測depthから3D featuresを更新し、既存memoryからのreconstructionとの差が閾値を超えるregionだけwriteする**discrepancy-driven update**を用いる。動かない構造を再書き込みせず、長期の幾何情報を保持。推論中もonline更新するため環境の変化に対応できるとするが、door開閉による急な幾何変化は失敗要因。

### 3.3 Episodic memory — 最近の進捗
$M_t^{epi}=\{(S_{t-k},t-k),\ldots,(S_{t-1},t-1)\}$ を長さ$k$のFIFOで保持。Scene memoryと異なり**raw encoded tokensを保持し、抽象的summaryへ圧縮しない**。Drawerを開けた、物を掴んだ等の最近の進捗を表現するが、FIFO外の古いイベントは保持しない。

### 3.4 Retrieval / attention
現在の3D mapと保存scene mapをcosine類似度で照合しtop-kを選択、coarse cross-attention:

$$Z_t^{scene}=\mathrm{CrossAttn}(q=V_t^{3D}, k/v=M_{sel}^{scene}).$$

現在のmultimodal state $S_t$ とepisodic bufferもcosine類似度で検索し、fine cross-attention:

$$Z_t^{epi}=\mathrm{CrossAttn}(q=S_t,k/v=M_{sel}^{epi}).$$

$H_t=[Z_t^{scene},Z_t^{epi}]$ をdiffusion expertへ渡す。ここでのmemoryの`key/value`はcross-attentionに与えるembeddingであり、**Transformerのprefill済みper-layer KV cacheを再利用する意味ではない**。

### 3.5 Per-part diffusion policy
Mobile baseとarmのactionを別々のdenoiserで生成する。$p\in\{base,arm\}$ に対し $\epsilon_\theta^{(p)}=\mathrm{Denoiser}_p(z_t,H_t,t)$、両partのdenoising MSEの和を最小化する。Scene/episodic memoryとpolicyは学習・更新が必要で、training-free手法ではない。

## 4. Experiment Setup
- **Simulation:** RoboCasaでPickPlaceCounterToStove、PickPlaceSinkToCounter、TurnOnSinkFaucet、TurnOnStove、およびnavigation-only。50 episodes/task、3 seeds平均と本文に記載。
- **MoMani:** 7,889 simulation episodes（うちnavigation-only 57%）、1,200 real-world episodes。MLLM-guided candidate generation→collision/pose/successによるquality gate→ranking/audit。実機データはTidyBot++ベース、Kinova Gen3 7-DoF＋holonomic base、ROS、30Hz記録。
- **Baselines:** BC-T、Diffusion Policy、DP3、WB-VIMA、π0.5。VLAモデルの完全同一backbone条件でのmemory-only比較とは限らない。
- **Training:** 8×NVIDIA A100で学習と記載。SigLIP frozen、PointAttn・memory関連・diffusion policyを学習。
- **Metrics:** task success rate、scene/episodic memory ablation、window size、scene update threshold、real-world success。**end-to-end inference latency / throughput / GPU memory / action control frequencyは比較表に未報告**。30Hzは収録rateであってpolicy推論周波数ではない。

## 5. Main Results
### 5.1 RoboCasa (PDF Table 2, SR)
| Method | Manipulation/Navigation avg | Mobile manipulation avg |
|---|---:|---:|
| BC-T | 0.28 | 0.05 |
| DP3 | 0.22 | 0.06 |
| WB-VIMA | 0.15 | 0.11 |
| π0.5 | 0.32 | 0.20 |
| **EchoVLA** | **0.52** | **0.31** |

π0.5に対してそれぞれ+0.20、+0.11 absolute。Mobile manipulationのタスク別EchoVLAはCounter→Stove 0.17、Sink→Counter 0.34、Faucet 0.29、Stove 0.43。**本文にπ0.5の0.47→0.36と記した文章があるが、Table 2の実数（0.32→0.20）と矛盾するため表を採用**。Versionの差にも注意。

### 5.2 Real robot (PDF Table 5)
| Method | OD | CM | PCIS | OR | RK | EnP | Avg SR |
|---|---:|---:|---:|---:|---:|---:|---:|
| π0.5 | .35 | .55 | .20 | .50 | .40 | .00 | .33 |
| Diffusion Policy | .40 | .60 | .50 | .30 | .10 | .03 | .32 |
| **EchoVLA** | **.45** | **.70** | **.50** | **.40** | **.50** | **.10** | **.44** |

## 6. 主要Ablation
PDF Table 3、Counter→Stove Mobile(M) / stationary(S)：
| Variant | M | S |
|---|---:|---:|
| Full RGB+PC+EM+SM | **.17** | **.21** |
| w/o RGB | .02 | .13 |
| w/o point cloud | .08 | .15 |
| w/o scene memory (SM) | .09 | .16 |
| w/o episodic memory (EM) | .14 | .13 |

Mobileでscene memoryを外すと.17→.09、episodic memoryを外すと.17→.14。Stationaryではepisodic memoryの寄与が大きい（.21→.13）。この非対称性は**空間記憶がnavigationを、短期経験が操作進捗を支える**という役割分担に整合。

PDF Table 4：Episodic window $L=2,4,8,16$ に対するMobile SR=.08,.12,.17,.15。Scene update threshold $\tau=.1,.3,.5,.7$ に対しSR=.11,.14,.17,.13。小windowでは進捗を忘れ、過大windowではlatency増加と説明するが**latencyのms値は未掲載**。小thresholdは不安定な頻繁update、大thresholdはstale scene mapを生む。

## 7. Limitations / 批判的評価
1. **KV cache研究ではない。** 持続する3D mapと短期FIFO token bufferが主対象で、visual KV再利用・prefill削減・decode高速化は検証されない。
2. **速度・VRAM tradeoff不明。** 3 camera + point cloud + scene retrieval + episodic retrieval + 2 diffusion headsは重くなりうるが、GPU memory、throughput、control frequencyを定量比較していない。
3. **長期記憶の限界。** Scene memoryは環境固有で再配置・動的遮蔽に弱く、episodic memoryは短期FIFOで古い出来事を忘れる。Semantic consolidationや長期forgetting policyは明示的に扱わない。
4. **成功率の絶対値。** 実機EnPは10%、複数段階の長時間タスクを十分に解いたとは言い難い。各20 trialsで誤差も大きい。
5. **比較条件と著者版差。** PDF v2とarXiv現在のmetadataでtitle/著者が異なる。PDF v2本文のTable 2内の記述と表にも矛盾があるため、後続版の再照合が望ましい。
6. **追加学習が必要。** SigLIPの一部はfrozenでも新規memory/PointAttn/policyは学習する。公開code URLは一次情報で確認できず`null`。
