# Block-Attention for Efficient Prefilling

> RAGで毎回すべてのretrieved passagesをprefillし直すのではなく、各passageを独立blockとしてKV cache化し、別requestでも再利用する。単純なparallel encodingではaccuracyが大きく落ちるため、**position re-encoding + block-aware fine-tuning**によってモデル自身をreuse-friendlyに適応させる点が中心的な貢献。

## 概要

RAGでは複数のretrieved passagesをinstruction・queryと連結するため、contextが長くなるほどprefill costとTime To First Token (TTFT)が大きくなる。

通常のdecoder-only Transformerでは、後ろのdocumentほど前に置かれたdocumentをattentionしてhidden state / KV stateを作る。そのため同じdocumentでも、前文脈や配置順が変わればKVも変わる。

これはprefix cachingでは問題にならない。prefixが完全一致していればcausal historyも同じなのでKVをそのままreuseできる。一方RAGでは、同じpassageがrequestごとに異なる位置へ現れるため、standard prefix cacheではreuse機会が少ない。

Block-Attentionはこのdependency自体を変更する。

各retrieved passageを独立blockとして計算し、passage block同士にはattentionさせない。最後のquery blockだけがすべてのpassage blockを参照する。

```text
Block 0: Document A ─┐
Block 1: Document B ─┤
Block 2: Document C ─┼─→ Final Block: User Query
       ...           │
Block k-1: Document ─┘
```

これにより各Document blockのKVは他Documentに依存しなくなり、同じpassageなら別requestでも再利用できる。

ただし、このattention patternは通常のfull-attention pretrained modelが学習していないため、maskだけを切り替えると性能が大きく低下する。本論文はこの問題を、推論時のpartial recomputationではなく**fine-tuningでモデルをBlock-Attentionへ適応させる**ことで解決する。

## 問題設定

入力を複数block

[
B_0, B_1, ldots, B_{k-1}, B_k
]

へ分割する。RAGでは (B_0 ldots B_{k-1}) がretrieved passages、(B_k) がqueryを含むfinal blockである。

standard causal attentionでは、(B_i) のKVはそれ以前のすべてのblockに依存する。

[
KV(B_i)=f(B_0,ldots,B_i)
]

したがって途中のdocumentが変わると、それ以降のdocumentも含めて再prefillが必要になる。

Block-Attentionでは、passage blockをblock-local attentionに制限し、

[
KV(B_i)=f(B_i)
]

となるようにする。final query blockだけは全passageへattentionできる。

概念的なmaskは次のようになる。

```text
             Key
          B0 B1 B2 Q
Query B0   ✓  ×  ×  ×
      B1   ×  ✓  ×  ×
      B2   ×  ×  ✓  ×
      Q    ✓  ✓  ✓  ✓
```

これによりdocument KVをrequest間で独立にcacheできる。

## 手法

### 1. Block Segmentation

RAGでは基本的に **1 retrieved passage = 1 block** とする。

各passage block内部では通常のcausal attentionを行うが、別passageは見ない。最後のquery blockだけが全passageを参照する。

この構造はRAG以外にも、

- ICL: 1 demonstration = 1 block
- multi-turn dialogue: 1 turn = 1 block
- code: function単位

のように適用できるとされる。

重要なのは、semanticに比較的独立した単位をblockにすることである。

### 2. Position Re-encoding

passage KVを別requestへ移す場合、contentが同じでもRoPE上のpositionが異なる。

たとえば同じDocument Aがrequestごとにposition 200と1800へ置かれるなら、RoPE適用済みKeyはそのままreuseできない。

Block-Attentionではcached KVから元のRoPE rotationを取り除き、block先頭をposition 0に正規化して保存する。その後、実request内での新しいblock位置に合わせてrotationを再適用する。

RoPEを (R(i)) とすると、概念的には

[
R(i')R(-i)
]

を用いてold position (i) からnew position (i') へ移す。

cacheをposition 0基準にしておくことで、runtime側は新しいblock startだけ分かればよくなる。

### 3. Block Fine-tuning

pretrained modelへBlock-Attention maskだけを適用すると大きくaccuracyが落ちる。

理由は、training時にはdocument間のcross-attentionが存在したのに、inference時だけそれを消すためである。

そこでfine-tuning時から、

- passage blockは自block内のみattention
- final blockは全blockへattention

というmaskを使う。

さらに著者らはBlock-Attentionだけでなく、**full attentionとBlock-Attentionの両modeを混ぜて学習**する。

これにより、RAGやICLではBlock-Attention、zero-shot taskではfull attentionという切り替えを可能にする。

論文では約800 training stepsで両modeのperformance gapがほぼ消えると報告する。

## Training Data

base modelは **Llama-3.1-Tulu-3-8B-SFT**。

training dataは主に2種類。

1. **Tulu3 SFT mixture**
   - multi-turnでは1 user-assistant turnを1 block
   - system messageとuser messageを別block
   - `\n\n` などのseparatorもboundaryに利用

2. **RAG-specific data**
   - TriviaQAと2WikiMultiHopQAから合計20,000 instances
   - Contrieverでtop-10 passagesをretrieve
   - answerはLlama-3.3-70B-Instructにretrieved passagesを見せて生成

ground-truth answerをそのままtargetにしないのは、retrieved contextに答えがない場合でもparametric knowledgeだけで正解してしまうtraining signalを避けるためである。

trainingは8× NVIDIA H20で行い、learning rate (2	imes10^{-5})、batch size 64、1 epoch、bf16、DeepSpeed、FlashAttentionを使用する。

## 評価

主要RAG benchmarkは、

- 2WikiMultiHopQA
- HotpotQA
- Natural Questions
- TriviaQA

である。

さらにMMLU、BBH、DROP、MATH、GSM8K、HumanEval、IFEvalなどを含め、RAG / ICL / general-domainの合計11 benchmarkを評価する。

比較modelには、

- Tulu3-SFT
- Tulu3-RAG（full-attention RAG fine-tuning）
- Tulu3-block-ft
- Tulu3-block-w/o-ft
- PromptCache
- Superposition

などを用いる。

## Main Results

### RAG accuracy

代表値は次の通り。

| Model | 2Wiki | HQA | NQ | TQA |
|---|---:|---:|---:|---:|
| Tulu3-RAG | 73.2 | 74.8 | 61.5 | 75.8 |
| Block w/o FT | 42.9 | 42.1 | 48.3 | 66.5 |
| Tulu3-block-ft | 72.2 | 72.3 | 60.4 | 75.1 |

maskだけBlock-Attentionへ変えると大幅に性能が落ちる一方、fine-tuning後はfull-attention RAG baselineにかなり近い水準まで回復する。

つまり本手法では、**independent KV reuseを成立させるためのmodel adaptationが本質的**である。

### Training-free parallel encodingとの比較

PromptCacheやSuperpositionもdocumentを独立encodeしてreuseするが、同じRAG benchmarkではBlock-Attention fine-tuned modelよりかなり低い。

代表例では、

| Method | 2Wiki | HQA | NQ | TQA |
|---|---:|---:|---:|---:|
| Superposition | 30.1 | 32.3 | 35.9 | 58.9 |
| PromptCache | 32.4 | 31.6 | 44.4 | 61.8 |
| Block-Attention FT | 72.2 | 72.3 | 60.4 | 75.1 |

となる。

この差から、position処理だけでなく、full-attention trainingとのdistribution mismatchをfine-tuningで吸収する必要があることが分かる。

### Position re-encoding ablation

position re-encodingを外すと、

| Model | 2Wiki | HQA | NQ | TQA |
|---|---:|---:|---:|---:|
| Block FT | 72.2 | 72.3 | 60.4 | 75.1 |
| w/o position re-encoding | 68.9 | 69.9 | 59.2 | 74.4 |

となり、平均約2 point低下する。

したがってfine-tuningを行っても、cached blockを正しいglobal positionへ再配置する処理は重要である。

## TTFT / FLOPs

efficiency評価ではquery部分を50 tokensに固定し、retrieved context lengthを増やす。

代表値は、

| Prompt Length | Full TTFT | Block TTFT |
|---:|---:|---:|
| 512 | 50 ms | 26 ms |
| 4K | 330 ms | 27 ms |
| 16K | 1515 ms | 34 ms |
| 32K | 3638 ms | 45 ms |

32K contextでは、

- TTFT: 3638 ms → 45 ms
- reduction: **98.7%**
- FLOPs-TFT reduction: **99.8%**

を報告する。

Block-Attention側のTTFTがcontext lengthにあまり増えないのは、retrieved passageのKVをcacheから読み出し、主にfinal query blockだけをforwardするためである。

ただしこの測定は、**passage KVが既にcacheされ利用可能**という条件であり、large-scale cache storage、CPU/NVMe transfer、eviction等のsystem costは含まれない。

## CacheBlendとの違い

[CacheBlend](2024-2405.16444-cacheblend.md)もRAG document KV reuseを目指すが、解き方が異なる。

CacheBlendはpretrained modelを維持し、独立KVをconcatしたことで失われたcross-document interactionを**selective recomputation**で補う。

```text
cached KV
  ↓
concatenate
  ↓
important tokens only recompute
```

一方Block-Attentionは、

```text
block-local attention
+
position re-encoding
+
fine-tuning
```

によって、そもそもdocument間attentionを必要としないようmodel側を適応させる。

| | CacheBlend | Block-Attention |
|---|---|---|
| pretrained model変更 | 原則不要 | fine-tuning必要 |
| runtime recomputation | あり | cached passageではほぼ不要 |
| cross-document interaction | 部分的に回復 | passage間では使わない |
| reuse方針 | cacheをfull-prefillへ近づける | modelをreuse cacheへ適応 |

この違いはreuse研究を整理する上で重要である。

## EPICとの違い

[EPIC](2024-2410.15332-epic.md)もposition-independent reuseを狙うが、EPICはattention sink等を**inference-time linking**で軽量補正する。

Block-Attentionはposition re-encodingに加えてmodel自体をblock-independent encodingへfine-tuneするため、training-adapted reuseに分類できる。

## Limitations

1. **Fine-tuningが必要**  
   maskだけ変更したdrop-in利用では性能が大きく落ちる。

2. **Passage間interactionを捨てる**  
   document block同士はattentionしない。multi-hop reasoningはfinal query blockで統合する設計になる。

3. **Cache storage costを十分評価していない**  
   実systemではGPU/CPU/NVMe容量、transfer bandwidth、lookup、evictionが重要になる。

4. **Cache hit率に依存**  
   初めて現れるpassageは新規prefillが必要。

5. **Block granularity依存**  
   semanticに独立したpassageでは扱いやすいが、強い前後依存を持つ長documentではboundary設計が性能へ影響する可能性がある。

## KV-cache taxonomyでの位置づけ

Block-Attentionは **reuse-aware fine-tuning / training-adapted reuse** の代表例。

reuse系は大きく、

- **Exact Prefix Reuse** — same prefixならそのままreuse
- **Inference-time Repair** — CacheBlendのようにreuse後にpartial recomputation
- **Position-independent Linking** — EPICのように軽量linkingで任意位置reuse
- **Reuse-aware Fine-tuning** — Block-Attentionのようにmodel自体をreuse前提へ適応

と整理できる。

特に本論文は、

> full prefillの内部stateを正確に再現する必要はなく、reuseされたKVで正しく動くmodelを学習すればよい

という別方向の解を示している。

## まとめ

Block-AttentionはRAGのprefillを、

```text
All documents
  ↓
Sequential full prefill
  ↓
Query
```

から、

```text
Reusable document blocks
  ↓
Cached KV
  ↓
Position re-encoding
  ↓
Query-only prefill
```

へ変える。

中心componentは、

| Component | Role |
|---|---|
| Block segmentation | passage間dependencyを切りKVを独立化 |
| Position re-encoding | cached KVを新しいprompt位置へ移動 |
| Block fine-tuning | full-attention trainingとのmismatchを解消 |

fine-tuningなしではRAG accuracyが大幅に落ちるが、block-aware fine-tuning後はfull-attention baselineに近い性能まで回復する。

32K contextではcached passageが利用可能という条件下でTTFTを98.7%、FLOPs-TFTを99.8%削減する。

KV reuse研究としては、[CacheBlend](2024-2405.16444-cacheblend.md)のように「cacheをfull-prefill stateへ近づける」のではなく、**modelをreuse cacheへ適応させる**代表的手法として位置づけられる。
