# Keyformer: KV Cache Reduction through Key Tokens Selection for Efficient Generative Inference

> 過去attentionが高いtokenを単純に残すのではなく、**KV eviction後にattention scoreの分布自体が変わる**ことを考慮してkey tokenを選ぶ。Scissorhands/H₂O系のattention-based evictionを、Gumbel regularizationとtemperature schedulingで改善する手法。

## 概要

autoregressive decodeでは、contextが長くなるほどKV cache容量とそのread bandwidthが増える。Keyformerは、generation中のattention weightのおよそ90%が少数tokenへ集中するという観察に基づき、重要な**key tokens**だけをKV cacheへ残す。

既存のattention-based evictionは、現在観測されるattention scoreをそのままimportanceとして使うことが多い。しかし一度tokenを捨てるとsoftmax denominatorが変わり、残ったtokenのattention distributionも変化する。そのbiasedなscoreで次のevictionを行うと誤差が蓄積する。

Keyformerはこのdistribution shiftを抑えるため、attention logitsへGumbel noiseを加え、temperature-controlled softmaxからimportance scoreを構成する。

## 問題設定

cache budgetを元prompt KVの一定割合に制限しながら、

- summarization / conversation accuracyを維持
- long-contextでKV memory trafficを削減
- fine-tuningなしで既存modelへ適用

することを目標とする。

cacheは大きく、

- **recent window**
- **historically important key tokens**

の2部分から構成される。

recent tokenは短距離dependencyを保つため必ず残し、それより古いtokenからkey tokenを選ぶ。

## 既存attention-score evictionの問題

tokenを削除する前のsoftmax attentionを

```text
p_i = exp(s_i) / Σ_j exp(s_j)
```

とすると、tokenを削除した後はdenominatorが変わる。

すると残存tokenのprobabilityが相対的に増え、削除前と同じ意味でimportanceを比較できなくなる。

このshiftを無視して累積attentionだけを使うと、一度のevictionによるbiasが後続stepのtoken rankingへ伝播する。

KeyformerはここをH₂O等との差分として明示的に扱う。

## Keyformer score

### Gumbel regularization

attention logitsへGumbel noiseを加え、temperature `τ` を使ってsoftmaxを計算する。

Gumbel noiseによりscoreを完全にdeterministicなcurrent distributionへ固定せず、削除tokenによるdistribution distortionへrobustにする。

### Temperature scheduling

`τ`はgeneration中に固定ではなく、概ね`τ_init = 1`から高い値へ徐々に増やす。

generationが進むほどeviction済みtokenが増え、元のfull-attention distributionとの差も大きくなるため、temperatureを上げてscoreを平滑化する。

supplementaryでは1→2程度へsweepする設定が有効と報告される。

## Cache management

cache sizeを`k`、recent-window sizeを`w`とすると、

```text
KV cache = recent w tokens + top-(k-w) key tokens
```

となる。

各decode stepで、

1. recent tokensを無条件に保持
2. older tokensについてKeyformer scoreを更新
3. budgetを超えるtokenをevict
4. recent windowから外れたtokenをkey-token候補へ移す

ことでcache sizeを一定に保つ。

model parameterのfine-tuningは不要。

## Position handling

KV tokenをevictした後、残ったtokenだけを新しい連続positionへ詰め直す方法も考えられる。

Keyformerのablationでは、**original positional informationを維持する方が良い**。

代表例としてMPT-7B / 60% cacheのCNN/DailyMailでは、

- Original Position: ROUGE-2 17.60
- New Position: 16.91
- H₂O: 16.39

と報告される。

KV compressionでもposition semanticsを壊さないことが重要であることを示す結果で、reuse系でのre-RoPE問題とも関連する。

## H₂Oとの差

[H₂O](2023-2306.14048-h2o.md)はcumulative attentionが高いHeavy Hittersとrecent tokensを保持する。

Keyformerもattention historyを利用するが、中心的な違いは**eviction後のscore distribution shiftを補正すること**。

| | H₂O | Keyformer |
|---|---|---|
| importance | cumulative attention | Gumbel-regularized attention score |
| recent protection | あり | あり |
| distribution-shift対策 | 明示的でない | Gumbel + temperature |
| training | 不要 | 不要 |
| granularity | token | token |

技術系譜としては、

```text
Scissorhands
  ↓ Persistence of Importance
H₂O
  ↓ accumulated Heavy Hitters
Keyformer
  ↓ eviction-induced score shiftをregularize
```

と整理できる。

## StreamingLLMとの差

[StreamingLLM](2023-2309.17453-streamingllm.md)はattention sink + recent windowを固定的に残す。

Keyformerはinitial sinkを固定保存する方式ではなく、older contextから**動的にkey token**を選ぶ。

そのためarbitrary old informationを残せる可能性がある一方、毎step importance scoreを更新するoverheadがある。

## Experiment Setup

以下3 modelを評価する。

- GPT-J
- Cerebras-GPT
- MPT

position encodingも異なり、

- learned positional embedding
- RoPE
- ALiBi

を横断する。

taskは主に、

- CNN/DailyMail
- GovReport
- SODA
- PIQA
- Winogrande
- OpenBookQA
- COPA

など。

summarizationとconversationを中心に、long-contextでcache削減時のaccuracyを比較する。

## Main Results

### Accuracy / cache reduction

長文GovReportでは、**50% KV cacheでも99% accuracy thresholdを維持**するcaseを報告する。

通常のsummarizationでも70%程度のcacheでfull-cache baselineに近いaccuracyを維持し、H₂Oより小さいcache budgetで同等qualityへ到達する結果を示す。

### System performance

50% KV cache reductionで、

- **最大2.1× inference latency改善**
- **最大2.4× token-generation throughput向上**

を報告する。

KV cache data movement自体も大きく減り、longer sequenceほどmemory-bandwidth reductionのbenefitが大きくなる。

## Ablation

### Gumbel vs other perturbations

CNN/DailyMail / 60% KV cacheの代表値では、GPT-JのROUGE-2が

- Gumbel: 19.44
- Gaussian: 14.53
- Constant: 12.49
- adjustmentなし: 18.87

Cerebras-GPTでは

- Gumbel: 15.25
- Gaussian: 9.54
- Constant: 8.98
- adjustmentなし: 12.73

となり、Gumbel-based scoringの効果が大きい。

### Per-layer score

全layerでshared importanceを使うより、**layerごとに独立scoreを持つ方が高精度**。

attentionの重要token patternがlayerごとに異なるため。

### Recent-window ratio

recent windowを大きくしすぎるとkey-token枠が減り、小さすぎるとlocal dependencyを失う。

論文では20–30%程度が有効な領域として示される。

### Temperature

固定temperatureより、generation中にtemperatureを徐々に増加させる方がaccuracyを維持しやすい。

## Limitations

1. token-level evictionは不可逆であり、後続queryで突然重要になるtokenを既に捨てている可能性がある。
2. attention score更新とGumbel-softmax計算のoverheadがある。
3. evaluation modelは現在の大規模GQA/MLA modelより古い世代が中心。
4. long-range exact retrieval taskでは、query-dependent access型のQUEST / RetrievalAttention等より不利になり得る。
5. cache budgetとrecent-window比率はtask/modelに応じた調整余地がある。

## KV-cache taxonomyでの位置づけ

**compress / token eviction / attention-based importance / training-free / online decode-time selection**。

保存するKV token数そのものを減らすため、主categoryは`compress`。

特に、

> 「どのtokenが重要か」だけでなく、**tokenを捨てた後にimportance score自体がどう歪むか**

を扱った点が重要。

## まとめ

Keyformerはattention sparsityを利用したtoken evictionを、distribution-shift-aware scoringへ進めた手法。

中心componentは、

| Component | Role |
|---|---|
| recent window | local dependencyを保護 |
| key-token score | older contextから重要KVを選択 |
| Gumbel noise | eviction-induced score biasをregularize |
| temperature scheduling | generation進行に伴うdistribution shiftへ適応 |
| original positions | positional semanticsを維持 |

50% KV cacheで最大2.1× latency改善、2.4× throughput向上を報告し、Scissorhands / H₂Oから続くattention-based KV evictionの重要なhistorical developmentとして位置づけられる。
