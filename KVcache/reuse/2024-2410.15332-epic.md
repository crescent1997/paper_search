# EPIC: Efficient Position-Independent Caching for Serving Large Language Models

> exact prefixが一致しなくても、同じdocument / example chunkのKVを任意位置で再利用するPosition-Independent Cachingをsystemとして実現する。単純PICで生じるaccuracy degradationを、segment先頭のattention sinkに着目して少量のrecomputationで補正する。

## 概要

prefix cachingは非常に効率が良いが、cache hit条件が厳しい。

request AとBで同じdocumentが使われていても、そのdocumentより前のinstructionやexampleが異なればprefixは一致せず、通常のcache reuseは成立しない。

few-shot learning、multi-document QA、RAGではまさにこの状況が頻繁に起きる。

EPICは、promptを再利用可能なchunkへ分け、各chunkのKVをprefix位置に依存せず使い回すPosition-Independent Caching、PICを定式化する。

## Prefix cachingの制約

standard context cacheでは、

same prefix → same hidden states → same KV

が成立する。

一方、同じchunk Cでも、

request A: Prefix A + C
request B: Prefix B + C

ではCのtokenが見るpast contextが違うため、厳密にはKVも違う。

そのためCを独立に計算したKVをrequest A/Bへそのまま差し込むと、full-prefill stateからずれる。

## Positionだけ直せばよいわけではない

RoPE等のposition encodingはre-position可能なので、一見するとcached chunkを新しいabsolute positionへ移せば十分に見える。

しかし著者らは、単純PICでaccuracyが落ちる主要因として、各independent chunkの先頭に生じる不適切なattention sinkを観察する。

通常の長いsequenceではsink tokenはsequence先頭付近に限られるが、chunkごとに独立prefillすると、各chunk先頭が「局所sequenceの先頭」として振る舞い、複数の偽attention sinkが生まれる。

chunkをconcatした後もこのartifactが残るため、full-context attention patternとずれる。

## PICの基本形

promptを複数chunkに分け、

- immutable / reusable chunks
- dynamic query / instruction chunks

として扱う。

immutable chunkは一度KV計算してcacheへ保存する。

新requestでは必要chunkを取り出し、新しいprompt位置へ配置して再利用する。

これにより、同じdocumentやfew-shot demonstrationが異なるprefix / orderで登場してもcache hitできる。

## KVSplit

EPICの1つ目の重要componentがKVSplit。

固定token数だけで機械的にchunk化するとsemantic boundaryを壊し、chunk内representationや再利用性が悪くなる。

KVSplitはapplicationに応じてchunk boundaryを調整できるcustomizable chunking方式で、semantic coherenceを保つことを重視する。

RAGならdocument / passage、few-shotならdemonstration、multi-document QAならretrieved context unitが自然なchunkになる。

この設計により「再利用単位」と「意味的単位」を一致させやすい。

## AttnLink / LegoLink

EPICの中心がAttnLink、最終版ではLegoLinkとして説明されるlinking mechanism。

目的は、independent chunkをそのままconcatするだけでは生じるattention sink artifactを、full recomputeよりずっと少ない追加計算で補正すること。

考え方は、すべてのtokenを再計算するのではなく、chunk boundaryやsink effectに関係する少数tokenだけを選び、linking用のrecomputationを行う。

これによりchunk同士をLego blockのように組み合わせながら、naive PICよりfull-contextに近いattention behaviorを作る。

## Static Attention Sparsityの利用

EPICは、attentionが全token間でdenseに必要ではないことを利用する。

特にposition-independent reuseで大きく壊れる箇所がsegment beginning周辺に集中するなら、全chunk全tokenを再計算する必要はない。

AttnLinkはこのstatic sparsityを利用し、accuracy recoveryに必要なminimum computationへ絞る。

この点はCacheBlendのdynamic HKVD selectionと似ているが、EPICはよりsystematicなchunk-boundary artifactへ焦点を当てる。

## Runtime Pipeline

概念的なrequest処理は次のようになる。

1. promptをreusable chunk単位へ分割
2. cache hit chunkのKVを取得
3. request内の新しいpositionへ再配置
4. AttnLink/LegoLinkでboundaryを補正
5. dynamic部分だけ通常prefill
6. generation開始

prefix cachingと異なり、prompt中間に置かれたcached chunkも利用できる。

## Application Scenario

EPICが特に有効なのは、

- few-shot demonstrationsを複数requestで共有
- RAG documentを異なるqueryで共有
- multi-document QAでdocument orderが変化
- common system / tool descriptionsを異なるprefixで利用

するworkload。

同じimmutable contentが頻繁に再登場するほどbenefitが大きい。

## Experiment Setup

few-shot learning、multi-document QA、RAG等を含む複数scenarioで評価する。

比較対象は、

- full prefill
- prefix-based caching
- naive PIC
- prior position-independent / modular cache reuse
- EPIC

。

評価指標はtask accuracy、TTFT、throughput、追加recomputation cost。

## Main Results: Accuracy

naive position-independent concatenationではaccuracy degradationが生じるが、AttnLink/LegoLinkを加えることでfull computationに近いaccuracyまで回復する。

論文はnegligible or no accuracy lossを主要結果として報告する。

特に重要なのは、full-context全tokenを再計算するのではなく、少量のlinking computeでこのqualityを得ること。

## Main Results: TTFT

既存systemに対して最大約8×のTTFT improvementを報告する。

prefix cacheではhitしないchunkまでreuseできるため、RAGやfew-shotのようにprompt構造が毎回変わるworkloadでreuse opportunityが増える。

## Main Results: Throughput

serving throughputは最大約7×向上。

reused chunkのprefill computeを減らし、GPUをgenerationや別requestへ回せるためsystem-level throughputが改善する。

## KVSplitの意味

EPICではcache hit率だけを最大化すればよいわけではない。

chunkを細かくしすぎるとreuse flexibilityは上がるが、boundaryが増えattention sink correctionも増える。

大きくしすぎるとsemantic coherenceは高いがcache match flexibilityが減る。

したがってchunk granularityは、

- reuse frequency
- semantic boundary
- linking overhead
- cache storage

のtrade-off。

KVSplitはこの問題を明示的に扱う。

## CacheBlendとの違い

[CacheBlend](2024-2405.16444-cacheblend.md)は、cached KVとfull-context KVの差が大きいtokenをdynamicに選び、selective recomputationする。

EPICはposition-independent caching時に繰り返し現れるattention sink artifactへ注目し、より構造化されたlinkingを行う。

整理すると、

- CacheBlend: token-wise deviation driven repair
- EPIC: chunk-boundary / attention-sink driven repair

。

両者ともmodelをfine-tuneせずruntime側で補正する。

## Block-Attentionとの違い

[Block-Attention](2024-2409.15355-block-attention.md)は、chunk同士をattentionしない挙動そのものをfine-tuningでmodelへ学習させる。

EPICは既存modelを維持し、PIC artifactをruntime linkingで補う。

そのためEPICはdrop-in compatibilityが高い一方、Block-Attentionはtraining adaptationを必要とする代わりにruntime repairを小さくできる。

## Prefix Cachingとの違い

prefix cacheはexactでlosslessだが、cache hit条件が厳しい。

EPICはapproximate / repaired reuseを許すことで、prompt中の任意位置でcacheを再利用する。

つまり、

prefix caching = correctness first, reuse opportunity limited

EPIC = broader reuse opportunity + small repair

という違い。

## Limitations

- arbitrary chunk compositionでfull-prefill内部stateと厳密一致するわけではない。
- attention sink以外のstrong cross-chunk dependencyがtask上重要な場合、軽量linkingだけでは不足する可能性がある。
- chunk granularityがsystem performanceへ大きく影響する。
- cache storage / lookup / transfer costはreuse率とhardware hierarchyに依存する。
- model architectureやposition encodingが変わるとlinking designの再検証が必要。

## KV-cache taxonomyでの位置づけ

EPICはmodular / position-independent reuse。

reuseカテゴリでは、prefix-only cacheを超えて「同じcontentをどこに置いてもreuseできるようにする」系統の代表。

CacheBlendのselective repairとBlock-Attentionのtraining-adapted reuseの中間に位置する。

## 研究上の重要な示唆

EPICの重要な観察は、position-independent reuseのquality lossが単なるRoPE position mismatchだけではなく、independent encodingが作るattention structureのartifactに由来すること。

特に各chunk先頭がattention sink化するという現象を特定したことで、full recomputationではなくtargeted repairへ問題を落とし込めた。

また、cache reuseのsystem designでは「何をcacheするか」だけでなく「どの単位でchunk化するか」が重要な第一級parameterになる。

## まとめ

EPICは、

1. exact prefixに依存しないPosition-Independent Cachingを導入
2. KVSplitでsemanticに自然なcache chunkを作成
3. cached chunkを任意位置へ再配置
4. AttnLink/LegoLinkでsegment beginningのattention sink artifactを少量recompute
5. full-prefillに近いqualityを維持

する。

few-shot・multi-document QA・RAGでcache hit機会を大きく増やし、最大8×のTTFT、7×のthroughput improvementを報告する。KV reuseにおける「positionを直すだけでは足りず、attention structureを補正する必要がある」ことを明確に示した研究。
