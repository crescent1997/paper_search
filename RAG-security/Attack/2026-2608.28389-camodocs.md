# CamoDocs: A Poisoning Attack Against Retrieval-Augmented Language Models Using Camouflaged Documents

> queryをpoison documentへ直接埋め込む既存RAG poisoningのdetectable artifactを除去し、poison embeddingsを分散させながらattacker target answerを維持するcamouflaged poisoning attack。

## 概要

[PoisonedRAG](2024-2402.07867-poisonedrag.md)以降のknowledge poisoningでは、target queryをpoison documentへ含めることでretrieval probabilityを高める設計が多い。しかしこれはquery-document lexical overlapを不自然に高くし、複数poisonsもembedding spaceでclusterしやすい。Query Detectionやclustering-based defenseはこのartifactを利用できる。

CamoDocsは、**queryをdocumentへ直接含めず、benign-looking textをcamouflageとして使い、poison embeddings自体を分散**させる。攻撃payloadとdefense evasionを異なるchunksへ分担させる点が中心的な設計である。

## 問題設定 / Threat Model

attackerはRAG corpusへ少数のdocumentsをwrite / injectでき、target queryに対してattacker-chosen answerを生成させたい。generator weightsを変更する必要はない。

optimizationにはsurrogate retrieverとしてANCEを利用するが、作成したpoisonsはContriever、Qwen3 embedding、closed-source embeddingへもtransferするか評価される。

## 先行研究からの改善点

PoisonedRAG型attackはretrieval successを優先する結果、query inclusionやpoison clusteringという検出可能な痕跡を残す。

CamoDocsは「retrievalされるpoisonを作る」だけでなく、**Defenseが利用しているpoison geometryそのものを崩す**方向へattackを拡張する。

これは[SilentRetrieval](2026-2605.28074-silentretrieval.md)がPPL / fluency artifactを消すのと補完的で、CamoDocsは主にquery overlap / embedding cluster artifactを狙う。

## Method

### Draft Synthesis

synthesizer LLMを用い、queryとcorrect answerからbenign drafts、query・correct answer・target answerからadversarial draftsを生成する。

両方をchunksへ分割し、benign/adversarial chunk pairsを作る。

### Payload / Camouflage Separation

adversarial chunksはtarget answerへの誘導能力を保つため基本的に固定する。一方、benign chunksをembedding-space camouflage用にoptimizationする。

この分離によりpayload semanticsを壊さず、document全体のretrieval geometryだけを変えられる。

### Dispersion Token Optimization

benign chunk中のtoken positionsを選び、surrogate ANCE encoder上でpoison embeddingsがcentroidから離れるようreplacement tokensを探索する。

単純なdistance maximizationはgibberishを生むため、候補tokensをcoherence / perplexityでfilterし、その中からdispersion objectiveが高いものを選ぶ。これを複数positionsへ反復する。

最終的にoptimized benign chunksとadversarial chunksを結合し、自然なdocument appearance、target-answer payload、embedding dispersionを同時に持たせる。

## Experiment Setup

DatasetsはHotpotQA / Natural Questions / MS-MARCO。Victim generatorsはQwen3-8B、Llama-3.1-8B、Mixtral-8x7Bを中心に、GPT-5.4-mini / Claude-Haiku-4.5も評価する。

default retrieverはContriever。transferではQwen3 embedding、text-embedding-ada-002等も利用する。

比較AttackはPoisonedRAG、PIA、CorruptRAG。DefenseはQuery Detection、Divide-and-Vote、RobustRAG、Isolation Forest、LLM Filter、reranking、TrustRAGなど7種類。

## Main Results

Query Detectionで既存poisoning attacksが大きく抑えられるsettingでも、CamoDocsは条件に応じて**ASR 26–78%**を維持する。

Llama-3.1-8B / HotpotQAでは7 defenses平均 **60.81% ASR**、Mixtralでは **62.57%**。proprietary victimでも平均ASRはGPT-5.4-mini **61.80%**、Claude-Haiku-4.5 **55.09%**。

### Retriever Transfer

ANCE surrogateで生成したpoisonsを別retrieverへ移すHotpotQA + Llama-3.1-8Bでは、7-defense平均ASRがContriever **60.81%**、Qwen3-emb-0.6B **51.24%**、text-embedding-ada-002 **41.04%**。

closed-source embedding + TrustRAGでも **20.90%**残り、完全なtarget-retriever white-box accessを必要としない。

## Defense / Utility Analysis

TrustRAGはCamoDocsを比較的強く抑える一方、retrieval依存度の高いNeoQAではclean RAG accuracy 29.13に対し、attackなしでもretrieved documentsの **91.48%**をeraseしaccuracy **5.79**まで低下する。

したがってaggressive filteringは「LLMがparametric knowledgeで答えられるbenchmark」では有効でも、RAGが本当に必要なprivate / long-tail knowledgeではutility costが大きくなり得る。

## RAG Security Taxonomyでの位置づけ

```
PoisonedRAG
  ↓
defenses exploit query inclusion / poison clustering
  ↓
CamoDocs
  ├─ payload / camouflage separation
  ├─ embedding dispersion
  └─ coherence-constrained token optimization
```

本論文はconfidentiality extractionではなくRAG integrityへのknowledge poisoning。ただしDefense-aware adaptive attackとして、今後のrobust RAG評価で重要な位置を占める。

## Limitations

corpusへのwrite accessが必要。optimizationではsurrogate encoderを利用し、retriever transferは完全ではない。

dispersionを強めるほどreadability / coherenceとのtrade-offが生じる。またTrustRAGのようなaggressive context erasureには依然かなり抑えられる。

## 実装・研究上の示唆

poison defenseをquery overlapやembedding clusterだけで評価すると、attackerがそのartifactをoptimization objectiveへ入れた時点で脆弱になる。

Defenseは単一のgeometric signatureではなく、content consistency、provenance、retrieval behavior、generation influenceなど独立signalを組み合わせる必要がある。
