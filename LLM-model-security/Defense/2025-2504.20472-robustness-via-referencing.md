# Robustness via Referencing: Defending against Prompt Injection Attacks by Referencing the Executed Instruction

## 概要

従来のprompt-injection defenseは、modelがuntrusted data内のinstructionを**実行しない**ようSFT/DPOやsystem promptで抑制する。本論文は別の性質に注目する。modelがmalicious instructionに従ってしまう場合でも、**「今どのinstructionを実行しているか」自体は正しく参照できることがある**。そこで回答にinstruction provenance tagを強制し、original trusted instructionに対応する部分だけを後処理で採用する。

これは**model weightsを変更しないtraining-free inference-time defense**である。ただしsource provenanceをLLMの出力したtagに依存させ、外部filterで実行するため、model-intrinsicなInstruction Hierarchyの実装ではなく**prompting + runtime filtering**として分類する。

## Problem Setting / Threat Model

original instruction $I_{ori}$ はsystem/developer側またはtrusted application instruction。attackerはdirect settingのuntrusted user-supplied dataや、indirect settingのretrieved document/tool contentへ $I_{inj}$ を埋め込めるが、trusted instructionやmodel weightsは変更できない。

static prompt-engineering attacksについてはtarget model / defense strategyをattackerが知らない想定。gradient-based GCG / AutoDANではtarget modelのgradient accessを仮定する。adaptive defense-aware attackerがruntime tagを観測・模倣できるsettingは別扱いとなる。

## Method / Algorithm

### 1. Tagging and Splitting

trusted original instructionを最初のlineに置き、untrusted dataを最大$K$語ごとに分割する。各lineに `[L 1]`, `[L 2]`, ... のtagを付与し、original instructionは `[L 1]` とする。instructionとdataはさらに`<Instruction Area>` / `<Data Area>`で区切る。

### 2. Instruction-reference generation

modelに各instructionについて `(tag, instruction, answer)` 形式で出力させ、回答の末尾には`[end]`を付ける。論文は**2件のin-context examples**を入れて出力形式の安定性を高める。概念的には

$$R=\{(t_i,I_i,r_i)\}_{i=1}^{N}$$

となる。modelがuntrusted instructionに従ってしまっても、正しいtagを付ければfilterが分離できる。

### 3. Filtering

最終的にtrusted tagと一致するanswerだけを採用する。

$$\widehat R=\{(t_i,I_i,r_i)\in R\mid t_i=t_{ori}\}$$

論文の静的settingでは $t_{ori}=[L\ 1]$。この操作は**malicious instructionをmodel内部で無視させるのではなく、出力後に破棄する**点がStruQ / SecAlignと異なる。

### 4. Dynamic tags

static `[L 1]` をattackerが知れば、malicious answerにもそのtagを付けるようspoofできる。そこでtag vocabularyからinteractionごとにrandomなreference tagを選ぶ緩和策を追加する。ただしこれはsecret tagに依存する確率的対策であり、tag leakageやadaptive attackerへのformal guaranteeではない。

## Experiment Setup

- **Direct:** AlpacaFarm 208 samples。
- **Indirect:** Inj-SQuAD / Inj-TriviaQA 各900 samples（phishing / advertisement / propaganda）。
- **Open models:** Llama3-8B-Instruct、Qwen2-7B-Instruct、Llama3.1-8B-Instruct。
- **Larger models:** Llama3-70B、Llama3.1-405B、Qwen2-72B。
- **Closed models:** GPT-4o-mini、GPT-4o、GPT-4.1。
- **Attack:** Naive、Ignore、Escape、Fake Completion、Combined。別途GCG、AutoDAN。
- **Defense baselines:** Sandwich、Reminder、Instructional、Spotlight、StruQ。
- **Metrics:** injected instructionの答えが最終出力に残るASR、SQuAD/TriviaQA/SST-2 utility accuracy。

## Main Results

**Indirect / Inj-SQuAD / Table 2:** 提案法は全15条件のASRが**0.11%–4.00%**。例えばQwen2-7B-InstructのFake Completion / CombinedはStruQ **78.56% / 82.78%**に対して提案法 **1.78% / 1.44%**。Llama3.1-8BではStruQ **46.22% / 56.00%**に対し **0.22% / 0.22%**。Inj-TriviaQAでも最大ASR 7%。

**Large models / Table 4:** Llama3-70B、Llama3.1-405B、Qwen2-72Bでも大部分のattackでASRが数%以下。

**Gradient attacks / Table 5:** Llama3-8BではGCGに対して**3.85%**（StruQ 2.88%）、AutoDAN **6.25%**（StruQ 5.77%）。**常にStruQより強いわけではない**。Qwen2-7BではGCG **6.25%**（StruQ 10.10%）、AutoDAN **8.65%**（StruQ 14.42%）。

**Utility:** QAでは概ね維持または改善。SST-2 accuracyの平均低下は1.53 pointsと報告し、StruQの平均低下5.77 pointsより小さい。

## Generalization / Robustness / Adaptive Attack

static attack familyとopen/closed modelへ幅広く適用可能。data splittingのwindow sizeの影響は限定的。一方、**2-shot exampleを省くと出力formatの崩れによってutilityが悪化**する。

最大の懸念は**tag spoofing**。論文自身が `[L 1]` を明示するadaptive injectionをfailure modeとして認め、random dynamic tagsで緩和する。ただしadaptive attackerがtagを推定できる・output formatを崩せる・同一tagを付けさせられる条件のsystematic worst-case evaluationは限定的。「adaptive attackは実運用で非現実的」という論文の仮定は、公開API / open-source prompt / agent traceがある現在の環境では強い仮定として読む必要がある。

## StruQ / SecAlign / ISEとの違い

- [StruQ](2024-2402.06363-struq.md)はtrusted instructionを守るmodel behaviorをSFTで学習。
- [SecAlign](2024-2410.05451-secalign.md)はsecure/insecure responseのDPO。
- [ISE](2024-2410.09102-instructional-segment-embedding.md) / [ASIDE](2025-2503.10566-aside.md)はsource roleをmodel内部representationへ反映。
- 本手法はmodelが複数instructionに応答してしまっても**answer provenanceを出力させる**。training-freeだが、model自体がcorrect priorityを実行するわけではない。
- [The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)との関係では、instruction-following能力とinstruction-priority complianceを切り離した設計として位置づけられる。

## GCG / Defense-aware Attackとの関係

[GCG](../Attack/2023-2307.15043-gcg.md)およびAutoDANはwhite-box gradientでprompt injection textを最適化する。提案法はそのようなattackに対しても一定のASR低下を示すが、**tag spoofingを目的関数に含むadaptive GCG**や[The Attacker Moves Second](../Attack/2025-2510.09023-attacker-moves-second.md)型Defense-aware red teamingは十分に検証されていない。[ChatInject](../Attack/2025-2509.22830-chatinject.md)のrole serialization spoofingも別の攻撃面である。

## Limitations

output tagの正しさとformat遵守に依存し、malicious contentがtrusted tagへ混入すればfilterは破れる。line-wise splitが意味境界を壊す可能性、token overhead / latency増加、長文・multi-turn agent・tool authorization未評価、static attack中心の評価、タグ推測に対するsecurity-by-obscurity性がある。system-level output filterなので、**既に実行されたtool actionを取り消せない**。

## LLM Model Security Taxonomy / 実装・研究上の示唆

**Defense → runtime provenance tagging + model-generated attribution + post-generation filtering**。純粋なmodel-level IH learningではないが、instruction attributionをmodelに行わせる方向は重要。実装する場合、(1) tagはtrustworthy wrapper側で付与、(2) JSON schemaなどでformatを強制、(3) original tagをuntrusted dataへ露出させない、(4) tool execution前にauthority check、(5) tag-aware adaptive attacksを評価、が必要。
