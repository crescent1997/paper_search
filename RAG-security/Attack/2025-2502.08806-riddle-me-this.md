# Riddle Me This! Stealthy Membership Inference for Retrieval-Augmented Generation

> target documentの本文を露骨に問い合わせるのではなく、そのdocumentをretrieveできれば答えられる自然な質問を多数生成し、RAGの回答正答性を集約することで、**特定documentがprivate RAG databaseに含まれるか**をblack-boxで推定するInterrogation Attack (IA) を提案する。

## 概要

RAGのprivacy riskはdocument本文の直接extractionだけではない。企業文書、医療記録、研究資料などでは、「あるdocumentがprivate databaseに存在する」というmembership自体がsensitive informationになり得る。

本論文はRAGに対するMembership Inference Attack (MIA)を扱う。既存RAG-MIAはtarget textをqueryへ直接含めたり、masked textを再構成させたりするため、queryが不自然・攻撃的になりやすい。production RAGにquery rewritingやmalicious-query detectionが導入されると、このようなattackは検出・無効化されやすい。

提案する **Interrogation Attack (IA)** は、target documentから通常のinformation-seeking questionに見えるprobeを作り、そのdocumentがretrievedされた場合だけRAGが高い確率で正答できるようにする。複数probeへの回答を統計的に集約してmembershipを推定することで、個々のqueryのstealthinessとattack accuracyを両立する。

## 問題設定 / Threat Model

attackerはmembershipを調べたいtarget document $d^*$ を保持している。目的は、$d^*$ がvictim RAGのretrieval databaseに含まれるかを判定することである。

attackerが利用できるのはblack-box query interfaceのみで、以下は観測できない。

- retrieval database全体
- retrieved document / chunk ID
- retrieval similarity score
- retriever parameter
- generator内部state

一方、attackerはtarget documentそのものを知っている。これは典型的なmembership inference settingであり、例えば漏洩候補のmedical recordやproprietary reportがある組織のRAGへ登録されているかを確認するケースに対応する。

またattackerはprobe作成やground-truth generationのためにauxiliary / shadow LLMを利用できる。

## 先行研究からの改善点

既存RAG membership inferenceには、target documentの一部をqueryへ含めたり、maskした部分をRAGに補完させたり、membershipを直接示唆する質問を行うものがある。これらはmembership signalを強くできる反面、通常ユーザのquery distributionから外れやすい。

また [Follow My Instruction and Spill the Beans](2024-2402.17840-follow-my-instruction-and-spill-the-beans.md) のようなdirect context extractionも、「retrieved contextをそのまま出せ」というmalicious intentがinput/output filterの検出surfaceになる。

IAはattack primitiveを **direct extraction / reconstructionからnatural interrogationへ変更**する。attack query単体にはtarget document本文やprivacy extraction instructionをほとんど露出させず、複数のbenign-looking interactionからmembership signalを積み上げる。

この考え方は後続の [Silent Leaks / IKEA](2025-2505.15420-silent-leaks-ikea.md) とも共通点がある。IKEAはbenign query sequenceを使ってknowledgeそのものを徐々に抽出するのに対し、IAは既知documentの**membership bit**を推定することが目的である。

## Method / Algorithm

IAはtarget documentから、(1) retrieval summary、(2) interrogation probes、(3) ground-truth answersを生成し、それらをvictim RAGへのqueryとmembership scoringに利用する。

### 1. Retrieval Summary

まずtarget document $d^*$ 全体を要約し、documentの主要topicやsemantic contentを表すsummary $s^*$ を生成する。

このsummaryはanswerを直接要求するためではなく、victim retrieverをtarget documentのsemantic neighborhoodへ誘導するためにqueryへ付与される。

単一の細かなquestionだけではretrieverがtarget documentをtop-kへ入れない可能性があるが、document-level summaryをprefix/contextとして含めることでretrieval probabilityを高める。

### 2. Interrogation Probe Generation

auxiliary LLMにtarget documentを読ませ、そのdocumentに基づいて答えられる自然なyes/no question $p_i$ を複数生成する。

probeは、target documentがretrievedされればgeneratorが高い確率で正答できる一方、documentがdatabaseに存在しなければparametric knowledgeだけでは答えにくい内容を狙う。

victimへ送るqueryは概念的に

$$q_i=s^*\Vert p_i$$

となる。

重要なのは、queryが「この文書はdatabaseにありますか」「次のmissing textを補完してください」のようなmembership attack特有の形式を取らないことである。個々のqueryは通常のquestion answering requestに近い。

### 3. Ground-Truth Generation

shadow / auxiliary LLMへtarget documentそのものを与え、各probe $p_i$ に対するground-truth answer $g_i$ を作る。

victim RAGから得られたresponse $r_i$ が $g_i$ と一致するかを評価する。yes/noの一致に加え、RAGが「わからない」「情報がない」と答えるUNK responseにはnegative evidenceとしてpenaltyを与える。

### 4. Membership Score Aggregation

単一queryの回答だけでは偶然の正答やgeneratorのparametric knowledgeによるfalse positiveが起こるため、複数probeのscoreをaggregateする。

多くの質問でtarget-document-derived ground truthと一致する場合、target documentがretrieval databaseに存在する可能性が高いと判定する。

論文ではdefaultで約30 queryを利用するが、query数とattack accuracy / costのtrade-offも評価する。

## Experiment Setup

主なdatasetは以下である。

- **NFCorpus**
- **TREC-COVID**
- **SCIDOCS**

retrieverとしてGTE、BGE系dense retrieverを用い、generatorにはPhi-4、Llama 3.1、Command-R、Gemma-2等の複数modelを組み合わせる。

実運用を意識して、ユーザqueryをそのままretrievalへ渡さずLLM等で書き換える **query rewriting** を有効にしたsettingも評価する。

比較対象には既存RAG membership inference attackであるRAG-MIA、S²MIA、MBA等が含まれる。

主要metricは、

- ROC-AUC
- Accuracy
- TPR@low FPR（特にTPR@1% FPR）
- malicious-query detectorによる検出率
- query budget / API cost

である。

privacy attackではfalse positiveを低く保つことが重要である。例えば大量の候補documentについてmembershipを調査する場合、FPRが高いattackは実用性が低いため、TPR@1%FPRが重要な指標になる。

## Main Results

NFCorpus + GTE retriever + Phi-4 generatorの代表settingでは、IAは **AUC 0.992、accuracy 0.945、TPR@1%FPR 0.897** を達成する。

同条件で既存attackのlow-FPR性能は大幅に低く、S²MIAのTPR@1%FPRは約0.208、MBAは約0.265である。つまりIAの利点は平均的なclassification accuracyだけでなく、**false positiveを厳しく抑えた領域でも高いmembership detection rateを維持すること**にある。

複数dataset、retriever、generatorへ変更しても優位性が概ね維持され、特定RAG configurationだけへのoverfitではないことを示す。

## Stealthiness / Defense Evaluation

本論文で特に重要なのがstealthiness評価である。

IA queryはtarget document本文を直接要求せず通常のQA queryに近いため、LakeraGuardでmaliciousと判定されるqueryは約 **5%**、GPT-4oを用いたclassifierでは約 **1.2%** に留まるsettingが報告される。

一方、既存membership attackはquery construction自体にattack intentが現れるため、条件によって非常に高い割合で検出される。論文では既存attackがIAより最大約76倍検出されやすいと整理されている。

さらにquery rewritingを導入したRAGでもIAは比較的robustである。自然なsemantic questionとして作られているため、rewriterが表面形式を変えてもtarget documentをretrieveさせるsemantic intentが残りやすい。

これはRAG securityにおいて、単純なprompt-injection detectorやmalicious-string filterだけではmembership leakageを防げないことを示す。

## Query Budget / Cost

probe数を増やすほどmembership evidenceを集約できるため性能は向上するが、30 query前後から改善は徐々に小さくなる。

一部settingでは5 questions程度でも既存baselineを上回る。したがってattackerはcostやrate limitに応じてquery budgetを調整できる。

論文で報告されるAPI costはtarget document 1件あたり **$0.02未満**であり、多数candidate documentへのmembership auditing / attackも現実的なcostで実施可能である。

## Failure Modes / Robustness

false positiveの重要な原因は、target documentそのものがdatabaseになくても、非常によく似たdocumentが登録されている場合である。この場合、target-specific probeへRAGが正答でき、memberと誤判定する可能性がある。

もう1つはgenerator自身のparametric knowledgeである。target documentがdatabaseになくてもLLMが同じfactをtraining dataから知っていれば、membership signalとparametric knowledgeを区別しにくい。

false negativeは、target documentがdatabaseに存在していてもretrieverがqueryに対してそのdocumentをtop-kへ入れられない場合に起こる。

またretrieval $k$ を増やせば常にattackが強くなるわけではなく、多数のirrelevant contextがgeneratorへ混入するとtarget document由来signalが薄まる場合がある。

## Limitations / 成立条件

IAはtarget documentをattackerが既に保持していることを前提とするため、未知corpusをゼロからreconstructするknowledge-base stealing attackではない。

またmembershipとsemantic-equivalent documentの存在を厳密に分離することは難しい。特にduplicate / near-duplicate corpusではdocument-level membershipの定義そのものに注意が必要である。

parametric knowledgeの強いgeneratorではnon-memberでも正答しやすくなり、attack accuracyが低下する可能性がある。

rate limitingやper-user query historyを用いたsequence-level anomaly detectionは、個々のquery detectorより有効な防御になる可能性があるが、benign userのmulti-turn research behaviorとの区別が課題となる。

## RAG Security Taxonomyでの位置づけ

本論文は **Attack / confidentiality / membership inference / retrieval-database privacy** に位置づけられる。

直接的なcorpus extractionより漏れるinformation量は小さいが、「ある人物のmedical recordが存在する」「あるproprietary documentを企業が保有している」といったmembership bit自体がsensitiveな場合には重大なriskとなる。

RAG extraction attackの系譜として見ると、

```text
direct context extraction
  ↓
masked/reconstruction-based membership inference
  ↓
natural interrogationによるstealthy membership inference
```

という改善であり、access requirementを増やすのではなく、**maliciousnessのobservable surfaceを減らす**方向の発展である。

## 実装・研究上の示唆

RAG privacy defenseでは、prompt injectionや「contextを表示して」といった露骨なattackだけを検出しても不十分である。自然な質問を複数回行うだけでretrieval membershipが統計的に漏れる可能性がある。

したがって防御側では、

- retrieval confidenceやanswer confidenceを過度に外部へ反映しない
- user/session単位でsemantic probe sequenceを監視する
- sensitive corpusではretrieval結果に応じた回答差を抑える
- membership privacyを独立metricとして評価する

といった対策が必要になる。
