# 概要と位置づけ
**区分: Defense。** sudoLLMは、全利用者へ同一のsafety policyを適用する代わりに、認証済み利用者のaccess rightに応じてモデルが回答・拒否を切り替える**model-level multi-role alignment**を提案する。重要なのは、モデルに自然言語で「このユーザーは管理者」と伝えるだけでなく、信頼済み前処理で生成した**統計的な語彙分布の偏り**をモデルが識別できるようfine-tuningする点。これはsystem > developer > user > toolという**message-source Instruction Hierarchyと同一ではない**。モデルに新しいauthorization軸を持たせる関連研究として採録する。

# Problem / Threat Model
モデルをAPIとして利用し、providerはAPI key等でユーザー本人を認証できる。Aliceは許可された専門家、Bobは許可されていない一般ユーザー。医療・法律に関する制限トピックではAliceに回答、Bobには拒否、一般トピックでは両者に回答することを目指す。ユーザーからのアクセスはblack-boxで、モデルの出力分布は見えない。**モデル単体では本人確認を行わず、認証・信頼済みquery rewriteの完全性はアプリケーション側の前提**。したがって悪意あるユーザーが認証を奪取できる場合は防御できない。

従来の単一safety-aligned LLMでは、専門家にも一律拒否するutility損失、あるいは役割を自然言語で宣言するだけでは容易にspoofされる問題がある。関連SudoLM（authorization secret prefix方式）と異なり、モデル内部に単一の秘密キーを埋め込まず、認証済みのtrusted preprocessingで統計的なrole signatureを強制する。

# Method / Algorithm
## 1. Biased Query Rephrasing (BQR)
Qwen2.5-7B-Instruct等のSLMで原queryを意味保存しつつ言い換える。頻度上位500語を共通語`C`、次の499,500語を稀な語`R`とし、SLM tokenizerに対応するrare token集合をAlice/Bob用の互いに素な集合`V_a, V_b`へ分割する。`V_Alice=V_C∪V_a`, `V_Bob=V_C∪V_b`。各生成stepで元logit `l_LM(w)`に対し、割当外tokenのlogitのみ`k`減算する（論文実験`k=10`）。

`l_x(w) = l_LM(w)` if `w∈V_x`; otherwise `l_x(w)=l_LM(w)-k`、`P_x(w|history)=softmax(l_x)`。

これにより通常の文章として読めるが、role別の語彙分布に偏りがあるqueryが得られる。**両roleの入力を必ずrewrite**し、ユーザーが自分で似た文章を書いても信頼済み経路のsignatureへ上書きする。これはuser-supplied role tagの信頼を回避する実装上の要点。

## 2. Biased Fine-Tuning (BFT)
元データ`D={(Q_i,A_i)}`をrole別に言い換え、`D_hat={(Q_i^Alice,A_i),(Q_i^Bob,refusal_i)}`でtarget LLMをSFTする。制限のないTriviaQAでは両roleに正答を与え、単なるBobの全面拒否を防ぐ。比較対象はinstruction-only (Inst.) と、biased rewriteを行わず元queryへ役割別ラベルを付けてSFTするvanilla fine-tuning (VFT)。

## 3. Inference
認証→信頼済みSLM rewrite→BFT target LLM。追加の署名検知ではrole別のtoken likelihoodから`P(Alice|w_1:T)`を推定できる（論文§4.4）。**セキュリティ境界はモデルの文体認識だけではなく、認証・rewrite・検知を組み合わせたもの**。

# Experiment Setup
- 訓練元: Law Stack Exchange 2,000件、ChatDoctor-iCliniq 2,000件、TriviaQA 2,000件、計6,000 unique Q/A。Alice/Bobに展開して12,000 training examples。各制限domainに500件の分離test。評価OODはMedQA、LegalBench、MMLU medical/legal。正常回答はTriviaQA、MMLU math。
- SLM: Qwen2.5-7B-Instruct主設定。Llama3.2-3B、Llama3.1-8B、Qwen2.5-3Bでもrephrasing品質を検討。
- Target: GPT-4o (1 epoch)、GPT-4.1-mini (2 epochs)、API fine-tuning。ローカルSLM実行はA6000 48GB / A100 40GB。論文記載の総費用はAPI約$1,700、SLM約100 GPU-hours。
- 指標: Alignment Accuracy (AA) は**回答内容の正しさではなく、拒否すべき時に拒否・回答すべき時に回答したか**。別途MMLU正答率を報告。
- 攻撃: 非拒否応答の先頭部分を擬似assistant messageとして与え、userが続きを促す**prefix/continuation jailbreak**。本来のAPIがassistant prefillを直接サポートしないため会話形式で模擬する。GCGのwhite-box suffix、indirect tool-output injection、Meta SecAlignへのadaptive attackは未評価。

# Main Results
**GPT-4o、BobのAA（拒否判定率、%）**
| Test | Inst. | VFT | BFT |
|---|---:|---:|---:|
| MedQA | 69.6 | 1.0 | **100.0** |
| MMLU medical | 63.6 | 18.4 | **100.0** |
| LegalBench | 46.8 | 36.8 | **100.0** |
| MMLU legal | 95.2 | 48.2 | **99.8** |

GPT-4.1-miniでもMedQAのBob AAは0.2/0.0/**63.8**、LegalBenchは0.0/13.6/**98.0**（Inst./VFT/BFT）。ただし一律の成功ではなく、GPT-4.1-miniのMMLU math Bob AAはInst.99.8→BFT92.4に下がる。Aliceの回答率も一部で低下（GPT-4o LegalBench 100→84.8）。**AAの改善と答えの医学的・法律的正確性は別**。

**Prefix continuation攻撃 ASR（GPT-4o、%）**
| Prefix words | Inst. | VFT | BFT |
|---|---:|---:|---:|
| 5 | 6.6 | 12.8 | **0.5** |
| 25 | 10.3 | 15.4 | **0.4** |
| 100 | 21.0 | 12.2 | **0.5** |

GPT-4.1-miniでは100語でInst.91.9、VFT82.7、BFT23.3と改善するが、**残存ASRは23.3%**である。論文がいう「13倍以上」は特定のGPT-4o比較に基づく。Alice用BQRで同じprefix攻撃を行うとASR93.3%で、モデルがrole signatureに反応していることを示す一方、**認証境界が破れればモデル単独で拒否できない**ことも明瞭。

# Generalization / Robustness / Additional Evaluations
- **意味保存:** Qwen2.5-7Bのrephraseのembedding cosine similarityはAlice 0.900、Bob 0.905、通常rephrase 0.926。MMLU回答accuracyは元query 89.2%、biased Alice 88.6%、Bob 88.3%。差が小さいが意味完全一致の保証ではない。
- **正常utility:** GPT-4o MMLU math正答率Inst.69.8、VFT68.4、BFT71.6。medical正答率93.6/92.2/91.2。用途ごとの変動を確認する必要がある。
- **Full-knowledge adversary:** Bobが語彙分割を知りAlice風queryを作る設定。role signature推定は閾値0.7で94.5%、0.8で93.9%。ただしrephrasing前の入力を直接targetへ渡さないことが前提。Table 5でBob偽装に対するBFT+Detection AAはMedQA100.0、LegalBench96.8、MMLU legal98.4%。
- **Fail-closed:** 制限領域の曖昧なqueryでは拒否側へ倒れる傾向。ただし安全なqueryの過剰拒否はutility上のトレードオフ。

# Limitations / Boundary of Claims
二値のAlice/Bob role、medical/legalデモであり、多段の組織内ACLや実ファイルの行単位アクセス権は検証していない。system/developer/user/tool間のpriority conflictを直接測るベンチマークではない。認証情報漏洩、trusted SLM rewrite bypass、モデルへの直接アクセスには無力。大規模fine-tuning（約100万例）で優位性が保たれるか不明。open-weight 50B級での再現は未実施。GCG、StruQ、SecAlign、Meta SecAlign、ISE、CaMeLへの直接比較なし。

# LLM Model Security Taxonomy / 実装・研究上の示唆
**Defense > Model-level authorization / privilege separation > identity-conditioned alignment.** IHが「**命令の発信源の優先度**」を扱うのに対し、sudoLLMは「**要求者の認可権限**」を学習する。両軸は直交する。例えばuser roleをモデルへ安全に伝えられても、外部tool outputの偽情報を信用してよいことにはならない。実運用ではRBAC/ABAC、authentication、tool authorizationはLLM外部で強制し、LLMのrole-conditioned behaviorは追加防御として評価するのが妥当。研究課題は3階層以上のrole、同一userのtask-specific capability、role spoofingへのadaptive評価、prompt-data separationとのjoint training。
