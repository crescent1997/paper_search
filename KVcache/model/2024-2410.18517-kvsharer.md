# KVSharer: Efficient Inference via Layer-Wise Dissimilar KV Cache Sharing

## 概要
KVSharerは、pretrained Transformerの全layerで独立K/Vを生成・保存する必要があるのかを問い、複数layerでKV cacheを共有する。GQA/MQAがhead axisを削減するのに対し、KVSharerは**layer axis**でcache generation/storageを減らす。

名前の似た[KVShare](../reuse/2025-2503.16525-kvshare.md)はcross-request semantic/multi-tenant reuseであり、KVSharerとは別系統。

## 問題設定
decoder-only Transformerではtoken数に比例して各layerのK/Vを保存するため、long contextとbatch sizeの増加でKV memoryが支配的になる。[Cross-Layer Attention](2024-2405.12981-cross-layer-attention.md)のようにarchitectureを最初からcross-layer sharing前提で設計する方法に対し、KVSharerはpretrained modelへsharing strategyを導入することを狙う。

## Dissimilar KV sharing
直感的には似たKV representationを持つlayer同士をshareすべきに見えるが、著者らはlayer間のKV similarityとsharing後performanceを調べ、**dissimilarなKV cacheを持つlayer間のsharingが有効になり得る**ことを観察する。

このempirical signalを使ってsharing pair / mapを探索し、一部layerでは独自KV cacheを作らず指定layerのcacheを利用する。

## Inference integration
公式実装では保存するlayerだけを持つDynamicDictCacheを導入し、modelへkv_cache_share_layers_mapを渡してsharing strategyを指定する。LlamaとInternLM2向け実装が公開されている。citeturn0search2

```text
layer 0 → own KV
layer 1 → own KV
layer 2 → reuse another layer KV
layer 3 → own KV
...
```

sharing layerではK/V projection/cache generationとcache storageを削減できる。

## GQA / CLAとの差
| Method | sharing axis | 適用 |
|---|---|---|
| [GQA](2023-2305.13245-gqa.md) | query heads間でK/V head共有 | uptraining / architecture |
| [Cross-Layer Attention](2024-2405.12981-cross-layer-attention.md) | adjacent layers | architecture/training |
| KVSharer | selected layers | pretrained modelへのsharing strategy |

CLAが規則的なcross-layer sharing architectureを設計するのに対し、KVSharerは既存modelのlayer redundancyを利用する。

## Compression系との併用
KVSharerは「cacheを持つlayer数」を減らすため、各保持layer内部のtoken evictionとは直交する。[H₂O](../compress/2023-2306.14048-h2o.md)等と併用でき、layer-axis reduction × token-axis compressionとして組み合わせられる。

## Experiment Setup
Llama / InternLM2系pretrained modelsでsharing strategyを探索し、language modeling / downstream evaluationとinference efficiencyを測定。baseline modelおよび既存KV reductionとのperformance-memory trade-offを比較する。

## Main Results
KV cache computationを約30%削減しつつ大きなquality degradationを避け、generationを少なくとも約1.3×高速化すると報告する。token-level compressionと組み合わせることで追加memory reductionも可能。

## Ablation / Analysis
layer similarityとsharing qualityの関係を比較し、単純に最類似layerをshareする戦略が最適とは限らないことを示す。sharing layer数を増やすほどKV reductionは大きくなる一方、quality degradationも増えるためstrategy selectionが重要。

## Limitations
- optimal sharing mapの探索がmodel依存。
- arbitrary pretrained modelで同じdissimilarity heuristicが最適とは限らない。
- irregular layer sharingはstandard attention/runtimeへ実装変更が必要。
- architecture-levelにtrainingされたCLA等と比べ、sharing耐性を学習しているわけではない。
- publication statusはarXiv上のreview表記で、主要venue採択としては扱わない。

## KV-cache taxonomyでの位置づけ
**model / cross-layer KV sharing / pretrained-model adaptation / structural cache reduction**。
