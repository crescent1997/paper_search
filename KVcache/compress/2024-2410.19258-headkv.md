# 概要

**HeadKV**は、固定した総KV token budgetを**layerをまたいで個々のattention headに割り当てる**compression frameworkである。単に各headでTop-K tokenを取るのではなく、headの重要度をあらかじめ測り、重要headにより多くのKVを配分する。**HeadKV-R2**は、retrievalだけでなくcontextual reasoningを必要とするsynthetic taskからhead importanceを推定する派生である。

[SnapKV](2024-snapkv.md)や[PyramidKV](2024-2406.02069-pyramidkv.md)のattention-based token選択を土台としつつ、**budget配分の粒度**をlayerからheadへ移した点が核心。カテゴリは`compress`。KVの再利用・recomputeではなく、prefill済みのKVをどれだけ保持するかを最適化する。

## 問題設定と既存法の問題

長いpromptのKV cacheを圧縮するとき、すべてのheadが同程度に重要とは限らない。PyramidKVはlayerごとに非均一budgetを配るが、同一layer内のheadには共通budgetが残る。[Ada-KV](2024-2407.11550-adakv.md)はhead budgetを調整するものの、**layerごとの総量が固定**される。実際には重要headが特定layerに偏る可能性があり、layer境界で予算を固定すると無駄が生じる。

さらにretrieval headの特定だけでは、long-context QAに必要な「複数の事実を検索して関係を推論する」能力を測りきれない。既存のRetrieval Heads scoreは、正答tokenへのattention最大値の厳密な一致を重視するため、約70%のheadのscoreが0となるほどsparseになる（Section 3.1）。これをそのまま予算配分に使うと、reasoningに有効なheadを過小評価する。

## 手法

### 1. Head importanceの推定: HeadKV-RとHeadKV-R2

**HeadKV-R**は従来のretrieval-head distributionを利用する。Needle-in-a-Haystackで、正解文字列にattentionを向けたheadを重要とみなす。一方**HeadKV-R2**は、年齢比較など**推論を経て正答候補を選ぶ**retrieval-reasoning needleを構成する。例えば人物2名の属性をcontextに埋め込み、年齢が若い方の好みを回答させる。正しい答えの全tokenに対するattention重みを集計することで、単一のargmax位置だけを見る指標より密なhead importance分布を得る（Eq. 2）。

重要度`S_h`はheadごとに計算して全headでL1 normalizeする。**ここでのimportance推定は評価用synthetic例に基づく事前のcalibration**であり、各本番requestのqueryを入力して毎回head importanceを再学習する方式ではない。HeadKV-RとHeadKV-R2はbudget配分に使うimportance distributionが異なる。

### 2. Global head-wise budget allocation

各headに均等に与える初期budgetを`b`、layer数を`L`、head数を`H`、pool比率を制御する係数を`β`とする。各headに基本枠`b - b/β`を残し、回収したglobal pool `B = (b/β) × L × H`をimportance `S_h`に比例配分する。

`b_h = (b - b/β) + S_h B`（Section 3.2, Eq. 4）。

この式の意味は、**global budgetの合計を一定に保ちながら、layerの境界を越えて重要headへ移す**ことである。`β`が小さいほどshared poolが大きくなり、importance scoreの影響が強まる。極端に重要度が低いheadにも基本枠を残すため、完全なhead削除ではない。

### 3. Head内のtoken selection

Budgetを決めた後、各headで残すtokenを選ぶ操作にはSnapKV型のattention selectionを使用する。末尾`α=8`のinstruction / observation windowを保護し、そこから過去tokenへのattention scoreを用いてTop-Kを選択する。つまり**head importanceは「何個残すか」**、**observation-window attentionは「どのtokenを残すか」**を決める別の信号である。

## Experiment Setup

- **Models**: Llama-3-8B-Instruct、Mistral-7B-Instruct。
- **Benchmarks**: LongBench（Single-Doc QA、Multi-Doc QA）、LooGLE（Long Dependency QA）、Needle-in-a-Haystack、Reasoning-in-a-Haystack。
- **Baselines**: FullKV、SnapKV、PyramidKV、Ada-SnapKV。比較では保持するKV entry数を揃える。
- **Budgets**: 主要表ではKV size=128 / 1024（各headの初期budgetに対応する実験設定）。`α=8`、`β∈{1.005,1.01,1.1,1.2,1.5,2,5,10}`から平均スコアに基づき選定。
- **Performance**: 32K入力とgeneration長1〜4096でdecode latency / peak memoryを比較。論文のlatency figureにはprefill時間も含まれるため、decode kernelだけの速度ではない。

## Main Results

**LongBench, Llama-3-8B-Instruct**（Table 1）: FullKVの6 QA平均は32.90。KV size=128ではSnapKV 26.43、PyramidKV 26.20、Ada-SnapKV 28.52に対して**HeadKV-R 30.38、HeadKV-R2 32.00**。KV size=1024ではHeadKV-R2 32.95でFullKV 32.90とほぼ同等。HeadKV-R2のLooGLE平均はsize=128で7.16、FullKVは7.01だが、タスク別に改善・悪化がある。

**LongBench, Mistral-7B-Instruct**（Table 1）: size=128の6 QA平均はSnapKV 26.65、Ada-SnapKV 28.09、HeadKV-R 31.01、**HeadKV-R2 31.41**、FullKV 32.98。size=1024ではHeadKV-R2 32.87でfullに近い。極端な圧縮設定ほどglobal head-wise allocationの効果が大きい。

**Needle-in-a-Haystack**（Figure 5）: Llama-3-8B、size=128ではFullKV 100.0、SnapKV 87.4、PyramidKV 97.3、HeadKV-R 98.1、HeadKV-R2 98.2。**「1.5%のKVでfull性能の97%」というabstractの表現は特定のcontextual QA条件での主張**であり、全ベンチマークで97%保証するわけではない。

**Memory / latency**（Figure 6）: 他の圧縮baselineと同程度のdecode latencyを保ちながら、full KVよりpeak memoryを大幅削減したと報告。head-wise allocationによる**追加のend-to-end高速化は主張の中心ではない**。実装の並列化効率は別途評価が必要。

## 主要ablation

1. **Head importanceの定義**（Table 2）: Llama-3-8B、size=128でHeadKV-R（従来retrieval score）30.38、HeadKV-ER（同じretrieval例でscoreだけ改良）31.04、HeadKV-R2（reasoning例も導入）32.00。Mistralでは31.01→31.02→31.41。したがって、**attention scoreの集計改善とreasoning例の導入の両方**が効いている。
2. **`β`感度**（Appendix G）: 小さい`β`ほどhead importanceへの予算集中が強い。HeadKV-R2は比較的小さな`β`で有利で、複数`β`設定でもAda-SnapKVを上回る傾向。論文はvalidation/test分割による`β`選択も示す（Figure 11）。
3. **Retrieval vs reasoning**（Table 3）: Reasoning-in-a-HaystackのLlama-3-8B平均はsize=128でFullKV 57.04、SnapKV 54.16、HeadKV-R 55.16、HeadKV-R2 56.84。retrievalだけでなくreasoningの保持が改善することを検証している。

## Limitations / 実装上の論点

- **事前calibration依存**: R2のhead importanceはsynthetic QAから推定される。coding、multilingual、RAG以外のタスクへ同じimportanceが一般化するとは限らない。
- **不均一なhead長**: headごとに異なるKV長を持つため、GQAのshared K/V head、FlashAttentionのtensor layout、paged KV memory、multi-GPU tensor parallelismで追加のpacking/synchronizationが必要。Appendix Iもmulti-GPUでのparallel overheadを明示する。
- **Baselineの性質**: HeadKVはbudget allocatorであり、選択自体はSnapKVに依存する。より優れたselectorと組み合わせる余地がある。
- **`β`探索**: 主結果は複数候補から良い値を選んでおり、未知データへのhyperparameter transferを別途検証すべき。
- **Prompt削除は不可逆**: Evictしたtokenは将来のquestionが変化しても復元できない。cross-request KV reuseやselective recomputationとは別の問題。

## Taxonomy / 関連研究との差分

| 項目 | HeadKV |
|---|---|
| Category | `compress` |
| Budget granularity | **全layer横断のhead-level** |
| Token selection | headごとのSnapKV型Top-K、末尾observation window保護 |
| Relevance signal | 事前calibrationによるretrieval/reasoning head importance、prompt末尾attention |
| Repair / fusion | なし（不要KVをevict） |
| Model modification / fine-tuning | 不要 |
| Objective | 与えたKV容量でQA/reasoning品質を維持 |

[FastGen](2023-2310.01801-fastgen.md)がhead別の**cache policy type**を切り替えるのに対し、HeadKVはhead別の**budget**を再配分する。[PyramidKV](2024-2406.02069-pyramidkv.md)はlayer単位、[Ada-KV](2024-2407.11550-adakv.md)はlayer内head単位、HeadKVは**全layer横断**という違いがある。[RazorAttention](2024-2407.15891-razorattention.md)はretrieval headを守る発想を共有するが、HeadKV-R2はreasoning headをcalibrationで明示的に考慮する。後続の[R-KV](2025-2505.24133-rkv.md)は長いCoT出力の**token redundancy**をdecode中に評価し、head importanceとは異なる次元を最適化する。
