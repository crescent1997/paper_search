# IH-Challenge: A Training Dataset to Improve Instruction Hierarchy on Frontier LLMs

## 概要

IH-Challengeは、Instruction Hierarchy (IH)をfrontier LLMへより頑健に学習させるための**reinforcement-learning training dataset / environment**である。

IHは、複数sourceから矛盾するinstructionを受けた際に、

```text
System
  > Developer
    > User
      > Tool / external data
```

のようなtrust orderingに従い、higher-priority instructionを維持しながらlower-priority instructionの非競合部分には従う能力を指す。

既存IH trainingでは、hierarchy failureと通常のinstruction-following failureが混ざる、conflictが曖昧、全てを拒否するshortcutで高scoreを取れる、といった問題がある。本論文はこれを避けるため、**簡単に理解でき、objectiveに採点でき、単純shortcutで全問を解けないchallenge**を構築し、online adversarial example generationと組み合わせてRL trainingする。

## 問題設定 / Threat Model

modelは複数のtrust levelからinstructionを受ける。

攻撃者はsystem / developer policyを直接変更できないが、user messageやtool / external content等のlower-trust sourceを制御し、higher-priority policyと競合するinstructionを提示できる。

対象failureには、

- jailbreak
- system prompt extraction
- direct prompt injection
- tool / external-data経由のindirect prompt injection
- benignなinstruction conflict

が含まれる。

Defenseの目標は単純な拒否ではなく、

1. conflictを正しく検出する
2. higher-priority constraintを維持する
3. lower-priority instructionのうち非競合部分は実行する

ことである。

## 先行研究からの改善点

### The Instruction Hierarchy

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)はcontext synthesis / context ignorance等のsynthetic dataでpriority behaviorを学習する代表的研究である。

IH-Challengeはその方向を大規模RLへ進める際のtraining-design問題に焦点を当て、**objective gradingとadversarial curriculum**を導入する。

### Reasoning Up the Instruction Ladder

[Reasoning Up the Instruction Ladder](2025-2511.04694-reasoning-up-instruction-ladder.md)はpriority resolutionをexplicit reasoning + RLVRとして扱う。

IH-Challengeもverifiable RLという点では近いが、frontier modelでのrobustness、shortcut resistance、online adversarial example generationを強く重視する。

## IH Trainingが難しい理由

### 1. Instruction-following failureとの混同

modelがhigher-priority instructionを守れなかったとき、それがpriority理解の失敗なのか、単にconstraint自体を実行できなかったのか区別しにくい。

IH-Challengeではbase taskを十分簡単にし、このconfoundを減らす。

### 2. Ambiguous conflict

自然言語policyでは、2つのinstructionが本当に矛盾するか人間でも曖昧な場合がある。

そこでprogrammatically checkableなconstraintを使い、正解を明確にする。

### 3. Over-refusal shortcut

security benchmarkだけで学習すると、「lower-priority requestを常に拒否する」だけでscoreが上がりうる。

IH-Challengeはaligned / non-conflicting behaviorも要求し、単純拒否ではrewardを最大化できない構造にする。

## Dataset / Environment Design

各sampleではhigher-priority instructionが明確なconstraintを与え、lower-priority sourceがそれと競合または整合するinstructionを与える。

constraintはPython等で自動採点できるよう設計され、RL rewardを人手judgeに依存しすぎない。

概念的には、

```text
High privilege:
  satisfy constraint A

Low privilege:
  satisfy B
  possibly violate A

Reward:
  obey A
  obey B only when compatible with A
```

となる。

この構造により「authorityを理解しているか」を通常task能力から切り分けやすくする。

## Online Adversarial Example Generation

固定datasetだけでtrainingすると、modelが表面的patternをmemorizeする可能性がある。

IH-Challengeではtraining中にmodelの現在のfailureを利用して新しいchallenging exampleを生成し、curriculumを更新する。

```text
current policy
   ↓
find hierarchy failures
   ↓
generate harder conflicts
   ↓
RL update
   ↓
repeat
```

というadversarial loopにより、static synthetic dataへのoverfitを抑える。

## Training

論文ではGPT-5 MiniをIH-Challengeでfine-tuneした **GPT-5 Mini-R** を中心に評価する。

training objectiveはprogrammatic graderで検証可能なhierarchy behaviorをrewardし、higher-priority constraintを守りつつhelpfulnessを維持する方向へpolicyを更新する。

## Experiment Setup

評価は**16のin-distribution / out-of-distribution / human-red-team evaluations**を含む。

代表的には、

- IH-Challenge held-out tasks
- TensorTrust系instruction conflict
- system-user conflict
- jailbreak / safety steerability
- agentic prompt injection
- human red teaming
- general capability benchmarks

を用い、training taskへのmemorizationだけでなく未知のsecurity settingへのtransferを測る。

## Main Results

GPT-5 MiniからGPT-5 Mini-Rへのtrainingで、16評価平均は

```text
84.1% → 94.1%
```

と **+10.0 points** 改善する。

またgeneral safety evaluationにおけるunsafe behaviorは

```text
6.6% → 0.7%
```

へ低下する一方、helpfulnessも改善する。

これは「安全性を上げるために何でも拒否する」というtrade-offだけでは説明できず、priority resolution自体の改善を示唆する。

## Prompt Injection Robustness

特に重要なのがagentic prompt injectionへのgeneralizationである。

tool outputやonline contentに悪意あるinstructionが混ざる場合、modelはそれをdataとして扱い、higher-priority system/developer instructionを維持する必要がある。

GPT-5 Mini-Rは内部static agentic prompt-injection evaluationをほぼsaturateする水準まで改善し、IH trainingがdirect system-user conflictだけでなくexternal-data conflictにもtransferすることを示す。

ただしstatic evaluationの高scoreはadaptive attackerに対するformal guaranteeではない。

## Safety Steerability

IHは単に「安全policyを強くする」機構ではない。system側で指定されたpolicyを、lower-priority requestより優先する**steerability mechanism**である。

そのためdeployment policyが異なる場合でも、higher-trust instructionを正しく優先できることが重要になる。

この点でIH-Challengeは固定refusal policyではなく、authority-aware instruction followingを学習対象とする。

## Generalization / Robustness

改善は、

- in-distribution
- OOD constraint
- human red-team
- agentic prompt injection

へ広く見られる。

またgeneral capability regressionは小さく、IH強化が通常能力を大きく破壊しないことを確認する。

一方で、評価は有限のrole structureとmodel familyに依存するため、任意のmany-tier privilege graphへ自動的に一般化する保証はない。この点は[Many-Tier Instruction Hierarchy](../Benchmark/2026-many-tier-instruction-hierarchy.md)の問題設定と接続する。

## GCG / Adaptive Attackとの関係

IH-Challengeは主にsemantic instruction conflictをtrainingするDefenseであり、[GCG](../Attack/2023-2307.15043-gcg.md)のようなwhite-box adversarial suffix optimizationにformal robustnessを与えるものではない。

また[The Attacker Moves Second](../Attack/2025-2510.09023-attacker-moves-second.md)が示すように、static benchmarkで高いrobustnessを示してもDefenseを知ったadaptive attackerが新しいfailureを探索できる。

したがって今後は、

- GCG / SlotGCG型optimization
- role confusion / priority spoofing
- adaptive prompt injection
- multi-tier conflict

をIH-Challenge-trained modelへ当てる評価が重要になる。

## StruQ / SecAlign / Meta SecAlignとの関係

[StruQ](2024-2402.06363-struq.md)はtrusted promptとuntrusted dataをstructured inputとして分離し、SFTでdata instructionを無視させる。

[SecAlign](2024-2410.05451-secalign.md) / [Meta SecAlign](2025-2507.02735-meta-secalign.md)はpreference optimization等でsecure responseを選好させる。

IH-Challengeはより一般にsystem / developer / user / tool間のtrust orderingをRL taskとして扱い、prompt injection専用の二値prompt/data分離から**multi-source priority following**へ広げる。

## CaMeLとの関係

[CaMeL](2025-2503.18813-defeating-prompt-injections-by-design-camel.md)はmodel内部のpriority behaviorに依存せず、capability / provenanceをsystem architecture側で強制する。

IH-Challengeはmodel-level Defenseであるため、両者は競合というより補完関係にある。

```text
IH-Challenge:
  model should choose correct authority

CaMeL:
  system prevents unauthorized effect
  even if model chooses badly
```

というdefense-in-depthが考えられる。

## Limitations

- programmatically gradeable taskは実世界の曖昧なpolicy conflictを完全には表現しない。
- GPT-5 Mini中心の結果で、すべてのmodel familyへの再現性は未確立。
- static agentic prompt-injection benchmarkのsaturationはadaptive robustnessを保証しない。
- system / developer / user / tool以外のarbitrary privilege graphやmany-tier settingは限定的。
- RL training costとonline adversarial generation costが必要。
- model-level hierarchyはtool permission / data-flow controlの代替ではない。

## LLM Model Security Taxonomyでの位置づけ

```text
The Instruction Hierarchy
  synthetic hierarchy training
          ↓
Reasoning Up the Instruction Ladder
  verifiable reasoning / RL
          ↓
IH-Challenge
  shortcut-resistant RL environment
  + online adversarial generation
  + frontier-model evaluation
```

Instruction Hierarchyをmodel behaviorとしてより頑健にinternalizeするDefenseの発展形と位置づけられる。

## 実装・研究上の示唆

IH training datasetを作る際は、securityらしい複雑なscenarioを増やすだけでなく、

- base taskを簡単にする
- conflictを客観的にする
- aligned caseも含める
- shortcutを潰す
- current model failureからonlineで難例を作る

ことが重要である。

これはprompt injection以外のprivilege separation trainingにも一般化できる設計原則である。
