# Language Shapes Instruction Hierarchy Compliance in Multilingual LLMs

## 概要

本論文はInstruction Hierarchy (IH)評価が英語中心である問題を扱い、multilingual settingへ拡張した**XIH-Bench**を提案する。

system / user / toolなどinstruction sourceのpriorityは言語とは独立であるべきだが、実際のmultilingual LLMではinstructionが書かれた言語によってpriority complianceが大きく変化する。

論文は特に、

1. **Language-dependent Asymmetry**
2. **Language Boundary Effect**

という2つの現象を示す。

## 問題設定

Instruction Hierarchyではsourceによってpriorityが決まる。

```text
System > User > Tool
```

なら、instructionの言語が英語でも中国語でもpriorityは同じであるべきである。

しかしmultilingual modelでは各言語へのinstruction-following能力が均一ではない。

そこでhigher-priority instructionとlower-priority instructionの言語を独立に変え、

```text
higher role × higher language
lower role  × lower language
```

をcontrolledに評価する。

## XIH-Bench

XIH-Benchは78,894 evaluation instancesを含む。

### Languages

6言語を扱う。

- English
- German
- Spanish
- French
- Hindi
- Chinese

### Domains

4 domainを含み、一般的instruction followingだけでなくsecurity-related settingも評価する。

### Hierarchy settings

3種類のpriority relationを評価する。

- System > User
- System > Tool
- User > Tool

これにより単純なsystem/user conflictだけでなく、tool outputをlower-trust sourceとして扱う能力も測る。

## Same-language / Cross-language Conflict

各conflictを、

```text
same-language:
  EN higher vs EN lower

cross-language:
  EN higher vs ZH lower
```

のように構成する。

6×6のlanguage pairを体系的に評価することで、特定言語がhigher側 / lower側に置かれたときの影響を分離できる。

## Language-dependent Asymmetry

第一の主要発見は、ある言語がmodelにとって強いinstruction-following signalである場合、その効果がpriority位置によって逆転することである。

例えばあるlanguage (L) に対するinstruction-following能力が高いmodelでは、

```text
L at higher priority
   -> hierarchy compliance improves

L at lower priority
   -> lower instruction becomes harder to ignore
   -> hierarchy compliance can decrease
```

となる。

つまり言語能力の強さは常に安全側へ働くわけではない。

## Language Boundary Effect

第二の主要発見は、**cross-language conflictの方がsame-language conflictよりInstruction Hierarchy complianceが高い**傾向である。

論文はこれをLanguage Boundary Effectと呼ぶ。

異なる言語で書かれたinstructionはmodel内部で分離しやすく、conflict resolutionが容易になる可能性が示唆される。

逆に同じ言語内ではhigher/lower instructionがより強く干渉する。

## Security Implication

この結果はmultilingual prompt injectionに直接関係する。

attackerがlower-priority instructionを書く言語を選べる場合、target modelが強く従いやすい言語を使うことでpriority boundaryを破りやすくなる可能性がある。

したがってDefense評価で英語attackだけを使用すると、multilingual deploymentのworst-caseを見逃す。

## Safety / Prompt Injection Domain

XIH-Benchのsafety domainではlower-priority prompt injectionへの抵抗を評価する。

単なるformat-following conflictではなく、malicious lower-priority instructionをhigher-priority safety / task instructionより優先してしまうfailureを測る。

これによりmultilingual IHをsecurity propertyとして評価できる。

## IHEvalとの関係

[IHEval](2025-2502.08745-iheval.md)はsystem / user / conversation history / tool output等のhierarchyをReference / Aligned / Conflict settingで評価する。

XIH-Benchはこの問題を、

```text
role priority
    ×
language identity
```

へ拡張する。

したがってIHEvalが「roleを正しく優先できるか」を測るのに対し、XIH-Benchは「そのpriority judgmentがlanguage choiceに対してinvariantか」を測る。

## Control Illusionとの関係

[Control Illusion](2025-2502.15851-control-illusion.md)はsystem/user roleをswapしたcontrolled experimentから、role priorityよりconstraint固有biasやsocial hierarchy cueがmodel behaviorを支配する場合を示す。

XIH-Benchではlanguage identityが同様の**priority-extraneous cue**として働く。

```text
desired:
  source role determines authority

observed:
  source role
    +
  language specialization
    ->
  realized authority
```

というfailureとして整理できる。

## Many-Tier IHとの関係

[Many-Tier Instruction Hierarchy](2026-many-tier-instruction-hierarchy.md)はroleとprivilegeを分離し、最大12 tierのarbitrary hierarchy reasoningを評価する。

XIH-Benchはtier数ではなくlanguage axisを追加する。

両者を組み合わせると、

```text
many privilege tiers
       ×
many languages
```

というより現実的なauthority evaluationになる。

## Experiment Setup

複数のmultilingual / frontier LLMを対象に、higher/lower language pairをsystematically入れ替える。

同一taskのsemantic contentを保ちながらlanguage configurationを変えることで、task difficultyではなくlanguage identityによる差を分析する。

評価ではreference / conflict behaviorとrole hierarchy complianceを測る。

## Main Results

複数modelを通じて2つの傾向が一貫して観測される。

### 1. Asymmetry

model-favored languageがhigher-priority instructionに使われるとcomplianceが改善するが、lower-priority instructionに使われるとそのinstructionを無視しにくくなる。

### 2. Boundary Effect

cross-language conflictはsame-language conflictより平均的にhierarchy complianceが高い。

これは「multilingual capabilityが高いほどIHも強い」という単純な関係ではないことを示す。

## Generalization / Robustness

6言語・4 domain・3 hierarchy relationで傾向を確認することで、特定のsystem-user English taskだけに依存しないことを検証する。

一方、6言語で世界のlanguage diversityを網羅するわけではなく、low-resource languageやcode-switchingは追加評価が必要である。

## Attack観点

XIH-Bench自体はAttack methodではないが、結果からlanguage selectionをadaptive variableにするattackが自然に導かれる。

```text
attacker:
  choose injection content
      +
  choose lower-priority language
```

とすることで、modelが最も無視しにくいlanguageを探索できる。

これはGCGのtoken optimizationやPISmithのprompt optimizationとは別のattack dimensionである。

## Defense観点

[The Instruction Hierarchy](../Defense/2024-2404.13208-instruction-hierarchy.md)、[Instructional Segment Embedding](../Defense/2024-2410.09102-instructional-segment-embedding.md)、[HIPO](../Defense/2026-2603.16152-hipo.md)等をmultilingual settingで評価する際、Englishだけでrobustnessを判断すべきではない。

training dataでもhigher/lower instructionのlanguage combinationsをcross-productで含め、priorityをlanguage-independentに学習させる必要がある。

## Dataset規模と構造

公開datasetは78,894 evaluation instancesを持ち、higher_lang / lower_lang、higher_role / lower_role、domain、hierarchy、same_language等のmetadataを含む。

この構造により、

- 特定language pair
- 特定role pair
- same vs cross language
- safety domain

を個別にsliceして分析できる。

## Limitations

- 対象は6言語で、low-resource languagesを広く網羅しない。
- translation qualityがtask difficultyへ影響する可能性がある。
- languageとscriptの効果を完全には分離できない。
- natural code-switching / mixed-language instructionは限定的。
- benchmark complianceが実agentのtool authorization securityを直接保証しない。
- Language Boundary Effectのmechanistic causeは完全には確定していない。
- multilingual adaptive attackerによるworst-case language searchは今後の課題。

## LLM Model Security Taxonomyでの位置づけ

```text
IHEval
  role hierarchy evaluation
      ↓
Control Illusion
  non-role cues can override hierarchy
      ↓
ManyIH
  arbitrary many-tier privilege
      ↓
XIH-Bench
  multilingual / cross-language hierarchy
```

Instruction Hierarchyをlanguage-invariant security propertyとして測るBenchmarkである。

## 実装・研究上の示唆

multilingual LLMのInstruction Hierarchy評価では平均scoreだけでなく、

1. higher language別
2. lower language別
3. language pair別
4. same / cross-language別
5. role pair別
6. safety / prompt-injection domain別

に分解すべきである。

特にlower-priority側でmodel-favored languageが強くなる現象は、multilingual red teamingでworst-case languageを探索する必要性を示す。
