# InceptionRAG: Stealthy Poisoning Attack Against Retrieval-Augmented Generation

> 従来のRAG poisoningが1 document内へmalicious payloadを明示的に埋め込むのに対し、InceptionRAGはtarget misinformationを複数の「単独では無害な」documentsへ論理的に分散する。documentsが同時retrieveされたときだけLLMのmulti-hop reasoningによってmalicious conclusionが生成されるため、document-level filteringというDefenseの基本前提を崩す。

## 概要

[PoisonedRAG](2024-2402.07867-poisonedrag.md)以降のknowledge poisoningでは、attacker-chosen answerやmalicious instructionをpoison document内へ直接記述する設計が中心だった。この場合、Defenseは各documentを独立に検査し、attention anomaly、keyword density、contradiction、LLM-based filtering等でmalicious payloadを検出できる。

InceptionRAGはこの前提を変え、**malicious conclusionそのものをどのdocumentにも書かない**。

代わりにlogical dependencyを複数documentsへ分割し、それらが同じRAG contextへ入った場合だけLLM自身にtarget misinformationを推論させる。

論文の設計思想は「dormant in isolation, toxic upon aggregation」と要約できる。

## 問題設定 / Threat Model

attackerはRAG corpusへ少数documentsを追加できる。一方で既存benign documentsの変更・削除はできない。

さらにstrict black-box settingを想定し、attackerは以下へaccessしない。

- retriever parameters / gradients
- document embeddings
- generator parameters / gradients
- token probabilities
- internal attention states

観測できるのはpublic RAG interfaceへのqueryと最終answerのみ。

この点で、retriever gradientをprimary optimizationに使う[SilentRetrieval](2026-2605.28074-silentretrieval.md)よりaccess requirementが弱く、target system feedbackだけを利用する[RIPRAG](2025-2510.10008-riprag.md)に近いblack-box threat modelを持つ。

## 先行研究からの改善点

### Single-document Poisoningの弱点

PoisonedRAG型attackでは、target entityとattacker target answerが同一document中に存在する。

そのためDefenseはdocument単位で、

- queryとの異常なsimilarity
- explicit false claim
- suspicious instruction
- anomalous attention
- poison cluster

等を検査できる。

[CamoDocs](2026-2608.28389-camodocs.md)はquery-overlap / embedding-cluster artifactを隠し、SilentRetrievalはPPL / linguistic artifactを減らすが、いずれも最終的なmalicious semanticsは個々のpoison document内に存在する。

InceptionRAGはさらに一段進み、**individual documentからmalicious conclusionを除去する**。

## Indirect Logic Induction

中心となるattack primitiveは、target relationを複数のbenign-looking logical factsへ分解すること。

概念的にはtarget entityを $T$、proxy entityを $P$、attacker target answerを $A$ とすると、

### Attribute Document

```
P has attribute A.
```

target entity $T$ は記述しない。

### Bridge Document

```
T and P are equivalent / share the relevant attribute.
```

target answer $A$ は記述しない。

### Joint Retrieval

両documentが同時にcontextへ入ると、

```
T ≡ P
P -> A
---------
T -> A
```

というtransitive reasoningをLLM自身が行う。

したがって「TのanswerはAである」というfalse statementはcorpus中のどこにも直接存在しない。

## Why Document-level Defense Fails

attribute documentだけを検査するとtarget queryとの直接的malicious relationがない。

bridge documentだけを検査するとattacker target answerが存在しない。

Defenseが各documentを独立にscoreする限り、attack semanticsは観測できない。

malicious behaviorは**documents間のcomposition**に存在するため、single-document classifierでは原理的に捉えにくい。

## Authoritative Suffix

logical trapだけでは、benign retrieved evidenceが正しいanswerを強く支持する場合、LLMがattack chainを採用しない。

そこでpoison documentsへauthority / credibilityを高めるsuffixを付加し、conflicting benign evidenceよりattack evidenceを優先させる。

しかしblack-box environmentではgenerator gradientやtoken probabilitiesを使ってsuffixを直接optimizationできない。

## ZOSO: Zeroth-Order Suffix Optimization

InceptionRAGはblack-box suffix searchのため **Zeroth-Order Suffix Optimization (ZOSO)** を提案する。

候補suffixesをcontinuous embedding representationへ写し、NTK-guided Gaussian Processでsuffix landscapeをsurrogate modelingする。

public RAG interfaceへのlimited queriesからcandidate suffixのattack effectivenessを評価し、Gaussian Processを更新する。

これにより全suffix × 全target queriesをbrute-force評価せず、有望なregionを優先して探索する。

ZOSOの目的は単なるretrieval score最大化ではなく、retrieved後にLLMがattack logical chainをauthoritative evidenceとして採用する確率を高めること。

## Dual-Ended Injection

logical documentsが同時retrieveされなければattackは成立しない。

そこでdocumentの前後へretrieval-oriented textを配置する。

### Subject Header

document先頭へtarget query/topicと関連するsubject informationを置き、dense retrieverのearly-position sensitivityを利用する。

### Pseudo-metadata Footer

末尾へmetadata風のretrieval cuesを追加し、semantic relevanceとauthorityを補強する。

この**Dual-Ended Injection**により、logical payloadの自然さを保ちながらattribute / bridge documentsの双方をtop-kへ押し込む。

## Global / Local Adaptation

global authoritative suffixを複数queriesへ共有できればquery costを削減できる。

一方、global suffixでattackが失敗するqueriesにはquery-specific local adaptationを行う。

さらにmetadata wrapperをrandomizeし、固定signatureに基づくDefenseを避ける。

したがってpipelineは、

```
logical decomposition
    ↓
global ZOSO suffix
    ↓
Dual-Ended Injection
    ↓
target RAG evaluation
    ↓
failed queries only
    ↓
local suffix adaptation
```

となる。

## Experiment Setup

### Datasets

- Natural Questions
- HotpotQA
- MS-MARCO

### Retrieval

default retrieverはContriever、主設定はtop-k=10。

各target queryへinjectするmalicious documentsは基本的に **2 documents**。

retrieved contextではbenign evidenceが多数派になるよう設定され、代表設定ではbenign:malicious = 4:1。

### Generators

複数LLMを評価し、Gemini-2.0-FlashやLlama-2-7B等でmodel reasoning capabilityとの関係も調べる。

### Baselines

- PoisonedRAG
- PIA
- HijackRAG
- その他single-document poisoning variants

### Defenses

attention-based AVFilterやRAGForensics等、traditional poisoning mitigationを含む複数Defenseを評価する。

### Metrics

- Attack Success Rate (ASR)
- Defense bypass rate
- retrieval success
- query / optimization efficiency

## Main Results

Gemini-2.0-Flashのundefended settingでは、

- NQ: **88.0% ASR**
- HotpotQA: **90.3%**
- MS-MARCO: **83.3%**

を達成する。

NQでPoisonedRAGは **32.3%**、PIAは **55.3%**であり、malicious evidenceが少数派でもdistributed logical poisoningが高いattack effectivenessを持つ。

## Defense Evasion

attention-based AVFilter下のNQではInceptionRAGが、

- **ASR 72.3%**
- **bypass rate 90.4%**

を維持する。

比較して、

- PoisonedRAG: ASR 16.7% / bypass 51.6%
- HijackRAG: 11.3% / 27.0%
- PIA: 9.2% / 17.7%

RAGForensics下でも3 datasetsで48%以上のASRが残る。

この差は既存Defenseがsingle-document maliciousnessを前提にしていることを示す。

## Ablation

### Logic Trap Only

Gemini + MS-MARCOではlogical decompositionだけで **40.0% ASR**。

random suffixでも **41.3%**程度で、distributed reasoningだけでは80%台のattackには到達しない。

### ZOSO

ZOSO-optimized suffixを加えると **83.3% ASR**まで上昇する。

したがって高いattack effectivenessはlogical decompositionだけでなく、LLMにmalicious chainをbenign evidenceより優先させるauthority optimizationにも依存する。

### Local Adaptation

global suffixだけでは一部settingで **22.0% ASR**に留まるが、query-specific local adaptationを加えると **83.3%**まで回復する。

black-box universal triggerだけではquery heterogeneityを十分吸収できず、hard queriesへのtargeted adaptationが重要。

## Reasoning Capability Paradox

NQの同一attackでGemini-2.0-Flashは **88.0% ASR**、Llama-2-7Bは **46.0%**。

通常RAGでは強いmulti-hop reasoningは望ましい能力だが、InceptionRAGではその能力がattribute documentとbridge documentを正確に結び付けるため、attack successを高める。

つまり「より強いreasonerほどdistributed logical poisonを自力で完成させやすい」というsecurity / capability trade-offを示す。

## HODOR Defense

著者はdocument isolation-based Defense **HODOR** を提案する。

複数retrieved documentsを同一contextへ入れず、各documentをisolated contextとして個別にanswer generationする。

その後、individual answersをaggregate / majority voteする。

これによりattribute documentとbridge documentが同じreasoning contextで結合されず、indirect logic inductionを切断できる。

## HODORのTrade-off

HotpotQAのような正規のmulti-hop QAでも複数documents間のreasoningが必要。

したがってdocument isolationを強くするとInceptionRAGを防げる一方、legitimate cross-document reasoningも破壊する。

これは本attackの重要な点で、Defenseは単に「documentsを分離すればよい」ではなく、

- malicious cross-document dependency
- legitimate multi-hop evidence composition

を区別する必要がある。

## CamoDocs / SilentRetrievalとの比較

```
PoisonedRAG
   ↓
single-document poison artifacts become detectable
   ├─ SilentRetrieval
   │    └─ hides linguistic / PPL artifacts
   │
   ├─ CamoDocs
   │    └─ hides query-overlap / embedding-cluster artifacts
   │
   └─ InceptionRAG
        └─ removes malicious conclusion from each individual document
             ↓
        malicious semantics exists only across documents
```

InceptionRAGは「poison documentをより自然にする」だけでなく、Defenseが検査する単位そのものをdocumentから**document set / logical dependency graph**へ変える必要性を示す。

## RAGSentinel / PRA-RAG / TRISへの示唆

[RAGSentinel](../Defense/2026-2608.23965-ragsentinel.md)はquery-conditioned document residual、[PRA-RAG](../Defense/2026-2607.00012-pra-rag.md)はsubset representation geometry、[TRIS](../Defense/2026-2609.00470-tris.md)はretrieval / structural / semantic filteringを利用する。

InceptionRAGのように各document単体がbenign-lookingな場合、document-level anomalyだけでは十分でない可能性がある。

特にDefense評価では、poison countだけでなく**複数poisons間にmalicious logical dependencyが存在するadaptive attack**を含める必要がある。

## RAG Security Taxonomyでの位置づけ

本論文はprivate corpus extractionではなく**integrity / knowledge poisoning**に属する。

```
RAG integrity attacks
  └─ Corpus poisoning
       ├─ explicit single-document poisoning
       │    └─ PoisonedRAG
       ├─ stealthy single-document poisoning
       │    ├─ SilentRetrieval
       │    └─ CamoDocs
       └─ distributed logical poisoning
            └─ InceptionRAG
```

## Limitations / 成立条件

corpusへのwrite accessが必要。

少なくともlogical chainを構成する複数poison documentsが同時retrieveされる必要があり、retrieval diversityやsource constraintsによってco-retrievalを阻害されるとattackは弱くなる。

ZOSO / local adaptationにはtarget RAGへの反復queriesが必要で、strict rate limitingやwrite/query monitoringはattack costを増やす。

HODORが示すようにdocument isolationは有効だが、legitimate multi-hop QAとのutility trade-offがある。

また評価は主にQA型RAGであり、agentic RAG、GraphRAG、multimodal RAG等への一般化は追加検証が必要。

## 実装・研究上の示唆

InceptionRAGの最大の示唆は、RAG securityの検査単位を**document単体からdocument combinationsへ拡張する必要がある**こと。

今後のDefenseでは、

- pairwise / subset consistency
- cross-document entailment graph
- provenance independence
- co-retrieval anomaly
- malicious conclusionがcontext aggregation後に初めて出現するか

といったinteraction-aware signalが重要になる。

一方、全document combinationsを検査するとcombinatorial costが発生するため、PRA-RAGのsubset samplingやRAGSentinel型geometryとの組み合わせは研究上興味深い。
