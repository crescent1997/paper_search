# 概要
VLMで一般的なvisual token pruningはprefill attentionなどの**言語・意味理解上の重要度**でtokenを残す。しかしVLAでは、実際にactionを生成するときに必要な局所視覚情報が異なる。VLA-Prunerはこのsemantic-action gapを明示的に扱い、**prefill由来のsemantic relevance**と**action decode由来のrelevance**を併用してvisual tokenを選択する。KVの再利用というより、各stepで処理するvisual token数の削減が主目的。

# 問題設定
VLAでは画像・命令をprefillし、後段でaction tokenまたはaction chunkを生成する。prefill時のattentionが強いtokenがaction時にも重要とは限らない。VLM用のFastVやSparseVLMをそのまま適用すると、物体の接触点やgripper周辺など操作に必要な局所情報が落ち、task successが悪化する。

# 手法
## 1. Semantic-action importance
現在stepのvision-language prefillからsemantic importanceを推定し、action decodeのattentionからaction importanceを得る。現在のaction decodeはpruning時点では未実行なので、**過去の制御stepのaction-to-vision attention**を時間方向に平滑化して現在のimportanceのproxyとする。

## 2. Temporal smoothing
過去のaction attentionをdecay付きで集約する。連続したロボット動作では重要な操作領域が急には変わらないという仮定に依存する。時間窓とdecay rateはheuristicなハイパーパラメータ。

## 3. Combine-then-Filter
semantic側・action側で重要なvisual token候補をまず結合し、重複や冗長性をfilterしてbudget内に収める。単純なattention scoreの線形加重平均よりも、両種類の重要tokenを取りこぼしにくい設計。

## 4. KV cacheとの関係
visual tokenをpruneすると、後段Transformerで生成・保持・読み出すvisual KVとattention演算も減る。ただし**前フレームのKVをコピーして使う方式ではない**。KV reuseとtoken pruningは別の最適化軸であり、同じ`vla`フォルダに置いて区別する。

# Experiment Setup
- モデル: OpenVLA、OpenVLA-OFT、追加検証でdiffusion-headのπ0。
- シミュレーション: LIBERO（Spatial/Object/Goal/Long）、SIMPLER。
- 実機: xArm6、4種の操作taskで各100 trial。
- 比較: FastV、SparseVLM、DivPrune、VLA-Cache、full model。
- visual token retention: 50%、25%、12.5%。metrics: success rate、relative accuracy、FLOPs、action/action-chunk latency。

# Main Results
- 論文abstractは最大**1.99倍高速化**、同程度のmanipulation qualityを報告する。高速化率とaccuracyはretention ratioに依存する。
- LIBERO、retention 25%: OpenVLAでrelative accuracy **98.48%** / latency **144.81 ms**（full 236.41 ms）；OpenVLA-OFTでrelative accuracy **98.37%** / latency **75.64 ms**（full 135.78 ms）。
- retention 12.5%: OpenVLAでrelative accuracy **88.90%** / latency **129.01 ms**；OpenVLA-OFTでrelative accuracy **88.27%** / latency **68.95 ms**。この条件では品質低下が無視できないため「常に同品質」と解釈すべきではない。
- retention 25%のOpenVLAでは、同条件のVLA-Cache（relative accuracy 88.08% / 164.17 ms）より成功率を維持する。これは論文内の実装・ベンチ条件での比較。

# Ablation
- prefill-only、action-only、両scoreの単純weighted fusionと比較し、Combine-then-Filterが優れると報告。
- smoothing window、decay rate、pruning layerを感度分析。retention 25%時のOpenVLAで、pruning layer K=3の平均成功率74.53、K=4で74.48、K=2では58.48。pruning位置に感度がある。
- π0などaction headが異なる構成でもtoken削減が成立することを追加検証。

# Limitations
- action importanceは**過去のattentionに基づく推定**であり、現在の急変を直接観測できない。
- wrist-cameraや高速搬送など視点・対象物が急変する状況では時間平滑化が不適切になり得る（著者らも明記）。
- attentionの保存・集約、候補統合、filter処理には追加コストがある。選択基準の優位性はbudget・model・taskによって変わる。
- token削減により操作上不可欠な局所情報を消すと回復できない。KVを保持したまま再利用する手法と精度・メモリ特性が異なる。

# Taxonomy / 関連研究
- **分類**: `KVcache/vla` / action-aware visual-token pruning / training-free / temporal attention estimation。
- [VLA-Cache](2025-2502.02175-vla-cache.md)は**静止visual tokenの過去KVを再利用**し、task-relevant tokenを再計算する。一方VLA-Prunerは**semantic/action両方に重要なtokenを保持し、それ以外を削除**する。
- LLM側のKV compressionと同様にtoken budgetを削減するが、重要度をlanguage semanticsだけで定義するとロボット制御品質を損なう点がVLA固有の問題。
