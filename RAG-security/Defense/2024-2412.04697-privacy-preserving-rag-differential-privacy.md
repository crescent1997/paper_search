# Privacy-Preserving Retrieval-Augmented Generation with Differential Privacy

> RAG outputがretrieval corpus中の個別documentへ過度に依存しないよう、retrieved documentsをdisjoint groupsへ分割して複数LLMのnext-token votesを作り、その集約へDifferential Privacyを適用する。さらにSparse Vector Techniqueを利用し、private corpusを必要としないtokenではprivacy budgetを消費しない **DPSparseVoteRAG** を提案する。

## 概要

RAGではprivate documentsをmodel parameterへtrainingしなくても、retrieval context経由でresponseへprivate informationが漏れる。特にmembership inferenceでは、あるdocumentがretrieval databaseに存在するかどうかをresponse behaviorから推測できる。

本論文はこの問題へ **document-level Differential Privacy (DP)** を導入する。neighboring databasesを「1 documentだけ異なるretrieval corpora」と定義し、そのdocumentの有無によって生成response distributionが大きく変化しないようにする。

中心となるのは2手法である。

- **DPVoteRAG**: retrieved documentsを複数groupへ分割し、groupごとのLLM voteをDP aggregationする。
- **DPSparseVoteRAG**: non-RAG LLMとprivate votersが一致するtokenではprivacy budgetを使わず、private knowledgeが本当に必要なstepだけDP mechanismを実行する。

## 問題設定 / Threat Model

private retrieval corpusを $D$ とし、neighboring corpus $D'$ は1 documentの追加 / 削除だけが異なるものとする。

RAG mechanism $M$ が $(\epsilon,\delta)$-DPであるとは、任意のneighboring $D,D'$ とoutput event $S$ に対して、

$$
\Pr[M(D)\in S] \le e^\epsilon \Pr[M(D')\in S] + \delta
$$

を満たすことを要求する。

この保証により、attackerがgenerated answerを観測しても、特定documentがcorpusに含まれているかを高confidenceで判別しにくくする。

attacker modelはblack-box membership inferenceを主に想定し、RAG outputへアクセスするがprivate corpus自体にはアクセスしない。

## 先行研究からの改善点

### Empirical Sanitizationとの違い

[SAGE](2024-2406.14773-sage.md) はprivate corpusをsynthetic corpusへ置換し、LLM privacy agentで残存private informationを除く。しかしこれはempirical defenseであり、特定documentのpresence / absenceに対するformal privacy guaranteeはない。

本論文はquery-time generation mechanismへDPを導入し、document-level guaranteeを与える。

### Naive DP Generationの問題

next tokenごとにDP mechanismを適用するとsequential compositionによりprivacy budgetが急速に消費される。

長いanswerでは各tokenの$\epsilon$が累積し、fixed total budget下では途中でgenerationを停止するか、1 tokenあたりのnoiseを大きくしてutilityを失う。

DPSparseVoteRAGは「private corpusが不要なtoken」を検出してbudget-free generationへ切り替えることでこの問題を改善する。

### DP-SynRAGとの技術的系譜

後続の [DP-SynRAG](2025-2510.06719-dp-synrag.md) はさらにprivacy mechanismをoffline corpus generationへ移し、一度DP synthetic corpusを作ればonline queryごとの追加budgetを消費しない設計を取る。

したがって、

```text
SAGE
  empirical synthetic sanitization
      ↓
DPVoteRAG / DPSparseVoteRAG（本論文）
  query-time formal DP generation
      ↓
DP-SynRAG
  one-time DP synthetic corpus generation
```

という比較が有用である。

## Method 1: DPVoteRAG

### Retrieval and Partitioning

query $q$ に対し、通常のTop-kだけでなく合計 $m\times k$ documentsをretrieveし、それらを $m$ 個のdisjoint subsetsへrandom partitionする。

各subset $D_i$ はk documentsを含み、それぞれ独立したRAG contextとして同一LLMへ入力される。

### LLM Voters

各subsetからnext-token candidateを生成する。

$$
v_i = \arg\max_t P(t\mid q, D_i, y_{<j})
$$

$m$ votersのtoken votesをhistogramへ集約する。

一つのprivate documentはdisjoint partitionのうち高々1つにしか含まれないため、neighboring databaseで変化し得るvoteも限定される。このsample-and-aggregate構造によってhistogram sensitivityを制御する。

### Private Token Selection

vote histogramへLimitedDomain等のDP mechanismを適用し、noiseを加えた上でwinning tokenを選択する。

これをautoregressive generationの各stepで繰り返す。

### 問題: Privacy Composition

各token selectionでprivacy budgetを消費するため、sequence length $T$ に応じてtotal privacy lossが増える。

論文中のillustrative exampleではDPVoteRAGが `The Great Gatsby is a ...` 程度でbudgetを使い切り、十分なanswerを生成できない場合がある。

## Method 2: DPSparseVoteRAG

DPSparseVoteRAGはSparse Vector Technique (SVT)を利用し、private informationを必要とするstepだけを識別する。

### Non-RAG Proposal

まずprivate retrieval contextを全く使わないbase LLMからnext-token candidate $t_0$ を生成する。

このtokenはpublic / parametric knowledgeだけに基づくため、private corpusに依存しない。

### Agreement Test

private RAG votersのうち何人が $t_0$ と一致するかを数える。

多くのvotersがnon-RAG tokenと一致する場合、そのtokenはprivate documentsが変化しても比較的stableであり、private corpus固有のsignalを必要としていない可能性が高い。

SVTを使ってagreement countがthresholdを超えているかをprivacy-preservingに判定する。

### Budget-Free Token

agreementが十分なら $t_0$ をそのままoutput tokenとして採用し、高costなprivate vote selectionをskipする。

これにより通常のfunction words、general knowledge、syntactic continuation等ではprivacy budget消費を抑えられる。

### Private Token

agreementが不足する場合だけDPVoteRAG型のprivate aggregationを行う。

つまり、

```text
Non-RAG token proposal
        ↓
Private votersとのagreement test
        ↓
   high agreement? ─ yes → non-RAG token
        │                  (small / no expensive budget)
        no
        ↓
DP private vote selection
        ↓
private-information-dependent token
```

というsparse budget allocationになる。

## Experiment Setup

### Datasets

- TriviaQA
- Natural Questions
- ChatDoctor

を使用する。ChatDoctorはprivacy-sensitiveなmedical dataとしてmembership inference評価にも利用する。

### Retriever

主にDPRを使用し、queryごとに多数documentsをretrieveしてvoter groupsを構成する。

### Generator Models

複数model familyを用い、代表的には、

- OPT-1.3B
- Pythia-1.4B
- Llama-3.1-8B

等を評価する。

### Privacy Parameters

主にtotal $\epsilon$を2～40程度で変化させ、$\delta=10^{-4}$、per-token / mechanism $\epsilon$として1,2,5等を比較する。

voter数 $m$ も30～50程度を含む複数settingで評価する。

### Metrics

utilityはQA accuracy / generation quality、privacyはformal $(\epsilon,\delta)$ guaranteeに加えてmembership inference AUCを測る。

## Main Results: Utility

DPSparseVoteRAGはほぼ全settingでDPVoteRAGを上回る。

privacy budgetが非常に小さい場合はNon-RAG baselineを下回ることもあるが、概ね **$\epsilon_{total}\ge10$** 付近からNon-RAGより高いQA utilityを示し、budgetを増やすにつれてnon-private VoteRAGへ近づく。

特にsequence lengthで差が大きく、DPVoteRAGはtoken-level budget compositionによって早期停止しやすい一方、DPSparseVoteRAGはnon-private tokenを多数budget-efficientに生成できるため、より長いcomplete answerを生成する。

## Membership Inference Evaluation

ChatDoctorに対してS2MIA系membership inferenceを実施する。

non-private VoteRAGではmembership AUCが、

- OPT: **0.631**
- Pythia: **0.620**
- Llama-3.1: **0.664**

となり、random guessing 0.5を明確に上回る。

DPSparseVoteRAG（代表的な$\epsilon=10$ setting）では、

- OPT: **0.452**
- Pythia: **0.488**
- Llama-3.1: **0.516**

まで低下し、ほぼrandom guessing levelとなる。

formal DP guaranteeだけでなく、実際のmembership attack effectivenessも低下していることを示す。

## Ablation / Privacy-Utility Trade-off

### Privacy Budget

$\epsilon$を大きくするとDP noiseが減りutilityは向上するがprivacy guaranteeは弱くなる。小さい$\epsilon$ではstrong privacyを得る一方、voter disagreement時にcorrect private tokenを選びにくくなる。

### Number of Voters

voter数を増やすとconsensus signalが強くなりDP noiseへのrobustnessが上がるが、LLM inference costがほぼ比例して増える。

### Sparse Voting

DPSparseVoteRAGの主なutility gainは、全tokenをprivate selectionするのではなく、non-RAG proposalとconsensusするstepをskipできることから来る。

この結果は「answer中のすべてのtokenがprivate knowledgeを必要とするわけではない」という観察をprivacy accountingへ利用できることを示す。

## Limitations / 成立条件

最大の実用上の問題は**計算量**である。1 queryに対して30～50程度のRAG voter inferenceを行うsettingがあり、standard RAGより大幅に高価になる。

またretrieved relevant documentsが少ないquestionでは、一つのdocumentの有無がvoter outputへ大きく影響しやすく、DP下でutilityを維持しにくい。

privacy budgetはquery / generationを通じて管理する必要があり、同じprivate corpusへ無制限にqueryするdeploymentではcompositionをどう扱うかが重要になる。

本論文のformal guaranteeはdocument-level neighboring relationに基づくため、一document内の複数individualsやcorrelated recordsなど、別のprivacy unitを要求する用途ではdefinitionの再設計が必要である。

## RAG Security Taxonomyでの位置づけ

本論文は **Defense / confidentiality / formal privacy / query-time DP generation** に位置づけられる。

RAG privacy defenseをlayer別に整理すると、

```text
Corpus preprocessing
  SAGE       : empirical synthetic sanitization
  DP-SynRAG  : formal DP synthetic corpus

Query-time generation
  DPVoteRAG / DPSparseVoteRAG ← 本論文

Runtime extraction defense
  RAGFort / CanaryRAG
```

となる。

RAGFort / CanaryRAGがmalicious extraction behaviorを抑制・検出するのに対し、本論文はattacker behaviorに依存せず、individual documentの影響度そのものを数学的に制限する点が異なる。

## 実装・研究上の示唆

private RAGでformal DPを導入する場合、単にLLM outputへnoiseを加えるのではなく、**retrieval resultsをdisjoint groupsへ分割してsensitivityを構造的に制御する**ことが重要である。

またDPSparseVoteRAGは、private knowledgeが必要なgeneration stepをsparsely検出するという発想を示している。この考え方はDP以外でも、expensive secure inferenceやprivate retrievalを必要なtokenだけに限定するoptimizationへ応用できる可能性がある。

一方、online privacy accountingと多数votersのcostは大きく、これが後続のDP-SynRAGのようなoffline one-time privatizationを動機付ける。
