# Know Thy Enemy: InstruCoT

## 概要

InstruCoTはprompt injection defenseをexternal detectorではなく**model自身のinstruction recognition / reasoning能力**として学習させる。

課題は、malicious instructionがuser prompt、retrieved data等の多様なsource/positionへ現れ、周辺textとのsemantic boundaryも明瞭でないことである。

そこで多様なattack dataを合成し、instruction-level Chain-of-Thoughtで「どのinstructionが存在し、何が危険で、どう応答すべきか」をSFTする。

## Threat Model

direct / indirect prompt injectionを扱い、攻撃者はcontext内へmalicious instructionを挿入する。

目的は主に、

- Behavior Deviation
- Privacy Leakage
- Harmful Output

の3種である。

model weightsへのattacker accessは不要で、in-context injectionが中心である。

## Diverse Data Synthesis

training distributionを単一attack templateへ固定せず、attack objective・source・positionを変化させる。

injection locationにはUser / Data / User+Data / Empty等を含める。

これにより「data部分だけをuntrustedと仮定する」ようなshortcutを避ける。

## Instruction-level CoT

単にsafe final responseをimitateするのではなく、context内instructionを明示的にreasoningさせる。

概念的には、

```text
Instruction Perception
  -> Violation Comprehension
  -> Response Projection
```

という流れになる。

### Instruction Perception

context中のinstruction / intentを識別する。

### Violation Comprehension

どのinstructionがsecurity goalと衝突し、malicious behaviorを誘発するかを判断する。

### Response Projection

malicious instructionを拒否しつつoriginal taskへ適切に応答する方針を作る。

## StruQ / SecAlignからの違い

[StruQ](2024-2402.06363-struq.md)はprompt/data separationをstructured inputとtrainingで学習し、[SecAlign](2024-2410.05451-secalign.md)はsecure/insecure response preferenceをDPOで強化する。

InstruCoTはsource delimiterだけに依存せず、**individual instructionをsemanticに認識してreasoningする**ことへ重点を置く。

## Experiment Setup

4 LLMを用い、7 attack methodsをdirect / indirect injectionで評価する。

対象modelにはLlama-3.1-8B、Llama-3-8B、Qwen2.5-7B、Qwen3-8B等を含む。

Defense Rateとutilityを評価する。

## Main Results

平均Defense Rateは、

```text
Behavior Deviation: 92.5%
Privacy Leakage:    98.0%
Harmful Output:     90.9%
```

direct injectionでは91.5%、indirect injectionでは93.4%を報告する。

複数attack vectorに対して比較的均衡したrobustnessを示す。

## Utility

security向上だけでなくbenign task utilityを評価し、平均win rate 82.9%を報告する。

単純なalways-refuse behaviorでDefense Rateを上げる方式ではないことを確認する。

## Generalization

source / positionを多様化したtrainingにより、特定delimiterや固定位置への依存を減らす。

これはprivilege sourceを明示的token typeとして与えるISEとは異なり、semantic instruction identificationのgeneralizationを狙う。

## Instruction Hierarchyとの関係

[The Instruction Hierarchy](2024-2404.13208-instruction-hierarchy.md)はhigher / lower privilege間のconflictをsynthetic trainingで学習する。

InstruCoTはprompt injectionをより細粒度に、

```text
find instructions
 -> reason about security conflict
 -> reject malicious instruction
```

として解く。

明示的role hierarchyだけでなく、context内に埋め込まれたinstruction boundaryの曖昧さを扱う点が特徴である。

## ISEとの関係

[Instructional Segment Embedding](2024-2410.09102-instructional-segment-embedding.md)はsource identityをarchitecture-level embeddingとして与える。

InstruCoTはarchitectureを変更せず、instruction semanticsとreasoning traceをtraining signalにする。

## Reasoning Upとの関係

[Reasoning Up the Instruction Ladder](2025-2511.04694-reasoning-up-instruction-ladder.md)はhierarchy resolutionをexplicit reasoning taskとして扱う。

InstruCoTもreasoningを使うが、focusはprompt injectionにおけるinstruction detection / maliciousness understandingである。

```text
InstruCoT:
 instruction recognition + security reasoning

Reasoning Up:
 explicit priority/hierarchy reasoning
```

と整理できる。

## IH-Challengeとの関係

[IH-Challenge](2026-2603.10521-ih-challenge.md)はprogrammatically gradeable RL environmentとonline adversarial generationを用いる。

InstruCoTはSFT-based CoT learningであり、adaptive online attackerをtraining loopへ組み込むわけではない。

## Adaptive Attack

複数attack methodsへgeneralizeするが、Defense-aware attackerがInstruCoTのreasoning patternを知ったうえで最適化するworst-case evaluationとは異なる。

[PISmith](../Attack/2026-2603.13026-pismith.md)等によるadaptive stress testが重要になる。

## Limitations

- CoT supervision品質に依存する。
- explicit reasoningがinference costを増やし得る。
- attackerがreasoning format自体をspoofする可能性がある。
- source/position diversityはreal-world attack space全体を網羅しない。
- adaptive white/black-box red teamingへのformal guaranteeはない。
- model自身のclassification/reasoning failureがDefense failureへ直結する。
- tool authorization等のsystem-level enforcementを代替しない。

## Taxonomy

```text
Structured privilege:
 StruQ / SecAlign

Role/source representation:
 Instruction Hierarchy / ISE

Instruction-level reasoning:
 InstruCoT
   ↓
Hierarchy reasoning / RL:
 Reasoning Up / IH-Challenge
```

## 実装・研究上の示唆

prompt injection training dataではattack stringの多様化だけでなく、

1. source
2. position
3. semantic boundary
4. malicious objective
5. direct / indirect vector

を独立に変化させる必要がある。

さらにfinal answerだけでなくinstruction-level reasoningをsuperviseすることで、unseen injectionへのgeneralizationを狙える。
