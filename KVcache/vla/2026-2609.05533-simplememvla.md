# 概要
長時間操作で必要な情報が過去の映像にしか存在しない部分観測問題に対し、専用の記憶バンク・圧縮器・recurrent stateを持たず、VLMが事前学習時から扱う **timestamp付きnative video** をそのまま履歴メモリとして入力する。過去のどの情報を保存すべきかを観測時点で確定してしまう *write-time commitment* を回避することが中心的な主張。歴史情報はsub-taskの文脈化hidden statesを通じてflow-matching action headに伝達する。これは「過去フレームのKVを再利用して特徴量を省く」VLA-Cache型とは異なるが、**共有prefixをaction実行中にprefillして次の制御判断へ引き継ぐ**点でKV cache再利用に直接関係する。

# 問題設定と先行研究との差
時刻tの履歴 h_t=(o_{<=t}, instruction) に対し、policy π(a_t|h_t) を推定する。retrievalは選ばれなかったフレーム、compressionは圧縮で消えた詳細、recurrentは上書きされた情報を、将来の問い合わせ時に復元できない。MEM (arXiv:2603.03596) の短期圧縮映像＋長期言語要約と対照的に、本手法は生のサンプリング動画をVLMの通常のattentionで読ませる。ただしnative contextはコンテキスト長に比例してKV容量が増加するため、メモリ容量一定のrecurrent法より常に有利という意味ではない。

# 手法
## Native Video History
観測fpsを f_c、動画サンプリングfpsを f_v、履歴窓を T_w とすると、K=T_w f_v 枚を間引いてvideo streamにする。時間順のフレームとplaintext timestampを保持し、手首カメラの現在画像は別のimage channelで与える。Qwen3.5-4B VLMが現在のsub-taskを一文で生成し、そのsub-task spanのcontextual hidden statesとtoken embeddingsを、現在のproprioceptionと共にflow-matching action headに入力する。長い履歴がaction headに直接cross-attentionされる構成ではなく、sub-taskのhidden stateが狭い伝達路となる。

## Shared-prefix prefillとKV
連続する判断では履歴の大部分が共通である。action chunkを実行している間に共有prefixを先にprefillし、次の判断時には差分を処理する。標準の60秒窓では約5.6k tokens（単一画像では約0.5k）。本文はこの方法が**full recomputationと同一の出力**を生成すると報告。prefixの時間表現が変わるとKV再利用の整合性が崩れ得るため、Appendix Fでは絶対timestampとsliding-window attentionを使ってappend/evictするbounded-cost変種も扱う。45分・245k tokensは人工的に構成したスケーリング入力であり、45分の実機タスク成功を実証した数字ではない。

# Experiment Setup
Qwen3.5-4B backboneとflow-matching action head。長期記憶ベンチマークRoboMME、RMBench、MIKASA-Robo、RoboMemArena、一般操作LIBEROとLIBERO-Plus、双腕実機を評価。RoboMMEではretrieval（8 frames）、token compression（64 tokens）、recurrent state（16 tokens）を同じbackbone・training data・action head・optimizerに移植して比較。latencyは単一H100、bf16、batch=1。実機は60秒履歴・2 fps、最大120 frames。control frequency、throughput、GPU peak memoryの比較数値はここで確認した実験記述からは確定できず、不明として扱う。

# Main Results
| 評価 | SimpleMemVLA | 比較・解釈 |
|---|---:|---|
| RoboMME平均成功率 | 88.3% | 同一stackのretrieval 31.5%、compression 22.6%、recurrent 20.6% |
| MIKASA-Robo平均成功率 | 74.0% | MemoryVLA 41.2%、MemoryVLA++ 44.4%（異なる研究実装の比較） |
| RoboMemArena TSR / CSR平均 | 63.6% / 72.1% | FrameSamp+Modul 46.2% / 63.9%。TransferringカテゴリではFrameSampの方が高い |
| LIBERO平均成功率 | 97.5% | 4 suite合計、各suite 500 trials |
| LIBERO-Plus zero-shot | 78.4% | MemoryVLA++ 73.1%、OpenVLA-OFT 69.6% |
| 実機 Cover Blocks | 58.3% (35/60) | 180 demonstrations、6初期配置 |
| 実機 Put Back Block | 70.0% (28/40) | 308 demonstrations、4初期配置 |
| 60秒履歴 decision latency | 1.02s → 0.68s | streaming prefix prefill、単一フレーム約0.65s。約1.50倍のdecision-path高速化 |
| 人工45分履歴 decision latency | 32.1s → 1.18s | 約27.2倍。ただし実タスク45分評価ではない |

注意：RoboMMEの大きな差は著者が同じstackに実装した**特定の**retrieval/compression/recurrent variantsに対する結果であり、各方式の最適実装全体への一般化はできない。また0.68sは判断パスのlatencyであり、ロボット制御周期全体やthroughputを直接示すものではない。

# 主要Ablation
- **メモリインターフェース統制比較**：native 88.3%、8-frame retrieval 31.5%、64-token compression 22.6%、16-token recurrent 20.6%。バックボーン等を揃えたため記憶インターフェースの差の根拠となるが、token予算は一致していない。
- **履歴窓**：Cover Blocksで約25秒前のイベントが30秒窓なら残るが15秒窓では消え失敗。Press Buttonでは窓短縮に伴いcountingが悪化。
- **順序とtimestamp**：フレーム順序シャッフルは両タスクを破壊。timestampゼロ化はCover Blocksにはほぼ影響せず、繰り返し回数を数えるPress Buttonに大きく影響。
- **hidden statesの役割**：sub-taskのtoken embeddingsを入れ替えても動作は比較的維持される一方、contextual hidden statesの置換で動作が変化し、ゼロ化では失敗。履歴由来の制御情報は主にhidden statesに載る。
- **History intervention**：過去イベントのmaskや別rolloutの映像への置換で、学習パラメータを変えずに計数・対象選択が変化。単なる言語的sub-task priorでなく視覚履歴を実際に参照している証拠。
- **streaming**：shared-prefix prefillにより60秒履歴1.02→0.68秒。精度を落とす近似cacheではなく出力一致を主張。

# Limitations / 実装上の論点
1. 60秒で5.6k tokens、45分で245k tokensのように履歴長とともにKV容量が増大。長期に一定メモリで動く設計ではない。Appendix FのSWAは補完策だが、窓外情報の消失を伴う。
2. リアルタイム性はH100上のbatch=1 decision-path測定が中心。GPU memory、低性能edge GPU、end-to-end control frequencyの比較は未確認。
3. 時間窓・サンプリング率によって決定的な短いイベントを取りこぼし得る。窓外に出た証拠は保持できない。
4. 実機の成功率は58.3%/70.0%で、低レベル把持失敗などの課題が残る。歴史推論の精度と動作成功を区別する必要がある。
5. VLM backboneとsub-task supervisionを含む学習・fine-tuningが必要。「training-free KV reuse手法」ではない。
6. 既存方式との数値比較は同条件の再実装と論文間比較を区別する。特にMEMとの直接同条件の成功率差はここからは断定できない。

# Taxonomy
- Primary: `KVcache/vla` — native-video long-horizon memory
- Secondary: prefix prefill / exact shared-prefix KV reuse; temporal history; flow-matching action head
- Not: visual KV eviction/compression, frame-to-frame approximate visual KV reuse, constant-size recurrent memory
