# TempoFit — Layer-Wise Temporal KV Memory

## 1. 概要と研究上の位置付け

既存のVLAは、各制御時刻に最新画像と言語指示を入力し、過去の作業状態を明示的には保持しない。物体が隠れたり、操作の前後で画像がほとんど変わらない場合、同じ観測でも異なる行動が必要になる。TempoFitは、**学習済みVLAの重み・action head・入力token数を変えず**、Transformer内部のprefix K/Vをフレーム間記憶として利用する推論時拡張である。VLA-Cacheの「変化の小さいtokenの再計算省略」と異なり、過去K/Vの検索結果を**現在のK/Vに融合して時間的情報を付加**する。現在フレームのprefill自体をスキップする技術ではない。

## 2. 問題設定・先行研究との差

フレーム連結は履歴長に比例してvisual token・attention計算・GPU memoryが増える。MemoryVLAのような外部memory bankや学習済みfusionは長期依存を扱える一方、追加学習と既存VLAへの適合が必要。TempoFitは、既存のkey projection空間を検索アドレスとして使うことで、別の学習済みquery/gateを不要にする。非Markov性に対処しながら、単一フレームで学習された表現分布をできるだけ維持するのが主眼。

## 3. 手法

### 3.1 中間層だけにprefix K/Vを保存

VLAをvision-language backbone `F` とaction headに分解。各時刻 `t` のprefix encoding中、選択された中間層 `l` の `K_l(t), V_l(t)` を時刻情報とともにFIFO記憶 `M_l(t)` に保持する。容量は `C` フレーム。action suffixは保存しない。**RoPE適用前のprojection**を保存するため、異なる時刻の位置位相を混ぜずに内容ベースで検索できる。保存層を全層に増やすと分布干渉が大きくなる。

### 3.2 K-to-K retrieval と時間バイアス

現在のkeyをqueryの代わりに用い、履歴keyと同一空間で類似度を計算する。

```text
A_kk(l,h) = K_current(l,h) @ K_history(l,h)^T / sqrt(d) + mask
W = softmax(A_kk + temporal_bias)
K_context = W @ K_history
V_context = W @ V_history
```

Frame-Gap Temporal Bias (FGTB) は `bias(t,τ) = -β * m_h * |t-τ| * α_S`（既定 `α_S=S`、`S` はprefix token数）というALiBi風の減衰項。古い履歴の過剰な支配を抑え、現在の観測を優先する。過去情報を一律に削除するのではなく、類似度とのsoftな競合を残す。

### 3.3 Norm-preserving residual loading

検索した `(K_context,V_context)` を、通常のself-attentionの前に現在の `(K,V)` に残差的に加える。ノルムを調整して元のK/Vの大きさを保ち、凍結モデルが想定していないscale変化を抑える。tokenの追加・attention maskの変更は不要。**過去のK/Vをそのまま連結するのではなく、現在のtoken位置に履歴を写像する**点が特徴。

## 4. Experiment Setup

- **Backbone**：π0.5、StarVLA系QwenGR00T。学習済みcheckpointを使用し、TempoFitの追加学習なし。
- **評価**：LIBERO-LONG 10タスク×50試行＝500試行、CALVIN D→DおよびABC→D、Realman RM-65B実機（主カメラ＋手首カメラ）。
- **効率**：NVIDIA RTX 5090、時刻ごとの平均推論遅延とpeak GPU memoryを計測。履歴長 `C=4,8,16,32`、単純なmulti-frame stackingを比較。
- **比較**：π0.5、QwenGR00T、MemoryVLA、HiF-VLAなど。ただし異なる学習・checkpointの絶対成功率を厳密な同条件比較とみなさない。

## 5. Main Results

### 5.1 成功率・長時間実行

| 評価 | Baseline | TempoFit | 差 |
|---|---:|---:|---:|
| LIBERO-LONG / π0.5 | 92.6% | 96.6% | +4.0pt |
| LIBERO-LONG / QwenGR00T | 90.8% | 94.4% | +3.6pt |
| CALVIN D→D / 5連続指示の平均達成数 | 3.78 | 3.84 | +0.06 |
| CALVIN ABC→D / 同上 | 3.83 | 3.87 | +0.04 |

CALVINの改善は後半の指示で比較的大きいが、平均達成数の差は小さい。実機3タスクでは論文が平均+9.5ptの改善を報告。各タスクの試行数や統計的不確実性を十分吟味する必要がある。

### 5.2 遅延とメモリ（RTX 5090）

| 手法 | 履歴フレーム | 遅延 | peak GPU memory |
|---|---:|---:|---:|
| π0.5 単一フレーム | 1 | 71.2ms | 6,396MB |
| frame stacking | 4 | 94.8ms | 22,640MB |
| TempoFit | 4 | 73.4ms | 6,498MB |
| frame stacking | 8 | 176.3ms | 45,980MB |
| TempoFit | 8 | 74.4ms | 6,600MB |
| TempoFit | 16 | 81.4ms | 6,761MB |
| TempoFit | 32 | 86.8ms | 7,030MB |

履歴8で単純連結より低コスト。ただし単一フレーム比では**速度向上ではなく4%程度の追加遅延**である。「低オーバーヘッドで成功率改善」と読むべき。制御周波数はこの表から直接の実機保証はできない。

## 6. 主要ablation（π0.5 / LIBERO-LONG、500試行）

| 条件 | 成功率 |
|---|---:|
| 履歴なし | 92.6% |
| KV memoryのみ | 93.8% |
| KV memory + FGTB | **96.6%** |
| Q-to-K retrieval | 93.3% |
| K-to-K retrieval | **96.6%** |
| 履歴K/Vの単純連結 | 0.8% |
| norm保持なしのresidual | 90.2% |
| norm保持ありのresidual | **96.6%** |
| 全層memory | 74.2% |
| 中間層memory | **96.6%** |
| 容量C=4/8/16/32 | 95.2 / **96.6** / 96.2 / 95.2% |

FGTB、K-to-K、norm保持、中間層選択のすべてが重要。履歴を増やせば単調に改善するわけではない。

## 7. Limitations / 批判的評価

1. FIFO容量を超える長期のエピソード記憶は保持しない。記憶検索はsoftで、明示的なイベント・サブタスク・失敗履歴の構造化はない。
2. **現在フレームのK/Vを計算してから過去情報を融合**するため、VLA-Cache/LACのようなtoken再計算削減やOxyGenのcross-task prefill共有とは別問題。
3. K-to-Kの類似度は内容と時刻の混合であり、異なるカメラ視点・物体配置変化に対する頑健性は追加検証が必要。
4. CALVINの平均差は小さく、実機での誤動作・制御周期・GPU差異に対する統計的保証は限定的。
5. 全層注入・単純連結が壊滅的に失敗することから、凍結VLAのKV分布の扱いは極めて繊細。任意のbackboneへの無調整移植を保証しない。

## 8. Taxonomy / 関連研究

- **分類**：`KVcache/vla/`。Cross-frame **KV-based memory retrieval and fusion**、training-free temporal augmentation。
- **[VLA-Cache](2025-2502.02175-vla-cache.md)**：不変visual tokenのKVを直接再利用して計算を省く。TempoFitは履歴を検索・融合して判断を改善する。
- **[LAC](2026-2602.00686-lac.md)**：再計算/再利用の選択を学習する。TempoFitは追加学習不要。
- **[MemoryVLA](2025-2508.19236-memoryvla.md)**：視覚・意味の長期Memory Bankを別に持つ。TempoFitはモデル内部のprefix KVをFIFOで保持。
- **[NativeMEM](2026-2607.06678-nativemem.md)**：履歴画像を1tokenに学習圧縮し入力する。TempoFitは入力長を増やさない。
